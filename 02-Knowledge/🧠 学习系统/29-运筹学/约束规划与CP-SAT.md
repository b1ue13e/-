# 约束规划与CP-SAT

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**；约束规划（CP）是与 LP/MIP 并列的第三大求解范式，OR-Tools 的 CP-SAT 是工业级实现——[[🧭 开源作业体系-运筹学]] 的 HW04（CP-SAT）、HW05（VRP）、HW06（排班 Capstone）全部建立在它之上。不懂 CP，就无法理解为什么某些问题 CP 几秒解完而 MIP 卡死。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：
> [[整数规划与分支定界]] 擅长"线性目标 + 线性约束"，但大量离散问题的难点是**组合/逻辑约束**：员工排班（每人每天至多一班）、数独（每行每列每宫互不相同）、作业车间调度（机器一次一个活）。这些约束写成线性不等式又长又松（"互不相同"要 $O(n^2)$ 条 $\ne$ 约束），MIP 松弛界还特别差。因此引入：**约束规划**（变量 + 值域 + 约束，靠**约束传播**与**回溯搜索**求解）及其工业实现 **CP-SAT**。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：CP 是运筹学"第三支柱"：MIP 擅长线性结构 + 目标，CP 擅长组合约束 + 可行性/调度；HW04 让两者在同一问题上对打，建立选型直觉。**实际应用场景**：排班/排课、生产调度、VRP（Routing 库基于 CP 思想）、芯片布局、谜题；CP-SAT 支持目标与可选区间变量（`NewOptionalIntervalVar`），是调度问题的事实标准。**高频题型/任务**：建模（`AddAllDifferent`、区间变量、累积约束）、理解传播与回溯、CP vs MIP 选型、VRP 建模元素。

## 4. 用直觉语言解释它

> «"约束规划就像人解数独：先看哪个格子候选数最少，填一个数，然后立刻检查——同行、同列、同宫里有这个数的格子全部划掉候选（这就是**传播**）；划着划着发现某格子没数可填，说明刚才填错了，退回重填（这就是**回溯**）。CP-SAT 就是把这个过程用算法做得又快又聪明。"»

- **直觉类比/几何图像**：每个变量有"候选集合"（域），约束是"过滤器"——任何约束都能立刻删掉不满足的候选值（传播），到不动点后再猜一个值（分支），递归下去。"填一个值 → 自动排除大批不可能 → 冲突就回头"正是人类解组合谜题的方式，是"搜索 + 推理"的朴素结合。
- **一句话直觉本质**：**把问题声明成变量+值域+约束，用传播把搜索树剪到极小，用回溯保证完备——不依赖线性结构，所以能吃下 MIP 难以表达的复杂约束。**

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
**约束满足问题（CSP）**：三元组 $(X, D, C)$：变量 $X=\{x_1,\dots,x_n\}$、值域 $D=\{D_1,\dots,D_n\}$（有限离散集）、约束集 $C$（限定若干变量的取值组合）。**CP 与 MIP 的本质区别**：MIP 靠"线性松弛 + 连续几何"剪枝；CP 靠"约束传播 + 离散域"剪枝；CP 的目标可为任意表达式，但通常不提供连续变量的全局最优证明。

**约束传播（propagation）**：对每条约束删除域中不可能出现在任何解里的值，反复到不动点。例：$x_1 \ne x_2$ 且 $x_1$ 赋值 1 ⇒ 从 $D_2$ 删 1；**弧一致性**是最基本传播强度：每条二元约束处理后每个剩余值都有搭档。**回溯搜索**：DFS 赋变量 → 传播 → 冲突则撤销 → 全部赋值即得解；现代 CP = 传播 + 回溯 + **MRV**（选域最小变量）+ **LCV**（选最可能成功的值）+ 子句学习/重启。

**CP 与 MIP 的本质区别**：MIP 靠"线性松弛 + 连续几何"剪枝；CP 靠"约束传播 + 离散域"剪枝。CP 的目标函数可为任意表达式，但通常不提供连续变量的全局最优证明。

### 2. 核心公式
**CP-SAT 建模三要素**（OR-Tools Python）：
```python
model = cp_model.CpModel()
x = model.NewIntVar(1, 4, "x")            # 变量 + 值域
model.AddAllDifferent([x1, x2, x3, x4])   # 组合约束（全局约束）
model.Add(sum(w[i] * x[i] for i in range(n)) <= capacity)  # 线性约束同样支持
solver = cp_model.CpSolver(); solver.parameters.max_time_in_seconds = 30.0
status = solver.Solve(model)              # OPTIMAL / FEASIBLE / INFEASIBLE
```

**VRP 建模元素**（Routing 库）：
```python
manager = pywrapcp.RoutingIndexManager(num_nodes, num_vehicles, depot)
routing = pywrapcp.RoutingModel(manager)
routing.SetArcCostEvaluatorOfAllVehicles(distance_callback)  # 弧代价
routing.AddDimension(demand_callback, 0, capacity, True, "Capacity")  # 容量
solution = routing.SolveWithParameters(search_parameters)
```

### 4. 常见变体与适用条件
- **变体**：CP-SAT（SAT 技术驱动的现代 CP）、Routing 库（VRP 专用，CP + 局部搜索）、CP 与 MIP 混合。**适用条件**：离散域、复杂组合约束、调度/排班/路径（变量数几万以内）；**限制**：连续变量+线性结构问题不如 LP/MIP，界弱时最优性证明可能长时间无进展。

## 6. 推导思路和思想来源

- **最初困难**：MIP 把一切翻译成线性不等式，但"互不相同""区间不重叠""至多 k 个同时进行"的线性翻译又长又松，搜索低效；朴素回溯（穷举赋值）不利用约束间的推理，树深指数爆炸。
- **关键"转念"**：**把约束当"推理引擎"而不是"检查器"**——每条约束主动删减变量域（传播），每次赋值后立即全量传播，把搜索树剪到极小；1970s AI 社区（Waltz 标注传播、Mackworth 弧一致性）奠定理论，2000s SAT 技术（子句学习、重启）注入 CP-SAT 后性能飞跃。
- **推导主线与动机**：CSP 形式化 → 弧一致性传播（删减不动点）→ 回溯框架（MRV/LCV）→ 全局约束（AllDifferent 把 $O(n^2)$ 二元约束压成一条强传播约束）→ 工业实现 CP-SAT。**为什么自然**："约束"本就是陈述式知识，让它主动参与推理（传播）比被动检查更自然——这是声明式建模（说"要什么"而非"怎么做"）的典范。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：4-皇后：$4\times4$ 棋盘放 4 个皇后互不攻击。用传播+回溯手算。
- **解题思路与关键步骤**：变量 $q_i \in \{1,2,3,4\}$（第 $i$ 行列号），约束 $q_i\ne q_j$ 且 $|q_i-q_j|\ne|i-j|$。赋 $q_1=2$：传播后 $q_2\notin\{2,3\}$ ⇒ $q_2\in\{1,4\}$；选 $q_2=4$：传播 $q_3\notin\{2,4,3\}$ ⇒ $q_3=1$；再传播 $q_4=3$ ✓。解 $(2,4,1,3)$ 与 $(3,1,4,2)$；某分支无候选（如 $q_1=1$ 时 $q_4$ 无值）即回溯。
- **易错点**：传播必须**迭代到不动点**（删一个值可能触发其他约束再删）。**🤔 追问**：$q_1=1$ 时首轮传播后 $q_2\notin\{1,2\}$、$q_3\notin\{1,3\}$、$q_4\notin\{1,4\}$；继续迭代后 $q_4$ 无候选 → 回溯。

### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：排班：3 员工、2 班次（早 A/晚 B）、连续 2 天；每天每班恰好 1 人、每人每天至多 1 班、同一人不能连续两天同班。建模：$x_{d,k}\in\{1,2,3\}$；约束：`AllDifferent([x_{d,A},x_{d,B}])`（每天两班不同人）+ $x_{d,k}\ne x_{d+1,k}$。CP 三行约束表达完毕；同样的约束用 MIP 需 12 个 0-1 变量加辅助约束且 LP 松弛极松——这正是 CP 在排班类问题的优势（对应 HW04/HW06）。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：CP-SAT 支持目标、区间变量、`AddCumulative`（机器容量）；HW04 用它求解并输出 status 与解，HW05 的 VRP 用 Routing 库（内部 CP + 邻域搜索）：
```python
from ortools.sat.python import cp_model
model = cp_model.CpModel()
q = [model.NewIntVar(1, 4, f"q{i}") for i in range(4)]   # 4-queens 的 CP-SAT 版
model.AddAllDifferent(q)
for i in range(4):
    for j in range(i + 1, 4):
        model.Add(q[i] != q[j] + (j - i)); model.Add(q[i] != q[j] - (j - i))
solver = cp_model.CpSolver(); solver.parameters.max_time_in_seconds = 10.0
status = solver.Solve(model)
print(solver.StatusName(status), [solver.Value(v) for v in q])  # OPTIMAL [2, 4, 1, 3]
```
- **与 MIP 对照的验收口径**（HW04）：同一排班问题分别用 CP-SAT 与 SCIP 求解，记录求解时间与最优值；若 MIP 界松卡死，报告"时间上限内 gap 未闭合"——这是 CP vs MIP 对比报告的标准写法。

## 8. 常见误区和易混概念

### 误区 1：以为"CP 一定比 MIP 快"
- **错误直觉**：CP 是新技术，应全面碾压 MIP；但 CP 没有连续几何，对"线性目标 + 弱组合约束"的大规模问题远慢于 MIP。
- **正确理解**：选型准则——组合约束强（AllDifferent/区间/累积）且离散 → CP；线性结构为主、连续变量多 → MIP。HW04 的意义就是亲手测出边界。

### 误区 2：以为"CP-SAT 只能做可行性判断"
- **错误直觉**：CP-SAT 不能优化；但它支持目标函数（`model.Minimize(...)`），内部"找可行解 → 收紧目标上界 → 再找更优"循环，输出 `OPTIMAL` 即证明最优。
- **正确理解**：传播是剪枝手段，搜索是完备框架，优化是"反复搜索更优可行解"。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| CP（约束规划） | 组合约束下的可行性/最优性 | 传播+回溯，离散域 | 排班、调度、谜题 |
| MIP（整数规划） | 线性结构的离散优化 | 线性松弛+割平面+B&B | 选址、投资、网络设计 |

### 题目与解析

#### 1. 约束规划与整数规划（MIP）最本质的区别是什么？
> [!question]- 答案解析
> - **答案**：MIP 把问题翻译成线性目标 + 线性约束，靠 **LP 松弛的连续几何**剪枝；CP 直接对变量域做**约束传播**（删候选值）再用回溯搜索，不依赖线性结构。
> - **解析**：因此 CP 擅长互异/区间/累积等组合约束，MIP 擅长线性结构；两者都能优化但剪枝机制完全不同——这是 HW04 对比实验的理论基础。易错点：把"都能解整数问题"误当成"等价"（对应误区 1）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 变量 $x \in \{1,2,3,4\}$，约束 `AddAllDifferent([x, y, z])`，已知 $y=2,\ z=2$。传播后 $x$ 的值域？
> [!question]- 答案解析
> - **答案**：$\{1,3,4\}$（删掉 2）。AllDifferent 是"两两互异"的全局约束，$x$ 域中与已赋值冲突的值被删；若传播后某域为空 ⇒ 无解，触发回溯。注意传播需迭代到不动点。

#### 3. 带线性目标、1000 个连续变量、少量整数变量的生产计划，选 CP-SAT 还是 MIP？
> [!question]- 答案解析
> - **答案**：选 MIP（SCIP 等）。问题以线性连续结构为主，LP 松弛界紧，MIP 能高效利用连续几何；CP-SAT 的传播对连续变量和弱组合约束几乎无剪枝优势。选型准则：连续变量多、线性结构强 → MIP；离散域 + 组合约束（排班/调度/路径）→ CP-SAT。HW04 对比实验正是为建立此直觉。

#### 4. 用 OR-Tools Routing 库建模容量受限 VRP（CVRP），需要哪些核心元素？各自作用？
> [!question]- 答案解析
> - **答案**：① `RoutingIndexManager`（节点数/车辆数/车场，统一索引）；② `distance_callback`（两点间代价，`SetArcCostEvaluatorOfAllVehicles` 设为弧代价）；③ `AddDimension`（容量等累积约束）；④ `SearchParameters` 与 `SolveWithParameters`（求解与取解）。
> - **解析**："每客户恰好被一车访问、容量不超限"本质是 CP 风格组合约束，Routing 内部正是 CP + 局部搜索（见 [[04-随机优化与实践/随机优化与实践-启发式方法-邻域搜索\|邻域搜索]]）。漏掉 `AddDimension` 会退化为无容量约束的 m-TSP。

#### 5. 为什么回溯搜索中"选值域最小的变量先赋值（MRV）"通常更快？指出一个反例情形。
> [!question]- 答案解析
> - **答案**：MRV（fail-first）让最可能出冲突的变量先定值，尽早发现矛盾、尽早回溯，剪掉更大子树——"早失败比晚失败便宜"。反例：域大小相同时 MRV 无差别；若存在"枢纽"变量（与很多变量有约束），优先赋它（约束密度启发式）可能更有效。变量/值排序启发式是 CP 工程性能核心（CP-SAT 内部还有学习到的分支策略）——这也是 HW04 调节求解器参数能大幅改变求解时间的原因。
