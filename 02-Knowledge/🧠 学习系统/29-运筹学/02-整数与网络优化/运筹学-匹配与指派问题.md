# 运筹学-匹配与指派问题

> 所属阶段：[[🧭 阶段2-整数与网络优化|🕸️ 第2阶段：整数与网络优化]]

## 这个知识点解决什么问题？

**我们遇到的麻烦**：把"人分配到任务、工人匹配机器、学生匹配宿舍"这类双边配对问题统一处理。看似简单（$\binom{n}{m}$ 种分配），但朴素枚举爆炸。本卡覆盖三个层次：**二分图最大匹配**（增广路径）、**指派问题**（匈牙利方法，带权重的最优匹配）、**稳定匹配**（Gale-Shapley，偏好排序下无人愿意私下更换）。三者都可建模为网络流或 0-1 整数规划。

## 核心概念

### 1. 二分图与最大匹配

- 二分图 $G=(L\cup R,E)$：边只连接左部与右部。**匹配**：两两不相邻的边集。
- **增广路径**：交替"非匹配边—匹配边"，起点终点都是未匹配点。存在增广路径 ⇔ 匹配不是最大（Berge 定理）。
- 算法：反复找增广路径（BFS/DFS，等价于网络流）直到没有——复杂度 $O(\lvert E\rvert\sqrt{\lvert V\rvert})$（Hopcroft-Karp）。

### 2. 指派问题（匈牙利方法）

$n$ 个人 × $n$ 个任务，成本 $c_{ij}$，求 $\min\sum c_{ij}x_{ij}$ s.t. $\sum_i x_{ij}=1,\ \sum_j x_{ij}=1,\ x_{ij}\in\{0,1\}$。

- 匈牙利算法（Kuhn-Munkres）：行/列减常数不改变最优解 → 找 0 元素覆盖 → 直到找到 $n$ 个独立 0。$O(n^3)$。
- 也是网络流（最小费用流）与指派 LP 的特例。

### 3. 稳定匹配（Gale-Shapley）

两组各有**偏好排序**，求稳定匹配：不存在"两人都更愿意彼此配对"的阻碍对。**延迟接受算法**：未匹配方按偏好依次求婚，被求婚方在"当前最佳"与"新求婚者"间择优暂时接受；一轮轮进行直到所有人配对。性质：男生最优/女生最劣（取决于谁主动求婚）、运行 $O(n^2)$。

## 一个最小例子（手算）

**指派**：3 人 3 任务成本矩阵 $\begin{pmatrix}9&2&7\\6&4&3\\5&8&1\end{pmatrix}$。

1. 行减最小：$\begin{pmatrix}7&0&5\\3&1&0\\4&7&0\end{pmatrix}$；列减：第一列减 3 → $\begin{pmatrix}4&0&5\\0&1&0\\1&7&0\end{pmatrix}$。
2. 找 3 个独立 0：$(1,2),(2,1),(3,3)$ → 成本 $2+6+1=9$。最优分配：人1→任务2、人2→任务1、人3→任务3，总成本 9。
3. 验证：任何其他排列（如人1→1,人2→2,人3→3 成本 14）都更大。

## 用代码验证（scipy 匈牙利 + OR-Tools 0-1 模型）

同一实例用两种方法独立求解，交叉验证：

```python
import numpy as np
from scipy.optimize import linear_sum_assignment
from ortools.linear_solver import pywraplp

cost = np.array([[9, 2, 7], [6, 4, 3], [5, 8, 1]])

# 方法 1：scipy 匈牙利算法
ri, ci = linear_sum_assignment(cost)
print("scipy:", list(zip(ri, ci)), "总成本 =", cost[ri, ci].sum())   # 9

# 方法 2：OR-Tools 0-1 整数模型（行和=列和=1）
s = pywraplp.Solver.CreateSolver("SCIP")
x = {(i, j): s.IntVar(0, 1, f"x{i}{j}") for i in range(3) for j in range(3)}
for i in range(3): s.Add(sum(x[i, j] for j in range(3)) == 1)   # 每人一任务
for j in range(3): s.Add(sum(x[i, j] for i in range(3)) == 1)   # 每任务一人
s.Minimize(sum(cost[i, j]*x[i, j] for i in range(3) for j in range(3)))
s.Solve()
print("OR-Tools obj =", s.Objective().Value())                   # 9.0
```

输出：两种方法都得到总成本 **9**（分配：人1→任务2、人2→任务1、人3→任务3），与手算一致。**注意**：指派模型把"行和 $=1$、列和 $=1$"写成等式（不是 $\le$），这是它区别于"最大匹配"的关键。

## 三类匹配问题对比

| 问题 | 目标 | 权重 | 算法 | 典型场景 |
|:---|:---|:---|:---|:---|
| 二分图最大匹配 | 边数最多 | 无 | 增广路径 / Hopcroft-Karp | 任务能否全部分配 |
| 指派问题 | 总成本最小 | 有（成本矩阵） | 匈牙利 / 费用流 | 人-任务最优搭配 |
| 稳定匹配 | 无阻碍对 | 偏好排序 | Gale-Shapley 延迟接受 | 学校录取、医生规培 |

**关系**：最大匹配是"能不能"，指派是"最优怎么配"，稳定匹配是"配了不散伙"——三者目标递进：数量 → 成本 → 稳定性；Gale-Shapley 中主动求婚方占优、被动方吃亏。

## 常见误区

- **误区 1**：最大匹配（无权重）与指派（带权重）混淆。前者数边数，后者最小化成本；匈牙利只用于后者。
- **误区 2**：稳定匹配"最优"含义。稳定 ≠ 总效用最大——它只保证"无人愿意拆对"，总福利不一定最优。
- **误区 3**：指派矩阵非方阵直接跑匈牙利。需补虚拟行/列（$c=\infty$ 或 0），否则算法失效。
- **误区 4**：指派约束写成 $\le$。必须 $=1$ 才是"每人恰一任务、每任务恰一人"的排列结构，写 $\le$ 会允许"有人闲着、有任务没人做"。
