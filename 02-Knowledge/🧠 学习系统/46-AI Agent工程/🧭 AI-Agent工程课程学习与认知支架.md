# 🧭 AI Agent 工程课程学习与认知支架

## 学习设计原则

- **先激活旧知识**：每周先闭卷回答 3 个诊断题，再看主题卡；不会则进入具体补救分支。
- **控制内在负荷**：每周只引入一个新控制概念，框架名和云产品放在稳定概念之后。
- **管理外在负荷**：统一使用同一个 `local-acceptance/` 场景演进，避免每章更换领域和代码风格。
- **增加生成性负荷**：固定执行“预测→手算→运行→故障注入→解释→迁移”，要求学习者产生答案而非只重读。
- **检索与间隔**：每张卡在次日、3 天、7 天、14 天闭卷复现；复习失败只回到具体卡点。
- **双编码但不装饰**：对 runtime、上下文流和协议边界画图；图必须能映射到状态、消息或代码对象。
- **小白 16 周，每周 7–9 小时**；已有 Python、ML/DL、LLM 与 Prompt/RAG 基础者可压缩为 12 周。Agentic RL 为选修，不用 GPU 训练阻塞核心路线。

| 5 | 上下文工程、记忆/RAG | GSSC 装配清单 + 证据 ID | 有预算、来源、隔离和污染测试 |

## 渐隐支架

1. **示范**：运行 `03-Projects/46-AI Agent工程/local-acceptance/`，从 trace 复述 intake→retrieve→score→aggregate→finalize，并检查每次 handoff。
2. **补全**：保留测试、`ToolRegistry` 与消息 schema，替换一个工具或阶段；不得删除异常、终止和恶意证据测试。
3. **迁移**：换成研究资料整理或只读诊断任务，独立定义工具权限、状态、checkpoint、威胁模型与验收矩阵。

失败时只回退一层；连续两次失败则回到具体先修卡，不盲目重抄框架代码。

具体 P0–P8 练习、故障注入与 Gate 见 [[AI-Agent工程-双教材渐进实践-知识点映射]]。

## 每周学习闭环

| 环节 | 时间 | 学习者动作 | 可检查证据 |
| :--- | :---: | :--- | :--- |
| 闭卷预测 | 15 分钟 | 回答 3 题并预测代码输出 | 未看答案的初稿 |
| 最小讲解 | 45–60 分钟 | 只读当前主题卡 0–6 节 | 一页概念图/状态图 |
| 手算与运行 | 60–90 分钟 | 手走一个输入，再运行代码 | 预测差异记录 |
| 故障注入 | 60 分钟 | 主动破坏一层并从 trace 定位 | 失败类别与修复 |
| 闭卷复现 | 20 分钟 | 不看笔记重写定义/流程/边界 | 自测分数 |
| 迁移 | 2–3 小时 | 换领域或工具并重跑测试 | 新用例与回归报告 |

> [!tip] 熟练标准
> “看懂”不计通过。至少要做到：闭卷解释、手算正确、代码可运行、能制造并定位失败、换场景仍能通过。

## 高阶验收量规

| 维度 | 0 分 | 1 分 | 2 分 |
| :--- | :--- | :--- | :--- |
| 边界 | 无边界 | 有说明 | 状态/工具/权限均明确 |
| 正确性 | 看演示 | 少量样例 | 正常、异常、对抗测试齐全 |
| 可观测 | 只看最终答案 | 有日志 | trace 可定位到层级 |
| 安全 | 靠 Prompt | 部分校验 | 最小权限、审批、沙箱、审计 |
| 可恢复 | 失败重跑 | 有重试 | 幂等、检查点、预算和终止 |
| 迁移 | 只改名称 | 换输入数据 | 换领域/工具后重新定义威胁与测试 |

总分至少 10/12；安全维度若为 0，则总分再高也不通过。

## 补救分支

- 不懂 ML/DL 或 LLM/RAG → 先完成 [[45-生成式AI基础与Prompt工程/🗺️ 生成式AI基础与Prompt工程学习路径|生成式 AI 与 Prompt 工程]] 的模型、评测、RAG、安全主线；数学和训练基础不足再转 [[17-机器学习/🗺️ 机器学习学习路径|机器学习]]。
- JSON/异常/测试不会 → [[AI-Agent-前置-消息JSON异常与单元测试]]。
- AutoGen 导入或注册报错 → [[AI-Agent-框架-AutoGen官方Lab版本补丁]]，核对环境而不是改 Prompt。
- 不知道该选框架还是自研 → [[AI-Agent-框架选型与最小运行时]]，先写需求和否决理由。
- 循环不终止 → [[AI-Agent-规划状态与工作流编排]]。
- 长任务越做越乱 → [[AI-Agent-上下文工程-选择压缩隔离]]，检查预算、陈旧状态和信任分区。
- 反思重复同一答案 → [[AI-Agent-反思与元认知-校验修正停止]]，检查验证证据与无进展停止。
- MCP/A2A 混淆 → [[AI-Agent-协议-MCP与A2A互操作]]，先判断是工具调用还是远程任务委托。
- 结果偶现错误 → [[AI-Agent-可观测性与生产运行-轨迹审批恢复]]，先查 trace 和失败分类。
- 不知道改进是否真实 → [[AI-Agent-评测与基准-任务轨迹成本]]，看逐样本、切片、安全与成本。
- 部署后只会看 200 → [[AI-Agent-部署与本地运行-伸缩路由烟测]]，区分 smoke、readiness 和 eval。
- 需要证明审批/日志未被偷换 → [[AI-Agent-安全审计-加密收据与审批绑定]]。
