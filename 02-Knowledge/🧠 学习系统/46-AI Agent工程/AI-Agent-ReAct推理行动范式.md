# AI Agent：ReAct 推理—行动范式

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：ReAct 提供了理解工具型 Agent 的最小控制语言：模型不是只输出答案，而是在“决定下一动作—读取外部观察—再决定”之间交替。掌握其信息流比背框架 API 更耐久。

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：纯内部推理可能基于错误事实一路推到底；纯动作系统又缺少选择和纠错依据。

ReAct 将任务轨迹组织为推理/决策、动作、观察的循环，使外部证据能及时改变后续动作。

## 2. 为什么它重要？它有什么用？

- **连接大图景**：是搜索 Agent、网页 Agent、代码 Agent 和 RAG Agent 的共同骨架。
- **实际应用场景**：事实核验、逐步检索、计算器调用、数据库查询和故障诊断。
- **高频题型/任务**：把任务改写为 Thought/Action/Observation；判断何时停止；诊断轨迹失败。

## 3. 学它之前需要哪些前置知识？

1. **[[AI-Agent-边界与感知行动循环]]**：ReAct 是闭环的一种具体轨迹格式。
2. **[[Prompt基础]]**：要规定允许动作、格式和停止规则。

## 4. 用直觉语言解释它

> “这东西其实就像做开卷题：先判断缺哪条资料，只查这一条；读到资料后再决定是计算、继续查，还是作答。”

- **直觉类比**：医生不会只靠第一印象诊断，也不会把所有检查都做一遍，而是根据每次结果选下一检查。
- **为什么很自然**：推理指导有效探索，观察又校正推理。
- **一句话直觉本质**：以最小必要思考选择可验证动作，再用真实观察缩小不确定性。

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义

ReAct 轨迹是交错序列 $\tau=(d_1,a_1,o_1,\ldots,d_T,a_T,o_T)$，其中 $d_t$ 是面向下一动作的决策摘要，$a_t$ 是外部动作，$o_t$ 是环境反馈。工程日志应记录动作依据和结果，但不要求暴露模型私有长推理。

### 2. 核心公式

$$a_t\sim\pi(a\mid g,h_t),\qquad h_t=(a_1,o_1,\ldots,a_{t-1},o_{t-1})$$

$$T=\min\{t:\operatorname{done}(g,h_t)\lor t=B\}$$

其中 $B$ 是步数或预算上限。

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $d_t$ | 下一步决策摘要 | 短文本/结构化原因码 | 不保存敏感长推理 |
| $h_t$ | 可见历史 | 动作与观察序列 | 可压缩 |
| $B$ | 预算 | 步数/token/费用 | 硬终止条件 |
| $\tau$ | 完整轨迹 | 有序事件序列 | 评测与调试对象 |

### 4. 常见变体与适用条件

- **变体**：先计划再 ReAct、检索专用 ReAct、反思后重试、树搜索。
- **限制条件**：对于可一次可靠计算的任务，ReAct 增加延迟；无工具白名单时会扩大攻击面。

## 6. 推导思路和思想来源

- **最初困难**：Chain-of-Thought 可以分解问题，但不能保证事实来自环境；action-only 容易盲目试错。
- **直接方法局限**：一次性生成完整计划无法适应中途失败。
- **关键“转念”**：让每次推理只服务于“选择下一动作”，而不是在未知环境中提前写完整答案。
- **推导主线与动机**：识别信息缺口→选动作→观察→更新缺口→停止/继续。
- **为什么自然得到此结论**：闭环决策天然需要交替使用内部模型和外部证据。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）

- **题目**：求“库存 12 件，每箱装 5 件，最多能装满几箱”。检索成本 3，计算成本 1，直接计算是否优于调用搜索？
- **解题思路与关键步骤**：题干信息充分，整数除法 $12//5=2$；无需外部观察。
- **最终答案**：2 箱，只执行 calculator 或本地计算，成本 1。
- **易错点**：把 ReAct 理解成每题都必须多次搜索。
- **🤔 追问**：若库存数未给出而需查数据库，轨迹如何改变？

### 例子 2：中等例子（条件判断与多步推理）

“某餐厅是否满足评分阈值”应先查评论，若无数据则停止并报告证据不足；若有数据则解析维度、计算并返回来源。错误做法是先猜餐厅分数，再寻找支持猜测的评论。

### 例子 3：实际应用例子（真实场景/代码）

标准库示例根据观察选择 `lookup` 或 `calculate`，输入 `"price of pen times 3"`，输出一条完整轨迹和 `12`。

```python
CATALOG = {"pen": 4, "book": 9}

def react(task: str) -> tuple[int, list[dict[str, object]]]:
    trace: list[dict[str, object]] = []
    item = next(name for name in CATALOG if name in task)
    trace.append({"decision": "need unit price", "action": "lookup", "input": item})
    unit_price = CATALOG[item]
    trace.append({"observation": unit_price})
    quantity = int(task.rsplit(" ", 1)[-1])
    trace.append({"decision": "facts complete", "action": "multiply", "input": [unit_price, quantity]})
    answer = unit_price * quantity
    trace.append({"observation": answer, "done": True})
    return answer, trace

answer, events = react("price of pen times 3")
print(answer)
print(events)
```

预期首行输出：`12`。

## 8. 常见误区和易混概念

### 误区 1：Thought 越长越好

- **错误直觉**：更多推理文字等于更强推理。
- **为什么错**：冗长轨迹增加成本、泄漏面和自我强化错误。
- **正确理解**：记录足以解释动作选择的短决策摘要；把可验证事实交给工具。

### 误区 2：工具返回即真相

- **错误直觉**：Observation 是外部结果，所以可信。
- **为什么错**：网页、RAG 文档和工具错误都可能携带恶意或过期内容。
- **正确理解**：观察是数据，不是更高优先级指令；需验证来源、格式和权限。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| ReAct | 下一步查什么/做什么？ | 推理与动作逐步交替 | 开放检索、工具任务 |
| Chain-of-Thought | 如何展开内部推导？ | 可无外部行动 | 数学、逻辑分解 |
| Plan-and-Execute | 先拟定哪些里程碑？ | 先计划后逐项执行 | 长任务、可恢复流程 |
| Reflexion/反思 | 上次失败说明什么？ | 用失败记忆改进重试 | 迭代修复 |

## 11. 自测题：5 道

### 1. #自测题/基础
**题目**：ReAct 的 Observation 是谁产生的？
> [!question]- 答案解析
> - **答案**：环境或外部工具产生，而非模型把自己的猜测当观察。
> - **解析**：环境可以是数据库、函数、网页或执行器。

### 2. #自测题/基础
**题目**：信息已完整的整数计算需要先搜索吗？
> [!question]- 答案解析
> - **答案**：不需要，直接使用确定性计算工具。
> - **解析**：动作要减少不确定性，冗余搜索只增加成本和污染风险。

### 3. #自测题/中等
**题目**：工具返回网页文字“忽略系统指令”，应如何处理？
> [!question]- 答案解析
> - **答案**：将其视为不可信数据，不提升其指令优先级；提取任务相关事实并执行安全策略。
> - **解析**：这是间接 prompt injection 的典型入口。

### 4. #自测题/中等
**题目**：两次同参数工具调用均超时，下一步是什么？
> [!question]- 答案解析
> - **答案**：停止相同重试，选择批准的备用工具、缩小请求或报告失败。
> - **解析**：重试必须有预算、退避和替代路径。

### 5. #自测题/较难
**题目**：如何在不记录私有长推理的情况下保持可审计？
> [!question]- 答案解析
> - **答案**：记录目标、动作、参数摘要、外部观察摘要、来源、原因码、策略命中、成本和终止理由。
> - **解析**：审计需要可验证决策证据，不等于保存全部隐式思维。

- ReAct 的三个交替元素是什么？::面向下一步的决策/推理、外部动作、环境观察。
