# 🧭 阶段 2：运行时、规划与状态

## 为什么现在学

工具循环可运行后，需要把状态、重试、检查点和框架 adapter 分开，才能在版本漂移或中断时恢复，而不是把业务逻辑锁进框架私有对象。

## 学习目标

- 识别最小 Agent runtime 的关键部件。
- 用 DAG/状态机表达依赖、错误转移和终止。
- 用结构化消息和可验证职责控制多角色协作成本。
- 隔离历史 AutoGen 0.2 Lab 与当前 Microsoft Agent Framework 主线。

## 学习顺序

1. [[AI-Agent-框架选型与最小运行时]]：需求先于框架，建立稳定本地接口。
2. [[AI-Agent-规划状态与工作流编排]]：显式表示状态、预算与恢复。
3. [[AI-Agent-多智能体协作与消息协议]]：按职责、工件、权限和收益决定是否拆角色。
4. [[AI-Agent-框架-AutoGen官方Lab版本补丁]]：只为 Berkeley F24 Lab 建立历史兼容环境。

## 阶段验收与作业

- **阶段作业**：[[AI-Agent工程-阶段作业-02-餐厅评论可恢复管线]]。
- **通过标准**：本地测试能执行真实工具、状态转移、有限终止和 checkpoint 恢复；框架替换不修改核心测试语义。
- **下一阶段**：通过后进入 [[🧭 阶段3-上下文记忆与校验]]。

## 阶段产出与回收

- **阶段产出**：交付显式状态机、handoff 消息、checkpoint 文件和中断恢复等价性记录。
- **回收节点**：次日、3 天后、7 天后闭卷重建五阶段状态和一次可重试/不可重试错误分类。
- **进入下一阶段条件**：阶段作业达到 85 分，恢复结果与不中断执行一致，历史 AutoGen 兼容层不得污染核心接口。
