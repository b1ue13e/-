# AI Agent 工程：作业必需与全面知识清单

## 1. 三层标记

- **P0 必须**：不会就难以理解题意或通过公开验收。
- **P1 强烈建议**：可能不直接出现在提交文件，却决定鲁棒性与调试效率。
- **P2 全面掌握**：把一次性作业升级为可复现、可维护、可评测的工程能力。

## 2. 共同前置补给

| 能力 | 层级 | 闭卷验收 |
| :--- | :---: | :--- |
| Python 函数、字典、列表、文件、异常 | P0 | 写一个读取文本、解析评分、失败时返回结构化错误的函数 |
| 类型与数据契约 | P0 | 能说明 `str -> dict` 为什么比“自由文本随便传”更可测 |
| 单元测试与边界样例 | P0 | 正常、空输入、格式错误各写 1 个测试 |
| LLM 消息角色与上下文窗口 | P0 | 区分 system/user/tool 消息和外部数据 |
| Prompt 基本结构 | P0 | 能写清角色、任务、输入边界、输出格式、失败策略 |
| JSON/结构化输出 | P1 | 能校验字段、类型、范围与缺失值 |
| 日志与可复现记录 | P1 | 保存模型、参数、输入、工具结果、最终输出和耗时 |

## 3. Lab 01：Restaurant Review Pipeline

### 完成作业的最小知识点集

- [ ] P0 [[AI-Agent-边界与感知行动循环]]：知道何时继续调用、何时停止。
- [ ] P0 [[AI-Agent-工具调用与结构化契约]]：评论查询、评分与聚合函数有明确契约。
- [ ] P0 [[AI-Agent-规划状态与工作流编排]]：输入→检索评论→抽取评分→聚合→答案的顺序和失败转移。
- [ ] P0 [[AI-Agent-多智能体协作与消息协议]]：角色、发言顺序、handoff 和终止条件。
- [ ] P0 AutoGen 最小概念：Conversable agent、message、function/tool、发起者/接收者（以官方 starter code 实际版本为准）。
- [ ] P0 浮点计算、范围约束、大小写与名称归一化。

### 全面掌握扩展

- [ ] P1 [[AI-Agent-ReAct推理行动范式]]：解释何时需要根据观察修正动作。
- [ ] P1 [[AI-Agent-记忆与检索增强生成]]：把评论语料看作外部证据，不让模型凭空评分。
- [ ] P1 测试替身：用确定性假模型替代真实 API 做管线测试。
- [ ] P2 幂等性、重试、超时、缓存、token/成本统计。
- [ ] P2 模型输出漂移与解析失败的属性测试。

## 4. Lab 02：Writing LLM Attacks

### 完成作业的最小知识点集

- [ ] P0 [[AI-Agent-安全威胁建模与系统评测]]：资产、信任边界、攻击目标、成功判据。
- [ ] P0 区分 prompt injection、jailbreak、数据外泄、工具滥用。
- [ ] P0 明确实验只能针对课程沙箱/授权目标，不外推到真实系统。
- [ ] P0 为每个攻击记录假设、载荷类别、模型响应与是否成功，不泄露敏感内容。
- [ ] P0 理解隐藏测试：优化攻击类别覆盖，而不是猜具体测试字符串。

### 全面掌握扩展

- [ ] P1 直接/间接注入、多轮上下文操纵、编码/混淆、角色冲突的分类学。
- [ ] P1 攻击成功率、拒绝率、误判率和跨模型迁移率。
- [ ] P2 自动化红队的预算、速率限制、审计与安全停机机制。

## 5. Lab 03：Defending Against LLM Attacks

### 完成作业的最小知识点集

- [ ] P0 [[AI-Agent-安全威胁建模与系统评测]]：安全与正常任务效用必须共同测量。
- [ ] P0 指令与数据分离、输入标记、最小权限、输出验证、拒绝策略。
- [ ] P0 使用 Lab 02 的攻击集做回归测试，但不只针对自己的少量字符串过拟合。
- [ ] P0 防御通过隐藏攻击至少 1/3 是官方门槛，不代表生产安全。

### 全面掌握扩展

- [ ] P1 纵深防御：prompt + parser + policy + tool ACL + sandbox + human approval。
- [ ] P1 测试安全率、正常任务成功率、误拒率、延迟和成本。
- [ ] P2 间接注入、记忆污染、RAG 中毒、工具输出污染与供应链风险。
- [ ] P2 版本化威胁模型、红队语料和上线门禁。

## 7. 证据包模板

每份作业至少保存：

```text
README.md           # 环境、命令、限制
requirements.txt    # 固定版本（若有第三方依赖）
src/                # 自己的实现
tests/              # 公开测试 + 自建边界测试
runs/               # 去敏后的运行摘要
report.md            # 设计、结果、失败分类、改进
```

## 🃏 Anki 卡片

- P0、P1、P2 分别表示什么？::P0 是完成作业的必要知识，P1 是显著提高鲁棒性与调试效率的知识，P2 是把作业提升为可复现工程能力的扩展知识。
- 为什么通过隐藏测试不等于生产安全？::隐藏测试只抽样有限威胁与输入分布；生产还涉及权限、供应链、间接注入、监控、误拒与持续回归。
