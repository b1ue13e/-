# 图神经网络-大规模训练与线上评估边界

## 1. 问题动机

离线小图分数不等于系统可用。图规模、邻域展开、特征更新、服务延迟、时间漂移和反馈回路都会改变模型的真实目标。本卡的出口不是“部署成功”，而是能写出何时需要采样/分区、如何测量资源、哪些线上结论仍未被验证。

## 2. 训练侧选择

- 全图传播：实现简单，适合小图或可容纳的稀疏图；
- 邻居采样：控制 fanout，付出采样方差和边界处理成本；
- Cluster-GCN/子图训练：减少跨簇通信，依赖分区质量；
- GraphSAINT：子图采样并做估计归一化，需核对采样分布；
- Graph Transformer：全局 attention 的成本可能主导系统，不应仅看 FLOPs 之外的内存和数据搬运。

## 3. 服务侧四个边界

1. **特征新鲜度**：训练/推理使用的时间窗口和更新延迟；
2. **图可见性**：线上请求时可用的邻居和关系，不能依赖未来边；
3. **延迟预算**：P50/P95/P99、采样节点数、缓存命中率和失败回退；
4. **评价口径**：离线 AUC/AP、线上点击/转化/投诉等指标不能直接互换。

线上 A/B 需要明确随机化单位、曝光分母、时间窗口和保护指标；离线回放只能证明协议一致，不能伪装成线上因果结果。

## 4. 最小资源记录

```python
from time import perf_counter

def timed(fn, repeat=3):
    values = []
    for _ in range(repeat):
        start = perf_counter()
        fn()
        values.append(perf_counter() - start)
    return {"runs": repeat, "min_s": min(values), "mean_s": sum(values) / repeat}

report = timed(lambda: sum(i * i for i in range(1000)))
assert report["runs"] == 3
print(report)
```

这是计时格式检查，不是性能结论。真实报告还要记录硬件、数据规模、批大小、fanout、缓存和失败请求。

## 5. 漂移与错误分析

- 结构漂移：节点度数、关系比例、组件结构变化；
- 特征漂移：分布、缺失率、标准化范围变化；
- 标签/反馈漂移：用户行为受模型推荐影响，离线标签不再独立；
- 采样偏差：线上只看到高活跃节点，导致长尾失效。

每种漂移都要有可观测统计和回滚/降级条件。没有线上数据时，报告必须明确“未验证”，不能用 OGB 或 toy graph 的分数替代生产证据。

## 6. 常见错误

1. 用参数量或单次训练时间代替端到端延迟。
2. 只优化平均指标，隐藏 P99 和长尾节点失败。
3. 把邻居缓存中的未来关系直接喂给离线 replay。
4. 把公开榜单分数写成业务收益或线上因果结论。

## 7. 检索练习与通过标准

- 为一个邻居采样训练任务列出至少 5 个必须记录的资源字段。
- 设计一个离线 replay 能验证、但仍不能证明线上因果的指标。
- 给出结构漂移和特征漂移各一个监控统计与触发动作。

通过标准：能画出训练→服务→评估的数据边界；能报告资源和失败，而不是只报 accuracy；明确任何未实际运行/未线上验证的部分。
