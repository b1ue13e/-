# 图神经网络-实验设计消融与错误分析

## 1. 问题动机

GNN 实验最容易犯的错误不是代码跑不通，而是比较不公平：模型用不同 split、不同特征、不同 seed 或不同早停规则，最后却把分数差异归因于架构。实验设计卡把“结论能否被复核”放在模型名称之前。

## 2. 最小实验协议

每个任务先冻结：

1. 数据版本、节点/边过滤规则和哈希；
2. train/val/test split 与 transductive/inductive 口径；
3. 输入特征、标签编码和缺失值处理；
4. 模型预算：层数、隐藏维度、参数量上限、训练轮次和早停规则；
5. seed 集合（最低 3 个，正式阶段作业建议 5 个）；
6. 指标、聚合方式（均值/中位数）和失败运行保留规则。

## 3. 基线与公平比较

- MLP：只用节点特征，验证结构是否真的带来增益；
- 结构启发式/浅层 embedding：验证非神经结构信号；
- GCN、GraphSAGE、GAT：统一任务头、split、optimizer 预算；
- 随机/多数类：检查指标是否被类别分布误导。

不能只比较三个 GNN，然后把最好的 GNN 与一个没有调参的 MLP 对照。

## 4. 消融问题必须可归因

一个合格消融只改变一个主要因素，例如：

- 去掉邻接传播，保持任务头和训练预算不变；
- 深度 2/4/8，报告表示方差、训练稳定性和验证性能；
- fanout 5/10/20，报告节点数、时间、性能和采样方差；
- 去掉自环/残差/特征，说明改动的理论假设。

消融不是“再跑几个配置”，而是为了回答一个明确的因果问题。

## 5. 错误分析模板

每次实验至少保留：

- 失败样本的节点/边/图 ID（脱敏后）；
- 度数、组件、标签频率、特征缺失、邻域同配性等上下文；
- 错误类型假设和一条可检验改进；
- 改进是否在冻结 test 前验证成功。

“模型不够强”不是错误分析；应指出信息缺口或数据协议。

## 6. 最小 manifest 检查

```python
import json
from pathlib import Path

manifest = {
    "seed": 42,
    "seeds": [7, 42, 2026],
    "split": "frozen-node-split-v1",
    "protocol": "transductive",
    "model": "gcn",
}
path = Path("split_manifest.json")
path.write_text(json.dumps(manifest, indent=2), encoding="utf-8")
loaded = json.loads(path.read_text(encoding="utf-8"))
assert loaded["split"] == "frozen-node-split-v1"
assert len(loaded["seeds"]) >= 3
```

作业会用自己的输出目录运行这段检查；不要把绝对路径、隐藏 notebook 状态或未记录的环境变量当作实验协议。

## 7. 报告最低表格

| 模型 | seed 数 | 参数量 | 训练时间 | 验证指标均值±标准差 | 测试指标 | 失败案例 |
|:---|---:|---:|---:|:---|:---:|:---|
| MLP | 3 | 记录 | 记录 | 记录 | 一次 | 至少 1 类 |
| GCN | 3 | 记录 | 记录 | 记录 | 一次 | 至少 1 类 |
| GraphSAGE | 3 | 记录 | 记录 | 记录 | 一次 | 至少 1 类 |
| GAT | 3 | 记录 | 记录 | 记录 | 一次 | 至少 1 类 |

表中“记录”不是结果占位，而是要求运行后填入真实证据。

## 8. 检索练习与通过标准

- 给一个“GCN 更高分”的结果，列出至少三种非模型原因并设计排查顺序。
- 解释为什么只报 test 的最佳 seed 不能算稳定证据。
- 写出一项消融的单一变量、控制变量和预期反证。

通过标准：能从 manifest 复原一次运行；能解释基线公平性；报告包含波动、失败和限制，不删除不利结果。
