> [!NOTE] 核心直觉：社交圈抽样代表制
> **类比**：在大型社交平台调查某个大V群体的影响力时，你不需要访问大V的所有数百万粉丝（这会耗尽人力物力），而是随机抽取20名活跃粉丝作为“代表”。通过这些代表的反馈逐层向上汇总，既能快速得到整体画像，又彻底避免了计算资源崩溃。

## 1. 为什么需要这个知识点？
- **背景**：传统的图卷积神经网络（如全图 GCN）采用 Full-batch 训练，每次前向传播与反向传播都需要将完整图结构的邻接矩阵 $\mathbf{A}$ 和节点特征矩阵 $\mathbf{X}$ 一起放入显存进行计算。
- **痛点**：
  1. **邻居爆炸 (Neighbor Explosion)**：在 $L$ 层 GNN 的消息传递中，目标节点的感受野随着层数增长呈现指数级扩散 $O(d^L)$（其中 $d$ 为平均节点度数）。在社交网络等存在幂律分布（Hub 节点）的图结构中，几层传递就会覆盖整张图。
  2. **显存溢出 (OOM)**：全图计算无法切分为 Mini-batch，导致面对亿级节点与百亿级边的社交网络时，单机 GPU 显存立刻崩塌。
  3. **难以支持动态图与归纳学习**：全图依赖使得新增节点或未见图的推理必须重新对全图进行矩阵乘法。
- **意义**：邻居采样（Neighbor Sampling）彻底解耦了 GNN 的层聚合复杂度与节点的实际度数，将计算节点数约束在固定的常数范围内，使图神经网络具备了 Mini-batch 梯度下降与大规模分布式训练的能力。

## 2. 核心定义与公式/代码
### 采样公式与计算图构建
在 $L$ 层 GNN 模型的第 $l$ 层消息传递中，对于目标节点集合中的任意节点 $v$，邻居采样并不聚合其全量邻居 $\mathcal{N}(v)$，而是从其邻居分布中随机采出固定数量 $S_l$ 的子集：

$$\hat{\mathcal{N}}^{(l)}(v) \sim \text{Sample}\left(\mathcal{N}(v), S_l\right)$$

节点 $v$ 在第 $l$ 层的状态更新公式如下（以 GraphSAGE 聚合为例）：

$$\mathbf{h}_{\mathcal{N}(v)}^{(l)} = \text{AGGREGATE}_l \left( \left\{ \mathbf{h}_u^{(l-1)}, \forall u \in \hat{\mathcal{N}}^{(l)}(v) \right\} \right)$$

$$\mathbf{h}_v^{(l)} = \sigma \left( \mathbf{W}^{(l)} \cdot \left[ \mathbf{h}_v^{(l-1)} \,||\, \mathbf{h}_{\mathcal{N}(v)}^{(l)} \right] \right)$$

其中 $\|$ 表示特征拼接（Concatenation），$S_l$ 为第 $l$ 层的超参数采样容量。单节点在 $L$ 层模型下的采样节点上限为 $\prod_{l=1}^L S_l$。

### PyTorch Geometric (PyG) 代码实现
```python
import torch
import torch.nn.functional as F
from torch_geometric.loader import NeighborLoader
from torch_geometric.nn import SAGEConv

# 1. 构建邻居采样加载器 (Mini-batch Sampler)
# input_nodes: 指定训练目标节点；num_neighbors: 各层邻居采样数（例如 [15, 10] 表示一阶采15个，二阶采10个）
train_loader = NeighborLoader(
    data,
    num_neighbors=[15, 10],
    batch_size=128,
    input_nodes=data.train_mask,
    shuffle=True
)

# 2. 定义基于邻居采样的 GraphSAGE 模型
class NeighborSamplingSAGE(torch.nn.Module):
    def __init__(self, in_channels, hidden_channels, out_channels):
        super().__init__()
        self.conv1 = SAGEConv(in_channels, hidden_channels)
        self.conv2 = SAGEConv(hidden_channels, out_channels)

    def forward(self, x, edge_index):
        x = self.conv1(x, edge_index).relu()
        x = self.conv2(x, edge_index)
        return x

model = NeighborSamplingSAGE(data.num_features, 64, dataset.num_classes)
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)

# 3. Mini-batch 训练循环
for batch in train_loader:
    optimizer.zero_grad()
    # 前向传播：传入采样的子图节点特征与边索引
    out = model(batch.x, batch.edge_index)
    
    # 核心细节：仅对当前 Mini-batch 的前 batch_size 个目标节点计算 Loss
    loss = F.cross_entropy(out[:batch.batch_size], batch.y[:batch.batch_size])
    loss.backward()
    optimizer.step()
```

## 3. 具体应用案例
**场景**：电商/社交平台（如 Pinterest 或 微信公众号推荐）的十亿级节点图嵌入计算。
在 Pinterest 的 PinSage 系统中，图包含 30 亿个节点（Pins 与 Boards）和 180 亿条边。若使用传统 GCN，计算某个拥有几百万收藏量的热门图片（Hub Node）会瞬间占用数十 GB 显存。
PinSage 引入基于随机游走（Random Walk）的重要性邻居采样：通过从目标节点出发模拟随机游走，统计各邻居节点的频次（PageRank score），仅挑选得分最高的 Top-$K$ 个邻居构建局部计算图。这使得单台机器利用普通 GPU 显存即可对数十亿级别的超级图网络完成高性能 Mini-batch 训练。

## 4. 常见误区与陷阱 (Pitfalls)
> [!WARNING] 踩坑预警
> - **混淆子图节点与目标节点（Batch 维度错位）**：`NeighborLoader` 返回的 `batch` 包含了目标节点及其多阶采样邻居（作为计算上下文）。在前向传播计算损失时，**只能取前 `batch.batch_size` 个节点的预测结果与标签计算 Loss**，后面的节点仅用于提供邻居特征。如果对整个子图矩阵计算损失，会导致重复计算与梯度偏置。
> - **误以为均匀采样（Uniform Sampling）对所有图都是最优解**：在严重倾斜的无标度社交网络中，简单均匀采样极易采样到大量无意义的边缘低度节点，带来高方差估计。现代工程中更倾向于采用基于重要性采样（Importance Sampling, FastGCN）或基于层间采样的 LADIES 方法。
