# 频繁子图挖掘

> [!NOTE] 核心直觉：分子基团与社交圈层的“公共拓扑基因”
> **类比**：频繁子图挖掘就像是在成千上万个化学分子中寻找重复出现的“活性基团”（如苯环），或者在海量社交关系网中寻找反复出现的“典型诈骗团伙联络网”。我们不需要分析整张复杂大图的所有局部细节，而是找出那些在图数据集中以超高频率反复出现的固定拓扑形态（Frequent Subgraph Patterns）。

## 1. 为什么需要这个知识点？
- **背景**：在社交网络挖掘、生物信息学（蛋白质与分子结构）、金融交易图谱分析中，图结构数据无处不在。从海量图中识别最具代表性、显著性的局部结构模式是理解图特征与功能的基础。
- **痛点**：由于子图同构测试（Subgraph Isomorphism Test）已被证明是 NP-Complete 问题，对于 $N$ 个节点的图，可能的子图组合数随着节点和边数呈指数级爆炸。若采用简单暴力的枚举与频次统计，搜索空间巨大，算法无法在合理时间内收敛。
- **意义**：频繁子图挖掘（Frequent Subgraph Mining, FSM）利用向下闭合性质（Apriori / Anti-monotonicity Property）建立起强大的搜索树剪枝机制，能够从海量图中高效挖掘出频次大于给定支持度阈值（$min\_sup$）的频繁结构形态，为图分类、图聚类、异常子图检测（风控反洗钱）以及分子药效筛选提供最核心的基元表征（Graph Motifs）。

## 2. 核心定义与公式/代码

### 2.1 形式化定义
1. **图数据集合**：设图数据集为 $\mathcal{G} = \{G_1, G_2, \dots, G_D\}$，其中每个图 $G_i = (V_i, E_i, L_V, L_E)$ 为顶点标号与边标号图。
2. **子图同构 (Subgraph Isomorphism)**：给定模式图 $g = (V_g, E_g)$ 和目标图 $G = (V, E)$，若存在单射映射 $f: V_g \to V$，使得：
   - $\forall u \in V_g, L(u) = L(f(u))$
   - $\forall (u, v) \in E_g, (f(u), f(v)) \in E \text{ 且 } L(u,v) = L(f(u), f(v))$
   则称 $g$ 同构于 $G$ 的子图（记作 $g \subseteq G$）。
3. **支持度 (Support)**：模式图 $g$ 在数据集 $\mathcal{G}$ 中的支持度定义为包含 $g$ 的图的数量：
   $$\text{Supp}(g) = \left| \{ G_i \in \mathcal{G} \mid g \subseteq G_i \} \right|$$
   相对支持度为 $\text{rel\_Supp}(g) = \frac{\text{Supp}(g)}{|\mathcal{G}|}$。
4. **频繁子图 (Frequent Subgraph)**：给定最小支持度阈值 $min\_sup$，若 $\text{Supp}(g) \ge min\_sup$，则称 $g$ 为频繁子图。
5. **向下闭合性质 / 反单调性 (Anti-monotonicity Property)**：
   $$\forall g' \subseteq g \implies \text{Supp}(g') \ge \text{Supp}(g)$$
   *推论*：如果子图 $g'$ 是非频繁的，则任意包含 $g'$ 的父图 $g$ 也必为非频繁的（树剪枝的核心依据）。

### 2.2 核心算法机制：gSpan 算法与 DFS 编码
为了避免枚举同构子图带来的巨大冗余，**gSpan (Graph-based Subgraph Pattern Mining)** 引入了 DFS 码（DFS Code）与规范码（Canonical Labeling）：
- 将子图转化为 DFS 搜索树生成的变长字符串。
- **最右路径扩展 (Rightmost Path Extension)**：仅在 DFS 树的最右路径节点上进行扩展，将搜索空间限制在深度优先树上。
- **规范编码 (Canonical Form)**：按字典序对 DFS 码排序，只保留字典序最小的 DFS 码，直接丢弃非规范扩展，彻底避免了子图重复生成。

```python
import networkx as nx

def check_subgraph_support(pattern, graph_dataset):
    """
    计算给定子图模式 pattern 在图数据集 graph_dataset 中的绝对支持度
    """
    support_count = 0
    for G in graph_dataset:
        # 使用 NetworkX 的 VF2 算法判定子图同构
        matcher = nx.algorithms.isomorphism.GraphMatcher(G, pattern)
        if matcher.subgraph_is_monomorphic():
            support_count += 1
    return support_count

def simple_frequent_edge_miner(graph_dataset, min_support):
    """
    简易频繁单边/单节点子图挖掘示例
    """
    edge_counts = {}
    for G in graph_dataset:
        seen_in_G = set()
        for u, v, data in G.edges(data=True):
            # 获取边与两端节点的特征标号
            u_label = G.nodes[u].get('label', 'node')
            v_label = G.nodes[v].get('label', 'node')
            e_label = data.get('label', 'edge')
            edge_pattern = tuple(sorted([u_label, v_label])) + (e_label,)
            
            if edge_pattern not in seen_in_G:
                seen_in_G.add(edge_pattern)
                edge_counts[edge_pattern] = edge_counts.get(edge_pattern, 0) + 1
                
    # 根据 min_support 筛选频繁边
    frequent_edges = {k: v for k, v in edge_counts.items() if v >= min_support}
    return frequent_edges

# 示例运行
if __name__ == "__main__":
    # 创建示例图数据集
    G1 = nx.Graph()
    G1.add_node(1, label='A'); G1.add_node(2, label='B')
    G1.add_edge(1, 2, label='trans')
    
    G2 = nx.Graph()
    G2.add_node(1, label='A'); G2.add_node(2, label='B'); G2.add_node(3, label='C')
    G2.add_edge(1, 2, label='trans'); G2.add_edge(2, 3, label='trans')
    
    dataset = [G1, G2]
    freq_patterns = simple_frequent_edge_miner(dataset, min_support=2)
    print("挖掘到的频繁单边模式:", freq_patterns)
```

## 3. 具体应用案例
**场景**：**金融反洗钱与团伙诈骗模式挖掘**
- **背景**：黑产团伙在社交网络与资金转账网中具有典型的洗钱拓扑结构，例如“资金分散转出 $\to$ 中转节点聚集 $\to$ 环状多层回流”。
- **做法**：
  1. 将千万人级的交易网络划分为若干连通子图或社区数据集 $\mathcal{G}$。
  2. 设定最小支持度 $min\_sup = 50$（即在过去一个月内至少在 50 个独立异常团伙中复现）。
  3. 执行频繁子图挖掘算法（如 gSpan），自动提取高频出现的拓扑模式 $g_{freq}$。
  4. 将挖掘得到的频繁子图转化为专家规则或图神经网络的局部特征结构（Motif Feature），实现毫秒级的实时团伙欺诈拦截。

## 4. 常见误区与陷阱 (Pitfalls)
> [!WARNING] 踩坑预警
> - **[误区 1：混淆“多图数据集 (Graph-Transaction Setting)”与“单张大图 (Single-Graph Setting)”的支持度定义]**：在多图集合中，支持度指包含子图的图数量；而在单张亿级社交大图中，若允许节点/边重叠计数，支持度将失去反单调性（Anti-monotonicity），必须使用基于最大独立集（MIS）的无重叠匹配计算支持度。
> - **[误区 2：盲目暴力扩展子图而忽略规范化编码（Canonical Form）]**：一个包含 $k$ 条边的子图可能通过 $k!$ 种不同的搜索路径被重复挖掘出来。若未采用 gSpan 的最右路径拓展与最小 DFS 码字典序判重，会导致算法计算时间呈数千倍增长而崩溃。
