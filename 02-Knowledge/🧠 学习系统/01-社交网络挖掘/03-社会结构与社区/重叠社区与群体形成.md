# 重叠社区与群体形成

## 0. 学习边界

- **类别**：A 类社会结构补全。
- **判断理由**：一个人可以同时属于家庭、实验室和兴趣群；强制每个节点只属于一个社区会丢失桥接身份和群体演化信息。

## 1. 这个知识点解决什么问题？

> 当节点允许多重归属时，怎样表示社区、怎样从局部团结构发现重叠群体，并区分“发现群体”和“预测谁会加入群体”？

## 2. 为什么它重要？它有什么用？

- 解释跨圈层用户、跨学科作者和多功能蛋白。
- 支持群体推荐、成员流失/加入预测和社区演化分析。
- 揭示硬划分指标的边界：高模块度分区不必等于真实多重身份。

## 3. 学它之前需要哪些前置知识？

1. [[社区发现-模块度与谱松弛]]：理解硬划分、模块度与谱二分。
2. [[三元闭包弱关系与同质性]]：群体形成既受结构机会也受属性选择影响。
3. [[网络演化-致密化收缩直径与Kronecker机制]]：群体成员和边会随时间变化。

## 4. 用直觉语言解释它

> 硬划分像要求每个人只能选一个微信群；重叠社区允许同一人出现在多个群，而团渗流通过“高度重叠的小团体”把局部关系串成群体。

## 5. 正式定义、核心公式、符号解释

### 1. Partition 与 cover

- **硬划分** $\mathcal P=\{C_1,\ldots,C_k\}$：$C_i\cap C_j=\varnothing$，且并集为 $V$。
- **重叠 cover** $\mathcal C=\{C_1,\ldots,C_k\}$：允许 $C_i\cap C_j\ne\varnothing$；节点也可暂时不属于任何群。

成员矩阵 $M\in\{0,1\}^{|V|\times k}$ 中，$M_{vc}=1$ 表示节点 $v$ 属于社区 $c$；一行可有多个 1。

### 2. $k$-clique percolation

- $k$-clique：含 $k$ 个节点的完全子图。
- 两个 $k$-clique 若共享 $k-1$ 个节点，则相邻。
- 以 $k$-clique 为节点建立“团图”，其每个连通分量对应一个社区；原图节点可出现在多个分量中，因此允许重叠。

### 3. 群体形成与演化

群体任务至少分三类：

1. **发现**：给定图，输出社区 cover。
2. **成员预测**：给定群体与候选节点，估计加入概率。
3. **演化匹配**：在相邻快照中判断群体延续、分裂、合并、诞生或消失。

快照间群体相似度可用 Jaccard：

$$
J(A,B)=\frac{|A\cap B|}{|A\cup B|},
$$

但匹配阈值和一对一/多对多策略会改变“分裂/合并”结论。

## 6. 推导思路和证据链

1. 先判断任务是否允许多重身份；若真实标签重叠，硬划分天然错配。
2. 选择局部密度定义，例如 $k$-clique，而不是先运行算法再解释。
3. 构造团图并取连通分量，得到社区 cover。
4. 在人工小图验证每个 $k$-clique、相邻关系和重叠节点。
5. 对时间快照，冻结节点身份与群体匹配规则，再报告成员变化。
6. 用结构、属性和时间三类基线比较成员预测，避免把“已加入后形成的边”泄漏进特征。

## 7. 例子：手算 → 参数影响 → 可运行代码

### 例子 1：两个重叠三角形

三角形 $\{a,b,c\}$ 与 $\{c,d,e\}$ 只共享节点 $c$。当 $k=3$ 时，它们没有共享 $k-1=2$ 个节点，因此属于两个团渗流社区；节点 $c$ 同时属于二者，形成重叠。

### 例子 2：参数影响

- $k$ 小：社区更大、可能把弱连接群体合并。
- $k$ 大：要求更密，可能只剩少量核心或没有社区。
- 不能用“得到最好看的图”选 $k$；应按任务、稳定性或外部标签预先定义选择规则。

### 例子 3：可运行最小验证

```python
import networkx as nx

graph = nx.Graph()
graph.add_edges_from([
    ("a", "b"), ("b", "c"), ("a", "c"),
    ("c", "d"), ("d", "e"), ("c", "e"),
])
communities = [set(group) for group in nx.community.k_clique_communities(graph, 3)]
assert {"a", "b", "c"} in communities
assert {"c", "d", "e"} in communities
assert sum("c" in group for group in communities) == 2
print(communities)
```

- **依赖**：`networkx>=3.2`。
- **输入**：无向简单图与预声明的 $k$。
- **输出**：社区 cover、每节点成员数；真实任务还需参数稳定性和外部/内部评价。

## 8. 常见误区和概念对比

- **社区重叠等于边重叠**：重叠指节点可有多个社区身份。
- **最大团等于团渗流社区**：社区可由多个相邻 $k$-clique 合并而成。
- **用最终图预测历史加入**：会泄漏加入后才形成的边。
- **忽略枚举成本**：最大团数量在某些图上可爆炸，需报告规模与计算预算。

| 概念 | 输出 | 适用边界 |
| :--- | :--- | :--- |
| 模块度硬划分 | 每节点一个社区 | 互斥群体或需要简洁分区 |
| 团渗流 | 重叠 cover | 局部高密、可解释团结构 |
| 成员预测 | 候选加入分数 | 需要时间切分和无泄漏特征 |
| 群体演化 | 分裂/合并/延续事件 | 需要稳定身份和匹配规则 |

## 11. 自测题：5 道

1. cover 是否要求社区两两不交？ #自测题/基础
   > [!question]- 不要求；同一节点可属于多个社区。
2. 两个 4-clique 至少共享几个节点才相邻？ #自测题/基础
   > [!question]- 3 个，即 $k-1$ 个。
3. 增大 $k$ 一定提高质量吗？ #自测题/中等
   > [!question]- 不一定；它提高密度要求，也可能碎裂真实群体或输出为空。
4. 为什么最终图不能直接做历史成员预测特征？ #自测题/中等
   > [!question]- 最终图包含加入后形成的关系，会把未来信息泄漏到训练/测试。
5. 怎样验证群体演化结论不是匹配阈值产物？ #自测题/较难
   > [!question]- 预声明匹配规则，并对多个合理阈值/匹配策略做敏感性分析。
