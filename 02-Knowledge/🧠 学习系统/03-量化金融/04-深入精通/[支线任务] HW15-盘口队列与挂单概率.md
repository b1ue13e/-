# HW15-盘口队列与挂单概率作业说明书 实战实验手册

---

## 0. 先判断它值不值得深挖
- **类别**：A 类核心实战任务。
- **理由**：在量化交易尤其是高频交易与做市策略中，订单能否成交直接决定了策略的盈亏。掌握盘口队列位置的估算和挂单成交概率的模型，是实现精准订单执行 (Execution) 的绝对基石。

---

## 1. 这个实战作业解决什么问题？
> **我们遇到了什么麻烦？**

当我们向交易所提交限价单 (Limit Order) 时，订单不会立刻成交，而是排在同一价格层级的队列末尾。如果不知道当前我们的订单在队列中的确切位置，我们就无法评估该订单在未来一段时间内被吃单 (Market Order) 击中并成交的概率。传统的“只要价格到了就能成交”的假设在真实回测中会产生严重的“回测乐观偏差”（Look-ahead Bias/Fill Assumption），导致实盘表现远逊于回测。本实验旨在教你如何通过逐笔数据或快照数据重构/估算队列，并计算挂单成交概率。

---

## 2. 为什么它重要？工程与业务价值在哪？
- **大图景位置**：位于微观结构分析与算法交易（如 TWAP, VWAP, 做市策略）的连接处。是连接“理想交易信号”与“真实账户盈亏”的桥梁。
- **实际应用**：做市商需要计算双边挂单的成交概率来调整 Quote 价格；高频策略需要根据队列长度判断是继续排队还是撤单重挂（Cancel and Replace）。
- **工程挑战**：处理海量 Level-2/Level-3 数据，追踪订单状态，并在极低延迟下计算概率分布。

## 4. 用直觉语言解释它
«“排队买限量版球鞋”»

你可以把挂限价单想象成在店门口排队买限量版球鞋。
- 价格层级就是不同的队伍。出价高的人（排在前面的队伍）先买到。
- 同一个队伍里，先来的人排在前面（时间优先）。
- 如果你排在队伍末尾，你能不能买到取决于两个因素：1. 前面的人有没有放弃排队（撤单）；2. 店里还会放出多少双鞋（后续的市价单成交量）。
**直觉本质**：估算前方阻碍（排队人数减去撤单人数）与消耗动力（市价交易量）的赛跑，从而得出成交的数学期望。

## 5. 核心架构与模型定义 (架构与Specs)

### 队列位置模型
设价格为 $P$ 的层级上，你下单时刻的总挂单量为 $V_{initial}$。你的初始队列位置 $Q_0 = V_{initial}$。
随着时间 $t$ 推移，前方位置 $Q_t$ 的更新逻辑为：
$$
Q_t = \max(Q_{t-1} - M_t - C_t, 0)
$$

### 符号解释表
| 符号 | 含义 | 业务场景 | 备注 |
|---|---|---|---|
| $Q_t$ | 你的订单在 $t$ 时刻前方排队量 | 队列位置 | 为 0 时你的订单开始成交 |
| $M_t$ | $t$ 时刻该价位发生的市价成交量 | 吃单量 | 消耗前方队列的主力 |
| $C_t$ | $t$ 时刻前方队列发生的撤单量 | 前方撤单 | Level-2 下需按比例估算，Level-3 可精确追踪 |
| $p_{fill}$ | 挂单成交概率 | 订单执行 | 依赖 $Q_t$ 与该价位流动性深度的比值 |

## 6. 实现逻辑与算法伪代码
### 估算逻辑（以 Level-2 快照数据为例）
由于 Level-2 不提供每个订单的 ID 追踪，我们需要估算前方撤单量 $C_t$。
假设撤单是均匀分布的，前方撤单量与整体撤单量成正比。

```python
# 伪代码：队列位置更新步进函数
def update_queue_position(Q_prev, V_prev, V_curr, M_curr):
    """
    Q_prev: 上一时刻你的前方队列量
    V_prev: 上一时刻该价位总挂单量
    V_curr: 当前时刻该价位总挂单量
    M_curr: 两时刻间的市价成交量
    """
    # 估算该价位总撤单量 (或者新增挂单量，这里简化为净变化)
    delta_V = V_curr - V_prev + M_curr
    
    if delta_V < 0:
        # 发生了净撤单，假设撤单在队列中均匀分布
        C_front = abs(delta_V) * (Q_prev / V_prev)
    else:
        # 只有新增挂单，排在我们后面，前方不撤单
        C_front = 0
        
    Q_curr = max(Q_prev - M_curr - C_front, 0)
    return Q_curr
```

## 7. 实战例子：基础 → 中等 → 实际应用

### 例子 1：基础手工推演（理想情况）
- **场景**：你在买一价（10.00元）挂单 100 手，下单时该价位已有 500 手。你的初始 $Q_0 = 500$。
- **动作**：下一秒，发生了一笔 200 手的市价卖单（主动砸盘），且无任何人撤单。
- **计算**：$Q_1 = 500 - 200 - 0 = 300$。
- **结果**：你还要等 300 手被吃掉才能成交。

### 例子 2：中等难度（引入撤单估算）
- **场景**：初始 $Q_0 = 500$, $V_0 = 1000$（你在队列正中间）。
- **动作**：下一秒，盘口总量变为 $V_1 = 800$，期间没有市价成交（$M_1 = 0$）。
- **计算**：总撤单量为 $1000 - 800 = 200$。由于你在正中间，假设均匀撤单，你前方的撤单 $C_1 = 200 \times (500/1000) = 100$。
- **结果**：$Q_1 = 500 - 0 - 100 = 400$。你的前方还有 400 手。

### 例子 3：量化工业应用 (微观状态机追踪)
- **实际场景**：使用交易所 Level-3 逐笔数据（Tick Data）。在 C++ 高频交易系统中，维护一个 OrderBook 状态机。每次收到 OrderAdd, OrderDelete, OrderExecute 消息时，精确更新自己的 OrderID 前方的累计 Volume。结合泊松强度模型，实时计算在 500 毫秒内被吃单的概率 $p(fill|\text{QueuePos, OrderFlow})$，如果概率 $< 10\%$，触发 Cancel 并调整价格。

## 8. 常见坑点与排错指南

- **坑点 1：回测时直接假设价格穿透即成交**
  - **现象**：只要最低价 $\le$ 挂单价，回测框架就认为你的挂单 100% 成交。
  - **后果**：严重高估策略收益，实盘由于排队靠后根本无法成交。**必须引入撮合排队逻辑！**
- **坑点 2：忽略隐藏订单 (Iceberg Orders)**
  - **现象**：前方队列似乎很短，但市价单砸下去却消耗不完。
  - **原因**：部分市场允许冰山订单，未显示部分会优先于你新挂的单成交。
- **坑点 3：Level-2 撤单估算的线性假设失效**
  - **现象**：估算的 $Q_t$ 经常变为负数。
  - **原因**：撤单并非均匀分布，通常挂在最前面的往往是做市商，撤单频率极高。工程上常需用历史数据拟合非线性的撤单分布系数。

## 11. 单元自测题 (Self-test)

> [!question]- 1. 概念理解 (基础)
> **题目**：中国A股市场的撮合原则主要是什么？
> A. 价格优先，数量优先
> B. 价格优先，时间优先
> C. 时间优先，数量优先
> 
> **答案解析**：答案为 **B**。在价格相同的情况下，谁先下单谁排在前面。这就是为什么要研究盘口队列位置的原因。

> [!question]- 2. 状态更新 (基础)
> **题目**：你在卖一价挂单，前方有 200 手排队。此时发生了一笔主动买单 150 手吃掉了卖一价。假设没有撤单，你前方还剩多少手？
> 
> **答案解析**：还剩 $200 - 150 = 50$ 手。

> [!question]- 3. 撤单估算 (中等)
> **题目**：你的前方有 300 手，总队列有 1000 手。下一时刻无市价成交，总队列减少了 200 手。假设均匀撤单，你的前方队列变为多少？
> 
> **答案解析**：你的位置在前 30%，撤单在前方发生的概率为 0.3。前方撤单量 = $200 \times 0.3 = 60$ 手。你的前方剩余 = $300 - 60 = 240$ 手。

> [!question]- 4. 回测偏差 (中等)
> **题目**：什么是“回测乐观偏差”在限价单上的体现？
> 
> **答案解析**：当真实市场价格刚触及限价单价格立刻反弹时，由于限价单排在队列后方，实盘未能成交，但简单的回测引擎会误判为完全成交，导致策略收益被高估。

> [!question]- 5. 工程应用 (较难)
> **题目**：在设计针对大单拆分的 TWAP 执行算法时，如何利用成交概率模型？
> 
> **答案解析**：TWAP 需要在限定时间内完成子单。可以基于订单簿深度和历史成交率，利用此模型计算当前挂单在 1 分钟内的成交概率。如果概率过低，算法应主动撤单，改为跨价位挂单或直接发市价单以确保执行进度。
