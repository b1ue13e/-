## 0. 优先级与价值评估
- **优先级**：A 类核心实战。
- **理由**：Almgren-Chriss (AC) 模型是算法交易（Algorithmic Trading）中最经典的基石框架。本作业贯穿了从数学推导（均值-方差优化）到工程落地（轨迹离散化与回测代码实现）的全流程，是进入高频与量化交易岗位的必考底座。

---

## 1. 我们遇到了什么麻烦？
> **核心痛点：大单卖不出去，且越卖越亏。**

在真实市场中，如果你手握 100 万股需要清仓（或建仓），直接下市价单会瞬间砸穿买盘（产生巨大的**市场冲击成本**，滑点极高）。
如果为了不砸盘，你把订单切得极碎，拖到好几天去卖，虽然没有冲击了，但期间市场可能暴跌，你承担了极大的**库存风险（价格波动风险）**。
我们面临的麻烦是：**如何在“立即卖出的高冲击成本”和“缓慢卖出的高风险”之间，找到一条数学上最优的拆单执行轨迹（Trading Trajectory）？**

---

## 2. 为什么它重要？大图景位置
- **工业界地位**：它是各大券商和对冲基金内部算法交易引擎（如 TWAP/VWAP 改进版）的核心数学引擎。所有的 Smart Execution（智能执行）算法几乎都以 AC 模型或其变种作为基础基准（Baseline）。
- **工程价值**：通过本作业，你将彻底掌握如何将连续时间的偏微分方程/变分法问题，转化为离散时间的动态规划或矩阵求解问题，并最终用 Python 面向对象（OOP）实现。

## 3. 实战前置知识
### 最小必要背景 (200 字以内)
1. **金融学概念**：理解执行落差（Implementation Shortfall, IS），即纸面收益与实际成交收益的差值。
2. **市场冲击**：
   - 临时冲击（Temporary Impact）：你一卖价格就跌，你停止卖价格立刻恢复。
   - 永久冲击（Permanent Impact）：你卖出导致市场均衡价格发生了不可逆的下降。
3. **数学基础**：均值-方差优化（Mean-Variance Optimization）、双曲函数（$\sinh, \cosh$）、基础的欧拉离散化。

## 4. 用直觉语言解释它
«“这东西其实就像……”»

**直觉类比：在小镇集市上卖大象。**
如果你直接把一头大象牵到集市上卖（单次抛售），大家会被吓到，大象肉的价格会瞬间暴跌（市场冲击）。
为了卖个好价钱，你决定把大象切成小块，每小时卖一点。这样价格不会跌，但问题是，如果卖得太慢，肉可能会变质，或者下午集市就关门了（库存风险与时间风险）。
**AC 模型就是那个精准的“切肉时间表”**，它根据你的“风险厌恶程度”（你有多怕肉坏掉），计算出每个时间点最完美的出货量。

**一句话本质**：在最小化市场冲击成本和最小化价格波动风险之间，求取效用最大化的最优交易路径。

## 5. 核心架构、公式与变量表

### 目标函数（均值-方差效用）
我们需要最小化执行落差（IS）的期望，加上风险厌恶惩罚项：
$$
\min_{n_1, ..., n_T} \mathbb{E}[IS] + \lambda \mathbb{V}ar[IS]
$$

### AC 模型离散化解析解（代码实现核心）
对于离散时间步 $t_k = k \tau$，最优持仓轨迹 $x_k$ （剩余未卖出的股数）公式为：
$$
x_k = X \frac{\sinh(\kappa(T - t_k))}{\sinh(\kappa T)}
$$
最优每期交易量 $n_k$（你要下到交易所的订单量）：
$$
n_k = x_{k-1} - x_k
$$

### 核心参数与符号表
| 变量/符号 | 代码命名建议 | 物理含义 | 数据类型/量纲 |
|---|---|---|---|
| $X$ | `total_shares` | 初始总需交易股数 | 整数 (Shares) |
| $T$ | `total_time` | 总交易时间（如 1 天） | 浮点数 (Days/Hours) |
| $\tau$ | `tau` | 离散化时间步长（如 5 分钟） | 浮点数 |
| $\lambda$ | `risk_aversion` | 风险厌恶系数 | 浮点数，越大越怕风险 |
| $\sigma$ | `volatility` | 资产价格波动率 | 浮点数 |
| $\eta$ | `temp_impact` | 临时冲击系数 | 浮点数 |
| $\kappa$ | `kappa` | 综合缩放因子，$\kappa = \sqrt{\frac{\lambda \sigma^2}{\eta}}$ | 浮点数（控制轨迹曲率） |

## 6. 代码架构设计与实现动机
### 架构动机
在实战作业中，我们不能只写一个脚本算算公式，必须将其封装为一个可复用的**交易引擎组件**。
架构上采用 OOP 面向对象设计：
1. `MarketEnvironment` 类：负责提供 $\sigma, \eta$ 以及模拟生成带冲击的真实价格序列。
2. `AlmgrenChrissSolver` 类：输入初始条件，计算并输出连续时间与离散时间的轨迹 $\{n_k\}$ 和 $\{x_k\}$。
3. `BacktestEngine` 类：拿着 $\{n_k\}$ 去市场环境中“执行”，计算真实的 IS、滑点和成本，并与 TWAP 对比。

## 7. 实战例子：基础 → 进阶 → 工业应用

### 例子 1：基础手工核算（Test Case 基准）
- **场景**：总头寸 $X=100$，分 2 个时间步 $T=2$ 卖完。不考虑风险厌恶（$\lambda = 0$）。
- **推演**：当 $\lambda \to 0$ 时，$\kappa \to 0$，$\frac{\sinh(\kappa(T-t))}{\sinh(\kappa T)}$ 趋近于线性比例 $\frac{T-t}{T}$。
- **结果**：$n_1 = 50, n_2 = 50$。
- **结论**：**极度风险偏好（$\lambda=0$）的 AC 模型自动退化为 TWAP（时间加权平均价格）策略。** 这是你写单元测试的第一个 Assert。

### 例子 2：核心代码片段（Medium）
求解轨迹的 Python 实现（注意处理 $\sinh$ 溢出的边界情况）：
```python
import numpy as np

def calculate_ac_trajectory(X, T, N_steps, risk_aversion, sigma, eta):
    tau = T / N_steps
    # 防止分母除零
    if risk_aversion == 0 or sigma == 0:
        return np.full(N_steps, X / N_steps) # 退化为 TWAP
        
    kappa = np.sqrt((risk_aversion * (sigma ** 2)) / eta)
    
    t_k = np.linspace(0, T, N_steps + 1)
    x_k = X * np.sinh(kappa * (T - t_k)) / np.sinh(kappa * T)
    
    # 交易量 = 前一刻持仓 - 当前刻持仓
    n_k = -np.diff(x_k) 
    return n_k, x_k
```

### 例子 3：量化基金真实回测 (Real-world)
- **应用**：要交易 1 亿股苹果股票（AAPL）。调用求解器得到 $n_k$ 后，发现前 10 分钟交易量巨大（因为害怕后面的波动）。
- **工程结合**：在实际订单簿（Limit Order Book, LOB）中，前 10 分钟如果硬吃流动性，临时冲击 $\eta$ 是非线性的。因此通常会将 AC 算出的 $n_k$ 作为目标，再交给底层的强化学习微观执行体（Micro-execution agent）去通过被动限价单（Limit Orders）完成具体的买卖。

## 8. 常见踩坑与 Debug 指南 (Pitfalls)

1. **坑点 1：把时间单位搞混。** 波动率 $\sigma$ 通常是年化的，而 $T$ 可能是按天/小时计算的。
   - *解法*：必须在传入 `Solver` 前，将 $\sigma, T, \tau$ 统一到同一时间维度（比如全换算成 Trading Days）。
2. **坑点 2：双曲正弦函数 (sinh) 溢出。** 当 $\kappa$ 或 $T$ 极大时（比如时间步切得极细），$\sinh(x) \approx \frac{e^x}{2}$ 会发生浮点数溢出 (Overflow)。
   - *解法*：使用指数形式进行对数转化，或者在代码中加入 `np.clip` 或引入大数近似优化。
3. **坑点 3：忽略了最后一期的清仓要求。** 数值计算的截断误差可能导致最后一期 $x_N \neq 0$，即没卖完。
   - *解法*：强制最后一笔订单 $n_N = x_{N-1}$，兜底清零。

## 11. 实战自测题 (Self-test)

> [!question]- 1. 基础概念测试
> **问题**：在 AC 模型中，如果我们认为市场非常平稳（波动率 $\sigma \to 0$），最优轨迹会变成什么形状？
> **答案解析**：当波动率接近 0，风险厌恶项的影响消失，模型退化为纯粹最小化冲击成本。为了最小化冲击，系统会绝对平均地把订单分散到每一刻。轨迹会变成一条完美的直线，即退化为 TWAP 策略。

> [!question]- 2. 代码实现边界条件
> **问题**：如果你的代码算出某一个时间步的订单量 $n_k < 0$（要求买入），这是什么原因导致的？
> **答案解析**：标准的经典 AC 模型解析解是单调递减的，不可能出现反向交易（买入）。如果代码中出现 $n_k < 0$，一定是离散化差分运算出现截断误差，或者在使用非线性冲击模型进行数值求解（如牛顿法）时未能收敛。

> [!question]- 3. 架构设计探讨
> **问题**：在面向对象设计中，临时冲击函数 $h(v)$ 应该作为方法写在 `Solver` 类中，还是 `Environment` 类中？为什么？
> **答案解析**：应写在 `Environment` 类中。Solver 只是求解器，它只需要知道市场参数（或者接口传入即可）；而市场冲击是市场本身的物理属性，属于环境的回馈机制。这种解耦方便未来把冲击函数换成更复杂的非线性函数，而不用动求解器的核心代码。

> [!question]- 4. 参数敏感性分析
> **问题**：如果我们在执行到一半时（$t = T/2$），突然发现市场波动率 $\sigma$ 飙升了 3 倍，在动态 AC 模型中，接下来的轨迹会怎么变？
> **答案解析**：波动率飙升代表风险大幅增加。模型会变得极度急躁，它会倾向于承受更大的瞬间市场冲击，以求尽快把手里的头寸清空。因此后续轨迹会呈现陡峭的悬崖式下降（加速平仓）。

> [!question]- 5. 高级推导拓展
> **问题**：标准 AC 假设永久冲击是线性的。如果引入“非线性”的临时冲击 $\eta v^\beta$（其中 $0 < \beta < 1$），还能得到漂亮的解析解吗？应该怎么用代码求解？
> **答案解析**：无法得到简单的双曲函数解析解。由于方程变为非线性，需要将其转化为离散的数值优化问题，使用 `scipy.optimize.minimize`，或者使用动态规划（Dynamic Programming）倒推求解，甚至使用深度强化学习 (RL)。
