# 交易成本

> **K09 目标**：不靠阅读完成度，而是通过定义、边界、反例和可运行断言证明掌握。

## 0. 先测再学

闭卷写出 交易成本 的输入、输出、成立条件和一个失败案例。若无法写清，先完成本页示例，不并行开启下一个 K 点。

## 1. 定义、机制、假设与边界

交易成本的定义至少拆为显式费用、买卖价差、滑点、冲击和机会成本。机制上，费率通常作用于成交名义金额，方向和最低收费可能不对称；组合净收益应由毛收益扣除与实际换手相容的成本。假设固定费率只能作为基线，不代表真实大单执行。反例是训练策略时忽略成本、最后仅从累计收益减一个常数。验证应逐笔核对买卖方向、成交额、费率与净值。

## 2. Worked example

```python
trades = [(1000, 0.0005), (-600, 0.0010)]
cost = sum(abs(notional) * rate for notional, rate in trades)
assert abs(cost - 1.1) < 1e-12
gross = 10.0
assert gross - cost < gross
```

运行后必须保存输入、期望输出和实际输出。代码可执行只证明局部定义一致，不证明策略在样本外有效。

## 成本分解：可见费用、价差、冲击和机会成本必须分开

**交易成本**至少包含佣金税费、买卖价差、滑点/市场冲击以及未成交造成的机会成本。机制上，前两项多近似线性，冲击随订单规模和参与率非线性上升，机会成本又与限价和等待时间相关；把所有成本压成固定 10bp 会错误奖励高换手和低容量信号。复现实验应按订单逐笔保存 arrival price、成交价、数量与未成交量，验证四项相加等于 implementation shortfall。

失效边界是用收盘价信号却仍假设收盘价成交，或用全日成交量估计盘中参与率。**交易成本**的通过标准是成本参数只从训练期或公开费率获得，结果至少覆盖低/中/高三档冲击情景，并报告成本翻倍时策略结论是否反转。

<!-- quant-route-reasoning-v4 -->
### 定义—推导—对比复核

**交易成本** 的定义必须能落到数据列和时点，而不能只停留在术语。从决策价到最终持仓价值逐项推导 implementation shortfall，并对比显性费用、价差、冲击和机会成本的不同规模律。因此，对 **交易成本** 的误区检查要同时保留正例、破坏条件后的反例和样本外结果；只要三者不能形成同一因果链，就暂不判定掌握。
