# 特征工程-量化应用

量化特征工程首先是时间协议问题，其次才是公式数量。Alpha158 可按价格位置、收益/动量、成交量、波动和横截面变换理解，无需逐个背公式。

## 五项审计

对每个特征记录：原始字段、窗口、复权/缩放、缺失规则、最早可得时间。任何使用 t 日完整 OHLCV 的特征，都必须在数据完成后形成并按预设时点执行。

高维特征集还需避免：全样本标准化、测试期筛选、重复特征叙事和因子方向事后修改。

## K18 最小作业与闸门

从 Alpha158 抽 5 个不同类别特征，写出字段、窗口和可得时间，并用小样本验证一个公式。通过要求：不复制 158 个公式冒充理解，每个特征都能回答“何时可交易”。

## K18 来源、边界与独立复核

### 定义、假设、机制与边界

特征工程-量化应用的定义是把历史可见原始字段转成稳定、可审计的模型输入。窗口收益、波动、量价关系和横截面排名都必须记录字段、运算符、窗口和最早可得时间。机制上同一表达式在 Qlib DataHandler 中还会经过处理器与数据切片。假设表达式只引用过去并不足够，全样本拟合的处理器仍可泄漏。反例是背诵 Alpha158 名称却说不清其中任意五个特征。验证应抽样追踪表达式到原始行。

### 可定位来源

1. Microsoft Qlib Data Layer, Section Expression Engine: https://qlib.readthedocs.io/en/stable/component/data.html
2. Qlib official repository, Alpha158 handler configuration: https://github.com/microsoft/qlib/tree/main/qlib/contrib/data
3. scikit-learn Common pitfalls, Section preprocessing leakage: https://scikit-learn.org/stable/common_pitfalls.html

### 可复现示例与验证

```python
close = [10.0, 10.5, 10.2]
ret_1 = [None] + [close[i] / close[i-1] - 1 for i in range(1, len(close))]
assert ret_1[0] is None
assert abs(ret_1[-1] - (10.2 / 10.5 - 1)) < 1e-12
```

该最小实验只验证 K18 的定义、符号或时间边界，不等价于策略有效。正式结论还必须保存输入版本、期望输出、实际结果和失败案例。

## 特征契约：公式、经济含义与可得时点缺一不可

**特征工程—量化应用**应为每个特征登记输入字段、窗口、滞后、缺失处理、`available_at` 和预期符号。机制上，收益率、波动率、成交量异常和基本面比率只有在可得时点正确且截面口径一致时才具有可比较性；同一公式在停牌、涨跌停和财报披露日附近可能代表不同机制。复现实验应删除未来原始数据后重算，断言历史特征不变，并对极端输入验证单位与符号。

反例是全样本 winsorize 后再切分，或按报告期直接连接财务指标。**特征工程—量化应用**的验收要求还包括消融：逐类删除价格、流动性或基本面特征，确认样本外增量与经济解释一致；无法说明来源与时点的特征即使 IC 高也不得进入主模型。

<!-- quant-route-reasoning-v4 -->
### 定义—推导—对比复核

**特征工程-量化应用** 的定义必须能落到数据列和时点，而不能只停留在术语。从原始字段的可得时点推导特征信息集，并对比同一公式在公告日、停牌日与普通交易日的不同经济含义。因此，对 **特征工程-量化应用** 的误区检查要同时保留正例、破坏条件后的反例和样本外结果；只要三者不能形成同一因果链，就暂不判定掌握。

检索锚点统一写作“特征工程量化应用”：特征工程量化应用强调金融数据的时间可得性，不等同于通用机器学习里的任意变量变换。
