# 量化预测

模型输出可能是收益预测、分类概率或仅有排序意义的分数。预测分数本身不是持仓：必须经过横截面排序、选股、权重、约束、调仓频率和执行规则才形成交易。

## 三层分离

1. `prediction`：每个资产—日期的分数。
2. `portfolio rule`：如何从分数变成目标权重。
3. `execution/backtest`：何时、以什么成本成交。

把三层写在一个函数里会难以公平比较 E1/E2，也难以发现前视和成本错误。

## K21 最小作业与闸门

保存预测产物，抽查 5 个日期的股票数、缺失、排序和极端值。通过要求：分数与组合规则分离；同一规则可同时接受 E1/E2；执行时间晚于预测可得时间。

## K21 来源、边界与独立复核

### 定义、假设、机制与边界

量化预测的定义是为每个资产—时点生成可保存的分数、概率或条件收益估计。预测层、组合层和执行层必须解耦，因为相同分数可对应完全不同的权重与成本。假设预测分数排序稳定不等于可盈利，容量、换手和基准会改变结果。反例是把模型输出的 score 直接称为收益率。验证要检查 MultiIndex 唯一、缺失比例、每日期排序，并让 E1/E2 共用同一组合规则。

### 可复现示例与验证

```python
pred = {("A", 1): 0.3, ("B", 1): -0.1, ("A", 2): 0.2}
assert len(pred) == len(set(pred))
day1 = {k:v for k,v in pred.items() if k[1] == 1}
ranking = sorted(day1, key=day1.get, reverse=True)
assert ranking[0][0] == "A" 
```

该最小实验只验证 K21 的定义、符号或时间边界，不等价于策略有效。正式结论还必须保存输入版本、期望输出、实际结果和失败案例。

## 从预测到决策：损失函数必须对应组合真正关心的错误

**量化预测**不是追求最低随机切分 MSE，而是估计部署时可用、能改善决策的条件信息。方向策略可能更关心 Rank IC 和排序稳定，风险模型关心尾部与校准，执行模型关心条件成交成本；标签、损失函数和验收指标必须一致。机制上，即使预测误差略降，只要增量集中在无法交易的微盘股或引发过高换手，组合效用仍可能下降。

反例是用价格水平而非收益作标签后得到极高 $R^2$，或把同一天股票随机分到训练和测试。**量化预测**的最小实验应采用扩展窗口与滚动窗口两种 walk-forward 方案，对比朴素零预测、线性基线和目标模型，并在成本后检验预测增量是否跨时期、跨行业保持同方向。
