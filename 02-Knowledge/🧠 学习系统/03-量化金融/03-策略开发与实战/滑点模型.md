# 滑点模型

> **K27 目标**：不靠阅读完成度，而是通过定义、边界、反例和可运行断言证明掌握。

## 0. 先测再学

## 1. 定义、机制、假设与边界

滑点模型的定义是订单决策价与实际可成交价之间的差异模型，应与方向、规模、流动性和延迟关联。固定基点、半价差和冲击函数是不同复杂度的假设，不可混称真实成交。机制上买单通常抬高成交价、卖单压低成交价，因此符号测试很重要。反例是成本上升后净收益反而系统性提高且没有再平衡解释。验证要做低中高三档压力表并保持其他配置不变。

## 2. Worked example

```python
mid, bps = 100.0, 10
buy_fill = mid * (1 + bps / 10000)
sell_fill = mid * (1 - bps / 10000)
assert buy_fill > mid > sell_fill
assert abs(buy_fill - 100.1) < 1e-12
```

运行后必须保存输入、期望输出和实际输出。代码可执行只证明局部定义一致，不证明策略在样本外有效。

## 成交约束：滑点是条件分布，不是任意扣减常数

**滑点模型**应以订单方向、规模、盘口深度、波动率和延迟为条件预测成交价格偏离。最简单基线可用半个买卖价差，进一步模型再加入参与率与平方根冲击；无论复杂度如何，都必须遵守买单价格通常不优于同时刻可成交卖价、卖单反之。复现实验要在零价差、薄盘口和跳空三种场景中验证符号、上界与随规模单调增加的性质。

反例是所有订单统一减去 5bp，导致买卖方向相同或大单成本不变。**滑点模型**只有在时间戳对齐、行情可得、部分成交和剩余量处理明确时才通过；报告同时给出无滑点、基准滑点和压力滑点，避免一个不可识别参数决定全部结论。

### 定义—推导—对比复核

**滑点模型** 的定义必须能落到数据列和时点，而不能只停留在术语。从可成交盘口而非中间价定义成交基准，再对比固定基点与参与率冲击模型，从而暴露大单和薄盘口的非线性成本。因此，对 **滑点模型** 的误区检查要同时保留正例、破坏条件后的反例和样本外结果；只要三者不能形成同一因果链，就暂不判定掌握。
