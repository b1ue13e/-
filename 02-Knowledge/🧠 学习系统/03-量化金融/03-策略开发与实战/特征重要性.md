# 特征重要性

> **K22 目标**：不靠阅读完成度，而是通过定义、边界、反例和可运行断言证明掌握。

## 0. 先测再学

闭卷写出 特征重要性 的输入、输出、成立条件和一个失败案例。若无法写清，先完成本页示例，不并行开启下一个 K 点。

## 1. 定义、机制、假设与边界

特征重要性的定义依赖模型、数据集和评分函数，不是特征的永久属性。树分裂重要性可能偏爱高基数变量；置换重要性测量打乱某列后验证性能的下降，但相关特征会互相替代。成立条件是模型本身具有样本外预测力。反例是在训练集上解释过拟合模型并宣布因果关系。验证应在冻结验证集重复置换，报告均值和方差，并做单变量消融确认方向。

## 2. Worked example

```python
baseline_scores = [0.10, 0.11, 0.09]
permuted_scores = [0.06, 0.08, 0.07]
importance = sum(baseline_scores)/3 - sum(permuted_scores)/3
assert importance > 0
assert len(baseline_scores) == len(permuted_scores)
```

运行后必须保存输入、期望输出和实际输出。代码可执行只证明局部定义一致，不证明策略在样本外有效。

## 解释协议：重要性回答模型依赖，不等于因果贡献

**特征重要性**至少要区分树分裂增益、置换重要性和样本级归因。分裂增益偏爱高基数与可多次切分的变量；置换重要性在强相关特征之间会稀释贡献；SHAP 解释依赖背景分布。复现实验应先在含一列真实信号、一列复制信号和一列噪声的合成数据上运行三种方法，检查复制特征如何分摊重要性。

失效边界是先看测试集重要性再删特征调参，或者把高重要性写成因果结论。**特征重要性**只有在每个 walk-forward 训练窗内独立计算、报告跨窗秩稳定性并配合成组置换与消融后才通过；解释结果不得回流污染最终测试集。

### 定义—推导—对比复核

**特征重要性** 的定义必须能落到数据列和时点，而不能只停留在术语。从置换后损失增量定义模型依赖，再与分裂增益和因果效应对比；相关特征会分摊贡献，因此必须成组消融。因此，对 **特征重要性** 的误区检查要同时保留正例、破坏条件后的反例和样本外结果；只要三者不能形成同一因果链，就暂不判定掌握。
