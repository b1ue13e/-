# 时间索引与频率（量化）

> [!info] 主线导航
> [[🗺️ 量化金融学习路径|返回路径]] · **Week 2 / K03** · 上一张 [[02-Knowledge/🧠 学习系统/03-量化金融/01-夯实基础/OHLCV字段清洗与复权]] · 下一张 [[Pandas分组聚合与透视表]]

> K03 的重点不是 Pandas 日期 API，而是回答：一条信息在什么时间可得，最早可以在什么时间成交？

## 四个必须分开的时间

| 时间 | 含义 |
|:---|:---|
| 交易日 | 市场实际开市的日期，不等于自然日 |
| 特征截止时间 | 计算特征所用最后一条信息的时间 |
| 信号形成时间 | 策略完成计算并产生目标持仓的时间 |
| 执行时间 | 订单可以真实成交的最早时间 |

若使用日期 $t$ 的收盘价构造信号，通常不能再假设以同一个收盘价无摩擦成交；应预先声明在 $t+1$ 开盘、VWAP 或其他可实现价格执行。

## Worked example

周五收盘后得到 20 日动量信号，周末没有交易。最早执行日通常是下一个交易日周一，而不是自然日周六。若周一停牌，则需要按预设规则延后、丢弃或标记不可成交，不能事后选择最有利处理。

## K03 最小作业

1. 导出数据日历首日、末日、缺口和测试期交易日数。
2. 任选 5 个信号日期，列出特征截止、信号形成和最早执行时间。
3. 断言 `feature_time <= signal_time < execution_time`。
4. 对周末、节假日、停牌各写一个处理规则。

## K03 来源、边界与独立复核

### 定义、假设、机制与边界

时间索引与频率的核心定义不是日期字符串，而是带时区、交易日历、观测区间和信息可得时点的事件轴。重采样的机制会改变每个桶的边界和标签，所以开高低收的聚合规则不能互换。假设日线收盘数据在收盘后可得时，含当日收盘的特征只能驱动更晚订单。反例是把自然日补齐后将周末当成零收益交易日，波动率与年化因子都会被扭曲。验证必须打印原始时间、桶边界、信号时间与执行时间。

### 可定位来源

1. pandas Time series/date functionality, Section Resampling: https://pandas.pydata.org/docs/user_guide/timeseries.html
2. pandas Resampler API, Section OHLC aggregation: https://pandas.pydata.org/docs/reference/resampling.html
3. Microsoft Qlib Data Layer, Section Calendar and Instrument APIs: https://qlib.readthedocs.io/en/stable/component/data.html

### 可复现示例与验证

```python
from datetime import datetime, timezone
signal = datetime(2026, 8, 1, 8, 0, tzinfo=timezone.utc)
execution = datetime(2026, 8, 2, 1, 30, tzinfo=timezone.utc)
assert signal.tzinfo is not None
assert signal < execution
```

这段最小实验不是收益证明；它只验证 K03 的局部定义与边界。正式作业仍需保存输入、期望输出、实际结果和失败案例。

## 适用条件与边界

- 只有在时区、交易日历、频率和可得时点明确时，重采样结果才可进入回测；自然日补齐不能自动等价于交易日。
- 使用 $t$ 日收盘生成信号时，执行时间必须晚于信号可得时间；跨市场数据需先统一时区再对齐。

## 公式与符号

记观测时间为 $t_i$，信号可得时间为 $a_i$，执行时间为 $e_i$，最小时间协议为 $t_i\le a_i<e_i$。`rule` 是重采样频率，`label`/`closed` 决定桶标签与边界。
