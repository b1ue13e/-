# 订单流不平衡 (Order Flow Imbalance, OFI)

---

## 0. 先判断它值不值得深挖

**分类：A 类（核心概念，必须深挖）**

**理由：**
订单流不平衡（Order Flow Imbalance, OFI，由 Cont, Kukanov and Stoikov 2014 提出）是高频交易（HFT）、统计做市与日内微观结构预测中最强大的线性 Alpha 信号之一。不同于静态的盘口挂单量不平衡（Order Book Imbalance, OBI），OFI 捕捉的是相邻 Tick 之间买一/卖一价格变化与挂单量增减的**动态净供给与净需求流动**。实证表明，OFI 对未来数秒至数分钟内资产中间价的变化具有极高的线性预测能力（$R^2$ 可达 50%~70%）。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦：**

假设你正在编写一个期货高频做市策略，需要预测未来 3 秒内价格是向上跳动 1 变动单位（Tick）还是向下跳动。
如果你只看静态的买一卖一挂单量（比如买一挂 1000 手，卖一挂 500 手）：
你可能会简单地认为“买盘大于卖盘，价格要涨”。
但如果下一毫秒，有一笔大单撤掉了买一的 800 手，或者市价卖单迅速吃光了买盘，静态盘口挂单量会立刻欺骗你。

**以前的方法在哪里卡住：**
1. **静态盘口 (OBI) 易被虚假挂单欺骗**：做市商或高频玩家可以通过挂大额虚假单（Spoofing）制造假买盘，随后瞬间撤单。
2. **只看成交量 (Volume)**：成交量只代表“已经发生的过去”，无法区分这笔成交是主动买单吃掉卖盘，还是主动卖单砸穿买盘。

**为什么必须引入 OFI 订单流不平衡：**
精确追踪相邻两个 Tick 之间，在**买一价与卖一价发生变动或未变动**时，由于**新限价单挂单 (Limit Order)**、**市价单吃单 (Market Order)** 和 **撤单 (Cancellation)** 带来的纯净买卖力量增减。

**它到底解决了哪类问题：**
解决了**毫秒/秒级微观时间尺度下，如何真实还原买卖双方意图、剔除虚假挂单噪音并高精度预测超短期价格变化**的问题。

---

## 2. 为什么它重要？它有什么用？

- **体系与大图景**：高频交易（第四阶段）的王牌信号，连接 Level-2/Level-3 订单簿流数据与高频信号/执行算法。
- **量化与实操应用**：
  1. **高频 Alpha 信号**：将 OFI 信号进行滑动窗口平滑后，直接作为高频趋势/反转策略的进入与退出触发条件。
  2. **动态做市商报价 skew 调整**：当 $OFI_t > 0$（强烈买入不平衡）时，做市商主动向上抬升买卖报价中枢（Ask1/Bid1 同时上移），规避被知情买单吃空风险。
  3. **算法拆单隐蔽执行**：VWAP / IS 算法在 OFI 顺向时加大切片下单量，逆向时暂缓下单。

## 4. 用直觉语言解释它

### 生活类比：拔河比赛中的动态拉力计

假设两队在进行拔河比赛：
- **静态盘口 (OBI)** 就像：只数左边站了 10 个人，右边站了 5 个人。看似左边占优，但可能左边的 5 个人只是滥竽充数，马上准备松手跑路（虚假挂单/即将撤单）。
- **订单流不平衡 (OFI)** 就像：在绳子中间装了一个高精度的**电子拉力矢量传感器**。它不管两边站了多少人，只实时测量这 1 毫秒内，左边队伍“净向左拉了多少公斤力”（新加入的力 - 松手的力 - 被拉倒的力）。

**OFI 的直觉本质**：
OFI 不是数盘口存量，而是测量绳子两端**力量的瞬间加速度与净流入流量**。

«“OFI 就是测量相邻毫秒内买盘新增力量与卖盘消耗力量的纯净差值。”»

## 5. 正式定义、核心公式、符号解释

### 核心定义
**订单流不平衡 (OFI)**：指在相邻两个订单簿快照（Tick $t-1$ 与 $t$）之间，考虑了价格变动方向后，买一端（Bid Level 1）订单流变化量与卖一端（Ask Level 1）订单流变化量的净差额。

### 核心公式

#### 1. 买一端订单流量 $e_{N,t}^{bid}$ 算子
根据 $t-1$ 与 $t$ 时刻买一价 $P_{b,t}$ 的关系划分：
$$e_{N,t}^{bid} = \begin{cases} v_{b,t}, & \text{if } P_{b,t} > P_{b,t-1} \quad (\text{买一价上涨，新买盘买入}) \\ v_{b,t} - v_{b,t-1}, & \text{if } P_{b,t} = P_{b,t-1} \quad (\text{买一价不变，挂单/撤单净变动}) \\ -v_{b,t-1}, & \text{if } P_{b,t} < P_{b,t-1} \quad (\text{买一价下跌，原买一被砸穿/撤单}) \end{cases}$$

#### 2. 卖一端订单流量 $e_{N,t}^{ask}$ 算子
根据 $t-1$ 与 $t$ 时刻卖一价 $P_{a,t}$ 的关系划分：
$$e_{N,t}^{ask} = \begin{cases} -v_{a,t-1}, & \text{if } P_{a,t} > P_{a,t-1} \quad (\text{卖一价上涨，原卖一被买光/撤单}) \\ v_{a,t} - v_{a,t-1}, & \text{if } P_{a,t} = P_{a,t-1} \quad (\text{卖一价不变，挂单/撤单净变动}) \\ v_{a,t}, & \text{if } P_{a,t} < P_{a,t-1} \quad (\text{卖一价下跌，新卖盘向下压价}) \end{cases}$$

#### 3. 单 Tick OFI 公式与时间窗口累积
$$OFI_t = e_{N,t}^{bid} - e_{N,t}^{ask}$$
$$OFI(k) = \sum_{t=1}^k OFI_t$$

#### 4. 价格变动与 OFI 的线性回归模型 (Cont et al.)
$$\Delta P_{mid, t} = \beta \cdot OFI_t + \epsilon_t$$

### 符号解释表

| 符号 | 含义 | 维度/量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $P_{b,t}, P_{a,t}$ | $t$ 时刻的买一价与卖一价 | 货币单位 | 最高买价与最低卖价 |
| $v_{b,t}, v_{a,t}$ | $t$ 时刻的买一量与卖一量 | 股数/手 | 挂单深度 |
| $e_{N,t}^{bid}$ | 买一端净新增订单流 | 股数/手 | 值为正代表买力增强 |
| $e_{N,t}^{ask}$ | 卖一端净新增订单流 | 股数/手 | 值为正代表卖力压制 |
| $OFI_t$ | 订单流不平衡量 | 股数/手 | $OFI > 0$ 预示股价向上跳动 |

## 6. 推导思路和思想来源

### 为什么 $P_{b,t} > P_{b,t-1}$ 时，买一贡献量直接取 $v_{b,t}$？
1. **盘口阶梯向上跳跃**：当买一价从 10.00 元上升到 10.01 元时，意味着在 10.01 元这个全新高价位上，有买方挂入了 $v_{b,t}$ 手新限价单（或者把原单向上抬升）。
2. **绝对力量涌入**：这代表买方愿意以更高的价格抢筹，因此这 $v_{b,t}$ 手订单**全部是全新的强力买入涌入量**！
3. **同理**：当 $P_{b,t} < P_{b,t-1}$ 时，旧买一（10.00元）被卖方市价单彻底砸穿（或被买方撤单），原有的 $v_{b,t-1}$ 手买盘供给完全消失，因此买力损失了 $-v_{b,t-1}$！

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础手算例题（单 Tick OFI 计算）

**题目**：
某股票两个连续 Tick 的 L2 盘口数据如下：
- **Tick 1**：$P_{b,1} = 10.00, v_{b,1} = 500$; $P_{a,1} = 10.02, v_{a,1} = 300$
- **Tick 2**：买方推高价格！$P_{b,2} = 10.01, v_{b,2} = 400$; 卖方价未变 $P_{a,2} = 10.02, v_{a,2} = 200$（有人砸掉了 100 手卖单）

求从 Tick 1 到 Tick 2 的 $OFI_2$ 净数值。

**解答过程**：
1. 计算买一端流量 $e_{N,2}^{bid}$：
   因为 $P_{b,2} (10.01) > P_{b,1} (10.00)$（买一价上升），
   $$e_{N,2}^{bid} = v_{b,2} = +400$$
2. 计算卖一端流量 $e_{N,2}^{ask}$：
   因为 $P_{a,2} (10.02) = P_{a,1} (10.02)$（卖一价不变），
   $$e_{N,2}^{ask} = v_{a,2} - v_{a,1} = 200 - 300 = -100$$
3. 计算总 $OFI_2$：
   $$OFI_2 = e_{N,2}^{bid} - e_{N,2}^{ask} = 400 - (-100) = 400 + 100 = +500 \text{ 手}$$
4. **结论**：$OFI_2 = +500 > 0$，买方展示出强烈的多头净力量，预示中间价极大概率向上跳动。

---

### 例子 2：中等例题（卖一价格下跌压价下的 OFI）

**题目**：
- **Tick 1**：$P_{b,1} = 20.00, v_{b,1} = 1000$; $P_{a,1} = 20.04, v_{a,1} = 800$
- **Tick 2**：卖方主动向下砸价！买一价不变 $P_{b,2} = 20.00, v_{b,2} = 600$（被卖方市价单砸走 400 手）；卖一价下跌 $P_{a,2} = 20.02, v_{a,2} = 500$（卖方压价）。

计算 $OFI_2$。

**解答过程**：
1. 买一端：$P_{b,2} = P_{b,1}$，则 $e_{N,2}^{bid} = v_{b,2} - v_{b,1} = 600 - 1000 = -400$
2. 卖一端：$P_{a,2} (20.02) < P_{a,1} (20.04)$（卖一价下跌），则 $e_{N,2}^{ask} = v_{a,2} = +500$
3. $OFI_2 = e_{N,2}^{bid} - e_{N,2}^{ask} = (-400) - (+500) = -900 \text{ 手}$
4. **结论**：$OFI_2 = -900 < 0$，强烈卖压砸盘，预示价格即将向下跌破。

### 例子 3：实际应用（Python 实时流式计算全套 OFI 高频信号）

```python
import numpy as np
import pandas as pd

def compute_ofi(df):
    """
    df 包含列: ['bid_price', 'bid_vol', 'ask_price', 'ask_vol']
    """
    p_b, v_b = df['bid_price'].values, df['bid_vol'].values
    p_a, v_a = df['ask_price'].values, df['ask_vol'].values
    N = len(df)
    
    e_bid = np.zeros(N)
    e_ask = np.zeros(N)
    
    for t in range(1, N):
        # Bid 流计算
        if p_b[t] > p_b[t-1]: e_bid[t] = v_b[t]
        elif p_b[t] == p_b[t-1]: e_bid[t] = v_b[t] - v_b[t-1]
        else: e_bid[t] = -v_b[t-1]
            
        # Ask 流计算
        if p_a[t] < p_a[t-1]: e_ask[t] = v_a[t]
        elif p_a[t] == p_a[t-1]: e_ask[t] = v_a[t] - v_a[t-1]
        else: e_ask[t] = -v_a[t-1]
            
    ofi = e_bid - e_ask
    return ofi

# 示例输出
df_ticks = pd.DataFrame({
    'bid_price': [10.00, 10.01, 10.01],
    'bid_vol': [500, 400, 600],
    'ask_price': [10.02, 10.02, 10.02],
    'ask_vol': [300, 200, 150]
})
print("计算出的高频 OFI 信号:", compute_ofi(df_ticks))
```

## 8. 常见误区与易混概念

### 误区 1：OFI 就是简单的买一量减去卖一量（$v_{bid} - v_{ask}$）

错误直觉：“OFI 不就是盘口买一挂单减去卖一挂单吗？”  
为什么错：$v_{bid} - v_{ask}$ 叫 **OBI（Order Book Imbalance，静态盘口不平衡）**。OBI 极易受虚假挂单和撤单误导。OFI 是**差分动态流量**，考虑了价格改变时的真实力量流动。  
正确理解：**OBI 测的是静态存量，OFI 测的是动态净流量。**

### 概念对比：OBI vs OFI vs VOI

| 信号名称 | 计算维度 | 核心公式/特点 | 抗虚假挂单能力 |
| :--- | :--- | :--- | :--- |
| **OBI (Order Book Imbalance)** | 单 Tick 静态存量 | $\frac{v_{bid} - v_{ask}}{v_{bid} + v_{ask}}$ | 极低（容易被欺诈挂单欺骗） |
| **OFI (Order Flow Imbalance)** | 动态跨 Tick 流量 | $e_{bid} - e_{ask}$ (考虑价格跳动分段) | **极高（工业级高频 Alpha 信号）** |
| **VOI (Volume Order Imbalance)** | 简化版动态流量 | 忽略价格变动条件下的近似流量 | 中等 |

### 第 2 题：公式运用（基础）
**题目**：某 Tick 中，买一价从 50.00 元跳涨至 50.01 元（挂单量 800 手），卖一价从 50.02 元跳降至 50.01 元（卖一压价，挂单量 600 手，即买卖碰撞）。求此 Tick 的 OFI。

> [!question]- 答案解析
> **答案**：
> 1. 买一价上涨：$e^{bid} = v_{b,t} = +800$。
> 2. 卖一价下跌：$e^{ask} = v_{a,t} = +600$。
> 3. $OFI = e^{bid} - e^{ask} = 800 - 600 = +200$ 手。  
> **Obsidian 标签**：`#自测题/OFI变动`

---

### 第 3 题：条件判断（中等）
**题目**：判断：“若 $OFI > 0$，说明市场上发生的必定全是主买交易（Take Order），没有任何撤单发生。”

> [!question]- 答案解析
> **答案**：错误。$OFI > 0$ 代表的是**净买力不平衡**。它可能是由新限价买单挂入（Add）、卖一撤单（Cancel）或主买吃单（Execute）共同作用的结果，反映的是综合净效果。  
> **Obsidian 标签**：`#自测题/OFI机制`

---

### 第 4 题：变式/综合（中等）
**题目**：某高频做市策略监控到过去 5 秒内的累积 $OFI_{cum} = +5000$ 手（极高多头不平衡）。为了规避风险，策略应该如何调整其在买一（Bid1）和卖一（Ask1）的挂单位置与挂单数量？

> [!question]- 答案解析
> **答案**：
> 1. **向上移动报价中枢 (Skew Up)**：提升 Ask1 和 Bid1 价格，顺应上涨趋势。
> 2. **调整挂单深度**：减少 Ask1 卖单挂数量（防止被知情买单吃空），增加 Bid1 买单挂数量或将 Bid1 价格推更紧，抢占多头成交。  
> **Obsidian 标签**：`#自测题/做市Skew`

---

### 第 5 题：开放/建模（较难）
**题目**：传统的 OFI 只关注 L1 盘口（买一/卖一）。如何将 OFI 扩展至 L2 盘口的前 5 档（Deep OFI / Multi-level OFI）？深层盘口流量应该施加怎样的距离衰减权重？

> [!question]- 答案解析
> **解析**：
> 1. **多层算子扩展**：对第 $k$ 档盘口（$k=1, 2, \dots, 5$），分别计算 $OFI_t^{(k)}$。
> 2. **距离衰减权重**：由于离中间价越远的盘口对即期价格影响越弱，引入指数或倒数衰减权重 $w_k = e^{-\alpha (k-1)}$ 或 $w_k = \frac{1}{k}$。
> 3. **综合多层 OFI**：
>    $$OFI_t^{Multi} = \sum_{k=1}^5 w_k \cdot OFI_t^{(k)}$$
>    这能有效捕捉在深层盘口挂大单、撤大单的机构高频隐蔽动作。  
> **Obsidian 标签**：`#自测题/多层OFI`

### 失效边界与验收协议

- **成立条件**：先写清数据时点、估计窗口、交易摩擦和分布/市场结构假设，再运行模型。
- **反例压力测试**：逐事件重建新增、撤单和成交量，检查 OFI 聚合窗口变化后预测符号是否保持。
- **最小实验**：固定随机种子或冻结原始数据快照，同时保存基线、破坏条件后的对照组、关键中间量与失败日志。
- **通过标准**：结论必须在样本外仍保持方向一致；若成本、延迟、参数扰动或结构突变使结论反转，就把该情形登记为适用边界而不是删除失败结果。
