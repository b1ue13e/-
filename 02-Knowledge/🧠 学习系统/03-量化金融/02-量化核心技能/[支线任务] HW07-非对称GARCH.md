- **理由**：本次作业验证你将计量经济学理论转化为工程代码的能力。非对称波动率（杠杆效应）是现代量化风控（如VaR、期权定价）必须考虑的市场事实，纯对称的 GARCH(1,1) 无法应对真实的股灾。写不出稳健的非对称模型，你的策略回测就会在极端行情下严重失真。

## 1. 这个知识点（实验）解决什么问题？
> **我们遇到了什么麻烦？**

在金融市场中，如果用上一讲基础的 GARCH(1,1) 建模，你会遇到一个致命的麻烦：模型认为“暴跌 5%”和“暴涨 5%”对未来波动率的冲击是一模一样的。这完全违背了真实市场规律！
在现实中，坏消息（暴跌）往往伴随着恐慌盘抛售、公司杠杆率被动飙升，从而引发比好消息（暴涨）大得多的后继波动。如果不解决这种“非对称性”，你的风控系统会在市场暴跌时给出盲目乐观的风险评估，直接导致爆仓。本次作业教你在代码中引入“恐慌杠杆”，解决这个致命缺陷。

## 4. 用直觉语言解释它
«“这东西其实就像……”»

想象一下，普通的 GARCH 就像一根普通的**弹簧**，无论你往上拉（股票涨）还是往下压（股票跌），你一松手，它的震荡幅度是一样的。
而非对称 GARCH（比如 GJR-GARCH）就像在“往下压”的方向额外串联了一个**恐慌放大器**。如果只是往上拉（好消息），放大器不工作，弹簧正常震荡；一旦往下压（坏消息），放大器立刻启动，把压力翻倍，导致后续的震荡极度剧烈。
**一句话本质**：“跌了更慌，涨了心安”的数学编码化。

## 5. 正式定义、核心公式与代码符号映射

### 最核心模型：GJR-GARCH(1,1,1)
给定收益率残差 $\epsilon_t$，其条件方差 $h_t$ 的更新方程为：
$$
h_t = \omega + \alpha \epsilon_{t-1}^2 + \gamma \epsilon_{t-1}^2 I_{t-1} + \beta h_{t-1}
$$

**指示函数 $I_{t-1}$** 定义：如果 $\epsilon_{t-1} < 0$，则 $I_{t-1} = 1$；否则 $I_{t-1} = 0$。

### 符号与代码变量解释表
| 数学符号 | 代码/库参数 | 经济学含义 | 取值约束 (稳健性要求) |
|---|---|---|---|
| $h_t$ | `volatility**2` | 当期条件方差预测值 | $h_t > 0$ |
| $\omega$ | `omega` | 长期基础波动率 | $\omega > 0$ |
| $\alpha$ | `alpha[1]` | 对称冲击系数 (好坏消息基础反应) | $\alpha > 0$ |
| $\gamma$ | `gamma[1]` / `o=1` | 非对称杠杆系数 (恐慌溢价) | $\gamma > 0$ (GJR模型中) |
| $\beta$ | `beta[1]` | 波动率的持续性 (长记忆) | $\beta > 0$, 且 $\alpha + \gamma/2 + \beta < 1$ |

---

## 6. 实验原理与架构动机
### 为什么引入指示函数而不是分别建两个模型？
如果直接写 `if-else` 分支或者分别拟合上涨和下跌日，会切断时间序列的长记忆性连续性（破坏 $\beta$ 项的迭代），而且在 Python 中 `for-if` 循环处理数万天数据速度极慢。
我们通过引入开关函数 $I_{t-1}$，在工程上可以完全转化为矩阵点乘：
`I_t = (residuals < 0).astype(int)`
`asym_shock = gamma * (residuals**2) * I_t`
这是一种纯向量化的操作（Vectorization），保留了方程的解析性和优化器的求导连续性。

## 7. 例子：基础推演 → 代码实现 → 真实量化场景

### 例子 1：基础（手工推演杠杆效应）
- **背景**：你刚训练完模型，得到参数 $\omega = 0.05, \alpha = 0.1, \beta = 0.8, \gamma = 0.15$。昨天模型预测的方差 $h_{t-1} = 1.0$。
- **情景 A (好消息)**：昨天的残差 $\epsilon_{t-1} = +2$ (无恐慌，指示函数 $I=0$)。
  $$ h_t = 0.05 + 0.1 \times (2^2) + 0.15 \times (2^2) \times 0 + 0.8 \times 1.0 = 0.05 + 0.4 + 0 + 0.8 = 1.25 $$
- **情景 B (坏消息)**：昨天的残差 $\epsilon_{t-1} = -2$ (引发恐慌，指示函数 $I=1$)。
  $$ h_t = 0.05 + 0.1 \times (-2)^2 + 0.15 \times (-2)^2 \times 1 + 0.8 \times 1.0 = 0.05 + 0.4 + 0.6 + 0.8 = 1.85 $$
- **结论**：绝对值相等的冲击下，坏消息导致的次日波动率（1.85）远大于好消息（1.25）。

### 例子 2：中等（核心代码实现）
利用 `arch` 库实现 GJR-GARCH 拟合的正确姿势：
```python
from arch import arch_model

# p代表基础滞后项，q代表持续性，o(order)代表非对称项！
# 这是作业中最容易配错的地方
gjr_model = arch_model(returns, vol='GARCH', p=1, o=1, q=1, dist='StudentsT')
results = gjr_model.fit(disp='off')
print(results.summary())
```
*注意：引入胖尾分布 (Student's t) 通常会让参数估计更稳健。*

### 例子 3：实际应用（作业压轴题：2008 股灾 VaR 回测）
- **任务描述**：使用标准 GARCH 和 GJR-GARCH 分别预测 2008 年标普 500 的 99% VaR。
- **实战结果**：你会发现在雷曼兄弟破产那几周，标准 GARCH 的 VaR 击穿率（突破阈值的天数）高达 5%，而 GJR-GARCH 迅速因为连续的负收益率调高了方差预测，将击穿率控制在理想的 1.5% 左右，成功守住了风控底线。

## 8. 实验常见坑点与易混概念（Debug 必看）

1. **坑点 1：模型不收敛 (Iteration limit reached / NaN)**
   - **原因**：你的收益率数据没有放大。直接输入 $0.0001$ 级别的日收益率，平方后变成 $10^{-8}$，浮点数精度直接让优化器崩溃。
   - **解法**：**必须**把收益率乘以 100（转化为百分比），然后再丢进模型。
2. **坑点 2：EGARCH 与 GJR-GARCH 的 $\gamma$ 符号倒置**
   - **易混点**：在 GJR-GARCH 中，$\gamma > 0$ 代表存在杠杆效应（坏消息增加方差）。但在另一种非对称模型 EGARCH 中，冲击项写为 $\gamma \frac{\epsilon}{\sigma}$，因此在 EGARCH 中 **$\gamma < 0$** 才代表坏消息推高波动率。写报告时极易混淆！
3. **坑点 3：未来函数 (Look-ahead Bias)**
   - **错误动作**：用 10 年全样本数据 fit 出一个 $\gamma$，然后去预测这 10 年内的每日 VaR。
   - **正确动作**：作业要求必须使用**滚动窗口 (Rolling Window)**。预测第 $T$ 天的方差，只能用 $T-1$ 天及以前的数据去 fit 模型。

## 11. 自测题：5 道

> [!question]- 1. 概念辨析 (基础)
> **题目**：在 GJR-GARCH 模型中，如果估计出的 $\gamma$ 接近于 0，且 p-value 很大，这在金融上意味着什么？
> 
> **答案解析**：意味着所分析的资产**不存在显著的非对称杠杆效应**。好坏消息对波动率的冲击是基本对称的，退化为普通的 GARCH(1,1)。常见于外汇市场。

> [!question]- 2. 代码参数 (基础)
> **题目**：在使用 Python 的 `arch` 库时，`arch_model(vol='GARCH', p=1, o=1, q=1)` 中的 `o` 代表什么？
> 
> **答案解析**：`o` 代表非对称冲击（Asymmetric shock）的阶数。设置为 1 即引入一阶的指示函数 $I_{t-1}\epsilon_{t-1}^2$ 项，从而将标准 GARCH 变为 GJR-GARCH。

> [!question]- 3. 稳健性 (中等)
> **题目**：为了保证 GJR-GARCH(1,1,1) 的长期方差（Unconditional Variance）是有限且平稳的，参数必须满足什么约束条件？
> 
> **答案解析**：必须满足 $\alpha + \frac{\gamma}{2} + \beta < 1$。因为指示函数的期望 $E[I_{t-1}] = 0.5$（假设冲击分布对称）。

> [!question]- 4. 纠错排雷 (中等)
> **题目**：某同学在跑 EGARCH 模型时发现得到的 $\gamma$ 参数是负数（比如 -0.15），他非常绝望地认为模型做反了，准备删了重跑。请你指出他的问题。
> 
> **答案解析**：他没有错。在 EGARCH 模型中，非对称项通常是 $\gamma (\frac{\epsilon_{t-1}}{\sigma_{t-1}})$，由于坏消息时 $\epsilon < 0$，只有当 $\gamma < 0$ 时，两者相乘才为正，才能代表“坏消息增加波动率”。他混淆了 EGARCH 和 GJR-GARCH 的参数符号约定。

> [!question]- 5. 架构设计 (较难)
> **题目**：如果让你不用 `arch` 库，从零手写 MLE 求解 GJR-GARCH，在计算所有 $h_t$ 时，你会如何避免使用非常慢的 for 循环？
> 
> **答案解析**：在传统的序列依赖问题中，由于 $h_t$ 依赖 $h_{t-1}$，纯粹的并行向量化是极难的。通常我们仍然必须保留外层的 1D 循环，但在计算每一项的非对称冲击时，可以通过预计算掩码数组 `mask = (returns < 0)` 并在循环中以标量乘法快速取值，同时可以利用 Numba 或 Cython 的 `@jit` 装饰器将这段不可避免的 C-level 循环编译，极大加速执行。
