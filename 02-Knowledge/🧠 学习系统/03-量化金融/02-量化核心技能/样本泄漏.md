## 1. 定义、机制、假设与边界

样本泄漏的定义是模型训练或研究选择使用了预测时不可获得的信息。泄漏机制至少包括未来特征、全样本预处理、标签窗口重叠和测试集反复调参；随机切分只是其中一种诱因。成立条件应由逐行 information set 证明，而不是看到高收益后凭直觉判断。反例是先用全样本均值标准化再划分训练测试，即使特征没有显式 lead，也已让测试分布进入训练。独立验证要制造一个会失败的泄漏测试。

## 2. Worked example

```python
train_end, test_start = 100, 101
fit_rows = set(range(0, train_end + 1))
test_rows = set(range(test_start, 130))
assert fit_rows.isdisjoint(test_rows)
feature_available_at, execution_at = 100, 101
assert feature_available_at < execution_at
```

运行后必须保存输入、期望输出和实际输出。代码可执行只证明局部定义一致，不证明策略在样本外有效。

## 泄漏证明：删除未来数据后，历史特征必须逐位不变

**样本泄漏**不是只有“直接用了明天价格”这一种形式，还包括全样本标准化、公告日回填、跨折标签区间重叠和用测试集调参。因果机制是训练阶段获得了部署时不存在的信息，使条件分布被人为收窄。最强的复现实验是时间截断测试：在日期 $T$ 后删除全部原始数据并重跑管线，断言 $T$ 以前的特征、股票池、模型参数选择输入完全一致。

反例是仅检查代码里有没有 `shift(-1)`，却允许财务数据按报告期而非公告期连接。**样本泄漏**的验收门槛是为每列维护 `available_at`，为每个标签维护信息区间，并在交叉验证中同时执行 purge 与 embargo；任何截断测试失败都必须阻断回测发布。

<!-- quant-route-reasoning-v4 -->
### 定义—推导—对比复核

**样本泄漏** 的定义必须能落到数据列和时点，而不能只停留在术语。用信息集包含关系定义泄漏：训练步骤读到部署时不可得变量；再与合法的历史滞后特征对比，边界由 `available_at` 判定。因此，对 **样本泄漏** 的误区检查要同时保留正例、破坏条件后的反例和样本外结果；只要三者不能形成同一因果链，就暂不判定掌握。
