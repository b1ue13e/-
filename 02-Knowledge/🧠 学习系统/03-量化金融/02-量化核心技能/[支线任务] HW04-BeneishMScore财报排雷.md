# HW04-BeneishMScore财报排雷作业说明书 实战演练笔记

---

## 0. 先判断它值不值得深挖
- **类别**：A 类实战作业。
- **理由**：量化投资中“防雷”与“找收益”同等重要。Beneish M-Score 是最经典的财务造假识别模型，本作业不仅要求掌握理论，更要求从真实金融数据库（如 Tushare/Wind）获取数据并完成代码落地，是打通“财务会计”到“量化工程”的关键节点，属于必须彻底掌握的实战底座。

---

## 1. 这个实验解决什么问题？
> **我们遇到了什么麻烦？**

在实盘量化中，如果我们只看市盈率或成长性，很容易买入看似亮眼实则财务造假的“地雷股”（如历史上的康美药业、瑞幸咖啡）。但人工排查几千家公司的财报耗时耗力。同时，在代码实现时，财报科目繁杂、不同季报发布时间存在滞后性（存在严重的 Look-ahead Bias 麻烦），数据中还充满缺失值与极值。本作业就是教我们如何写出一套健壮的自动化排雷代码，并优雅处理这些工程麻烦。

---

## 2. 为什么它重要？它有什么用？
- **大图景位置**：它是量化风控系统（Risk Management）的第一道防线。在执行任何 Alpha 因子选股前，必须先经过 M-Score 排雷池过滤。
- **实际应用**：自动剔除高财务造假风险的股票；生成多空策略的“做空”信号；辅助企业信贷风控定价。
- **工程价值**：通过本实验，你将彻底掌握时序面板数据（Panel Data）的滚动计算、财务指标的 Pandas 向量化运算以及截面数据去极值/标准化处理的工程落地能力。

## 3. 实验前置知识
### 最小必要背景 (200 字以内)
1. **基础财务报表**：理解资产负债表（应收账款、存货、总资产）和利润表（营业收入、销售费用、净利润）的基本结构。
2. **Pandas 进阶操作**：熟练使用 `shift()` 计算同比变化，`groupby()` 处理面板数据，以及处理 `NaN` 与无穷大 `inf` 的技巧。
3. **前视偏差（Look-ahead Bias）**：理解为什么不能用 12 月 31 日的数据在次年 1 月 1 日交易（因为年报通常在次年 4 月才实际发布）。

## 4. 用直觉语言解释它
«“这东西其实就像……”»

Beneish M-Score 就像是给企业做**“全面血液体检”**。我们不去猜测企业老板的人品，而是化验 8 个财务“生物标志物”（比如：应收账款是不是涨得比收入还快？毛利率是不是突然暴跌？）。如果这 8 项指标通过一个特定的加权公式计算出的总分异常高，就说明企业这套“生理系统”严重不协调，企业为了掩盖亏损或虚增利润而“吃兴奋剂”（操纵利润）的概率极大。

**直觉本质**：用 8 个财务变动比率的线性组合，计算出量化的财务造假概率得分。

---

## 5. 核心模型、代码架构与符号表

### 核心计算公式
M-Score = -4.84 + 0.920×**DSRI** + 0.528×**GMI** + 0.404×**AQI** + 0.892×**SGI** + 0.115×**DEPI** - 0.172×**SGAI** + 4.679×**TATA** - 0.327×**LVGI**
*(注：如果 M-Score > -1.78，则被模型判定为造假风险极高)*

### 模块化代码架构设计
本作业要求实现一个 `BeneishMScore` 类，必须包含以下核心接口：
1. `data_loader()`: 获取并清洗资产负债表、利润表、现金流量表。
2. `calc_components()`: 向量化计算 8 大底层因子。
3. `calc_m_score()`: 综合算分，并生成 Boolean 信号矩阵（1代表排雷，0代表安全）。

### 核心变量/符号解释表
| 变量/符号 | 全称 (含义) | 对应财报科目/计算逻辑 | 物理直觉/排雷逻辑 |
|---|---|---|---|
| DSRI | 应收账款指数 | (本期应收/本期收入) / (上期应收/上期收入) | 虚增收入通常表现为应收账款暴增（卖不出去硬塞给经销商） |
| GMI | 毛利率指数 | 上期毛利率 / 本期毛利率 | 盈利恶化时，管理层造假的动机急剧增加 |
| AQI | 资产质量指数 | 1 - (流动资产+固定资产)/总资产 的期际比 | 增加无形资产等科目以资本化费用，隐藏当期成本 |
| SGI | 营业收入指数 | 本期收入 / 上期收入 | 高增长公司为维持股价，造假压力更大 |
| TATA | 总应计项对总资产比 | (净利润 - 经营活动现金流) / 总资产 | 纸面富贵，利润极高但没有真金白银流入 |

## 6. 实现步骤与工程动机
### 动机与“转念”
最初在实验中，我们可能想遍历每只股票，用 `for` 循环按财报发布日期一行行算这 8 个指标。但面对 A 股 5000 只股票十余年的数据，循环计算极其缓慢，难以支撑回测。
关键的“转念”是：**摒弃循环，全面利用 Pandas 的向量化与索引对齐机制**。
1. **统一对齐（Alignment）**：先将所有报表表单按 `(Ticker, Report_Date)` 合并到同一个大宽表中。
2. **时序平移**：严格使用 `.groupby('Ticker')['col'].shift(1)` 获取上期或上年同期数据。
3. **矩阵运算**：直接通过列之间的四则运算得到 8 个因子，最后与系数常数向量执行点乘，将几十分钟的计算压缩至百毫秒级。

## 7. 例子：手工推演 → 代码实现 → 真实测试标准

### 例子 1：基础手工推演 (Debug 标定用)
- **场景**：某公司上期营业收入100亿，应收账款20亿；本期营业收入150亿，应收账款60亿。
- **计算 DSRI**：上期应收占比 = 20/100 = 0.2。本期应收占比 = 60/150 = 0.4。DSRI = 0.4 / 0.2 = 2.0。
- **分析结果**：DSRI 为 2.0，远大于正常值 1。这意味着公司应收账款的增速是收入增速的两倍，必须高度警惕其“提前确认收入”或“虚假销售”的造假行为。

### 例子 2：核心代码段 (中等)
```python
import numpy as np
import pandas as pd


def add_dsri(data):
    required = {'Ticker', 'report_date', '应收账款', '营业收入'}
    missing = required.difference(data.columns)
    if missing:
        raise ValueError(f'missing columns: {sorted(missing)}')

    result = data.sort_values(['Ticker', 'report_date']).reset_index(drop=True).copy()
    current_ratio = result['应收账款'] / result['营业收入']
    previous_ratio = current_ratio.groupby(result['Ticker']).shift(1)
    result['DSRI'] = (current_ratio / previous_ratio).replace(
        [np.inf, -np.inf], np.nan
    )
    return result


sample = pd.DataFrame({
    'Ticker': ['DEMO', 'DEMO'],
    'report_date': ['2024-12-31', '2025-12-31'],
    '应收账款': [20.0, 60.0],
    '营业收入': [100.0, 150.0],
})
result = add_dsri(sample)
assert np.isnan(result.loc[0, 'DSRI'])
assert np.isclose(result.loc[1, 'DSRI'], 2.0)
print(result)
```

## 8. 常见坑点与排雷误区 (作业重点)

1. **工程误区：致命的前视偏差 (Look-ahead Bias)**
   - **错误直觉**：把一季报（3月31日）的数据直接在回测中 4月1日 用于交易选股。
   - **为什么错**：财报在期末日并不发布，一季报通常在4月底前才公布。用未来数据回测会导致收益率虚高，实盘直接爆仓。
   - **正确做法**：必须使用**财报实际披露日（公告日 `ann_date`）**进行时序对齐，或者强制将报告期财务数据滞后 45~90 天。
2. **数据处理误区：分母为零或极值**
   - **陷阱**：直接进行财务数据除法运算。如果上期收入为 0（如初创刚盈利），DSRI 将变成 `inf`。
   - **正解**：代码中必须包含对 `np.inf` 的替换逻辑（转为 `NaN`），并在最终合成分数前，对截面数据进行 Winsorize（去极值）和 Z-score 标准化处理。
3. **行业适用性误区：错杀金融股**
   - **陷阱**：直接将 M-Score 用于所有 A 股，导致大量银行股被错判为造假。
   - **正解**：金融股（银行、券商、保险）的资产负债结构与实体企业完全不同（例如银行的存款是负债），计算前必须在 Universe 中根据申万行业分类剔除金融股。

## 11. 自测题：5 道

> [!question]- 1. 概念辨析 (基础)
> **题目**：你的回测系统输出某股票 M-Score 得分为 -1.2，这意味着什么？
> 
> **答案解析**：由于 -1.2 大于临界值 -1.78，说明该股票财务造假风险极高。在量化策略中，该股票应该被立即拉入黑名单，拒绝建仓。

> [!question]- 2. 财务逻辑 (基础)
> **题目**：为什么毛利率指数（GMI）是 = 上期毛利率 / 本期毛利率，而不是用本期除以上期？
> 
> **答案解析**：模型设计的原则是“造假嫌疑越大，因子数值越大”。当本期毛利率严重恶化（下降）时，企业为了掩盖颓势，粉饰报表的动机最强。此时“上期 / 本期”的值才会大于 1，从而推高 M-Score 总分。

> [!question]- 3. 代码纠错 (中等)
> **题目**：在计算 TATA (总应计项) 时，某同学核心代码写为 `TATA = (净利润 - 经营活动现金流净额) / 净资产`，哪里有问题？
> 
> **答案解析**：分母错了，应该是**总资产 (Total Assets)**，而不是净资产 (Equity)。总应计项反映的是没有真实经营现金流支持的“纸面利润”占整个企业资产总盘子的比例。

> [!question]- 4. 避坑工程 (中等)
> **题目**：处理 Tushare 接口获取的财报数据时，报告期(end_date)和公告日(ann_date)有什么区别？合并到日频行情数据时该使用哪一列作为时间键？
> 
> **答案解析**：报告期指财报统计周期的最后一天（如12月31日），公告日指财报正式向公众发布的日期（如次年4月28日）。在量化回测中，为了避免使用未来数据（前视偏差），**绝对必须使用公告日(ann_date)**，确保信号在财报真正公开后才发生作用。

> [!question]- 5. 架构优化 (较难)
> **题目**：当你算好了一份基于公告日的季频 M-Score 信号表，如何高效将其与 10 年的日频股票价格宽表对齐，以进行每日回测？
> 
> **答案解析**：应使用 Pandas 的 `pd.merge_asof()`，或者先将 M-Score 的日期作为索引拼接入日频表，然后使用 `ffill()`（前向填充）。这代表在下一份财报公布之前，模型将一直沿用最新一期财报算出的 M-Score 状态。
