# 计算机视觉-HW06：视觉 Transformer 多模态开放项目（大作业）

## 1. 作业身份与来源

- 编号：HW06（capstone），本地融合开放项目：综合 ViT / 多模态 / 部署，覆盖全课程迁移。
- 许可：开放项目型任务，自定数据集与方案，鼓励复用公开基座（ViT / CLIP 类）并以开放许可为准。

## 2. 学习目标

完成本作业后，应能：独立定义一个**有现实意义**的视觉（或视觉-语言）任务；做数据/材料处理、方法选择、实现、结果评价、错误分析与改进方向；产出可展示的成果与报告。大作业不是加题量，而是**端到端的一次综合迁移**。

## 3. 任务背景与边界

- 自定题目（示例方向，任选其一或自拟）：
  1. 细粒度分类：用 ViT 做某类目细粒度识别（如遥感/动植物），对比 CNN 基线。
  2. 图文检索：用视觉-语言基座做跨模态检索，评估召回。
  3. 高效部署：将一个阶段3-4 模型做量化/蒸馏，报告精度-延迟权衡。
- 输入输出：由自定题目明确；须给出可复现的推理入口。
- 假设：可组合此前 HW01-05 的任意技术；允许公开基座权重。
- 禁止：直接提交他人现成仓库当成果；必须包含**自己的数据处理/实验/分析**。

## 4. 环境与依赖

- `torch`、`torchvision`、多模态依赖（如 `transformers` / `clip` 类）按题目选装。
- 运行：自定 `python -m project.main` + 推理脚本。
- 资源：按题目自报（GPU 推荐）；需写清资源约束。

## 5. 稳定题号（阶段化交付）

1. **P1 问题定义**：写 1 页命题书（背景、目标、评价指标、为什么难）。
2. **P2 数据处理**：采集/清洗/划分数据集，写数据卡（规模、分布、偏差）。
3. **P3 方法**：选基线 + 改进（如 ViT + 微调 / 多模态对齐），给出结构图。
4. **P4 实现**：训练/推理脚本，含日志与随机种子。
5. **P5 评价**：在主指标 + 至少 1 个消融上报告，附误差分析样例。
6. **P6 展示**：README 演示 + 5 分钟讲解稿/录屏要点。

## 6. 提交产物

- `project/` 代码目录、`data_card.md`、`report.md`（含命题书、消融表、误差分析）、`README.md`（运行+演示）。
- 最终模型权重或生成产物（如推理示例图/检索样例）。

## 7. 验收标准（Rubric）

| 维度 | 满分 | 通过线 |
|:---|:---:|:---:|
| 问题定义与数据 | 20 | 命题书清晰、数据卡完整 |
| 方法合理性 | 20 | 结构与指标匹配，有基线对照 |
| 实现与可复现 | 20 | 他人按 README 可跑通推理 |
| 评价与错误分析 | 25 | 有消融 + 至少 3 个真实错误样例归因 |
| 展示与反思 | 15 | README/演示清晰，含改进方向 |

## 8. 引导自检（不泄露答案）

- **检查点 C1**：先写命题书再写代码，避免「为做而做」；用一页纸反问「这指标高是否真解决问题」。
- **渐进提示 H1**：选公开基座时，先确认其输入预处理与你的数据分布一致，再微调。
- **调试 D1**：训练不动先看「学习率/数据划分/标签映射」三件套，而非立刻换模型。
- **调试 D2**：多模态对齐差，先查「文本端与图像端是否在同一投影空间、温度是否合适」。

## 9. 常见失败

- 题目过大导致只做了一半；应缩小范围做深，而非铺开做浅。
- 只报主指标不报消融，无法判断改进来自哪一处。
- 错误分析用「模型不够深」敷衍，未定位到具体数据/激活/对齐问题。
