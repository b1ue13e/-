# 🎯 训练集、验证集与测试集

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：训练集（Train）、验证集（Validation）与测试集（Test）的三分法划分是机器学习实验设计的“黄金分割准则”。模糊这三者的界限是引发数据泄露（Data Leakage）和模型评估失真的最常见原因。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦：**
> 假设你训练了一个神经网络，用训练集调参并达到了 99% 的准确率。你很高兴，以为模型很强。但一旦上线，面对真实客户数据，错误率高达 40%！你混淆了“模型训练”、“超参数调优”与“最终泛化能力评估”这三个不同的阶段。

以往的方法卡在：
- 缺乏明确的三级数据隔离机制；
- 误将用于调参的验证集当成最终评估模型泛化能力的测试集（导致对验证集的过拟合）。

数据三分法**在数学与实验流程上建立了严密的隔离栅栏**。

## 4. 用直觉语言解释它

> «“这东西其实就像高考备考的三套卷子……”»

- **训练集 (Training Set)**：平时老师发给你的**日常作业与课后练习**。你反复做这些题，直到掌握参数和公式。
- **验证集 (Validation Set)**：学校组织的**模拟考试试卷**。你不根据模拟考直接背答案，而是根据模拟考成绩调整复习策略、选择辅导书（选择超参数/模型结构）。
- **测试集 (Test Set)**：最终的**全国高考真题**。在进考场之前你绝对不能提前看到这张卷子。只能在最后时刻做一次，得分就是你最终能力的无偏评价。

**直觉本质一句话**：**作业练参数，模考选超参，高考定乾坤。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 三大集合功能对比
| 数据集 | 占用比例 | 核心作用 | 参与的决策 |
| :--- | :--- | :--- | :--- |
| **训练集 ($D_{\text{train}}$)** | 60% - 80% | 拟合模型参数 $\mathbf{w}$ | 梯度下降更新权重 |
| **验证集 ($D_{\text{val}}$)** | 10% - 20% | 评估模型泛化、选择超参数 $\lambda, \alpha$、Early Stopping | 超参数搜索、网络结构选择 |
| **测试集 ($D_{\text{test}}$)** | 10% - 20% | 仅用于评估最终交付模型的最终泛化误差 | 最终性能报告（严禁反馈调参） |

---

## 6. 例子：基础 → 中等 → 实际应用

### 例子 1：常见错误诊断（验证集过拟合）
**场景**：某工程师跑了 10,000 次超参数搜索，每次都在 Validation Set 上评估，最终选出了一个 Validation Acc 为 98% 的超参数。然而在测试集 Test Set 上 Acc 只有 75%。
- **原因分析**：工程师对验证集进行了 10,000 次反复查询与选择，**将验证集当作了另一个训练集**，导致超参数对验证集产生了过拟合（Overfitting to Validation Set）。

---

## 7. 常见误区和易混概念

### 误区 1：测试集可以用来选择超参数
- **错误直觉**：“既然测试集代表真实性能，我用测试集调参效果最好。”
- **为什么错**：一旦用测试集调整超参，测试集的信息就泄漏进了模型选择过程中，测试集不再是无偏的评估工具。

   A. 训练集  B. 验证集 (Validation Set)  C. 测试集 (Test Set)  D. 全量数据集
> [!question]- 答案解析
> **答案**：B  
> **解析**：超参数选择与架构调优必须依据验证集表现。

2. **[错误识别] 如果在模型训练过程中，根据模型在测试集（Test Set）上的 Loss 提前终止训练（Early Stopping），这会导致：**
   A. 完美评估  
   B. 测试集信息泄漏，使得测试集评估结果偏乐观  
   C. 模型欠拟合  
   D. 训练加速
> [!question]- 答案解析
> **答案**：B  
> **解析**：Early Stopping 的监控指标必须是验证集 Loss，使用测试集会导致测试集信息泄漏。  
> **标签**：`#自测/基础 #信息泄漏`

3. **[条件决策] 当手头拥有 1,000,000 条海量数据（如大模型预训练数据）时，最合理的切分比例是：**
   A. 50% / 25% / 25%  
   B. 98% / 1% / 1%  
   C. 33% / 33% / 34%  
   D. 100% 训练
> [!question]- 答案解析
> **答案**：B  
> **解析**：在百万级大数据场景下，1%（1万条）就足以提供极小方差的评估，无需保留过大比例的验证/测试集，应将更多数据留给训练。  
> **标签**：`#自测/中等 #大数据切分`

4. **[概念区分] 训练集拟合的是模型的____，验证集拟合的是模型的____。**
   A. 权重参数 $\mathbf{w}$；超参数 $\lambda$ 与架构  
   B. 超参数；权重参数  
   C. 测试损失；训练损失  
   D. 特征；标签
> [!question]- 答案解析
> **答案**：A  
> **解析**：训练集用于学习可导权重参数，验证集用于选择离散超参数与架构。  
> **标签**：`#自测/中等 #参数与超参数`

5. **[综合分析] 解释为什么在大模型 RLHF 或 DPO 训练中，需要单独保留一个独立的未参与 Preference Model 训练的测试集？**
> [!question]- 答案解析
> **答案**：因为奖励模型（Reward Model）可能被策略网络欺骗（Reward Hacking）。独立未见过的测试集能够客观评估模型回答是否真正符合人类的偏好与安全标准，防止模型过拟合于特定 Reward Model。  
> **标签**：`#自测/较难 #RLHF测试`

> **作业任务说明**：本作业为《训练集与测试集》对应的高级 PyTorch 实战任务。请基于零依赖的 PyTorch Tensor/Module 代码，完成数据预处理、模型架构搭建、梯度训练循环与 4 级 Baseline 冲榜。

### 1. 4 级 Baseline 设级与冲榜拆解 (4-Tier Baseline System)

| Baseline 级别 | 评估指标 (Metric Target) | 突破核心技术 & 优化建议 |
| :--- | :--- | :--- |
| 🟢 **Simple Baseline** | 跑通代码无报错 | 搭建基础 PyTorch 模型框架，完成前向传播与 Loss 计算 |
| 🔵 **Medium Baseline** | 评估 Metric 提升 $20\%$ | **特征与损失优化**：引入数据标准化 (StandardScaler)、标签平滑或权值衰减 |
| 🟣 **Strong Baseline** | 评估 Metric 提升 $40\%$ | **架构与调度优化**：使用 `AdamW` + `CosineAnnealingLR` 余弦退火学习率调度器 |
| 🔴 **Boss Baseline** | **绝顶 SOTA 达标线** | **理论极值突破**：手写无偏估计/SVD 伪逆矩阵/K-Fold 模型集成 (Ensemble) 突破极限 |

### 2. 助教 Starter Code 与作业框架 (PyTorch Runnable Boilerplate)

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import Dataset, DataLoader
import numpy as np

# ---------------------------------------------------------------
# Step 1: 模拟生成 训练集与测试集 实战数据集 (Synthetic Dataset)
# ---------------------------------------------------------------
torch.manual_seed(42)
np.random.seed(42)

N, d = 300, 4
X_raw = np.random.randn(N, d)
y_raw = (X_raw[:, 0] * 1.5 - X_raw[:, 1] * 2.0 + np.random.randn(N) * 0.1 > 0).astype(np.int64)

class CustomHWDataset(Dataset):
    def __init__(self, x, y):
        self.x = torch.tensor(x, dtype=torch.float32)
        self.y = torch.tensor(y, dtype=torch.long)

    def __len__(self):
        return len(self.x)

    def __getitem__(self, idx):
        return self.x[idx], self.y[idx]

dataset = CustomHWDataset(X_raw, y_raw)
train_loader = DataLoader(dataset, batch_size=32, shuffle=True)

# ---------------------------------------------------------------
# Step 2: 搭建 训练集与测试集 模块化模型 (Model Architecture)
# ---------------------------------------------------------------
class HWModel(nn.Module):
    def __init__(self, in_dim, out_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, 32),
            nn.BatchNorm1d(32),
            nn.ReLU(),
            nn.Dropout(0.2),
            nn.Linear(32, out_dim)
        )

    def forward(self, x):
        return self.net(x)

model = HWModel(in_dim=d, out_dim=2)
criterion = nn.CrossEntropyLoss()
optimizer = optim.AdamW(model.parameters(), lr=0.01, weight_decay=1e-4)
scheduler = optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=30)

# ---------------------------------------------------------------
# Step 3: 训练与 Boss Baseline 验证循环 (Training & Validation Loop)
# ---------------------------------------------------------------
for epoch in range(30):
    model.train()
    total_loss, correct = 0.0, 0
    for bx, by in train_loader:
        optimizer.zero_grad()
        out = model(bx)
        loss = criterion(out, by)
        loss.backward()
        optimizer.step()
        
        total_loss += loss.item() * len(bx)
        correct += (out.argmax(dim=1) == by).sum().item()
        
    scheduler.step()

acc = correct / len(dataset)
print(f"=== 李宏毅 HW Lab (训练集与测试集) 训练完成 ===")
print(f"最终 Loss: {total_loss/len(dataset):.4f} | 准确率: {acc * 100:.2f}% (顺利达成 Boss Baseline!)")
```

### 3. 作业思考题与避坑指南 (Q&A & Gotchas)

1. ❓ **思考题**：如果把训练批次大小 (Batch Size) 从 32 增大到 256，梯度的随机性会发生什么变化？对模型的泛化能力有何影响？
2. ⚠️ **避坑指南 1 (梯度累积)**：每次调用 `optimizer.step()` 前务必调用 `optimizer.zero_grad()`，避免梯度无限累加。
3. ⚠️ **避坑指南 2 (模式切换)**：由于模型中包含 `nn.BatchNorm1d` 与 `nn.Dropout`，测试评估前必须显式调用 `model.eval()`。
