# 🎯 计算图与自动微分

计算图（computation graph）是把一次数学运算拆成「节点 = 操作、边 = 张量」的有向图。它是反向传播在工程上能高效落地的载体：现代框架（PyTorch / TensorFlow / JAX）本质都是在计算图上做**自动微分**。

## 1. 为什么需要计算图

- 一个复杂损失 $L$ 往往是成百上千个基本运算（加、乘、激活、规约）的组合。
- 手工写每个参数的梯度既容易错又难维护；计算图让「求梯度」变成图上的机械遍历。
- 关键收益：**一次前向得到值，一次反向得到所有参数的梯度**，复杂度与边数成正比，而非与参数个数平方相关。

## 2. 前向：建图 + 求值

- 把表达式按运算顺序展开为图。例：$L = (w x + b - y)^2$
  - 节点：`u = w*x` → `v = u + b` → `e = v - y` → `L = e*e`
- 前向遍历：代入具体数值，得到每个节点的输出。
- 此时图里既记录了「拓扑顺序」，也缓存了中间结果，供反向复用。

## 3. 反向：反向模式自动微分（reverse-mode autodiff）

- 核心工具是**链式法则**：对图中每个节点，计算其关于输出的局部梯度（局部雅可比），再沿边向后乘加。
- 从输出节点 $L$ 出发，给 $L$ 赋「上游梯度」1，按逆拓扑序向后传播：
  - 每个节点收到的「上游梯度」×「局部梯度」= 它自己的梯度；
  - 继续向下游节点传递。
- 这就是**反向传播（backprop）**：计算图视角下的链式法则工程实现。

## 4. 与反向传播的关系

- 反向传播 ≠ 计算图；反向传播是**算法**，计算图是**数据结构 / 表示**。
- 没有显式建图也能手推反向传播（见 [[机器学习-反向传播算法|反向传播算法]]）；但框架把「建图 + 自动求逆」自动化，才让深层网络可训练。
- 训练时分工：计算图 + 反向传播负责**算梯度**，优化器（[[机器学习-梯度下降|梯度下降]] / Adam 等）负责**用梯度更新参数**。

## 5. 工程注意点

- **不可微点**：ReLU、取整、argmax 等处的次梯度约定要确认，否则自动微分结果依赖框架默认选择。
- **静态图 vs 动态图**：TF 1.x 类静态图先建全图再跑；PyTorch 类动态图边跑边建。对课程理解，重点在「反向模式如何在图上求梯度」，与是否静态无关。
- **显存-时间权衡**：反向需要前向缓存的中间激活，因此训练比纯推理吃显存。

## 6. 知识连接

- 数学前置：链式法则（与 [[机器学习-反向传播算法|反向传播算法]] 共用）。
- 模型载体：神经网络（[[机器学习-神经网络|神经网络]]）的前向/反向都跑在计算图上。
- 训练闭环：计算图产出梯度 → 优化器（[[机器学习-梯度下降|梯度下降]]）更新权重 → 下一轮前向。
