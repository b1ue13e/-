# 分布式强化学习 (Distributed RL)

## 0. 学习边界

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：单机 RL 的瓶颈在"环境交互"与"梯度更新"串行。大规模 RL（Atari 基准、围棋、机器人）依赖分布式架构把数据收集与训练解耦。Ape-X / IMPALA / R2D2 / SEED 是四种代表路线，面试与论文高频。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：
> 单个 actor 与环境交互很慢，且 on-policy 算法每步都要用新策略重采，吞吐上不去。想把训练扩展到成百上千 CPU / TPU，必须让"采样"与"学习"并行、并容忍 actor 与 learner 之间的策略延迟。

**分布式 RL 的答案**：用多个并行 actor 加速数据采集，用中心化 learner 做更新；差异在于**如何修正 actor 与 learner 的策略偏差（off-policy correction）**以及**如何摆放推理与训练**。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：[[DQN深度Q网络]] 与 [[A3C算法]] 的分布式扩展；[[PPO近端策略优化]] 也常用向量化环境并行（见 [[PPO 工程实践与调参]]）。
- **实际应用场景**：Atari 基准、AlphaGo/AlphaZero 式搜索树、大规模机器人仿真、LLM RLHF 的 rollout 集群。
- **高频题型/任务**：对比 Ape-X / IMPALA / R2D2 / SEED 的架构与离策略修正机制。

---

## 3. 学它之前需要哪些前置知识？

1. **[[Q-Learning算法]]**：DQN 系列（Ape-X / R2D2）的基座。
2. **[[A3C算法]]**：A3C 异步多 worker 是 IMPALA 的前身。
3. **[[Actor-Critic架构]]：中心化 learner + 分布式 actor 的通用框架。

---

## 4. 用直觉语言解释它

> «"餐厅里一个厨师（learner）炒菜太慢，因为要自己买菜（交互）。于是雇 50 个采购员（actor）分头买菜送后厨；问题是采购员路上政策会变（策略延迟），厨师得判断'这菜是按老菜单还是新菜单买的'（离策略修正）。"»

- **一句话直觉本质**：**把 RL 的'采样'和'学习'拆开并行，并用修正机制消化二者之间的策略偏差。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 四种代表架构

| 架构 | 类型 | 离策略修正 | 核心思想 |
| :--- | :--- | :--- | :--- |
| **Ape-X** | 分布式 DQN | PER（优先经验回放） | 多 actor 写共享 PER，单 learner 更新 |
| **IMPALA** | 分布式 AC | **V-trace** | 中心 learner + 数百 actor，异步修正偏差 |
| **R2D2** | 递归分布式 DQN | n 步回报 + 目标网络 | Ape-X + LSTM + 序列回放 |
| **SEED** | 引擎化分布式 | actor-learner 共置 | 推理放加速硬件引擎，零网络传输 |

### 2. 核心公式（Ape-X / IMPALA）
Ape-X：一组并行 actor 各自 $\epsilon$-greedy 探索、把转移写入**共享优先级经验池**；单个 learner 用 PER 采样更新 Q 网络，再把新参数推回 actor。

IMPALA 用 **V-trace** 把 actor 策略 $\mu$ 采的轨迹校正回 learner 策略 $\pi$：
$$v_s = V(s) + \sum_{l\ge 0} \gamma^l \Big(\prod_{i\le l} c_i\Big)\big(r_l + \gamma V(s_{l+1}) - V(s_l)\big)$$
其中截断系数 $c_i=\min(\bar{c},\,\rho_i)$，$\rho_i=\dfrac{\pi(a_i|s_i)}{\mu(a_i|s_i)}$ 是重要性比率。

### 3. 符号说明表

| 符号 | 含义 | 备注 |
| :--- | :--- | :--- |
| actor | 并行采样器 | 只采环境，不更新网络（Ape-X） |
| learner | 中心更新器 | 算梯度、更新参数 |
| PER | 优先经验回放 | 按 TD 误差优先级采样 |
| V-trace | 离策略修正 | IMPALA 专用 |
| $\rho_i$ | 重要性比率 | actor/learner 策略比 |

### 4. 变体与适用条件
- **Ape-X**：value-based、off-policy，吞吐极高；适合 Atari。
- **IMPALA**：policy-based、容许多 actor 异步，吞吐与稳定性兼得。
- **R2D2**：部分可观 / 需时序记忆（LSTM）的任务。
- **SEED**：推理延迟是瓶颈、且有加速硬件的场景。

---

## 6. 推导思路和思想来源

- **最初困难**：串行采样慢、on-policy 复用受限。
- **关键"转念"**：actor 与 learner 解耦；若允许 actor 用旧参数（off-policy），就得用 V-trace / 重要性截断把返回值校正回 learner 策略。
- **设计轴**：① 数据并行（Ape-X）vs 算法并行（IMPALA）vs 引擎化（SEED）；② 是否带循环结构（R2D2）。

---

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（Ape-X）
50 个 actor 同时玩 Atari，learner 每秒更新数千步；actor 只采样，learner 才更新——若误让 actor 也更新网络，参数会互相覆盖。

### 例子 2：中等例子（IMPALA V-trace）
1 learner + 数百 actor，用 V-trace 修正 off-policy 偏差；256 actor 吞吐可达百万步/秒级。若直接异步、忽略 V-trace，会引入大 off-policy 偏差。

### 例子 3：实际应用例子（R2D2 / SEED）
- R2D2：递归（LSTM）agent + 大 replay（如 100 万帧）+ 多步回报 $n=5$；回放时整段序列送 LSTM，避免 RNN 状态错乱。$n=5$ 多步使 TD 偏差下降。
- SEED：actor 与 learner 共置同进程（每 TPU 核一 actor+learner），零网络传输；延迟从毫秒级降到微秒级。

---

## 8. 常见误区和易混概念

### 误区 1：actor 也更新网络
- **错误直觉**：分布式就是多份完整训练。
- **为什么错**：Ape-X 中 actor 只采样，更新集中在 learner；否则参数冲突。
- **正确理解**：分布式 RL 大多"并行采样 + 中心更新"。

### 误区 2：异步 = 无视策略偏差
- **错误直觉**：IMPALA 异步就直接学。
- **为什么错**：actor 用旧参数采，与 learner 策略有延迟偏差，必须用 V-trace 校正。
- **正确理解**：异步节省同步等待，但必须用离策略修正补回偏差。

### 概念对比表

| 架构 | 修正机制 | 适用 |
| :--- | :--- | :--- |
| Ape-X | PER | value-based / Atari |
| IMPALA | V-trace | policy-based / 大规模 |
| R2D2 | n 步 + LSTM | 部分可观 |
| SEED | 引擎化共置 | 推理瓶颈 |

#### 1. Ape-X 如何并行化 DQN？actor 与 learner 职责如何划分？
> [!question]- 答案解析
> - **答案**：多 actor 各自 $\epsilon$-greedy 探索写共享 PER，单 learner 用 PER 采样更新 Q 并回传参数；actor 只采样、learner 更新。

#### 2. IMPALA 用什么机制修正离策略偏差？与 A3C 区别？
> [!question]- 答案解析
> - **答案**：V-trace 截断重要性比率校正返回值；A3C 是每 worker 独立更新（on-policy 限制强），IMPALA 中心 learner + 异步 actor + 离策略修正。
