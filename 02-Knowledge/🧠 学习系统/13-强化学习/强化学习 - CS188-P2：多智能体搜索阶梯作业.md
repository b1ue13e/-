# 强化学习 - CS188-P2：多智能体搜索阶梯作业

> 🎯 **作业目标**：在 Pacman 与 Ghost 的对抗环境中实现 Minimax、Alpha-Beta 剪枝、Expectimax 与自定义 Evaluation Function，通过 CS188 官方 autograder，并在 mediumClassic 上完成多 agent 策略的分数对比。

---

## 1. ⚙️ 环境与 Starter Code（CS188 官方 Pacman 项目）

- **官方来源**：Berkeley CS188 Intro to AI Project 2 Multi-Agent Search（http://ai.berkeley.edu/project_overview.html）
- **关键文件**：`multiAgents.py`（实现 MinimaxAgent / AlphaBetaAgent / ExpectimaxAgent / betterEvaluationFunction）、`pacman.py`、`game.py`、`util.py`、`autograder.py`
- **核心依赖**：Python 3 + 官方 pacman 项目包（纯对抗搜索，无深度学习依赖）
- **运行方式**：

```bash
python pacman.py -p MinimaxAgent -l minimaxClassic -a depth=2      # 深度受限 Minimax
python pacman.py -p AlphaBetaAgent -a depth=3 -l smallClassic      # 剪枝版
python pacman.py -p ExpectimaxAgent -l minimaxClassic -a depth=3   # 随机 Ghost 假设
python autograder.py -q q1 -q q2                                   # 官方自动评测（按题打分）
```

- **验收口径**：autograder 按 q1 Minimax → q5 Bonus 逐题打分（共 5 题，q3 为 Expectimax、q4 为 Evaluation Function），检查决策正确性与（q2/q3）剪枝后节点访问数；只允许补全 `multiAgents.py`，不得修改评测逻辑。

## 2. 🎯 阶梯式 Baseline / 难度设计 (4-Tier Difficulty)

| 梯度级别 | 评测环境 / 验收 | 关键实现细节与要求 |
| :--- | :--- | :--- |
| 🟢 **L1 - Simple Baseline** | minimaxClassic，autograder q1 | 实现 `MinimaxAgent.getAction`：Max 层（Pacman）与 Min 层（Ghost）交替递归，叶子用评估函数估值并返回最佳行动；depth=2 通过官方测试。 |
| 🟡 **L2 - Medium Baseline** | smallClassic / mediumClassic，autograder q2 | 实现 `AlphaBetaAgent`：alpha（Max 下界）/ beta（Min 上界）剪枝，决策与 Minimax 完全一致但访问节点数显著减少；正确处理深度限制与终止状态。 |
| 🔴 **L3 - Strong Baseline** | minimaxClassic（随机 Ghost），autograder q3 | 实现 `ExpectimaxAgent`：Ghost 层改为期望值（各行动估值加权平均）而非取最小，模拟随机 Ghost 行为；对比与 Minimax 的决策差异。 |
| 👑 **L4 - Boss Baseline** | mediumClassic，autograder q4 + q5（Bonus） | 设计 `betterEvaluationFunction`：综合当前分数、最近食物距离、最近鬼距离与危险惩罚；在 mediumClassic 上多次运行，对比 Minimax / Alpha-Beta / Expectimax 的平均得分与胜率。 |

```bash
# 官方 autograder 全量评测（P2 共 5 题）

# 单题复跑

python autograder.py -q q4   # betterEvaluationFunction
```

```python
# 本地轻量断言：剪枝不得改变最优决策
from multiAgents import MinimaxAgent, AlphaBetaAgent

def test_alpha_beta_equals_minimax():
    state = load_state("minimaxClassic")      # 简化示意：固定种子构造游戏状态
    mm = MinimaxAgent(depth=2).getAction(state)
    ab = AlphaBetaAgent(depth=2).getAction(state)
    assert mm == ab, "Alpha-Beta 只剪枝不改变决策，最优行动必须与 Minimax 一致"
```

## 🃏 Anki 卡片

- Q: Minimax 中 Max 层与 Min 层的价值函数如何递归定义？
- A: Max 层取子节点最大值（Pacman 选对自己最有利的行动），Min 层取子节点最小值（Ghost 选对 Pacman 最不利的回应）；叶子或到达深度限制时返回 Evaluation Function 估值。
- Q: Alpha-Beta 剪枝为什么不影响最终决策？
- A: alpha 是 Max 层已知价值下界、beta 是 Min 层已知价值上界；一旦某分支 alpha ≥ beta，该分支不可能影响根节点决策，直接剪掉，结果与完整 Minimax 完全一致，只是少遍历节点。
- Q: Expectimax 与 Minimax 的本质区别？
- A: Minimax 假设 Ghost 总是选最坏结果（Min 层取最小值）；Expectimax 假设 Ghost 按概率分布随机行动，Min 层改为对子节点估值求期望（加权平均），更贴近真实随机 Ghost 的行为。
- Q: Evaluation Function 设计的关键权衡是什么？
- A: 既要足够接近真实价值（纳入未来信息：到最近食物距离、被鬼包围风险），又要计算廉价（搜索树每个叶子节点都要调用）；常用「分数 − 食物距离 + 鬼距离惩罚」加权组合，需调参平衡。
