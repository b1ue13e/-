# 哈希表HashTable

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：6.006 中哈希表是"集合/字典"接口的默认实现（Lec 4），是图算法 `visited` 集合与 `dist` 映射（[[图遍历BFS与DFS]]、[[Dijkstra最短路径]]）的底层依赖；HW02 官方 PS4 与 BYOW 作业直接考它，也是面试最高频的数据结构。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：我们要在动态数据集上做"插入、删除、查找"。数组查找 $O(1)$ 但插删 $O(n)$；链表插删 $O(1)$ 但查找 $O(n)$；平衡树（[[红黑树]]）三者 $O(\log n)$ 已很好——但"按 key 直接取 value"的字典需求太普遍，我们希望**平均 $O(1)$** 完成全部操作，因此必须引入哈希表：用**散列函数**把任意 key 映射到数组下标，让"在哪里找"由 key 自己决定，而不是靠比较。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：6.006 的 Set/Dict 接口标准实现；后续图算法（BFS 的 `visited`、Dijkstra 的 `dist`）默认它存在；HW02 PS4 直接考查。
- **实际应用场景**：数据库索引、缓存、编译器符号表、Python `dict`/`set`、Java `HashMap`；LeetCode 约三成题目的优化靠它。高频题型：散列函数设计、负载因子分析、冲突策略选型、扩容均摊、查重、与平衡树取舍论证。

---

## 3. 学它之前需要哪些前置知识？

1. **[[知识地图/复杂度分析|复杂度分析]]**：需区分最坏/平均/均摊，否则看不懂"平均 O(1) 但最坏 O(n)"。
2. **[[知识地图/数组与链表|数组与链表]]**：哈希表底层就是"数组 + 链表"；数组随机访问 O(1) 是散列成立的前提。

---

## 4. 用直觉语言解释它

> «"哈希表就像图书馆的索引卡柜：每本书（key）按书名算出该进哪个抽屉（桶），找书直接开那个抽屉，而不是全馆一本本翻。抽屉太挤（冲突）就在抽屉里挂挂钩串起来（链地址法）；柜子太满就换大柜子重新分书（动态扩容）。"»

- **直觉类比/几何图像**：散列函数 = 确定性魔术：同一 key 永远算出同一下标；不同 key 可能撞格（冲突），用"挂链表"或"往后找空位"解决。
- **为什么很自然**：数组随机访问是 $O(1)$，只要把"任意 key"变成"数组下标"，查找就退化为数组访问——剩下的问题只有冲突。
- **一句话直觉本质**：**用散列函数把无限 key 空间压进有限数组，用冲突解决策略收拾"压不进去"的边角料，用动态扩容控制负载因子——换来平均 $O(1)$ 的字典操作。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **哈希表**：以"散列函数 + 数组 + 冲突解决策略"实现字典接口（`insert/delete/search`）的数据结构。
- **散列函数**：$h: U \to \{0,1,\dots,m-1\}$，把全域 $U$ 的 key 映射到表长 $m$ 的下标。
- **简单一致散列假设**：每个 key 等可能且独立地散列到 $m$ 个槽之一。

### 2. 核心公式
链地址法期望查找代价（$\alpha = n/m$）：
$$\text{不成功查找} = 1 + \alpha,\qquad \text{成功查找} = 1 + \frac{\alpha}{2}$$
倍增扩容均摊：$n$ 次插入总代价 $O(n)$，单次均摊 $O(1)$。

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $m$ | 表长（槽数） | 正整数 | 常取素数 |
| $n$ | 已存元素数 | $\le$ 容量 | |
| $\alpha = n/m$ | 负载因子 | $\ge 0$ | 链地址下即期望链长 |
| $h(k)$ | key $k$ 的散列值 | $\{0,\dots,m-1\}$ | 需均匀、快速、确定 |

### 4. 常见变体与适用条件
- **变体**：链地址法、开放寻址（线性探测/双重散列）、布谷鸟散列、完美散列。
- **适用条件**：只按 key 存取、无需有序遍历；key 可哈希（不可变）。
- **限制条件**：无序（无法范围查询）、最坏 $O(n)$（恶意 key 全冲突）、依赖散列质量与负载因子控制。

---

## 6. 推导思路和思想来源

- **最初困难**：数组找快插删慢、链表插删快找慢、平衡树 $O(\log n)$——能否"找、插、删"全常数？
- **直接方法局限**：任何基于比较的查找有 $\Omega(\log n)$ 下界（决策树），必须跳出"比较"。
- **关键"转念"**：**不比较，直接算**——散列函数把 key 变下标，把查找变成数组访问；冲突用期望分析消化。
- **推导主线与动机**：数组访问 $O(1)$ → 需要 key→下标映射 → 散列函数 → 冲突不可避免（鸽巢原理 $|U|>m$）→ 链地址摊到链表 → 均匀假设下期望链长 $\alpha$ → 控制 $\alpha$ 常数 → 倍增扩容（每次 $O(n)$，$n$ 次插入总代价 $O(n)$）→ 均摊 $O(1)$。
- **为什么自然得到此结论**："算出来在哪"天然比"找出来在哪"快，代价只是偶尔撞车——概率保证撞车可控。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：$m=7$，$h(k)=k \bmod 7$，依次插入 $10,22,31,4,15$（链地址法），求 $\alpha$ 与不成功查找期望代价。
- **解题思路与关键步骤**：$10\to3, 22\to1, 31\to3, 4\to4, 15\to1$；槽 3 链 $10\to31$，槽 1 链 $22\to15$，槽 4 放 $4$。最终答案：$n=5,m=7,\alpha=5/7\approx0.71$，期望比较 $1+\alpha\approx1.71$。
- **易错点**：把 $\alpha$ 算成 $n$ 或 $m$；忘记期望公式前提是均匀散列。
- **🤔 追问**：改用开放寻址线性探测会怎样？——产生**聚集**，连续占用让后续探测变长，这正是双重散列存在的原因。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：$n=1000$ 要求不成功查找期望比较 $\le 2$：链地址法需多大表？开放寻址（线性探测）呢？
- **解题思路与完整解答**：链地址 $1+\alpha\le2 \Rightarrow m\ge1000$。开放寻址期望探测 $\approx 1/(1-\alpha)$，需 $\alpha\le0.5$，$m\ge2000$——**开放寻址更省内存但负载因子上限更低**（$\alpha\to1$ 时代价爆炸，这正是必须提前扩容的原因）。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：Python `dict` 即开放寻址哈希表，负载因子约 2/3 触发倍增扩容；`visited=set()` 是图算法 O(1) 查询的基础。教学实现：
```python
class HashTable:                     # 链地址法 + 倍增扩容（教学用）
    def __init__(self, m=8):
        self.m, self.n, self.buckets = m, 0, [[] for _ in range(m)]
    def _hash(self, k): return hash(k) % self.m
    def _resize(self):
        old, self.m = self.buckets, self.m * 2
        self.buckets = [[] for _ in range(self.m)]
        for b in old:
            for k, v in b: self.buckets[self._hash(k)].append((k, v))
    def set(self, k, v):
        b = self.buckets[self._hash(k)]
        for i, (kk, _) in enumerate(b):
            if kk == k: b[i] = (k, v); return
        b.append((k, v)); self.n += 1
        if self.n > self.m: self._resize()   # α>1 扩容
    def get(self, k):
        for kk, v in self.buckets[self._hash(k)]:
            if kk == k: return v
        raise KeyError(k)
```

## 8. 常见误区和易混概念

### 误区 1：以为"哈希表查找是严格 O(1)"
- **错误直觉**：查找永远常数时间。
- **为什么错**：$O(1)$ 是**期望/均摊**意义；全冲突时最坏 $O(n)$。
- **正确理解**："平均 O(1)"须带两个前提：散列均匀 + 负载因子受控（必要时扩容）。

### 误区 2：以为"扩容后查找变慢"
- **错误直觉**：扩容要重散列所有元素，是灾难。
- **为什么错**：倍增扩容下 $n$ 次插入总代价 $O(n)$（见第 11 节题 4），均摊仍 $O(1)$。
- **正确理解**：偶尔慢一次（$O(n)$），长期平均不变——这是 6.006 PS4 table doubling 的考点。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 哈希表 | 按 key 存取 | 平均 $O(1)$、无序 | 字典/查重/缓存 |
| 平衡树（[[红黑树]]） | 有序动态集合 | $O(\log n)$ 最坏、可范围查询 | TreeMap、需序场景 |
| 有序数组 | 静态有序集 | 二分 $O(\log n)$、插入 $O(n)$ | 只读数据 |

### 题目与解析

#### 1. 为什么说哈希表查找是"平均 O(1)"而不是"严格 O(1)"？
> [!question]- 答案解析
> - **答案**：$O(1)$ 建立在两个前提上：散列均匀（简单一致散列假设）+ 负载因子受控（表满扩容）；否则全冲突时退化为 $O(n)$。期望意义而非最坏保证，这是它与平衡树最本质的区别（对应误区 1）。标签：`#自测题/基础`

#### 2. 表长 $m=10$，已存 $n=7$（链地址法），求负载因子与不成功查找期望比较次数。
> [!question]- 答案解析
> - **答案**：$\alpha=0.7$；期望比较 $=1+\alpha=1.7$。解析：不成功查找遍历整条链（期望 $\alpha$）加定位 1 次；成功查找为 $1+\alpha/2\approx1.35$。易错：混淆成功/不成功公式。

#### 3. 什么场景应选平衡树而非哈希表？
> [!question]- 答案解析
> - **答案**：需要有序遍历/前驱后继/范围查询，或要求最坏 $O(\log n)$ 保证（实时系统）时。解析：哈希表无序且最坏 $O(n)$；平衡树牺牲常数因子换有序性与最坏保证。易错：只看单点查找速度而忽略"有序性"维度。

#### 4. 为什么倍增扩容后单次插入仍均摊 O(1)？若每次只加 1 个槽呢？
> [!question]- 答案解析
> - **答案**：倍增时扩容发生在第 $1,2,4,\dots$ 次插入，总重散列代价 $O(1+2+4+\cdots+n)=O(n)$，均摊 $O(1)$；每次加 1 槽则 $O(n)$ 次 $O(n)$ 扩容，均摊 $O(n)$。解析："偶尔大代价"须被"频繁小操作"摊薄——势能法（势 $=2n-m$）。易错：只看单次扩容不看总代价。

#### 5. 简单一致散列假设下，证明链地址法一次不成功查找的期望时间为 O(1+α)。
> [!question]- 答案解析
> - **答案**：设指示变量 $X_i^{(j)}$ 表示第 $j$ 个 key 散列到槽 $i$，则槽 $i$ 链长 $n_i=\sum_j X_i^{(j)}$；由线性期望 $E[n_i]=n\cdot\frac{1}{m}=\alpha$。不成功查找 = 算 $h(k)$（$O(1)$）+ 遍历期望 $\alpha$ 个元素，总期望 $O(1+\alpha)$；$\alpha=O(1)$ 时即 $O(1)$。解析：CLRS 11.2 标准证明，工具是指示变量 + 线性期望（PS4 证明题模板）。易错：跳过指示变量直接"感觉"结论。
