# 线性排序计数与基数排序

---

## 0. 先判断它值不值得深挖

- **类别**：**B 类（常用工具，值得掌握）**
- **判断理由**：它不是"万能排序"，但在**键是（或能映射成）小范围整数**的场景里，它是唯一能突破 $\Omega(n\log n)$ 下界的武器（6.006 Lec 5）；更重要的是它逼你理解"比较排序下界"这个复杂度理论基石，以及"稳定性"这个在后续（后缀数组、基数排序、多关键字排序）反复出现的概念。HW01 排序专题值得补充。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：归并、快排、堆排都受限于**比较排序下界**——任何只靠"两两比较"的排序至少 $\Omega(n\log n)$ 次比较。但现实里大量排序任务的键是**小范围整数**：0~100 的分数、0~255 的字节、0~9 的数字。它们根本不需要"比较大小"——可以直接**用数组下标当"排名"**：数一数每个键出现几次，就能算出每个元素该放哪个位置。这就是计数排序；把多位数字拆开逐位排，就是基数排序。**用"键的结构"换"时间的下界"**，是这类算法的核心思想。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：6.006 Lec 5 位于"排序 → 哈希"的交界：线性排序展示了"键有结构时可突破比较下界"，为 Lec 4/8 的哈希（同样是"用键结构换时间"）做铺垫。比较排序下界 $\Omega(n\log n)$ 是决策树思想的首次登场，也是[[知识地图/复杂度分析|复杂度分析]] 的巅峰应用之一。
- **实际应用场景**：按分数/年龄/频次排序（计数排序）、**后缀数组构建**（基数排序是核心步骤）、字符串排序（字典序）、多关键字排序（先次关键字再主关键字）、GPU 上的整数排序。**高频题型/任务**：判断何时线性排序适用、计数排序手算、基数排序轮数与复杂度、稳定性判断、写出稳定版本、用决策树证明 $\Omega(n\log n)$。

---

## 3. 学它之前需要哪些前置知识？

1. **[[知识地图/复杂度分析|复杂度分析]]**：理解 $O(n+k)$ 的意义与"比较下界 $\Omega(n\log n)$"的证明框架（决策树）。
2. **[[知识地图/数组与链表|数组与链表]]**：计数数组 $C[0..k-1]$ 的下标寻址是计数排序的全部"魔法"。**[[知识地图/递归|递归]]**：归并排序的分治结构是"比较排序"的参照系；"稳定归并"为稳定性概念提供例子。

## 4. 用直觉语言解释它

> «"计数排序就像按成绩发卷子：老师先数一数每个分数段有几个人（计数），再算出'比我低的人一共有几个'（前缀和），于是每张卷子该放第几个位置就一目了然——根本不用把卷子两两比较。基数排序则像整理一沓身份证：先按个位数字分成 10 摞，再把 10 摞按顺序叠回去；然后按十位再来一遍……只要每轮都是'稳定'地收（同一数字保持原来的相对顺序），低位的顺序就永远不会被高位打乱，最后自然完全有序。"»

- **直觉类比/几何图像**：发卷子/分桶 + 前缀和定位；基数排序 = 多轮稳定分桶，像字典按字母逐位排序。
- **为什么很自然**：比较排序浪费了"键本身"的信息；计数排序把键直接映射到数组下标，一步到位；基数排序把大整数拆成多位小整数，用"轮数×小计数排序"摊薄成本。**一句话直觉本质**：**不比较、只计数——用小范围整数键的下标做排名（计数排序），或把大键拆成多轮小键的稳定排序（基数排序），从而把排序做到 $O(n)$ 量级。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **计数排序（Counting Sort）**：输入 $n$ 个键在 $[0,k-1]$ 内的整数；用计数数组 $C$ 统计频次，转前缀和得到"每个键的最后一个位置"，**从后往前**扫描输入放置元素（保证稳定），即得有序输出。复杂度 $O(n+k)$，空间 $O(n+k)$。
- **基数排序（Radix Sort, LSD）**：对 $d$ 位数字，从**最低位**到最高位，每轮对当前位做一次**稳定**的计数排序；$d$ 轮后整体有序。复杂度 $O(d(n+k))$，$k$ 为每位的取值范围（如 10 进制 $k=10$，字节 $k=256$）。
- **稳定性**：相等键的元素在排序后保持原有相对顺序。计数排序（从后往前版）、归并排序稳定；快排、堆排不稳定。

### 2. 核心公式
$$T_{\text{counting}}=O(n+k),\qquad S_{\text{counting}}=O(n+k)$$
$$T_{\text{radix}}=O\big(d(n+k)\big)\qquad(\text{LSD，d 位、每位 k 种取值})$$
比较排序下界：
$$T_{\text{comparison}}=\Omega(n\log n)\quad(\text{决策树：}n!\text{ 个叶子，树高}\ge\log_2 n!)$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $n$ | 元素个数 | $\ge 1$ | |
| $k$ | 键的取值范围大小 | $\ge 1$ | $k=O(n)$ 时计数排序 $O(n)$ |
| $d$ | 键的位数 | $\ge 1$ | 基数排序的轮数 |
| $C[i]$ | 键值 $i$ 的计数/位置 | $0..n$ | 前缀和后为"末位置" |
| $B[i]$ | 输出数组 | — | 从后往前放保稳定 |

### 4. 常见变体与适用条件
- **变体**：计数排序（稳定版/不稳定版）、基数排序（LSD 低位优先、MSD 高位优先）、桶排序（键均匀分布时 $O(n)$ 期望）、鸽巢排序。**适用条件**：键为小范围整数（或可双射映射到小范围）、需要 $O(n)$ 且空间可承受；**限制**：$k$ 大时 $O(k)$ 空间时间爆炸，浮点/字符串需先映射，MSD 需递归分桶实现复杂。

---

## 6. 推导思路和思想来源

- **最初困难**：所有比较排序（选择/插入/归并/快排/堆排）最坏都是 $\Omega(n\log n)$，似乎"排序就该这么慢"。**直接方法局限**：比较是"黑盒"——每次比较只产生 1 bit 信息，$n!$ 种排列需要 $\log_2(n!)=\Omega(n\log n)$ 次比较；想更快必须**绕开比较**。
- **关键"转念"**：**用键的取值本身当地址**——计数数组的下标就是键值，频次+前缀和直接给出排名，不需要任何两两比较；稳定性则靠"从后往前放置"这个顺序技巧保住。
- **推导主线与动机**：决策树证明下界（叶子 = $n!$ 种排列，比较次数 = 树高 $\ge\log_2 n!$）→ 指出突破下界的唯一出路是不比较 → 计数排序：频次统计 + 前缀和定位 → 稳定性技巧 → 基数排序：LSD 逐位稳定排序的正确性（归纳：处理完低 $i$ 位后按低 $i$ 位有序；高位的稳定排序不破坏低位序）→ 复杂度 $O(d(n+k))$ 与"$k=O(n)$ 时线性"的选型。
- **为什么自然得到此结论**：整数键天然有序且取值范围已知——这是比较排序浪费掉的结构信息；"排名 = 小于等于我的个数"是前缀和的自然含义；"低位先排、高位稳定覆盖"是字典序排序的逐位自然分解。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：对 $[3,1,2,0,3]$ 做计数排序（$k=4$），写出每步数组。
- **解题思路与关键步骤**：计数：$C=[1,1,1,2]$。前缀和（末位置+1）：$C=[1,2,3,5]$。从后往前扫描输入（下标 4 起）：$3$ → 放 $C[3]-1=4$ 位，$C[3]=4$；$0$ → 放 $C[0]-1=0$ 位，$C[0]=0$；$2$ → 放 $C[2]-1=2$ 位，$C[2]=2$；$1$ → 放 $C[1]-1=1$ 位，$C[1]=1$；$3$ → 放 $C[3]-1=3$ 位。输出 $[0,1,2,3,3]$。
- **最终答案**：$[0,1,2,3,3]$，稳定（两个 3 保持原先后顺序）。
- **易错点**：前缀和存的是"末位置"（从 0 计数需减 1）；**必须从后往前**扫描，从前往后放会破坏稳定性；下标越界（键 ≥ k）要先检查。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：对三位数 $[329,457,657,839,436,720,355]$ 做 LSD 基数排序，列出每轮结果；说明为什么不能用不稳定排序。
- **解题思路与完整解答**：第 1 轮按个位稳定排序：$[720,355,436,457,657,329,839]$（个位 0,5,6,7,7,9,9）。第 2 轮按十位稳定排序：$[720,329,436,839,355,657,457]$（十位 2,2,3,3,5,5,5）。第 3 轮按百位稳定排序：$[329,355,436,457,657,720,839]$。**为什么必须稳定**：第 2 轮后"个位有序"靠的是第 1 轮结果；第 3 轮若不稳定，百位相同的组（如 329 与 355）内部会乱掉，个位/十位序丢失。**易错点**：轮次是**低位到高位**（LSD）；每轮都是完整计数排序（含前缀和与从后往前放）；位数不足补 0。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：**后缀数组**（字符串算法基石）用基数排序对"二元组排名"排序；GPU/数据库的整数排序；按"年级(主) + 学号(次)"双关键字排序。稳定计数排序代码：
```python
def counting_sort(arr, k):
    """arr: [0, k) 内整数；稳定版，O(n+k)"""
    n = len(arr)
    cnt = [0] * k
    for x in arr: cnt[x] += 1
    for i in range(1, k): cnt[i] += cnt[i - 1]   # 前缀和 = 末位置+1
    out = [0] * n
    for x in reversed(arr):                      # 从后往前：稳定
        cnt[x] -= 1
        out[cnt[x]] = x
    return out

def radix_sort(arr, d, base=10):
    for pos in range(d):                         # LSD：从个位到最高位
        arr = counting_sort_digit(arr, pos, base)  # 对第 pos 位稳定排序
    return arr
```
复杂度：计数排序 $O(n+k)$（$k=O(n)$ 时线性）；基数排序 $O(d(n+k))$；后缀数组场景 $d\approx\log_k(\max)$ 轮。

## 8. 常见误区和易混概念

### 误区 1：以为"计数排序能排任意键"
- **错误直觉**：任何数据都能转成整数，计数排序就都能用。
- **为什么错**：计数排序的代价是 $O(n+k)$，$k$ 是**取值范围**不是元素个数；键取值范围大（如 64 位整数、浮点、字符串）时 $k$ 天文数字，空间时间双爆炸。**正确理解**：适用前提是"键可高效映射到小范围整数"（$k=O(n)$）；否则老老实实用比较排序。

### 误区 2：以为"基数排序永远比快排快"
- **错误直觉**：$O(d(n+k))$ 是线性的，肯定优于 $O(n\log n)$。
- **为什么错**：$d\approx\log_k(\max)$ 不是常数；64 位整数 $d=64$ 轮（若 $k=2$），$64n$ 的常数、缓存不友好、额外 $O(n)$ 空间，实际未必赢快排；快排的 $n\log n$ 常数极小且原地。**正确理解**：基数排序赢在"$k$ 和 $d$ 都小"（如固定位数的小整数、字节串）；通用场景快排/内省排序仍是默认。

### 误区 3：以为"MSD 和 LSD 实现一样简单"
- **错误直觉**：一个从高位一个从低位，换个方向而已。
- **为什么错**：MSD 每轮后要**递归**处理每个桶（各桶位数不同、需分治），且桶间不排序；LSD 是简单的迭代 $d$ 轮。**正确理解**：LSD 靠"多轮稳定排序的累积"完成全序；MSD 是分治结构，适合字符串且可提前结束，但实现与复杂度分析都更复杂。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 归并/快排/堆排 | 通用排序 | 比较驱动，$\Omega(n\log n)$ | 通用场景 |
| 计数排序 | 小范围整数排序 | 计数+前缀和，$O(n+k)$ | 分数、频次、字节 |
| 基数排序 | 多位整数/字符串 | $d$ 轮稳定计数，$O(d(n+k))$ | 后缀数组、身份证号 |
| 桶排序 | 均匀分布实数 | 分桶+桶内排序，期望 $O(n)$ | 均匀浮点数据 |

### 题目与解析

#### 1. 计数排序的适用条件是什么？为什么它不能取代快排？
> [!question]- 答案解析
> - **答案**：键必须是（或能高效映射为）小范围整数，$k=O(n)$ 时复杂度 $O(n+k)=O(n)$。不能取代快排：键范围大时 $O(k)$ 空间/时间爆炸，且快排原地、常数小、适用任意可比较类型。
> - **解析**：适用条件 = "$k$ 与 $n$ 同量级"。易错：只看"键是整数"就套用，忽略 $k$ 的规模。标签：`#自测题/基础`

#### 2. 手算 $[2,0,2,1,1]$（$k=3$）的稳定计数排序，写出前缀和与放置过程。
> [!question]- 答案解析
> - **答案**：计数 $C=[1,2,2]$；前缀和 $C=[1,3,5]$。从后往前：$1$→位 $2$（$C[1]=2$）；$1$→位 $1$（$C[1]=1$）；$2$→位 $4$（$C[2]=4$）；$0$→位 $0$（$C[0]=0$）；$2$→位 $3$（$C[2]=3$）。输出 $[0,1,1,2,2]$。**解析**：两个 1 落位 2、1（保持原先后）、两个 2 落位 4、3——稳定性来自从后往前。易错：前缀和当作"位置"时忘记减 1。

#### 3. 为什么基数排序的每一轮都必须是稳定排序？给出反例说明。
> [!question]- 答案解析
> - **答案**：第 $i$ 轮只按第 $i$ 位排序，必须保留前 $i-1$ 轮建立的"低 $i-1$ 位有序"性质；若不稳定，第 $i$ 位相同的元素内部会乱序，破坏低位序。反例：两位数 $[19,13]$，第 1 轮按个位稳定排序得 $[13,19]$；第 2 轮按十位（都是 1），不稳定排序可能把 $19$ 放前面输出 $[19,13]$，而正确结果应为 $[13,19]$——正是个位序被破坏。**解析**：正确性证明是归纳"处理完低 $i$ 位后按低 $i$ 位有序"。易错：以为"每轮排完就局部有序，稳定无所谓"。

#### 4. 对 0~999 的整数排序，基数排序（10 进制）的 $d$ 与复杂度是多少？若改二进制 $k=2$ 呢？
> [!question]- 答案解析
> - **答案**：10 进制 $d=3$，$T=O(3(n+10))=O(n)$；二进制 $d=10$（$2^{10}=1024>999$），$T=O(10(n+2))=O(n)$，但常数从 3 变 10，且每轮只按 1 bit 分桶、缓存不友好，实际更慢。
> - **解析**：$d=\lceil\log_k(\max+1)\rceil$；$k$ 与 $d$ 此消彼长，$T=O(d(n+k))$ 需要同时看。易错：只算 $d$ 不看 $k$，误以为二进制最优。

#### 5. 用决策树证明：任何基于比较的排序算法最坏需要 $\Omega(n\log n)$ 次比较。
> [!question]- 答案解析
> - **答案**：对 $n$ 个互异元素，比较结果构成一棵决策树：每条根到叶路径对应一种比较序列，叶子对应最终排列，故叶子数 $\ge n!$。二叉树高度 $h$ 至多有 $2^h$ 个叶子，故 $2^h\ge n!$，$h\ge\log_2(n!)\ge\log_2((n/2)^{n/2})=\Theta(n\log n)$。最坏比较次数 = 树高 ≥ $h$，下界得证。**解析**：斯特林近似 $\log n!=\Theta(n\log n)$ 收尾。易错：忘记"互异元素"假设（有重复时叶子数减少、下界仍成立但表述需小心）；把平均与最坏混为一谈。
