## 💡 问题动机与直观解析

在涉及频繁**单点/区间修改**与**区间和/最值查询**的动态场景中：
- 动态数组单点修改 $\mathcal{O}(1)$，但区间查询需 $\mathcal{O}(n)$。
- 前缀和数组区间查询 $\mathcal{O}(1)$，但单点修改需 $\mathcal{O}(n)$ 更新后续所有元素。

为了打破这种“单点修改与区间查询无法兼得”的瓶颈，引入了高级数据结构：
1. **树状数组 (Fenwick Tree / Binary Indexed Tree)**：代码极简（不足 20 行），以 $\mathcal{O}(\log n)$ 完美支持单点修改与前缀和查询。
2. **线段树 (Segment Tree)**：表达能力极强，结合**懒惰标记 (Lazy Propagation)** 思想，以 $\mathcal{O}(\log n)$ 支持任意区间修改与区间统计（和、最大值、最小值、GCD）。

---

## 📐 算法原理与二进制操作

### 1. 树状数组位运算原理 (`lowbit`)

定义 `lowbit(x)` 为整数 $x$ 在二进制表示下最低位的 $1$ 及其后续 $0$ 构成的数值：
$$\text{lowbit}(x) = x \ \& \ (-x)$$

树状数组节点 $C[i]$ 管理的区间长度正好等于 $\text{lowbit}(i)$，对应区间范围为 $(i - \text{lowbit}(i), i]$。
- **单点更新**：$i \gets i + \text{lowbit}(i)$ 向上沿父节点修改。
- **前缀和查询**：$i \gets i - \text{lowbit}(i)$ 向左剥离已统计区间。

---

### 2. 线段树懒惰标记 (Lazy Propagation)

在执行区间修改（如给区间 $[L, R]$ 内所有元素增加 $v$）时，若递归更新到叶子节点，复杂度将恶化为 $\mathcal{O}(n)$。

**懒惰标记核心策略**：如果当前线段树节点代表的区间 $[l, r]$ 被目标区间 $[L, R]$ **完全覆盖**，则只在该节点上打上 `lazy += v` 标记并更新当前节点累加和，**不再向下递归**！仅当后续查询或修改需要访问其子节点时，才将 `lazy` 标记向下传递一层（Push Down）。

## 💻 树状数组 Python 代码实现

```python
class FenwickTree:
    def __init__(self, n: int):
        self.n = n
        self.tree = [0] * (n + 1)

    @staticmethod
    def _lowbit(x: int) -> int:
        return x & (-x)

    def add(self, i: int, delta: int):
        """单点增加：在 1-indexed 索引 i 处增加 delta"""
        while i <= self.n:
            self.tree[i] += delta
            i += self._lowbit(i)

    def query(self, i: int) -> int:
        """前缀和查询：求 [1, i] 的元素和"""
        s = 0
        while i > 0:
            s += self.tree[i]
            i -= self._lowbit(i)
        return s

    def range_query(self, l: int, r: int) -> int:
        """区间和查询：求 [l, r] 的元素和"""
        return self.query(r) - self.query(l - 1)
```

## 🃏 Anki 卡片

- Q: 树状数组中 `lowbit(x)` 的计算公式及其含义是什么？
- A: `x & (-x)`。它代表 $x$ 在二进制下最低位的 $1$ 对应的十进制数值，等于节点 $C[x]$ 所管理的区间长度。

- Q: 线段树中的懒惰标记 (Lazy Tag) 解决什么问题？
- A: 避免区间修改时递归更新到叶子节点的 $\mathcal{O}(n)$ 开销。通过延迟更新标记，将区间修改复杂度控制在 $\mathcal{O}(\log n)$。
