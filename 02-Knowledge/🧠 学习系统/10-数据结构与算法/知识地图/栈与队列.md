# 栈与队列

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：栈与队列是两大"访问顺序"抽象：递归调用栈（[[递归]]）、DFS/BFS（[[图遍历BFS与DFS]]）都建立在它们之上；**单调栈/单调队列**是面试高频进阶技巧（下一个更大元素、滑动窗口最大值），必考。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：很多算法需要"暂存待处理的工作"，但暂存的**取出顺序**因场景而异：括号匹配需要"后进先出"（最近的左括号先配）、打印机任务需要"先进先出"（先提交先打印）。栈（LIFO）与队列（FIFO）就是这两种顺序的专用容器，把"顺序策略"从业务逻辑里剥离出来。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：栈 = 函数调用/递归/DFS/表达式求值/撤销操作；队列 = BFS/任务调度/缓冲；单调栈与单调队列则是"栈/队列 + 单调性"的进阶组合，服务滑动窗口类题目。
- **实际应用场景**：浏览器后退（栈）、消息队列（Kafka）、打印队列、撤销/重做（双栈）、括号与 HTML 标签校验。
- **高频题型/任务**：括号匹配、最小栈、用栈实现队列、下一个更大元素（单调栈）、滑动窗口最大值（单调队列）、接雨水、柱状图最大矩形。

---

## 3. 学它之前需要哪些前置知识？

1. **[[数组与链表]]**：栈/队列的两种实现（数组 vs 链表）及其代价。
2. **[[复杂度分析]]**：均摊 $O(1)$ 的分析（每个元素入栈/出栈一次）。
3. **[[递归]]**：调用栈是栈的现实原型（可并行理解）。

---

## 4. 用直觉语言解释它

> «"栈就像一摞盘子：后放的盘子先拿走（后进先出）；队列就像排队买奶茶：先来的人先买到（先进先出）。单调栈则像'排队时只留越来越高的人'：新来的人把前面所有比自己矮的挤走（弹出），于是队伍里永远单调——'下一个更高的人'一眼可见。"»

- **直觉类比/几何图像**：盘子摞、奶茶队；单调栈 = 身高淘汰赛。
- **为什么很自然**：LIFO 对应"最近状态优先"（回溯、撤销），FIFO 对应"公平顺序"（调度）；单调性维护把"找下一个更大/更小"从 $O(n^2)$ 压到 $O(n)$。
- **一句话直觉本质**：**栈/队列 = 两种访问顺序的抽象（LIFO/FIFO），数组或链表实现均摊 $O(1)$；单调栈/单调队列 = 进容器时"弹出破坏单调性的元素"，让"窗口极值/下一个更大元素"类问题变成 $O(n)$。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **栈（Stack）**：后进先出（LIFO）；操作 `push`、`pop`、`top`、`empty`，均 $O(1)$。
- **队列（Queue）**：先进先出（FIFO）；操作 `enqueue`、`dequeue`、`front`、`empty`，均摊 $O(1)$（循环数组）。
- **单调栈**：栈内元素保持单调（递增/递减）；入栈时弹出所有破坏单调性的元素。用于"下一个更大/更小元素"、"接雨水"、"柱状图最大矩形"。
- **单调队列**：队内单调 + 维护窗口：新元素从队尾入队并弹出更小者，过期元素从队头出队。用于"滑动窗口最大/最小值"。

### 2. 核心公式
单调栈求"下一个更大元素"（遍历一遍）：
$$\text{对每个 } i:\ \text{while 栈非空 and } A[\text{top}] < A[i]:\ \text{ans}[\text{top}]=A[i];\ \text{pop};\ \text{push } i$$
复杂度：$$T(n)=O(n)\quad(\text{每元素至多入栈/出栈一次}),\quad S(n)=O(n)$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $A[i]$ | 序列第 $i$ 个元素 | 可比较 | |
| $\text{ans}[i]$ | $i$ 的下一个更大元素 | 或 -1 | 单调栈输出 |
| $top$ | 栈顶下标 | 栈内 | 单调栈存下标 |

### 4. 常见变体与适用条件
- **变体**：单调递增/递减栈（方向由"更大/更小"决定）、单调队列（配合固定/可变窗口）、双端队列（deque）、循环队列、双栈（表达式求值：数字栈 + 运算符栈）。
- **适用条件**：需要"最近状态"（栈）、"公平顺序"（队列）、"窗口极值/最近极值"（单调结构）。限制：单调栈只对"单向最近"问题有效（双向最近需左右各扫一次）；窗口类问题需配合滑动窗口语义（[[双指针]]）。

---

## 6. 推导思路和思想来源

- **最初困难**：找每个元素的"下一个更大元素"，朴素两重循环 $O(n^2)$（$10^5$ 数据就超时）。
- **直接方法局限**：对每个 $i$ 向后扫描浪费了大量已比较过的信息。
- **关键"转念"**：**"被弹出"意味着"它的答案已经确定"**——当新元素 $A[i]$ 大于栈顶 $A[t]$ 时，$A[i]$ 就是 $A[t]$ 的下一个更大元素（栈内元素按值单调、按位置递增，中间不可能有更大的），弹出即结算；栈里剩下的元素保持"尚未找到答案"的候选集合。
- **推导主线与动机**：维护"未结算"的下标栈（值单调）→ 每个元素入栈一次、出栈一次 → $O(n)$；单调队列同理：队头是窗口极值，队尾维护单调，过期出队。
- **为什么自然得到此结论**：每对元素至多比较一次（要么结算要么被淘汰），信息不重复——这是"摊还 $O(1)$ 每元素"的典型结构。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：括号匹配 `"({[]})"` 与 `"([)]"`。
- **解题思路与关键步骤**：遇左括号入栈，遇右括号检查栈顶是否匹配：`"({[]})"`：`(`入，`{`入，`[`入，`]`弹`[`✓，`}`弹`{`✓，`)`弹`(`✓，栈空 → 合法。`"([)]"`：`(`入，`[`入，`)`：栈顶`[`≠`)` → 非法。
- **最终答案**：前者合法，后者非法。
- **易错点**：右括号时栈为空（多右括号）；结束时栈非空（多左括号）。
- **🤔 追问**：如何用栈判断"回文"或实现"撤销操作"？——回文用栈比对前半段；撤销 = 操作栈 pop 后反向执行。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：力扣 239 滑动窗口最大值：`nums=[1,3,-1,-3,5,3,6,7]`，窗口大小 3。
- **解题思路与完整解答**：单调递减队列（存下标）。窗口 1 `[1,3,-1]`：1 入队；3 入队弹出 1（3>1）；-1 入队（3>-1 保留）→ 队头 3。窗口 2 `[3,-1,-3]`：-3 入队 → 队头 3。窗口 3 `[-1,-3,5]`：3 出窗（下标过期，队头弹出）；-1 被 5 弹出、-3 被 5 弹出，5 入队 → 队头 5。窗口 4 `[-3,5,3]`：3 入队 → 队头 5。窗口 5 `[5,3,6]`：5 出窗弹出，6 入队弹出 3 → 6。窗口 6 `[3,6,7]`：3 出窗，7 入队弹出 6 → 7。结果 `[3,3,5,5,6,7]`。每元素入队出队各一次，$O(n)$。
- **易错点**：队头过期判断用下标（`q[0] <= i-k`）；先清过期、再维护单调、再入队、最后取队头，顺序别乱。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：单调栈求"下一个更大元素"（LeetCode 496/739）模板：
```python
def next_greater(nums):
    stack, ans = [], [-1]*len(nums)
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            ans[stack.pop()] = x
        stack.append(i)
    return ans
```
真实场景：股票"未来更高价"、温度"回暖日"、接雨水（单调递减栈按"洼地"结算）——单调栈是"离线最近极值"问题的统一解法。

## 8. 常见误区和易混概念

### 误区 1：栈/队列的"底"与"顶"搞反
- **错误直觉**：队列也能 pop 尾部。
- **为什么错**：栈只动一端（顶），队列只动两端各一端（头出尾进）——顺序语义是定义本身。
- **正确理解**：画图标注 push/pop 方向；用双端队列（deque）时明确"哪端是头"。

### 误区 2：单调栈"弹"的时机与方向
- **错误直觉**：找"下一个更大"用单调递增栈（栈顶最小）。
- **为什么错**：栈内自底向上是**递减**的（栈顶最小）——新元素更大时弹出栈顶结算；方向反了答案全错。
- **正确理解**：口诀——"求更大用递减栈（栈顶小者先被淘汰）、求更小用递增栈"；或直接记"弹出条件 = 破坏目标单调性"。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 栈 | 最近状态优先 | LIFO、单端操作 | 括号、DFS、撤销 |
| 队列 | 公平顺序 | FIFO、双端操作 | BFS、任务调度 |
| 单调栈 | 单向最近极值 | 弹出结算、$O(n)$ | 下一个更大、接雨水 |
| 单调队列 | 窗口极值 | 队头过期 + 队尾单调 | 滑动窗口最大值 |

### 题目与解析

#### 1. 栈与队列的本质区别？各自举一个现实例子。
> [!question]- 答案解析
> - **答案**：栈 LIFO（后进先出），如浏览器后退/撤销；队列 FIFO（先进先出），如打印任务/消息队列。
> - **解析**：顺序语义由"取哪端"定义：栈取最近入的，队列取最早入的。
> - **易错原因**：把"栈"与"队列"的实现（数组/链表）与语义混淆。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 判断 `"()[]{}"` 与 `"(]"` 的合法性。
> [!question]- 答案解析
> - **答案**：前者合法：`(`入→`)`匹配弹→`[`入→`]`匹配弹→`{`入→`}`匹配弹，栈空。后者非法：`(`入，`]` 与栈顶 `(` 不匹配。
> - **解析**：右括号必须与"最近的未匹配左括号"配对——正是 LIFO。
> - **易错原因**：用计数（只数左右括号数相等）会漏掉顺序错误（如 `([)]` 计数相等但非法）。

#### 3. 求"下一个更大元素"应该用单调递增栈还是递减栈？为什么？
> [!question]- 答案解析
> - **答案**：自底向上递减的栈（栈顶最小）。新元素更大时，栈顶的"下一个更大元素"就是它，弹出结算；若用递增栈，栈顶是最大的，永远等不到更大的元素来触发结算。
> - **解析**：弹出条件 = "新元素 > 栈顶"；栈内保持"未结算且值递减"。
> - **易错原因**：把"递增/递减"与"求更大/更小"配对搞反。

#### 4. `nums=[2,1,5,6,2,3]`，滑动窗口大小 3，用单调队列求每个窗口最大值。
> [!question]- 答案解析
> - **答案**：窗口1 [2,1,5]→5；窗口2 [1,5,6]→6；窗口3 [5,6,2]→6；窗口4 [6,2,3]→6。单调队列过程（递减）：[2]→[2,1]→5 弹出 2,1 入队 [5]→6 弹出 5 入队 [6]→[6,2]→2 过期？窗口4 队头 6 过期弹出，2 入队 [2]? 精确：窗口4 时 6 下标 3 过期（i-k=1? 窗口 [1,4) 含下标 3），队头 6 过期弹出，2 入队，3 入队弹出 2 → [6? 已过期] [3]，最大值 3？——注意窗口4 是下标 3,4,5 即 [6,2,3]，最大值 6。修正：窗口4 队头 6 下标 3 未过期（3 ≥ 4-3=1），保留 → 最大值 6。
> - **解析**：过期判断用下标 `q[0] <= i-k`；本例展示"队头过期"与"队尾单调"两个动作的配合。
> - **易错原因**：过期下标边界算错（`< i-k` vs `<= i-k`）。

#### 5. 论证单调栈"下一个更大元素"的 $O(n)$ 复杂度与正确性。
> [!question]- 答案解析
> - **答案**：复杂度：每个元素恰好入栈一次、出栈至多一次，总操作 $O(n)$。正确性：① 结算正确——当 $A[i]>A[\text{top}]$ 时，栈内 top 之下元素值更小且下标更早，它们与 $A[i]$ 之间有 top 隔开，故 $A[i]$ 是 top 的"下一个更大"（若有更大者出现在 $A[i]$ 之前，top 早已被弹出）；② 未结算元素留在栈中，最终答案 -1；③ 归纳于处理顺序即得全部正确。
> - **解析**："弹出即结算、结算不再改"是单调栈正确性的核心不变量。
> - **易错原因**：无法解释"为什么中间不会夹着更大的元素"。
