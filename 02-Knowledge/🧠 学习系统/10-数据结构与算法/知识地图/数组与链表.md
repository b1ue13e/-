# 数组与链表

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：数组与链表是所有数据结构的物理基础：[[栈与队列]]、[[堆]]、[[哈希表]] 都建立在它们之上；"随机访问 vs 顺序访问"的取舍贯穿全部算法选型，也是面试最基础的考点。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：程序要存储一组数据，面临两个矛盾的需求：**随机访问**（"给我第 $k$ 个元素"要快）与**灵活增删**（"在中间插一个"要快）。数组用连续内存换随机访问，链表用指针换增删灵活性——**没有一种结构同时擅长两者**，理解这个权衡才能正确选型。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：数组是 [[二分搜索]]、[[堆]]（数组存储）、[[哈希表]]（桶数组）的载体；链表是 LRU 缓存、邻接表（[[图结构]]）的基础。
- **实际应用场景**：内存数据库的行存储 vs 列存储、缓存友好的遍历（数组）、频繁插入删除的文本编辑器（链表/块状链表）。
- **高频题型/任务**：链表反转/环检测（[[双指针]]）、合并有序链表、原地去重、数组第 k 大、设计 LRU（哈希 + 双向链表）。

---

## 3. 学它之前需要哪些前置知识？

1. **[[复杂度分析]]**：用 $O(1)/O(n)$ 描述操作代价是本节语言。
2. **指针/引用概念**（编程基础）：链表节点 = 值 + 指向下一节点的引用。

---

## 4. 用直觉语言解释它

> «"数组就像电影院连排座位：票上写着 12 排 5 座，你直接走到那个位置（$O(1)$ 随机访问）；但要在中间插一个人，所有人都得挪一个位置（$O(n)$）。链表就像寻宝游戏：每个盒子只告诉你下一个盒子的位置，插入新盒子只需'改两张纸条'（$O(1)$），但找第 100 个盒子必须从第一个开始一个个找（$O(n)$）。"»

- **直觉类比/几何图像**：连排座位 vs 寻宝盒子；内存里的"连续房间" vs "散落房间 + 门牌指引"。
- **为什么很自然**：连续内存的地址可算术（`base + k*size`）→ 随机访问；散落内存只能靠指针链 → 顺序访问。物理布局决定操作代价。
- **一句话直觉本质**：**数组 = 连续内存 + 下标寻址（随机访问 $O(1)$、插入删除 $O(n)$）；链表 = 指针串联（插入删除 $O(1)$、访问 $O(n)$）；外加缓存局部性差异——数组遍历快一个数量级。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **数组**：同类型元素的连续内存块；元素 $i$ 的地址 $= base + i\times size$，故随机访问 $O(1)$。
- **链表**：节点（值 + 指针）的非连续集合；单链表（next）、双链表（prev+next）、循环链表。
- **动态数组**：倍增扩容的数组（如 Python list / C++ vector），均摊插入 $O(1)$（见 [[复杂度分析]] 的摊还分析）。

### 2. 核心公式
| 操作 | 数组 | 链表（已知节点指针） |
| :--- | :--- | :--- |
| 随机访问 $A[k]$ | $O(1)$ | $O(n)$ |
| 头部插入 | $O(n)$（整体后移） | $O(1)$ |
| 中间插入 | $O(n)$ | $O(1)$（找位置 $O(n)$） |
| 末尾插入 | 均摊 $O(1)$ | $O(1)$（尾指针） |
| 删除 | $O(n)$ | $O(1)$（双链表） |

地址公式：$$\text{addr}(A[i]) = \text{base} + i\cdot \text{sizeof}(T)$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $A[i]$ | 数组第 $i$ 个元素 | $0\le i<n$ | |
| $\text{base}$ | 数组起始地址 | 内存地址 | |
| $\text{sizeof}(T)$ | 元素类型大小 | 字节 | 地址算术依据 |
| $n$ | 元素个数 | $\ge0$ | |

### 4. 常见变体与适用条件
- **变体**：动态数组、双链表、循环链表、跳表（链表 + 多级索引，$O(\log n)$ 查找）、块状链表（数组 + 链表混合）。
- **适用条件**：读多写少/需随机访问/缓存敏感 → 数组；写多（插入删除频繁）→ 链表。限制：数组扩容搬运 $O(n)$；链表指针开销大（每节点额外 8 字节）且缓存不友好。

---

## 6. 推导思路和思想来源

- **最初困难**：随机访问与灵活增删无法兼得。
- **直接方法局限**：纯数组增删要整体搬移；纯链表访问要逐个爬。
- **关键"转念"**：**把两种需求的代价显式化**——数组赌"访问多"，链表赌"修改多"；工程上用组合结构弥补（动态数组摊还、跳表、块状链表、LRU 用哈希+双链表）。
- **推导主线与动机**：物理存储 → 操作代价推导（地址算术/指针遍历）→ 复杂度表 → 权衡选型；再引入均摊（动态数组）与多级索引（跳表）两个"调和"方案。
- **为什么自然得到此结论**：任何结构都是"用某种操作的代价换另一种操作的便宜"——数组与链表是这个权衡的两个极端，理解极端才能理解中间形态。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：在数组 `[1,3,5,7]` 下标 1 处插入 2，写出搬移过程；在链表 `1→3→5→7` 同样位置插入。
- **解题思路与关键步骤**：数组：从尾部开始 `A[4]=A[3], A[3]=A[2], A[2]=A[1]`，再 `A[1]=2`（3 次搬移 + 1 次写）；链表：新建节点 2，`2.next=3` 所在节点，`1.next=2`（2 次指针修改）。
- **最终答案**：数组 `[1,2,3,5,7]`（$O(n)$）；链表 `1→2→3→5→7`（$O(1)$，若已有指向 1 的指针）。
- **易错点**：数组搬移必须从后往前（否则覆盖）；链表插入顺序"先接后断"（先 `new.next = cur.next` 再 `cur.next = new`）。
- **🤔 追问**：链表中"找第 $k$ 个节点"的代价？——$O(k)$；这就是"数组随机访问 vs 链表顺序访问"的日常体现。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：设计 LRU 缓存（get/put 均 $O(1)$，容量 2）。
- **解题思路与完整解答**：哈希表（[[哈希表HashTable]]）提供 $O(1)$ 定位节点，双向链表维护访问顺序：get 命中 → 把节点移到链表头；put → 若满，删除链表尾节点并删哈希项，新节点插头。示例：容量 2，`put(1,a), put(2,b), get(1)→a（1 移到头）, put(3,c)`：满（1,2）→ 淘汰最久未用的 2，插入 3 → 缓存 {1:a, 3:c}。哈希解决"找节点"，链表解决"记顺序"——两种基础结构各司其职。
- **易错点**：双向链表删除节点要处理前后指针；哈希值与链表节点同步删除（漏删导致悬垂引用）。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：链表反转（面试必考）的迭代写法：
```python
def reverse(head):
    prev = None
    while head:
        nxt = head.next
        head.next = prev
        prev, head = head, nxt
    return prev
```
真实场景：文本编辑器用"行链表"支持光标处 $O(1)$ 插入；数据库列存（数组）与行存（记录指针）之争本质就是数组 vs 链表的工程版。

## 8. 常见误区和易混概念

### 误区 1：以为"链表插入删除一定快"
- **错误直觉**：链表插入 $O(1)$，所以链表增删永远比数组好。
- **为什么错**：$O(1)$ 的前提是**已持有目标位置的指针**；从值找位置仍需 $O(n)$ 遍历。
- **正确理解**：完整操作是"查找 $O(n)$ + 修改 $O(1)$"；只有"已知节点"场景（如 LRU、合并有序链表）才真正快。

### 误区 2：忽略缓存局部性
- **错误直觉**：复杂度相同（都 $O(n)$ 遍历）就性能相同。
- **为什么错**：数组连续内存命中 CPU 缓存行，链表节点散落导致每次指针跳转都可能缓存未命中——常数差距可达 10-100 倍。
- **正确理解**：复杂度之外的"常数因子"在工程中决定胜负；遍历首选数组。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 数组 | 随机访问 | 连续内存、$O(1)$ 下标 | 二分、堆、DP 表 |
| 链表 | 灵活增删 | 指针、$O(1)$ 已知点插入 | LRU、邻接表 |
| 动态数组 | 两者调和 | 均摊 $O(1)$ 尾插 | 语言内置 list |
| 跳表 | 链表加速 | 多级索引 $O(\log n)$ | 有序集合、Redis |

### 题目与解析

#### 1. 数组为什么能 $O(1)$ 随机访问？链表为什么不能？
> [!question]- 答案解析
> - **答案**：数组元素连续存放，地址 $\text{base}+i\cdot size$ 可算术计算，一次访存；链表节点散落，必须从头部沿指针逐个走，$O(n)$。
> - **解析**：随机访问的本质是"地址可计算"。
> - **易错原因**：把"查找快"与"访问快"混淆（哈希查找快但无序，数组访问快且有序）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 数组 `A` 首地址 1000，元素为 4 字节 int，`A[3]` 的地址？
> [!question]- 答案解析
> - **答案**：$1000+3\times4=1012$。
> - **解析**：地址算术是随机访问的数学基础。
> - **易错原因**：下标从 0 起（$A[3]$ 是第 4 个元素）。

#### 3. 需求：频繁在中间插入删除、偶尔随机访问、数据量大——选数组还是链表？为什么？
> [!question]- 答案解析
> - **答案**：链表（或块状链表）。中间插入删除数组 $O(n)$ 搬移、链表 $O(1)$（若已定位）；随机访问需求低，链表的 $O(n)$ 查找可接受。若随机访问频繁则选数组/跳表。
> - **解析**：选型 = 统计各操作频率 × 各操作代价。
> - **易错原因**：不看"是否已持有指针"就断言链表快。

#### 4. 手算链表 `1→2→3→4` 反转的每步指针变化。
> [!question]- 答案解析
> - **答案**：`prev=None`；处理 1：`nxt=2, 1.next=None, prev=1`；处理 2：`nxt=3, 2.next=1, prev=2`；处理 3：`nxt=4, 3.next=2, prev=3`；处理 4：`4.next=3, prev=4`。结果 `4→3→2→1`。
> - **解析**：先存 `nxt` 再改 `next`，避免断链。
> - **易错原因**：改 `next` 前未保存后继，链表断裂。

#### 5. 论证动态数组"倍增扩容"下 $n$ 次 push 的总代价 $O(n)$，并说明其缓存行为优于链表的原因。
> [!question]- 答案解析
> - **答案**：扩容发生在第 $1,2,4,\dots$ 次插入，复制代价 $1+2+4+\cdots+2^{\lceil\log n\rceil}=O(n)$，总代价 $O(n)$，均摊 $O(1)$。缓存：数组连续，遍历时每 64 字节一个缓存行、预取有效；链表节点分散，每节点一次随机访存，缓存未命中率高。故实测链表遍历常慢 5-20 倍。
> - **解析**：均摊分析的聚合法 + 局部性原理（见 [[复杂度分析]] 摊还节）。
> - **易错原因**：只比较渐近复杂度，忽略常数与缓存。
