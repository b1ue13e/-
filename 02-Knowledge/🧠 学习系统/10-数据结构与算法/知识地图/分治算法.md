# 分治算法

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：归并排序、快速排序、最近点对、Strassen、FFT 全部是分治；主定理是面试手推复杂度的标准工具，几乎必考。分治与 [[动态规划]] 的边界辨析也是高频考点。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：$O(n^2)$ 的朴素做法在 $n=10^6$ 时不可行（$10^{12}$ 次运算）。很多问题（排序、逆序对、最近点对）看似必须全局处理，但若能把问题**切成互不重叠的独立子问题**，各自解决后合并，复杂度往往能降到 $O(n\log n)$ 甚至更低——这就是分治的威力。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：分治是三大算法范式之一（贪心、分治、DP）；归并/快排是 [[线性排序计数与基数排序|排序]] 的主干；[[最近点对问题-分治进阶]] 与 FFT（[[快速傅里叶变换FFT]]）是其高级应用。
- **实际应用场景**：大数据排序、逆序对统计（股票风险）、最近点对（地理聚类）、多项式乘法加速。
- **高频题型/任务**：归并排序/快排手写、逆序对、主定理求复杂度、二分（减治特例）、矩阵乘 Strassen。

---

## 3. 学它之前需要哪些前置知识？

1. **[[递归]]**：分治的"解决"阶段就是递归调用，递归树是分析工具。
2. **[[复杂度分析]]**：需要先会解 $T(n)=aT(n/b)+f(n)$ 这类递推。
3. **[[数组与链表]]**：归并的合并阶段需要线性扫描与临时数组。

---

## 4. 用直觉语言解释它

> «"分治就像班级大扫除：老师把全班分成两组，每组再分两组……直到每个人只扫自己脚下那一小块（分解）；扫完后逐级汇报合并，组长汇总两组的成果（合并）。全体干活的量还是 $O(n)$，但'协调开销'每层只有 $O(n)$，共 $\log n$ 层——总开销 $O(n\log n)$。"»

- **直觉类比/几何图像**：大扫除分层汇报；折纸对折再展开的层数。
- **为什么很自然**：子问题"结构相同、规模更小"，天然适配递归；关键收益来自"合并代价 $f(n)$"远小于"暴力全局处理"。
- **一句话直觉本质**：**把问题切成 $a$ 个规模 $n/b$ 的独立子问题，递归求解后花 $f(n)$ 合并；总代价由"子问题个数 × 规模缩减"与"合并代价"的赛跑决定——主定理就是这个赛跑的记分牌。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **分治法**：① **分解**（Divide）：把规模 $n$ 的问题分成 $a$ 个规模 $n/b$ 的子问题；② **解决**（Conquer）：递归求解子问题（规模足够小时直接解）；③ **合并**（Combine）：把子问题解合成原问题解。
- **主定理**：设 $T(n)=aT(n/b)+f(n)$（$a\ge1, b>1$），令 $c_{crit}=\log_b a$：
  - 情形 1：$f(n)=O(n^{c_{crit}-\varepsilon})$ → $T(n)=\Theta(n^{c_{crit}})$；
  - 情形 2：$f(n)=\Theta(n^{c_{crit}})$ → $T(n)=\Theta(n^{c_{crit}}\log n)$；
  - 情形 3：$f(n)=\Omega(n^{c_{crit}+\varepsilon})$ 且 $af(n/b)\le cf(n)\ (c<1)$ → $T(n)=\Theta(f(n))$。

### 2. 核心公式
$$T(n)=aT(n/b)+f(n),\qquad c_{crit}=\log_b a$$
典型结果：$$T(n)=2T(n/2)+O(n)\Rightarrow \Theta(n\log n);\quad T(n)=T(n/2)+O(1)\Rightarrow\Theta(\log n)$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $a$ | 子问题个数 | $\ge1$ | |
| $b$ | 规模缩减倍数 | $>1$ | |
| $f(n)$ | 分解+合并代价 | 多项式级 | 主定理要求"多项式可比" |
| $c_{crit}$ | 临界指数 | $\log_b a$ | 比较 $f(n)$ 与 $n^{c_{crit}}$ |

### 4. 常见变体与适用条件
- **变体**：二分（$a=1$ 的减治）、归并（$a=2$）、快排（非均衡划分）、Strassen（$a=7$）、Karatsuba（$a=3$）。
- **适用条件**：子问题相互独立（不重叠——重叠请用 [[动态规划]]）；可高效合并。限制：主定理要求 $f(n)$ 与 $n^{c_{crit}}$ 多项式可比（如 $f(n)=n\log n$ 属于情形 2 与 3 之间的"间隙"）。

---

## 6. 推导思路和思想来源

- **最初困难**：排序的朴素做法（冒泡/选择）是 $O(n^2)$，信息都浪费在"相邻比较"上。
- **直接方法局限**：插入排序利用"已有序前缀"增量插入，最坏仍是 $O(n^2)$。
- **关键"转念"**：**先让两半各自有序（递归保证），再线性合并——把"全局排序"转化为"两次局部排序 + 一次线性归并"**；合并时利用两半已有序，双指针一趟扫完。
- **推导主线与动机**：$T(n)=2T(n/2)+O(n)$ → 递归树每层代价 $O(n)$、共 $\log n$ 层 → $\Theta(n\log n)$；主定理正是"递归树求和"的封闭形式。
- **为什么自然得到此结论**：$n\log n$ 是比较排序的信息论下界（$n!$ 种排列需 $\ge\log_2(n!)\approx n\log n$ 次比较）——分治排序达到下界，是"必然的最优"。

---

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：用归并排序排 $[5,2,4,7,1,3,2,6]$。
- **解题思路与关键步骤**：分解：$[5,2,4,7]\mid[1,3,2,6]$ → $[5,2]\mid[4,7]\mid[1,3]\mid[2,6]$ → 单元素。合并：$[2,5]\mid[4,7]\to[2,4,5,7]$；$[1,3]\mid[2,6]\to[1,2,3,6]$；最终 $[1,2,2,3,4,5,6,7]$。
- **最终答案**：$[1,2,2,3,4,5,6,7]$，比较次数 16 次（$n\log_2 n=24$ 内）。
- **易错点**：合并时忘记处理"一边耗尽"的收尾；用 $O(n)$ 辅助数组（非原地）。
- **🤔 追问**：若合并阶段发现"左边元素 > 右边元素"，能顺便统计什么？——逆序对：右半元素 $a_j$ 被放到前面时，左半剩余元素都与 $a_j$ 构成逆序对，一趟归并同时求出逆序对数。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：用主定理求 $T(n)=4T(n/2)+n^2$ 与 $T(n)=4T(n/2)+n$ 的渐近复杂度。
- **解题思路与完整解答**：① $c_{crit}=\log_2 4=2$，$f(n)=n^2=\Theta(n^2)$ → 情形 2 → $T(n)=\Theta(n^2\log n)$；② $f(n)=n=O(n^{2-\varepsilon})$ → 情形 1 → $T(n)=\Theta(n^2)$。直觉：① 合并代价与"叶子数×叶子代价"同级，每层代价相同共 $\log n$ 层；② 合并代价低于叶子规模，总代价由叶子层主导。
- **易错点**：把 $a$（子问题数）与 $b$（缩减倍数）搞反；忽略情形 3 的正则条件 $af(n/b)\le cf(n)$。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：快速排序的分区思想（期望 $O(n\log n)$、原地）：
```python
def quicksort(a, lo, hi):
    if lo >= hi: return
    p = a[hi]; i = lo
    for j in range(lo, hi):
        if a[j] < p: a[i], a[j] = a[j], a[i]; i += 1
    a[i], a[hi] = a[hi], a[i]
    quicksort(a, lo, i-1); quicksort(a, i+1, hi)
```
快排的"分解"代价 $O(n)$ 但划分可能不均衡（最坏 $O(n^2)$），用随机化/三数取中缓解；归并稳定但需 $O(n)$ 空间——选型依据见 [[复杂度分析]]。

## 8. 常见误区和易混概念

### 误区 1：把"分治"与"减治"混为一谈
- **错误直觉**：二分搜索也是分治，所以分治 = 递归。
- **为什么错**：二分只进入**一个**子问题（$a=1$），另一半个子问题被直接丢弃，属于"减治"；分治要求所有子问题都解决再合并（$a\ge2$）。
- **正确理解**：[[二分搜索]] 是减治特例；分治的复杂度收益来自"合并"。

### 误区 2：滥用主定理
- **错误直觉**：任何 $T(n)=aT(n/b)+f(n)$ 都能直接套主定理。
- **为什么错**：$f(n)=n\log n$ 与 $n^{c_{crit}}$ 之间"多项式不可比"（$\log n$ 增长慢于任何 $n^\varepsilon$），主定理三种情形都不适用；需用递归树手工求和。
- **正确理解**：主定理适用条件是 $f(n)$ 与 $n^{c_{crit}}$ 多项式可比；不可比时回到递归树。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 分治 | 独立子问题递归+合并 | 子问题不重叠、$a\ge2$ | 归并排序、最近点对 |
| 减治（[[二分搜索]]） | 每步排除一部分 | 只进一个子问题 | 二分查找 |
| 动态规划（[[动态规划]]） | 重叠子问题 | 记忆化/填表、自底向上 | 背包、LIS |
| 回溯（[[回溯算法]]） | 穷举所有解 | 试探+撤销、剪枝 | N 皇后、全排列 |

### 题目与解析

#### 1. 分治法的三个步骤是什么？为什么子问题必须"相互独立"？
> [!question]- 答案解析
> - **答案**：分解（Divide）、解决（Conquer，递归）、合并（Combine）。若子问题重叠，同一子问题被重复求解，指数级浪费——此时应改用 [[动态规划]] 的记忆化/填表。
> - **解析**：独立性保证"解决一次"即可，总代价是各层代价之和；重叠时递归树坍缩为 DAG，分治分析失效。
> - **易错原因**：把"分治"与"DP"的适用条件混淆。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 用主定理求 $T(n)=9T(n/3)+n$ 与 $T(n)=3T(n/3)+n$ 的渐近复杂度。
> [!question]- 答案解析
> - **答案**：① $c_{crit}=\log_3 9=2$，$f(n)=n=O(n^{2-\varepsilon})$ → 情形 1 → $\Theta(n^2)$；② $c_{crit}=\log_3 3=1$，$f(n)=n=\Theta(n^1)$ → 情形 2 → $\Theta(n\log n)$。
> - **解析**：情形 1 时叶子层（$n^{c_{crit}}$）主导，情形 2 时每层代价相同。
> - **易错原因**：把 $a=9,b=3$ 的 $\log_3 9$ 算成 $3$。

#### 3. 为什么 $T(n)=2T(n/2)+n\log n$ 不能直接套主定理？
> [!question]- 答案解析
> - **答案**：$c_{crit}=1$，$f(n)=n\log n$：它比 $n^1$ 大、但比任何 $n^{1+\varepsilon}$ 小——与 $n^{c_{crit}}$ 多项式不可比，三种情形均不适用（情形 2 要求 $\Theta(n^c)$ 精确匹配，情形 3 要求 $\Omega(n^{c+\varepsilon})$）。
> - **解析**：递归树：每层代价 $n\log(n/2^k)$，求和 $\approx n\sum_{k=0}^{\log n}(\log n-k)=O(n\log^2 n)$。
> - **易错原因**：把"$\Theta(n^c)$"错放宽成"$O(n^c)$"去套情形 2。

#### 4. 用递归树求 $T(n)=T(n/3)+T(2n/3)+O(n)$（快排期望递推）。
> [!question]- 答案解析
> - **答案**：递归树每层代价 $O(n)$；从根到叶的最长路径 $\log_{3/2}n$，最短路径 $\log_3 n$，树高 $O(\log n)$，总代价 $\Theta(n\log n)$。
> - **解析**：非均衡划分导致树不是满的，但每层总代价仍为 $n$，层数由最长路径界定。
> - **易错原因**：以为必须均衡划分才能得到 $n\log n$。

#### 5. 说明如何用归并排序统计逆序对，并解释 $O(n\log n)$ 为什么是"合理"的复杂度。
> [!question]- 答案解析
> - **答案**：合并时若右半元素 $a_j$ 先于左半剩余元素入列，则左半剩余元素个数即新增逆序对数（它们都比 $a_j$ 大且位置在前）；排序过程顺带累加。复杂度 $O(n\log n)$：归并排序是分治，每次合并 $O(n)$ 顺带统计，不改变主定理结论。$n\log n$ 合理是因为比较排序下界 $\log_2(n!)\approx n\log n$——任何基于比较的算法（包括求逆序对的信息变体）都不可能更快。
> - **解析**：这是"分治 + 顺带求解"的经典模式：把统计问题塞进合并阶段。
> - **易错原因**：忘记"左半剩余个数"才是新增逆序对，而误加右半元素。
