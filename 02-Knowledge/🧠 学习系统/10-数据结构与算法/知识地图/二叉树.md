# 二叉树

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：树是"层级关系"的通用模型（文件系统、DOM、表达式、决策树），二叉树是树的规范形；遍历是递归思想的第一个实战场景（[[递归]]），BST 又是有序动态集合的基石（通往 [[红黑树]]）。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：线性结构（[[数组与链表]]）只能表达"前后关系"，无法表达"父子/分支关系"；而现实里到处是层级结构：目录套目录、表达式嵌套、组织架构。二叉树用"每个节点至多两个孩子"的简单规则，把任意多叉结构规范化，让"分而治之"有了天然载体。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：二叉树是树形数据结构的枢纽：[[堆]] 是完全二叉树，[[红黑树]]/[[AVL树与平衡树]] 是 BST 的平衡化，表达式树、哈夫曼树、线段树都是二叉树。
- **实际应用场景**：文件系统目录、编译器语法树、数据库索引（B+ 树的退化形态）、优先队列。
- **高频题型/任务**：三种遍历（递归/迭代）、最大深度、层序遍历、判断 BST、最近公共祖先（LCA）、树的序列化。

---

## 3. 学它之前需要哪些前置知识？

1. **[[递归]]**：遍历天然用递归写，"先处理自己还是先处理孩子"就是遍历顺序。
2. **[[数组与链表]]**：完全二叉树可以用数组存（下标 $2i,2i+1$），普通树用"孩子指针/链式存储"。
3. **[[复杂度分析]]**：$O(h)$（高度）与 $O(n)$（节点数）的关系是树复杂度分析的核心。

---

## 4. 用直觉语言解释它

> «"二叉树就像家族族谱的简化版：每个人最多生两个孩子。你问'这家一共几代人'（高度），只要问两个孩子'你们那边几代'，取大者加一——问题自动分解成两个更小的同构问题，这就是递归的直觉。"»

- **直觉类比/几何图像**：族谱、倒置的树根、括号嵌套结构。
- **为什么很自然**：层级结构天然可递归定义——"一棵树 = 根 + 两棵子树"，于是遍历、计数、求高全变成同构子问题。
- **一句话直觉本质**：**二叉树是"一分为二"的结构化表达；遍历顺序 = 决定"根"在何时被访问；BST 在有序性上加码，使查找变成二分导航。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **二叉树**：每个节点至多有两个孩子（左/右）的有根树；递归定义：空树或"根 + 左子树 + 右子树"。
- **遍历**：前序（根左右）、中序（左根右）、后序（左右根）、层序（BFS 队列）。
- **BST（二叉搜索树）**：对任意节点，左子树所有值 < 根值 < 右子树所有值；**中序遍历得到递增序列**。

### 2. 核心公式
- 深度 $h$ 的二叉树最多 $2^{h}-1$ 个节点；$n$ 个节点的高度 $h \ge \lceil\log_2(n+1)\rceil$。
- 第 $i$ 层（根为第 1 层）最多 $2^{i-1}$ 个节点。
- 完全二叉树数组存储：节点 $i$ 的左孩子 $2i$、右孩子 $2i+1$、父节点 $\lfloor i/2\rfloor$。
- 遍历复杂度：$$T(n)=O(n),\quad 空间\ O(h)\ (\text{递归栈})\ \text{或}\ O(n)\ (\text{层序队列})$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $n$ | 节点总数 | $\ge 1$ | |
| $h$ | 树高（最大层数） | $[\lceil\log_2(n+1)\rceil, n]$ | 链状时 $h=n$ |
| $i$ | 完全二叉树节点下标 | $[1,n]$ | 从 1 开始 |

### 4. 常见变体与适用条件
- **变体**：满二叉树（每层满）、完全二叉树（除末层外满且靠左）、平衡二叉树（左右子树高差 ≤1）、BST、线索二叉树。
- **适用条件**：层级/分支建模用普通树；动态有序集合用 BST；"始终取最值"用 [[堆]]。限制：BST 在插入有序序列时退化为链表（$O(n)$），需平衡化。

## 6. 推导思路和思想来源

- **最初困难**：如何系统、不重不漏地访问一棵树的全部节点？
- **直接方法局限**：按"节点编号"硬扫需要额外结构；且无法体现"先访问谁"的语义差异。
- **关键"转念"**：**把访问顺序归结为"根在何时被处理"**——根先（前序）、根中（中序）、根后（后序）；再配合递归，三种顺序只是三行代码的顺序差。
- **推导主线与动机**：递归定义树 → 递归遍历自然成立（访问根 + 递归左右）→ 用栈模拟递归得到迭代版 → 层序用队列按"先进先出"逐层推进。BST 的正确性：中序有序 ⇔ 每个节点满足左<根<右（归纳可证）。
- **为什么自然得到此结论**：遍历的三种顺序 + 层序恰好覆盖"所有可能的第一访问时机"，信息完备：前序+中序（或后序+中序）可唯一重建二叉树。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：对树 `1(2(4,5),3(,6))` 写出三种遍历与层序。
- **解题思路与关键步骤**：前序：根先——1,2,4,5,3,6；中序：左根右——4,2,5,1,3,6；后序：左右根——4,5,2,6,3,1；层序：1,2,3,4,5,6。
- **最终答案**：如上；注意中序里 6 是 3 的右孩子，所以在 3 之后。
- **易错点**：把中序写成"左中右"时忽略空子树占位；层序用栈而非队列。
- **🤔 追问**：仅凭前序+后序能否唯一重建？——不能（如 `1(2,)` 与 `1(,2)` 前序后序相同但树不同）。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：判断一棵二叉树是否为 BST（力扣 98）。
- **解题思路与完整解答**：不能只比较"根 > 左孩子 < 右孩子"（会漏掉"左子树的右子树值必须 < 根"这类跨层约束）。正确做法：中序遍历并检查是否严格递增；或递归传参 `(low, high)` 区间：对每个节点要求 $low < val < high$，向左递归时 `high=val`，向右时 `low=val`。反例 `[5,4,6,null,null,3,7]`：局部看每层都满足，但 3 在 5 的右子树却小于 5，中序 `4,5,3,6,7` 非递增，判否。
- **易错点**：只做局部比较；忽略相等元素（BST 通常要求严格不等，或允许左子树 ≤）。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：求最大深度是树类题的"hello world"：
```python
def maxDepth(root):
    if not root: return 0
    return 1 + max(maxDepth(root.left), maxDepth(root.right))
```
复杂度 $O(n)$ 时间、$O(h)$ 栈空间。推广：层序遍历可求"每层最值"（树的宽度）、锯齿遍历；BST 插入/删除/查找都是 $O(h)$——配合平衡化（[[红黑树]]、[[AVL树与平衡树]]）才能保证 $O(\log n)$。

## 8. 常见误区和易混概念

### 误区 1：以为"BST 查找一定快"
- **错误直觉**：BST 是树，所以查找 $O(\log n)$。
- **为什么错**：插入有序序列 $1,2,3,\dots,n$ 后 BST 退化成单链，$h=n$，查找 $O(n)$。
- **正确理解**：$O(h)$ 是精确界，$O(\log n)$ 只对"平衡"的树成立（AVL/红黑树用旋转保证 $h=O(\log n)$）。

### 误区 2：混淆"堆"与"BST"
- **错误直觉**：都是二叉树，都能找最值。
- **为什么错**：堆只保证"父 ≤ 子"的偏序（只能快速取根），BST 保证"左<根<右"的全序（可快速查找任意值）；堆的数组存储也无指针。
- **正确理解**：取最值/优先队列用 [[堆]]；查找/有序遍历用 BST。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 二叉树 | 层级结构建模 | 无有序性约束 | 表达式树、遍历题 |
| BST | 动态有序集合 | 左<根<右、中序有序 | 有序查找、前驱后继 |
| 堆（[[堆]]） | 快速取最值 | 偏序、数组存储 | 优先队列、TopK |
| 平衡树（[[红黑树]]） | BST 退化防护 | 旋转保持 $h=O(\log n)$ | 工业级有序 Map |

### 题目与解析

#### 1. 满二叉树与完全二叉树的区别？
> [!question]- 答案解析
> - **答案**：满二叉树：每层都满（$2^h-1$ 个节点）；完全二叉树：除最后一层外全满，最后一层节点靠左连续。满二叉树必是完全二叉树，反之不然。
> - **解析**：完全二叉树的关键是"可用数组连续存储"（下标 $2i,2i+1$），[[堆]] 依赖此性质。
> - **易错原因**：把"完全"误认为"左右子树高度差 ≤1"（那是平衡二叉树）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 一棵有 $n=100$ 个节点的完全二叉树，高度 $h$ 的范围？第 5 层最多几个节点？
> [!question]- 答案解析
> - **答案**：$h=\lceil\log_2(101)\rceil=7$；第 5 层最多 $2^{4}=16$ 个。验证：6 层满树 $2^6-1=63<100$，7 层满树 $127\ge100$。
> - **解析**：层数与节点数互推公式 $\lceil\log_2(n+1)\rceil$ 与 $2^{i-1}$。
> - **易错原因**：忘记 $\log_2$ 的下取整/上取整细节。

#### 3. 前序+中序能唯一重建二叉树，前序+后序为什么不能？
> [!question]- 答案解析
> - **答案**：前序定根，中序定左右子树划分（根左侧全在左子树）——每层划分唯一；前序+后序只能确定"根"，无法确定某个单孩子节点是左还是右（如 `1(2,)` 与 `1(,2)` 前序后序相同）。
> - **解析**：需要"能定位左右边界"的信息，中序（或带空标记的层序）提供该信息。
> - **易错原因**：只记结论不记"为什么缺信息"。

#### 4. 判断 BST 为什么不能只做"局部比较"？给出反例。
> [!question]- 答案解析
> - **答案**：反例 `[5,4,6,null,null,3,7]`：每个节点局部满足左<根<右，但 3 位于 5 的右子树却 <5，违反 BST 全局约束。正确做法：中序遍历检查递增，或递归传递 `(low,high)` 区间约束。
> - **解析**：BST 约束是"跨层"的：右子树所有值都 > 根，而非仅右孩子。
> - **易错原因**：把"孩子关系"误当"子树关系"。

#### 5. 证明递归求最大深度的时间复杂度，并说明最坏/最好情况下的栈空间。
> [!question]- 答案解析
> - **答案**：每个节点恰好访问一次，$T(n)=O(n)$。栈空间 = 递归深度 = 树高 $h$：最好（完全平衡）$O(\log n)$，最坏（退化为链）$O(n)$。改进：迭代层序用队列 $O(n)$ 空间但无栈溢出风险。
> - **解析**：$T(n)=T(n_L)+T(n_R)+O(1)$，累加得 $O(n)$；空间随 $h$ 变化是"递归 vs 迭代"选型的核心依据。
> - **易错原因**：把空间复杂度写成 $O(n)$ 而忽略平衡情形下的 $O(\log n)$。
