# 回溯算法

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：组合/排列/子集三大题型（全排列、N 皇后、数独）全部是回溯；"搜索树 + 剪枝"的框架是所有"枚举类"题目的标准解法，也是通往 [[动态规划]]（记忆化）与 [[状态压缩]]（位掩码剪枝）的桥梁。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：很多问题要求"枚举所有可能组合并筛选"：N 皇后要摆出所有合法布局、全排列要列出所有顺序。朴素嵌套循环层数不定（排列长度可变），根本无法写死循环层数；暴力枚举所有 $n!$ 或 $2^n$ 种方案又需要系统性的"生成 + 检查"机制。回溯用**递归 + 撤销**统一解决：把选择过程建成一棵决策树，深度优先遍历，不合法/不可能的分支提前砍掉。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：回溯 = DFS（[[图遍历BFS与DFS]] 的思想）在"隐式决策树"上的应用；是 [[动态规划]]（记忆化剪枝）与 [[状态压缩]]（位掩码表示状态）的前置知识。
- **实际应用场景**：约束满足问题（数独、八皇后、填字游戏）、正则表达式匹配、编译器语法分析（递归下降）、布线规划。
- **高频题型/任务**：全排列/组合/子集、N 皇后、数独求解、括号生成、单词搜索、分割回文串。

---

## 3. 学它之前需要哪些前置知识？

1. **[[递归]]**：回溯是"递归 + 状态撤销"，递归基对应"找到一个完整解"。
2. **[[二叉树]]**：决策树是回溯的搜索空间视图（每个节点 = 一个部分解）。
3. **[[复杂度分析]]**：能分析 $O(n!)$ / $O(2^n)$ 与剪枝后的实际开销。

---

## 4. 用直觉语言解释它

> «"回溯就像走迷宫时拿一根粉笔：每到一个岔路口，选一条路走并做记号（选择）；走到死胡同就原路退回岔路口，擦掉记号（撤销），试下一条路（换选择）。粉笔记号保证不重复走同一条路；'知道前面必是死路就提前掉头'就是剪枝。"»

- **直觉类比/几何图像**：迷宫粉笔 + 退路、下棋试招（落子→后悔→重下）。
- **为什么很自然**：决策天然是树状的（第 $k$ 步选谁 → 第 $k+1$ 步选谁），DFS 恰好按字典序生成所有叶子（完整解）。
- **一句话直觉本质**：**回溯 = 在决策树上做 DFS：递归深入做选择（路径），到底或非法时返回并撤销选择（回溯），用剪枝在深入前砍掉不可能的分支。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **回溯框架（模板）**：`backtrack(path, 候选集)`：① 若 `path` 是完整解 → 记录并返回；② 遍历候选：**剪枝判断**（不合法/不可能最优 → `continue`）；③ 做选择（加入 `path`、标记占用）；④ 递归 `backtrack`；⑤ **撤销选择**（弹出、解除标记）——保证状态在兄弟分支间正确复用。
- **剪枝（pruning）**：可行性剪枝（约束不满足）与最优性剪枝（不可能优于已知最优，如分支限界）。
- **决策树规模**：排列 $O(n!)$、子集/组合 $O(2^n)$、N 皇后 $O(n!)$（带约束剪枝后大幅减少）。

### 2. 核心公式
全排列数量与回溯复杂度：
$$P(n)=n!;\qquad T(n)=O(n\cdot n!)\ (\text{每叶子 }O(n)\text{ 复制})$$
N 皇后：$$T(n)=O(n!)\quad\text{（剪枝后实际远小于 }n^n\text{）}$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $path$ | 当前部分解 | 长度 $\le n$ | 递归参数 |
| $n$ | 元素个数/棋盘大小 | 正整数 | |
| $used$ | 占用标记 | 布尔数组/位掩码 | 撤销时复位 |

### 4. 常见变体与适用条件
- **变体**：组合（`start` 参数防重复）、排列（`used` 数组）、子集（选/不选二分）、带重复元素（先排序 + 同层去重）、数独/图着色（约束传播剪枝）。
- **适用条件**：解空间可枚举、需要"所有解"或"第一个解/最优解（配合剪枝）"。限制：无剪枝时指数爆炸，$n>20$ 左右的全排列不可行，需换思路（[[动态规划]]/[[状态压缩]]）。

---

## 6. 推导思路和思想来源

- **最初困难**：枚举层数不定的所有组合，循环写不出来。
- **直接方法局限**：$n$ 重嵌套循环需要 $n$ 固定；递归天然支持"层数 = 深度"。
- **关键"转念"**：**把"枚举"变成"深度优先搜索一棵决策树"**：第 $k$ 层递归 = 决定第 $k$ 个位置选谁；"已做的选择"存在 `path` 里，用 `used`/`start` 保证不重不漏；返回时撤销，让同一个 `path` 被所有分支复用。
- **推导主线与动机**：定义"部分解"与"完整解" → 递归生成 → 约束检查放最前面（剪枝）→ 撤销保证状态正确 → 复杂度 = 叶子数 × 每叶子代价，剪枝减少实际访问节点。
- **为什么自然得到此结论**：决策过程天然构成树（每个节点是"前缀选择"），DFS 恰好能按序枚举所有叶子——回溯是"树的 DFS"这一成熟工具的直接套用。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：生成 $[1,2,3]$ 的全排列。
- **解题思路与关键步骤**：决策树第 1 层选 1/2/3，第 2 层选剩余，第 3 层选最后。以 1 开头：`[1,2,3]`、`[1,3,2]`；以 2 开头：`[2,1,3]`、`[2,3,1]`；以 3 开头：`[3,1,2]`、`[3,2,1]`。共 $3!=6$ 个。撤销示例：`[1,2,3]` 完成后撤销 3、撤销 2，再试 2 位置换 3 → `[1,3,2]`。
- **最终答案**：6 个排列如上。
- **易错点**：忘记撤销 `used[2]=False`，导致后续分支缺失元素；在递归内修改共享列表不复制。
- **🤔 追问**：若元素有重复（`[1,1,2]`）？——先排序，同一层跳过与前一个相同的值（`if i>0 and nums[i]==nums[i-1] and not used[i-1]: continue`），得 `[1,1,2],[1,2,1],[2,1,1]` 3 个。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：N 皇后（$n=4$）：在 $4\times4$ 棋盘放 4 皇后互不攻击，求所有布局。
- **解题思路与完整解答**：逐行放皇后，列、主对角线（`row-col` 恒定）、副对角线（`row+col` 恒定）各用集合记录占用。第 1 行放 (0,1)：第 2 行试 (1,3)；第 3 行 (2,0) 与 (0,1) 冲突（列/对角线检查）→ 试 (2,?) 全失败 → 回溯到第 2 行换 (1,?)：第 2 行试 (1,0)? (1,0) 与 (0,1) 副对角冲突；... 最终找到解 `(0,1),(1,3),(2,0),(3,2)` 与对称解 `(0,2),(1,0),(2,3),(3,1)`。剪枝：每行只试 $O(n)$ 列且立即检查冲突，无需生成全部 $4^4=256$ 种布局。
- **易错点**：对角线的 `row-col` 可能为负，需平移或直接用 `row-col` 集合（Python 集合允许负数）；忘记恢复对角线占用。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：子集枚举是回溯最小模板（每个元素"选/不选"），也是 [[状态压缩]] 的对照实现：
```python
def subsets(nums):
    res, path = [], []
    def dfs(i):
        if i == len(nums): res.append(path[:]); return
        path.append(nums[i]); dfs(i+1)   # 选
        path.pop(); dfs(i+1)             # 不选（撤销）
    dfs(0)
    return res
```
关键点：`path[:]` 复制快照（否则引用同一列表全被覆盖）；撤销必须在递归返回后执行。真实场景：数独求解器、游戏 AI 的试招（落子/悔棋）都是这个骨架。

## 8. 常见误区和易混概念

### 误区 1：忘记"撤销"，状态污染兄弟分支
- **错误直觉**：`used` 标记了就不用管，递归返回后自然恢复。
- **为什么错**：`used`/`path` 是共享可变状态，不撤销会让兄弟分支以为元素仍被占用/已加入。
- **正确理解**：**撤销与选择一一对称**（选择做了什么，返回前就还原什么）；或用不可变方式传参（每层复制，牺牲性能）。

### 误区 2：混淆"回溯"与"DFS/递归"
- **错误直觉**：递归遍历树 = 回溯。
- **为什么错**：DFS 是遍历**显式**图/树的通用工具；回溯特指在**隐式决策树**上枚举解，核心是"选择-递归-撤销"循环与剪枝。
- **正确理解**：回溯 = DFS + 状态撤销 + 剪枝，用于解空间搜索（见 [[图遍历BFS与DFS]] 的对比）。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 回溯 | 枚举所有可行解 | 撤销 + 剪枝、深度优先 | 排列/组合/数独 |
| DFS（[[图遍历BFS与DFS]]） | 遍历图/树节点 | 无撤销语义 | 连通性、拓扑 |
| 动态规划（[[动态规划]]） | 重叠子问题最优值 | 记忆化、不枚举重复 | 背包、LIS |
| 状态压缩（[[状态压缩]]） | 集合状态表示 | 位掩码 + 记忆化 | TSP、子集 DP |

### 题目与解析

#### 1. 回溯与普通 DFS 的核心区别是什么？
> [!question]- 答案解析
> - **答案**：回溯 = DFS（深度优先遍历）+ 状态撤销 + 剪枝，且遍历的是"隐式决策树"（节点是部分解）；DFS 遍历显式图/树，无"选择-撤销"语义。
> - **解析**：撤销让同一状态空间被所有分支复用；剪枝让不可能分支不深入。
> - **易错原因**：把"递归遍历树"直接叫回溯。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 子集数量与全排列数量公式？$n=4$ 时各多少？
> [!question]- 答案解析
> - **答案**：子集 $2^n=16$；全排列 $n!=24$。子集每个元素选/不选独立；排列每个位置选剩余元素。
> - **解析**：复杂度上界：子集 $O(2^n)$，排列 $O(n\cdot n!)$。
> - **易错原因**：把组合数 $C(n,k)$ 与子集总数 $2^n$ 混淆。

#### 3. 回溯中为什么"撤销"必不可少？不撤销会怎样？
> [!question]- 答案解析
> - **答案**：`path`/`used` 是共享可变状态。不撤销，兄弟分支会看到被污染的状态：排列会漏元素（`used` 恒 True）、子集会无限增长（`path` 残留）。必须"选择什么就撤销什么"，与递归返回严格对称。
> - **解析**：这是回溯最常见的 bug 来源（状态未还原）。
> - **易错原因**：以为递归参数传值就自动隔离——共享列表/集合是引用传递。

#### 4. 含重复元素的全排列如何避免重复？以 `[1,1,2]` 为例。
> [!question]- 答案解析
> - **答案**：先排序，DFS 每层跳过"与前一个相同且前一个未被使用"的元素：`if i>0 and nums[i]==nums[i-1] and not used[i-1]: continue`。结果 `[1,1,2],[1,2,1],[2,1,1]` 共 3 个而非 6 个。
> - **解析**：该剪枝保证"相同值的元素只按固定顺序被选取"，同层不重复。
> - **易错原因**：不排序直接去重（无法判断"同层"）；或条件写反（`used[i-1]` 为 True 时跳过会漏解）。

#### 5. 分析 N 皇后（$n=8$）回溯的搜索规模，并说明剪枝的实际收益。
> [!question]- 答案解析
> - **答案**：无剪枝决策树规模 $\sum_{k=1}^{8}8^k\approx10^7$（每行 8 种选择）；加"列/对角线冲突剪枝"后实际只访问约 2 万个节点（经验值），找到 92 个解。剪枝把"深度优先全遍历"变成"约束驱动的定向搜索"。
> - **解析**：回溯复杂度通常写最坏 $O(n!)$ 或 $O(n^n)$，但剪枝后实际运行远低于上界——面试说明复杂度时应指出"最坏 vs 实际"。
> - **易错原因**：只报最坏复杂度，不会讲剪枝的收益量级。
