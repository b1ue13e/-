# 递归

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：递归是树遍历、分治、回溯、DP 四大主题的共同语法（[[二叉树]]、[[分治算法]]、[[回溯算法]]、[[动态规划]] 全部依赖它）；调用栈与递归树是分析"深度、空间、复杂度"的必备工具，面试必考。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：很多问题具有"自相似"结构——树的子树还是树、汉诺塔的子问题还是汉诺塔。用循环硬写需要手动维护"接下来该处理谁"的栈，极易出错；递归让函数**调用自己**，把"管理未完成工作"的责任交给调用栈，代码与数学归纳一一对应。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：递归是"程序化表达数学归纳"的机制：分治（[[分治算法]]）、回溯（[[回溯算法]]）、树遍历（[[二叉树]]）、DP 记忆化（[[动态规划]]）都建立其上。
- **实际应用场景**：文件目录递归遍历、编译器的语法分析（递归下降）、JSON/XML 解析、分形绘制。
- **高频题型/任务**：阶乘/斐波那契、汉诺塔、树的深度/遍历、递归转迭代、爆栈问题排查。

---

## 3. 学它之前需要哪些前置知识？

1. **[[复杂度分析]]**：递归的时间复杂度是递推式 $T(n)=aT(n/b)+f(n)$，空间是调用栈深度。
2. **[[数组与链表]]**：理解"栈"这种后进先出的内存结构（详见 [[栈与队列]]）。
3. **[[二叉树]]**：树是练习递归最自然的载体（可并行学习）。

---

## 4. 用直觉语言解释它

> «"递归就像俄罗斯套娃：打开最大的娃娃，里面是一个小一号的自己；不断打开，直到最小的娃娃（递归基）；然后从小往大逐层合拢，每一层完成自己那点事。调用栈就是'暂时搁置的打开中的娃娃堆'——后打开的（更深的）先合拢。"»

- **直觉类比/几何图像**：俄罗斯套娃、照镜子里的镜子、数学归纳法。
- **为什么很自然**：自相似结构（树、括号、分形）天然适合"自己调用自己"；每个调用只关心"我这一步 + 子问题结果"。
- **一句话直觉本质**：**递归 = 递归基（最小的、直接可解的情形）+ 递推关系（把规模 $n$ 的问题转化为规模更小的同构问题）；执行时由调用栈记录每一层的"未完成现场"，返回时逐层恢复。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **递归函数**：直接或间接调用自身的函数；必须满足两条性质：① **递归基**（base case）：存在不递归调用的输入；② **规模递减**：每次调用都向递归基靠近（否则死循环/栈溢出）。
- **调用栈（call stack）**：每次函数调用压入一个栈帧（参数、局部变量、返回地址）；递归深度 $=d$ 时栈空间 $O(d)$。
- **递归树**：把递归调用画成树，每层标注该层总代价，用于求解递推式。

### 2. 核心公式
递归的时间复杂度由递推式给出：
$$T(n)=aT(n/b)+f(n)\quad(\text{如归并 }T(n)=2T(n/2)+O(n)=\Theta(n\log n))$$
朴素斐波那契：$$T(n)=T(n-1)+T(n-2)+O(1)=\Theta(2^n)$$
空间复杂度：$O(\text{递归深度})$，如斐波那契 $O(n)$、归并 $O(\log n)$。

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $n$ | 问题规模 | 正整数 | 每层递减 |
| $a$ | 每次调用产生的子调用数 | $\ge1$ | |
| $d$ | 递归深度 | $\le n$ | 栈空间来源 |
| $T(n)$ | 规模 $n$ 的时间 | 递推式 | 用递归树/主定理求解 |

### 4. 常见变体与适用条件
- **变体**：线性递归（阶乘）、树形递归（斐波那契）、尾递归（最后一步调用自身，可被编译器优化为迭代）、间接递归（A 调 B、B 调 A）、互递归（语法分析）。
- **适用条件**：问题自相似 + 子问题独立（重叠时需记忆化）。限制：深度过大（>1000 层，Python 默认限制）会爆栈——此时改迭代或显式栈。

## 6. 推导思路和思想来源

- **最初困难**：如何描述"嵌套的、未完成的多层工作"而不引入复杂状态？
- **直接方法局限**：迭代需要手动维护栈（如非递归树遍历），代码与问题结构脱节。
- **关键"转念"**：**让语言运行时替我们管理"未完成现场"**——每次调用把自己的状态压栈，返回时自动恢复；程序员只需写"递归基 + 递推关系"。
- **推导主线与动机**：数学归纳法保证递归正确性（基例成立 + 归纳步成立 ⇒ 全部成立）；栈机制保证执行可行性；递归树给出复杂度直观。
- **为什么自然得到此结论**：函数调用本来就有栈语义，"调用自己"只是把"调用另一个函数"的机制复用——递归是零额外成本的语法糖。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：手算 `fact(4)` 的递归过程。
- **解题思路与关键步骤**：`fact(4)=4*fact(3)`；`fact(3)=3*fact(2)`；`fact(2)=2*fact(1)`；`fact(1)=1`（递归基）。回溯：`fact(2)=2`、`fact(3)=6`、`fact(4)=24`。调用栈深度 4。
- **最终答案**：24。调用序列 `fact(4)→fact(3)→fact(2)→fact(1)`，栈帧 4 层。
- **易错点**：忘记递归基；把"递推"与"回溯"两个阶段搞混（先压栈后弹栈）。
- **🤔 追问**：`fact(n)` 是尾递归吗？——不是：`n*fact(n-1)` 在递归调用返回后还要做乘法，最后一步不是调用自身。改写为 `fact(n, acc)=fact(n-1, n*acc)` 才是尾递归。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：斐波那契 `fib(5)` 朴素递归调用了多少次？为什么是 $O(2^n)$？
- **解题思路与完整解答**：调用树：`fib(5)` → `fib(4)+fib(3)` → …；`fib(2)` 被重复计算 3 次，`fib(1)` 被算 5 次——大量重叠子问题。设调用次数 $C(n)=C(n-1)+C(n-2)+1$，解得 $C(n)\approx 2F_n=O(2^n)$。深度仅 $n$（栈空间 $O(n)$），但时间指数爆炸。改进：记忆化（自顶向下 DP）后 $O(n)$。
- **易错点**：把"空间 $O(n)$"误当"时间 $O(n)$"；未意识到重复计算是性能杀手。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：树的最大深度（递归的实战模板）与显式栈迭代版：
```python
def max_depth(root):          # 递归：深度 = 1 + max(左右子树深度)
    return 0 if not root else 1 + max(max_depth(root.left), max_depth(root.right))

def max_depth_iter(root):     # 迭代：显式栈模拟调用栈，避免爆栈
    if not root: return 0
    stack, mx = [(root, 1)], 0
    while stack:
        node, d = stack.pop()
        mx = max(mx, d)
        if node.left: stack.append((node.left, d+1))
        if node.right: stack.append((node.right, d+1))
    return mx
```
当树高接近 $10^5$ 时递归版会爆栈，迭代版以 $O(n)$ 空间换安全——这是"递归 vs 迭代"选型的真实案例。

## 8. 常见误区和易混概念

### 误区 1：以为"递归一定比迭代慢/差"
- **错误直觉**：递归有函数调用开销，能不用就不用。
- **为什么错**：语义清晰度、正确性论证（归纳）的优势远大于常数开销；且尾递归可被优化为循环。
- **正确理解**：真正的风险是**爆栈**（深度过大）与**重复计算**（无记忆化），两者都有明确解法（迭代化/记忆化），不该因噎废食。

### 误区 2：混淆"递归深度"与"调用总数"
- **错误直觉**：斐波那契递归了 $2^n$ 次，所以栈会爆。
- **为什么错**：栈空间只与**最大深度**（$n$）有关，与总调用次数无关——$2^n$ 是时间，$n$ 是空间。
- **正确理解**：时间 = 调用总数，空间 = 调用栈最大深度；二者独立分析。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 递归 | 自相似问题表达 | 代码=归纳、栈自动管理 | 树、分治、回溯 |
| 迭代 | 同问题循环表达 | 显式状态、无栈开销 | 尾递归、性能敏感 |
| 递归树 | 复杂度可视化 | 每层代价求和 | 递推式求解 |
| 调用栈（[[栈与队列]]） | 未完成现场管理 | LIFO、深度=空间 | 所有函数调用 |

### 题目与解析

#### 1. 一个合法递归必须满足哪两条性质？缺了会怎样？
> [!question]- 答案解析
> - **答案**：① 有递归基（base case，不再调用自身）；② 每次调用规模严格递减。缺①直接栈溢出（无限递归）；缺②可能死循环或无限递归。
> - **解析**：递归基对应数学归纳的基例，规模递减对应归纳步。
> - **易错原因**：写了递归基但"规模不减"（如 `f(n)` 里调用 `f(n)` 而非 `f(n-1)`）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 朴素递归求 `fib(50)` 大约需要多少次调用？空间呢？
> [!question]- 答案解析
> - **答案**：约 $2^{50}\approx10^{15}$ 次调用（$C(n)\approx2F_n$），不可行；空间仅 $O(50)$（递归深度 50）。
> - **解析**：时间被重叠子问题拖垮，空间却很小——这是"时间 vs 空间"分析的经典陷阱。
> - **易错原因**：把 $O(2^n)$ 时间误记为空间。

#### 3. 判断 `def f(n): return f(n-1)` 与 `def g(n): return n if n==0 else n+g(n-1)` 谁是尾递归？
> [!question]- 答案解析
> - **答案**：`f` 是尾递归（最后一步直接调用自身），但它没有递归基，非法；`g` 不是尾递归（返回前还要执行 `n+`）。
> - **解析**：尾递归 = 递归调用是函数的最后一条语句且返回值直接透传；`g` 的 `n+` 运算发生在返回后，需保留当前栈帧。
> - **易错原因**：把"递归写在最后一行"误当尾递归（关键是"返回前无剩余运算"）。

#### 4. 用显式栈把二叉树前序遍历改写为迭代，并说明为什么这样能避免爆栈。
> [!question]- 答案解析
> - **答案**：`stack=[root]; while stack: node=stack.pop(); visit(node); 右孩子先入栈、左孩子后入栈`。显式栈与调用栈功能等价（LIFO 保存"待访问"节点），但堆空间远比系统栈大，且深度由数据规模决定而非递归层数限制。
> - **解析**：递归栈帧含大量元数据（返回地址、寄存器），显式栈只存必要数据，同样深度下更省、更可控。
> - **易错原因**：入栈顺序写反导致访问顺序错误。

#### 5. 证明汉诺塔 $n$ 个盘需要 $2^n-1$ 次移动，并写出递推式。
> [!question]- 答案解析
> - **答案**：设 $T(n)$ 为 $n$ 盘最少移动次数。策略：把上面 $n-1$ 盘移到辅助柱（$T(n-1)$ 次）→ 移动最大盘（1 次）→ 把 $n-1$ 盘移到目标柱（$T(n-1)$ 次）。递推式 $T(n)=2T(n-1)+1$，$T(1)=1$。展开：$T(n)=2^{n-1}T(1)+(2^{n-1}-1)=2^n-1$。归纳证明：基例 $n=1$ 成立；若 $T(n-1)=2^{n-1}-1$，则 $T(n)=2(2^{n-1}-1)+1=2^n-1$。
> - **解析**：这是"递归正确性证明 = 数学归纳"的标准示范，也是指数复杂度的经典例子（$n=64$ 时 $2^{64}-1$ 次）。
> - **易错原因**：递推式写成 $T(n)=T(n-1)+2$ 之类的错误形式。
