## 1. 🎯 核心原理与算法动机

**前缀和（Prefix Sum）** 是一种预处理算法思想。通过构建辅助数据结构，将原数组的前缀累加和预先存储，把静态数组上任意连续子区间的和查询时间复杂度从 $O(N)$ 降至 $O(1)$。

### 递推定义与 1-Based 偏移设计
设原数组为 $A[0..N-1]$（0-based 下标），定义前缀和数组 $P[0..N]$ 为：
$$P[i] = \sum_{k=0}^{i-1} A[k], \quad (P[0] = 0)$$

递推关系为：
$$P[i] = P[i-1] + A[i-1], \quad \forall i \in [1, N]$$

对于任意原数组闭区间 $[L, R]$（其中 $0 \le L \le R < N$），其元素之和可表示为：
$$\text{Sum}(L, R) = \sum_{k=L}^{R} A[k] = \sum_{k=0}^{R} A[k] - \sum_{k=0}^{L-1} A[k] = P[R+1] - P[L]$$

```
原数组 A:     [  3,  -1,   4,   2,  -5,   6 ]  (下标 0..5)
前缀和 P:  [ 0,  3,   2,   6,   8,   3,   9 ]  (下标 0..6)
Sum(1, 4) = P[5] - P[1] = 3 - 3 = 0  (-1 + 4 + 2 + -5 = 0)
```

## 2. 💻 规范 C++20 实现

包含预处理区间查询类 `PrefixSum1D` 以及扩展应用：基于前缀和哈希表求**和为 K 的子数组个数**。

```cpp
#include <vector>
#include <unordered_map>
#include <cstddef>
#include <cstdint>
#include <stdexcept>

namespace Algorithm::PrefixSum {

// 1. 一维前缀和封装类 (1D Range Sum Query Class)
class PrefixSum1D {
private:
    std::vector<int64_t> P; // 使用 int64_t 预防前缀和溢出

public:
    explicit PrefixSum1D(const std::vector<int>& A) {
        const size_t n = A.size();
        P.resize(n + 1, 0);
        for (size_t i = 0; i < n; ++i) {
            P[i + 1] = P[i] + A[i];
        }
    }

    // 查询原数组闭区间 [L, R] 的累加和 (0-based)
    [[nodiscard]] int64_t query(size_t L, size_t R) const {
        if (L > R || R >= P.size() - 1) {
            throw std::out_of_range("PrefixSum1D::query Range out of bounds");
        }
        return P[R + 1] - P[L];
    }
};

// 2. 和为 K 的子数组个数 (Subarray Sum Equals K)
// 利用前缀和 Hash Map 将 O(N^2) 降至 O(N)
[[nodiscard]] int subarraySum(const std::vector<int>& nums, int k) noexcept {
    std::unordered_map<int64_t, int> prefix_freq;
    prefix_freq[0] = 1; // 初始化前缀和为 0 的频次为 1

    int count = 0;
    int64_t current_prefix = 0;

    for (int num : nums) {
        current_prefix += num;
        
        // 查找是否存在前缀和 P[j] 满足 current_prefix - P[j] == k
        const int64_t target = current_prefix - k;
        if (auto it = prefix_freq.find(target); it != prefix_freq.end()) {
            count += it->second;
        }

        prefix_freq[current_prefix]++;
    }

    return count;
}

} // namespace Algorithm::PrefixSum
```

## 3. 🔍 状态跟踪与图解分析

对输入数组 $A = [3, -1, 4, 2, -5, 6]$ 构建前缀和数组 $P$ 的生成全过程：

| $i$ | $A[i-1]$ (输入元素) | $P[i] = P[i-1] + A[i-1]$ 算式 | $P[i]$ 值 | 对应表达的前缀物理意义 |
|---|---|---|---|---|
| **0** | - | 初始设定 | **0** | 空前缀和 $\sum \emptyset = 0$ |
| **1** | $A[0] = 3$ | $0 + 3$ | **3** | $A[0]$ |
| **2** | $A[1] = -1$ | $3 + (-1)$ | **2** | $A[0] + A[1]$ |
| **3** | $A[2] = 4$ | $2 + 4$ | **6** | $A[0] + \dots + A[2]$ |
| **4** | $A[3] = 2$ | $6 + 2$ | **8** | $A[0] + \dots + A[3]$ |
| **5** | $A[4] = -5$ | $8 + (-5)$ | **3** | $A[0] + \dots + A[4]$ |
| **6** | $A[5] = 6$ | $3 + 6$ | **9** | $A[0] + \dots + A[5]$ |

#### 区间查询测试：
1. **查询 $\text{Sum}(0, 2)$**：$P[3] - P[0] = 6 - 0 = 6$。（验证：$3 + (-1) + 4 = 6$）
2. **查询 $\text{Sum}(2, 4)$**：$P[5] - P[2] = 3 - 2 = 1$。（验证：$4 + 2 + (-5) = 1$）

## 4. 📈 复杂度分析与严格证明

### 算法复杂度
- **预处理阶段**：
  - **时间复杂度**：$O(N)$。单层循环扫描一次原数组，每次计算仅需一次加法。
  - **空间复杂度**：$O(N)$。创建长度为 $N+1$ 的前缀和数组。
- **查询阶段**：
  - **时间复杂度**：$O(1)$。仅需一次减法运算 `P[R+1] - P[L]`。
  - **空间复杂度**：$O(1)$。

---

## 5. ⚠️ 常见坑点与边界条件

1. **下标偏移错位 (Off-by-one Error)**
   - 0-indexed 原数组的闭区间 $[L, R]$，其前缀和算式必须是 $P[R+1] - P[L]$，而不是 $P[R] - P[L-1]$。若试图使用 0-indexed 的前缀和数组，查询 $L=0$ 时会触发 `P[-1]` 的非法越界访问。
2. **32位整数溢出 (Integer Overflow)**
   - 若原数组长度 $N = 10^5$，元素均为 $10^9$，则前缀和最大可达 $10^{14}$，远超 32 位 signed `int`（约 $2 \times 10^9$）上限。前缀和数组必须使用 64 位 `int64_t` 或 `long long`。

## 6. 🧠 💡 Flashcards (Guided Recall)

Q: 前缀和数组中 $P[0]$ 为什么设定为 0？1-based 前缀和数组有何优势？
A: $P[0] = 0$ 代表空前缀的累加和，充当加法单位元。1-based 前缀和数组使得查询区间 $[0, R]$ 的公式统一为 $P[R+1] - P[0] = P[R+1]$，彻底消除了对 $L=0$ 边界特判分支的需求。

Q: 如何利用前缀和与哈希表在 $O(N)$ 时间内求解“和为 K 的子数组个数”？
A: 遍历数组维护当前前缀和 $S$。如果哈希表中已存在前缀和 $S - K$，说明从过去某个位置到当前位置的子数组和为 $K$。每次将 $S - K$ 的出现次数累加进答案，并将 $S$ 的频次存入哈希表。
