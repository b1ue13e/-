# 选择排序 (Selection Sort & Instability Mechanics)

> **所属课程**：数据结构与算法  
> **所属阶段**：[[🧭 阶段1-算法入门与基本分析]]  
> **前置知识**：[[数据结构与算法-排序概述]]

## 1. 🎯 选择排序核心机制

选择排序（Selection Sort）是一种直观的基于比较的排序算法。其基本思想是将数组划分为“已排序前缀”与“未排序后缀”两个部分：
1. **搜寻极值**：在每一轮遍历中，算法扫描整个未排序后缀区间，找到最小元素的下标 `min_idx`。
2. **长距离交换固定**：将找到的最小元素与未排序后缀的首个元素 `arr[i]` 进行位置交换，将其纳入已排序前缀末尾。
3. **最小交换次数特性**：尽管比较次数固定为 $O(n^2)$，但选择排序在整个过程中**最多仅触发 $n-1$ 次数据交换**（Swap Operations），这使得它在写入代价极高的存储介质（如 Flash/EEPROM）中具有独特的物理优势。

---

## 2. 🔍 步骤跟踪 (Step-by-Step Trace)

以输入数组 `[64, 25, 12, 22, 11]`（长度 $n=5$）为例，跟踪选择排序的每轮选择与交换过程：

```
初始状态: [64, 25, 12, 22, 11]
```

### 轮次 1 (`i = 0`): 未排序区间 `[0, 4]` (即 `[64, 25, 12, 22, 11]`)
- 初始化 `min_idx = 0` (对应元素 `64`)。
- 扫描比较：`25 < 64` $\to$ `min_idx = 1`；`12 < 25` $\to$ `min_idx = 2`；`22 > 12`；`11 < 12` $\to$ `min_idx = 4`。
- 未排序区最小值为 `11`（下标 4）。
- **交换** `arr[0]` (`64`) 与 `arr[4]` (`11`) $\implies$ 数组变为 `[11, 25, 12, 22, 64]`。

### 轮次 2 (`i = 1`): 未排序区间 `[1, 4]` (即 `[25, 12, 22, 64]`)
- 初始化 `min_idx = 1` (对应元素 `25`)。
- 扫描比较：`12 < 25` $\to$ `min_idx = 2`；`22 > 12`；`64 > 12`。
- 未排序区最小值为 `12`（下标 2）。
- **交换** `arr[1]` (`25`) 与 `arr[2]` (`12`) $\implies$ 数组变为 `[11, 12, 25, 22, 64]`。

### 轮次 3 (`i = 2`): 未排序区间 `[2, 4]` (即 `[25, 22, 64]`)
- 初始化 `min_idx = 2` (对应元素 `25`)。
- 扫描比较：`22 < 25` $\to$ `min_idx = 3`；`64 > 22`。
- 未排序区最小值为 `22`（下标 3）。
- **交换** `arr[2]` (`25`) 与 `arr[3]` (`22`) $\implies$ 数组变为 `[11, 12, 22, 25, 64]`。

### 轮次 4 (`i = 3`): 未排序区间 `[3, 4]` (即 `[25, 64]`)
- 初始化 `min_idx = 3` (对应元素 `25`)。
- 扫描比较：`64 > 25`。
- 最小值即为当前元素 `25`（下标 3）。
- 交换 `arr[3]` 与 `arr[3]`（原地空交换） $\implies$ 数组保持 `[11, 12, 22, 25, 64]`。

**最终输出**：`[11, 12, 22, 25, 64]`，经历 4 轮扫描，共发生 3 次有效位置交换。

## 3. 🚨 选择排序的不稳定性反例证明 (Instability Proof)

选择排序是一种**不稳定排序算法**。原因在于：将未排序区间的最小值与未排序区首元素交换时，可能会跨越并打破中间相同键值元素的原始顺序。

### 反例构造与推导：
考虑输入数组包含重复键值：`[5_a, 8, 5_b, 2]`，其中 `5_a` 与 `5_b` 数值相等，但初始位置 `5_a` 在 `5_b` 前面（下标分别为 0 和 2）。

1. **第 1 轮 (`i = 0`)**：
   - 扫描未排序序列 `[5_a, 8, 5_b, 2]`，找到最小值元素为 `2`（下标 3）。
   - 将 `arr[0]` (`5_a`) 与 `arr[3]` (`2`) 进行位置交换。
   - 交换后数组状态变为：`[2, 8, 5_b, 5_a]`。
2. **后续轮次**：
   - 最终排好序的数组为：`[2, 5_b, 5_a, 8]`。

**结论**：原来排在前面的 `5_a` 最终被甩到了 `5_b` 的后面，打破了同值元素的相对相对位置。因此，选择排序在物理上是**不稳定**的。

## 4. 📐 复杂度分析

1. **比较时间复杂度（最好、平均、最坏均相同）**：
   - 无论初始数组是否有序，外层 `i` 从 `0` 到 `n-2`，内层 `j` 必须完整扫描 `n-1-i` 个元素。
   - 比较总次数为固定的算术级数：
     $$T_{\text{cmp}}(n) = \sum_{i=0}^{n-2} (n - 1 - i) = \frac{n(n-1)}{2}$$
   - 故最优、最坏和平均时间复杂度均为 $\Theta(n^2)$。

2. **交换时间复杂度**：
   - 交换操作仅在每轮内循环结束后触发一次，总交换次数最多为 $n-1$ 次。
   - 交换时间复杂度为 $O(n)$。

3. **空间复杂度**：
   - 原位排序（In-place Sorting），仅需 `i`, `j`, `min_idx` 变量，额外空间复杂度为 $O(1)$。

## 5. 💻 C++20 完整实现代码

```cpp
#include <iostream>
#include <vector>
#include <utility>
#include <cassert>

template <typename T>
void selection_sort(std::vector<T>& arr) {
    const size_t n = arr.size();
    if (n <= 1) return;

    for (size_t i = 0; i < n - 1; ++i) {
        size_t min_idx = i;
        // 扫码未排序子数组 [i+1, n-1]，寻找最小值下标
        for (size_t j = i + 1; j < n; ++j) {
            if (arr[j] < arr[min_idx]) {
                min_idx = j;
            }
        }
        // 仅在找到更小元素时才触发交换
        if (min_idx != i) {
            std::swap(arr[i], arr[min_idx]);
        }
    }
}

int main() {
    std::vector<int> data = {64, 25, 12, 22, 11};
    selection_sort(data);

    std::vector<int> expected = {11, 12, 22, 25, 64};
    assert(data == expected);

    std::cout << "[选择排序测试] 排序成功: ";
    for (int v : data) std::cout << v << " ";
    std::cout << "\n";
    return 0;
}
```

## 6. ⚠️ 常见工程陷阱与边界坑点

1. **盲目增加稳定控制导致性能大幅下滑**  
   若为了追求稳定性而将交换改为“将最小值插入首部并整体右移”，选择排序的移动复杂度将从 $O(n)$ 急剧升至 $O(n^2)$，从而完全失去了选择排序相比于插入排序的移动次数优势。

2. **无条件执行 `std::swap`**  
   若忽略 `if (min_idx != i)` 判断，每轮都会强制执行 `std::swap(arr[i], arr[i])`，虽然结果正确，但在处理大对象（Large Objects）时会导致大量无谓的内存移动开销。

## 7. 🃏 闭卷自测考点 (Anki Card)

- Q: **为什么选择排序在已完全有序的数组上，时间复杂度依然是 $O(n^2)$？**
- A: 因为选择排序每轮必须在未排序区间内寻找最小值，内层循环不会因为数组有序而提前终止，比较次数固定为 $\frac{n(n-1)}{2}$，因此最优与最坏比较时间复杂度均为 $\Theta(n^2)$。

- Q: **请通过一个具体数组反例说明选择排序为什么是不稳定排序。**
- A: 对于数组 `[5_a, 8, 5_b, 2]`，第一轮选择最小值 `2` 与首元素 `5_a` 交换，数组变为 `[2, 8, 5_b, 5_a]`。此时原本在前方的 `5_a` 被交换到了 `5_b` 的后方，颠覆了同值元素的原始位置关系。

- Q: **在什么特定的硬件或存储场景下，选择排序比冒泡排序和插入排序更有优势？**
- A: 选择排序具有 $O(n)$ 的极低数据交换/写入次数（最多 $n-1$ 次）。在对擦写寿命有限或写入开销极大的存储介质（如 EEPROM/Flash）中，选择排序能极大减少存储硬件的磨损。

## 🚨 常见误区与边界条件

1. **选择排序的不稳定性**：直接交换最小值与当前位置元素可能跨越相同元素，破坏稳定性（例如 `[5, 8, 5, 2]`，第一个 `5` 会与 `2` 交换到第二个 `5` 后面）。
2. **无论初始状态如何均为 $O(n^2)$**：选择排序无法像冒泡排序或插入排序那样利用数组的局部有序性提前终止。
