## 1. 🎯 核心原理与连续域二分特性

**浮点数二分（Floating-Point Binary Search）** 用于在连续实数区间 $[left, right]$ 上寻找某个满足连续单调函数的解（如根号 $\sqrt{x}$、立方根 $\sqrt[3]{x}$、方程近似根等）。

与整数二分相比，浮点二分具备以下本质区别：
1. **连续域无“偏置 +1/-1”**：实数是连续的，不存在最小整数步长 1。因此**绝不能使用 `mid + 1` 或 `mid - 1`**，区间更新只能精确赋值为 `left = mid` 或 `right = mid`。
2. **精度与终止条件**：没有“精准命中”的概念，只有**近似精度极限**。终止条件主要有两种模式：
   - 模式 A：精度差值控制 `while (right - left > eps)`；
   - 模式 B：固定高频迭代 `for (int i = 0; i < 100; i++)`。

```
求解 sqrt(2.0) 搜索区间收敛示意 (eps = 1e-4):
[0.0 ────────────────────── mid=1.0 ────────────────────── 2.0]  1.0^2 < 2.0 -> left=1.0
[1.0 ───────────── mid=1.5 ───────────── 2.0]                  1.5^2 > 2.0 -> right=1.5
[1.0 ────── mid=1.25 ────── 1.5]                                1.25^2 < 2.0 -> left=1.25
[1.25 ── mid=1.375 ── 1.5]                                      1.375^2 < 2.0 -> left=1.375
... 经过约 25 次分割后，区间缩小至 [1.41421, 1.41428]
```

### 1.1 初始搜索域防护：当 $x < 1.0$ 时的离群边界
求平方根 $\sqrt{x}$ 时，习惯将初始区间设为 $[0, x]$。**然而这在 $x < 1.0$ 时是致命逻辑漏洞**！
例如：若 $x = 0.25$，其实际平方根为 $\sqrt{0.25} = 0.5$。若初始区间设为 $[0.0, 0.25]$，正确解 $0.5$ 根本落不在搜索区间内，算法必然求出错误解。

因此，求平方根的初始右边界必须设为 $\max(1.0, x)$，即初始区间为：

$$[left, right] = [0.0, \max(1.0, x)]$$

## 2. 📐 渐近分析与精度迭代公式

### 2.1 迭代次数与精度关系推导
设初始区间长度为 $L = right - left$，目标精度为 $\epsilon = eps$。
每次迭代后区间长度减半，经过 $K$ 次迭代后区间长度缩减为 $\frac{L}{2^K}$。
当区间长度小于等于 $\epsilon$ 时终止：

$$\frac{L}{2^K} \le \epsilon \implies 2^K \ge \frac{L}{\epsilon} \implies K = \left\lceil \log_2 \left( \frac{L}{\epsilon} \right) \right\rceil$$

#### 算例分析：
若初始区间 $L = 2.0 - 0.0 = 2.0$，要求保留 6 位小数（$\epsilon = 10^{-7}$）：

$$K = \left\lceil \log_2 \left( \frac{2}{10^{-7}} \right) \right\rceil = \left\lceil \log_2 (2 \times 10^7) \right\rceil = \lceil 24.25 \rceil = 25 \text{ 次}$$

### 2.2 两种终止条件的性能与鲁棒性对比

| 终止方式 | 实现逻辑 | 优点 | 缺点 / 隐藏危险 |
| :--- | :--- | :--- | :--- |
| **`right - left > eps`** | 达到指定差值立即退出 | 迭代次数恰好满足要求 | 若 `eps` 设得过小（接近 `DBL_EPSILON`），由于 IEEE 754 精度舍入，`right - left` 无法继续减小，**引发死循环**！ |
| **固定 100 次循环** | `for(int i=0; i<100; i++)` | 100 次分割使精度达到 $1/2^{100} \approx 10^{-30}$，**100% 避免死循环** | 额外进行少量常数次无用计算（但极为安全） |

## 3. 💻 C++ 20 完整工程实现与测试

以下代码演示了使用固定 100 次迭代与 `eps` 两种方式计算 `sqrt(x)` 和支持负数的 `cbrt(x)`（立方根），并与标准库 `std::sqrt` 进行精度断言比较：

```cpp
#include <iostream>
#include <algorithm>
#include <cmath>
#include <cassert>
#include <iomanip>

using namespace std;

class FloatBinarySearch {
public:
    // 1. 浮点二分求平方根 sqrt(x)
    static double my_sqrt(double x) {
        if (x < 0) throw invalid_argument("x must be non-negative");
        if (x == 0.0) return 0.0;

        // 边界防护：处理 x < 1.0 的情况 (如 x = 0.25 -> right = 1.0)
        double left = 0.0;
        double right = max(1.0, x);

        // 推荐采用固定 100 次迭代，精度极高且防死循环 (2^100 逼近机器极限)
        for (int i = 0; i < 100; ++i) {
            double mid = left + (right - left) / 2.0;
            if (mid * mid >= x) {
                right = mid;
            } else {
                left = mid;
            }
        }
        return left;
    }

    // 2. 浮点二分求立方根 cbrt(x) (支持负数)
    static double my_cbrt(double n, double eps = 1e-8) {
        bool is_negative = n < 0;
        double val = abs(n);

        double left = 0.0;
        double right = max(1.0, val);

        while (right - left > eps) {
            double mid = left + (right - left) / 2.0;
            if (mid * mid * mid >= val) {
                right = mid;
            } else {
                left = mid;
            }
        }
        return is_negative ? -left : left;
    }
};

int main() {
    // 测试 1: 普通正实数 sqrt(2.0)
    double res1 = FloatBinarySearch::my_sqrt(2.0);
    double std_res1 = sqrt(2.0);
    cout << setprecision(10);
    cout << "[Sqrt Test] Calculated sqrt(2.0) = " << res1 << " | std::sqrt = " << std_res1 << endl;
    assert(abs(res1 - std_res1) < 1e-9);

    // 测试 2: 小于 1.0 的实数 sqrt(0.04) -> 应为 0.2
    double res2 = FloatBinarySearch::my_sqrt(0.04);
    cout << "[Sqrt Test] Calculated sqrt(0.04) = " << res2 << " | Expected = 0.2" << endl;
    assert(abs(res2 - 0.2) < 1e-9);

    // 测试 3: 负实数立方根 cbrt(-1000.0) -> 应为 -10.0
    double res3 = FloatBinarySearch::my_cbrt(-1000.0);
    cout << "[Cbrt Test] Calculated cbrt(-1000.0) = " << res3 << " | Expected = -10.0" << endl;
    assert(abs(res3 - (-10.0)) < 1e-7);

    return 0;
}
```

## 5. ⚠️ 经典陷阱与边界防御

1. **`x < 1.0` 导致右边界不足（Insufficient Upper Bound Hazard）**：
   - *陷阱*：对于 $x = 0.09$，若令 `right = x`（即 `right = 0.09`），由于正确解 $\sqrt{0.09} = 0.3 > 0.09$，解落在区间外部，算法将永远输出错误值 `0.09`。
   - *防御*：右边界必须设为 `right = max(1.0, x)`。

2. **精度 `eps` 设置过微小引发死循环（Double Precision Limit Bug）**：
   - *陷阱*：写 `while (right - left > 1e-18)`。在 C++ 中，`double` 的有效精度约为 15~17 位十进制数（机器 epsilon 为 $2.22 \times 10^{-16}$）。当区间缩小到浮点精度极限时，`right - left` 不再变小，`while` 无法退出，CPU 占用率飙升 100%。
   - *防御*：题目要求保留 $k$ 位小数时，`eps` 通常设为 $10^{-(k+2)}$；或者直接采用极其稳妥的 `for (int i = 0; i < 100; ++i)`。

3. **错误添加 `mid + 1` 导致计算离散破坏**：
   - *陷阱*：将整数二分的习惯误用到浮点数：写成 `left = mid + 1`。
   - *后果*：将浮点搜索跳过了整整 1.0 的区间，丢失所有小数解。

## 6. 🃏 闭卷自测与 Anki 卡片

### 闭卷自测考点
- **问答**：用浮点二分计算 $\sqrt{x}$ 时，如果要求绝对误差不超过 $10^{-6}$，且初始搜索范围为 $[0, 1000]$，最少需要进行多少次二分迭代？
- **标准解答**：
  - 公式：$K = \lceil \log_2(L / \epsilon) \rceil$。
  - 带入数据：$L = 1000, \epsilon = 10^{-6} \implies L / \epsilon = 10^9$。
  - $K = \lceil \log_2(10^9) \rceil = \lceil 29.897 \rceil = 30$ 次。

## 🚨 常见误区与边界条件

1. **浮点数精度死循环**：不能直接用 `left == right` 作为终止条件。应指定精度 `right - left > eps`（如 `eps = 1e-8`），或直接控制固定循环次数（如 `for _ in range(100)`）。
2. **精度丢失**：双精度 `double` 有 53 位尾数，单精度 `float` 只有 23 位尾数。浮点二分尽量使用 `double` 避免精度累积误差。

## 🃏 Anki 卡片

- Q: 为什么浮点二分求平方根 $\sqrt{x}$ 时，初始右边界不能直接写成 `right = x`？
- A: 当 $x < 1.0$ 时（例如 $x=0.25$），其平方根 $\sqrt{0.25} = 0.5 > 0.25$。若 `right = x`，正确解将落在初始搜索区间之外导致错误。正确写法为 `right = max(1.0, x)`。
---
- Q: 为什么在工程和竞赛中推荐使用 `for (int i = 0; i < 100; i++)` 替代 `while (right - left > eps)`？
- A: 100 次二分能使区间缩小 $2^{100} \approx 10^{30}$ 倍，远远超过浮点数精度极限；同时能彻底杜绝因 `eps` 设置低于浮点数机器 epsilon 造成的死循环。
---
- Q: 浮点二分中为什么不能写 `left = mid + 1` 或 `right = mid - 1`？
- A: 浮点数在连续实数域上没有最小整数单位 1，加上 1 会跳过连续的实数解空间，必须精确写为 `left = mid` 或 `right = mid`。
