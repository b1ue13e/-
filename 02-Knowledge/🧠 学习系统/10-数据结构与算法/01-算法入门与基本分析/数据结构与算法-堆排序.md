# 堆排序 (Heapsort: O(n) Build-Heap & Siftdown Analysis)

## 1. 🎯 堆排序物理结构与二叉堆索引公式

堆排序（Heapsort）是一种利用**大顶堆（Max-Heap）**数据结构设计的原位比较排序算法。在连续数组存储的完全二叉树中，节点下标存在严密的代数对应关系（以 0-based 索引为例）：
* **左子节点下标**：`left = 2 * i + 1`
* **右子节点下标**：`right = 2 * i + 2`
* **父节点下标**：`parent = (i - 1) / 2`
* **最后一个非叶节点下标**：`last_non_leaf = (n / 2) - 1`

堆排序分为两大阶段：
1. **建堆阶段 (Build-Heap)**：从最后一个非叶节点开始，自底向上对每个节点执行 `siftdown`（下沉/下洗）调整，将无序数组原地构建为一个合法的大顶堆。
2. **提取与下沉阶段 (Extract-Max Loop)**：重复将堆顶最大值（`arr[0]`）与当前堆末尾元素交换，堆有效大小减 1，并对新的堆顶重新执行 `siftdown`，直到堆大小收缩至 1。

## 2. 📐 建堆 $O(n)$ 时间复杂度的严格数学证明

建堆有两种策略：基于 `siftup`（上浮）的累加法和基于 `siftdown`（下沉）的批量建堆法。两者的渐近复杂度存在本质差异：

### 2.1 基于 Siftdown 的建堆推导（为何是 $O(n)$）
设包含 $n$ 个节点的完全二叉树高度为 $H = \lfloor \log_2 n \rfloor$。
在高度为 $h$ 处的节点数量最多为 $\lceil \frac{n}{2^{h+1}} \rceil$。对高度为 $h$ 的节点执行 `siftdown` 最多需要下沉 $h$ 步。

建堆总下沉步数为：
$$S(n) = \sum_{h=0}^{\lfloor \log_2 n \rfloor} \frac{n}{2^{h+1}} \cdot O(h) = O\left( n \sum_{h=0}^{\infty} \frac{h}{2^h} \right)$$

利用级数求和公式（已知 $\sum_{h=0}^{\infty} \frac{h}{2^h} = 2$）：
$$S(n) = O\left( n \cdot 2 \right) = \mathbf{O(n)}$$

**直观解释**：树中约 $50\%$ 的节点是叶节点（高度 0，下沉 0 步），约 $25\%$ 的节点高度为 1（下沉 1 步）。绝大部分节点处于树的底层，下沉距离极短，因此总开销为严格线性 **$O(n)$**。

### 2.2 为什么基于 Siftup 建堆是 $O(n \log n)$
若通过逐个插入元素使用 `siftup` 建堆，叶节点位于树底（高度 $H$），上浮距离最长（$O(\log n)$ 步）。
总步数为 $\sum_{i=1}^n O(\log i) = \mathbf{\Theta(n \log n)}$。因此工业实现必须采用 `siftdown` 建堆。

## 3. 🔍 步骤跟踪 (Step-by-Step Trace)

以输入数组 `[4, 10, 3, 5, 1]`（长度 $n=5$）为例：

### 1. 建堆阶段 (Build Max-Heap)
- 最后一个非叶节点 `last_non_leaf = (5/2) - 1 = 1`（即元素 `10`）。
- **`i = 1` (元素 `10`)**: 左右子节点为 `5` (idx 3) 与 `1` (idx 4)。`10` 大于两子节点，无需下沉 $\to$ `[4, 10, 3, 5, 1]`。
- **`i = 0` (元素 `4`)**: 左右子节点为 `10` (idx 1) 与 `3` (idx 2)。较大孩子为 `10`。
  - `4` 与 `10` 交换 $\to$ `[10, 4, 3, 5, 1]`。
  - `4` 下沉至 idx 1，继续检查其孩子 `5` (idx 3) 和 `1` (idx 4)。较大孩子为 `5`。
  - `4` 与 `5` 交换 $\to$ `[10, 5, 3, 4, 1]`。
- **建堆完成**：大顶堆为 `[10, 5, 3, 4, 1]`。

### 2. 排序抽取阶段 (Extract-Max Loop)
- **轮次 1 (`n = 5`)**：
  - 交换堆顶 `10` (idx 0) 与末尾 `1` (idx 4) $\to$ `[1, 5, 3, 4, 10]`。
  - 有效堆大小降为 4。对 `arr[0]` (`1`) 执行 `siftdown`：
    - `1` 与 `5` 交换 $\to$ `[5, 1, 3, 4, 10]`；
    - `1` 与 `4` 交换 $\to$ `[5, 4, 3, 1, 10]`。
- **轮次 2 (`n = 4`)**：
  - 交换堆顶 `5` (idx 0) 与末尾 `1` (idx 3) $\to$ `[1, 4, 3, 5, 10]`。
  - 有效堆大小降为 3。对 `1` 执 `siftdown` $\to$ `1` 与 `4` 交换 $\to$ `[4, 1, 3, 5, 10]`。
- **轮次 3 (`n = 3`)**：
  - 交换堆顶 `4` (idx 0) 与末尾 `3` (idx 2) $\to$ `[3, 1, 4, 5, 10]`。
  - 有效堆大小降为 2。对 `3` 执 `siftdown` $\to$ `3 > 1` 无需下沉 $\to$ `[3, 1, 4, 5, 10]`。
- **轮次 4 (`n = 2`)**：
  - 交换堆顶 `3` (idx 0) 与末尾 `1` (idx 1) $\to$ `[1, 3, 4, 5, 10]`。
  - 有效堆大小降为 1，循环结束。

**最终有序输出**：`[1, 3, 4, 5, 10]`。

## 4. 💻 C++20 完整实现代码

```cpp
#include <iostream>
#include <vector>
#include <utility>
#include <cassert>

// siftdown 下沉调整函数
template <typename T>
void siftdown(std::vector<T>& arr, size_t n, size_t i) {
    size_t largest = i;

    while (true) {
        size_t left = 2 * i + 1;
        size_t right = 2 * i + 2;

        if (left < n && arr[left] > arr[largest]) {
            largest = left;
        }
        if (right < n && arr[right] > arr[largest]) {
            largest = right;
        }

        if (largest != i) {
            std::swap(arr[i], arr[largest]);
            i = largest; // 迭代式下沉，避免递归栈开销
        } else {
            break;
        }
    }
}

// 堆排序核心
template <typename T>
void heap_sort(std::vector<T>& arr) {
    const size_t n = arr.size();
    if (n <= 1) return;

    // 1. O(n) 建堆：从最后一个非叶节点自底向上下沉
    for (ssize_t i = static_cast<ssize_t>(n / 2) - 1; i >= 0; --i) {
        siftdown(arr, n, static_cast<size_t>(i));
    }

    // 2. O(n log n) 提取最大值循环
    for (size_t i = n - 1; i > 0; --i) {
        std::swap(arr[0], arr[i]); // 堆顶最大值放到已排序区间前缀
        siftdown(arr, i, 0);       // 对缩小后的堆重新下沉调整
    }
}

int main() {
    std::vector<int> data = {4, 10, 3, 5, 1};
    heap_sort(data);

    std::vector<int> expected = {1, 3, 4, 5, 10};
    assert(data == expected);

    std::cout << "[堆排序测试] 排序成功: ";
    for (int v : data) std::cout << v << " ";
    std::cout << "\n";
    return 0;
}
```

## 5. ⚠️ 常见工程陷阱与不稳定性分析

1. **堆排序的不稳定性（Unstability）**  
   堆顶元素与堆末尾元素交换时，会将原本在前面的最大值瞬间移动到数组末尾。若存在两个相同键值的最大值，先到达堆顶的那个会被先交换到后方，彻底颠覆它们的初始相对物理顺序。因此**堆排序是不稳定排序**。

2. **`siftdown` 索引边界越界**  
   在检查左孩子 `left = 2*i + 1` 和右孩子 `right = 2*i + 2` 时，必须优先检查 `left < n` 与 `right < n`（`n` 为当前有效堆大小，而非原数组总长度 `arr.size()`），否则会在提取阶段访问已被剔除堆外的已排序元素。

## 6. 🃏 闭卷自测考点 (Anki Card)

- Q: **请证明为什么基于 `siftdown` 的建堆过程时间复杂度是 $O(n)$ 而非 $O(n \log n)$？**
- A: 高度为 $h$ 的节点数量为 $\frac{n}{2^{h+1}}$，每个节点下沉最多 $h$ 步。建堆总步数为 $S(n) = \sum \frac{n}{2^{h+1}} O(h) = O(n \sum \frac{h}{2^h})$。由于级数 $\sum \frac{h}{2^h} = 2$ 收敛，故总时间复杂度为严格的 $O(n)$。

- Q: **堆排序的空间复杂度是多少？为什么它比归并排序更省内存？**
- A: 堆排序的空间复杂度为 $O(1)$。因为它直接利用原数组的物理连续空间映射为完全二叉树，在数组内部完成节点交换与下沉，完全不需要归并排序所需的高达 $O(n)$ 的辅助合并数组。

- Q: **已知当前节点索引为 `i`（0-based），如何计算其父节点、左右孩子的数组下标？**
- A: 父节点下标为 `(i - 1) / 2`；左孩子下标为 `2 * i + 1`；右孩子下标为 `2 * i + 2`。

## 🚨 常见误区与边界条件

1. **建堆复杂度误解**：自顶向下逐个 `heappush` 插入建堆的时间复杂度为 $O(n \log n)$；自底向上 `heapify` 建堆的时间复杂度才是真正的 $O(n)$。
2. **1-indexed 与 0-indexed 节点的父子索引**：
   - 0-indexed 数组：左子节点为 `2*i + 1`，右子节点为 `2*i + 2`，父节点为 `(i - 1) // 2`；
   - 混淆索引会导致访问错位或无限下沉。
