## 1. 🎯 核心原理与算法动机分析

均摊分析（Amortized Analysis）用于分析在一连串数据结构操作序列中，**单次操作的平摊平均时间上界**。与平均时间复杂度不同，均摊分析**不涉及任何概率分布假设**，它在最坏操作序列下给出了确定的单次均摊性能保证。

当一个数据结构绝大多数操作成本低昂（如 $\mathcal{O}(1)$），而偶尔会有一次高昂昂贵的操作（如 $\mathcal{O}(N)$ 的扩容重新分配），均摊分析可以证明：高昂操作的成本可以分摊到大量便宜的操作上。

### 三大经典均摊分析方法

1. **聚合分析 (Aggregate Analysis)**：
   直接计算 $N$ 个操作组成的操作序列的总成本 $T(N)$，则单次操作的均摊成本即为 $\frac{T(N)}{N}$。
2. **记账员法 / 银行家法 (Accounting Method)**：
   为每种操作指定一个虚拟的“均摊费用” $\hat{c}_i$。当实际费用 $c_i < \hat{c}_i$ 时，将差额存入“银行账户”作为存款；当实际费用 $c_i > \hat{c}_i$ 时，消耗账户中的存款来支付昂贵操作。只要保证账户余额时刻 $\ge 0$，均摊费用的累加和就是实际总成本的上界。
3. **势能法 (Potential Method)**：
   将数据结构的状态映射为一个实数势能值 $\Phi(D_i)$，要求对任意状态 $i$ 均有 $\Phi(D_i) \ge \Phi(D_0)$。
   第 $i$ 次操作的均摊成本定义为：
   $$\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1})$$
   对 $N$ 次操作求和，势能差抵消后得到：
   $$\sum_{i=1}^N c_i = \sum_{i=1}^N \hat{c}_i - (\Phi(D_N) - \Phi(D_0)) \le \sum_{i=1}^N \hat{c}_i$$

## 2. 💻 真实 C++20 算法实现

下例实现了一个具备显式均摊追踪功能的动态数组 `AmortizedVector<T>`。在 `push_back` 发生翻倍扩容（容量由 $K \to 2K$）时，记录实际昂贵开销与势能函数变化。

```cpp
#include <iostream>
#include <memory>
#include <iomanip>
#include <cassert>

namespace dsa {

template <typename T>
class AmortizedVector {
private:
    T* data_{nullptr};
    std::size_t size_{0};
    std::size_t capacity_{0};

public:
    explicit AmortizedVector(std::size_t initial_cap = 1) 
        : capacity_(initial_cap) {
        data_ = new T[capacity_];
    }

    ~AmortizedVector() {
        delete[] data_;
    }

    // 禁用拷贝以简化内存演示
    AmortizedVector(const AmortizedVector&) = delete;
    AmortizedVector& operator=(const AmortizedVector&) = delete;

    /**
     * @brief 尾部插入元素，追踪扩容成本
     * @return struct OperationStats { actual_cost, old_cap, new_cap, potential }
     */
    struct Stats {
        std::size_t actual_cost;
        std::size_t old_cap;
        std::size_t new_cap;
        long long potential; // 势能函数 Φ(D_i) = 2 * size - capacity
    };

    Stats push_back(const T& value) {
        std::size_t cost = 1; // 写入新元素的实际基本操作成本 1
        std::size_t old_cap = capacity_;

        if (size_ == capacity_) {
            // 发生翻倍扩容
            std::size_t new_capacity = capacity_ * 2;
            T* new_data = new T[new_capacity];
            
            for (std::size_t i = 0; i < size_; ++i) {
                new_data[i] = data_[i];
                cost++; // 元素搬移操作成本
            }
            
            delete[] data_;
            data_ = new_data;
            capacity_ = new_capacity;
        }

        data_[size_++] = value;
        
        // 势能定义：Φ(D_i) = 2 * size - capacity
        long long potential = static_cast<long long>(2 * size_) - static_cast<long long>(capacity_);

        return {cost, old_cap, capacity_, potential};
    }

    [[nodiscard]] std::size_t size() const noexcept { return size_; }
    [[nodiscard]] std::size_t capacity() const noexcept { return capacity_; }
};

} // namespace dsa

int main() {
    dsa::AmortizedVector<int> vec(1);

    std::cout << std::left << std::setw(10) << "Elem Index"
              << std::setw(15) << "Actual Cost c_i"
              << std::setw(15) << "Capacity C_i"
              << std::setw(20) << "Potential Φ(D_i)"
              << std::setw(15) << "Bank Credit B_i" << "\n";
    std::cout << std::string(75, '-') << "\n";

    std::size_t total_actual_cost = 0;
    long long bank_balance = 0;

    for (int i = 1; i <= 9; ++i) {
        auto stats = vec.push_back(i * 10);
        total_actual_cost += stats.actual_cost;
        
        // 假定每步收取的均摊费用 c_hat = 3
        bank_balance += (3 - static_cast<long long>(stats.actual_cost));

        std::cout << std::left << std::setw(10) << i
                  << std::setw(15) << stats.actual_cost
                  << std::setw(15) << stats.new_cap
                  << std::setw(20) << stats.potential
                  << std::setw(15) << bank_balance << "\n";
    }

    std::cout << "\n推送 9 个元素累计总实际成本: " << total_actual_cost << "\n";
    std::cout << "均摊单次预测上界 (3 * 9 = 27) >= 实际成本 (" << total_actual_cost << ")\n";
    assert(bank_balance >= 0);

    return 0;
}
```

## 3. 🔍 逐步执行跟踪 (Step-by-Step State Trace)

推演初始容量为 `1` 的动态数组，连续插入 `N = 9` 个元素的均摊状态推演表：

| 插入序号 $i$ | 插入前元素数 $size$ | 插入前容量 $C$ | 是否触发扩容 | 实际开销 $c_i$ (搬移+写入) | 插入后容量 $C'$ | 势能值 $\Phi_i = 2i - C'$ | 均摊开销 $\hat{c}_i = c_i + \Delta\Phi$ | 银行余额 $B_i$ (累加 $3 - c_i$) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | 0 | 1 | 否 (0 < 1) | 1 | 1 | $2(1)-1 = 1$ | $1 + (1-0) = 2$ | $+2$ |
| **2** | 1 | 1 | **是 ($1 \to 2$)** | **$1+1 = 2$** | 2 | $2(2)-2 = 2$ | $2 + (2-1) = 3$ | $+3$ |
| **3** | 2 | 2 | **是 ($2 \to 4$)** | **$2+1 = 3$** | 4 | $2(3)-4 = 2$ | $3 + (2-2) = 3$ | $+3$ |
| **4** | 3 | 4 | 否 (3 < 4) | 1 | 4 | $2(4)-4 = 4$ | $1 + (4-2) = 3$ | $+5$ |
| **5** | 4 | 4 | **是 ($4 \to 8$)** | **$4+1 = 5$** | 8 | $2(5)-8 = 2$ | $5 + (2-4) = 3$ | $+3$ |
| **6** | 5 | 8 | 否 (5 < 8) | 1 | 8 | $2(6)-8 = 4$ | $1 + (4-2) = 3$ | $+5$ |
| **7** | 6 | 8 | 否 (6 < 8) | 1 | 8 | $2(7)-8 = 6$ | $1 + (6-4) = 3$ | $+7$ |
| **8** | 7 | 8 | 否 (7 < 8) | 1 | 8 | $2(8)-8 = 8$ | $1 + (8-6) = 3$ | $+9$ |
| **9** | 8 | 8 | **是 ($8 \to 16$)** | **$8+1 = 9$** | 16 | $2(9)-16 = 2$ | $9 + (2-8) = 3$ | $+3$ |

**观察分析**：除了第 1 步外，不论是否触发扩容，在势能法下计算出的单次均摊开销 $\hat{c}_i$ **恒定等于 3**！银行账户余额 $B_i$ 永远严格非负。

## 4. 🧮 复杂度分析与数学证明

### 动态数组容量翻倍策略的聚合分析证明

假设动态数组从容量 1 开始，进行 $N$ 次 `push_back` 操作。
其中第 $i$ 次操作的实际开销为：

$$c_i = \begin{cases} 
i & \text{若 } i - 1 \text{ 为 2 的幂（触发扩容搬移）} \\ 
1 & \text{其他情况} 
\end{cases}$$

总实际开销 $T(N)$ 为所有常规写入与扩容搬移开销的总和：

$$T(N) = \sum_{i=1}^N c_i = \sum_{i=1}^N 1 + \sum_{j=0}^{\lfloor \log_2 N \rfloor} 2^j = N + (2^{\lfloor \log_2 N \rfloor + 1} - 1)$$

由于 $2^{\lfloor \log_2 N \rfloor} \le N$，代入得：

$$T(N) < N + 2N - 1 = 3N - 1 = \mathcal{O}(N)$$

**结论**：连续进行 $N$ 次 `push_back` 的总时间复杂度为 $\mathcal{O}(N)$，因此单次 `push_back` 的均摊时间复杂度为：

$$\text{Amortized Cost} = \frac{T(N)}{N} = \frac{\mathcal{O}(N)}{N} = \mathcal{O}(1)$$

## 5. ⚠️ 常见陷阱与边角情况 (Common Pitfalls)

1. **混淆“均摊复杂度”与“平均复杂度”**：
   平均复杂度依赖对输入数据的**概率分布假设**；而均摊复杂度适用于**确定性的最坏操作序列**，能够给出无概率依赖的 100% 确定性单次均摊界限。
2. **错误的扩容增长因子（固定步长增加 $\Delta K$）**：
   如果将扩容策略改为每次增加固定容量 $K$（如 `capacity += 100`），则对连续 $N$ 次插入，总搬移开销为等差数列 $\sum_{m=1}^{N/K} m \cdot K = \mathcal{O}(N^2)$，单次均摊复杂度退化为 $\mathcal{O}(N)$！必须采用按比例倍增（如几何级数 $\alpha = 1.5$ 或 $2.0$）才能维持 $\mathcal{O}(1)$ 均摊。
3. **势能函数不满足初始/终态约束**：
   定义势能函数 $\Phi$ 时，若存在某个中间状态使 $\Phi(D_i) < \Phi(D_0)$，则势能差累加无法抵消，导出的均摊界失效。

## 🚨 常见误区与边界条件

1. **混淆均摊复杂度与平均复杂度**：均摊复杂度 (Amortized Complexity) 适用于对确定的操作序列分析最坏情况下的平均成本（如动态数组扩容）；而平均复杂度依赖于输入数据的概率分布。
2. **最坏单次操作开销忽略**：即便均摊复杂度为 (1)$，单次最坏操作（如扩容时的数组拷贝）仍可能达到 (n)$，在实时高并发或硬实时系统中仍需防范该延迟峰值。
