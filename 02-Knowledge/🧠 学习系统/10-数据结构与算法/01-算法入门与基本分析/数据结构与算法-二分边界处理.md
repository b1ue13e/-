## 1. 🎯 核心机制：死循环死锁根源与整除取整偏置

二分查找代码极其简洁，却被著名计算机科学家 Donald Knuth 评价为“90% 的程序员写不对二分”。其根本难点在于**边界处理（Boundary Conditions）**，特别是当搜索区间收敛到仅剩 2 个相邻元素（$right = left + 1$）时，因**整数向下取整偏置**所引发的**死循环死锁（Deadlock / Infinite Loop）**。

```
死循环触发的底层几何机制:
假设区间只剩 2 个元素: left = 4, right = 5

采用向下取整 mid = (left + right) / 2 = (4 + 5) / 2 = 4
若分支逻辑为 left = mid:
更新后 left 依然等于 4! 新区间依旧为 [4, 5]!
算法陷入原地转圈死循环! 

修复方案: 向上取整 mid = (left + right + 1) / 2 = (4 + 5 + 1) / 2 = 5
若分支逻辑为 left = mid:
更新后 left 变为 5! 新区间变为 [5, 5]，成功跳出死锁!
```

### 1.1 整数除法的取整偏置（Floor vs Ceil Division）
在 C++ 中，整数除法 `(l + r) / 2` 采取向零取整（Floor Division）：
- 当 $r = l + 1$ 时，`mid = (l + l + 1) / 2 = l`。中点偏向**左侧**。
- 如果条件分支试图将左边界跟进为 `left = mid`，那么 `left` 的值完全没有发生改变，算法无法收敛。
- 只有将中点公式改为向上取整 `mid = (l + r + 1) / 2`，在 $r = l + 1$ 时求得 `mid = r`，`left = mid` 才能将 `left` 推进到 `r`，从而保证区间严格缩小。

### 1.2 AcWing / 算法竞赛两大标准无痛模板

#### 模板 1：寻找左侧边界 / 满足 `check(mid)` 的第一个位置
- **更新分支**：`right = mid` 与 `left = mid + 1`
- **中点公式**：向下取整 `mid = left + (right - left) / 2`
- **收敛分析**：当 $r = l + 1$ 时，`mid = l`。若走 `right = mid`，则 `right` 变为 $l$，区间变为 $[l, l]$ 收敛；若走 `left = mid + 1`，`left` 变为 $l+1$，区间变为 $[l+1, l+1]$ 收敛。**无死循环风险**。

#### 模板 2：寻找右侧边界 / 满足 `check(mid)` 的最后一个位置
- **更新分支**：`left = mid` 与 `right = mid - 1`
- **中点公式**：**必须向上取整 `mid = left + (right - left + 1) / 2`**
- **收敛分析**：当 $r = l + 1$ 时，`mid = r`。若走 `left = mid`，`left` 变为 $r$，区间变为 $[r, r]$ 收敛；若走 `right = mid - 1`，`right` 变为 $l$，区间变为 $[l, l]$ 收敛。**完美规避死循环**。

## 2. 📐 渐近收敛性证明与收敛不变性

### 严格收敛性定理
设第 $k$ 步的区间长度为 $L_k = right_k - left_k$（$L_k \ge 1$）。
算法收敛的充分必要条件是：**在每一次迭代中，新区间长度必须严格单调递减，即 $L_{k+1} < L_k$**。

1. 对于模板 1（`mid = (l + r) / 2`）：
   - 当 $L_k \ge 2$ 时，$mid \in [l+1, r-1]$，无论走哪条分支，$L_{k+1} \le L_k - 1$。
   - 当 $L_k = 1$（即 $r = l+1$）时，$mid = l$：
     - 若 `right = mid`，新区间 $[l, l]$，长度 $L_{k+1} = 0 < L_k = 1$。
     - 若 `left = mid + 1`，新区间 $[l+1, l+1]$，长度 $L_{k+1} = 0 < L_k = 1$。
   - **证明结论**：长度严格递减，必然在有限步内收敛至 $L = 0$（即 $left == right$）。

2. 对于模板 2（`mid = (l + r + 1) / 2`）：
   - 当 $L_k = 1$（即 $r = l+1$）时，$mid = r$：
     - 若 `left = mid`，新区间 $[r, r]$，长度 $L_{k+1} = 0 < L_k = 1$。
     - 若 `right = mid - 1`，新区间 $[l, l]$，长度 $L_{k+1} = 0 < L_k = 1$。
   - **证明结论**：长度严格递减，收敛性得证。

## 3. 💻 C++ 20 完整工程实现与 4 大 canonical 边缘测试

以下代码实现了两大标准边界模板，并包含对 4 类典型边缘用例的自动化检测：

```cpp
#include <iostream>
#include <vector>
#include <cassert>

using namespace std;

class BinarySearchBoundary {
public:
    // 模板 1: 寻找 >= x 的首个位置 (左边界)
    static int search_left_bound(const vector<int>& arr, int target) {
        if (arr.empty()) return -1;
        int left = 0, right = static_cast<int>(arr.size()) - 1;

        while (left < right) {
            int mid = left + (right - left) / 2; // 向下取整
            if (arr[mid] >= target) {
                right = mid;      // 包含 mid，解在左侧或就是 mid
            } else {
                left = mid + 1;   // 排除 mid
            }
        }
        // 退出时 left == right
        return arr[left] >= target ? left : -1;
    }

    // 模板 2: 寻找 <= x 的最后一个位置 (右边界)
    static int search_right_bound(const vector<int>& arr, int target) {
        if (arr.empty()) return -1;
        int left = 0, right = static_cast<int>(arr.size()) - 1;

        while (left < right) {
            // 补 +1 防止 left = mid 陷入死循环
            int mid = left + (right - left + 1) / 2; // 向上取整
            if (arr[mid] <= target) {
                left = mid;       // 包含 mid，解在右侧或就是 mid
            } else {
                right = mid - 1;  // 排除 mid
            }
        }
        // 退出时 left == right
        return arr[left] <= target ? left : -1;
    }
};

// 自动化 4 大 Canonical 边缘测试框架
void run_canonical_edge_tests() {
    cout << "=== 运行 4 大 Canonical 二分边界边缘测试 ===" << endl;

    // 用例 1: 查找比最小值还小的元素 (Target < arr[0])
    vector<int> arr1 = {10, 20, 30, 40};
    assert(BinarySearchBoundary::search_left_bound(arr1, 5) == -1);
    cout << "[Edge Test 1 Pass] Target smaller than min correctly returned -1." << endl;

    // 用例 2: 查找比最大值还大的元素 (Target > arr[n-1])
    vector<int> arr2 = {10, 20, 30, 40};
    assert(BinarySearchBoundary::search_right_bound(arr2, 50) == 3); // <= 50 的最后一个是 40 (索引 3)
    assert(BinarySearchBoundary::search_left_bound(arr2, 50) == -1);
    cout << "[Edge Test 2 Pass] Target larger than max correctly handled." << endl;

    // 用例 3: 查找落在元素缝隙间的元素 (Target 在数组中不存在)
    vector<int> arr3 = {10, 20, 30, 40};
    // 找 >= 25 的首个位置 -> 应为 30 (索引 2)
    assert(BinarySearchBoundary::search_left_bound(arr3, 25) == 2);
    // 找 <= 25 的最后一个位置 -> 应为 20 (索引 1)
    assert(BinarySearchBoundary::search_right_bound(arr3, 25) == 1);
    cout << "[Edge Test 3 Pass] Missing target correctly routed to neighboring bounds." << endl;

    // 用例 4: 极小数组 (N=1) 与全重复元素数组
    vector<int> arr4_single = {100};
    assert(BinarySearchBoundary::search_left_bound(arr4_single, 100) == 0);
    assert(BinarySearchBoundary::search_left_bound(arr4_single, 200) == -1);

    vector<int> arr4_dup = {5, 5, 5, 5, 5};
    assert(BinarySearchBoundary::search_left_bound(arr4_dup, 5) == 0);   // 首个 5 索引为 0
    assert(BinarySearchBoundary::search_right_bound(arr4_dup, 5) == 4);  // 末个 5 索引为 4
    cout << "[Edge Test 4 Pass] Single element & All duplicate element arrays verified." << endl;
}

int main() {
    run_canonical_edge_tests();
    return 0;
}
```

## 4. 📊 状态转换对比 Trace：死循环 vs 向上取整修复

### 场景：数组 `[10, 20]` ($left=0, right=1$)，查找 `<= 20` 的最后一个位置 (Target=20)

#### 错误对照轨迹（使用向下取整 `mid = (l + r)/2` 配对 `left = mid`）：

```
Step 1: left = 0, right = 1
mid = (0 + 1) / 2 = 0
arr[0] = 10 <= 20 -> 执行 left = mid -> left 依然为 0!

Step 2: left = 0, right = 1
mid = (0 + 1) / 2 = 0
arr[0] = 10 <= 20 -> 执行 left = mid -> left 依然为 0!
... 陷入死循环 (Infinite Loop Deadlock)
```

#### 正确标准轨迹（使用向上取整 `mid = (l + r + 1)/2` 配对 `left = mid`）：

| 步骤 | `left` | `right` | `mid` 计算公式 | `arr[mid]` | 比较分支 | `left` / `right` 新状态 | 结论 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Init | 0 | 1 | - | - | - | $[0, 1]$ | 长度 1 |
| Step 1 | 0 | 1 | $0 + (1-0+1)/2 = 1$ | `arr[1] = 20` | $20 \le 20 \implies left = mid = 1$ | $left = 1, right = 1$ | 区间变为 $[1, 1]$ |
| End | 1 | 1 | - | - | - | `left == right` 退出循环 | 成功收敛，返回索引 1 |

## 5. ⚠️ 经典陷阱与边界防御

1. **分支 `left = mid` 时忘记在中点计算中加 1（The "Missing +1" Bug）**：
   - *口诀配对*：只要写出了 `left = mid`，**`mid` 的计算必须补上 `+1`**（写成 `left + (right - left + 1) / 2`）。忽略 `+1` 是二分查找引发线上 CPU 100% 死循环的第一大杀手。

2. **忽略 `left == right` 退出后的结果防护**：
   - *陷阱*：二分边界模板在退出循环时必然满足 `left == right`，但这只代表该位置是**最有可能**满足条件的位置。若整个数组的所有元素都不满足条件（例如寻找比最大值还大的元素），`arr[left]` 依然不符合要求。
   - *防御*：退出循环后，必须补一步校验：`if (arr[left] == target)` 或 `if (check(left))`。

3. **空数组处理防护缺位**：
   - *陷阱*：传入空数组 `vector<int> arr` 时，`right = arr.size() - 1` 将发生无符号数下溢导致 Segmentation Fault。
   - *防御*：方法开头强行防线校验：`if (arr.empty()) return -1;`。

## 6. 🃏 闭卷自测与 Anki 卡片

### 闭卷自测考点
- **问答**：为什么当更新逻辑为 `left = mid` 时，`mid` 计算公式必须采用向上取整 `left + (right - left + 1) / 2`？用包含 2 个元素的简单算例说明。
- **标准解答**：
  - 原因：当区间只剩 2 个相邻元素 $left = k, right = k + 1$ 时，若采用向下取整，求得 $mid = k$。若走分支 $left = mid$，则 $left$ 被重新赋值为 $k$，区间保持 $[k, k+1]$ 不变，算法陷入无限死循环。
  - 向上取整求得 $mid = k + 1$，赋值 $left = mid$ 后 $left$ 推进为 $k + 1$，区间收敛至 $[k+1, k+1]$，成功跳出死循环。

## 🚨 常见误区与边界条件

1. **左闭右闭 `[L, R]` vs 左闭右开 `[L, R)` 混用**：
   - 左闭右闭 `while left <= right:` 退出时 `left = right + 1`；
   - 左闭右开 `while left < right:` 退出时 `left == right`。
   混用循环条件与指针更新逻辑会导致越界或遗漏端点元素。
2. **查找首个/最后一个相等元素**：查找 `lower_bound` (≥x的首个位置) 时，遇到 `nums[mid] == x` 不能立即返回，必须收缩右边界 `right = mid` 或 `right = mid - 1` 继续探索前半段。

- A: 当搜索区间收敛至 2 个元素且分支为 `left = mid` 时，整数向下取整导致 `mid == left`，更新后 `left` 值保持不变，算法无法缩小区间从而陷入死循环。

- Q: 请背诵记忆 AcWing 二分模板中 `left = mid` 与 `mid` 的配对规则。
- A: 只要更新分支出现 `left = mid`，`mid` 的计算必须**向上取整**，即 `mid = left + (right - left + 1) / 2`。
