## 1. 🎯 核心原理与底层内存模型

**字符串（String）** 在计算机中本质上是连续字符的序列。然而，不同的编程语言与库实现对于字符串的内存管理、边界界定与字符编码机制有着本质的不同。

### 1. C 风格字符串 (`char[]`) vs C++ `std::string`
- **C 风格字符串 (`char[]`)**：
  - 采用**空字符终止符（Null-Terminator `'\0'`）** 标示结尾。
  - 获取长度 `strlen(s)` 需要扫描整个数组，时间复杂度为 $O(N)$。存在缓冲区溢出（Buffer Overflow）安全隐患。
- **C++ `std::string`**：
  - **显式长度前缀（Length-Prefixed）** 数据结构。记录 `size` 与 `capacity`。
  - `s.size()` 时间复杂度为 $O(1)$。内部维持连续内存，且结尾自动补充 `'\0'` 以兼容 C API。

### 2. 小字符串优化 (SSO, Small String Optimization)
在主流 C++ 标准库实现（如 GCC `libstdc++` 和 MSVC `STL`）中，`std::string` 占用 24 或 32 字节。为了避免短字符串频繁触发代价高昂的堆内存分配（Heap Allocation），STL 采用了 **SSO 优化**：
- 当字符串长度小于临界阈值（在 64 位系统上通常为 15 或 22 字节）时，直接存储在 `std::string` 对象内部的栈缓冲区（Buffer）中，不分配堆内存。
- 当字符串超过阈值时，对象内部转化为 `{ char* ptr; size_t size; size_t capacity; }` 指向堆上分配的空间。

```
64位系统上的 SSO 内存结构示意图:
[ 短字符串 s.length() <= 15 (SSO 激活) ]
+------------------------------------+----------------+--------------+
| 内部静态栈缓冲区 s_buf[0..14]       | length (1B)    | '\0'         |  <- 零堆内存分配
+------------------------------------+----------------+--------------+

[ 长字符串 s.length() > 15 (堆内存模式) ]
+------------------+------------------+------------------+
| char* heap_ptr   | size_t size      | size_t capacity  |  --> [ 堆上动态分配的字符数组... ]
+------------------+------------------+------------------+
```

### 3. 编码机制：ASCII vs UTF-8
- **ASCII 编码**：单字节定长编码（1 Byte = 8 bits），定义了 0~127 范围内的字符。`s[i]` 直接对应一个字符。
- **UTF-8 编码**：变长多字节编码（1~4 Bytes）。包含中文字符的 UTF-8 字符串中，单个中文字符通常占用 3 个字节。`s[i]` 取出的是**字节（Byte）而非字符（Code Point）**。

## 2. 💻 规范 C++20 实现

以下代码演示了如何检测 SSO 堆/栈状态、使用 `std::string_view` 进行零拷贝切片，以及解析 UTF-8 编码字符数。

```cpp
#include <iostream>
#include <string>
#include <string_view>
#include <cstddef>
#include <cstdint>

namespace Algorithm::StringFundamentals {

// 1. SSO 状态检验函数
void inspectSSO(const std::string& str) {
    const void* obj_addr = static_cast<const void*>(&str);
    const void* data_addr = static_cast<const void*>(str.data());

    std::cout << "String: \"" << str << "\" | Size: " << str.size()
              << " | Capacity: " << str.capacity() << "\n";
    
    // 如果 data() 指向的内存与 string 对象地址接近，说明使用了内部 SSO buffer
    const auto diff = reinterpret_cast<uintptr_t>(data_addr) - reinterpret_cast<uintptr_t>(obj_addr);
    if (diff < sizeof(std::string)) {
        std::cout << "  -> [SSO 激活] 字符保存在栈内存对象内部\n";
    } else {
        std::cout << "  -> [堆内存] 字符保存在堆空间: " << data_addr << "\n";
    }
}

// 2. UTF-8 字符（Code Point）数量统计 (而非字节数)
[[nodiscard]] size_t utf8Length(std::string_view sv) noexcept {
    size_t char_count = 0;
    for (size_t i = 0; i < sv.length(); ) {
        const auto byte = static_cast<unsigned char>(sv[i]);
        if ((byte & 0x80) == 0) {
            i += 1; // 1-byte ASCII
        } else if ((byte & 0xE0) == 0xC0) {
            i += 2; // 2-byte sequence
        } else if ((byte & 0xF0) == 0xE0) {
            i += 3; // 3-byte sequence (常见中文)
        } else if ((byte & 0xF8) == 0xF0) {
            i += 4; // 4-byte sequence (Emoji等)
        } else {
            i += 1; // 损坏编码保护
        }
        ++char_count;
    }
    return char_count;
}

// 3. std::string_view 零拷贝区间传递
[[nodiscard]] std::string_view getSubspanZeroCopy(std::string_view sv, size_t pos, size_t count) noexcept {
    if (pos >= sv.length()) return {};
    return sv.substr(pos, count); // O(1) 零内存分配
}

} // namespace Algorithm::StringFundamentals
```

## 3. 🔍 状态跟踪与图解分析

对比 UTF-8 编码字符串 `"Hi! 算法"` 在内存中的实际字节表示与字符解算：

#### 内存字节排布表（字符串空间）：

| 字节偏移 Index | 十六进制 Hex | ASCII / 编码特征 | 代表的 UTF-8 字符 | `utf8Length` 推进步幅 | 字符计数器 |
|---|---|---|---|---|---|
| **0** | `0x48` | `'H'` (0xxxxxxx) | `'H'` (ASCII) | `+1` | **1** |
| **1** | `0x69` | `'i'` (0xxxxxxx) | `'i'` (ASCII) | `+1` | **2** |
| **2** | `0x21` | `'!'` (0xxxxxxx) | `'!'` (ASCII) | `+1` | **3** |
| **3** | `0x20` | `' '` (0xxxxxxx) | `' '` (ASCII) | `+1` | **4** |
| **4** | `0xE7` | 1110xxxx (3-Byte首字节) | `'算'` (第1/3字节) | - | - |
| **5** | `0xAE` | 10xxxxxx (续字节) | `'算'` (第2/3字节) | - | - |
| **6** | `0x97` | 10xxxxxx (续字节) | `'算'` (第3/3字节) | `+3` | **5** |
| **7** | `0xE6` | 1110xxxx (3-Byte首字节) | `'法'` (第1/3字节) | - | - |
| **8** | `0xB3` | 10xxxxxx (续字节) | `'法'` (第2/3字节) | - | - |
| **9** | `0x95` | 10xxxxxx (续字节) | `'法'` (第3/3字节) | `+3` | **6** |

**结果**：`s.size()` (字节数) = **10** Bytes；`utf8Length(s)` (字符数) = **6** 个字符。

## 4. 📈 复杂度分析

| 操作类型 | C 风格字符串 `char[]` | C++ `std::string` | C++ `std::string_view` |
|---|---|---|---|
| **求长度 Size/Length** | $O(N)$ (遍历找 `'\0'`) | $O(1)$ (读取 size 字段) | $O(1)$ |
| **随机访问 `s[i]`** | $O(1)$ | $O(1)$ | $O(1)$ |
| **切片 / 子串 (Substr)** | $O(K)$ (动态分配复制) | $O(K)$ (堆内存复制) | **$O(1)$ (零拷贝视图)** |
| **内存开销** | $N + 1$ 字节 | $24\sim32$ 字节 + 堆空间 | $16$ 字节 (`ptr + len`) |

## 5. ⚠️ 常见坑点与边界条件

1. **`std::string_view` 悬空引用 (Dangling Reference)**
   - `std::string_view` 不拥有字符串的生命周期，仅保存指针与长度。若其引用的临时 `std::string` 对象被销毁，`string_view` 将变成野指针，解引用触发未定义行为！
2. **UTF-8 乱码与按字节截断**
   - 对包含中文字符的 `std::string` 直接使用 `s.substr(0, 5)` 会将 3 字节的 UTF-8 字符从中间截断，导致显示乱码（）。必须进行 UTF-8 边界校验后再进行截断。

## 6. 🧠 💡 Flashcards (Guided Recall)

Q: 什么是 C++ 的 SSO（小字符串优化）？它如何提升性能？
A: SSO 是当 `std::string` 长度小于特定阈值（如 15~22 字节）时，直接利用对象自身的栈空间存储字符，避免在堆上动态分配内存。这显著减少了堆分配开销并提升了 CPU 缓存局部性。

Q: 为什么在 UTF-8 字符串中 `s.length()` 与真实字符数通常不相等？
A: 因为 `std::string::length()` 返回的是**字节数（Bytes）**。UTF-8 是变长编码，ASCII 占 1 字节，而中文字符通常占 3 字节，因此字节数往往大于字符数。

## 🃏 Anki 卡片

### Card 1: 字符串不可变性与内存拷贝
- **Front**: 为什么在 Python/Java 中频繁进行字符串拼接 `s += char` 会导致 $O(n^2)$ 复杂度？如何解决？
- **Back**:
  - 原因：字符串是不可变对象 (Immutable)，每次 `+=` 都会在内存中重新分配空间并拷贝已有字符串。
  - 解法：在 Python 中使用列表 `[]` 暂存字符最后 `''.join(list)`；Java 中使用 `StringBuilder` / `StringBuffer`。
