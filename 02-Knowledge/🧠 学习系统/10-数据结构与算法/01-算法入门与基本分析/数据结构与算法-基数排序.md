## 1. 🎯 基数排序核心原理 (LSD vs MSD)

基数排序（Radix Sort）是一种非比较的多关键字线性时间排序算法。其物理思想是将待排序的整数拆分为 $d$ 个“数位”（Digit），从低位到高位（或从高位到低位）依次进行轮次排序：
1. **LSD (Least Significant Digit，低位优先)**：从最右侧最低有效位（如个位）开始，逐位向左（十位、百位...）排序。**LSD 每次针对单位的排序必须使用严格稳定排序算法（通常为[[数据结构与算法-计数排序|计数排序]]）**。
2. **MSD (Most Significant Digit，高位优先)**：从最高有效位开始拆分桶，递归处理各子桶，适合处理变长字符串排序。

### 核心物理推导：为什么 LSD 能够正确工作？
LSD 的正确性完全依赖于子排序的**稳定性**。假设前 $k-1$ 位已经排序完毕。当处理第 $k$ 位时：
- 若两个元素的第 $k$ 位数值不同，高位大的元素必定被排在后面；
- 若两个元素的第 $k$ 位数值相同，由于子排序的稳定性，它们在前 $k-1$ 轮建立的相对高低次序不会被颠覆！
因此，自底向上的迭代能天然归纳保证全局有序。

## 2. 🔍 步骤跟踪 (LSD Step-by-Step Trace)

以输入数组 `[170, 45, 75, 90, 802, 24, 2, 66]`（长度 $n=8$，最大值 802 $\implies$ 位数 $d=3$，基数 $b=10$）为例：

```
初始输入: [170, 45, 75, 90, 802, 24, 2, 66]
```

### 第 1 轮：按个位排序 (`exp = 1`)
提取各元素个位数值：
- `170` (0), `45` (5), `75` (5), `90` (0), `802` (2), `24` (4), `2` (2), `66` (6)
应用稳定计数排序（桶 0~9）：
- 桶 0: `[170, 90]`
- 桶 2: `[802, 2]`
- 桶 4: `[24]`
- 桶 5: `[45, 75]`
- 桶 6: `[66]`
$$\text{个位排序后结果}: [170, 90, 802, 2, 24, 45, 75, 66]$$

### 第 2 轮：按十位排序 (`exp = 10`)
提取各元素十位数值：
- `170` (7), `90` (9), `802` (0), `2` (0), `24` (2), `45` (4), `75` (7), `66` (6)
应用稳定计数排序（注意：在同一桶内部保留上轮相对顺序）：
- 桶 0: `[802, 2]`
- 桶 2: `[24]`
- 桶 4: `[45]`
- 桶 6: `[66]`
- 桶 7: `[170, 75]` (170 在前 75 在后)
- 桶 9: `[90]`
$$\text{十位排序后结果}: [802, 2, 24, 45, 66, 170, 75, 90]$$

### 第 3 轮：按百位排序 (`exp = 100`)
提取各元素百位数值：
- `802` (8), `2` (0), `24` (0), `45` (0), `66` (0), `170` (1), `75` (0), `90` (0)
应用稳定计数排序：
- 桶 0: `[2, 24, 45, 66, 75, 90]`
- 桶 1: `[170]`
- 桶 8: `[802]`
$$\text{百位排序后最终结果}: [2, 24, 45, 66, 75, 90, 170, 802]$$

## 3. 📐 复杂度分析与基数选择

### 3.1 时间与空间复杂度
- **时间复杂度**：
  设元素最大位数位 $d$，基数为 $b$（对于十进制 $b=10$）。
  共进行 $d$ 轮计数排序，每轮计数排序扫描 $n$ 个元素与 $b$ 个桶，耗时 $O(n + b)$。
  **总时间复杂度为 $\mathbf{O(d \cdot (n + b))}$**。

- **空间复杂度**：
  每轮计数排序开辟大小为 $b$ 的频次数组与大小为 $n$ 的输出缓冲区。
  **额外空间复杂度为 $\mathbf{O(n + b)}$**。

### 3.2 工业级基数 $b$ 的权衡优化（Base Trade-off）
对于 32 位无符号整数：
- 若取十进制（$b=10$），$d = 10$ 轮。每轮扫描开销小，但循环轮次较多。
- 若取 $b = 2^{16} = 65536$（16 位二进制基数），$d = 2$ 轮！仅需 2 轮计数排序即可完成 32 位整数的排序，常数极小，性能远超 `std::sort`。

## 4. 💻 C++20 完整实现代码 (LSD Radix Sort)

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <cassert>

// 按指定数位 (exp) 对数组进行稳定计数排序
void counting_sort_by_digit(std::vector<int>& arr, int exp) {
    const size_t n = arr.size();
    std::vector<int> output(n);
    int count[10] = {0}; // 十进制基数 b = 10

    // 1. 统计当前数位的频次 (val / exp) % 10
    for (size_t i = 0; i < n; ++i) {
        int digit = (arr[i] / exp) % 10;
        count[digit]++;
    }

    // 2. 计算前缀和
    for (int i = 1; i < 10; ++i) {
        count[i] += count[i - 1];
    }

    // 3. 逆向填充保证稳定性
    for (ssize_t i = static_cast<ssize_t>(n) - 1; i >= 0; --i) {
        int digit = (arr[static_cast<size_t>(i)] / exp) % 10;
        output[count[digit] - 1] = arr[static_cast<size_t>(i)];
        count[digit]--;
    }

    arr = std::move(output);
}

// LSD 基数排序主入口
void radix_sort_lsd(std::vector<int>& arr) {
    if (arr.size() <= 1) return;

    // 1. 获取最大值确定最大位数 d
    int max_val = *std::max_element(arr.begin(), arr.end());

    // 2. 从低位到高位依次执行稳定计数排序
    for (int exp = 1; max_val / exp > 0; exp *= 10) {
        counting_sort_by_digit(arr, exp);
    }
}

int main() {
    std::vector<int> data = {170, 45, 75, 90, 802, 24, 2, 66};
    radix_sort_lsd(data);

    std::vector<int> expected = {2, 24, 45, 66, 75, 90, 170, 802};
    assert(data == expected);

    std::cout << "[基数排序测试] 排序成功: ";
    for (int v : data) std::cout << v << " ";
    std::cout << "\n";
    return 0;
}
```

## 5. ⚠️ 常见工程陷阱与局限

1. **子排序误用不稳定算法导致结果彻底崩溃**  
   若将按位排序中的计数排序换成快速排序或选择排序，由于高位排序破坏了低位建立的相对次序，整个基数排序结果将完全紊乱。

2. **负数取模计算陷阱**  
   在 C++ 中，`-170 % 10` 的结果是 `-0` 或负数，直接作为 `count` 数组下标会导致严重的负索引越界崩溃。处理包含负数的数组时，需事先平移偏移量 `min_val` 或将符号位单独分为正负两个桶处理。

## 6. 🃏 闭卷自测考点 (Anki Card)

- Q: **为什么 LSD 基数排序要求每轮按位排序算法必须是稳定的？**
- A: 因为低位建立的次序代表了在更高位数相同时的相对优先关系。若高位排序不稳定，会破坏低位排序已建立好的正确相对顺序，导致最终结果失效。

- Q: **基数排序的时间复杂度为 $O(d(n+b))$，其中各字母代表什么？**
- A: $n$ 代表待排序元素个数；$d$ 代表元素拆分出的最大数位数量（如最大值的总位数）；$b$ 代表数位的基数（Radix Base，如十进制 $b=10$，二进制 $b=2$）。

- Q: **对于 32 位无符号整数，如何通过调整基数 $b$ 优化基数排序的运行常数？**
- A: 可将基数设为 $b = 2^{16} = 65536$，将 32 位整数拆分为高 16 位与低 16 位两个数位。这样只需执行 2 轮计数排序即可完成全局排序，大幅减少了循环开销。

## 🚨 常见误区与边界条件

1. **负数处理遗漏**：标准基数排序假设数值非负（按位求余提取桶）。若存在负数，需先找出最小值 `min_val`，将所有数整体加上 `abs(min_val)` 转为非负数，排序完成后再减回。
2. **不稳定性破坏**：基数排序依赖于低位到高位每一步计数排序的**稳定性**。若低位排序不稳定，高位排序会破坏低位相对顺序。
