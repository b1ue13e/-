## 1. 🎯 核心原理与算法动机

**字符串操作（String Operations）** 包含拼接、反转、子串提取以及子串模式匹配。在性能敏感的场景中，忽视字符串的内存复制成本会导致时间复杂度由 $O(N)$ 隐蔽退化至 $O(N^2)$。

### 1. 字符串拼接与 `reserve()` 优化
在循环中对字符串进行追加（如 `s = s + c`）会触发 $O(N^2)$ 的内存重新分配与拷贝。通过使用 `+=` 并提前调用 `s.reserve(total_capacity)`，可将拼接操作优化至均摊 $O(1)$（总时间 $O(N)$）。

### 2. KMP 字符串模式匹配算法 (Knuth-Morris-Pratt)
暴力模式匹配在主串 $T$（长 $N$）中查找模式串 $P$（长 $M$）的时间复杂度为 $O(N \cdot M)$。
**KMP 算法的核心动机**：当发生字符不匹配时，利用已匹配的前缀信息，通过预计算的**前缀函数（$\pi$ 数组/Next 数组）**，将模式串向右“跳跃”移动，使主串指针**绝不回退**，从而将匹配复杂度降低至 $O(N + M)$。

- **前缀函数 $\pi[i]$ 定义**：子串 $P[0..i]$ 中，既是**真前缀**又是**真后缀**的最长相等字符串的长度。

```
KMP 跳跃匹配机制:
主串 T:     A  B  A  B  A  B  A  C
模式串 P:   A  B  A  B  A  C
                        ^
                     匹配失败! (P[5]='C' != T[5]='B')
查表 π[4]=3, 模式串指针跳跃至 p_idx = 3 ('B'):
主串 T:     A  B  A  B  A  B  A  C
模式串 P:         A  B  A  B  A  C (主串指针无需回退!)
```

## 2. 💻 规范 C++20 实现

以下给出 **原地字符串反转**、**高效拼接** 以及 **完整的 KMP 模式匹配算法** C++20 实现：

```cpp
#include <vector>
#include <string>
#include <string_view>
#include <algorithm>
#include <cstddef>

namespace Algorithm::StringOperations {

// 1. 原地字符串反转 (In-place Reversal)
void reverseString(std::string& s) noexcept {
    if (s.size() < 2) return;
    size_t left = 0;
    size_t right = s.size() - 1;
    while (left < right) {
        std::swap(s[left], s[right]);
        ++left;
        --right;
    }
}

// 2. 高效字符串拼接 (Optimized Concatenation)
[[nodiscard]] std::string joinStrings(const std::vector<std::string_view>& parts, std::string_view delim) {
    if (parts.empty()) return {};

    size_t total_length = 0;
    for (const auto& part : parts) total_length += part.length();
    total_length += delim.length() * (parts.size() - 1);

    std::string result;
    result.reserve(total_length); // 一次性预分配内存，杜绝多次 Realloc

    for (size_t i = 0; i < parts.size(); ++i) {
        result.append(parts[i]);
        if (i + 1 < parts.size()) {
            result.append(delim);
        }
    }
    return result;
}

// 3. KMP 算法：计算前缀函数 π 数组
[[nodiscard]] std::vector<int> computePrefixFunction(std::string_view P) {
    const size_t m = P.length();
    std::vector<int> pi(m, 0);
    int j = 0; // 最长相等前后缀长度

    for (size_t i = 1; i < m; ++i) {
        while (j > 0 && P[i] != P[j]) {
            j = pi[j - 1]; // 模式串指针回退
        }
        if (P[i] == P[j]) {
            ++j;
        }
        pi[i] = j;
    }
    return pi;
}

// KMP 字符串查找 (返回首次匹配成功处的起始索引，未找到返回 -1)
[[nodiscard]] int strStrKMP(std::string_view text, std::string_view pattern) {
    if (pattern.empty()) return 0;
    if (text.length() < pattern.length()) return -1;

    const std::vector<int> pi = computePrefixFunction(pattern);
    int j = 0; // 模式串匹配指针

    for (size_t i = 0; i < text.length(); ++i) {
        while (j > 0 && text[i] != pattern[j]) {
            j = pi[j - 1]; // 利用 π 表实现 O(1) 跳转，主串 i 不回退
        }
        if (text[i] == pattern[j]) {
            ++j;
        }
        if (static_cast<size_t>(j) == pattern.length()) {
            return static_cast<int>(i - pattern.length() + 1); // 匹配成功
        }
    }

    return -1;
}

} // namespace Algorithm::StringOperations
```

## 3. 🔍 状态跟踪与图解分析

对模式串 $P = \text{"ABABAC"}$ 计算前缀函数 $\pi$ 数组，并在主串 $T = \text{"ABABABABAC"}$ 中查找：

#### 1. 前缀函数 $\pi$ 计算步演：

| $i$ | $P[i]$ | 字符子串 $P[0..i]$ | 最长相等前后缀 | $\pi[i]$ 值 |
|---|---|---|---|---|
| **0** | `'A'` | `"A"` | 无 (真前后缀要求长度 $< 1$) | **0** |
| **1** | `'B'` | `"AB"` | 前缀 `"A"`, 后缀 `"B"` $\implies$ 不匹配 | **0** |
| **2** | `'A'` | `"ABA"` | 前缀 `"A"`, 后缀 `"A"` $\implies$ 匹配 | **1** |
| **3** | `'B'` | `"ABAB"` | 前缀 `"AB"`, 后缀 `"AB"` $\implies$ 匹配 | **2** |
| **4** | `'A'` | `"ABABA"` | 前缀 `"ABA"`, 后缀 `"ABA"` $\implies$ 匹配 | **3** |
| **5** | `'C'` | `"ABABAC"` | 前缀无匹配 (遇到 `'C'` 触发 `j = pi[2] = 1`, 终未匹配) | **0** |

前缀表结果：$\pi = [0, 0, 1, 2, 3, 0]$

#### 2. KMP 主串匹配跟踪 ($T = \text{"ABABABABAC"}$):

| 主串指针 $i$ | $T[i]$ | 模式串指针 $j$ | $P[j]$ | 比较结果 | 指针调整与说明 |
|---|---|---|---|---|---|
| 0~4 | `"ABABA"` | 0~4 | `"ABABA"` | 匹配 | $i$ 与 $j$ 同步前进至 $i=4, j=4$ |
| **5** | `'B'` | 5 | `'C'` | **失配** ($'B' \neq 'C'$) | 查表 $j = \pi[4] = 3$！模式串右移，**$i$ 保持 5 不变** |
| **5** | `'B'` | 3 | `'B'` | 匹配 | $i=5, j=3$ 重新匹配成功！同步推进 |
| 6~8 | `"BAC"` | 4~5 | `"AC"` | 匹配 | $i$ 与 $j$ 同步推进至 $i=8, j=5$ (`j == 6`) |

**匹配成功**！返回起始索引：$i - M + 1 = 8 - 6 + 1 = \mathbf{3}$。

## 4. 📈 复杂度分析与严格证明

### KMP 时间复杂度
- **定理**：KMP 算法求解字符串模式匹配的时间复杂度为 $\Theta(N + M)$，其中 $N$ 为主串长度，$M$ 为模式串长度。
- **均摊证明**：
  - 计算 $\pi$ 数组：`i` 指针移动 $M$ 次；`j` 指针单调增加，但在 `while` 中 `j = pi[j-1]` 使得 `j` 减少。因为 `j` 增加的总量不超过 $M$，故 `j` 在 `while` 中减少的总步数也**绝不会超过 $M$**。耗时 $O(M)$。
  - 文本匹配阶段：主串指针 `i` 精确自增 $N$ 次，绝不回退。模式串指针 `j` 的回退总步数同样受限于 `j` 增加的总步数（不超过 $N$）。耗时 $O(N)$。
  - 总复杂度为 $O(N + M)$。

## 5. ⚠️ 常见坑点与边界条件

1. **`s = s + c` 导致的隐蔽 $O(N^2)$ 性能灾难**
   - 在 C++ 中，`s = s + c` 会先创建一个临时 `std::string` 对象，将 `s` 拷贝过去后再追加 `c`；而 `s += c` 或 `s.push_back(c)` 则直接在原对象后追加。在大循环中，前者会导致严重的 $O(N^2)$ 耗时与堆内存碎片。
2. **KMP $\pi$ 数组回退未校验 `j > 0`**
   - 在 `while (j > 0 && P[i] != P[j])` 条件中，若缺失 `j > 0` 约束，当 `j = 0` 且不匹配时，`pi[j-1]` 会访问 `pi[-1]`，导致严重的非法内存访问越界 crash。

## 6. 🧠 💡 Flashcards (Guided Recall)

Q: KMP 算法中前缀函数（$\pi$ 数组）的物理含义是什么？
A: $\pi[i]$ 表示模式串前缀子串 $P[0..i]$ 中，既是真前缀又是真后缀的最长相等字符串的长度。

Q: 为什么 KMP 算法能保证主串指针 $i$ 绝不回退？
A: 因为当发生失配时，主串与模式串在失配点之前的部分已经完全匹配。KMP 借助预计算的 $\pi$ 数组，直接提取已匹配部分的重叠前后缀信息，将模式串右移到最佳对齐位置，从而无需重新扫描主串。
