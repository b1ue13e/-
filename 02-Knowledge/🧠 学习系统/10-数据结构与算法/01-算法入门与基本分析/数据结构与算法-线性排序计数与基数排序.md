## 1. 🎯 线性时间排序三大族的本质差异与领域划分

非比较线性排序算法族通过避开“两两比较决策树”的下界约束（$\Omega(n \log n)$），在特定数据分布下实现 $O(n)$ 级别的极速排序。线性排序三大主力算法（[[数据结构与算法-计数排序|计数排序]]、[[数据结构与算法-基数排序|基数排序]]、桶排序 Bucket Sort）的物理机制与适用假设存在深刻差异：

1. **[[数据结构与算法-计数排序|计数排序]] (Counting Sort)**：
   * **物理本质**：频次统计 + 连续绝对索引直接映射。
   * **核心假设**：输入必须为小范围整数（Key 空间 $k = \text{max} - \text{min} + 1$ 满足 $k = O(n)$）。

2. **[[数据结构与算法-基数排序|基数排序]] (Radix Sort)**：
   * **物理本质**：多关键字/多数位正交拆分 + 迭代施加稳定子排序。
   * **核心假设**：键值可拆分为固定长度 $d$ 的进制位（如 integer/fixed-string），每一位的取值基数 $b$ 较小。

3. **桶排序 (Bucket Sort)**：
   * **物理本质**：连续区间区间划分（Bucket Hash） + 桶内二次比较排序 + 桶间顺序拼接。
   * **核心假设**：输入数据在连续区间（如 $[0, 1)$）内服从**均匀分布（Uniform Distribution）**。

## 2. 📊 线性排序算法三剑客深度对比矩阵

| 维度 | [[数据结构与算法-计数排序\|计数排序]] | [[数据结构与算法-基数排序\|基数排序]] | 桶排序 (Bucket Sort) |
| :--- | :--- | :--- | :--- |
| **数据类型约束** | 仅限于有限范围离散整数 | 可拆分为 $d$ 位的离散结构/整数/定长字符串 | 连续实数 / 浮点数 / 任意可哈希对象 |
| **分布分布假设** | 无要求（只需值域范围 $k$ 有限） | 无要求（只需最大位数 $d$ 有限） | **必须假设均匀分布**（分布倾斜会导致退化） |
| **平均时间复杂度** | $\Theta(n + k)$ | $\Theta(d(n + b))$ | $\Theta(n + \frac{n^2}{B} \cdot \frac{B}{n}) = \mathbf{\Theta(n)}$ |
| **最坏时间复杂度** | $\Theta(n + k)$ | $\Theta(d(n + b))$ | $O(n^2)$（当所有元素全部倾斜挤入同一个桶时） |
| **额外空间复杂度** | $O(n + k)$ | $O(n + b)$ | $O(n + B)$ ($B$ 为桶数量) |
| **稳定性** | 稳定（依赖逆向扫描前缀和） | 稳定（依赖按位子排序的稳定性） | 稳定（取决于桶内排序算法是否稳定） |
| **浮点数适应性** | 无法直接支持（需离散化） | 无法直接支持（需 IEEE 754 映射） | **天然原生支持连续浮点数** |

## 3. 📐 桶排序 (Bucket Sort) 在均匀分布下的 $O(n)$ 数学期望证明

设将 $n$ 个分布在区间 $[0, 1)$ 的元素均匀分配到 $n$ 个桶中。每个桶中分配到的元素个数 $n_i$ 服从二项分布 $B(n, 1/n)$。

### 桶内插入排序总期望时间推导：
假设桶内采用插入排序（时间为 $O(n_i^2)$），总运行时间的数学期望为：
$$E[T(n)] = \Theta(n) + \sum_{i=0}^{n-1} O\left( E[n_i^2] \right)$$

根据概率论，二项分布随机变量的二阶矩满足：
$$E[n_i^2] = \text{Var}(n_i) + (E[n_i])^2$$
其中均值 $E[n_i] = n \cdot \frac{1}{n} = 1$，方差 $\text{Var}(n_i) = n \cdot \frac{1}{n} \left( 1 - \frac{1}{n} \right) = 1 - \frac{1}{n}$。

代入二阶矩：
$$E[n_i^2] = \left( 1 - \frac{1}{n} \right) + 1^2 = 2 - \frac{1}{n}$$

求和计算总期望：
$$\sum_{i=0}^{n-1} E[n_i^2] = n \cdot \left( 2 - \frac{1}{n} \right) = 2n - 1 = \Theta(n)$$

**证明结论**：当数据在区间内均匀分布时，桶排序的总期望运行时间为严格的 **$\Theta(n)$**。

## 4. 💻 C++20 浮点数桶排序 (Bucket Sort) 完整实现代码

以下代码实现了标准桶排序，用于对位于 $[0, 1)$ 区间的连续浮点数数组进行高效线性排序：

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <cmath>
#include <cassert>

// 桶内辅助插入排序
void bucket_insertion_sort(std::vector<double>& bucket) {
    const size_t n = bucket.size();
    for (size_t i = 1; i < n; ++i) {
        double key = bucket[i];
        ssize_t j = static_cast<ssize_t>(i) - 1;
        while (j >= 0 && bucket[static_cast<size_t>(j)] > key) {
            bucket[static_cast<size_t>(j) + 1] = bucket[static_cast<size_t>(j)];
            j--;
        }
        bucket[static_cast<size_t>(j) + 1] = key;
    }
}

// 桶排序主函数 (假设输入元素均匀分布在 [0, 1) 区间)
void bucket_sort(std::vector<double>& arr) {
    const size_t n = arr.size();
    if (n <= 1) return;

    // 1. 创建 n 个空桶
    std::vector<std::vector<double>> buckets(n);

    // 2. 将每个元素根据映射公式 floor(n * x) 放入对应的桶中
    for (size_t i = 0; i < n; ++i) {
        size_t bucket_idx = static_cast<size_t>(std::floor(n * arr[i]));
        if (bucket_idx >= n) bucket_idx = n - 1; // 边界保护
        buckets[bucket_idx].push_back(arr[i]);
    }

    // 3. 对每个桶分别进行插入排序
    for (size_t i = 0; i < n; ++i) {
        bucket_insertion_sort(buckets[i]);
    }

    // 4. 顺序拼接各个桶的元素回原数组
    size_t idx = 0;
    for (size_t i = 0; i < n; ++i) {
        for (double val : buckets[i]) {
            arr[idx++] = val;
        }
    }
}

int main() {
    std::vector<double> data = {0.897, 0.565, 0.656, 0.1234, 0.665, 0.3434};
    bucket_sort(data);

    assert(std::is_sorted(data.begin(), data.end()));

    std::cout << "[桶排序测试] 连续浮点数排序成功: ";
    for (double v : data) std::cout << v << " ";
    std::cout << "\n";
    return 0;
}
```

## 5. ⚠️ 线性排序三大工程陷阱与适应性选型

1. **陷阱一：在非均匀分布数据上滥用桶排序**  
   若数据出现严重的数据倾斜（如 99% 的浮点数都集中在 `[0.0, 0.01]` 之间），桶排序的大部分桶变空，而某个桶塞满了大量元素。此时桶内插入排序的时间复杂度会急剧退化为最坏情况 **$O(n^2)$**。

2. **陷阱二：忽略浮点数转整数索引时的精度截断（IEEE 754 Limit）**  
   对于极度精细的双精度浮点数，若映射函数设计不当（如乘法溢出），会导致算术截断误将不同的浮点数映射到同一索引，破坏排序正确性。

3. **陷阱三：选型决策盲目追求 $O(n)$ 而忽视内存开销**  
   虽然线性排序时间渐近性能优异，但它们普遍需要额外的空间开销（计数数组 $O(k)$，桶数组 $O(n+B)$）。在嵌入式受限内存（RAM < a few KB）场景下，额外内存分配失败会导致程序崩溃，原位（In-place）的[[数据结构与算法-快速排序|快速排序]]或[[数据结构与算法-堆排序|堆排序]]依然是工程首选。

## 6. 🃏 闭卷自测考点 (Anki Card)

- Q: **请对比计数排序、基数排序与桶排序的核心适用场景与物理假设。**
- A: 计数排序适用于“小范围离散整数”（$k=O(n)$）；基数排序适用于“可正交拆分为固定数位/关键字的数据”（如 32/64 位整数、定长字符串）；桶排序适用于“在连续区间（如 $[0,1)$）内服从均匀分布的实数/浮点数”。

- Q: **桶排序在最坏情况下的时间复杂度是多少？为什么会发生退化？**
- A: 最坏时间复杂度为 $O(n^2)$。当输入数据高度倾斜，全部 $n$ 个元素被分配到同一个桶中时，算法退化为对这 $n$ 个元素执行单桶内的插入排序，耗时 $O(n^2)$。

- Q: **为什么桶排序能够天然支持连续浮点数的 $O(n)$ 排序，而计数排序却不能？**
- A: 计数排序依赖离散整数到连续频次数组下标的 1:1 绝对物理映射，实数无穷不可数导致计数数组无法建立；而桶排序通过 Hash 映射函数 `floor(n * x)` 将连续的实数区间离散化切分为有限个连续槽位，因此能原生支持浮点数。

## 🚨 常见误区与边界条件

1. **值域 $K$ 过大导致空间爆破**：计数排序适用于 $K \ll n$ 的场景。若数据范围极其分散（例如 $n=100$, 包含 $10^9$ 的数），计数数组开销不可接受。
2. **基数排序桶数量**：基数排序按 $b$ 进制分桶（常用 10 进制或 256 进制），进制越大轮数越少但桶内存分配越大，需权衡空间与轮数。
