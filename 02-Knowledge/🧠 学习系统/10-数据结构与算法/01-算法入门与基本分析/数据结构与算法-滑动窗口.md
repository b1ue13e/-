# 滑动窗口 (Sliding Window Paradigm)

## 1. 🎯 核心原理与算法动机

**滑动窗口（Sliding Window）** 是一种在连续序列（数组或字符串）上维护符合特定条件的子区间（[left, right]）的技术。通过将子区间的左右边界同向滑动，避免重复计算重叠区域的状态，从而将 $O(N^2)$ 或 $O(N^3)$ 的区间子集枚举优化至 $O(N)$。

### 窗口分类与状态维护策略
1. **定长滑动窗口（Fixed-size Window）**：
   - 窗口长度 $K$ 恒定。右边界右移入队 `right++`，左边界同步右移出队 `left++`。
   - 常用维护状态：滑动窗口最大值（单调队列 Monotonic Deque）、固定长度子串异位词检测。
2. **变长滑动窗口（Variable-size Window）**：
   - **求极小窗口**：主动扩大 `right` 直至满足条件；随后收缩 `left` 直至打破条件，在收缩过程中更新最小长度。
   - **极大窗口**：主动扩大 `right`；若打破条件，则收缩 `left` 直至恢复合规，在扩充过程中更新最大长度。

```
变长滑动窗口通用范式结构:
[left] --------> [right] (不断扩充右边界以纳入新元素)
   ^               |
   |--- left ++ ---| (当窗口满足/打破条件时，收缩左边界)
```

## 2. 💻 规范 C++20 实现

以下提供三个核心范式实现：**长度最小的子数组**（变长）、**无重复字符的最长子串**（哈希状态维护）、**滑动窗口最大值**（单调队列维护）。

```cpp
#include <vector>
#include <string_view>
#include <deque>
#include <unordered_map>
#include <algorithm>
#include <climits>
#include <array>

namespace Algorithm::SlidingWindow {

// 1. 长度最小的子数组 (Minimum Size Subarray Sum) - 变长求极小
[[nodiscard]] int minSubArrayLen(int target, const std::vector<int>& nums) noexcept {
    const size_t n = nums.size();
    size_t left = 0;
    int current_sum = 0;
    size_t min_len = static_cast<size_t>(INT_MAX);

    for (size_t right = 0; right < n; ++right) {
        current_sum += nums[right];

        // 当窗口满足条件时，尝试收缩左边界寻找更短子数组
        while (current_sum >= target) {
            min_len = std::min(min_len, right - left + 1);
            current_sum -= nums[left];
            ++left;
        }
    }

    return (min_len == static_cast<size_t>(INT_MAX)) ? 0 : static_cast<int>(min_len);
}

// 2. 无重复字符的最长子串 (Longest Substring Without Repeating Characters)
[[nodiscard]] int lengthOfLongestSubstring(std::string_view s) noexcept {
    std::array<int, 256> last_seen{};
    last_seen.fill(-1); // 记录每个字符最后出现的索引位置

    int max_len = 0;
    int left = 0;

    for (int right = 0; right < static_cast<int>(s.length()); ++right) {
        const auto ch = static_cast<unsigned char>(s[right]);
        
        // 若字符已存在于当前窗口内，将 left 跳跃更新到冲突字符下一位置
        if (last_seen[ch] >= left) {
            left = last_seen[ch] + 1;
        }
        
        last_seen[ch] = right;
        max_len = std::max(max_len, right - left + 1);
    }

    return max_len;
}

// 3. 滑动窗口最大值 (Sliding Window Maximum) - 单调队列维护
[[nodiscard]] std::vector<int> maxSlidingWindow(const std::vector<int>& nums, int k) {
    if (nums.empty() || k <= 0) return {};

    std::vector<int> result;
    result.reserve(nums.size() - static_cast<size_t>(k) + 1);
    std::deque<size_t> mono_deque; // 存放下标，维持 nums[index] 单调递减

    for (size_t i = 0; i < nums.size(); ++i) {
        // 1. 弹出队首超出当前窗口 [i - k + 1, i] 范围的过期下标
        if (!mono_deque.empty() && mono_deque.front() + static_cast<size_t>(k) <= i) {
            mono_deque.pop_front();
        }

        // 2. 维护单调递减队列：弹出尾部所有小于等于当前 nums[i] 的元素
        while (!mono_deque.empty() && nums[mono_deque.back()] <= nums[i]) {
            mono_deque.pop_back();
        }

        mono_deque.push_back(i);

        // 3. 形成合法窗口后记录队首最大值
        if (i + 1 >= static_cast<size_t>(k)) {
            result.push_back(nums[mono_deque.front()]);
        }
    }

    return result;
}

} // namespace Algorithm::SlidingWindow
```

## 3. 🔍 状态跟踪与图解分析

对 `minSubArrayLen` 执行状态追踪：输入 `target = 7, nums = [2, 3, 1, 2, 4, 3]`

| `right` | `nums[right]` | 窗口元素 | `current_sum` | 条件 (`>= 7`) | `left` 移动过程与操作 | `min_len` |
|---|---|---|---|---|---|---|
| 0 | 2 | `[2]` | 2 | 否 | 无 | $\infty$ |
| 1 | 3 | `[2, 3]` | 5 | 否 | 无 | $\infty$ |
| 2 | 1 | `[2, 3, 1]` | 6 | 否 | 无 | $\infty$ |
| 3 | 2 | `[2, 3, 1, 2]` | 8 | **是** | 记录 len=4; `sum -= nums[0](2)`, `left=1` $\implies$ sum=6 < 7 终止 | **4** |
| 4 | 4 | `[3, 1, 2, 4]` | 10 | **是** | 记录 len=4; `sum -= nums[1](3)`, `left=2` $\implies$ sum=7 >= 7<br/>记录 len=3; `sum -= nums[2](1)`, `left=3` $\implies$ sum=6 < 7 终止 | **3** |
| 5 | 3 | `[2, 4, 3]` | 9 | **是** | 记录 len=3; `sum -= nums[3](2)`, `left=4` $\implies$ sum=7 >= 7<br/>记录 len=2; `sum -= nums[4](4)`, `left=5` $\implies$ sum=3 < 7 终止 | **2** |

**最终解**：`min_len = 2`（对应子数组 `[4, 3]`）。

## 4. 📈 复杂度分析与均摊证明

### 时间复杂度
- **定理**：变长滑动窗口算法的总运行时间为 $O(N)$。
- **均摊证明（Aggregate Analysis）**：
  - 尽管存在嵌套的 `while (current_sum >= target)` 循环，但外层 `for` 循环使 `right` 指针递增精确 $N$ 次。
  - 内层 `while` 循环使 `left` 指针只能向前递增。因为 `left <= right < N`，`left` 在整个算法生命周期内**最多递增 $N$ 次**。
  - 因此，`left` 和 `right` 的移动次数之和不超过 $2N$，单次移动内部操作为 $O(1)$，故均摊复杂度为 $\Theta(N)$。

### 单调队列滑动窗口最大值复杂度
- 每个数组元素最多入队 `mono_deque` 1 次，出队 1 次。双端队列总操作次数 $\le 2N$，均摊单次处理耗时 $O(1)$，总时间复杂度为 $O(N)$，辅助空间复杂度为 $O(K)$。

## 5. ⚠️ 常见坑点与边界条件

1. **结果更新时机不一致（更新极小 vs 极大）**
   - 寻找**最小窗口**时，更新 `min_len` 必须放在内层 `while (valid)` 内部（收缩前或收缩时）；寻找**最大窗口**时，更新 `max_len` 必须在窗口调节为合规状态后在外层进行。混淆更新时机将导致无效窗口被记录。
2. **非正数数组打破单调性**
   - 普通变长滑动窗口依赖“`right` 扩大使 Sum 严格单调递增”的前提。若数组中包含负数，扩大窗口可能使 Sum 减小，导致 `left` 的收缩决策失效。存在负数时需结合**前缀和 + 哈希表 / 单调栈**处理。

## 6. 🧠 💡 Flashcards (Guided Recall)

Q: 为什么变长滑动窗口算法虽然有双重循环，但时间复杂度依然是 $O(N)$？
A: 因为 `left` 和 `right` 指针都只单向递增，绝不回退。每个元素最多被 `right` 探访入窗一次，被 `left` 移出窗口一次，总指针移动步数不超过 $2N$。

Q: 单调队列（Monotonic Deque）在求解滑动窗口最大值时，队列中保存的是元素值还是下标？为什么？
A: 必须保存**下标**。因为需要通过 `i - deque.front() >= k` 判断队首的最大值元素是否已经滑出当前窗口范围。

Q: 变长滑动窗口在处理包含负数的数组求和目标时为什么会失效？
A: 因为负数的加入打破了窗口累加和的单调递增性（即扩大窗口不一定增大 Sum，收缩窗口不一定减小 Sum），导致无法依据 Sum 大小正确决定 `left` 的收缩行为。
