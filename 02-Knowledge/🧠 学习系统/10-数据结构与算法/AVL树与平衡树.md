# AVL树与平衡树

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：二叉搜索树（BST）最坏退化成链表、查找 $O(n)$ 的痛点，靠"平衡"解决；AVL 树是 6.006 Lec 7 的主题，是[[红黑树]]、B 树等整个平衡树家族的第一课，也是"用局部操作维护全局不变量"这一算法设计思想的经典案例，HW02 手撕红黑树前必须补。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：BST 的插入/查找/删除平均 $O(\log n)$，但**最坏是 $O(n)$**——按有序序列插入时树退化成一条链表，所有操作都退化成线性扫描。哈希表虽然 $O(1)$，但**无序**、不支持范围查询和找前驱后继；堆虽然能取极值，但**不能按任意键查找**。我们需要一个同时满足"有序 + 任意键查找 + 最坏 $O(\log n)$"的结构——思路是：**插入/删除后主动检查树的"歪斜程度"，一旦失衡就用旋转把它"扶正"**，让树始终保持近乎完美的高度平衡。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：AVL 是 6.006 Lec 7"平衡 BST"的代表；学完它再看[[红黑树]]（Lec 7 后半）、B 树、跳表都只是"平衡策略不同"的变体。它的"旋转不改中序遍历"这一事实贯穿所有树形结构。HW02 官方 PS4 的红黑树实现依赖这里的旋转直觉。
- **实际应用场景**：Java `TreeMap`/`TreeSet`、C++ `std::map`（红黑树）、数据库索引（B 树）的祖先都是平衡树；凡是需要"有序动态集合 + 范围查询"的地方（订单按时间区间查、排行榜、日程表）都是它的主场。**高频题型/任务**：判断旋转类型（LL/RR/LR/RL）、手写旋转、计算平衡因子、AVL 与红黑树选型、证明高度 $O(\log n)$。

---

## 3. 学它之前需要哪些前置知识？

1. **二叉搜索树（BST）**：左小右大性质、查找/插入/删除过程——AVL 就是在 BST 操作后多加一步"检查平衡"。
2. **[[知识地图/递归|递归]]**：树的插入、旋转、求高度都用递归，理解"先递归到底，再回溯时更新"的执行顺序。
3. **[[知识地图/复杂度分析|复杂度分析]]**：理解"树高 = 操作代价"，才能体会平衡为什么把最坏从 $O(n)$ 压到 $O(\log n)$。

---

## 4. 用直觉语言解释它

> «"AVL 树就像杂技演员叠椅子：每把椅子（节点）都要求自己左右两侧的"叠高"相差不超过 1 层——这保证整摞椅子的总高度只能是 $\log n$ 量级。每放上一把新椅子（插入）或抽走一把（删除），就从最底下往上检查，哪把椅子"歪"了（两边差 2 层），就把它当轴"转"一下：把重的那侧抬上来、轻的那侧压下去，转完它又是直的，而且椅子堆的有序性一点没变。"»

- **直觉类比/几何图像**：天平/跷跷板 + 旋转轴；失衡 = 一边沉，旋转 = 以某节点为轴翻转，把"沉的一侧"翻上来。
- **为什么很自然**：树高决定了所有操作代价；只要每个节点两侧高度差 ≤ 1，树高就被强制压到 $O(\log n)$（斐波那契式的最坏结构也长不高）；而旋转是 $O(1)$ 的局部手术，一次失衡只需沿祖先链做有限次旋转。
- **一句话直觉本质**：**BST 操作后若某节点两侧高度差超过 1，就用"保持中序遍历不变的旋转"把失衡局部修复，使树高始终 $O(\log n)$。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **AVL 树**：一棵二叉搜索树，且对每个节点 $v$ 有 $|\text{BF}(v)|\le 1$，其中**平衡因子** $\text{BF}(v)=h(\text{left}(v))-h(\text{right}(v))$（空子树高度记为 $-1$）。
- **旋转**：改变根与子树的父子关系、保持 BST 性质的 $O(1)$ 局部重排。右旋（RR 修复）：以左孩子为轴把当前节点"压下去"；左旋对称。
- **插入后的重平衡**：沿插入路径自底向上找第一个 $|\text{BF}|=2$ 的节点，按"插入点在它的哪一侧"分四种情形修复：LL 单右旋、RR 单左旋、LR 先左旋后右旋、RL 先右旋后左旋。删除后同理，但可能需要在祖先链上连续旋转（至多 $O(\log n)$ 次）。

### 2. 核心公式
树高上界（含 $n$ 个节点的 AVL 树）：
$$h \le \log_\varphi(n+2)-2 \approx 1.44\log_2(n+2)-2,\qquad \varphi=\frac{1+\sqrt5}{2}$$
操作复杂度（查找/插入/删除均最坏）：
$$T_{\text{search}}=T_{\text{insert}}=T_{\text{delete}}=O(h)=O(\log n)$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $h(v)$ | 以 $v$ 为根的子树高度 | $\ge -1$ | 空子树为 $-1$ |
| $\text{BF}(v)$ | 平衡因子 | $\{-2,-1,0,1,2\}$ | AVL 要求 $|\text{BF}|\le 1$ |
| $n$ | 节点数 | $\ge 1$ | |
| $\varphi$ | 黄金比例 | $\approx 1.618$ | 最坏结构呈斐波那契形 |
| LL/RR/LR/RL | 失衡的四种形态 | — | 由"失衡点+插入方向"决定 |

### 4. 常见变体与适用条件
- **变体**：AVL（严格平衡，查快）、[[红黑树]]（黑高平衡，写快）、B 树/B+ 树（多路，磁盘友好）、跳表（概率平衡）、替罪羊树（摊还重平衡）。**适用条件**：频繁查找、最坏有硬性要求（实时系统）；**限制**：写操作旋转多于红黑树，写多读少时红黑树更优。

## 6. 推导思路和思想来源

- **最初困难**：BST 最坏 $O(n)$，有序插入直接退化成链表；朴素想法"每次操作后把整棵树重建为完美平衡"代价 $O(n)$ 太高。
- **直接方法局限**：全局重排太贵；只想"动局部"，但不知道哪些局部操作能同时保持 BST 性质和平衡。
- **关键"转念"**：**旋转**——一个 $O(1)$、只动 3 个指针的局部重排，它保持中序遍历（BST 序）不变，却能把高度差转移走。于是"重平衡"从"全局重构"降级为"沿祖先链做有限次局部手术"。
- **推导主线与动机**：定义 BF → 插入后只有祖先链的 BF 可能变 → 自底向上找到第一个 BF=±2 的节点 → 分四种形态（插入方向 × 孩子方向）→ 单旋不够时先对孩子反向旋一次凑成单旋（双旋）→ 删除同理但需继续向上检查（可能多次）→ 最坏结构满足 $N(h)=N(h-1)+N(h-2)+1$（斐波那契），解得 $h=O(\log n)$。
- **为什么自然得到此结论**：旋转不改 BST 序是 BST 性质"左小右大"的直接推论；而"两侧高度差 ≤ 1"是保证树高对数的最省力条件——放松一点（红黑树）写操作更少旋转，收紧一点（完美平衡）维护成本过高，AVL 恰好在中间。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：依次插入 5, 3, 8, 2, 1，构造 AVL 树，指出哪一步触发旋转、旋转类型。
- **解题思路与关键步骤**：插 5,3,8 都平衡。插 2：$5$ 的 BF=2（左高），但左孩子 3 的 BF=1（也偏左）→ **LL 型**，对 5 右旋：3 升为根，5 变 3 的右孩子，2 挂 3 左。插 1：此时 $3$ 的 BF=2 且左孩子 2 的 BF=1 → 又是 LL，对 3 右旋：2 为根，3、5 依次挂右。
- **最终答案**：根 2，左 1，右子树 3→5→8 单链但各节点 $|\text{BF}|\le 1$，树高 3（$\log_2 5\approx2.32$ 量级，合格）。
- **易错点**：BF 用"子树高度"而非"节点数"；空子树高度是 $-1$ 不是 0；旋转前先确认孩子侧的 BF 方向（同向单旋，反向双旋）。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：从空树插入 10, 20, 30, 40, 50，逐步行旋转。
- **解题思路与完整解答**：插 10,20 平衡。插 30：10 的 BF=-2 且右孩子 20 的 BF=-1 → RR，对 10 左旋：20 为根，10 左、30 右。插 40：20 的 BF=-1，平衡。插 50：30 的 BF=-2 且右孩子 40 的 BF=-1 → RR，对 30 左旋：40 升上，30 为 40 左。最终：20 为根，左 10，右 40（左 30、右 50），树高 2。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：Java `TreeMap`（红黑树）、内存中的有序索引、游戏排行榜的按分查询。插入 + 重平衡的核心骨架：
```python
def insert(root, key):
    if root is None: return Node(key)
    if key < root.key: root.left = insert(root.left, key)
    elif key > root.key: root.right = insert(root.right, key)
    else: return root
    root.h = 1 + max(height(root.left), height(root.right))
    bf = height(root.left) - height(root.right)
    if bf > 1 and key < root.left.key:        return rotate_right(root)      # LL
    if bf < -1 and key > root.right.key:       return rotate_left(root)      # RR
    if bf > 1 and key > root.left.key:         # LR
        root.left = rotate_left(root.left); return rotate_right(root)
    if bf < -1 and key < root.right.key:       # RL
        root.right = rotate_right(root.right); return rotate_left(root)
    return root
```
删除类似：先按 BST 删，再沿路径向上检查，整条链至多 $O(\log n)$ 次旋转。

## 8. 常见误区和易混概念

### 误区 1：以为"AVL 一定比红黑树快"
- **错误直觉**：AVL 平衡更严格，所以任何操作都更快。
- **为什么错**：严格平衡让**查找**更快（树更矮），但插入/删除需要更多旋转（AVL 至多 $O(\log n)$ 次 vs 红黑树至多 2~3 次）。**正确理解**：读多写少选 AVL；写多读少选[[红黑树]]；二者最坏都是 $O(\log n)$，只是常数分配不同。

### 误区 2：以为"旋转会打乱有序性"
- **错误直觉**：旋转改了父子关系，中序遍历顺序一定变。
- **为什么错**：右旋时"左孩子的右子树"整体移到原根左边——该子树所有键介于两者之间，位置移动后依然夹在中间，中序不变。**正确理解**：**旋转保持中序遍历不变**，这是旋转合法的根本原因，也是所有平衡 BST 的共同基石。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 普通 BST | 有序动态集合 | 无平衡约束，最坏 $O(n)$ | 静态/随机插入 |
| AVL 树 | 严格平衡 BST | $\|\text{BF}\|\le1$，查快写慢 | 读多写少、实时系统 |
| 红黑树（[[红黑树]]） | 近似平衡 BST | 黑高平衡，写快 | `std::map`、`TreeMap` |
| 堆（[[堆与堆排序]]） | 极值优先 | 只保证父子偏序，无序 | 优先队列 |

### 题目与解析

#### 1. 什么是 AVL 树？平衡因子的取值范围是多少？
> [!question]- 答案解析
> - **答案**：每个节点的平衡因子 $\text{BF}=h(\text{left})-h(\text{right})$ 都满足 $|\text{BF}|\le 1$ 的二叉搜索树。取值范围 $\{-1,0,1\}$（空子树高度为 $-1$）。
> - **解析**：BF=2 或 -2 即失衡，需要旋转。易错：空子树高度记 $-1$ 而非 0。标签：`#自测题/基础`

#### 2. 高度为 $h$ 的 AVL 树最少有多少个节点？（用递推式表达并写出 $h=3$ 的值）
> [!question]- 答案解析
> - **答案**：$N(h)=N(h-1)+N(h-2)+1$，$N(0)=1,N(1)=2$；$h=3$ 时 $N=7$。
> - **解析**：最坏（最矮）结构是根两侧分别为高度 $h-1$ 和 $h-2$ 的 AVL 子树——这正是斐波那契递推，由此反解 $h\le\log_\varphi(n+2)-2$。易错：忘加根的 1；误以为两侧都取 $h-1$（那是最多节点而非最少）。

#### 3. 插入后某节点 $\text{BF}=2$ 且其左孩子的 $\text{BF}=-1$，属于哪种旋转？为什么？
> [!question]- 答案解析
> - **答案**：LR 型，先对左孩子左旋，再对当前节点右旋（双旋）。
> - **解析**：失衡点在左侧（BF=2），但左孩子偏向右侧（BF=-1）——"内侧重"需要先把它旋成外侧（LL），才能单右旋修复。易错：看到 BF=2 就右旋，忽略孩子侧方向；单旋对 LR/RL 无效。

#### 4. 从空树依次插入 1,2,3,4，画出最终 AVL 树并说明每步旋转。
> [!question]- 答案解析
> - **答案**：插 1,2 平衡；插 3：1 的 BF=-2、右孩子 2 的 BF=-1（RR）→ 对 1 左旋，2 为根（左 1 右 3）；插 4：2 的 BF=-1，平衡，4 挂 3 右。最终根 2，左 1，右 3（右 4），高 2。
> - **解析**：递增序列连续触发 RR 左旋，树保持对数高。易错：插 4 后误以为 3 失衡——3 的 BF=-1 在允许范围；只有 |BF|=2 才旋转。

#### 5. 证明：含 $n$ 个节点的 AVL 树高度为 $O(\log n)$。
> [!question]- 答案解析
> - **答案**：设 $N(h)$ 为高度 $h$ 的 AVL 树最少节点数。根两侧高度至多为 $h-1,h-2$（BF 约束），故 $N(h)\ge N(h-1)+N(h-2)+1$，$N(0)=1,N(1)=2$。归纳得 $N(h)\ge F_{h+2}-1$（$F$ 为斐波那契数），而 $F_k\ge\varphi^{k-2}$，故 $n\ge\varphi^{h}-1$，即 $h\le\log_\varphi(n+1)=O(\log n)$。
> - **解析**：核心是"最坏结构 = 斐波那契形"，把高度问题转化为斐波那契增长问题。易错：把"最少节点"写成 $2^h$（那是满二叉树的最大节点数，方向反了）。
