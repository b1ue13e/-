## 1. 🎯 栈帧结构与物理 CPU 寄存器机理 (Stack Frame Architecture)

递归在宏观上表现为“函数自身调用自身”，而在底层硬件微架构层面，依赖于 CPU 的**过程调用机制 (Procedure Calls)** 与 **系统调用栈 (Call Stack)**。

### 1.1 x86-64 体系下的栈帧结构 (Stack Frame Layout)
内存栈区从高地址向低地址延伸。每次发起函数调用时，系统会在栈顶压入一个新的**栈帧 (Stack Frame)**，其物理布局如下：

```
高地址  +-----------------------------------+
        |  调用方参数 (Argn ... Arg7)        | (超越 6 个寄存器传输的额外参数)
        +-----------------------------------+
        |  返回地址 (Return Address)        | ← 执行 CALL 时 CPU 自动压入 (%rip)
        +-----------------------------------+
        |  旧帧基址 (Old %rbp)              | ← PUSH %rbp 产生的帧基指针
  %rbp →+-----------------------------------+
        |  被调用者保存寄存器 / 局部变量    |
        |  (Local Variables Area)           |
  %rsp →+-----------------------------------+
低地址  (栈顶向低地址生长)
```

### 1.2 关键寄存器与 ABI 约定 (System V AMD64 ABI)
- **`%rsp` (Stack Pointer)**：栈指针寄存器，始终指向当前栈帧的最低有效字节物理地址。
- **`%rbp` (Base Pointer / Frame Pointer)**：基址指针寄存器，指向当前栈帧的基准位置。通过 `%rbp + offset` 访问参数，通过 `%rbp - offset` 访问局部变量。
- **参数传递约定**：前 6 个整型/指针参数依次通过寄存器 `%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8`, `%r9` 传输；函数返回值存放在 `%rax`。

## 2. 🔬 递归调用栈帧 Push/Pop 动态 Trace 模拟 (Step-by-Step Call Stack Trace)

以计算 `factorial(4)` 为例，追踪 CPU 执行递归时的栈帧创建 (Push / Expansion) 与销毁 (Pop / Contraction) 过程：

```cpp
int factorial(int n) {
    if (n <= 1) return 1;          // 基准情形 (Base Case)
    return n * factorial(n - 1);   // 递推步骤 (Recursive Step)
}
```

### 2.1 递推压栈阶段 (Call Phase / Expansion)

1. **`main()` 发起 `factorial(4)`**：
   - 寄存器 `%rdi = 4`。执行 `CALL`，压入返回地址 `0x4011fa`，`%rsp` 下移 8 字节。
   - 分配帧 $F_4$，保存 `Old %rbp`，`%rbp` 更新为 $F_4$ 的基址。
2. **$F_4$ 评估 `4 * factorial(3)`**：
   - 寄存器 `%rdi = 3`。执行 `CALL` 压入返回地址，分配帧 $F_3$。
3. **$F_3$ 评估 `3 * factorial(2)`**：
   - 寄存器 `%rdi = 2`。执行 `CALL` 压入返回地址，分配帧 $F_2$。
4. **$F_2$ 评估 `2 * factorial(1)`**：
   - 寄存器 `%rdi = 1`。执行 `CALL` 压入返回地址，分配帧 $F_1$。

**此时调用栈达到最大深度 $D = 4$，栈帧状态全景**：

```
+--------------------------------------------------------------+
| Frame F4 (n=4): Base = 0x7fff00, Ret = 0x4011fa (main)       |
+--------------------------------------------------------------+
| Frame F3 (n=3): Base = 0x7ffe40, Ret = 0x401080 (factorial)  |
+--------------------------------------------------------------+
| Frame F2 (n=2): Base = 0x7ffd80, Ret = 0x401080 (factorial)  |
+--------------------------------------------------------------+
| Frame F1 (n=1): Base = 0x7ffcc0, Ret = 0x401080 (factorial)  | ← %rbp & %rsp (栈顶)
+--------------------------------------------------------------+
```

### 2.2 回溯弹栈阶段 (Return Phase / Contraction)

| 步骤 | 当前执行栈帧 | 条件评估 / 计算逻辑 | 返回值 (`%rax`) | 栈帧动作 | `%rsp` 指针移动 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Step 1** | $F_1 (n=1)$ | 触发 `n <= 1` Base Case | `%rax = 1` | 恢复 `Old %rbp`，执行 `RET` 弹栈 | $F_1$ 销毁，`%rsp` 回退至 $F_2$ |
| **Step 2** | $F_2 (n=2)$ | 接收 `%rax=1`，计算 $2 \times 1 = 2$ | `%rax = 2` | 执行 `RET` 弹栈 | $F_2$ 销毁，`%rsp` 回退至 $F_3$ |
| **Step 3** | $F_3 (n=3)$ | 接收 `%rax=2`，计算 $3 \times 2 = 6$ | `%rax = 6` | 执行 `RET` 弹栈 | $F_3$ 销毁，`%rsp` 回退至 $F_4$ |
| **Step 4** | $F_4 (n=4)$ | 接收 `%rax=6`，计算 $4 \times 6 = 24$ | `%rax = 24` | 执行 `RET` 弹栈，回到 `main` | $F_4$ 销毁，控制权交给 `main` |

## 3. 📐 递归复杂度与递推方程推导 (Recurrence Relations)

递归算法的时间复杂度分析依赖于求解数学**递推方程 (Recurrence Relation)**：

### 3.1 线性递归 (Linear Recursion)
- **方程**：$T(n) = T(n-1) + \Theta(1)$
- **展开法**：$T(n) = T(n-2) + 2\Theta(1) = \dots = T(1) + (n-1)\Theta(1) = \Theta(n)$
- **空间复杂度**：由于最大栈深度为 $n$，系统栈占用为 $O(n)$。

### 3.2 分治递归 (Divide and Conquer - MergeSort)
- **方程**：$T(n) = 2T(n/2) + \Theta(n)$
- **主定理 (Master Theorem)**：$a=2, b=2, f(n)=\Theta(n)$。由于 $n^{\log_b a} = n^{\log_2 2} = n^1 = f(n)$，属于 Case 2。
- **解**：$T(n) = \Theta(n \log n)$。
- **空间复杂度**：二叉递归树最大高度为 $\log_2 n$，故调用栈深度空间开销为 $O(\log n)$。

### 3.3 重叠子问题指数递归 (Naive Fibonacci)
- **方程**：$T(n) = T(n-1) + T(n-2) + \Theta(1)$
- **特征方程**：$r^2 - r - 1 = 0 \implies r = \frac{1 + \sqrt{5}}{2} = \phi \approx 1.618$ (黄金分割比)
- **解**：$T(n) = \Theta(\phi^n) = O(2^n)$ 呈现暴涨指数阶。

## 4. 💻 C++20 递归栈跟踪、显式栈转换与尾递归优化

以下完整的 C++ 代码包含三个模块：
1. **带栈深度检测防溢出的安全递归**；
2. **显式数据结构 `std::stack` 消除递归**；
3. **尾递归 accumulator 优化模式**。

```cpp
#include <iostream>
#include <vector>
#include <stack>
#include <stdexcept>
#include <cstdint>
#include <cassert>

// 1. 带栈深度监测的安全递归 (递归栈过深防崩溃)
class RecursionStackMonitor {
private:
    static inline size_t current_depth = 0;
    static constexpr size_t MAX_SAFE_DEPTH = 1000; // 假定安全深度上限

public:
    static uint64_t safe_factorial(uint32_t n) {
        current_depth++;
        if (current_depth > MAX_SAFE_DEPTH) {
            current_depth = 0; // 重置
            throw std::runtime_error("StackOverflowError: Maximum recursion depth exceeded!");
        }

        uint64_t result = 0;
        if (n <= 1) {
            result = 1;
        } else {
            result = n * safe_factorial(n - 1);
        }

        current_depth--; // 退栈恢复
        return result;
    }
};

// 2. 使用显式 std::stack 拟合系统调用栈 (消除递归，防止 Stack Overflow)
uint64_t explicit_stack_factorial(uint32_t n) {
    if (n <= 1) return 1;

    std::stack<uint32_t> st;
    for (uint32_t i = n; i >= 2; --i) {
        st.push(i);
    }

    uint64_t result = 1;
    while (!st.empty()) {
        result *= st.top();
        st.pop();
    }
    return result;
}

// 3. 尾递归形式 (Tail Recursion)
// 最后一个动作直接返回子递归调用的结果，不带后续乘法
uint64_t tail_factorial(uint32_t n, uint64_t accumulator = 1) {
    if (n <= 1) return accumulator;
    return tail_factorial(n - 1, n * accumulator); // 尾调用位置
}

int main() {
    std::cout << "[1. Testing Safe Recursion Stack Guard]\n";
    try {
        uint64_t res = RecursionStackMonitor::safe_factorial(5);
        std::cout << "5! = " << res << " (Success)\n";
        assert(res == 120);

        // 触发深度超限测试
        std::cout << "Attempting safe_factorial(1500)...\n";
        RecursionStackMonitor::safe_factorial(1500);
    } catch (const std::exception& e) {
        std::cout << "Caught expected exception: " << e.what() << "\n\n";
    }

    std::cout << "[2. Testing Explicit Stack Emulation]\n";
    uint64_t exp_res = explicit_stack_factorial(6);
    std::cout << "6! (Explicit Stack) = " << exp_res << "\n";
    assert(exp_res == 720);

    std::cout << "\n[3. Testing Tail Recursion Accumulator]\n";
    uint64_t tail_res = tail_factorial(6);
    std::cout << "6! (Tail Recursion) = " << tail_res << "\n";
    assert(tail_res == 720);

    return 0;
}
```

## 5. ⚠️ 常见陷阱与工程边界 (Common Pitfalls & Edge Cases)

1. **爆栈引发段错误 (Stack Overflow Crashes)**
   - **成因**：Windows 系统默认线程栈空间为 1MB，Linux 默认为 8MB。每一个栈帧占用约 32-64 字节。若递归深度超过 $10^5$ 级（例如深层 DFS 遍历长单链表图），会导致 `%rsp` 移动超越栈边界页，引发 OS 硬件保护违规 Segment Fault。
   - **工程解法**：在大规模数据深度遍历场景中，必须使用堆区分配的 `std::vector` 或 `std::stack` 改写为**迭代式遍历**；或在 Linux 下调整 `ulimit -s` 扩充栈空间。

2. **缺少基准情形 (Missing Base Case) 或基准条件覆盖不全**
   - **成因**：未正确处理 $n=0$、空指针 `nullptr` 或负数边界，导致递归条件永不满足，引发死循环压栈直到 Stack Overflow。
   - **工程解法**：编写递归函数时，**首行必须优先且完备地写出 Base Case 的逻辑分支**，并使用 `assert` 对输入参数的非负性/非空性进行严格防卫。

3. **Debug 与 Release 模式下尾递归优化的失效假象**
   - **成因**：虽然写出了尾递归 accumulator 模式，但许多 C++ 编译器（如 GCC / Clang / MSVC）在默认 Debug 调试模式下（`-O0`）**会显式禁用 Tail Call Optimization (TCO)**，以保留完整栈帧用于断点单步调试。
   - **工程解法**：不能盲目依赖编译器的 TCO 优化来保证空间安全性，工程关键路径上若需 $O(1)$ 空间保障，应使用显式 `while` 循环重构代码。

## 6. 🃏 Anki 记忆卡片 (Card-Specific Anki Cards)

- Q: 在 x86-64 函数调用约定中，`%rsp` 与 `%rbp` 寄存器分别扮演什么角色？`CALL` 指令在压栈时做了什么？
- A: `%rsp` 始终指向栈顶（最低地址），`%rbp` 指向当前栈帧基址。执行 `CALL` 指令时，CPU 会自动将下一条指令物理地址 (`%rip` 返回地址) 压入栈顶，并移动 `%rsp` 8 字节。

- Q: 为什么非尾递归函数的空间复杂度至少为 $O(D)$（$D$ 为最大递归深度）？
- A: 因为在递推深入阶段，父栈帧由于需要等待子递归返回结果后继续完成算术运算，其栈帧物理内存无法被销毁释放，必须同时常驻于系统栈区中，故空间占用与最大递归深度 $D$ 成正比。

- Q: 尾递归 (Tail Recursion) 能够被编译器优化为 $O(1)$ 空间开销的充要条件是什么？
- A: 函数的最后一个动作是直接返回子递归调用的返回值，且该返回值**不参与任何后续算术或逻辑运算**。编译器据此可将 `CALL` 指令替换为 `JMP`，直接复用当前栈帧。

- Q: 避免递归引发 Stack Overflow (栈溢出) 的两种工程标准改写手段是什么？
- A: 1) 改用 `while` 循环进行迭代计算；2) 使用堆内存 (Heap) 分配的 `std::stack` 数据结构手工模拟系统栈帧保存状态。
