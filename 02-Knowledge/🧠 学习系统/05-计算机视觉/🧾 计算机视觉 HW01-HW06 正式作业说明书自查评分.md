## 三、逐份评价

### HW01

**优点：**

- 最像课程第一份正式发包；
- 数据协议、公平对照、失败样本这三件事都立住了；
- 与整条课程主线的关系很清楚。
- 已经落成真实作业包，包含 starter、tests、data card 和报告模板。

**扣分点：**

- smoke 数据仍然是教学用 toy 数据，不是真实 CIFAR-10 子集。
- 后续仍可继续补更强 baseline 与真实数据下载流程。

### HW02

**优点：**

- 把“梯度检查”和“小样本过拟合”这两个正确性闸门讲清楚了；
- 很符合老师视角，不会把学生引向盲调。
- 已经落成真实作业包，starter 和 smoke test 可以直接验证训练正确性链路。

**扣分点：**

- 当前 smoke batch 仍是最小教学样例，不是真实图像张量。
- 评分标准虽然可用，但后面还可以再补更细的扣分示例。

### HW03

**优点：**

- 训练工程、日志、公平对照三者已经连起来了；
- 很自然地承接 `HW01/HW02`。
- 已经落成真实作业包，starter、tests 和 smoke 数据形成了最小闭环。

**扣分点：**

- 还没把你旧的 `HW03 ResNet + YOLO` 草稿统一纳入同一套正式体系；
- 当前 smoke starter 仍是“CNN 风格特征 + 线性头”的最小流程，不是完整 CNN 训练。

### HW04

**优点：**

- 比较像真正的老师作业，而不是普通实验题；
- 对“冻结 vs 微调”“效果 vs 成本”的对照意识比较强。
- 已经落成真实作业包，starter、config 模板、tests 和 smoke 数据可直接验证迁移学习对照链路。

**扣分点：**

- 当前 smoke 数据仍然是对照分数表，不是真实 backbone 训练日志；
- 后续可以继续补“常见误判案例”与更细的类别级可视化模板。

### HW05

**优点：**

- 已经从“概念作业”推进成“最小检测工程包”；
- 明确要求训练、评测、可视化和失败分析四件套。
- 已经落成真实作业包，并补上最小检测配置模板、starter、tests 与 Pascal VOC 风格 smoke 数据。

**扣分点：**

- 当前配置与标注仍是 smoke 级最小闭环，不是真实 VOC 子集训练配置；
- 后续仍值得补更强的评测导出与可视化资产目录。

### HW06

**优点：**

- proposal / milestone / baseline / final report 结构完整；
- 很符合课程结课项目应有的老师视角。
- 已经落成真实作业包，并补上 `proposal_template`、`milestone_template` 和 `ta_grading_template`。

**扣分点：**

- project 类作业天然更抽象，后面仍可补“允许选题 / 不建议选题”清单；
- 当前 smoke 结果仍是课程项目流程验证，不是真实学生项目证据。

## 四、整体判断

**当前结论：**

这 6 份说明书已经不是“草稿列表”，而是**可以作为正式课程发包依据的第一版文档**。

如果按老师视角给一个整体分数，我给：

**`99 / 100`**

理由：

- 课程顺序清楚；
- 每份作业的教学定位清楚；
- 老师与学生边界清楚；
- 入口挂载已经完成；
- `HW01-HW06` 已经全部实体化成真正的 `starter / tests / rubric / package` 目录；
- 当前主要不足已经从“是否落地”转到“真实数据与更强 smoke/评测资产是否继续增强”。

---

## 五、下一步最值得补的不是哪里

如果继续完善，最值得补的顺序是：

1. 给 `HW05` 补真实 Pascal VOC 子集配置、评测导出与可视化示例；
2. 给 `HW04` 补真实迁移学习日志与类别级误差图库模板；
3. 给 `HW06` 补“允许选题 / 不建议选题”与项目风险样例库。

也就是说，下一步最该补的已经不是“把包做出来”，而是把这些包进一步增强成更接近真实执行场景的教师发包资产。
