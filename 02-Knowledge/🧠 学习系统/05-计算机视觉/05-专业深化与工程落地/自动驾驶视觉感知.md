# 自动驾驶视觉感知（BEV / 多传感器融合 / 车道线 / Occupancy）

## 0. 学习边界

**B 类专题（自动驾驶主线）**。自动驾驶感知要把"多相机图像"变成"以车为中心的俯视世界"：**BEV（鸟瞰图）**是统一表示，**多传感器融合**把相机/激光雷达/毫米波对齐，**车道线检测**提供可行驶区域，**Occupancy** 给出通用 3D 占用表示。本卡合并 MOC 中 BEV感知 / 多传感器融合 / 车道线检测 / Occupancy 四个规划项——它们是"自动驾驶视觉"同一系统的四个模块，拆开学反而割裂。

## 1. 这个知识点解决什么问题？

- 相机图像是**透视视角**：远处物体小、被遮挡、没有深度——规划控制需要**俯视、带深度、统一坐标**的世界表示；
- 单一传感器有缺陷：相机缺深度、激光雷达贵且稀疏、毫米波低分辨率——需要融合；
- 需要输出"哪条路能开"（车道线/可行驶区域）、"空间哪里被占据"（Occupancy，长尾障碍物通用表示）。

## 2. 为什么它重要？它有什么用？

- BEV 是 2020 年起自动驾驶感知的事实标准（LSS、BEVFormer、Tesla Occupancy）；
- 统一坐标系让检测/分割/预测/规划在同一个"上帝视角"上协作；
- Occupancy 把"检测（已知类别）"扩展到"任意障碍物占据"（未知类别也能避障）——安全关键。

## 3. 学它之前需要哪些前置知识？

## 4. 用直觉语言解释它

BEV 就是"给车装一只在天上的眼睛"：多台相机各自看到局部视角，系统把它们"摊平投影"到车顶俯视的地图上，得到一张"上帝视角"的语义地图（车、人、车道线都画在正确的位置和深度上）。LSS 的做法是"先把每个像素抬到 3D 锥体（lift），再把锥体拍扁到 BEV 网格（splat）"；BEVFormer 则用 Transformer 的 query 从多相机特征里"采样"出每个 BEV 格子的内容。多传感器融合就是"让相机和激光雷达互相补盲"：激光雷达给深度锚点，相机给颜色语义。Occupancy 更进一步：把 BEV 抬成 3D 体素，每个格子回答"空 or 被占 + 语义"，任何障碍物都逃不掉。

## 5. 正式定义、核心公式、符号解释

### 5.1 相机到 BEV 的几何（LSS 的 lift-splat）

对像素 $(u, v, 1)$，深度假设 $d$ 时相机坐标系下的 3D 点：

$$\begin{bmatrix} x_c \\ y_c \\ z_c \end{bmatrix} = d \cdot K^{-1} \begin{bmatrix} u \\ v \\ 1 \end{bmatrix}, \qquad \begin{bmatrix} x \\ y \\ z \end{bmatrix} = R^{-1}\left(\begin{bmatrix} x_c \\ y_c \\ z_c \end{bmatrix} - t\right)$$

每个像素沿射线放出一组"深度离散候选"（lift），经外参变换到车体坐标后投影到 BEV 网格累加（splat）。网络用可微的方式学习"哪些深度候选可信"。

### 5.2 BEVFormer：query 采样

BEV 网格的每个 query 通过**可变形注意力**从多相机特征图中采样（沿参考点射线），再用时间注意力融合历史帧：

$$\text{BEV}_t = \text{Decoder}\left(\text{DeformAttn}(Q_{\text{BEV}}, \text{MultiCamFeat}_t), \text{TempAttn}(Q_{\text{BEV}}, \text{BEV}_{t-1})\right)$$

特点：无需显式深度监督，端到端输出 BEV 检测/分割。

### 5.3 多传感器融合范式

| 范式 | 融合位置 | 代表 | 特点 |
|:---|:---|:---|:---|
| 早期（数据级） | 点云与图像像素对齐后拼接 | 简单融合 | 对位误差敏感 |
| 中期（特征级） | 图像特征与点云特征融合 | TransFuser、BEVFusion | 主流，鲁棒 |
| 后期（决策级） | 各传感器独立感知后投票 | — | 简单但信息利用不足 |

BEVFusion 的核心：把**图像特征也投影到 BEV**，与**点云 BEV 特征**直接拼接，统一在 BEV 空间做检测/分割——相机与激光雷达共享坐标系，融合自然。

### 5.4 车道线与 Occupancy

- **车道线检测**：分割式（每个像素车道类别）或参数式（拟合曲线/关键点），输出车道线点列与可行驶区域（drivable area）；
- **Occupancy（占用网络）**：输出体素栅格 $\mathcal{O} \in \{0,1\}^{X \times Y \times Z}$（或带语义），每个格子被占与否——对**任意形状/未知类别**障碍物有效，是检测的补集；训练用点云投影的体素真值。

### 例子 1：基础——相机投影到 BEV 的几何直觉

```python
# 地面假设 z=0：像素(u,v) + 深度d → 世界点(x,y,0)（标定后）
# BEV 网格 = 把世界点按 (x,y) 落入的格子累加特征
# 近处像素深度小 → BEV 近端；远处像素深度大 → BEV 远端
# 单目歧义：同一像素不同深度对应不同世界点 → 需要网络学习深度分布（LSS）
```

### 例子 2：中等——BEV 特征图与图像特征的对齐（PyTorch 伪代码）

```python
import torch

def project_to_bev(img_feats, K_inv, R, t, bev_range, grid_size):
    """img_feats: (B, C, H, W)；返回 BEV 网格 (B, C, gx, gy)"""
    B, C, H, W = img_feats.shape
    # 1. 每个像素生成深度候选 (D 个)，lift 成 3D 锥体点 (B, C, D*H*W)
    # 2. 外参变换到车体坐标 (B, C, D*H*W)
    # 3. 按 (x, y) 投影到 BEV 网格并 sum 池化（splat）
    bev = img_feats.new_zeros(B, C, grid_size[0], grid_size[1])
    # ...（省略逐点 scatter 细节）
    return bev
# 关键：整个 lift-splat 可微 → 网络能学习深度分布，无需深度真值
```

## 7. 常见误区和易混概念

| 误区 | 正确理解 |
|:---|:---|
| "BEV 就是俯视摄像头" | BEV 是**多相机+几何**重建的语义表示，不是物理摄像头 |
| "融合越多传感器越好" | 特征级融合为主流；对位误差与算力成本要权衡 |
| "Occupancy 取代检测" | Occupancy 是通用占用的补集；检测提供语义类别，两者互补 |
| "车道线检测 = 语义分割" | 输出是"线/可行驶区域"的结构化表示，比像素分割更贴合规划 |
| "BEV 不需要标定" | 相机外参标定误差直接导致 BEV 投影错位——标定是前提（阶段5 标定卡） |
