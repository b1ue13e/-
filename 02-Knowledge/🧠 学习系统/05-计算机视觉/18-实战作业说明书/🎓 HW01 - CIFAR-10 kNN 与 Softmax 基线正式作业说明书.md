# 🎓 HW01 - CIFAR-10 kNN 与 Softmax 基线正式作业说明书

> 这是一份老师正式发包用的作业说明书。  
> 它定义的是题目边界、教学目标、交付格式和评分口径，不提供实验答案。

---

## 一、作业主题

在固定的 `CIFAR-10` 数据协议下，完成两类最基础但最重要的视觉分类 baseline：

1. `kNN`
2. `Softmax / 线性分类器`

并基于统一测试集完成结果对比、失败样本审计和最小报告。

---

## 二、布置时机

这份作业应放在以下内容之后发出：

1. 已经学完图像数据的基本表示方式；
2. 已经理解训练 / 验证 / 测试切分；
3. 已经学完距离度量、线性分类和交叉熵损失的基本概念；
4. 已经能用 `NumPy` 完成向量化运算和最小训练循环。

**为什么在这个时点布置：**

- 这份作业的目标不是追求高分，而是让学生第一次真正建立“视觉实验协议”的意识；
- 如果这一步不稳，后面的 MLP、CNN、迁移学习都会失去公平对照的地基。

---

## 三、前置知识

开始这份作业前，学生至少应具备以下前置：

- `NumPy` 数组、矩阵乘法与广播机制；
- 训练 / 验证 / 测试切分的作用；
- 欧氏距离、L1 / L2 距离的直觉；
- 线性分类器、Softmax、交叉熵损失；
- 准确率、混淆矩阵的基本解释。

如果以下内容仍然不稳，建议先回补后再做作业：

- 为什么测试集不能参与模型选择；
- 为什么 baseline 必须和改进方法共用同一切分与同一评价脚本；
- 为什么单次最好结果不能直接当最终结论。

---

## 四、教学目标

完成这份作业后，学生应证明自己具备以下能力：

1. 能在固定数据协议下独立跑通一个视觉分类 baseline；
2. 能解释 `kNN` 与 `Softmax` 在表示能力、训练成本和推理成本上的差异；
3. 能输出最基本的实验证据，而不是只报一个准确率数字；
4. 能开始做最初级的失败样本审计，知道模型到底错在什么地方。

---

## 五、老师提供什么

老师应提供以下内容，但不替学生完成实验：

- `README` 模板；
- 数据契约；
- 最小 starter；
- smoke test；
- 评分标准；
- 报告模板；
- FAQ / submission checklist / milestones / grader notes。

老师不提供：

- 最终最优超参数；
- 完整实验答案；
- 调好后的最佳结果；
- 可直接提交的成品实现。

---

## 六、作业任务

### 任务 1：建立数据协议

学生需要明确记录：

- 使用的 `CIFAR-10` 来源；
- 数据版本；
- 训练 / 验证 / 测试切分方式；
- 是否做像素标准化；
- 所有随机种子与运行入口。

### 任务 2：完成 kNN baseline

学生需要：

- 实现或复核 `kNN` 分类流程；
- 在固定切分下完成验证；
- 报告最基本的性能指标与运行成本。

### 任务 3：完成 Softmax baseline

学生需要：

- 实现或复核 `Softmax / 线性分类器`；
- 在与 `kNN` 相同的数据协议下评测；
- 保持评价口径一致。

### 任务 4：做公平对照

学生需要至少回答：

- 哪个 baseline 更强；
- 哪个 baseline 训练更慢；
- 哪个 baseline 推理更慢；
- 两者各自容易在哪些类别上出错。

### 任务 5：失败样本审计

学生至少给出：

- 若干代表性错误分类样本；
- 每类错误的简单解释；
- 自己对“后续为什么需要更强模型”的判断。

---

## 七、数据与实验协议

这份作业必须遵守以下统一协议：

1. 不允许使用测试集做模型选择；
2. `kNN` 与 `Softmax` 必须共用同一切分；
3. 不允许只报告最好的一次结果而不说明设置；
4. 必须保留至少一个失败案例；
5. 所有结论都要能从提交物中复核出来。

建议记录但不强制预先追求的内容：

- 推理耗时；
- 参数量；
- 单次实验日志；
- confusion matrix。

---

## 八、评分标准

总分 `100` 分，建议按以下口径评分：

| 维度 | 分值 | 评分关注点 |
|:---|---:|:---|
| 数据与协议正确性 | 20 | 数据来源、切分、标准化、种子、评价口径是否清楚 |
| kNN baseline | 20 | 是否可运行、是否按协议评测、结果记录是否完整 |
| Softmax baseline | 20 | 是否可运行、是否按协议评测、是否与 kNN 公平对照 |
| 失败样本与误差分析 | 20 | 是否真正分析错误，而不是只贴图 |
| 报告与可复现性 | 20 | README、运行命令、结果表与结论是否可复核 |

**通过线建议：**

- `75/100` 及以上；
- 且所有硬验收项通过。

---

## 九、硬验收项

以下项目任一失败，都不能靠总分抵消：

- [ ] 训练 / 验证 / 测试切分清楚；
- [ ] `kNN` 与 `Softmax` 共用同一评价协议；
- [ ] 提交物中可以复核主要结果；
- [ ] 至少包含一个失败样本分析；
- [ ] 没有把测试集用于模型选择；
- [ ] 没有直接照搬外部答案。

---

## 十、交付格式

建议统一使用以下目录：

```text
submission/
├── README.md
├── manifest.yml
├── src/
├── tests/
├── artifacts/
└── report.md
```

### 最低交付要求

#### 1. `README.md`

必须写清：

- 任务是什么；
- 数据从哪里来；
- 如何运行；
- 主要结果有哪些；
- 已知限制是什么。

#### 2. `manifest.yml`

至少记录：

- 数据版本；
- 随机种子；
- 运行入口；
- 关键依赖版本；
- 结果文件位置。

#### 3. `src/`

包含：

- `kNN` 实现；
- `Softmax` 实现；
- 数据加载与评测逻辑。

#### 4. `tests/`

至少包含：

- 一个 smoke test；
- 一个基础正确性检查。

#### 5. `artifacts/`

建议包含：

- 混淆矩阵；
- 失败样本截图；
- 结果表。

#### 6. `report.md`

至少回答：

1. 两个 baseline 的表现差异是什么；
2. 哪些类别更容易混淆；
3. 为什么这份作业说明后续需要 MLP / CNN。

---

## 十一、老师批改时主要看什么

老师最关心的不是“有没有刷到最高分”，而是：

1. 学生有没有遵守实验协议；
2. 学生有没有给出公平 baseline；
3. 学生有没有解释错误，而不是只堆数字；
4. 提交物能不能被别人复核。

老师明确不以以下内容作为唯一标准：

- 是否用了最复杂的技巧；
- 是否达到了某个网上流传的最好分数；
- 是否写了特别长的代码。

---

## 十二、与课程主线的关系

这份作业对应课程主线中的第一道正式闸门。

如果这份作业完成质量不高，后续不建议直接跳到：

- `HW03 CNN`
- `HW04 迁移学习`
- 检测 / 分割专题

因为这些更高级的作业都依赖本作业建立的基本实验规范。
