## 1. 直觉：调试的第一性原理

深度学习训练是一条**单向流水线**：

$$\text{数据} \rightarrow \text{前向} \rightarrow \text{损失} \rightarrow \text{反向} \rightarrow \text{参数更新}$$

任何异常都发生在其中**某一环**。新手最大的错误是"改超参碰运气"——那是在没定位故障点的情况下随机扰动系统。正确做法是**二分定位**：先确定故障在哪一环，再在那一环内部细查。

判据很简单：**能不能让模型在 1 个 batch 上过拟合到 loss≈0？**

- 不能 → 故障在「数据 / 前向 / 反向」，是**代码 bug**。
- 能 → 代码通路是对的，故障在「泛化 / 超参 / 数据量」，是**建模问题**。

这一条判据把"模型效果不好"这个模糊问题，切成了两个性质完全不同的子问题。

---

## 2. 三层定位法

| 层 | 检查什么 | 典型手段 |
|:---|:---|:---|
| **L1 数据层** | 形状、数值范围、标签对齐、归一化、增强是否作用在验证集上 | 打印一个 batch 的 `shape` / `min` / `max` / `dtype`，把图片和标签一起可视化 |
| **L2 前向层** | 各层输出形状、是否有 NaN/Inf、激活是否饱和 | 注册 forward hook 打印每层输出统计量 |
| **L3 反向/优化层** | 梯度是否为 None、梯度范数量级、学习率、`optimizer.zero_grad()` 是否漏调 | 打印梯度范数（见 [[梯度流问题]] 的监控代码） |

> 顺序不能颠倒。80% 的"模型不收敛"最终查出来是 L1 的问题——标签错位、归一化写反、验证集混入了训练增强。

## 3. 常见报错速查表

| 报错 / 症状 | 直接原因 | 定位动作 |
|:---|:---|:---|
| `RuntimeError: shape '[...]' is invalid` / `mat1 and mat2 shapes cannot be multiplied` | 全连接层输入维度与展平后的特征图不匹配 | 在 `flatten` 前打印 `x.shape`，反推 `in_features` 该是多少 |
| `Expected all tensors to be on the same device` | 模型在 GPU、数据在 CPU（或反之） | 检查 `model.to(device)` 与 `x.to(device)` 是否都执行了 |
| `Expected object of scalar type Long but got Float` | 分类标签传成了浮点 | `CrossEntropyLoss` 要求标签为 `int64`，用 `.long()` 转换 |
| `CUDA out of memory` | batch size 过大 / 推理时未关梯度 / 累积了计算图 | 减小 batch；推理包 `torch.no_grad()`；记录 loss 时用 `.item()` 而非张量 |
| loss 变成 `NaN` | 学习率过大、除零、`log(0)`、输入含 NaN | 见 [[梯度流问题]]；先把 lr 降一个数量级，并检查数据里是否有 NaN |
| loss 完全不下降（水平线） | 漏了 `optimizer.step()`；或 `zero_grad()` 位置错；或 lr 太小 | 打印梯度范数：全为 0 或 None → 反向没接上 |
| loss 下降但准确率不动 | 标签与预测的类别索引未对齐；评估时忘了 `argmax` | 手工比对 5 个样本的预测与真值 |
| 训练准确率高、验证准确率低 | 过拟合，或验证集被污染 | 见 [[数据增强与正则化]]；同时确认验证集没做随机增强 |
| 每个 epoch 结果都不同 | 未固定随机种子 | 固定 `torch`/`numpy`/`random` 三处种子 |
| `DataLoader worker exited unexpectedly` | Windows 下多进程 + 未加 `if __name__ == "__main__"` | 先把 `num_workers=0` 排除数据管线问题 |

## 4. 标准调试流程：过拟合一个 batch

这是最有价值的单个调试技巧，来自 Karpathy 的训练配方。

```python
# 目标：让模型在 1 个 batch 上把 loss 压到接近 0
# 若做不到，说明代码通路有 bug，与超参无关

x, y = next(iter(train_loader))
x, y = x[:8].to(device), y[:8].to(device)      # 只取 8 个样本

model.train()
opt = torch.optim.Adam(model.parameters(), lr=1e-3)

for step in range(200):
    opt.zero_grad()
    out = model(x)
    loss = criterion(out, y)
    loss.backward()
    opt.step()
    if step % 50 == 0:
        print(f"step {step:>3} loss {loss.item():.6f}")

# 预期：loss 单调下降到 ~1e-4 量级
# 若卡在某个值不动 → 检查 L3（梯度/优化器）
# 若直接 NaN      → 检查 L1（数据范围）与学习率
```

**为什么有效**：8 个样本远少于模型参数量，一个正确实现的网络必然能"背下来"。背不下来，就一定是实现错了，而不是"数据不够"或"模型太弱"。

## 5. 随手可用的诊断代码

```python
# (1) 数据层体检：一眼看出归一化写反、标签越界
x, y = next(iter(train_loader))
print(f"x: {tuple(x.shape)} {x.dtype} range=[{x.min():.3f}, {x.max():.3f}]")
print(f"y: {tuple(y.shape)} {y.dtype} unique={y.unique().tolist()[:10]}")
# 常见异常：range=[0,255] 说明忘了除以 255；y 里出现 -1 或 num_classes 说明标签越界

# (2) 前向层体检：定位 NaN 最早出现在哪一层
def hook(name):
    def fn(m, i, o):
        if torch.isnan(o).any():
            print(f"NaN first appears at layer: {name}")
    return fn
for name, m in model.named_modules():
    m.register_forward_hook(hook(name))

# (3) 反向层体检：确认梯度真的接上了
loss.backward()
none_grad = [n for n, p in model.named_parameters() if p.grad is None]
print("params without grad:", none_grad)   # 非空 → 该参数没参与计算图
```

## 6. 常见误区

| 误区 | 为什么错 |
|:---|:---|
| 「loss 不降就调学习率」 | 学习率只是 L3 的一个旋钮。若梯度是 None，调多少都没用。先定位层级再调参。 |
| 「报错太长，直接搜第一行」 | Python 的 traceback 中**最后一行**才是真实错误类型，中间是调用栈。应从下往上读。 |
| 「验证集准确率低就加正则」 | 先排除验证集被训练增强污染、或标签映射不一致。加正则是在确认过拟合之后。 |
| 「显存不够就换卡」 | 大多数 OOM 来自推理时忘记 `torch.no_grad()`，或把张量 loss 累加进列表导致计算图不释放。 |
| 「结果不可复现是随机性正常现象」 | 未固定种子时无法判断改动是否有效，等于失去了实验对照能力。 |

## 🧪 自测题

1. **(基础)** 训练时 loss 始终是一条水平线，一步都不降。按三层定位法，你应该先查哪一层？给出你的第一条打印语句。
   <details><summary>💡 思路</summary>回想 L3 的判据：先确认梯度是否真的回传了。想想哪个量能一眼区分「梯度为 None」「梯度全 0」「梯度正常但 lr 太小」这三种情况。</details>

2. **(中等)** 模型能在 8 个样本上过拟合到 loss≈0，但在完整训练集上准确率只有 20%。这个结果排除了哪一类问题、指向了哪一类问题？
   <details><summary>💡 思路</summary>回到本卡第 1 节的二分判据：过拟合成功说明「数据→前向→反向」这条通路本身是通的。那么剩下的可能性集中在哪几个方向？逐一列出并想怎么验证。</details>

3. **(较难)** 训练 loss 正常下降，但每次重跑结果差异很大，且验证准确率总比训练准确率高。请给出至少两个可能原因及各自的验证方法。
   <details><summary>💡 思路</summary>「验证高于训练」是个反常信号——想想 Dropout/BatchNorm 在 `train()` 与 `eval()` 两种模式下行为有何不同，训练准确率是在哪个模式下统计的。另一条线索是随机性：种子、数据划分、增强是否只作用在训练集。</details>
