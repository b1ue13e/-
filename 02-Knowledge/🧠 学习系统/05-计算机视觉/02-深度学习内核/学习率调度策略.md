# 🎯 学习率调度策略 (Learning Rate Scheduling)

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：学习率（Learning Rate, LR）被广泛认为是深度学习训练中最重要的超参数。如果说优化器（SGD、Adam）是训练的"方向盘"，那么学习率调度器（LR Scheduler）就是训练的"油门控制器"——它决定了模型在每个训练阶段以多大的步伐前进。固定学习率在训练初期面临发散风险（太大）或收敛极慢（太小）；而在训练后期，持续的大步长会让模型在最优解附近来回震荡，永远无法精准收敛。一个合适的调度策略，通常能将最终精度提升 2~5 个百分点，甚至决定模型能否收敛。从经典 StepLR 到现代 Cosine Annealing + Warmup 组合，学习率调度已成为 CV、NLP、多模态等所有深度学习领域的标配工程实践。

---

## 1. 这个知识点解决什么问题？

> **We Encountered a Problem（我们遇到了什么麻烦）**：

**① 固定学习率的"不可能三角"**：
- **太大**→ 训练初期可能发散或剧烈震荡，loss 变成 NaN；
- **太小**→ 收敛速度极慢，可能训练 300 epochs 还没到最优区域；
- **适中**→ 前期勉强不炸，但后期在最优解附近来回震荡，无法精细收敛。

下图直观展示了这个问题：固定 LR 要么前期发散，要么后期无法精细逼近。

**② 不同训练阶段需要不同的学习率**：
训练初期，权重是随机初始化的，模型离最优解很远——需要大步快跑（大 LR）；训练后期，模型已接近局部最优点，需要小步微调（小 LR）以避免跳过去。这就像从北京开车去上海：高速公路上可以 120 km/h 巡航，但到了上海市区就得减速到 40 km/h 避免撞墙。

**③ 深度网络的特殊性**：
Transformer 等架构在训练初期极其脆弱——参数随机初始化时，梯度的方向和尺度都很不稳定。如果不加 Warmup 直接上大学习率，模型可能在头几千步就"炸掉"（梯度爆炸导致不可逆的参数损坏）。这也是为什么 Warmup 从 Trick 变成了 Transformer 训练的硬性要求。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：学习率调度是连接"优化理论"和"训练工程"的关键桥梁。它让模型在训练的不同阶段获得不同大小的参数更新，是实现"快速收敛 + 高精度"的工程基石。在几乎所有 SOTA 模型的论文中，学习率调度策略都是不可或缺的实验设定。
- **实际应用场景**：
  - ImageNet 分类训练（ResNet/EfficientNet/ViT）：Cosine Annealing + Linear Warmup 是标配
  - 目标检测（YOLO/Faster R-CNN）：StepLR 或 Cosine，配合 Warmup
  - Transformer 预训练（BERT/GPT/ViT）：Warmup 是刚需，否则训练必炸
  - 语义分割（UNet/DeepLab）：ReduceLROnPlateau 或 Cosine
  - 微调（Fine-tuning）：通常使用较小的固定 LR 或 Cosine 衰减
- **高频考点/任务**：Cosine Annealing 的数学公式、Warmup 为什么对 Transformer 必不可少、StepLR vs Cosine 的效果差异、ReduceLROnPlateau 的触发条件、PyTorch 中 `torch.optim.lr_scheduler` 的 API 使用、OneCycleLR 背后的直觉。

## 4. 用直觉语言解释它

> «"这东西其实就像……"»

- **直觉类比 1 — 登山者调整步幅**：
  想象你在一片漆黑的大山里寻找最深的山谷（全局最优点）。一开始你不知道自己在哪里，只能大步流星地试探——步子太小走不出当前区域，步子太大可能一脚踏空摔下悬崖。当感觉地势开始往下了，你缩小步幅，精细地沿着坡度走下去。到了谷底附近，你用极小的碎步慢慢摸索，确保停在最低点。**学习率调度就是登山者的步幅调整策略**：前期大步探索（大 LR），后期碎步收敛（小 LR）。

- **直觉类比 2 — 模拟退火（Simulated Annealing）**：
  物理学中的退火过程：先将金属加热到高温（原子剧烈运动、大范围搜索），然后缓慢降温（原子逐渐稳定到最低能量态）。Cosine Annealing 的名字正是来源于此——学习率像温度一样从一个较高值逐渐"冷却"到接近零。

- **直觉类比 3 — Warmup 就像汽车预热**：
  Transformer 的 Warmup 就像冬天开车前需要热车——冷启动时润滑油还没到位（梯度方向不稳定），直接猛踩油门（大 LR）会损坏发动机（参数被破坏）。先让引擎低速运转几分钟（小 LR 预热几千步），等一切就绪再加速。

- **一句话直觉本质**：**学习率调度 = 在训练的不同阶段，用不同的"学习步长"，让模型从"快速探索"平滑过渡到"精准收敛"。**

## 5. 正式定义、核心公式、符号解释

### 5.1 通用框架

设初始学习率为 $\eta_0$（即 `base_lr`），当前训练步数为 $t$（可以是 epoch 或 iteration），学习率调度器是一个函数：

$$\eta_t = \eta_0 \cdot f(t)$$

其中 $f(t)$ 是衰减因子，随 $t$ 单调递减（Warmup 阶段除外）。不同调度器的区别就在于 $f(t)$ 的具体形式。

### 5.2 StepLR — 阶梯式衰减

每经过 $S$ 个 epoch，学习率乘以衰减因子 $\gamma$：

$$\eta_t = \eta_0 \cdot \gamma^{\lfloor t / S \rfloor}$$

典型设定：$\eta_0 = 0.1$，$S = 30$，$\gamma = 0.1$，即每 30 epochs 学习率降为原来的 1/10。

```python
scheduler = torch.optim.lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.1)
```

**MultiStepLR**：在预先指定的 epoch 列表处衰减（更灵活）。

$$\eta_t = \eta_0 \cdot \gamma^{\text{count}(t > \text{milestones})}$$

```python
scheduler = torch.optim.lr_scheduler.MultiStepLR(
    optimizer, milestones=[60, 120, 160], gamma=0.2
)
```

### 5.3 ExponentialLR — 指数衰减

每个 epoch 以固定因子连续衰减：

$$\eta_t = \eta_0 \cdot \gamma^t$$

典型设定：$\gamma = 0.95$，即每个 epoch 学习率变为原来的 95%。

```python
scheduler = torch.optim.lr_scheduler.ExponentialLR(optimizer, gamma=0.95)
```

### 5.4 Cosine Annealing — 余弦退火（⭐ 最常用）

以余弦函数的形式平滑地从 $\eta_0$ 衰减到 $\eta_{\min}$：

$$\eta_t = \eta_{\min} + \frac{1}{2}(\eta_0 - \eta_{\min})\left(1 + \cos\left(\frac{t}{T_{\max}} \cdot \pi\right)\right)$$

其中 $T_{\max}$ 是总 epochs（或总 iterations），$\eta_{\min}$ 是最终衰减到的下限（通常为 0 或 $\eta_0 \times 10^{-3}$）。

**核心优势**：
- 前期：LR 缓慢下降（余弦在 $t=0$ 附近斜率接近 0），给模型充分探索空间；
- 中期：LR 快速下降（余弦在 $\pi/2$ 附近斜率最大），加速收敛；
- 后期：LR 缓慢逼近 $\eta_{\min}$（余弦在 $\pi$ 附近斜率再次接近 0），精细微调。

```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer, T_max=200, eta_min=0
)
```

**Cosine Annealing with Warm Restarts（软重启）**：
不同于单次衰减，该策略每 $T_i$ 个 epoch 将 LR 重置回 $\eta_0$ 并开始新一轮余弦衰减（$T_i$ 可逐轮翻倍）。这允许模型周期性地跳出局部最优，探索更广的参数空间。训练结束后，可取多轮"快照"做模型集成（Snapshot Ensembling）。

```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingWarmRestarts(
    optimizer, T_0=50, T_mult=2, eta_min=1e-6
)
```

### 5.5 ReduceLROnPlateau — 基于验证损失的自适应衰减

不预设衰减时间表，而是监控验证集指标（如 val_loss）：当该指标连续 $p$ 个 epoch 不再改善时，自动降低学习率。

$$\text{If } \text{val\_loss}_t > \text{val\_loss}_{t-p} \ \text{(no improvement for } p \text{ epochs):}$$
$$\quad \eta \leftarrow \eta \cdot \gamma$$

典型设定：`factor=0.5`（降为原来的 1/2），`patience=10`（连续 10 个 epoch 不改善即触发），`threshold=1e-4`（低于该改善量不算）。

```python
scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
    optimizer, mode='min', factor=0.5, patience=10, min_lr=1e-6
)
# 注意：ReduceLROnPlateau 需要在 step() 时传入 val_loss
scheduler.step(val_loss)
```

### 5.6 Warmup — 预热策略

在前 $W$ 个 iteration（或 epoch），学习率从一个小值（如 0 或 $\eta_0 \times 10^{-3}$）线性/余弦增加到 $\eta_0$，之后再按正常调度衰减。

**线性 Warmup**：

$$\eta_t = \eta_0 \cdot \frac{t}{W}, \quad t \leq W$$

**余弦 Warmup**：

$$\eta_t = \eta_0 \cdot \frac{1}{2}\left(1 - \cos\left(\frac{t}{W} \cdot \pi\right)\right), \quad t \leq W$$

```python
# PyTorch 1.13+ 内置
scheduler = torch.optim.lr_scheduler.LinearLR(
    optimizer, start_factor=1e-3, total_iters=1000
)
# Cosine Warmup
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer, T_max=1000  # Warmup 阶段
)
# 更常用：SequentialLR 组合 Warmup + Cosine
warmup = torch.optim.lr_scheduler.LinearLR(
    optimizer, start_factor=1e-3, total_iters=1000)
main = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer, T_max=199000, eta_min=1e-5)
scheduler = torch.optim.lr_scheduler.SequentialLR(
    optimizer, schedulers=[warmup, main], milestones=[1000])
```

**为什么 Transformer 必须用 Warmup？**
在训练初期，Transformer 的自注意力权重是随机初始化的，导致 (1) 注意力分布接近均匀（每个 token 被等权关注），梯度方向极度不稳定；(2) 层归一化前的激活值方差极大，Adam 的第二动量估计 $v_t$ 非常不准确——在 $v_t$ 被充分积累之前使用大 LR，会导致参数更新过大且方向错误。Warmup 给了 Adam 足够的时间建立可靠的二阶动量估计，从而避免了训练初期的模型崩溃。

### 5.7 OneCycleLR — 单周期策略

由 Leslie Smith (2017) 提出，整个训练过程仅有**一个周期**：学习率先从 $\eta_{\min}$ 线性上升到 $\eta_{\max}$（约 30% 训练时长），再从 $\eta_{\max}$ 余弦下降到 $\eta_{\min}$（约 70% 训练时长）。同时，momentum 反方向变化（LR 上升时 momentum 下降）。

这一策略的理论依据是：大 LR 相当于强正则化，在训练中期使用极大的 LR 可以驱使模型到达更平坦的最优区域（flat minima），泛化能力更强。

```python
scheduler = torch.optim.lr_scheduler.OneCycleLR(
    optimizer, max_lr=0.1, total_steps=total_steps,
    pct_start=0.3, anneal_strategy='cos'
)
```

### 5.8 符号说明表

| 符号 | 含义 | 典型值 |
| :--- | :--- | :--- |
| $\eta_0$ | 初始/基础学习率 (base_lr) | 0.1 (SGD), 1e-3 (Adam) |
| $\eta_t$ | 第 $t$ 步的学习率 | 随调度变化 |
| $\eta_{\min}$ | 最小学习率下限 | 0 或 1e-6 |
| $\eta_{\max}$ | OneCycleLR 的峰值学习率 | 0.1 ~ 1.0 |
| $\gamma$ | 衰减因子 | 0.1 (StepLR), 0.95 (ExpLR) |
| $S$ | StepLR 的衰减间隔 | 30 epochs |
| $T_{\max}$ | Cosine Annealing 的总步数 | 200 epochs |
| $W$ | Warmup 步数 | 1000 ~ 4000 iterations |
| $p$ | ReduceLROnPlateau 的耐心值 | 10 epochs |

## 6. 推导思路和思想来源

### 6.1 从经验炼丹到理论指导

- **最初困难**：2012 年 AlexNet 训练时，研究者发现固定学习率几乎无法训练出好模型——学习率稍大就发散，稍小就欠拟合。最初的解决方案是纯经验的：看 loss 曲线手动调。loss 不降了就手动把 LR 除以 10，这就是 StepLR 的雏形。
- **关键转念 1 — "退火"的数学化**：Ilya Loshchilov & Frank Hutter (ICLR 2017) 在论文「SGDR: Stochastic Gradient Descent with Warm Restarts」中系统论证了 Cosine Annealing 的优越性——与 StepLR 的"暴力跳变"不同，余弦函数天然提供了"前期缓慢→中期快速→后期缓慢"的平滑过渡，且与模拟退火有着深刻的数学联系。他们进一步证明了周期性重启（Warm Restarts）可帮助 SGD 跳出局部最优，所需的训练时间仅为传统方案的 1/2 ~ 1/4。
- **关键转念 2 — Warmup 的理论解释**：最初 Warmup 被当作一个"有用的 trick"，直到 Popel & Bojar (2018) 和 Xiong et al. (2020) 的研究揭示了 Transformer 预训练中 Warmup 的深层原因——Adam 优化器在训练初期的自适应学习率 $\eta / \sqrt{\hat{v}_t + \epsilon}$ 是极其不稳定的（因为 $\hat{v}_t$ 的估计方差巨大），Warmup 用小 LR 给了 Adam 足够的时间积累可靠的二阶动量。这解释了为什么即使使用 LayerNorm 的 Transformer 依然需要 Warmup。

### 6.2 Cosine Annealing 斜率分析

对 Cosine Annealing 公式求导：

$$\frac{d\eta_t}{dt} = -\frac{\pi(\eta_0 - \eta_{\min})}{2T_{\max}} \sin\left(\frac{t}{T_{\max}} \cdot \pi\right)$$

- 当 $t \approx 0$ 时，$\sin(0) = 0$ → 斜率接近 0（前期缓慢下降）
- 当 $t = T_{\max}/2$ 时，$\sin(\pi/2) = 1$ → 斜率最大（中期快速下降）
- 当 $t \approx T_{\max}$ 时，$\sin(\pi) = 0$ → 斜率再次接近 0（后期精细微调）

这与训练的直觉完美吻合——前期保持大 LR 充分探索，中期加速压缩，后期精细收敛。

### 6.3 为什么 Warmup 对 Transformer 是"刚需"

> **关键数学直觉**：Transformer 中自注意力层的输出方差与序列长度的平方根成正比。在权重随机初始化时，这个方差可能极大，导致：
> $$\text{Var}(\nabla_\theta L) \gg \text{正常值}$$
> 梯度方向的信噪比极低。此时若使用标准学习率 $\eta$，参数更新 $\Delta\theta = -\eta \cdot \nabla L$ 的方向几乎随机，一旦朝错误方向走了一步，后续很难纠正——因为 LayerNorm 的无偏性并不能阻止参数被推向不可恢复的区域。Warmup 用极小的 LR 让模型在最脆弱的阶段"安全度过"。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础 — 手算 StepLR 的学习率

设 $\eta_0 = 0.1$，`step_size=30`，`gamma=0.5`，训练 100 epochs：

| Epoch 范围 | 学习率 | 计算 |
| :--- | :--- | :--- |
| 0–29 | 0.1 | $\eta_0 \cdot 0.5^{0}$ |
| 30–59 | 0.05 | $\eta_0 \cdot 0.5^{1}$ |
| 60–89 | 0.025 | $\eta_0 \cdot 0.5^{2}$ |
| 90–100 | 0.0125 | $\eta_0 \cdot 0.5^{3}$ |

> 关键观察：StepLR 在每个衰减点发生"跳变"，loss 曲线在衰减点处会出现一个 **台阶式下降**。

### 例子 2：中等 — 不同调度器的 PyTorch 实现与对比

```python
import torch
import torch.optim as optim
import matplotlib.pyplot as plt

total_epochs = 200
lr_records = {}

# StepLR
opt = optim.SGD([torch.nn.Parameter(torch.zeros(1))], lr=0.1)
sch = optim.lr_scheduler.StepLR(opt, step_size=50, gamma=0.5)
lr_records["StepLR (γ=0.5, S=50)"] = [
    (sch.step() or opt.param_groups[0]['lr']) for _ in range(total_epochs)]

# ExponentialLR
opt = optim.SGD([torch.nn.Parameter(torch.zeros(1))], lr=0.1)
sch = optim.lr_scheduler.ExponentialLR(opt, gamma=0.98)
lr_records["ExponentialLR (γ=0.98)"] = [
    (sch.step() or opt.param_groups[0]['lr']) for _ in range(total_epochs)]

# CosineAnnealing
opt = optim.SGD([torch.nn.Parameter(torch.zeros(1))], lr=0.1)
sch = optim.lr_scheduler.CosineAnnealingLR(opt, T_max=total_epochs, eta_min=0)
lr_records["CosineAnnealing"] = [
    (sch.step() or opt.param_groups[0]['lr']) for _ in range(total_epochs)]

# CosineWarmRestarts
opt = optim.SGD([torch.nn.Parameter(torch.zeros(1))], lr=0.1)
sch = optim.lr_scheduler.CosineAnnealingWarmRestarts(
    opt, T_0=50, T_mult=2, eta_min=1e-6)
lr_records["CosineWarmRestarts"] = [
    (sch.step() or opt.param_groups[0]['lr']) for _ in range(total_epochs)]

# ReduceLROnPlateau
opt = optim.SGD([torch.nn.Parameter(torch.zeros(1))], lr=0.1)
sch = optim.lr_scheduler.ReduceLROnPlateau(opt, mode='min', factor=0.5, patience=20)
vals = [2.0 * 0.995**e * (1.01 if e % 30 == 0 else 1) for e in range(total_epochs)]
lr_records["ReduceLROnPlateau"] = [
    (sch.step(v) or opt.param_groups[0]['lr']) for v in vals]

# 绘图对比
fig, axes = plt.subplots(1, 5, figsize=(18, 3.5))
for ax, (name, lrs) in zip(axes, lr_records.items()):
    ax.plot(lrs, linewidth=1.5)
    ax.set_title(name, fontsize=9); ax.set_xlabel("Epoch"); ax.grid(True, alpha=0.3)
plt.tight_layout(); plt.show()
```

**效果对比总结**：

| 调度器 | 曲线形态 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **StepLR** | 阶梯式跳变 | 简单可控，经典 baseline | 跳变点敏感，需要手动设 milestones |
| **ExponentialLR** | 平滑指数衰减 | 连续衰减，无需预设跳变点 | 衰减速度固定，后期降太快 |
| **CosineAnnealing** | 平滑余弦衰减 | 前期保持→中期加速→后期精细 | 需要预设 T_max，无法动态调整 |
| **CosineWarmRestarts** | 周期性重启 | 可跳出局部最优，支持快照集成 | 周期设计需经验 |
| **ReduceLROnPlateau** | 触发式阶梯 | 自适应，不需预设训练时长 | 反应滞后，可能错过最佳衰减时机 |

### 例子 3：实际应用 — ImageNet 训练完整管线

```python
import torch
import torch.nn as nn
import torchvision.models as models
from torch.optim.lr_scheduler import (
    LinearLR, CosineAnnealingLR, SequentialLR
)

# === 标准 ImageNet 训练配置 ===
model = models.resnet50(num_classes=1000)
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.1,              # base_lr
    momentum=0.9,
    weight_decay=1e-4
)

total_epochs = 200
warmup_epochs = 5
steps_per_epoch = len(train_loader)  # ~5000 for ImageNet

# === Warmup + Cosine 组合（SOTA 标配）===
warmup_scheduler = LinearLR(
    optimizer,
    start_factor=1e-3,   # 从 0.0001 开始
    total_iters=warmup_epochs * steps_per_epoch
)
main_scheduler = CosineAnnealingLR(
    optimizer,
    T_max=(total_epochs - warmup_epochs) * steps_per_epoch,
    eta_min=1e-5
)
scheduler = SequentialLR(
    optimizer,
    schedulers=[warmup_scheduler, main_scheduler],
    milestones=[warmup_epochs * steps_per_epoch]
)

# === 训练循环 ===
for epoch in range(total_epochs):
    model.train()
    for batch_idx, (images, labels) in enumerate(train_loader):
        images, labels = images.cuda(), labels.cuda()

        optimizer.zero_grad()
        outputs = model(images)
        loss = criterion(outputs, labels)
        loss.backward()
        optimizer.step()
        scheduler.step()  # ⚠️ 每个 iteration 调用一次

    # 验证阶段...
    val_loss = validate(model, val_loader)
    print(f"Epoch {epoch}: LR={scheduler.get_last_lr()[0]:.6f}, "
          f"Val Loss={val_loss:.4f}")

print("训练完成！最终 LR:", scheduler.get_last_lr()[0])
```

## 8. 常见误区和易混概念

### 误区 1：Adam 不需要学习率调度

- **错误直觉**："Adam 自带自适应学习率，固定 LR 就够了。"
- **为什么错**：Adam 的自适应机制（$1/\sqrt{\hat{v}_t}$）确实让每个参数有独立的学习率缩放，但这并不能替代全局的 LR 衰减。大量实验表明，即使使用 Adam/AdamW，加上 Cosine Annealing 依然能带来约 1~3% 的精度提升。特别地，Adam 在训练后期依然需要降低全局 LR 来精细收敛。而且 Adam **必须加 Warmup**（见误区 3）。
- **正确做法**：Adam + Cosine Annealing + Linear Warmup ≈ 当前最稳的组合。

### 误区 2：`scheduler.step()` 在每个 batch 调用还是每个 epoch 调用都行

- **错误直觉**："随便放哪，反正都是衰减。"
- **为什么错**：这取决于你在调度哪个量——如果按 epoch 调度（StepLR, CosineAnnealing），每个 epoch 调用一次；如果按 iteration 调度（OneCycleLR, Warmup），每个 batch 调用一次。**混用会导致 LR 衰减速度偏差数十倍甚至数百倍**。
- **正确做法**：
  - 按 epoch：`scheduler.step()` 放在 epoch 循环末尾
  - 按 iteration：`scheduler.step()` 放在 batch 循环内部
  - ReduceLROnPlateau：`scheduler.step(val_loss)` 放在每个 epoch 验证后

### 误区 3：Warmup 只是一个可选的 Trick

- **错误直觉**："不加 Warmup 也能训练，只是收敛慢一点。"
- **为什么错**：对于 Transformer 架构，不加 Warmup 可能根本**无法收敛**。在 BERT/GPT/ViT 等模型的预训练中，缺少 Warmup 几乎必然导致训练初期 loss 变成 NaN 或模型严重次优。这不是经验 tweak，而是架构级别的硬性要求。即使对于 CNN，Warmup 也能显著提升大 batch size（如 8192+）训练的稳定性。
- **正确做法**：Transformer 训练必须加 Warmup（通常 4000~10000 steps）；CNN 大 batch 训练强烈建议加。

### 误区 4：学习率越小最终精度越高

- **错误直觉**："LR 小一点总没错，慢慢训总比训炸好。"
- **为什么错**：过小的 LR 不仅拖慢训练，更严重的是会让模型陷入**尖锐的局部最优**（sharp minima），泛化能力反而更差。相反，适当的大 LR 会将模型推向**平坦的局部最优**（flat minima），泛化更好——这也是 OneCycleLR 用极大峰值 LR 的理论依据。
- **正确做法**：学习率不是"越小越好"，而是"在稳定训练的前提下尽量大"。

### 概念对比表

| 调度策略 | 衰减方式 | 是否依赖验证集 | 是否预设总步数 | 最佳场景 |
| :--- | :--- | :--- | :--- | :--- |
| **StepLR** | 阶梯跳变 | ❌ | ❌ | ResNet 经典 baseline |
| **Cosine** | 平滑余弦 | ❌ | ✅ | CV 分类/分割 SOTA 标配 |
| **ExponentialLR** | 连续指数 | ❌ | ❌ | 快速原型 |
| **ReduceLROnPlateau** | 自适应阶梯 | ✅ | ❌ | 训练时长不确定的任务 |
| **OneCycleLR** | 先升后降 | ❌ | ✅ | 追求泛化 + 快速训练 |
| **Warmup** | 线性/余弦上升 | ❌ | ✅ | Transformer 刚需 |

### 题目与解析

#### 1. 学习率调度的根本目的是什么？

- A. 让学习率始终保持不变，稳定训练
- B. 让学习率在训练过程中从较大值逐渐减小，实现"先探索后收敛"
- C. 让学习率与 batch size 保持正比关系
- D. 完全替代优化器的动量机制

> [!question]- 答案解析
> - **答案**：B
> - **解析**：前期大 LR 快速探索参数空间，后期小 LR 精细收敛到最优解。A 与调度的定义矛盾。C 描述的是 Linear Scaling Rule（与 batch size 的关系），不是调度的根本目的。D 错误，动量机制与调度是互补关系。
> - **对应章节**：§1, §2。

#### 2. Cosine Annealing 的完整公式是 $\eta_t = \eta_{\min} + \frac{1}{2}(\eta_0 - \eta_{\min})\left(1 + \cos\left(\frac{?}{T_{\max}} \cdot \pi\right)\right)$，问号处应填入：

- A. $T_{\max} - t$
- B. $t^2$
- C. $t$
- D. $\sqrt{t}$

> [!question]- 答案解析
> - **答案**：C
> - **解析**：余弦退火公式中，自变量是当前步数 $t$。当 $t=0$ 时 $\cos(0)=1$，$\eta_0$ 取最大值；当 $t=T_{\max}$ 时 $\cos(\pi)=-1$，$\eta_t$ 取 $\eta_{\min}$。
> - **对应章节**：§5.4。

#### 3. 以下场景最适合使用哪种调度器？

- 场景 1：ResNet-50 在 ImageNet 上训练 200 epochs，追求 SOTA 精度
- 场景 2：未知数据集，不确定训练多久 loss 会收敛
- 场景 3：Transformer 预训练（ViT-B/16）

匹配选项：A. CosineAnnealingLR / B. ReduceLROnPlateau / C. CosineAnnealing + Linear Warmup

> [!question]- 答案解析
> - **答案**：场景1→A, 场景2→B, 场景3→C
> - **解析**：场景1已知总 epochs=200，Cosine 是最佳选择；场景2未知训练时长，ReduceLROnPlateau 自适应触发最合适；场景3为 Transformer，Warmup 是刚需，Cosine 是主流衰减方案。
> - **对应章节**：§5, §8 概念对比表。

#### 4. 关于 Transformer 训练中的 Warmup，以下哪项解释是**不正确**的？

- A. 训练初期 LayerNorm 的统计量不稳定，Warmup 给了 LN 适应时间
- B. 训练初期 Adam 的二阶动量 $v_t$ 估计不可靠，Warmup 用小 LR 等待 $v_t$ 积累
- C. Warmup 是为了让模型在训练初期充分"探索"不同的注意力模式
- D. 训练初期自注意力层的梯度方向信噪比极低，直接用大 LR 可能破坏参数

> [!question]- 答案解析
> - **答案**：C
> - **解析**：Warmup 用小 LR 正是**限制**探索（而非鼓励探索），因为大 LR 探索在初期会因梯度不可靠而导致灾难性后果。A 有一定道理但不是主因；B 和 D 是学术界的两个主流解释（Adam 动量不可靠 + 梯度信噪比低）。
> - **对应章节**：§5.6, §6.3。

#### 5. 【工程实践】下列代码中，`scheduler.step()` 的位置是否正确？

```python
for epoch in range(epochs):
    for batch in train_loader:
        loss = model(batch)
        loss.backward()
        optimizer.step()
        scheduler.step()  # 使用 CosineAnnealingLR(optimizer, T_max=epochs)
```

- A. 正确，CosineAnnealingLR 应该每个 batch 调用
- B. 错误，应该移到 epoch 循环末尾（每个 epoch 调用一次）
- C. 错误，应该移到 `optimizer.step()` 之前
- D. 错误，应该改为 `scheduler.step(loss)`

> [!question]- 答案解析
> - **答案**：B
> - **解析**：`CosineAnnealingLR` 的 `T_max=epochs` 表示以 epoch 为粒度调度，因此应每个 epoch 调用一次 `scheduler.step()`。放在 batch 循环内会导致 LR 在第一个 epoch 内就被衰减完毕（原本 200 个 epoch 的调度被压缩为 200 个 batch）。A 对于按 iteration 调度的 OneCycleLR 才是正确的。D 是 ReduceLROnPlateau 的调用方式。
> - **对应章节**：§8 误区 2。
