## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）** 
- **判断理由**：文本生成策略是所有生成式大语言模型（如 ChatGPT）与用户交互的最后一步。哪怕模型训练得再好，如果解码策略选错，生成的文本可能会不断重复、不知所云或者缺乏创造力。它是实际部署和应用大模型时必须掌握的调参基础。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：
> 语言模型在每一步都会输出词表中所有词的概率分布。但我们最终需要的是一段确定的文本。如何从这个概率分布中挑选出下一个词？如果每次都挑概率最大的词，生成的文本往往像机器人一样单调且容易陷入重复死循环；如果完全随机挑，又会胡言乱语。我们需要一种机制，在“确定性（连贯合理）”和“随机性（丰富多样）”之间找到最佳平衡。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：它是语言模型训练和实际部署推理之间的桥梁。不学它，就不知道怎么控制模型生成的结果。
- **实际应用场景**：在开发基于大模型的应用时，通过调整 Temperature、Top-p 等参数来控制 AI 的语气和创造力；在机器翻译场景中获取最准确的翻译结果。
- **高频题型/任务**：文本生成（开放域对话、故事生成）、序列到序列任务（机器翻译、摘要）。

---

## 3. 学它之前需要哪些前置知识？

最小必要背景（各 200 字以内）：

1. **[[语言模型 (Language Model)]]**：语言模型的核心任务是给定前文，预测下一个词的概率分布 $P(w_t | w_{1:t-1})$。
2. **[[Softmax 函数]]**：将模型输出的 logits（无界实数）转化为合法的概率分布，使得所有词的概率之和为 1。

## 4. 用直觉语言解释它

> «“这东西其实就像你在玩文字接龙游戏时的不同策略。”»

- **直觉类比/几何图像**：
  - **Greedy（贪心）**：每次只挑你脑海中最先冒出来（最有可能）的那个词。容易走进死胡同。
  - **Beam Search（束搜索）**：像下棋时往后多想几步，同时保留几条看起来都不错的句子主干，最后挑一条整句得分最高的。

> **Greedy vs Beam Search 树状展开对比**
> ```mermaid
> graph TD
>     subgraph Greedy Search
>         G_Root((Start)) -->|0.6| G_A((A))
>         G_Root -.->|0.4| G_B((B))
>         G_A -->|0.5| G_AA((A, A))
>         G_A -.->|0.2| G_AB((A, B))
>     end
>     
>     subgraph Beam Search k=2
>         B_Root((Start)) -->|0.6| B_A((A))
>         B_Root -->|0.4| B_B((B))
>         B_A -->|0.5| B_AA((A, A))
>         B_B -->|0.9| B_BB((B, B))
>     end
> ```
> *(Greedy 走 A 后错过 B->B 总体概率更大的支路；Beam Search 保留 k=2 个最优候选从而探索更优解)*
  - **Top-k / Top-p**：在备选词的池子里进行抽奖。为了防止抽到离谱的词，把概率太小的词剔除掉，然后在剩下的高概率词里随机抽。
  - **Temperature（温度）**：调节抽奖池子里概率差距的放大镜。温度高，大家概率差不多，抽奖更随机；温度低，概率高的词更突出，抽奖更保守。
- **为什么很自然**：人类在说话时，有时会下意识用最常用的词（贪心），有时又会为了生动而挑选稍微生僻一点的词（采样）。
- **一句话直觉本质**：控制从概率分布中选择下一个词时的“随机性与确定性的权衡”。

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
给定词汇表 $V$ 和上下文 $x_{<t}$，模型输出下一个词 $x_t$ 的概率分布 $P(x_t | x_{<t})$。生成策略即是一个从该分布中采样或选择 $x_t$ 的函数。

### 2. 核心公式与策略

1. **Greedy Decoding (贪心解码)**:
   $$x_t = \arg\max_{x \in V} P(x | x_{<t})$$
   - **Tensor Flow**: `Logits: [Batch, SeqLen, Vocab_size]` $\rightarrow$ 取当前步 `Logits[:, -1, :]` 得到 `[B, V]` $\rightarrow$ `argmax(dim=-1)` 得到 `[B, 1]`。

2. **Beam Search (束搜索)**:
   在每一步 $t$，保留当前得分最高的前 $k$（Beam Size）个序列。序列得分为对数概率之和：
   $$\text{Score}(x_{1:t}) = \sum_{i=1}^t \log P(x_i | x_{<i})$$
   - **Tensor Flow**: 在每一步中展开所有候选 `[B * k, V]` $\rightarrow$ 提取 `topk(dim=-1)` $\rightarrow$ 选出最优的 `Next Beams: [B, k]`。

3. **Temperature Scaling (温度缩放)**:
   在 Softmax 之前，将 logits 除以温度 $T$：
   $$P(x_i) = \frac{\exp(z_i / T)}{\sum_{j} \exp(z_j / T)}$$
   - $T = 1$：原始分布。
   - $T < 1$：分布变尖锐，更倾向于高概率词。
   - $T > 1$：分布变平缓，更均匀。
   - **Tensor Flow**: `Logits: [B, V]` $\rightarrow$ 逐元素除以 $T$ $\rightarrow$ `Softmax(dim=-1)` $\rightarrow$ 新 `Probs: [B, V]`。

4. **Top-k Sampling**:
   仅在概率最大的 $k$ 个词中进行采样，重新归一化这 $k$ 个词的概率。
   - **Tensor Flow**: `Logits: [B, V]` $\rightarrow$ 取 `topk` 找到阈值 $\rightarrow$ 小于阈值的值用 `torch.where` 设为 `-inf` $\rightarrow$ `Softmax(dim=-1)` 得到截断后的分布。

5. **Nucleus (Top-p) Sampling**:
   按概率从大到小排序，选取累积概率刚好超过阈值 $p$ 的最小词汇集合，在这个集合内重新归一化并采样。

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $V$ | 词汇表 | 集合 | 包含所有可能的词 |
| $x_t$ | 第 $t$ 步生成的词 | $x_t \in V$ | |
| $z_i$ | 模型输出的 logit | $\mathbb{R}$ | Softmax 前的原始分数 |
| $T$ | 温度参数 | $(0, \infty)$ | 控制分布平滑度 |
| $k$ | Beam size 或 Top-k 大小 | 正整数 | |
| $p$ | 累积概率阈值 | $(0, 1]$ | 通常在 0.9 左右 |

### 4. 常见变体与适用条件
- **适用条件**：机器翻译等要求准确的任务多用 Beam Search；开放式生成（聊天、写诗）多用 Top-p + Temperature。
- **限制条件**：Beam Search 在开放域生成中容易产生重复且平庸的文本；单纯的随机采样容易产生逻辑错误。

## 6. 推导思路和思想来源

- **最初困难**：直接使用贪心搜索，每一步的最优并不意味着全局最优（可能错过后续极高概率的词）。寻找全局最优需要穷举整个词汇表序列（复杂度 $|V|^L$），这在计算上是不可能的。
- **直接方法局限**：贪心容易陷入局部最优，穷举又太慢。
- **关键“转念”**：
  - **Beam Search**：采用启发式搜索，不穷举所有，但也不只看一个，而是保留 $k$ 个最有潜力的“种子”继续发展。
  - **采样方法**：对于开放式生成，完美的“概率最高”句子反而往往无聊（如“我不知道”）。引入截断随机采样（Top-k/Top-p），既保证了语法正确（过滤掉长尾低概率词），又增加了创造力。
- **推导主线与动机**：为了打破生成文本的单调性，同时不让随机性毁掉文本连贯性，逐步引入了截断（Top-k/p）和重塑分布（Temperature）的方法。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：假设词表 $V=\{A, B, C\}$，当前 logits 为 $[2.0, 1.0, 0.1]$，求不同 Temperature 下的概率分布。
- **解题思路与关键步骤**：
  - **$T=1.0$**：$\exp(2)=7.39, \exp(1)=2.72, \exp(0.1)=1.11$。总和 $11.22$。概率 $[0.66, 0.24, 0.10]$。
  - **$T=0.5$**：logits 变为 $[4.0, 2.0, 0.2]$。$\exp(4)=54.6, \exp(2)=7.39, \exp(0.2)=1.22$。概率 $[0.86, 0.12, 0.02]$。
  - **$T=2.0$**：logits 变为 $[1.0, 0.5, 0.05]$。概率 $[0.48, 0.29, 0.23]$。
- **最终答案**：温度越低，最高概率词 A 的概率越大（从 0.66 升至 0.86），分布更陡峭。
- **易错点**：计算 Softmax 时忘记先除以 $T$。

### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：理解 Top-p 采样。假设词汇按概率降序排列为 $w_1 (0.5), w_2 (0.3), w_3 (0.15), w_4 (0.05)$。设 $p=0.85$。
  - 累积概率：$w_1 \rightarrow 0.5$ (小于0.85)
  - 加 $w_2 \rightarrow 0.8$ (小于0.85)
  - 加 $w_3 \rightarrow 0.95$ (大于0.85，停止加入)
  - 候选集合为 $\{w_1, w_2, w_3\}$。
  - 重新归一化：将它们的概率除以总和 $0.95$。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：在调用 OpenAI API 或使用 HuggingFace `generate()` 方法时，通常将 `do_sample=True, top_p=0.9, temperature=0.7` 作为聊天机器人的标准参数组合，确保回答既有逻辑又不失风趣。

## 8. 常见误区和易混概念

### 误区 1：认为 Beam Search 总是能产生更好的文本
- **错误直觉**：既然束搜索找到了概率更高的句子，那它生成的文本就应该更自然、更好。
- **为什么错**：在开放式生成任务（如写故事）中，人类语言往往不遵循最高概率原则。“最高概率”的句子往往是极其通用且乏味的短句（如 "I don't know"）。
- **正确理解**：Beam Search 适合目标明确的任务（翻译、摘要），采样策略（Top-p/Temperature）更适合开放式任务。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| Top-k | 如何截断词表 | 固定取前 $k$ 个，无视概率分布的实际长相（可能把好词漏掉或混入差词） | 早期的随机生成控制 |
| Top-p | 如何截断词表 | 动态确定候选数量，基于概率质量截断，适应不同平缓度的分布 | 当前主流的大模型文本生成 |
| Temperature | 如何改变概率分布 | 不截断词表，而是放大或缩小已有概率的差距 | 配合 Top-p 使用，控制“创造力”大小 |

### 题目与解析

#### 1. 为什么机器翻译更适合用 Beam Search，而对话生成更适合 Top-p 采样？
> [!question]- 答案与解析（复盘阶段查看）
> - **答案**：机器翻译有唯一的或有限个“标准答案”，其目标是寻找最忠实原文的最高概率序列；而对话生成是开放式的，需要多样性和创造力，不断输出“高概率但平庸”的回答会让人觉得乏味。
> - **解析**：通过具体场景体会解码目标的不同——寻找极值 vs. 从合理分布中采样。

#### 2. 当 Temperature $T \rightarrow 0$ 时，采样策略退化为了什么策略？
> [!question]- 答案与解析（复盘阶段查看）
> - **答案**：退化为 Greedy Decoding (贪心解码)。
> - **解析**：当 $T$ 趋于 0，最大的 logit 被无限放大，其对应的 Softmax 概率趋近于 1，其他趋近于 0。此时从该分布采样等价于直接取最大值。

#### 3. 写一段简单的 Python 伪代码，实现 Top-k 过滤。
> [!question]- 答案与解析（复盘阶段查看）
> - **代码片段**：
```python
import torch

def top_k_logits(logits, k):
    # 找到第 k 大的值
    values, _ = torch.topk(logits, k)
    kth_value = values[:, -1].unsqueeze(-1)
    # 将小于该值的 logits 设为负无穷
    logits_filtered = torch.where(logits < kth_value, torch.tensor(float('-inf')), logits)
    return logits_filtered
```

#### 4. 在 Top-p 采样中，如果当前概率分布为 [0.1, 0.6, 0.2, 0.1]，p=0.75，最后候选集包含哪些词？
> [!question]- 答案与解析（复盘阶段查看）
> - **答案**：包含概率为 0.6 和 0.2 的这两个词。
> - **解析**：先排序 [0.6, 0.2, 0.1, 0.1]。累积：0.6 -> 0.8。因为加入 0.2 时累积达到 0.8，超过了 0.75，所以截断，只保留前两个。

#### 5. 什么是 Beam Search 的长度惩罚（Length Penalty），为什么要引入它？
> [!question]- 答案与解析（复盘阶段查看）
> - **答案**：长度惩罚是指在计算序列得分时，除以序列长度的一个函数（如 $L^\alpha$）。
> - **解析**：因为序列概率是各个词的概率连乘，由于概率均小于 1，序列越长得分必然越低。如果不加惩罚，Beam Search 会倾向于输出极短的句子。加入惩罚项可以鼓励模型生成适当长度的完整句子。
