# 问答系统
---
## 0. 先判断它值不值得深挖
- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：问答（QA）是 NLP 的"终极任务"之一，融合检索、阅读理解与生成；SQuAD 是 BERT 论文的验证基准，[[项目-文档问答]] 直接落地；面试必考"抽取式 vs 生成式 QA""SQuAD 的 EM/F1""RAG 怎么衔接 QA"。LLM 时代 QA = RAG + 生成，是 [[检索增强生成RAG]] 卡的自然延伸。
---
## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> 用户问"珠穆朗玛峰多高？"，需要从知识（文档/网页/数据库）里找到并组织答案。传统搜索只给"文档列表"，用户还得自己读；纯生成式 LLM 会"自信地编造"（幻觉），因为它不检索。
> 问答系统的回答：**按答案来源分三类**——① **抽取式 QA**：给定文档与问题，从文档中"圈出"答案片段（BERT 输出起始/结束位置，SQuAD 基准）；② **生成式 QA**：模型根据上下文"写出"答案（abstractive，可概括/改写）；③ **开放域 QA**：先检索（BM25/向量检索）再阅读理解/生成——这就是 [[检索增强生成RAG]] 的标准管线：检索器召回候选文档，阅读器在候选中定位/生成答案。
---
## 2. 为什么它重要？它有什么用？
- **连接大图景**：QA 是 [[BERT及其变体]] 的成名战场（SQuAD 2.0 超越人类）、[[检索增强生成RAG]] 的核心下游、[[项目-文档问答]] 的产品形态；它与 [[信息抽取]]（实体检索）、[[对话系统]]（多轮问答）交织。
- **实际应用场景**：文档问答机器人、搜索引擎的"直接回答"框、知识库问答（KBQA）、客服自助查询、企业知识助手。
- **高频题型/任务**：面试"抽取式 QA 的模型结构（start/end logits）""EM 和 F1 怎么算""开放域 QA 的 two-stage 流程""RAG 与微调怎么选"。

## 4. 用直觉语言解释它
> «"问答系统像'图书馆里的答题员'：抽取式 QA 是'划线员'——它把问题在文档里对应的答案用红笔圈出来（模型预测'答案从第 3 个词开始、到第 7 个词结束'，即 start/end 两个位置）；生成式 QA 是'总结员'——读完材料用自己的话回答（能概括，但也可能自由发挥）；开放域 QA 是'先找书再划线'——面对整个图书馆，先用检索器快速筛出可能藏着答案的几本书（召回），再让阅读器在其中精确划线。RAG 就是这个流程的工程化：检索器（向量/BM25）→ 阅读器（BERT/LLM）→ 带来源的答案。"»
- **直觉类比/几何图像**：抽取式 = 在序列上做"起点-终点"两段分类（span prediction）；开放域 = 漏斗：全库 → top-k 文档 → 答案片段。
- **为什么很自然**：人类查资料也是"先定位来源，再细读提取"——检索 + 阅读的两阶段是人类认知的镜像。
- **一句话直觉本质**：**"QA = 从知识源到答案的映射：抽取式做 span 定位（start/end），生成式做条件生成，开放域加检索器做召回；评测用 EM/F1（SQuAD）与人工/LLM 打分，LLM 时代用 RAG 缝合检索与生成。"**
---
## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
**抽取式 QA（SQuAD 范式）**：输入问题 $q$ 与段落 $p$（token 化后拼接），BERT 输出每个 token 的 start/end logits，预测答案片段 $[i^*, j^*]$。
**生成式 QA**：$P(a|q, c) = \prod_t P(a_t|a_{<t}, q, c)$，$c$ 为上下文。
**开放域 QA**：检索器 $R(q)$ 召回 top-k 文档 → 阅读器 $A(q, R(q))$ 产出答案。
### 2. 核心公式
**抽取式 span 预测**：
$$P_{\text{start}}(i) = \text{softmax}(W_s h_i), \quad P_{\text{end}}(j) = \text{softmax}(W_e h_j), \qquad \hat{a} = \arg\max_{i\leq j} P_{\text{start}}(i)\cdot P_{\text{end}}(j)$$
**EM / F1**：
$$\text{EM} = \mathbb{1}[\hat{a} = a^*], \qquad \text{F1} = \frac{2\cdot\text{Precision}\cdot\text{Recall}}{\text{Precision}+\text{Recall}} \ (\text{token 级})$$
### 3. 符号说明表
| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $q, p$ | 问题/段落 | 文本 | 输入 |
| $h_i$ | 第 $i$ token 的 BERT 向量 | $\mathbb{R}^d$ | 编码器输出 |
| $W_s, W_e$ | start/end 分类头 | $\mathbb{R}^{1\times d}$ | 可学习 |
| $i^*, j^*$ | 答案起止位置 | $1\leq i\leq j\leq n$ | 预测目标 |
| $a^*$ | 标准答案 | 文本 | SQuAD 标注 |
| $k$ | 检索文档数 | 3-20 | RAG 召回量 |
### 4. 常见变体与适用条件
- **抽取式**：答案必须在原文中（SQuAD 1.1）；SQuAD 2.0 加"无答案"类（需 [CLS] 判断）。
- **生成式**：可概括/改写（如对话式 QA、多文档综合）；有幻觉风险，需引用约束。
- **检索式 + 阅读**：BM25（稀疏、快、可解释）+ BERT（精读）；向量检索（稠密、语义）；混合检索（工业标准）。
- **KBQA**：把问题转成知识图谱查询（SPARQL），结构化精确。
- **限制条件**：多跳推理（跨文档综合）难；长文档定位弱；评估自动化指标与人类判断有差距。

## 6. 推导思路和思想来源
- **最初困难**：QA 需要"理解 + 定位"，早期做法（信息检索 + 人工规则）只返回文档，无法给答案片段。
- **直接方法局限**：基于特征的单任务模型（SQuAD 之前的 pipeline）泛化差；seq2seq 生成答案缺乏可验证性（无来源）。
- **关键"转念"**：① 把"找答案"转成"找起止位置"：阅读理解 = 序列上的两段分类（start/end pointer，Wang & Jiang 2016），配合 BERT 双向表示一举超越人类（Devlin 2019 SQuAD 2.0）；② 开放域 = 两阶段漏斗：检索（BM25/向量）召回 + 阅读器精读，避免对全库建模；③ LLM 时代：生成式 + RAG 缝合——检索给"事实锚点"，生成给"自然表达"，引用约束防幻觉。
- **推导主线与动机**：检索（给文档）→ 抽取（给片段）→ 生成（给表述）→ RAG（给事实）：答案的"精确性-自然度"天平逐步平衡。
- **为什么自然得到此结论**：QA 的信息论本质 = "从大知识源中条件采样答案"，检索降复杂度、阅读提精度、生成提自然度——各司其职。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：段落 token 化后 BERT 输出 start 分数 [0.1, 0.8, 0.3, 0.2]（对应 词1..词4）、end 分数 [0.2, 0.4, 0.9, 0.1]。答案在 2-3 之间。计算 span 概率。
- **解题思路与关键步骤**：span(2,3) 概率 $=P_s(2)\cdot P_e(3)$（softmax 后相乘）；比较 span(2,2)、span(3,3)、span(2,3) 等合法组合。
- **最终答案**：softmax(start) = (0.19, 0.38, 0.23, 0.20)；softmax(end) = (0.18, 0.22, 0.36, 0.16)。span(2,3) = 0.38×0.36 = 0.137 最大 → 预测答案 = 词2到词3。
- **易错点**：忘记 softmax（直接用原始分数相乘）；允许 $i>j$ 的非法 span。
- **🤔 追问**：若要求"无答案"（SQuAD 2.0）？—— 加 [CLS] 的"无答案分数"，与最优 span 分数比较，无答案分高则回答"无法回答"。
### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：为什么开放域 QA 必须检索而不是把所有文档拼进上下文？—— ① 上下文窗口有限（几千 token，全库不可行）；② 检索把"从全库找"变成"从 top-k 找"，复杂度与噪声骤降；③ 检索相关性本身是可审计证据（来源引用）。这也解释了 RAG 为什么是开放域 QA 的标准范式。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：RAG 问答管线（[[项目-文档问答]] 的骨架）：
```python
from transformers import pipeline
from sentence_transformers import SentenceTransformer
import numpy as np

docs = ["珠穆朗玛峰高 8848.86 米。", "长江全长约 6300 公里。", ...]
model = SentenceTransformer("BAAI/bge-small-zh-v1.5")
emb = model.encode(docs)

def answer(question, k=2):
    qv = model.encode([question])
    idx = np.argsort(emb @ qv.T, axis=0)[-k:].flatten()[::-1]   # 检索 top-k
    ctx = " ".join(docs[i] for i in idx)
    qa = pipeline("question-answering", model="uer/roberta-base-chinese-extractive-qa")
    return qa(question=question, context=ctx)["answer"]          # 抽取式阅读器

print(answer("珠穆朗玛峰有多高？"))   # 8848.86 米
```

## 8. 常见误区和易混概念
### 误区 1：以为"抽取式 QA 和文本分类一样，输出一个标签"
- **错误直觉**：答案就是一个类别。
- **为什么错**：抽取式输出的是**连续 span 的起止位置**（两个指针），答案长度可变、内容来自原文；SQuAD 的 EM 要求逐 token 精确匹配，比分类严格得多。
- **正确理解**：抽取式 = 序列上的"双指针回归"（start/end），本质是结构化预测。
### 误区 2：以为"生成式 QA 一定比抽取式好"
- **错误直觉**：能自由生成当然更强。
- **为什么错**：生成式有幻觉风险、无来源可查；抽取式答案 100% 来自证据文本，可验证、可审计。事实性要求高的场景（医疗/法律）抽取式或"抽取+引用"更稳。
- **正确理解**：抽取保证忠实，生成保证自然——工业方案常"抽取式定位 + 生成式润色"组合。
### 概念对比表
| 概念 | 答案来源 | 输出 | 评测 | 典型场景 |
| :--- | :--- | :--- | :--- | :--- |
| 抽取式 QA（本概念） | 原文 span | 起止位置 | EM/F1 | SQuAD、文档问答 |
| 生成式 QA | 模型生成 | 自由文本 | 人工/ROUGE | 对话式问答 |
| 开放域 QA | 检索+阅读 | 片段/文本 | EM/F1 | 搜索引擎 |
| KBQA | 知识图谱 | 结构化查询 | 准确率 | 企业知识库 |

## 11. 自测题：5 道
| 题号 | 类型 | 难度 | 考查点 |
| :--- | :--- | :--- | :--- |
| 1 | 概念辨析 | 基础 | 三类 QA 的区别 |
| 2 | 公式运用 | 基础 | span 概率手算 |
| 3 | 条件判断 | 中等 | SQuAD 2.0 的无答案处理 |
| 4 | 变式/综合 | 中等 | EM/F1 计算 |
| 5 | 开放/证明/建模 | 较难 | 设计多跳 QA 方案 |
### 题目与解析
#### 1. 抽取式、生成式、开放域 QA 的区别？
> [!question]- 答案解析
> - **答案**：抽取式：从给定文档圈出答案 span（起止位置）；生成式：根据上下文自由生成（可概括）；开放域：先检索再抽取/生成（不限定单文档）。
> - **解析**：忠实度：抽取 > 开放域（有来源）> 生成；自然度反之。`#自测题/基础`
#### 2. start softmax=(0.1,0.7,0.2)，end softmax=(0.2,0.3,0.5)（3 token），求最优合法 span。
> [!question]- 答案解析
> - **答案**：span(1,1)=0.1×0.2=0.02；span(1,2)=0.1×0.3=0.03；span(1,3)=0.1×0.5=0.05；span(2,2)=0.7×0.3=0.21；span(2,3)=0.7×0.5=0.35；span(3,3)=0.2×0.5=0.10。最优 = span(2,3)。
> - **解析**：只枚举 $i\leq j$ 的合法组合；span(2,3) 0.35 最大。`#自测题/基础`
#### 3. SQuAD 2.0 与 1.1 的区别？模型如何输出"无答案"？
> [!question]- 答案解析
> - **答案**：2.0 加入"问题在文中无答案"的样本（约 1/3）。模型在 [CLS] 上加"无答案分数"，与最优 span 分数比较：无答案分更高则回答"无法回答"（或空）。
> - **解析**：这训练模型"拒答"能力，防止强行圈无关片段；也是幻觉缓解的一种范式。`#自测题/中等`
#### 4. 标准答案 "北京 是 中国 首都"，预测 "北京 是 中国"，计算 EM 与 F1（token 级）。
> [!question]- 答案解析
> - **答案**：EM=0（不完全匹配）。精确率=3/3=1，召回率=3/4=0.75，F1=2×1×0.75/(1+0.75)≈0.857。
> - **解析**：EM 严苛（全对才 1），F1 容忍部分重叠——SQuAD 两者都报，F1 是主要排序指标。`#自测题/中等`
#### 5. 设计"多跳问答"（答案需综合两篇文档）的 RAG 方案。
> [!question]- 答案解析
> - **答案**：① 迭代检索：先用初始问题检索，从首轮文档中提取"中间线索"（实体/子问题），再带着线索二次检索（IRCoT 风格）；② 子问题分解：LLM 把复杂问题拆成可单跳回答的子问题，逐个检索回答后综合；③ 图检索：把文档/实体建成图，沿关系跳转扩展；④ 综合生成：把所有跳的证据拼进上下文，要求分步引用。
> - **解析**：单次检索只能覆盖单跳；多跳的关键是"用中间答案指导下一跳检索"，这也是开放域 QA 的前沿难点。`#自测题/较难`
