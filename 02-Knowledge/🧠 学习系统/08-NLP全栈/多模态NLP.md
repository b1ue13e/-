# 多模态NLP
---
## 0. 先判断它值不值得深挖
- **类别**：**B 类（常用工具）**
- **判断理由**：图文对齐（CLIP）与多模态指令微调（LLaVA）是 2022 年后最热的方向，[[项目-多模态搜索]] 直接依赖；面试高频"CLIP 的对比学习目标""图文检索怎么做""LLaVA 怎么把视觉喂给 LLM"。掌握 CLIP + LLaVA 两条主线即可覆盖 80% 的多模态面试题。
---
## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> 传统 CV 模型看不懂文字，NLP 模型看不懂图片：想实现"搜图（输入文字找图）""看图说话""根据图片回答问题"，两个单模态模型拼不起来——它们没有共享空间。
> 多模态 NLP 的回答：**让文本和图像进入同一表示空间**——① **对齐派**（CLIP/BLIP）：用对比学习把"配对的图文"拉到向量空间近处、不配对的推远，得到通用图文编码器；② **融合派**（LLaVA/多模态 LLM）：把图像变成"视觉 token"（图像 patch 的向量），拼进 LLM 的输入序列，让 LLM 直接"看图说话"（多模态指令微调）。
---
## 2. 为什么它重要？它有什么用？
- **连接大图景**：CLIP 的对比学习是 [[文本表示方法]] 的跨模态延伸；LLaVA 是 [[GPT系列]] 的"长眼睛"版本；[[项目-多模态搜索]] 直接建在图文对齐之上。
- **实际应用场景**：文搜图/图搜文（电商、图库）、零样本图像分类（CLIP 提示分类）、视觉问答 VQA、图文生成（Stable Diffusion 用 CLIP 文本编码器）、多模态 Agent（看图操作）。
- **高频题型/任务**：面试"CLIP 的损失函数""对比学习为什么用 InfoNCE""LLaVA 的 projector 是什么""图文检索的评估（Recall@K）"。
---

## 4. 用直觉语言解释它
> «"CLIP 像一个'跨国婚介所'：它不看脸（不生成），只做匹配——把 4 万张图片和 4 万句描述两两打分，训练目标是'原配分数最高、别人家分数低'（对比学习）。练好后，任何图片和任何文字都能在同一个'爱琴海'（共享向量空间）里比距离。LLaVA 则更进一步：它把图片切成小块（patch），每块翻译成一个'视觉单词'（projector 把图像向量映射成 LLM 认识的词向量），然后直接拼在文字前面喂给 LLM——LLM 从此'睁开了眼'，能看图聊天。"»
- **直觉类比/几何图像**：对比学习 = 拉近正对（配对图文）、推开负对（batch 内其他图文）；InfoNCE = 在"找出 batch 里的原配"任务上做 softmax 分类。
- **为什么很自然**：互联网上海量"图片-alt 文本"天然配对，自监督信号免费；对比学习是"判别式"的，比生成式重建图像便宜得多。
- **一句话直觉本质**：**"对齐派用对比学习把图文编码进同一空间（CLIP），融合派用视觉 token 投影把图像接入 LLM（LLaVA）——两条路都让'语言理解视觉'成为可能。"**
---
## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
**CLIP（Radford et al. 2021）**：图像编码器 $f$ 与文本编码器 $g$，对 batch 内 $N$ 对图文计算相似度矩阵 $S_{ij} = f(I_i)\cdot g(T_j)$，目标：对角元素最大（InfoNCE 对称形式）。
**LLaVA（Liu et al. 2023）**：视觉编码器（CLIP ViT）→ 线性投影（projector）→ 视觉 token 拼入 LLM 输入；用"图像+指令→回答"数据做指令微调。
### 2. 核心公式
**CLIP 对比损失**（对称交叉熵，温度 $\tau$）：
$$\mathcal{L} = -\frac{1}{N}\sum_{i=1}^{N}\log\frac{\exp(S_{ii}/\tau)}{\sum_{j=1}^{N}\exp(S_{ij}/\tau)} - \frac{1}{N}\sum_{j=1}^{N}\log\frac{\exp(S_{jj}/\tau)}{\sum_{i=1}^{N}\exp(S_{ij}/\tau)}$$
**LLaVA 前向**：$H_v = W_p \cdot \text{ViT}(I)$（投影），输入 $[H_v; E_{q}]$ 给 LLM 生成回答。
### 3. 符号说明表
| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $f(I)$ | 图像向量 | $\mathbb{R}^d$ | 归一化后 |
| $g(T)$ | 文本向量 | $\mathbb{R}^d$ | 同一空间 |
| $S_{ij}$ | 图文相似度 | $\mathbb{R}$ | 内积 |
| $\tau$ | 温度系数 | $>0$ | 控制锐度 |
| $W_p$ | 投影矩阵 | $\mathbb{R}^{d_{\text{llm}}\times d_v}$ | projector |
| $H_v$ | 视觉 token | 序列 | 喂给 LLM |
### 4. 常见变体与适用条件
- **CLIP 家族**：SigLIP（sigmoid 损失，更稳）、EVA-CLIP；用于检索/零样本分类/特征提取。
- **BLIP/BLIP-2**：图文理解 + 生成（ITC/ITM/ITG 三目标；Q-Former 桥接冻结视觉与冻结 LLM）。
- **LLaVA 家族**：LLaVA-1.5/1.6、Qwen-VL、InternVL；用于 VQA、图表理解、多模态对话。
- **限制条件**：CLIP 对细粒度属性（数量、颜色组合）仍弱；多模态 LLM 幻觉（看图编造不存在物体）；训练数据质量决定对齐质量。
---
## 6. 推导思路和思想来源
- **最初困难**：图像与文本异构，没有天然的统一表示；人工标注图文对（对齐、描述）昂贵。
- **直接方法局限**：早期 VQA 用 CNN+RNN 拼接，只在任务内对齐、无通用性；生成式重建图像（VQ-VAE 类）训练贵且不稳定。
- **关键"转念"**：① 用**网页 alt-text 海量弱配对**当免费监督（CLIP 的数据观）；② 对比学习只要求"区分正负对"，比生成简单得多，且天然学到判别性表示；③ 大模型时代：不再训练新模型，而是**给 LLM 加视觉输入口**（projector 映射 + 指令微调）——复用语言知识，视觉只是"新的词表"。
- **推导主线与动机**：任务内对齐（拼接模型）→ 通用对齐（CLIP 对比学习）→ 生成式融合（BLIP）→ 指令跟随（LLaVA）；每步让"跨模态"更通用、更会生成。
- **为什么自然得到此结论**：语言是强先验（LLM 已懂世界），视觉信息只需"翻译"成语言可消费的形式——投影器就是"视觉-语言翻译官"。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：$N=2$，相似度矩阵 $S = \begin{pmatrix}0.9 & 0.2 \\ 0.3 & 0.8\end{pmatrix}$，$\tau=1$。计算图像方向的 InfoNCE 损失。
- **解题思路与关键步骤**：行 1：$\log\frac{e^{0.9}}{e^{0.9}+e^{0.2}} = \log\frac{2.46}{2.68}\approx-0.086$；行 2：$\log\frac{e^{0.8}}{e^{0.3}+e^{0.8}} = \log\frac{2.23}{2.58}\approx-0.145$；平均 $=(-0.086-0.145)/2\approx-0.115$。
- **最终答案**：图像方向损失 ≈ 0.115（nats）。加上文本方向对称项取平均即总损失。
- **易错点**：softmax 分母是整行（batch 内所有图文对）；忘记温度 $\tau$ 或未归一化向量。
- **🤔 追问**：若把对角改成 0.5/0.4？—— 损失升高（配对分不清），模型被迫拉近正对——这就是学习信号。
### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：为什么 CLIP 的 batch size 越大越好？—— 负对来自 batch 内其他样本；batch 越大负样本越多、任务越难、梯度越有信息量（InfoNCE 是"batch 内分类"）。这也是 CLIP 用 32768 大 batch 的原因；代价是显存与工程复杂度。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：零样本图文检索与分类，几行代码：
```python
from transformers import CLIPProcessor, CLIPModel
from PIL import Image

model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

image = Image.open("cat.jpg")
inputs = processor(text=["a photo of a cat", "a photo of a dog"],
                   images=image, return_tensors="pt")
probs = model(**inputs).logits_per_image.softmax(dim=1)
print(probs)   # 零样本分类：猫的概率最高
```

## 8. 常见误区和易混概念
### 误区 1：以为"CLIP 能识别图像中的任意细节"
- **错误直觉**：CLIP 什么都能看出来。
- **为什么错**：CLIP 学的是"图文整体对齐"（全局表征），对细粒度属性（"第三只猫的颜色"）、计数、空间关系弱；它是检索/分类器，不是检测/分割器。
- **正确理解**：CLIP 强在零样本类别与语义检索；细粒度任务需检测模型或多模态 LLM。
### 误区 2：以为"LLaVA 就是把 CLIP 和 LLM 简单拼接"
- **错误直觉**：接个投影层就能用。
- **为什么错**：需要两阶段训练：① 冻结视觉与 LLM，只训 projector（特征对齐）；② 解冻 LLM 做指令微调（行为对齐）；数据也要精心构造（图文对话对）。且 projector 的维度映射与 token 数（分辨率）都有讲究。
- **正确理解**：拼接是结构，两阶段训练才是能力来源。
### 概念对比表
| 概念 | 目标 | 结构 | 典型用途 |
| :--- | :--- | :--- | :--- |
| CLIP（本概念） | 图文对齐 | 双塔编码器 | 检索、零样本分类 |
| BLIP/BLIP-2 | 理解+生成 | 编码器+Q-Former+LLM | VQA、caption |
| LLaVA | 多模态对话 | ViT+projector+LLM | 看图问答 |
| 图文检索传统 | 匹配 | 特征+度量学习 | 搜索引擎 |

### 题目与解析
#### 1. CLIP、BLIP-2、LLaVA 各自的核心思路？
> [!question]- 答案解析
> - **答案**：CLIP：双塔对比学习做图文对齐（检索/分类）；BLIP-2：Q-Former 桥接冻结视觉编码器与冻结 LLM（理解+生成）；LLaVA：projector 把视觉 token 接入 LLM + 指令微调（多模态对话）。
> - **解析**：演进：对齐 → 生成 → 对话；复杂度与能力递增。`#自测题/基础`
#### 2. $N=2$，$S=\begin{pmatrix}0.9&0.2\\0.3&0.8\end{pmatrix}$，$\tau=1$，求图像方向 InfoNCE 损失。
> [!question]- 答案解析
> - **答案**：$-\frac{1}{2}[\log\frac{e^{0.9}}{e^{0.9}+e^{0.2}}+\log\frac{e^{0.8}}{e^{0.3}+e^{0.8}}]\approx0.115$ nats。
> - **解析**：每行是"图片 vs batch 内所有文本"的 softmax 分类；对角是正对。`#自测题/基础`
#### 3. 温度 $\tau$ 太小会怎样？batch 大小如何影响训练？
> [!question]- 答案解析
> - **答案**：$\tau\to0$ 时 softmax 变锐利（近似 one-hot），负样本梯度趋零、训练不稳定甚至塌缩；$\tau$ 是可学习或调参的。batch 越大负对越多，任务越有判别力，但显存与 OOM 风险上升。
> - **解析**：温度控制"困难负样本"的利用程度；大 batch 是 CLIP 成功的工程前提。`#自测题/中等`
#### 4. 为什么 CLIP 在"数一数图里有几只猫"这类任务上会失败？
> [!question]- 答案解析
> - **答案**：CLIP 学全局图文对齐，对数量、属性组合、空间关系等细粒度信息不敏感（对比学习只要求"整体配对"）；且 alt-text 数据本身不含细粒度描述。
> - **解析**：细粒度需要检测/分割模型或多模态 LLM 的推理能力；CLIP 定位是"语义级匹配"。`#自测题/中等`
#### 5. 设计一个"看图操作网页"的多模态 Agent：视觉信息如何接入？
> [!question]- 答案解析
> - **答案**：方案：① 截图 → 视觉编码器（如 CLIP ViT）→ 投影成视觉 token → 多模态 LLM（如 Qwen-VL）理解界面；② Agent 循环：LLM 输出操作（点击/输入坐标）→ 工具执行 → 新截图作为下一轮视觉输入（类似 ReAct 但感知是图像）；③ 坐标需视觉模型输出定位（grounding 能力）或用"截图切块+OCR"辅助。
> - **解析**：这结合了 [[Agent与工具使用]] 的循环与多模态感知；关键难点是 grounding（把语言指令映射到像素坐标）。`#自测题/较难`
