# 信息抽取
---
## 0. 先判断它值不值得深挖
- **类别**：**B 类（常用工具）**
- **判断理由**：信息抽取（IE）是把非结构化文本变成结构化知识（实体/关系/事件）的核心技术，[[项目-知识图谱]] 的地基。NER 是序列标注的旗舰任务（与 [[序列标注]] 卡强关联）；关系/事件抽取是 [[问答系统]] 与 [[检索增强生成RAG]] 的上游。面试高频"BiLSTM-CRF 为什么好""NER 和关系抽取的范式差异"。
---
## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> 文本是"非结构化"的：一万篇新闻里"苹果发布新手机"，机器不知道"苹果"是公司、不知道它和"手机"有什么关系。人工建库成本不可接受。
> 信息抽取的回答：**从文本自动提取结构化三元组**——① **命名实体识别（NER）**：找出人名/地名/机构/时间（序列标注）；② **关系抽取（RE）**：判断实体间关系（如 收购/位于/出生于），输出 (头实体, 关系, 尾实体)；③ **事件抽取（EE）**：提取事件触发词与论元（谁在何时何地做了什么）。
---
## 2. 为什么它重要？它有什么用？
- **连接大图景**：NER 是 [[序列标注]] 的旗舰应用；抽取结果喂给 [[项目-知识图谱]]（三元组入库）、[[问答系统]]（结构化检索）、[[检索增强生成RAG]]（实体链接增强）。
- **实际应用场景**：知识图谱构建、金融/医疗文书结构化、舆情监控（谁骂了谁）、简历解析、客服工单自动分拣。
- **高频题型/任务**：面试"BIO 标注怎么标""BiLSTM-CRF 的 CRF 层解决什么""关系抽取的 pipeline vs 联合模型""基于 LM 的方法怎么做 NER"。
---
## 3. 学它之前需要哪些前置知识？
1. **[[序列标注]]**：BIO 标注、HMM/CRF、BiLSTM-CRF 是 NER 的直接武器。
2. **[[循环神经网络RNN]]**：BiLSTM 编码上下文的机制。
3. **[[BERT及其变体]]**：预训练 LM 做序列标注（token 级分类头）。
---
## 4. 用直觉语言解释它
> «"信息抽取像'给文本做结构化体检'：NER 是'圈出专有名词'（红笔圈人名、蓝笔圈地点——就像 BIO 标签给每个词贴 B-人名/I-人名/O）；关系抽取是'画箭头'（在苹果和库克之间画'CEO 是'）；事件抽取是'填事件表格'（谁、何时、何地、做了什么）。传统做法是流水线：先圈实体再画箭头；现代做法是端到端联合：一个模型同时干完。"»
- **直觉类比/几何图像**：BIO 标注 = 给词序列着色（B=块开始，I=块内部，O=块外）；CRF 层 = "标签合法性检查器"（B-PER 后面不能直接跟 B-LOC）。
- **为什么很自然**：实体是连续片段，用"开始-内部-外部"编码天然匹配；关系是实体对的结构，需要跨片段建模。
- **一句话直觉本质**：**IE = 从"词序列"到"结构化图"：NER 做节点识别（序列标注），RE 做边识别（实体对分类），EE 做事件模板填充；深度学习时代从 pipeline 走向联合建模。**
---
## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
**NER**：输入词序列 $w_1,\dots,w_n$，输出标签序列 $y_1,\dots,y_n$（BIO 标签），识别实体片段。
**关系抽取**：给定头尾实体 $(e_h, e_t)$ 与句子，预测关系 $r \in \mathcal{R} \cup \{\text{None}\}$。
**事件抽取**：识别触发词 $t$ 与论元角色填充 $(r_i, e_i)$。
### 2. 核心公式
**BiLSTM-CRF 打分**（BiLSTM 输出发射分数 $E$，CRF 加转移分数 $T$）：
$$s(x,y) = \sum_{i=1}^{n} E_{i,y_i} + \sum_{i=1}^{n-1} T_{y_i, y_{i+1}}, \qquad \hat{y} = \arg\max_{y} s(x,y)$$
**关系分类（基于 LM 的典型范式）**：把 (头实体, 尾实体) 标记进句子，取特殊 token 表示分类：
$$r = \arg\max_{r'} P(r' \mid [\text{CLS}], \text{sentence with } \langle e_h\rangle \dots \langle e_t\rangle)$$
### 3. 符号说明表
| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $y_i$ | 第 $i$ 词标签 | BIO 集合 | 如 B-PER/I-PER/O |
| $E_{i,y}$ | 发射分数 | $\mathbb{R}$ | BiLSTM 输出 |
| $T_{y,y'}$ | 转移分数 | $\mathbb{R}$ | CRF 可学习参数 |
| $e_h, e_t$ | 头/尾实体 | 文本片段 | RE 输入 |
| $r$ | 关系类型 | $\mathcal{R}$ | 预定义 schema |
### 4. 常见变体与适用条件
- **Pipeline 抽取**：NER → RE 顺序执行，模块复用性好，但错误传播。
- **联合抽取**：共享编码器同时预测实体与关系（如 CopyRE、CasRel），缓解错误传播。
- **基于 LM**：BERT + 序列标注头做 NER；标记实体 span 做 RE（PURE 等）；生成式 IE（把抽取当 seq2seq 生成，如 UIE）。
- **限制条件**：领域迁移难（金融 NER ≠ 医疗 NER）；长尾实体与嵌套实体（"北京大学人民医院"）仍是难点；关系 schema 需人工定义。

## 6. 推导思路和思想来源
- **最初困难**：规则抽取（正则+词典）精度高但召回低、不可迁移；实体/关系组合爆炸。
- **直接方法局限**：把 NER 当词分类（每词独立 softmax）会输出非法标签序列（B 后跟 I 属别的实体）。
- **关键"转念"**：① NER 是**结构化预测**：标签间有约束（BIO 依赖），用 CRF 建模标签转移（Lafferty 2001）；② 双向 RNN 补上下文（BiLSTM-CRF 成为 2015-2019 标准，Huang et al.）；③ 预训练时代直接 BERT+CRF，或干脆用生成模型输出结构化文本（UIE：用提示模板生成抽取结果）。
- **推导主线与动机**：规则 → 统计序列模型（HMM/CRF）→ 神经编码（BiLSTM-CRF）→ 预训练（BERT+头）→ 生成式（seq2seq IE）；每步用更强的编码/解码提升泛化。
- **为什么自然得到此结论**：任务结构（片段+标签约束+实体对）决定模型结构：序列约束用 CRF，跨实体依赖用联合模型。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：句子"马云在杭州创立了阿里巴巴"，写出 BIO 标注（PER=人，LOC=地，ORG=机构）。
- **解题思路与关键步骤**：马云=B-PER（I-PER 可省，单字人名）；杭州=B-LOC；创立=O；阿里巴巴=B-ORG。
- **最终答案**：马/B-PER 云/I-PER 在/O 杭/B-LOC 州/I-LOC 创/O 立/O 了/O 阿/B-ORG 里/I-ORG 巴/I-ORG 巴/I-ORG。
- **易错点**：实体内部词漏标 I（只标 B）；跨实体串标签（B-PER 后跟 I-LOC）。
- **🤔 追问**：若"杭州"出现两次、一次是地名一次是人名？—— 上下文决定，BiLSTM 的双向上下文正是为此。
### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：为什么 CRF 层比逐词 softmax 好？—— 逐词 softmax 无视标签约束：可能输出 "B-PER I-LOC I-PER" 这种非法序列。CRF 显式建模转移概率 $T_{y,y'}$（B-PER→I-LOC 转移分被学成很负），并对整条序列做全局归一化（softmax 是逐位置归一化）——预测的是"整条最优路径"而非"每点最优"。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HuggingFace + 预训练模型做 NER，几十行完成：
```python
from transformers import AutoTokenizer, AutoModelForTokenClassification, pipeline

model_name = "dslim/bert-base-NER"
nlp_ner = pipeline("token-classification", model=model_name,
                   tokenizer=AutoTokenizer.from_pretrained(model_name))
for ent in nlp_ner("Elon Musk founded Tesla in Palo Alto."):
    print(ent["word"], ent["entity"], round(ent["score"], 3))
# 输出示例: Elon B-PER 0.999 / Musk I-PER 0.999 / Tesla B-ORG ... / Palo B-LOC ...
```

## 8. 常见误区和易混概念
### 误区 1：以为"NER 就是词分类，每个词独立预测"
- **错误直觉**：softmax 逐词分类即可。
- **为什么错**：标签有序列依赖（BIO 语法），独立预测产生非法序列，且丢失片段级信息。
- **正确理解**：NER 是结构化预测，CRF/约束解码（Viterbi）是标配。
### 误区 2：以为"关系抽取必须两步走（先抽实体再判关系）"
- **错误直觉**：pipeline 是唯一方式。
- **为什么错**：pipeline 错误传播（实体错则关系必错），且无法利用关系对实体的约束。
- **正确理解**：联合模型（共享编码、实体与关系联合解码）和生成式方法在现代更常用。
### 概念对比表
| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| NER（本概念） | 找实体片段 | 序列标注 | 实体识别 |
| 关系抽取 | 实体间关系 | 实体对分类 | 知识图谱 |
| 事件抽取 | 事件结构与论元 | 触发词+角色填充 | 舆情、金融 |
| 序列标注 | 逐词打标签 | 通用框架 | POS/NER/分块 |

### 题目与解析
#### 1. 命名实体识别、关系抽取、事件抽取各自输出什么？
> [!question]- 答案解析
> - **答案**：NER → 实体片段与类型（词序列→BIO 标签）；RE → (头实体, 关系, 尾实体) 三元组；EE → 事件触发词 + 论元角色（谁/何时/何地/何事）。
> - **解析**：三者的信息粒度：实体 < 关系 < 事件，可流水线组合。`#自测题/基础`
#### 2. 给句子"李明毕业于清华大学"标注 BIO（PER/LOC/ORG）。
> [!question]- 答案解析
> - **答案**：李/B-PER 明/I-PER 毕/O 业/O 于/O 清/B-ORG 华/I-ORG 大/I-ORG 学/I-ORG。
> - **解析**：实体首词 B、内部 I、外部 O；连续实体间必须有 O 或新 B 分隔。`#自测题/基础`
#### 3. 只用 BiLSTM 逐词 softmax 做 NER 有什么问题？CRF 如何修复？
> [!question]- 答案解析
> - **答案**：逐词独立预测会输出非法标签序列（如 B-PER 后直接 I-LOC），且忽略标签间转移约束。CRF 加转移分数 $T_{y,y'}$ 并做整条序列归一化，Viterbi 解码保证全局最优合法序列。
> - **解析**：发射分数（BiLSTM）+ 转移分数（CRF）= 结构化预测标准配方。`#自测题/中等`
#### 4. Pipeline 抽取与联合抽取各自的优缺点？
> [!question]- 答案解析
> - **答案**：Pipeline：模块解耦、可单独替换/复用，但错误传播（实体错→关系错）且无法双向约束；联合：共享编码、联合解码，缓解错误传播、利用交叉信息，但训练复杂（需联合损失）、可解释性弱。
> - **解析**：工程快速迭代用 pipeline；追求上限用联合/生成式。`#自测题/中等`
#### 5. 如何解决嵌套实体（"北京大学人民医院" 同时是 ORG 和 LOC 内嵌）？
> [!question]- 答案解析
> - **答案**：① 超图/多标签 BIO（每层一个标注序列）；② 基于 span 的模型（枚举所有片段分类，天然支持嵌套）；③ 生成式（UIE：让模型生成嵌套结构文本）；④ 序列到序列 + 层次解码。
> - **解析**：扁平 BIO 只能表达一层嵌套；span 分类把"片段"当基本单元，是处理嵌套的主流方向。`#自测题/较难`
