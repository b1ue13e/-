# 文本预处理

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：预处理是所有 NLP 管线的第一环：HW01 的语料清洗、HW02 的 TF-IDF 特征、HW04 的 BPE、HW05 的 tokenizer——全部从这里开始。CS224N 讲义第一讲就讲 tokenization 与子词切分；预处理质量直接决定下游上限（"garbage in, garbage out"）。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：
> 原始文本是"脏"的：大小写混杂（"Apple" vs "apple"）、标点粘连（"hello,"）、URL/表情/HTML 标签、拼写变体（"color"/"colour"）、不同语言没有空格（中文"我爱自然语言处理"怎么切？）、新词层出不穷（"Transformer" 在 2017 年前不存在）。
> 直接把原始文本喂给模型会导致：词表爆炸（每种变体一个词）、OOV（未登录词）无法处理、特征稀疏、统计失效。因此需要一套标准化的**预处理管线**：规范化（normalization）→ 分词（tokenization）→ 子词切分（subword）→ 停用词/去噪——把"任意文本"变成"干净、可控、可统计的 token 序列"。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：预处理决定词表 $V$（HW01）、特征空间（HW02 的 BoW/TF-IDF）、tokenizer 的 BPE 训练（HW04/HF Course Ch.6）；[[词向量与Word2Vec]]、[[BERT及其变体]] 全部建立在 token 流之上。
- **实际应用场景**：任何 NLP 系统第一环：搜索索引、情感分析、机器翻译、LLM 的 tokenizer 训练（GPT-2 的 byte-level BPE）。
- **高频题型/任务**：HW01 的语料加载与词频统计；HF Course Ch.6 的"从零训练 BPE tokenizer"；面试问"为什么现代模型不用词级分词""BPE 的合并规则""中文分词的特殊性"。

1. **正则表达式**：规范化与分词的核心工具（`re` 模块：`\w+`、`re.sub`）。
2. **N-gram 与词频统计**：分词质量的评估与词表构建（见 [[02-传统NLP方法/N-gram定义|N-gram定义]]）。
3. **Python 字符串处理**：编码（UTF-8）、Unicode、大小写转换。

## 4. 用直觉语言解释它

> «"文本预处理就像'食材初加工'：买菜（原始文本）不能直接下锅——要去皮（去 HTML/URL）、切块（分词）、按菜品需求切丁切丝（词级或子词级）、挑掉坏的部分（去停用词/低频词）。不同菜品要求不同刀法：传统菜（BoW/TF-IDF）要切大块（词），现代菜（BERT/GPT）要切细丝（子词 BPE），这样无论多怪的食材（生僻词）都能下锅。"»

- **直觉类比/几何图像**：BPE 像"拼乐高"：先从字母/字符开始，反复把"最常一起出现的两片"粘成一片，直到达到目标词表大小——最后得到一堆"半成品积木"（子词），任何新词都能用它们拼出来。
- **为什么很自然**：词表要小（训练成本），覆盖要全（无 OOV），两者冲突——子词切分在"字符"和"词"之间取平衡，是信息论与工程约束的自然折中。
- **一句话直觉本质**：**用"规范化 + 分词 + 子词"三层管线，把任意原始文本变成词表可控、无 OOV、统计稳定的 token 序列。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
**预处理管线**：① **规范化**：统一大小写/Unicode、去噪声（URL/HTML/表情）、展开缩写；② **分词**：把文本切成 token（词级或子词级）；③ **子词切分**：用 BPE/WordPiece/Unigram 把词切成子词单元；④ **后处理**：停用词过滤（传统方法）、低频词裁剪、特殊 token 插入（[CLS]/[SEP]/[MASK]）。

### 2. 核心公式
**BPE（Byte Pair Encoding）合并规则**：反复合并语料中最频繁的相邻符号对：
$$(a, b)^* = \arg\max_{(a,b)} \text{count}(a, b) \quad \text{合并为} \quad ab$$
直到词表达到目标大小 $V_{\text{target}}$。

**WordPiece 合并准则**（BERT，按"合并后似然增益"选对）：
$$\text{score}(a,b) = \frac{\text{count}(ab)}{\text{count}(a)\cdot\text{count}(b)}$$

**切分后的词概率**（Unigram LM，Viterbi 解码）：
$$P(w) = \prod_{i} P(t_i), \qquad t^* = \arg\max_{t \in \text{segment}(w)} \prod_i P(t_i)$$

### 3. 符号说明表

| 符号/名称 | 含义 | 取值范围 | 备注 |
| :--- | :--- | :--- | :--- |
| $V$ | 词表大小 | 30k-100k（子词） | 词级可达数百万 |
| $(a,b)$ | 相邻符号对 | 字符或子词 | BPE 合并单元 |
| $\text{count}(\cdot)$ | 语料中频次 | 非负整数 | 预扫描一次 |
| `##` | WordPiece 续词标记 | 前缀符号 | "playing"→"play"+"##ing" |
| `<unk>` | 未登录词 token | 特殊 token | 子词后几乎不用 |

### 4. 常见变体与适用条件
- **词级分词**：英文空格切分 + 标点剥离；适合传统方法（BoW/TF-IDF）与词向量训练。
- **字符级**：无 OOV 但序列太长、语义碎片化；适合拼写敏感任务（罕见词语言）。
- **子词级（BPE/WordPiece/Unigram）**：现代模型标准；BPE 无监督、语言无关；WordPiece 带词频加权；Unigram 概率模型（SentencePiece 默认）。
- **中文分词**：无空格，需词典（jieba 正向最大匹配）或统计（HMM/CRF，见 [[02-传统NLP方法/统计分词|统计分词]]）或直接字符/子词（BERT 中文用字级 + 全词掩码）。
- **适用条件**：传统方法用词级+停用词；神经网络用子词级，**不要**去停用词（模型自己学权重）。

## 6. 推导思路和思想来源

- **最初困难**：词级词表太大（10 万+）、OOV 严重；字符级序列太长（信息密度低）。
- **直接方法局限**：固定词表无法覆盖新词（"COVID-19"、"chatGPT"）；把新词都加进词表则词表无限膨胀。
- **关键"转念"**（Sennrich et al., 2016 引入 BPE 到 NLP）：**用"训练语料统计出的合并规则"代替"人工词表"**——高频词（the, 的）整词保留，低频词拆成子词（"unbelievable"→"un"+"believ"+"able"），OOV 自然消失。合并规则本身是可逆的（编码/解码），训练一次永久使用。
- **推导主线与动机**：统计相邻对频次 → 贪心合并最高频对 → 重复至词表达标 → 用合并规则表切分任意文本；WordPiece 把"频次"换成"似然增益"；Unigram 把切分变成概率模型上的 Viterbi 解码。
- **为什么自然得到此结论**：这是数据压缩（BPE 源自 gzip 的 PPM 思想）与语言统计的相遇：语言中最常见的模式值得保留为整块，罕见模式分解为小块——最优编码的自然结果。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：语料只有两个词："low low low low low low low low low lower lowest newest newest newest newest newest newest newest newest newest"。目标词表 = 字符 + 2 个合并。演示 BPE 前两步。
- **解题思路与关键步骤**：统计相邻字符对：`lo` 出现 9+1+1+1=12 次（low×9, lower, lowest, newest 无 lo... 实际：low×9→"lo"×9，"ow"×9；lower→"lo","ow","we","er"；lowest→"lo","ow","we","es","st"；newest×9→"ne","ew","we","es","st"×9）。`we` 与 `es`、`st` 各 9 次，`lo` 最多（9+1+1=11 次? 数一下：low×9 中 lo 出现 9 次；lower 1 次；lowest 1 次 → 11 次）。合并 `lo` → `lo`（第一步）。第二步：重新统计，`low` 出现 9+1+1=11 次，`we` 10 次，`es`+`st` 10 次 → 合并 `low`。
- **最终答案**：词表变为 {l,o,w,e,r,s,t,n, lo, low}。
- **易错点**：合并后要**重新统计**（`lo`+`w` 变成 `low` 的频次来自新序列）；不要跨词合并。
- **🤔 追问**：为什么 "low" 而不是 "we" 先合并？—— 因为 `low` 出现 11 次 > `we` 10 次；频次驱动。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：同一段文本，词级分词与 BPE 分词后词表/序列长度如何变化？什么时候选哪个？
- **解题思路与完整解答**：词级：词表大（含全部变形）、序列短（每词 1 token）、OOV 存在；BPE：词表固定（30k）、序列略长（罕见词拆 2-4 个子词）、无 OOV。选择：传统统计方法（朴素贝叶斯/TF-IDF，HW02 前半）用词级（+停用词）；神经网络（HW03-05、LLM）用 BPE/WordPiece；多语言/低资源用 SentencePiece（Unigram）。中文任务直接字级或预训练中文 tokenizer。
- **易错点**：给神经网络模型也去停用词（丢失语法信息，模型可自己加权）；或给传统模型保留全部标点（特征爆炸）。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HF Course Ch.6 的 lab 就是"从零训练 BPE tokenizer 并在小语料上对比词级 vs 子词"。代码形态：
```python
import re, collections

def get_stats(vocab):                     # 统计相邻对频次
    pairs = collections.defaultdict(int)
    for word, freq in vocab.items():
        symbols = word.split()
        for i in range(len(symbols)-1):
            pairs[symbols[i], symbols[i+1]] += freq
    return pairs

def merge_vocab(pair, vocab):             # 合并最高频对
    v_out = {}
    bigram = re.escape(" ".join(pair))
    p = re.compile(r"(?<!\S)" + bigram + r"(?!\S)")
    for word in vocab:
        w_out = p.sub("".join(pair), word)
        v_out[w_out] = vocab[word]
    return v_out

# 使用：反复 get_stats → max(pairs) → merge_vocab，直到词表达标。
# 现代实践直接用 tokenizers 库：tokenizers.BPE 或 tokenizers.models.BPE
```

## 8. 常见误区和易混概念

### 误区 1：以为"预处理对神经网络不重要，模型能自己学"
- **错误直觉**：BERT 很强大，脏文本直接喂也没事。
- **为什么错**：tokenizer 是**训练时固定的**——训练语料没见过的格式（新 emoji、乱码、超长 URL）会被切得稀碎或产生大量无用 token；预训练模型有固定 max_length，超长文本截断会丢关键信息。
- **正确理解**：模型只能处理"tokenizer 能表达的文本"；预处理（清洗、截断策略、特殊 token 规范）决定模型看到什么。

### 误区 2：以为"BPE 分词和词级分词对同一文本结果差不多"
- **错误直觉**：反正都是切词。
- **为什么错**：BPE 会把 "unhappiness" 切成 "un"+"happiness"（或 "unhappi"+"ness"），词级是 1 个 token；低频词两者差异巨大，且 BPE 天然处理 OOV。序列长度与词表覆盖完全不同。
- **正确理解**：词级=离散符号表，子词级=可组合的符号系统（"乐高"）。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 文本预处理（本概念） | 原始文本→token | 规范化+分词+子词 | 一切 NLP 管线第一环 |
| 词级分词 | 空格/词典切分 | OOV 存在、词表大 | 传统方法、词向量 |

### 题目与解析

#### 1. "规范化（normalization）"和"分词（tokenization）"各解决什么问题？
> [!question]- 答案解析
> - **答案**：规范化统一文本的"表面形式"（大小写、Unicode、缩写、去 URL/HTML），让同一语义只有一种写法；分词把连续文本切成离散 token（词/子词），供词表与模型使用。
> - **解析**：先规范化再分词：规范化不改变 token 边界，但减少 token 变体（"Apple"/"apple" 归一后一个 token）；分词质量决定词表与 OOV。
> - **易错原因**：两者混淆——规范化是"清洗"，分词是"切分"。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 语料 {"low":9, "lower":1, "newest":10}（词：频次），目标词表=字符集+1 个合并，BPE 第一步合并哪对？
> [!question]- 答案解析
> - **答案**：统计相邻对：`lo`:9+1=10（low×9、lower×1），`ow`:10，`we`:1+10=11（lower、newest×10），`er`:1，`ne`:10，`es`:10，`st`:10。最高频是 `we`（11 次）→ 合并为 `we`。
> - **解析**：注意 `newest` 里的 `we` 贡献 10 次，`lower` 贡献 1 次，共 11 次 > `lo` 的 10 次。合并后词 "newest"→"ne"+"we"+"st"+"..."。
> - **易错原因**：只数第一个词的频次；漏掉跨词统计（`we` 在两个词里都出现）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 3. 什么场景下用词级分词 + 停用词过滤，什么场景用子词 BPE？
> [!question]- 答案解析
> - **答案**：传统统计方法（HW02 的 BoW/TF-IDF/朴素贝叶斯）：词级 + 停用词（降维、去噪）；神经网络（词向量、RNN、BERT/GPT）：子词 BPE/WordPiece，**不去停用词**（模型可学习其作用，去词丢失信息）。
> - **解析**：传统方法特征是"词是否存在"，停用词只会稀释信号；神经方法特征是"词的表示"，停用词也携带语法信息。
> - **易错原因**：给 BERT 也做停用词过滤——破坏预训练分布，反而掉点。
> - **Obsidian 标签建议**：`#自测题/中等`

#### 4. BPE 与 WordPiece 的合并准则有什么不同？
> [!question]- 答案解析
> - **答案**：BPE 按**相邻对绝对频次** $\text{count}(a,b)$ 合并；WordPiece 按**归一化似然增益** $\frac{\text{count}(ab)}{\text{count}(a)\text{count}(b)}$ 合并——惩罚高频单字符（如 "t"、"e"），避免它们总被合并。
> - **解析**：WordPiece 的分数是"合并后节省多少"（PMI 式）：$ab$ 共现强于随机才合并。BERT 用 WordPiece（词首加 `##` 标记续词），GPT 用 BPE。
> - **易错原因**：把两者混为一谈；或以为 WordPiece 也按纯频次。
> - **Obsidian 标签建议**：`#自测题/中等`
