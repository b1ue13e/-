## 4. 用直觉语言解释它
> «"NLP 工具链像'厨房里的三把刀'：jieba 是'中式菜刀'（中文分词又快又稳）；nltk 是'教学刀具套装'（什么菜都能切，但多为演示用）；spaCy 是'厨师机'（从洗菜到摆盘一条龙流水线）；pandas 是'砧板'（大批量切配、清洗、统计）；正则表达式是'镊子'（在文本里精准夹出指定模式的碎片）。"»
- **直觉类比/几何图像**：pipeline = 流水线：`文本 → 清洗 → 分词 → 词性 → 依存 → NER`，spaCy 一行 `nlp(text)` 全跑完。
- **为什么很自然**：语言处理本身是分层的（字符→词→句法→语义），工具按层组织与语言结构天然对应。
- **一句话直觉本质**：**"清洗用 pandas+正则，中文分词用 jieba，传统全套用 nltk，生产 pipeline 用 spaCy，深度学习用 transformers"——按任务选刀。**

## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
**分词**：把连续文本切为词序列 $w_1,\dots,w_n$。中文无天然空格，需词典+统计（jieba 默认词典 + HMM 识别新词）。
**词性标注（POS）**：为每个词分配词性标签 $t_i \in \mathcal{T}$（如 n/v/adj）。
**文本清洗**：去噪（HTML/URL/Emoji）、归一化（大小写/繁简）、去停用词。
### 2. 核心公式
**jieba 分词的核心**（前缀词典 + 动态规划最大化概率）：
$$\hat{w}_{1:n} = \arg\max_{w_{1:n}} \prod_{i} P(w_i), \qquad P(w_i) = \frac{\text{count}(w_i)}{\sum_{w}\text{count}(w)}$$
**正则匹配**：模式 $R$ 在文本 $s$ 中匹配子串；`re.findall(r"模式", s)` 返回全部命中。
### 3. 符号说明表
| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $w_i$ | 第 $i$ 个词 | 字符串 | 分词结果 |
| $t_i$ | 词性标签 | $\mathcal{T}$ | 如 n/v/adj |
| $P(w_i)$ | 词概率 | $[0,1]$ | 频次估计 |
| $R$ | 正则模式 | 字符串 | 语法如 `\d+` |
| n-gram | 连续 $n$ 词 | $n=1,2,3$ | 特征/统计单元 |
### 4. 常见变体与适用条件
- **jieba**：精确模式（默认，DP 最优切分）、全模式（所有可能词）、搜索引擎模式（长词再切）；`jieba.posseg` 带词性。
- **spaCy**：多语言模型（`zh_core_web_sm`），pipeline 含 tok2vec→tagger→parser→ner。
- **nltk**：传统算法库（HMM 分词、朴素贝叶斯、树库工具），适合教学与算法验证。
- **限制条件**：jieba 对专业领域词表需自定义词典；spaCy 中文模型规模小；正则无法处理嵌套/递归语法（需解析器）。
---
## 6. 推导思路和思想来源
- **最初困难**：中文没有空格边界，分词是"夹缝求生"；英文也有连写与缩写问题。
- **直接方法局限**：纯词典最大匹配（正向/逆向）会切出歧义："南京市长江大桥" 两种切法都合法。
- **关键"转念"**：① 把切分看作**概率最大化**问题——词典 + 动态规划（jieba 的核心）；② 对未登录词用 **HMM**（隐状态 = B/M/E/S 边界）识别；③ 句法/语义任务不靠正则硬解，用统计模型（spaCy 的 pipeline）。
- **推导主线与动机**：清洗（规则）→ 分词（统计）→ 标注（监督学习）→ 解析/NER（结构化预测），每层工具解决一层问题。
- **为什么自然得到此结论**：语言处理分层与算法复杂度匹配：规则快但脆，统计稳但需数据，深度强但需算力。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：用正则从 `"价格：¥299.5，库存 12 件"` 中提取价格数字。
- **解题思路与关键步骤**：模式 `¥(\d+\.?\d*)` 匹配 ¥ 后的数字；`re.search(r"¥(\d+\.?\d*)", s).group(1)`。
- **最终答案**：`"299.5"`。
- **易错点**：`\d+\.?\d*` 会匹配 `299.` 吗？—— 会（`.` 可选、`\d*` 可空），应写 `\d+(\.\d+)?` 强制小数点后至少一位。
- **🤔 追问**：如果价格写成 `299,5`（德语格式）？—— 换模式 `\d+[.,]\d+` 并统一归一化为 `299.5`。
### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：为什么 "南京市长江大桥" 用最大匹配会切错，jieba 却通常切对？—— 最大匹配贪心选最长词（"南京市"+"长江大桥" 或 "南京市长"+"江大桥"），歧义无法靠长度解决；jieba 用**全切分图 + DP 最大概率**，把整句所有可能切分综合打分，"南京市/长江/大桥" 的联合概率通常最高。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HW01 文本预处理的标准流水线：
```python
import re, jieba, pandas as pd
from collections import Counter

def clean(text: str) -> str:
    text = re.sub(r"<[^>]+>", "", text)      # 去 HTML
    text = re.sub(r"[^\u4e00-\u9fa5a-zA-Z0-9]", " ", text)  # 去标点
    return text

df = pd.read_csv("reviews.csv")
df["words"] = df["text"].apply(lambda t: [w for w in jieba.cut(clean(t)) if w.strip()])
top = Counter(w for ws in df["words"] for w in ws).most_common(20)
print(top)
```

## 8. 常见误区和易混概念
### 误区 1：以为"分词后必须去停用词"
- **错误直觉**：停用词没用，全删。
- **为什么错**：情感词往往带否定（"不""没"），粗暴删除会破坏语义；停用词表需按任务定制。
- **正确理解**：停用词过滤是**任务相关**决策，分类/检索常用，情感/依存分析慎用。
### 误区 2：以为"正则能解析一切文本结构"
- **错误直觉**：写个复杂模式就能处理嵌套括号/引号。
- **为什么错**：正则等价于有限自动机，无法处理递归嵌套（"匹配成对括号"是经典不可正则问题）。
- **正确理解**：嵌套/树结构用解析器（spaCy 依存、括号配对用栈）；正则做"扁平模式"抽取。
### 概念对比表
| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| jieba（本概念） | 中文分词 | 词典+DP+HMM | 中文语料切词 |
| nltk | 传统算法全套 | 教学、算法验证 | 课程作业 |
| spaCy | 生产 pipeline | 分词→依存→NER 一条龙 | 工业级文本分析 |
| pandas+正则 | 清洗与统计 | 表格化批量处理 | 数据预处理 |
| transformers | 深度预训练 | 现代模型推理/微调 | 深度学习任务 |

### 题目与解析
#### 1. 中文分词场景下，jieba、nltk、spaCy 各自的定位是什么？
> [!question]- 答案解析
> - **答案**：jieba：中文分词事实标准（词典+DP+HMM）；nltk：传统算法教学与验证（分词能力弱，中文需插件）；spaCy：生产级多任务 pipeline（分词→词性→依存→NER），中文模型需单独下载。
> - **解析**：选型看任务：只要切词用 jieba；要词性/依存/NER 一条龙用 spaCy；要复现经典算法用 nltk。`#自测题/基础`
#### 2. 用正则从 "手机号: 138-1234-5678" 提取完整号码（含连字符）。
> [!question]- 答案解析
> - **答案**：`re.search(r"\d{3}-\d{4}-\d{4}", s).group()` → `"138-1234-5678"`。
> - **解析**：`\d{3}` 精确三位；注意 `-` 在字符类外无需转义。若号码无分隔符，模式为 `1\d{10}`。`#自测题/基础`
#### 3. 什么情况下最大匹配分词会失败？jieba 如何解决？
> [!question]- 答案解析
> - **答案**：歧义切分（"南京市长江大桥"）与未登录词（新词/人名）会失败。jieba 用全切分图 + DP 最大化整体概率解决歧义；HMM 的 B/M/E/S 状态识别未登录词。
> - **解析**：最大匹配是贪心（局部最优），DP 是全局最优；HMM 处理词典外词汇。`#自测题/中等`
#### 4. 设计一个"爬虫评论 → 词频统计"的清洗流水线，说明每一步的工具。
> [!question]- 答案解析
> - **答案**：① 去 HTML/URL/Emoji（正则）；② 繁简/大小写归一（`zhconv`/`.lower()`）；③ 去标点与空白（正则）；④ jieba 分词（精确模式）；⑤ 自定义停用词过滤（任务相关）；⑥ pandas `value_counts()` 或 `Counter` 统计。
> - **解析**：清洗顺序有讲究：先结构化去噪，再归一化，最后分词统计；停用词过滤放分词后。`#自测题/中等`
#### 5. 给一个医疗问答语料设计分词增强方案（jieba 切错专业术语怎么办）。
> [!question]- 答案解析
> - **答案**：① 自定义词典 `jieba.add_word("心肌梗死")` / `jieba.load_userdict("med.txt")` 提高词频；② 收集未登录术语加入词典（从标注语料挖掘高频 n-gram）；③ 对词典无法覆盖的，用领域语料重训 HMM 或改用领域预训练模型分词；④ 必要时用 spaCy 的 tok2vec 或 BERT 子词方案替代词级分词。
> - **解析**：分词质量直接影响下游 NER/检索；领域词典是最便宜有效的杠杆，词频设置（`freq`）影响 DP 选择。`#自测题/较难`
