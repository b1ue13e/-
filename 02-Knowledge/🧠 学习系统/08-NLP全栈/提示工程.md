# 提示工程
---
## 0. 先判断它值不值得深挖
- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：提示工程是"零成本使用 LLM"的核心技能：不训练、不改模型，只改输入就能大幅提升效果。[[Agent与工具使用]] 的 ReAct 格式、[[检索增强生成RAG]] 的检索指令都是提示工程的应用；面试必考"CoT 为什么有效""少样本怎么选示例""幻觉怎么缓解"。
---
## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> 同样的模型，有人问出垃圾答案，有人问出完美答案——LLM 对输入措辞、结构、示例极其敏感："荷花每天翻倍，30 天开满，几天开一半？"直接问大概率答错（推理链不完整）。
> 提示工程的回答：**不训练模型，而是设计输入**——零样本（指令+格式）、少样本（示例做"上下文学习"）、CoT（引导"先推理再回答"）、思维树（多路径搜索）、结构化模板（角色/步骤/约束），用输入侧工程榨出模型能力；同时用约束与验证缓解幻觉。
---
## 2. 为什么它重要？它有什么用？
- **连接大图景**：提示是 LLM 时代的"编程语言"：[[Agent与工具使用]]（ReAct/工具格式）、[[检索增强生成RAG]]（检索指令与引用格式）、[[对话系统]]（人设与多轮）全是提示设计；它与 [[指令微调与对齐]] 互补（训练式 vs 输入式）。
- **实际应用场景**：日常问答、代码生成、结构化输出（JSON）、推理题、Agent 系统提示词；面试"CoT 原理（算力转移）""few-shot 示例怎么选""幻觉成因与缓解"。

## 4. 用直觉语言解释它
> «"提示工程像'给新手员工写任务单'：零样本 = 只写'把这堆数据整理成表格'（指令清晰，但没示范）；少样本 = 附两个做好的例子（'像这样整理'，员工照葫芦画瓢）；CoT = 要求'先写步骤再给答案'（逼他把思路摊开，就像老师要求写解题过程——写过程时错误更容易自己发现）；思维树 = 让员工'多想几条路，每条试两步，再选最好的'（搜索式推理）。幻觉 = 员工'记不清就编'，缓解办法是'要求引用来源、允许说不知道、把答案限制在给定材料里'。"»
- **直觉类比/几何图像**：上下文学习（ICL）= 在输入里"现场示范"；CoT = 把隐式推理显式化（推理时计算预算转移到输出 token 上）。
- **为什么很自然**：LLM 是"从上下文学规律"的机器（in-context learning 是其涌现能力），给示例=给规律样本；让模型"写过程"利用了自回归的"边写边想"特性。
- **一句话直觉本质**：**"提示工程 = 用输入侧的'指令+示例+推理结构+约束'控制 LLM 输出：零样本定格式、少样本做示范、CoT 引推理、ToT 做搜索；幻觉靠'限定来源+允许拒答+验证'缓解。"**
---
## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
**上下文学习（ICL）**：不更新参数，把示例拼入输入，$P(y|x, \{(x_i,y_i)\}_{i=1}^{k})$。
**CoT（Chain-of-Thought, Wei et al. 2022）**：提示模型先输出推理步骤再给出答案；few-shot CoT 给带推理的示例，zero-shot CoT 用"Let's think step by step"触发。
**思维树（ToT, Yao et al. 2023）**：把推理变成树搜索：生成多个"思维步骤"候选，评估打分，回溯扩展，选最优路径。
### 2. 核心公式
**ICL 形式**：
$$P(y \mid x, S) = \prod_{t} P_\theta(y_t \mid y_{<t}, x, S), \qquad S = \{(x_1,y_1),\dots,(x_k,y_k)\}$$
**CoT 分解**（把答案拆成步骤）：
$$P(y \mid x) \approx \prod_{j} P(\text{step}_j \mid \text{step}_{<j}, x) \quad \Rightarrow \quad \hat{y} = \text{最后一步}$$
### 3. 符号说明表
| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $S$ | 示例集 | $k$ 个样本 | 少样本数 |
| $x, y$ | 输入/输出 | 文本 | 任务对 |
| $k$ | 示例个数 | 0–几十 | 越多越贵 |
| step$_j$ | 推理步骤 | 文本 | CoT 中间产物 |
| $\tau$ | 温度 | $[0,2]$ | 采样随机性 |
### 4. 常见变体与适用条件
- **零样本**：指令清晰即可；快、省 token；复杂任务效果差。
- **少样本**：2-8 个高质量示例；示例要覆盖困难情况（负面示例也有效）；token 成本线性增长。
- **CoT**：数学/逻辑/多跳推理任务收益大；简单任务反而可能降级（"想太多"）。
- **ToT**：需要可评估中间步骤的任务（游戏、规划）；成本高（多次采样+评估）。
- **限制条件**：上下文窗口限制示例规模；提示对措辞敏感（同义改写效果不同）；模型能力上限决定提示上限。

## 6. 推导思路和思想来源
- **最初困难**：GPT-2/3 时代"提示"是自然语言指令，效果不稳定；复杂推理（多步数学）直接生成答案错误率高。
- **直接方法局限**：加大模型（涌现但昂贵）；微调（需要数据与算力）。
- **关键"转念"**：① ICL：模型预训练时见过"示例-延续"模式，输入里放示例=激活这种模式（Brown et al. 2020 GPT-3 论文提出 few-shot）；② CoT：让模型"把推理写出来"——自回归的每一步都基于前面已写内容，显式中间步骤降低"一步到位的组合误差"，本质是**把计算量转移到生成过程**（Wei et al. 2022）；③ ToT：单链不够就分支搜索——把"解码"升级为"树搜索 + 评估"（Yao et al. 2023）。
- **推导主线与动机**：指令（0-shot）→ 示例（few-shot ICL）→ 推理链（CoT）→ 搜索（ToT/Self-Consistency）：从"让模型直接答"到"让模型想好了再答"再到"多想几条再选"。
- **为什么自然得到此结论**：LLM 是"概率续写器"，提示工程的本质是**把任务转成它最擅长的续写模式**并给足"思考预算"。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：对比零样本与 CoT 提示回答"池塘荷花每天翻倍，30 天开满，几天开一半？"
- **解题思路与关键步骤**：零样本：直接答，模型易答"15 天"（错——直觉线性思维）。CoT 提示："请一步一步推理：第 30 天开满；每天翻倍，则第 29 天是第 30 天的一半；所以答案是 29 天。"（示例化 CoT 或 "Let's think step by step" 触发）。
- **最终答案**：29 天。关键转念："开一半"是"开满"的前一天（翻倍逆推）。
- **易错点**：把"翻倍增长"误当"线性增长"；CoT 的关键是**显式写出逆推步骤**。
- **🤔 追问**：若问"第几天开四分之一"？—— 第 28 天（再逆推一天）。
### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：为什么少样本示例要包含"困难/边界案例"？—— ICL 是"从示例归纳规律"：全给简单例子，模型学到"简单模式"；包含失败/边界例子（如"这不是 XX"）能让模型学到判别边界。示例顺序也有影响（近期示例权重更高，recency bias）。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：结构化输出 + Self-Consistency 的生产用法：
```python
from openai import OpenAI
client = OpenAI()

prompt = """从评论中提取情感，只输出 JSON：{"sentiment": "positive|negative|neutral", "reason": "..."}
示例：评论"物流太慢了" -> {"sentiment": "negative", "reason": "物流慢"}
评论"{review}" ->"""
ans = client.chat.completions.create(model="gpt-4o-mini",
    messages=[{"role": "user", "content": prompt}], temperature=0)
import json; print(json.loads(ans.choices[0].message.content))

# Self-Consistency：temperature=0.7 采样 5 次，多数投票
votes = []
for _ in range(5):
    r = client.chat.completions.create(model="gpt-4o-mini",
        messages=[{"role": "user", "content": "池塘荷花…请推理"}], temperature=0.7)
    votes.append(r.choices[0].message.content)
print(max(set(votes), key=votes.count))   # 投票取多数
```

## 8. 常见误区和易混概念
### 误区 1：以为"CoT 是模型学会了新知识"
- **错误直觉**：写步骤让模型"懂"了推理。
- **为什么错**：CoT 不改变参数；它是把"隐式计算"显式化——每步只做小步预测，降低单步错误概率，本质是**推理时计算量的重新分配**。
- **正确理解**：CoT 有效的前提是模型已有推理能力（预训练学到）；提示只是"解锁"。
### 误区 2：以为"提示越长越好，示例越多越好"
- **错误直觉**：堆 50 个示例、写 2000 字指令。
- **为什么错**：上下文窗口有限，示例过多稀释注意力（lost in the middle：中间内容被忽略）；无关指令增加噪声。
- **正确理解**：少而精（3-8 个高质量示例）、关键指令前置或后置、结构化（分隔符/编号）。
### 概念对比表
| 概念 | 机制 | 成本 | 典型场景 |
| :--- | :--- | :--- | :--- |
| 零样本（本概念） | 指令 | 最低 | 简单任务 |
| 少样本 ICL | 示例示范 | 低 | 分类、格式 |
| CoT | 显式推理链 | 中 | 数学、逻辑 |
| ToT | 树搜索 | 高 | 规划、谜题 |
| 指令微调 | 训练 | 高 | 系统性改造 |

### 题目与解析
#### 1. 零样本、少样本、CoT、ToT 的提示结构分别是什么？
> [!question]- 答案解析
> - **答案**：零样本：指令+问题；少样本：指令+$k$ 个示例+问题；CoT：指令"逐步推理"+推理链示例或"Let's think step by step"；ToT：指令"生成多条思路→评估→选最优"+状态表示。
> - **解析**：复杂度与 token 成本递增，收益集中在推理/规划任务。`#自测题/基础`
#### 2. 写出少样本 ICL 的预测概率形式并解释每个符号。
> [!question]- 答案解析
> - **答案**：$P(y|x,S)=\prod_t P_\theta(y_t|y_{<t},x,S)$，$S=\{(x_i,y_i)\}_{i=1}^{k}$ 为示例集，$\theta$ 为冻结参数。
> - **解析**：参数不更新（区别于微调），能力来自预训练 + 上下文示范。`#自测题/基础`
#### 3. 什么任务适合 CoT，什么任务不适合？
> [!question]- 答案解析
> - **答案**：适合：数学、多跳推理、逻辑、代码调试（需要中间步骤）；不适合：简单分类、抽取、格式化输出（CoT 增加 token 成本且可能引入错误中间步骤，简单任务"想太多"反而降级）。
> - **解析**：用验证集对比 zero-shot 与 CoT 效果决定；成本也是考量。`#自测题/中等`
#### 4. Self-Consistency 为什么能提升准确率？与投票的类比。
> [!question]- 答案解析
> - **答案**：多次采样（temperature>0）得到多条推理路径，多数投票取最终答案。原理：正确路径不止一条（殊途同归），错误路径各错各的（分散）；类似集成学习/多数表决——系统性错误被稀释。比单条 CoT 显著提升（数学推理 +10% 以上）。
> - **解析**：代价是推理成本 ×N；可并行采样。`#自测题/中等`
#### 5. 设计一个"客服问答防幻觉"的提示系统方案。
> [!question]- 答案解析
> - **答案**：① 限定来源：只允许基于给定 FAQ/文档回答（RAG 检索片段），提示中声明"不得使用外部知识"；② 要求引用：回答必须带来源编号，无来源则答"资料中未找到"；③ 允许拒答：显式授权"不知道就说不知道"；④ 结构化输出 + 规则校验：JSON 输出，字段校验失败重试；⑤ 温度调低 + 后验验证：关键事实用检索结果比对。
> - **解析**：幻觉缓解三板斧 = 限制知识源 + 强制证据 + 允许拒答；系统级验证兜底。`#自测题/较难`
