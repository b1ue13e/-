# LLM推理优化
---
## 0. 先判断它值不值得深挖
- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：LLM 的"贵"和"慢"是部署第一痛点：7B 模型 FP16 权重就要 14GB 显存，每生成一个 token 都要过全部参数。[[🧭 开源作业体系-NLP全栈|开源作业体系]] 项目层要本地部署小模型，不掌握 KV Cache / 量化 / vLLM 就跑不动；面试必问"为什么自回归慢""PagedAttention 解决什么"。
---
## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> ① **慢**：自回归解码每步都重算前面所有 token 的注意力（朴素 $O(n^2)$ 重复计算）；② **贵**：7B 模型 FP16 权重 14GB，消费级显卡放不下；③ **吞吐低**：多用户并发时显存碎片化，8GB 卡只能服务 1-2 个会话。
> 推理优化的回答：**KV Cache**（缓存历史 K/V 免重复计算）、**量化**（INT8/INT4 压权重位宽）、**投机解码**（小模型猜、大模型验）、**vLLM/PagedAttention**（显存按页管理，吞吐提升 10-20 倍）、**蒸馏**（大模型教小模型）。
---
## 2. 为什么它重要？它有什么用？
- **连接大图景**：推理优化是 [[GPT系列]] 到产品落地的桥梁；[[参数高效微调PEFT]] 压训练成本，推理优化压部署成本；[[Agent与工具使用]] 多步循环放大延迟，优化更迫切。
- **实际应用场景**：本地部署（llama.cpp/Ollama）、高并发 API（vLLM）、边缘设备（手机端 3B 量化）、成本控制。
- **高频题型/任务**：面试"KV Cache 省了多少计算""INT8 量化误差来源""投机解码加速比上限""PagedAttention 与操作系统分页"；实验：vLLM 吞吐 benchmark。

## 4. 用直觉语言解释它
> «"KV Cache 像'会议速记员'：前面发言（K/V）都记在便签上，后面发言不用再回头问'你刚才说了啥'（不重算历史注意力），直接翻便签。量化像'把高精度记账本改成四位小数'：略糙但基本准，内存省一半。投机解码像'实习生先写草稿，主管只改错的地方'。PagedAttention 像'操作系统把内存切成页'：谁的便签占不满一页就拼着用，同时服务的人就多了。"»
- **直觉类比/几何图像**：自回归生成 = 开 $T$ 轮会；朴素实现每轮重述全部历史，KV Cache 让每轮只算新发言。量化 = 权重的有效信息位宽远小于 16 位。
- **为什么很自然**：历史 KV 在解码中不变，缓存天经地义；权重近似高斯分布且容忍噪声，量化自然可行。
- **一句话直觉本质**：**用"缓存复用（KV）、精度换空间（量化）、小模型换步数（投机解码）、显存页管理（PagedAttention）、模型换小（蒸馏）"把自回归成本从 $O(T^2)$ 与 16bit 拉低到可部署水平。**
---
## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
**KV Cache**：解码第 $t$ 步缓存前 $t-1$ 步所有层的 $K,V$，每步只对新 token 算 $Q$ 并复用缓存，单步复杂度从 $O(t^2 d)$ 降到 $O(t d)$。
**量化**：权重/激活从 FP16 映射到低精度整数，INT8 对称量化 $x_q = \text{round}(x/s)$，反量化 $\hat{x}=s\cdot x_q$。
### 2. 核心公式
$$\text{Mem}_{\text{KV}} = 2 \cdot L \cdot d_{\text{model}} \cdot n_{\text{tokens}} \cdot \text{bytes/elem}, \qquad x_q = \text{clamp}\left(\text{round}\left(\frac{x}{s}\right), -127, 127\right),\ s = \frac{\max|x|}{127}$$
$$\text{Speedup}_{\text{spec}} = \frac{\gamma(1-\alpha)}{1-\alpha^{\gamma+1}}$$
### 3. 符号说明表
| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $L$ | 层数 | 12–80 | 每层存一份 KV |
| $d_{\text{model}}$ | 隐藏维度 | 768–8192 | KV 维度 |
| $s$ | 量化缩放因子 | $\mathbb{R}^+$ | 对称量化 |
| $\alpha$ | 草稿接受率 | $[0,1]$ | 越高加速越大 |
| $\gamma$ | 草稿长度 | 4–8 | 一次验证的 token 数 |
| $n_{\text{tokens}}$ | 序列长度 | 1–128K | KV 随长度线性增长 |
### 4. 常见变体与适用条件
- **INT8/INT4（GPTQ/AWQ）**：仅权重量化（W8A16）最稳；权重+激活（W8A8）更快但需校准数据。
- **投机解码**：草稿与目标分布接近才有效；草稿差则加速比 $\to 1$。
- **限制条件**：KV Cache 随序列长度线性增长；低比特时权重 outlier 致精度崩坏；投机解码多一次模型调用。
---
## 6. 推导思路和思想来源
- **最初困难**：自回归生成 $T$ 个 token，朴素总计算 $O(T^2)$ 且历史重复计算；16bit 权重昂贵；显存碎片压低并发吞吐。
- **直接方法局限**：加显存（贵）、砍序列（伤质量）、纯批处理（延迟上升）。
- **关键"转念"**：① KV 解码中不变 → 缓存（KV Cache）；② 权重分布方差大但 outlier 少 → 线性量化可逼近；③ 大模型验证比小模型生成贵 → 小模型生成候选、大模型并行验证（Leviathan 2023）；④ 显存碎片似内存碎片 → 分页思想（PagedAttention, vLLM 2023）；⑤ 知识可迁移 → 教师-学生蒸馏（Hinton 2015）。
- **推导主线与动机**：每项优化针对一个可量化瓶颈：重复计算（KV）、存储位宽（量化）、串行步数（投机）、显存管理（PagedAttention）、模型规模（蒸馏）。
- **为什么自然得到此结论**：瓶颈在哪，优化就在哪——是对成本结构的逐一拆解。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：7B 模型（$L=32$，$d_{\text{model}}=4096$，FP16）服务 100 个并发会话，每会话上下文 4096 token。KV Cache 总显存多少 GB？
- **解题思路与关键步骤**：每 token 每层 KV = $2\times4096\times2\text{B}=16\text{KB}$；每会话 $=32\times4096\times16\text{KB}=2\text{GB}$；100 会话 $=200\text{GB}$。
- **最终答案**：约 200GB——远超单卡，这正是 vLLM 做 KV 分页/共享的动机。
- **易错点**：忘乘 2（K 和 V）或忘乘层数；FP16 为 2 字节。
- **🤔 追问**：换成 INT8 KV cache？—— 减半为 100GB，这就是 KV 量化的价值。
### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：权重出现极端 outlier（如 50）时，INT8 对称量化会怎样？—— $s=50/127\approx0.394$，绝大多数权重（如 0.1）量化后 $\approx0$，精度崩坏。缓解：① AWQ 按激活幅度保护重要通道；② 非对称量化（零点+缩放）；③ per-channel 量化；④ outlier 通道保留 FP16。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：vLLM 三行部署，自动 PagedAttention + 连续批处理：
```python
from vllm import LLM, SamplingParams

llm = LLM(model="Qwen/Qwen2.5-7B-Instruct",
          gpu_memory_utilization=0.9, quantization="awq")   # INT4 权重
out = llm.generate(["写一首关于秋天的诗"], SamplingParams(temperature=0.7, max_tokens=256))
print(out[0].outputs[0].text)
```

## 8. 常见误区和易混概念
### 误区 1：以为"KV Cache 只是推理优化技巧，与训练无关"
- **错误直觉**：只在部署时有用。
- **为什么错**：训练（尤其长上下文）同样需要；且 KV Cache 影响架构设计——MQA/GQA 就是压缩 KV 头（[[GPT系列]] 的 GQA 配置）。
- **正确理解**：KV Cache 是注意力机制的自然推论；GQA 是"架构级"KV 压缩。
### 误区 2：以为"量化就是无损压缩"
- **错误直觉**：INT8 和 FP16 效果一样。
- **为什么错**：量化有损，权重分布、激活 outlier、任务敏感度都影响误差；且 INT8 加速依赖特定硬件 kernel。
- **正确理解**：量化是"精度-速度-内存"三角权衡，需校准数据与任务评测。
### 概念对比表
| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| KV Cache（本概念） | 重复计算 | 缓存历史 K/V | 所有自回归推理 |
| 量化 | 存储/带宽 | 低比特权重 | 本地部署 |
| 投机解码 | 串行步数 | 小模型+大模型验证 | 高吞吐服务 |
| 蒸馏 | 模型规模 | 教师-学生训练 | 小模型替代 |
| PagedAttention | 显存碎片 | 页式管理 KV | vLLM 服务 |

### 题目与解析
#### 1. 分别说明 KV Cache、量化、投机解码、PagedAttention、蒸馏各解决哪个瓶颈。
> [!question]- 答案解析
> - **答案**：KV Cache → 历史注意力重复计算；量化 → 权重存储/带宽；投机解码 → 自回归串行步数；PagedAttention → 显存碎片与低并发；蒸馏 → 模型规模过大。
> - **解析**：五种手段正交可叠加（vLLM 同时用 KV Cache + 连续批处理 + 量化加载）。`#自测题/基础`
#### 2. 8B 模型（$L=36$，$d_{\text{model}}=4096$），FP16，单会话上下文 8192 token，KV Cache 多少 GB？
> [!question]- 答案解析
> - **答案**：每 token 每层 KV $=2\times4096\times2\text{B}=16\text{KB}$；共 $36\times8192\times16\text{KB}=4.7\text{GB}$。
> - **解析**：与模型权重（约 16GB FP16）同量级——KV Cache 是显存第二大户。`#自测题/基础`
#### 3. 什么场景该用 W8A16 权重量化，什么场景该用 W8A8，什么场景不适合量化？
> [!question]- 答案解析
> - **答案**：仅部署省显存、追求精度 → W8A16；需激活量化提速、任务对精度不敏感 → W8A8；3bit 以下或数值极敏感任务（代码生成、长链推理）→ 谨慎或混合精度。
> - **解析**：激活 outlier 是 W8A8 的主要误差源；校准集要与任务分布接近。`#自测题/中等`
#### 4. 投机解码：草稿长度 $\gamma=4$，接受率 $\alpha=0.7$ 与 $\alpha=0.3$ 的理论加速比各是多少？
> [!question]- 答案解析
> - **答案**：$\text{Speedup}=\frac{\gamma(1-\alpha)}{1-\alpha^{\gamma+1}}$。$\alpha=0.7$：$\frac{1.2}{1-0.7^5}\approx1.44\times$；$\alpha=0.3$：$\frac{2.8}{1-0.3^5}\approx2.81\times$。
> - **解析**：公式假设草稿模型零成本；工程上草稿也耗时，$\alpha$ 太低时反而更慢，通常要求 $\alpha>0.6$ 才划算。`#自测题/中等`
#### 5. 推导：为什么 KV Cache 把单步解码复杂度从 $O(t^2 d)$ 降到 $O(t d)$？
> [!question]- 答案解析
> - **答案**：第 $t$ 步朴素实现对所有 $t$ 个位置重算 $QK^\top$（$t\times t$ 打分矩阵）——$O(t^2 d)$，且前 $t-1$ 步的 K/V 每步重算。缓存后第 $t$ 步只算新 token 的 $q_t$ 与全部 K 的点积（$t$ 个）再与 V 加权——$O(t d)$。总生成 $T$ 个 token：朴素 $O(T^3 d)$，缓存 $O(T^2 d)$。
> - **解析**：KV Cache 本质是记忆化（memoization）：不变的中间结果只算一次；长上下文成本随长度线性而非立方增长。`#自测题/较难`
