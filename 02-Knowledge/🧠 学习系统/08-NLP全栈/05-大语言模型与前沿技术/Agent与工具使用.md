# Agent与工具使用
---
## 0. 先判断它值不值得深挖
- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：LLM Agent 是 [[GPT系列]] 之后最大的应用范式——从"聊天"到"干活"的跃迁。[[🧭 开源作业体系-NLP全栈|开源作业体系]] 项目层（智能客服、文档问答）需要 Agent 编排；面试高频"ReAct 与 Function Calling 的区别""Agent 三大组件"。
---
## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> LLM 只会生成文本：问实时天气只能编造；处理 PDF 做不到，因为它是纯文本模型、不能执行操作。
> Agent 的回答：**给 LLM 装上"手脚"**——工具调用（搜索/计算/代码/API）、记忆（多轮目标）、规划（拆解步骤）。LLM 当"大脑"，循环"思考 → 行动 → 观察"直到任务完成。
---
## 2. 为什么它重要？它有什么用？
- **连接大图景**：Agent 是 [[指令微调与对齐]] 的下游应用；[[检索增强生成RAG]] 是"单检索工具"的 Agent 特例；工具调用依赖 Function Calling 微调。
- **实际应用场景**：自主任务执行、代码助手、[[项目-智能客服]]、[[项目-文档问答]] 编排层。
- **高频题型/任务**：面试"ReAct 推理循环""Function Calling 的 schema""记忆分几种"；项目验收要求正确调用工具。
---
## 3. 学它之前需要哪些前置知识？
1. **[[GPT系列]]**：Agent 的大脑是自回归生成模型。
2. **[[提示工程]]**：ReAct 的"思考/行动/观察"格式本质是结构化提示。
3. **[[指令微调与对齐]]**：Function Calling 是 SFT 阶段用"对话+工具定义+调用"数据训出来的能力。
---
## 4. 用直觉语言解释它
> «"Agent 像一个'会打电话求助的实习生'：老板派任务后，先在心里列计划（规划），遇到不会的就打电话问（工具调用），把结果记在便签上（记忆），再决定下一步——不断'想一下 → 问一下 → 看结果 → 再想'，直到办完。"»
- **直觉类比/几何图像**：ReAct = "Reasoning + Acting" 循环：Thought / Action / Observation，类似强化学习的"状态-动作-奖励"环，只是决策者是 LLM。
- **为什么很自然**：人类解决问题本就是"计划-执行-反馈"；把 LLM 推理与工具执行交替编排，是让静态模型动态化的最直接方式。
- **一句话直觉本质**：**LLM 当控制器，循环"推理 → 调工具 → 观察 → 更新记忆"直到满足目标；工具调用靠函数 schema 微调或提示约束实现。**
---
## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
**LLM Agent** = 大语言模型 $\pi_\theta$ + 工具集 $\mathcal{T}=\{t_1,\dots,t_k\}$ + 记忆 $\mathcal{M}$ + 规划器，循环生成动作 $a_1,\dots,a_n$（调工具或直接回答），依据观察 $o_i$ 更新状态，直到产出最终答案。
### 2. 核心公式
$$\text{Trajectory}_t = [\text{Thought}_1, \text{Action}_1, \text{Observation}_1, \dots, \text{Thought}_t], \qquad \text{Action}_t = \arg\max p_\theta(a \mid \text{Trajectory}_{t-1}, \text{Task})$$
$$\text{Input} = [\text{Sys}, \text{schema}_1, \dots, \text{schema}_k, \text{User}, \text{History}] \to \text{Output} = \text{JSON}\{\text{name}, \text{arguments}\}$$
### 3. 符号说明表
| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $\pi_\theta$ | 策略（LLM） | 概率分布 | 生成下一 token |
| $\mathcal{T}$ | 工具集 | 有限集合 | 搜索/计算/API |
| $\mathcal{M}$ | 记忆 | 短期+长期 | 对话历史/向量库 |
| $o_i$ | 第 $i$ 步观察 | 工具返回值 | 文本拼回上下文 |
| $\gamma$ | 最大步数 | 整数 | 防死循环 |
### 4. 常见变体与适用条件
- **ReAct**（Yao 2022）：思考/行动/观察写进提示，无需微调，适合推理任务。
- **Function Calling**（OpenAI 2023）：SFT 训出结构化 JSON 调用，适合 API 精确参数。
- **Plan-and-Execute**：先整体计划再逐步执行，适合长任务。
- **限制条件**：上下文窗口限制轨迹长度；错误累积无回滚；工具结果需校验。
---
## 6. 推导思路和思想来源
- **最初困难**：LLM 无法获取实时信息、无法执行操作、无法验证答案。
- **直接方法局限**：RAG 只能"读"不能"做"；让模型输出"我要调用搜索"再解析，格式不稳定。
- **关键"转念"**：① 不要求模型会做事，只要求它"描述要做什么"（动作文本化）；② 用"思考-行动-观察"循环把单次生成变成多步决策；③ 工具调用规范成 JSON，可被程序解析执行。
- **推导主线与动机**：智能体 = 感知 → 决策 → 行动 → 记忆更新，闭环迭代；每一步都是条件生成。
- **为什么自然得到此结论**：模型能力（生成）与任务需求（执行）的鸿沟，只能靠"外部执行器 + 循环"补上——Agent 是补丁，不是新模型。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：给工具 `calc(expr)`，任务"计算 23×4 再减 5"。写 ReAct 轨迹。
- **解题思路与关键步骤**：Thought₁ 需乘法 → Action₁ `calc("23*4")` → Obs₁ `92` → Thought₂ 92−5 → Action₂ `calc("92-5")` → Obs₂ `87` → Final: 87。
- **最终答案**：6 步轨迹，输出 87。
- **易错点**：把计算写在 Thought 里不调工具（幻觉算错）；一个 Action 写两个表达式。
- **🤔 追问**：若工具是 `calc(a, op, b)`？—— `{"name":"calc","arguments":{"a":23,"op":"*","b":4}}`，这就是 Function Calling schema 的价值。
### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：工具返回"查无此人"时应改变策略而非重复调用——LLM 沿上下文惯性重复失败动作（stuck loop）。对策：① 设最大步数 $\gamma$；② 观察中注入失败原因；③ 提示声明"失败时换查询方式"。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：LangChain 几十行封装整个循环：
```python
from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_core.tools import tool

@tool
def get_weather(city: str) -> str:
    """查询城市天气（模拟）"""
    return f"{city}: 37°C, 晴"

agent = create_tool_calling_agent(ChatOpenAI(model="gpt-4o-mini"), [get_weather], prompt=system_prompt)
executor = AgentExecutor(agent=agent, tools=[get_weather], max_iterations=5)
print(executor.invoke({"input": "北京天气怎么样？"}))
```

## 8. 常见误区和易混概念
### 误区 1：以为"Agent = 某个特定模型"
- **错误直觉**：ChatGPT 就是 Agent。
- **为什么错**：Agent 是**编排架构**，任何有工具调用能力的 LLM 都能当大脑。
- **正确理解**：Agent = 模型 + 工具 + 记忆 + 循环控制，缺一不可。
### 误区 2：以为"ReAct 和 Function Calling 是同一个东西"
- **错误直觉**：都是让模型调工具。
- **为什么错**：ReAct 是**提示范式**（文本格式，无需微调）；Function Calling 是**微调能力**（输出结构化 JSON）。产品常两者结合。
- **正确理解**：ReAct 解决"怎么想"，Function Calling 解决"怎么说规范"。
### 概念对比表
| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| Agent（本概念） | 自主完成任务 | 循环+工具+记忆 | 自主任务执行 |
| 对话系统 | 多轮对话 | 单轮生成、无工具 | 客服闲聊 |
| RAG | 知识外挂 | 只读检索、无多步规划 | 文档问答 |
| 工作流 pipeline | 固定流程 | 顺序执行、无决策 | 批处理 |

### 题目与解析
#### 1. LLM Agent 的四个核心组件是什么？
> [!question]- 答案解析
> - **答案**：规划器、工具集 $\mathcal{T}$、记忆 $\mathcal{M}$、控制器（LLM 本体）。
> - **解析**：缺规划无方向、缺工具只能空谈、缺记忆多轮失忆、缺 LLM 无法决策。`#自测题/基础`
#### 2. 写出"计算 12+8 再乘 2"任务的完整 ReAct 轨迹。
> [!question]- 答案解析
> - **答案**：Thought₁ 先加法 → Action₁ `calc("12+8")` → Obs₁ `20` → Thought₂ 再乘 2 → Action₂ `calc("20*2")` → Obs₂ `40` → Final: 40。
> - **解析**：Observation 必须来自工具而非模型想象；每个 Action 可被工具解析。`#自测题/基础`
#### 3. 什么场景选 ReAct 提示范式，什么场景选 Function Calling 微调？
> [!question]- 答案解析
> - **答案**：快速原型、模型不支持工具微调、偏推理任务 → ReAct；生产环境、参数须精确（API 调用）、格式稳定 → Function Calling。
> - **解析**：ReAct 零成本但格式不稳定；Function Calling 稳定但需 SFT 数据训练。`#自测题/中等`
#### 4. Agent 陷入"反复调用同一失败工具"的死循环，给出至少三种工程对策。
> [!question]- 答案解析
> - **答案**：① 设最大迭代数 $\gamma$ 强制终止；② 观察中注入失败原因与替代建议；③ 系统提示声明"重复动作无效时换策略"；④ 预算/超时控制成本。
> - **解析**：LLM 沿上下文惯性行动，外部硬控制（步数、超时、结果校验）是必要安全带。`#自测题/中等`
#### 5. 设计一个"文档问答 Agent"：说明工具集、记忆组织与循环终止条件。
> [!question]- 答案解析
> - **答案**：工具 = {向量检索 retriever, 文档读取 read, 引用定位 cite}；记忆 = 短期对话历史 + 长期文档向量索引；循环：提问 → 检索 top-k → 读文档 → 信息不足换 query 重试（≤3 次）→ 带引用作答。终止：输出 Final 或达步数上限。
> - **解析**：这是 [[检索增强生成RAG]] 与 Agent 循环的融合——检索失败"换问法"就是 ReAct 的反思能力。`#自测题/较难`
