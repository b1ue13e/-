# 句法分析
---
## 0. 先判断它值不值得深挖
- **类别**：**B 类（常用工具）**
- **判断理由**：句法分析是传统 NLP 的核心任务（CS224N A3 就是依存解析器），训练"从零写 parser"能建立结构化预测的完整直觉。深度学习时代句法知识被隐式编码进预训练模型，但依存树仍是解释性与知识图谱的上游工具；面试常考"UAS/LAS""arc-standard 算法"。
---
## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> "我昨天看见了用望远镜观测星星的科学家"——谁用望远镜？句子歧义来自结构：是"科学家用望远镜"还是"用望远镜观测"？词序列本身不携带结构信息。
> 句法分析的回答：**给句子显式结构**——① **成分句法**：递归地把句子拆成短语（NP/VP），画括号树；② **依存句法**：为每个词找"中心词"（head）并标关系（主谓/动宾/定中），画依存弧。结构一出来，"用望远镜"修饰谁一目了然；机器翻译、问答、信息抽取都受益于结构约束。
---
## 2. 为什么它重要？它有什么用？
- **连接大图景**：句法分析是 [[语言学基础]] 的"句法层"的落地任务；依存树是现代神经 parser（spaCy/Stanza）的输出；[[信息抽取]] 的依存路径特征、[[问答系统]] 的句法约束都源于它。
- **实际应用场景**：句法特征（关系抽取）、句子压缩/改写（保持结构）、语法纠错、学术研究（树库评测）。
- **高频题型/任务**：CS224N A3 手写依存 parser；面试"UAS 和 LAS 的区别""arc-standard 转移系统""依存句法与成分句法的选择"。

## 4. 用直觉语言解释它
> «"依存句法像'给句子排兵布阵'：每个词必须认一个'长官'（head），自己当'士兵'（dependent），最后所有词都听命于一个'总司令'（root）。比如'小明吃苹果'：'吃'是总司令，'小明'和'苹果'都归它管（主谓、动宾）。转移式解析像'排队入列'：从左往右扫词，手里的词要么'压栈等配对'，要么'和栈顶配对成弧'，要么'归队（还原）'——arc-standard 就是这套'入栈-配对-归队'的规则，配合神经网络打分器决定每一步走哪条。"»
- **直觉类比/几何图像**：依存树 = 有向图（一棵树：$n$ 个节点、$n-1$ 条弧、一个根）；转移系统 = 在"栈-缓冲-弧集"状态空间里走一条路径。
- **为什么很自然**：人类理解句子就是在找"谁修饰谁"；依存关系比成分树更贴近"词与词的直接联系"，标注更便宜。
- **一句话直觉本质**：**"依存句法 = 给每个词找一个 head 并标关系（有根有向树）；arc-standard 用'左归约/右归约/移进'三步操作机械地构造这棵树，神经打分器让每一步更聪明。"**
---
## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
**依存树**：对句子 $w_1,\dots,w_n$，每词有 head $h_i$（$h_i=0$ 表示 root），关系 $l_i$；约束：单头、无环、连通（构成树）。
**arc-standard 转移系统**：状态 $(\sigma, \beta, A)$（栈、缓冲、弧集），三种转移：SHIFT（缓冲首词入栈）、LEFT-ARC$_l$（栈顶两词 $s_1,s_2$ 建弧 $s_2 \to s_1$，$s_1$ 出栈）、RIGHT-ARC$_l$（建弧 $s_1 \to s_2$，$s_2$ 出栈）。
### 2. 核心公式
**打分式解析（graph-based 神经 parser）**：对每个候选弧 $(h, m)$ 打分（MLP 作用在 head/dep 表示上）：
$$s(h, m) = \text{MLP}\big([h_{\text{head}}; h_{\text{dep}}; h_{\text{rel}}]\big), \qquad \hat{y} = \arg\max_{y \in \text{树}} \sum_{(h,m)\in y} s(h,m)$$
**UAS / LAS**：
$$\text{UAS} = \frac{\text{head 正确的弧数}}{\text{总弧数}}, \qquad \text{LAS} = \frac{\text{head 与关系都正确的弧数}}{\text{总弧数}}$$
### 3. 符号说明表
| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $h_i$ | 第 $i$ 词的中心词 | $\{0,1,\dots,n\}$ | 0 = root |
| $l_i$ | 依存关系标签 | 关系集合 | 如 nsubj/obj |
| $\sigma$ | 栈 | 词序列 | 转移系统状态 |
| $\beta$ | 缓冲区 | 词序列 | 未处理词 |
| $A$ | 已建弧集 | 弧集合 | 累积输出 |
| $s(h,m)$ | 弧打分 | $\mathbb{R}$ | 神经打分器 |
### 4. 常见变体与适用条件
- **转移式解析**（arc-standard/arc-eager）：线性时间、增量、适合流式；贪心误差传播。
- **图式解析**（graph-based，如 biaffine parser）：对全部弧打分 + MST 解码（Eisner 算法），全局最优、精度更高。
- **成分句法（PCFG/CKY）**：递归短语树，适合完整结构理解；标注贵、评测复杂。
- **限制条件**：跨语言依存关系集合不一致；长距离非投影弧（交叉弧）超出 arc-standard 能力（需 swap）；树库规模限制神经模型。

## 6. 推导思路和思想来源
- **最初困难**：成分句法树标注昂贵（短语边界难标）；规则/PCFG 解析准确率低、覆盖差。
- **直接方法局限**：CKY 动态规划对 PCFG 是 $O(n^3)$ 且规则泛化差；早期依存解析靠手工特征 + 贪心决策。
- **关键"转念"**：① 依存比成分更省标注且更贴近语义关系 → 依存句法成为主流（Nivre 2003 arc-eager）；② 解析 = **序列决策**：把建树过程变成"转移动作序列"，动作打分可用分类器/神经网络（Chen & Manning 2014 首个神经转移 parser）；③ 图式视角：把解析当"给每对词打分 + 最大生成树"，与转移式互补。
- **推导主线与动机**：结构（树）→ 过程（转移系统）→ 学习（动作打分）→ 全局化（biaffine + Eisner）；每步把"结构约束"翻译成"可优化目标"。
- **为什么自然得到此结论**：树 = 局部弧的集合；只要弧打分正确，全局树由约束解码得到——"结构化预测"的标准配方。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：句子 "我 吃 苹果"，用 arc-standard 逐步解析（无关系标签）。
- **解题思路与关键步骤**：初始 $\sigma=[\text{root}], \beta=[我,吃,苹果], A=\emptyset$。① SHIFT: $\sigma=[\text{root},我]$；② SHIFT: $\sigma=[\text{root},我,吃]$；③ LEFT-ARC: 我←吃（我 是 dependent），$\sigma=[\text{root},吃]$；④ SHIFT: $\sigma=[\text{root},吃,苹果]$；⑤ RIGHT-ARC: 吃→苹果，$\sigma=[\text{root},吃]$；⑥ RIGHT-ARC: root→吃，结束。
- **最终答案**：弧集 $\{(吃,我),(吃,苹果),(root,吃)\}$——"吃"是根。
- **易错点**：LEFT-ARC 的弧方向（栈顶第二词指向栈顶）；root 只能有 RIGHT-ARC。
- **🤔 追问**：若先 SHIFT 到 $\sigma=[\text{root},我,吃,苹果]$ 再操作？—— LEFT-ARC 会先处理"吃,苹果"（右依赖），顺序不同但树相同：转移系统有多种路径到同一棵树。
### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：为什么贪心转移解析有错误传播，图式解析没有？—— 转移式每步贪心选最高分动作，一步错后续状态全错（无法回溯）；图式解析对所有弧打分后一次性解最大生成树（MST），无中间状态，全局最优。因此 biaffine 图式 parser（Dozat & Manning 2017）成为 SOTA。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：spaCy/Stanza 一行拿依存树，直接服务下游：
```python
import spacy

nlp = spacy.load("zh_core_web_sm")
doc = nlp("小明在杭州吃了苹果")
for tok in doc:
    print(f"{tok.text} <-{tok.dep_}-- {tok.head.text}")
# 小明 <-nsubj-- 吃 / 杭州 <-pobj-- 在 / 吃 <-ROOT-- 吃 / 苹果 <-dobj-- 吃
```

## 8. 常见误区和易混概念
### 误区 1：以为"UAS 高就说明解析完全正确"
- **错误直觉**：UAS 95% 就很好了。
- **为什么错**：UAS 只看 head 对错，忽略关系标签；LAS 才同时检查关系。UAS 95% 时 LAS 往往只有 92% 左右。
- **正确理解**：两者一起报；下游任务关注关系语义时看 LAS。
### 误区 2：以为"依存句法树就是成分句法树的简化版"
- **错误直觉**：同一种东西，粒度不同。
- **为什么错**：两者是不同理论：依存树节点是词（有向弧带标签）；成分树节点是短语（无向、无标签弧、递归嵌套）。"吃苹果"在成分树里是 VP 下的 NP，在依存树里是 obj 弧。
- **正确理解**：选择看任务：关系抽取用依存（弧即关系路径），完整结构理解用成分。
### 概念对比表
| 概念 | 结构单元 | 表示 | 典型评测 |
| :--- | :--- | :--- | :--- |
| 依存句法（本概念） | 词 | 有向带标签弧 | UAS/LAS |
| 成分句法 | 短语 | 递归括号树 | F1（span） |
| 词性标注 | 词 | 无结构标签 | 准确率 |
| 语义角色标注 | 谓词-论元 | 角色填充 | F1 |

### 题目与解析
#### 1. 依存句法与成分句法在表示和评测上的区别？
> [!question]- 答案解析
> - **答案**：依存：节点为词、有向带标签弧、一棵树；评测 UAS/LAS。成分：节点为短语、递归嵌套、括号树；评测 span F1。
> - **解析**：依存更贴语义关系、标注便宜；成分给出完整短语结构。`#自测题/基础`
#### 2. 用 arc-standard 解析 "猫 追 狗"（root 为"追"）。
> [!question]- 答案解析
> - **答案**：SHIFT 猫 → SHIFT 追 → LEFT-ARC（猫←追）→ SHIFT 狗 → RIGHT-ARC（追→狗）→ RIGHT-ARC（root→追）。弧：追←猫(nsubj)、追→狗(obj)、root→追。
> - **解析**：LEFT-ARC 先于 RIGHT-ARC 处理左侧依赖；root 只在最后连接。`#自测题/基础`
#### 3. 一个 parser UAS=94、LAS=90，说明了什么？
> [!question]- 答案解析
> - **答案**：head 判断 94% 正确，但关系标签多错 4 个百分点（约 2/3 的 head 错误同时是标签错误——实际是标签错误单独贡献 4%）。两者都要报告。
> - **解析**：UAS 是 LAS 的上界；差距大说明关系分类是瓶颈。`#自测题/中等`
#### 4. 转移式解析与图式解析的优缺点？
> [!question]- 答案解析
> - **答案**：转移式：线性时间、增量可流式、实现直观；贪心误差传播、无全局最优。图式：全局打分 + MST 解码最优、精度高（biaffine 是 SOTA）；$O(n^2)$ 打分、解码略重。
> - **解析**：生产快速场景用转移式（spaCy），精度优先用图式（Stanza 可选）。`#自测题/中等`
#### 5. 什么是非投影弧？arc-standard 为什么处理不了？如何扩展？
> [!question]- 答案解析
> - **答案**：非投影弧 = 两条弧交叉（弧 (i,j) 与 (k,l)，$i<k<j<l$），常见于德语/荷兰语等自由语序语言。arc-standard 的栈结构只允许嵌套（投影）弧，交叉弧无法在建弧时保持栈内顺序。扩展：加 SWAP 转移（把栈中词退回缓冲重排，Nivre 2009），或对语序受限语言直接用投影假设。
> - **解析**：投影性是转移系统可表达性的边界；汉语/英语基本投影，故 arc-standard 够用。`#自测题/较难`
