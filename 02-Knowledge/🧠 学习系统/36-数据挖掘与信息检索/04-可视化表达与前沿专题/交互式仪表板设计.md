## 💡 直觉与动机

静态图表适合报告展示，但在复杂数据分析与检索系统中，用户需要**探索式数据分析（Exploratory Data Analysis, EDA）**。

交互式仪表板（Interactive Dashboard）将多维数据、检索结果与模型评价指标有机整合，允许用户通过筛选、下钻、联动（Linked Brushing）等方式自由探索数据背后的模式。

---

## 📐 核心设计原则

### 1. Shneiderman 交互箴言 (Visual Information-Seeking Mantra)

$$\text{Overview first} \to \text{Zoom and filter} \to \text{Details-on-demand}$$

1. **先看全貌（Overview）**：提供高层级的 KPI 摘要与全局趋势。
2. **缩放与过滤（Zoom & Filter）**：允许用户限定时间段、特定类别或异常范围。
3. **按需查看细节（Details-on-demand）**：悬停或点击具体数据点时显示精确明细数据。

### 2. 联动过滤机制 (Linked Brushing)

在一个图表中选中某区域，其他相关图表自动高亮或更新过滤对应的数据点：

$$\text{Chart}_A(\text{Select Range}) \implies \text{Event} \implies \text{State Filter Update} \implies \text{Chart}_B, \text{Chart}_C \text{ Re-render}$$

## 💻 最小 Python 实现 — 基于 Plotly/Dash 逻辑的交互响应

```python
import pandas as pd

class MockDashboardState:
    """模拟 Dash/Streamlit 响应式交互状态机"""
    def __init__(self, df: pd.DataFrame):
        self.raw_df = df
        self.selected_category = None
        self.min_score = 0.0

    def update_filter(self, category: str = None, min_score: float = 0.0) -> pd.DataFrame:
        filtered = self.raw_df.copy()
        if category:
            filtered = filtered[filtered['category'] == category]
        filtered = filtered[filtered['score'] >= min_score]
        return filtered

    def render_summary(self, filtered_df: pd.DataFrame) -> dict:
        """概览指标"""
        return {
            "total_count": len(filtered_df),
            "avg_score": round(filtered_df['score'].mean(), 3) if len(filtered_df) > 0 else 0
        }

# 测试数据
df = pd.DataFrame({
    'doc_id': [f'doc_{i}' for i in range(10)],
    'category': ['IR', 'DM', 'IR', 'NLP', 'DM', 'IR', 'NLP', 'DM', 'IR', 'NLP'],
    'score': [0.95, 0.42, 0.88, 0.76, 0.31, 0.91, 0.82, 0.55, 0.67, 0.73]
})

dash = MockDashboardState(df)
# 用户在 UI 上选择 category='IR', min_score=0.80
view = dash.update_filter(category='IR', min_score=0.80)
print("联动筛选后的数据视图:\n", view)
print("顶部卡片概览:", dash.render_summary(view))
```

## ⚠️ 常见误区与避坑指南

1. **信息过载（Dashboard Cognitive Overload）**：在一个页面塞入几十张图表和控件。记住 Few 的原则：仪表板应能“在单个屏幕内一目了然传递核心信息”。

2. **忽略响应延迟**：交互响应如果超过 1 秒，会破坏用户的探索连贯性。对大数据量分析，仪表板后端必须做预聚合或使用 ClickHouse/Redis 加速查询。
