# 重排序与学习排序

---

## 0. 学习边界

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：[[🧭 开源作业体系-数据挖掘与信息检索]] 的 HW05 主题就是"混合检索与重排序"（验收：融合后 nDCG@10 ≥ 单路最优、RRF 的 k 消融、重排时延对比）；HW06 Capstone 也要跑通"BM25→Dense→Hybrid"；NDCG 是全部 HW 的统一度量，LTR 是搜索排序的核心范式。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：BM25 或稠密检索（见 [[稠密检索与评估指标]]）在千万级语料上只能做**轻量打分**——单个模型召回质量有限（BM25 词不匹配、稠密检索精确度不足），而直接在全部候选上跑强模型（大模型/深度排序器）算不动。以前的方法卡在：**单一排序器在"效率"与"效果"之间二选一**。因此引入**两阶段检索**：第一阶段（召回）用廉价模型从全库取 top-1000，第二阶段（精排）用强模型只对候选重排序。**学习排序（LTR）**把"排序"本身当成监督学习问题：用相关性标注训练排序器，按**目标函数**分为 pointwise/pairwise/listwise 三类；**RankNet/LambdaRank** 是 pairwise 的经典神经网络实现，直接近似优化 **NDCG**。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：HW05 的全部内容（RRF 融合 + 重排）；HW06 统一评测的语言；从"打分启发式"（BM25）到"学习式排序"（LTR）是检索系统演进的骨架。
- **实际应用场景**：搜索引擎精排（特征 + 神经网络/GBDT）、推荐排序、RAG 的 reranker（monoT5/coCondenser）。**高频题型/任务**：手算 nDCG@k；解释三范式区别；RankNet 损失与 LambdaRank 梯度加权；两阶段时延/效果权衡。

---

## 3. 学它之前需要哪些前置知识？

1. **[[BM25与TF-IDF]]**：第一阶段的典型召回器；LTR 特征常包含 BM25 分数。
2. **[[稠密检索与评估指标]]**：NDCG/MRR/Recall 的定义出处；HW04 的稠密召回是两阶段的第一路。
3. **梯度下降与神经网络**：RankNet 是 MLP + 逻辑损失；理解梯度与反向传播即可。

---

## 4. 用直觉语言解释它

> «"两阶段检索像'初试 + 复试'：初试（BM25/稠密）廉价但粗糙，从千万人里筛出 1000 个候选人；复试（重排器）昂贵但精准，只对这 1000 人细细打分。LTR 则像'按试卷难度加权评分'：pointwise 是每题独立判分，pairwise 是两两对比'谁排前面'，listwise 是直接对着整份榜单打分——而 NDCG 就是那张'靠前的题权重更大'的评分表。"»
- **直觉类比/几何图像**：NDCG 的 $\log_2(i+1)$ 折扣因子 = "位置越靠前越值钱"；RankNet 把排序变成"两两 PK 的胜率预测"；LambdaRank 给每对 PK 加上"交换后 NDCG 变化量"作为权重——就像裁判只关注"会改变奖牌归属的 PK"。
- **为什么很自然**：检索效果按"排在前面的相关文档"衡量（NDCG），所以排序器应该直接优化这个量，而不是逐文档分类或只做两两比较。
- **一句话直觉本质**：**召回阶段用廉价模型粗筛、精排阶段用强模型细排；LTR 用标注数据把"排序"学出来——pointwise 学分数、pairwise 学顺序、listwise 学榜单，并以 NDCG 为最终度量。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **两阶段检索**：Stage-1 召回（BM25/稠密，top-1000）→ Stage-2 精排（重排器，top-100）。
- **LTR 三范式**：pointwise（回归/分类单文档分数）、pairwise（文档对相对顺序，RankNet）、listwise（整个列表的排序分布/度量优化，ListNet、LambdaMART）。
- **RankNet**：对每对 $(i,j)$ 预测 $P(s_i>s_j)$，用交叉熵训练；**LambdaRank** 给每对梯度乘以 $|\Delta NDCG|$ 权重，直接近似优化 NDCG。
- **NDCG**：位置折扣的归一化累计增益，检索排序的默认度量。

### 2. 核心公式
**NDCG**：
$$DCG@k=\sum_{i=1}^{k}\frac{2^{rel_i}-1}{\log_2(i+1)},\qquad nDCG@k=\frac{DCG@k}{IDCG@k}$$
**RankNet（pairwise 概率 + 交叉熵）**：
$$P_{ij}=\frac{1}{1+e^{-\sigma(s_i-s_j)}},\qquad L_{ij}=-\bar P_{ij}\log P_{ij}-(1-\bar P_{ij})\log(1-P_{ij})$$
**LambdaRank 梯度（简化）**：
$$\lambda_{ij}=-\sigma\,|\Delta_{NDCG}(i,j)|\,\frac{1}{1+e^{\sigma(s_i-s_j)}}$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $rel_i$ | 第 $i$ 位的相关性等级 | 如 0-3 | 标注决定 |
| $DCG/IDCG$ | 累计增益 / 理想累计增益 | $>0$ | 归一化分母 |
| $s_i$ | 文档 $i$ 的排序分数 | $\mathbb{R}$ | 模型输出 |
| $\sigma$ | 逻辑函数陡度 | $>0$（常 1） | RankNet 超参 |
| $\bar P_{ij}$ | 真实顺序标签 | $\{0,1\}$ 或 $(0,1)$ | 文档对标签 |
| $\Delta_{NDCG}$ | 交换 $i,j$ 的 NDCG 变化 | $[-1,1]$ | LambdaRank 权重 |

### 4. 常见变体与适用条件
- **变体**：pairwise（RankNet、RankSVM、GBRank）、listwise（ListNet、LambdaMART 即 GBDT+LambdaRank）；重排器 monoT5/coCondenser；融合 RRF（无监督）vs 学习融合。**适用/限制**：两阶段收益来自"召回全但精排强"——召回漏了再强的精排也救不回（Recall 是上限）；pairwise 忽略位置权重；NDCG 的 rel 需分级标注（binary 标注下退化为位置折扣的 MRR 变体）。

---

## 6. 推导思路和思想来源

- **最初困难**：单一打分器质量有限；全量强排序不可行；分类/回归目标（pointwise）与"排序质量"不一致——把相关度分对 4 级不等于把榜单排对。**直接方法局限**：pointwise 忽略文档间相对关系；手工融合多路分数权重难调。
- **关键"转念"**：① **pairwise**：排序只需"谁在谁前面"——把训练数据变成文档对，用逻辑回归预测相对顺序（RankNet），代价函数与"排序正确率"更一致；② **listwise 度量优化**：既然最终看 NDCG，就让梯度正比于"交换位置带来的 NDCG 变化"——LambdaRank 把 pairwise 梯度乘上 $|\Delta_{NDCG}|$，这是 NDCG 的平滑近似梯度。
- **推导主线与动机**：召回（Recall 上限）→ 精排（NDCG 优化）→ 训练信号从"单文档"到"文档对"再到"整榜度量"；LambdaRank 的 $\lambda_{ij}$ 就是把"排序损失"翻译成"可反向传播的梯度"。
- **为什么自然得到此结论**：因为排序质量由"相关文档是否靠前"决定（NDCG 的折扣位置），任何不涉及位置权重的损失都与最终度量有 gap——LambdaRank 直接把 gap 补进梯度。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：3 篇文档真实相关度 $rel=[3,2,1]$（3 最相关）。排序器输出顺序为 [doc2, doc1, doc3]（即 rel 序列 [2,3,1]）。求 $nDCG@3$。
- **解题思路与关键步骤**：$DCG@3 = 2/\log_2 2 + 3/\log_2 3 + 1/\log_2 4 = 2 + 3/1.585 + 0.5 \approx 4.393$；理想排序 rel [3,2,1]：$IDCG = 3/1 + 2/1.585 + 1/2 \approx 4.762$。
- **最终答案**：$nDCG@3 \approx 4.393/4.762 \approx 0.923$。**易错点**：第一项折扣是 $\log_2(1+1)=1$ 不是 0；$2^{rel}-1$ 的指数形式不能丢。
- **🤔 追问**：若输出顺序 [doc3, doc2, doc1]（rel [1,2,3]）？——$DCG=1+2/1.585+3/2=3.762$，$nDCG=0.790$——最相关的 doc1 被排到第 3 位，即使后两位全对，分数也明显下降：NDCG 的"位置敏感"正是 LTR 要优化的东西。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：RankNet 中 $s_i=1.5, s_j=0.5$，$\sigma=1$，真实标签 $i$ 优于 $j$。求 $P_{ij}$、损失与对 $s_i$ 的梯度；再用 LambdaRank 说明梯度如何变化（设交换 $i,j$ 使 NDCG 变化 $\Delta_{NDCG}=0.1$）。
- **解题思路与完整解答**：$P_{ij}=1/(1+e^{-1})\approx0.731$；$L=-\log0.731\approx0.313$；$\partial L/\partial s_i=\sigma(P_{ij}-\bar P_{ij})=-0.269$。LambdaRank：$\lambda_{ij}=-\sigma\cdot|\Delta|\cdot P_{ij}(1-P_{ij})\approx-0.0197$——比 RankNet 的 0.269 小，因为该交换对 NDCG 影响不大。**关键推理**：LambdaRank 梯度 = RankNet 梯度 × $|\Delta_{NDCG}|$——对 NDCG 影响大的文档对（如第 1、2 位互换）获得大梯度，影响小的对梯度趋近 0，这就是"直接优化 NDCG"的实现机制。**易错点**：把 $P_{ij}$ 当排序分数本身；忘记对 $s_i,s_j$ 梯度符号相反。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HW05 验收 = 混合检索（BM25+稠密 RRF 融合，$k$ 消融）+ 重排序（monoT5），报告 nDCG@10 ≥ 单路最优与重排前后时延。代码形态：
```bash
# 两路召回融合（RRF，k=60 默认）
python -m pyserini.search.hybrid --sparse-index msmarco-v1-passage --dense-index msmarco-v1-passage.d2q-t5 --fusion-rrf --k 60 --topics msmarco-passage-dev-subset --output run.hybrid.txt
```
```python
from pygaggle.rerank.transformer import MonoT5
reranker = MonoT5()                       # T5 打分：query + doc → 相关分数
reranked = reranker.rerank(query, hits)   # hits = 第一阶段候选
```
- **实际价值与转化**：monoT5 在 MS MARCO 上把 BM25 的 MRR@10 从 ~0.19 提到 ~0.39（两阶段收益的量级参考）；代价是单查询数百 ms——这就是为什么必须只对 top-100 精排；HW05 报告里"重排前后时延对比"正是这个权衡的量化。

## 8. 常见误区和易混概念

### 误区 1：精排器强，召回随便做做就行
- **错误直觉**：两阶段里精排决定一切。
- **为什么错**：精排只能重排召回结果，**Recall 是高级**——BM25 召回 top-1000 里没有相关文档，monoT5 也无能为力；反之召回全但精排弱则精度差。**正确理解**：两阶段是接力：召回保证"不漏"（Recall@1000），精排保证"排对"（nDCG@10），HW05 验收要同时看两路的指标。

### 误区 2：pointwise 训练好就能排好序
- **错误直觉**：相关度回归/分类分数排序即可。
- **为什么错**：pointwise 忽略文档间相对关系与位置：把所有文档都打 3 分的模型分类误差很小，但排序毫无区分度；且 NDCG 的位置折扣在 pointwise 损失里不存在。**正确理解**：排序是"相对"任务，pairwise/listwise 的目标与 NDCG 更一致；pointwise 只在特征简单时够用。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| pointwise | 单文档打分 | 分类/回归，忽略相对关系 | 简单排序、特征基线 |
| pairwise（RankNet） | 文档对顺序 | 两两 PK，无位置权重 | 中小规模排序 |
| listwise（LambdaMART） | 整榜优化 | 梯度含 NDCG 变化 | 搜索引擎精排（GBDT 标配） |
| RRF 融合 | 多路分数合并 | 无监督 rank 倒数融合 | HW05 混合检索 |
| 两阶段流水线 | 效率-效果权衡 | 召回全 + 精排强 | 生产检索系统 |

### 题目与解析

#### 1. pointwise、pairwise、listwise 各自把"排序问题"简化成什么？
> [!question]- 答案解析
> - **答案**：pointwise 简化成单文档回归/分类（学相关度分数）；pairwise 简化成文档对二分类（学相对顺序）；listwise 直接对整榜建模（学排序分布或优化度量）。
> - **解析**：简化程度递减、与 NDCG 的一致性递增；pairwise 丢失位置信息（第 1、2 位互换与第 8、9 位互换同等惩罚），listwise 保留位置权重——LambdaRank 正是用 $|\Delta_{NDCG}|$ 把位置权重补回 pairwise 框架。
> - **易错原因**：把 pairwise 当"最高级"——生产环境标准是 listwise（LambdaMART）。
> - **对应误区**：误区 2（pointwise 够用论）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. $k=3$，真实 rel=[3,1,2]（按文档 ID），系统输出顺序为 [doc3, doc1, doc2]，求 nDCG@3。
> [!question]- 答案解析
> - **答案**：输出 rel 序列 [2,3,1]：$DCG=2/1+3/\log_2 3+1/\log_2 4=2+1.893+0.5=4.393$；$IDCG$（理想 [3,2,1]）$=3+2/1.585+1/2=4.762$；$nDCG=4.393/4.762\approx0.923$。
> - **解析**：注意 rel 序列按"系统输出位置"排列而非文档 ID 顺序；$2^{rel}-1$ 在 rel=3 时为 7（公式版本要统一）。**易错原因**：rel 序列排错顺序；忘记第一项 $\log_2(1+1)=1$；把 $2^{rel}-1$ 写成 $rel$。

#### 3. 两阶段检索中，召回器 Recall@1000=0.6、精排器 nDCG@10 完美（=IDCG）。最终 nDCG 的上限是多少？说明什么？
> [!question]- 答案解析
> - **答案**：上限约为 0.6——精排只能在召回到的相关文档里排；若相关文档根本没进 top-1000，精排无解。**说明**：精排效果受召回高级约束，两阶段要同时优化：先提 Recall@1000（如 doc2query、稠密融合），再提精排精度。
> - **解析**：HW05 验收"融合后 nDCG@10 ≥ 单路最优"的本质就是"用融合提 Recall，再让精排吃满 Recall"；只看精排器效果而忽视召回是全链路优化的常见盲区。**易错原因**：把两阶段当"精排一锤定音"；不做 Recall 侧诊断。

#### 4. RankNet 与 LambdaRank 的梯度有什么本质差异？为什么后者"直接优化 NDCG"？
> [!question]- 答案解析
> - **答案**：RankNet 对所有文档对一视同仁（梯度 $\propto P_{ij}-\bar P_{ij}$）；LambdaRank 给每对乘 $|\Delta_{NDCG}(i,j)|$——交换两文档对 NDCG 影响越大梯度越大。因为 NDCG 的梯度不可导，LambdaRank 用"交换位置的 NDCG 变化量"作为平滑近似，使参数更新方向近似于 NDCG 上升方向。
> - **解析**：$|\Delta_{NDCG}|$ 在相关文档排到不相关文档前面时最大（位置折扣差大），在高位互换时也大；这就是"排序损失"与"检索度量"之间的桥。**易错原因**：以为 LambdaRank 换了损失函数——它换的是**梯度加权**，训练仍是 pairwise 框架。

#### 5. 给一个 10 万文档的搜索系统设计 LTR 方案：特征、训练数据、模型、评估各给出具体选择与理由。
> [!question]- 答案解析
> - **答案**：特征 = 查询-文档对特征（BM25 各变体分、稠密相似度、PageRank/流行度、文档长度、词项覆盖）+ 查询侧特征（长度、idf 均值）；训练数据 = 历史点击日志构造 pairwise 样本（点击 > 未点击）或人工分级标注（rel 0-3，约 5k-20k 查询）；模型 = LambdaMART（GBDT+LambdaRank，特征少、可解释、工业标配）；评估 = 留出查询集上 nDCG@10 / MRR@10，与 BM25 基线配对检验显著性，并报告线上 A/B 时延。
> - **解析**：选择理由链：pairwise 样本易得（日志）→ listwise 损失与 NDCG 一致（LambdaMART）→ 评估用 NDCG 避免 MRR 只关心首位；显著性检验防止"提升是噪声"。**易错原因**：训练/评估用同一批查询（泄漏）；只用 binary 标注导致 NDCG 退化为 MRR；忽略"召回分数"这一最重要特征。
