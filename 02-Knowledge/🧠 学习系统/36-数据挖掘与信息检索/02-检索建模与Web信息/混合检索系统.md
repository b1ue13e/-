## 💡 直觉与动机

稀疏检索（BM25）和稠密检索（Dense Retrieval）各有优势：

| 特性 | BM25 稀疏检索 | 稠密检索（向量） |
|:---|:---|:---|
| **精确词匹配** | ✅ 强 | ❌ 弱 |
| **语义理解** | ❌ 弱 | ✅ 强 |
| **长尾词、专有名词** | ✅ 强 | ❌ 易漏 |
| **同义词/改写查询** | ❌ 弱 | ✅ 强 |
| **延迟** | ⚡ 极快 | 🐌 较慢 |

混合检索（Hybrid Search）将两路信号融合，取长补短，是工业界现代搜索系统的标准架构。

---

## 📐 正式定义与融合公式

### 线性加权融合

$$\text{Score}_{\text{hybrid}}(d, q) = \alpha \cdot \text{Score}_{\text{BM25}}(d, q) + (1 - \alpha) \cdot \text{Score}_{\text{dense}}(d, q)$$

问题：两路分数的量纲不同（BM25 通常 0-20；向量相似度通常 -1 to 1），直接相加需要先**归一化**（Min-Max 或 Softmax 归一化）。

### 互惠排名融合 RRF（Reciprocal Rank Fusion）

Cormack et al. 2009 提出，无需归一化，只用排名（Rank）：

$$\text{RRF}(d) = \sum_{i \in \text{rankers}} \frac{1}{k + r_i(d)}$$

其中 $r_i(d)$ 是文档 $d$ 在第 $i$ 路检索结果中的排名（从 1 开始），$k=60$ 是平滑参数（防止排名第 1 的文档分数过高）。

**RRF 的优势**：
- 无需调参 $\alpha$，直接融合不同量纲的排名
- 对排名靠前的文档给予更高权重（倒数关系）
- 在 TREC 多路融合实验中持续超越线性加权

### 工程实现选型

| 融合策略 | 适用场景 | 缺点 |
|:---|:---|:---|
| **RRF** | 快速上线，无标注数据 | 不可学习，权重固定 |
| **线性加权** | 有验证集可调参 | 需要分数归一化，量纲敏感 |
| **学习排序（LTR）** | 有点击/评分标注数据 | 需要训练，复杂度高 |

## 💻 最小 Python 实现 — RRF 融合

```python
def reciprocal_rank_fusion(
    *rankings: list[str],
    k: int = 60
) -> list[tuple[str, float]]:
    """
    互惠排名融合（RRF）
    rankings: 多个排名列表，每个列表为文档 ID 的有序序列
    返回融合后的 (doc_id, rrf_score) 列表，降序
    """
    scores: dict[str, float] = {}

    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, start=1):
            scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank)

    return sorted(scores.items(), key=lambda x: x[1], reverse=True)


# 示例：BM25 和 Dense 两路召回结果融合
bm25_results   = ["doc_A", "doc_C", "doc_B", "doc_E", "doc_D"]
dense_results  = ["doc_B", "doc_A", "doc_D", "doc_C", "doc_F"]

fused = reciprocal_rank_fusion(bm25_results, dense_results, k=60)
print("融合结果 Top-5：")
for doc_id, score in fused[:5]:
    print(f"  {doc_id}: {score:.5f}")
```

## ⚠️ 常见误区与避坑指南

1. **两路分数直接相加（未归一化）**：BM25 分数范围 0-20，余弦相似度 -1 到 1，直接相加 BM25 会完全主导结果。线性融合前必须先做 Min-Max 归一化或将两路结果各自排名后再融合（使用 RRF）。

2. **忽略 k 参数的选择**：RRF 中 $k=60$ 是经验值，$k$ 越小对排名靠前的文档越有利（马太效应越强），$k$ 越大越平滑。通常 $k \in [20, 100]$，可在验证集上网格搜索。

3. **两路召回数量不对等**：若 BM25 召回 Top-100，Dense 只召回 Top-20，则大量文档只参与 BM25 排名，RRF 结果会严重偏向 BM25。应保证两路召回数量相近（如均为 Top-100）。

4. **混合检索后不做重排序**：RRF 融合后的 Top-50 仅是粗排结果，应接一个 Cross-Encoder 精排（如 `ms-marco-MiniLM-L-6-v2`）进一步提升 NDCG。

5. **延迟预算超支**：Dense 检索需要 ANN（近似近邻）查询，延迟通常 20-50ms；加上 BM25（5-10ms）和 RRF 融合（<1ms），总延迟约 30-60ms。Cross-Encoder 精排又增加 50-200ms，需要做延迟预算规划。
