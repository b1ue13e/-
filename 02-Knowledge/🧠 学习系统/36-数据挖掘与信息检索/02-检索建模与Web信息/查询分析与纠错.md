## 💡 直觉与动机

用户输入的查询往往存在拼写错误（"infomation retriveal"）、歧义（"apple"：水果还是公司？）和语义缺口（用户说"车费"，索引中只有"交通费"）。如果系统不处理这些问题，就会出现"明明有相关文档却召回不到"的情况。

查询分析（Query Analysis）包含：**查询解析 → 纠错 → 查询改写（扩展）** 三个子任务，是搜索引擎前端处理的核心流水线。

## 📐 正式定义与关键算法

### 1. 查询预处理流水线

```
原始查询 → Tokenization → 大小写归一化 → 停用词删除 → 词干化/词形还原 → 索引词项
```

**词干化 vs 词形还原**：
- **词干化（Stemming）**：规则截断（Porter Stemmer）：`running` → `run`，快但不精确
- **词形还原（Lemmatization）**：基于词典（WordNet）：`am/is/are` → `be`，慢但准确

### 2. 编辑距离（Edit Distance / Levenshtein Distance）

$$d(s, t) = \min\text{（删除/插入/替换操作次数将 } s \text{ 变为 } t \text{）}$$

动态规划求解：

$$dp[i][j] = \begin{cases} 0 & \text{if } i=0 \text{ or } j=0 \\ dp[i-1][j-1] & \text{if } s[i] = t[j] \\ 1 + \min(dp[i-1][j],\ dp[i][j-1],\ dp[i-1][j-1]) & \text{otherwise} \end{cases}$$

时间复杂度：$O(|s| \cdot |t|)$，适用于拼写纠错（通常 $d \leq 2$ 的词认为是候选纠错项）。

### 3. 噪声信道模型（Noisy Channel Model）拼写纠错

$$\hat{c} = \arg\max_c P(c|q) = \arg\max_c \frac{P(q|c) \cdot P(c)}{P(q)} = \arg\max_c P(q|c) \cdot P(c)$$

- $P(c)$：语言模型（正确词的先验概率，用词频统计）
- $P(q|c)$：信道模型（正确词 $c$ 被误打为 $q$ 的概率，基于混淆矩阵）

### 4. 查询意图分类

搜索查询按意图分为三类（Broder 2002）：

| 查询类型 | 描述 | 示例 | 优化方向 |
|:---|:---|:---|:---|
| **导航型（Navigational）** | 找特定网站/页面 | "京东商城官网" | 确保官方页面排第一 |
| **信息型（Informational）** | 获取知识/信息 | "什么是 BM25" | 结构化内容、知识图谱 |
| **事务型（Transactional）** | 完成某个操作 | "下载 Python 3.12" | 直接提供下载链接 |

## 💻 最小 Python 实现

```python
import re
from collections import Counter

def edit_distance(s: str, t: str) -> int:
    """动态规划计算 Levenshtein 编辑距离"""
    m, n = len(s), len(t)
    dp = list(range(n + 1))
    for i in range(1, m + 1):
        prev, dp[0] = dp[0], i
        for j in range(1, n + 1):
            temp = dp[j]
            if s[i-1] == t[j-1]:
                dp[j] = prev
            else:
                dp[j] = 1 + min(prev, dp[j], dp[j-1])
            prev = temp
    return dp[n]

def spell_corrector(query: str, vocabulary: Counter, max_dist: int = 2) -> str:
    """
    基于编辑距离 + 语言模型的拼写纠错
    vocabulary: 词频字典（词 -> 出现次数）
    """
    words = query.lower().split()
    corrected = []
    for word in words:
        if word in vocabulary:
            corrected.append(word)
            continue
        # 找编辑距离 <= max_dist 的所有候选词
        candidates = [(w, edit_distance(word, w)) for w in vocabulary
                      if abs(len(w) - len(word)) <= max_dist]
        candidates = [(w, d) for w, d in candidates if d <= max_dist]
        if not candidates:
            corrected.append(word)
            continue
        # 按 P(c) * 1/(d+1) 选最优（简化噪声信道）
        best = max(candidates, key=lambda x: vocabulary[x[0]] / (x[1] + 1))
        corrected.append(best[0])
    return ' '.join(corrected)

# 示例
corpus = "information retrieval data mining search engine query processing"
vocab = Counter(corpus.split() * 100)  # 模拟词频

test_queries = ["infomation retriveal", "data minng", "serch engin"]
for q in test_queries:
    fixed = spell_corrector(q, vocab)
    print(f"'{q}' → '{fixed}'")
```

## ⚠️ 常见误区与避坑指南

1. **停用词删除过激**：在短查询（2-3词）中，删除停用词可能破坏查询语义。如"to be or not to be"全是停用词，不应删除。现代搜索引擎对短查询保留停用词。

2. **词干化跨语言误用**：Porter Stemmer 专为英文设计，中文分词后直接用英文词干化规则会完全失效。中文应使用 jieba 分词 + 同义词词典扩展。

3. **编辑距离太大（> 2）的候选过多**：edit\_distance = 3 时，英文单词的候选纠错词数量会爆炸式增长，必须配合语言模型过滤。实践中限制 max\_dist ≤ 2。

4. **纠错模型在专业词汇上失效**："BERT"、"Transformer" 不在普通词频词典中，会被错误纠错。需要维护一个专业术语白名单（不纠错）。

5. **忽略查询意图分类**：同样的关键词在不同意图下排序策略不同。"iPhone" 是导航/事务型，应优先展示官方购买页；"iPhone 评测" 是信息型，应优先展示深度测评文章。混淆意图会导致用户体验大幅下降。
