# TF-IDF与BM25

---

## 0. 学习边界

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：BM25 是稀疏检索的事实标准基线（Elasticsearch 默认、Pyserini 默认、TREC/BEIR 一切对比的"地板"）；HW03 的验收就是"自实现 BM25 与 Pyserini 官方基线对拍"，而 HW04 稠密检索、HW05 混合融合全部要跟它比较。TF-IDF 是理解"词项加权"的最小模型，跳过它无法读懂任何排序模型。
---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：
> 布尔检索（见 [[倒排索引与布尔检索]]）只回答"命中与否"，无法回答"哪篇文档更相关"——查询 "apple" 命中一篇只提一次 apple 的 1000 页文档和一篇通篇讲 apple 的短文，布尔模型一视同仁。以前的方法（词频直接相加）卡在**稀有词与常见词权重失衡**：`the` 出现 100 次远不如 `检索` 出现 1 次有价值，且长文档天然词频高，直接比词频对短文档不公平。
> 因此必须引入**词项加权**：TF-IDF 用"篇内词频 × 全局稀有度"给每个词定价，向量空间模型把文档变成向量并用余弦相似度排序；BM25 在此基础上加入**词频饱和**（k1）与**文档长度归一化**（b），成为概率检索模型的工程化实现。
---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：HW03 的全部内容；HW04 的稠密检索（见 [[稠密检索与评估指标]]）本质上是用 embedding 余弦相似度替换 BM25 的稀疏打分，评测时必与 BM25 基线对比；RAG（NLP 全栈）的 retriever 默认就是 BM25 或混合。
- **实际应用场景**：Elasticsearch 的 `BM25` similarity；Pyserini/Anserini 复现 SIGIR 论文的默认基线；面试高频题"BM25 的 k1、b 各控制什么"。
- **高频题型/任务**：手算 TF-IDF 与余弦相似度；解释 IDF 为什么取对数；k1/b 变化对打分的影响；BM25 与语言模型平滑（JM/Dirichlet）的对比。
---

## 3. 学它之前需要哪些前置知识？

1. **[[倒排索引与布尔检索]]**：倒排表提供 $tf$、$df$、文档长度等全部输入数据。
2. **对数与指数**：IDF 的对数压缩、BM25 的分式结构需要熟练的对数运算；概率检索的推导需要贝叶斯公式。
---

## 4. 用直觉语言解释它

> «"TF-IDF 就像拍卖行的估价"：一件藏品（词）在某个库房里出现次数越多越值钱（TF 高），但满大街都是的藏品（`the` 这种常见词）不值钱，反而越稀有越贵（IDF 高）。BM25 则是给估价加了两个修正：东西多到一定程度就"饱和"不再加价（k1），而且库房越大单价越便宜（b，长文档的词频要打折）。"»

- **直觉类比/几何图像**：文档是向量空间里的点，查询也是点；余弦相似度就是两个向量夹角的余弦——方向越一致越相关，与向量长度（文档篇幅）无关。词频正比于"这篇文档多强调这个词"，IDF 反比于"这个词多没区分度"，二者相乘是"强调度 × 区分度"的自然定价。
- **一句话直觉本质**：**用"篇内词频 × 全局稀有度"给词定价，把文档和查询都变成向量按方向排序；BM25 再加"词频饱和 + 长度归一"两个工程修正。**
---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **TF-IDF 权重**：$w_{t,d} = tf_{t,d} \cdot idf_t$，其中 $idf_t = \log\frac{N}{df_t}$（$N$ 文档总数，$df_t$ 含词项 $t$ 的文档数）。
- **向量空间模型（VSM）**：文档与查询各表示为 TF-IDF 向量 $\vec d, \vec q$，按**余弦相似度**排序。
- **BM25（Okapi BM25）**：概率检索模型（二值独立模型 + 词频/长度修正）的工程实现，对查询中每个词项累加打分。

### 2. 核心公式
$$\cos(\vec q, \vec d) = \frac{\vec q \cdot \vec d}{\|\vec q\| \|\vec d\|}$$
$$\text{BM25}(q,d) = \sum_{t \in q} idf_t \cdot \frac{tf_{t,d}\,(k_1+1)}{tf_{t,d} + k_1\left(1 - b + b\frac{|d|}{avgdl}\right)}$$
$$idf_t = \log\frac{N - df_t + 0.5}{df_t + 0.5}$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $tf_{t,d}$ | 词项 $t$ 在文档 $d$ 中的词频 | $\ge 0$ 整数 | 可截断为 $1+\log tf$ |
| $df_t$ | 含 $t$ 的文档数 | $1 \le df_t \le N$ | 倒排表长度 |
| $idf_t$ | 逆文档频率 | $> 0$ | 稀有词权重大 |
| $k_1$ | 词频饱和参数 | 典型 $1.2$–$2.0$ | 越大饱和越慢 |
| $b$ | 长度归一化强度 | $0 \le b \le 1$ | $b=0$ 不归一化长度 |
| $\|d\|, avgdl$ | 文档长度、平均长度 | 词数 | 长度归一化的分母 |

### 4. 常见变体与适用条件
- **变体**：BM25L（长文档修正）、BM25+（下界修正）；TF-IDF 的 $tf$ 可加 $\log$ 饱和、$idf$ 有平滑版本。
- **适用/限制**：查询与文档是词袋表示，语料无极端长文档；无法处理同义词与词汇不匹配（"car" 查不到 "automobile"）；$k_1,b$ 需按语料调（Pyserini 的 MS MARCO 默认 $k_1=0.82, b=0.68$）；BM25 是**无监督**模型，不带学习信号。
---

## 6. 推导思路和思想来源

- **最初困难**：词频直接求和使常见词与长文档主导排序，纯 tf 无区分度、纯 IDF 又忽略篇内强度。
- **关键"转念"**：① 把"稀有度"从"出现次数"中解耦出来——IDF 只由全局统计决定；② 把文档当向量，用**余弦**而不是内积消除长度影响；③ BM25 把打分来源从"启发式"换成"概率检索框架"（Robertson-Sparck Jones 二值独立模型），再从概率公式反推出词频的**饱和函数** $\frac{tf(k_1+1)}{tf+k_1}$。
- **推导主线与动机**：相关度 = 词项权重之和；词项权重 = 篇内证据（tf）× 全局区分度（idf）× 长度修正；饱和函数源自"词频收益递减"的统计观测；$b$ 控制长度归一化强度。
- **为什么自然得到此结论**：收益递减（饱和）是几乎所有排序系统的经验法则；长度归一化是因为长文档词频高的原因一半是"内容多"而非"更相关"。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：$N=1000$ 文档，词 `检索` 出现在 10 篇中，词 `的` 出现在 900 篇中。某文档 $d$ 中 `检索` 出现 3 次、`的` 出现 50 次，求两词的 TF-IDF 权重。
- **解题思路与关键步骤**：$idf_{检索} = \log(1000/10) = \log 100 \approx 4.6$，$idf_{的} = \log(1000/900) \approx 0.105$；权重 = tf × idf。
- **最终答案**：$w_{检索,d} = 3 \times 4.6 = 13.8$；$w_{的,d} = 50 \times 0.105 = 5.25$。`检索` 出现 3 次的贡献超过 `的` 出现 50 次。
- **易错点**：直接比较 tf 会误判 `的` 更重要；对数 IDF 是必要的压缩，否则稀有词权重爆炸。
- **🤔 追问**：若换 BM25 打分（$k_1=1.2, b=0.75$，$avgdl=100$ 词，$\|d\|=200$ 词）？——`检索` 项得分 $\approx idf \cdot \frac{3\times2.2}{3+1.2(1-0.75+0.75\times2)} = idf \cdot \frac{6.6}{3+1.05} \approx 1.63\cdot idf$，可见长文档的词频被明显打折。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：查询 `q = 数据 挖掘`，文档 $d_1$="数据 数据 挖掘"、$d_2$="数据 挖掘 挖掘"、$d_3$="数据 分析"，$N=100$，$df_{数据}=50$、$df_{挖掘}=10$、$df_{分析}=5$。用 TF-IDF + 余弦相似度排序。
- **解题思路与完整解答**：$idf_{数据}=\log2\approx0.69$，$idf_{挖掘}=\log10\approx2.30$。$d_1$ 向量 $(2\times0.69, 1\times2.30)=(1.39,2.30)$，$d_2$ 向量 $(0.69,4.60)$，$q$ 向量 $(0.69,2.30)$。余弦：$\cos(q,d_1)=\frac{0.69\times1.39+2.30\times2.30}{\|q\|\|d_1\|}\approx\frac{6.25}{2.40\times2.69}\approx0.97$；$\cos(q,d_2)=\frac{0.48+10.58}{2.40\times4.65}\approx0.99$。**关键推理**：$d_2$ 虽只含一次 `数据`，但两次 `挖掘`（高 IDF 词）使方向更接近查询。
- **易错点**：忘记对向量归一化就比内积——长文档内积天然大，会得到错误排序。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HW03 验收 = 自实现 BM25 与 Pyserini 官方基线对拍（Recall@100 / MRR@10 / nDCG@10 差距 ≤ 2%），并做 $k_1,b$ 网格扫描；这也是 Elasticsearch 中文检索调参的标准流程。
- 代码形态（手写 BM25 + Pyserini 对照）：
```python
import math
def bm25(query_terms, postings, dl, avgdl, N, k1=1.2, b=0.75):
    score = 0.0
    for t in query_terms:
        df = len(postings[t]); idf = math.log((N - df + 0.5) / (df + 0.5))
        tf = postings[t].get(doc_id, 0)   # 词频来自倒排表
        denom = tf + k1 * (1 - b + b * dl / avgdl)
        score += idf * tf * (k1 + 1) / denom
    return score
```
```bash
# Pyserini 官方基线：MS MARCO passage 默认参数 k1=0.82, b=0.68
python -m pyserini.search.lucene --index msmarco-v1-passage \
  --topics msmarco-passage-dev-subset --output run.bm25.txt \
  --bm25 --k1 0.82 --b 0.68
python -m pyserini.eval.trec_eval -m recall.100 -m map -m ndcg_cut.10 \
  msmarco-passage-dev-subset run.bm25.txt
```

## 8. 常见误区和易混概念

### 误区 1：TF-IDF 和 BM25 是两种并列的"模型"
- **错误直觉**：选一个用就行，效果差不多；**为什么错**：BM25 是 TF-IDF 的**概率化升级**：同样的 IDF 思路 + 词频饱和 + 长度归一，在 TREC/BEIR 上稳定优于朴素 TF-IDF。
- **正确理解**：把 TF-IDF 当"词项加权组件"，BM25 当"完整排序函数"；HW03 两个都要实现并报告差距。

### 误区 2：$k_1$ 越大越好，$b$ 越小越好
- **错误直觉**：参数越大/越小代表"更先进"；**为什么错**：$k_1 \to \infty$ 退化为线性词频（不饱和，长文档又占便宜）；$b=0$ 完全不做长度归一；二者都需在验证集上扫描（Pyserini 官方 MS MARCO 最优是 $k_1=0.82,b=0.68$）。
- **正确理解**：$k_1$ 控制"词频收益递减速度"，$b$ 控制"长度惩罚强度"，是语料相关的最优化问题。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| TF-IDF | 词项权重 | 无词频饱和、无长度归一 | 关键词提取、简单排序 |
| BM25 | 文档相关度排序 | 概率推导 + k1/b 两参数 | 搜索默认基线 |
| 向量空间模型 | 相似度排序 | 余弦相似度、可叠加任意权重 | 与 TF-IDF/BM25 组合 |
| 语言模型平滑 | 查询生成概率 | JM/Dirichlet 平滑，见下 | 概率检索（Ponte-Croft 系） |

**与语言模型平滑对比**：语言模型检索（QL）把文档打分看作"查询由文档语言模型生成的概率"，用 **Dirichlet 平滑** $\hat P(t|d)=\frac{tf_{t,d}+\mu \frac{cf_t}{|C|}}{|d|+\mu}$（$\mu$ 控制向集合先验 $cf_t/|C|$ 的折扣）。BM25 与 QL 在 TREC 上性能接近；BM25 的优势是参数解释直观（饱和 + 长度）、QL 的优势是有概率解释且天然处理零概率。两者都受"词汇不匹配"限制——这正是 [[稠密检索与评估指标|稠密检索]] 的切入点。

### 题目与解析

#### 1. 为什么 IDF 要取对数？去掉对数会怎样？
> [!question]- 答案解析
> - **答案**：对数把"稀有度"从线性放大压成温和增长，避免极端稀有词（$df=1$ 时 $\log N$）权重失控；去掉对数后权重被少数超稀有词主导，排序质量显著下降。
> - **解析**：$idf=\log(N/df)$ 的直觉是"信息量"：一个词在所有文档都出现（$df=N$）时 $idf=0$，完全无区分度。
> - **易错原因**：把 IDF 当"越大越好"的线性量，忽略对数压缩的动机。
> - **对应误区**：误区 1 的变体（把 TF-IDF 当并列模型）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. $N=1000$，`算法` 出现在 20 篇文档中，某文档出现 5 次，求其 TF-IDF 权重（tf 不截断）。
> [!question]- 答案解析
> - **答案**：$idf = \log(1000/20) = \log 50 \approx 3.91$，$w = 5 \times 3.91 \approx 19.6$。
> - **解析**：先算 IDF（全局、与文档无关），再乘篇内词频；注意若用 BM25 的平滑 IDF 公式则 $idf=\log\frac{1000-20+0.5}{20+0.5}\approx3.87$。
> - **易错原因**：把 $df_t$ 与 $tf_{t,d}$ 混淆——前者是"多少篇有这个词"，后者是"这一篇里出现几次"。

#### 3. 若把 $k_1$ 从 1.2 调到 10，检索行为会发生什么变化？
> [!question]- 答案解析
> - **答案**：词频饱和几乎消失，打分趋近"tf × idf"线性——高频词在长文档中的优势被放大，短文档被系统性低估；通常导致 MRR/nDCG 下降。
> - **解析**：$k_1 \to \infty$ 时 $\frac{tf(k_1+1)}{tf+k_1(...)} \to tf$（长度修正项也趋近 1 的倍数关系被稀释），即退化为朴素词频加权。
> - **易错原因**：认为参数越大"越精细"；正确做法是在验证集上做网格扫描（HW03 验收项）。

#### 4. BM25 与 Dirichlet 平滑语言模型（QL）的本质区别是什么？何时选 QL？
> [!question]- 答案解析
> - **答案**：BM25 是概率检索模型的工程近似（饱和 + 长度归一，参数 $k_1,b$）；QL 假设文档按语言模型生成查询，用 $\mu$ 向集合先验平滑。性能接近，但 QL 有完整的概率解释、处理零词频更自然（平滑即兜底），适合需要可解释概率的场合；BM25 参数语义更直观、调参成本低，是默认基线。
> - **解析**：两者都属于稀疏词袋模型，都受词汇不匹配限制；这是 HW03 理论对比题的标准答法。
> - **易错原因**：把 QL 的 $\mu$ 和 BM25 的 $k_1$ 混为一谈——$\mu$ 控制"向集合先验折扣"，$k_1$ 控制"词频饱和"。

#### 5. 已知 BM25 完全无法召回"同义词改写"的文档（查询 "car" 不含 "automobile"），设计一个不换模型就能缓解的方案，并说明代价。
> [!question]- 答案解析
> - **答案**：① 查询扩展：词典/同义词表把 "car" 扩展为 "car automobile vehicle" 再检索（如 RM3 伪相关反馈）；② 索引侧：doc2query 用 T5 为文档生成伪查询并加入索引。代价：扩展引入噪音会降低精确率（nDCG 可能下降），且扩展词权重需重新调 $k_1,b$。
> - **解析**：这是稀疏检索的经典边界问题，也是 HW05 混合检索（BM25 + 稠密）动机的简化版；完整解法见 [[稠密检索与评估指标]]。
