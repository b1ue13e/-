## 💡 直觉与动机

海量文本检索（如网页搜索）与频繁模式挖掘的关键性能瓶颈在于检索与匹配效率：
1. **线性扫描失效**：若对 $10^9$ 篇文档执行 $O(N)$ 暴力扫描，即使每次比较耗时 1 微秒，单次查询也需 1000 秒，无法满足工业级 50ms 响应要求；
2. **多路求交与图遍历优化**：通过**倒排链表（Posting Lists）**、**字典树（Trie / Radix Tree）**、**跳表（Skip List）**、**最小堆（Min-Heap）** 与 **图邻接表（Adjacency List）**，将匹配复杂度压缩至 $O(L)$ 或 $O(\log N)$。

---

## 📐 核心数据结构体系

### 1. 倒排索引与跳表（Inverted Index & Skip Lists）
倒排表由 **词典（Dictionary / Lexicon）** 与 **倒排记录表（Posting List）** 组成：
$$\text{Term}_i \to [(\text{DocID}_1, \text{TF}_1, [\text{pos}_1, \dots]), (\text{DocID}_2, \text{TF}_2, [\dots]), \dots]$$
- **跳表指针（Skip Pointers）**：在长度为 $P$ 的倒排链表上，每隔 $\sqrt{P}$ 步长放置跳跃指针，使双指针求交（Merge Intersection）的比较次数从 $O(P_1 + P_2)$ 显著下降至 $O(\sqrt{P_1} + \sqrt{P_2})$。

### 2. 前缀字典树（Trie & Radix Tree）
- 将词条公共前缀共享在树路径上，支持 $O(L)$ 的前缀检索、自动补全（Autocomplete）与拼写纠错（Levenshtein 自动机）。

### 3. 优先队列 / 最小堆（Min-Heap for Top-K）
- 在海量文档打分时，使用容量为 $K$ 的最小堆维护当前最高分文档，插入与维护复杂度仅为 $O(N \log K)$，避免全局 $O(N \log N)$ 排序导致的内存爆炸。

### 4. 图邻接表与转移矩阵（Sparse Adjacency List）
- 在 PageRank、HITS 与 GraphSAGE 图检索中，Web 链接图是极度稀疏的（平均每页出链仅 10~50 条），采用 CSR（Compressed Sparse Row）或字典邻接表表达稀疏随机游走转移矩阵 $\mathbf{M}$。

## 💻 最小 Python 实践：倒排链表跳跃求交与最小堆 Top-K

```python
import heapq
from typing import List, Tuple, Dict
from collections import defaultdict

class PostingNode:
    def __init__(self, doc_id: int):
        self.doc_id = doc_id
        self.skip: 'PostingNode' = None

class FastInvertedIndex:
    def __init__(self):
        self.index: Dict[str, List[int]] = defaultdict(list)

    def add_document(self, doc_id: int, tokens: List[str]):
        for t in set(tokens):
            self.index[t].append(doc_id)

    @staticmethod
    def intersect_postings(list_a: List[int], list_b: List[int]) -> List[int]:
        """双指针线性扫描求交（AND 查询），复杂度 O(|A| + |B|)"""
        res = []
        i, j = 0, 0
        while i < len(list_a) and j < len(list_b):
            if list_a[i] == list_b[j]:
                res.append(list_a[i])
                i += 1
                j += 1
            elif list_a[i] < list_b[j]:
                i += 1
            else:
                j += 1
        return res

def top_k_heap_filter(doc_scores: List[Tuple[int, float]], k: int) -> List[Tuple[int, float]]:
    """使用 Min-Heap 维持 Top-K 得分，空间 O(K)"""
    # 堆中存放 (score, doc_id)
    min_heap = []
    for doc_id, score in doc_scores:
        if len(min_heap) < k:
            heapq.heappush(min_heap, (score, doc_id))
        elif score > min_heap[0][0]:
            heapq.heapreplace(min_heap, (score, doc_id))
    return sorted([(doc_id, score) for score, doc_id in min_heap], key=lambda x: x[1], reverse=True)

# 驱动验证
if __name__ == "__main__":
    idx = FastInvertedIndex()
    idx.add_document(1, ["data", "mining", "retrieval"])
    idx.add_document(2, ["information", "retrieval", "search"])
    idx.add_document(3, ["data", "retrieval", "search"])

    # AND 检索: data AND retrieval
    matches = idx.intersect_postings(idx.index["data"], idx.index["retrieval"])
    print("AND 查询结果 DocIDs:", matches)

    # Top-2 堆打分模拟
    scored_candidates = [(1, 0.85), (2, 0.42), (3, 0.96)]
    top2 = top_k_heap_filter(scored_candidates, k=2)
    print("Top-2 最佳候选:", top2)
```

## ⚠️ 常见误区与避坑指南

1. **误区 1：在多词项求交时任意选择两两求交顺序**
   - **避坑**：若查询包含 3 个词项 $A, B, C$，其倒排链表长度分别为 $1000, 100000, 50$。应**优先从最短链表开始（按长度升序排序）**，先求交 $C \cap A$（最多 50 次比较），再与 $B$ 求交，可避免与 $10^5$ 长度链表做无谓比较。

## 🃏 Anki 卡片

**Q: 为什么倒排链表必须严格按 DocID 升序存储？**
**A**:
1. **支持 $O(|A|+|B|)$ 双指针线性求交**：若无序则两两匹配退化为 $O(|A| \times |B|)$；
2. **支持差分编码（d-gaps 压缩）**：有序存储后可记录相邻差值 $\Delta = \text{DocID}_{i} - \text{DocID}_{i-1}$，使数值极小化，适配 Variable Byte 与 Gamma 压缩编码。
