# 稠密检索与评估指标

---

## 0. 学习边界

- **类别**：**A 类（核心概念，必须深挖）**；**判断理由**：HW04-HW06 的全部内容都在这张卡上：稠密检索（Pyserini faiss 索引）、混合检索（RRF 融合）、评测指标（Recall/MRR/nDCG 是 HW03-HW06 统一的验收语言）；同时它是 RAG 系统 retriever 的理论基础，是稀疏→稠密→混合这条主线的收口。
---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：
> BM25（见 [[BM25与TF-IDF]]）只在"字面重合"上工作：查询 "car" 永远召回不了写 "automobile" 的文档，这就是**词汇不匹配（vocabulary mismatch）**。以前的方法（词袋 + 词项加权）卡在"语义等价但字面不同"上，且排序质量用词频这种表面信号近似相关度。
> 因此必须引入两样东西：**稠密检索**——用神经网络把查询和文档都编码成稠密向量（embedding），在向量空间里用余弦/内积找语义近邻（"car" 与 "automobile" 的向量很接近）；以及**检索评估指标**——因为新方法效果是否真的好、好多少，必须用 Recall/MRR/nDCG 这种统一尺子量出来，否则无法判断稠密是否值得替换 BM25。
---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：HW04 用 Pyserini 的 faiss 索引做稠密检索；HW05 把 BM25 与稠密结果用 RRF 融合（混合检索）得到最优；HW06 在 BEIR/TREC 上统一评测。RAG（NLP 全栈）的召回阶段就是这套东西。
- **实际应用场景**：faiss / Milvus / Weaviate 等向量数据库；搜索引擎的"语义检索"；面试高频题"稠密检索 vs 稀疏检索""RRF 为什么有效""nDCG 怎么算"。
- **高频题型/任务**：手算 Recall@k/MRR/nDCG；faiss IVF 与暴力检索误差对比；RRF 融合手算；稠密检索失效场景分析（领域偏移、罕见实体）。
---

## 3. 学它之前需要哪些前置知识？

1. **[[BM25与TF-IDF]]**：稀疏基线长什么样、混合要融合的是什么，必须先有对照；**向量与矩阵**：余弦相似度、内积、矩阵乘法；faiss 的 IVF 本质是 K-means。

## 4. 用直觉语言解释它

> «"稠密检索就像给每篇文档拍一张语义照片，查询来了就拍一张查询的照片，然后去相册里找最像的几张。BM25 是'按字面对暗号'，稠密检索是'按意思找相似'——说'轿车'和写'汽车'的人能被认成一路人。但照片太多时一张张比太慢，faiss 就是先按'大致风格'分几十个抽屉（聚类），只翻最近的那个抽屉（nprobe）。"»

- **直觉类比/几何图像**：embedding 把语义压进 $d$ 维空间（如 768 维），语义相近的点聚在一起；查询向量就是空间里的一个点，检索 = 找最近邻。神经编码器见过海量文本，学会把"同义改写"映射到相近区域，直接补上 BM25 的词汇不匹配短板。
- **一句话直觉本质**：**把文本变成向量、把检索变成最近邻查找（faiss 加速），再与稀疏检索融合取长补短；一切效果用 Recall/MRR/nDCG 量化。**
---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **双编码器（bi-encoder）**：查询编码器 $E_q$ 与文档编码器 $E_d$（常共享），得分 $\text{score}(q,d) = \langle E_q(q), E_d(d)\rangle$（内积）或余弦。
- **faiss 近似最近邻（ANN）**：IVF（倒排文件）先对全部文档向量做 K-means 聚类，查询时只搜最近的 $nprobe$ 个聚类。
- **混合检索与 RRF**：稀疏 + 稠密两路结果用**倒数排名融合**合并为最终排序。
- **评估指标**：Recall@k、MRR、nDCG@k（定义见下）。

### 2. 核心公式
$$\text{score}(q,d) = \cos\big(E_q(q),\, E_d(d)\big)$$
$$\text{RRF}(d) = \sum_{r \in \mathcal{R}} \frac{1}{k_{\text{rrf}} + \text{rank}_r(d)} \qquad (k_{\text{rrf}} = 60)$$
$$\text{DCG@k} = \sum_{i=1}^{k} \frac{rel_i}{\log_2(i+1)},\qquad \text{nDCG@k} = \frac{\text{DCG@k}}{\text{IDCG@k}}$$
$$\text{Recall@k} = \frac{|\text{相关文档} \cap \text{前 } k \text{ 个结果}|}{|\text{相关文档}|},\qquad \text{MRR} = \frac{1}{|Q|}\sum_{q\in Q} \frac{1}{\text{rank}(\text{首个相关结果})}$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $E_q, E_d$ | 查询/文档编码器 | $\mathbb{R}^d$（$d$=768 等） | 如 `msmarco-distilbert-dot-v5` |
| $\text{rank}_r(d)$ | 文档 $d$ 在第 $r$ 路结果中的名次 | $\ge 1$ | RRF 输入 |
| $rel_i$ | 第 $i$ 位结果的相关性 | 0/1（二值）或 0-3 分级 | TREC 常用分级 |
| $k$ | 截断位置 | 10/100/1000 | 指标后缀 |

### 4. 常见变体与适用条件
- **变体**：① 稠密索引：IVF vs HNSW vs PQ（Pyserini/faiss 默认 IVFPQ）；② 融合：RRF（免调参）vs 学习权重（alpha、LTR）；③ 重排序：先粗排（ANN）再精排（cross-encoder）。
- **适用/限制**：需训练好的编码器（零样本用 BEIR 官方模型）、语料向量可离线预计算；对**领域外**语料可能不如 BM25（BEIR 18 个数据集各有胜负）；向量索引有量化误差；分布偏移时退化明显。

## 6. 推导思路和思想来源

- **最初困难**：BM25 的词汇不匹配无法用词项信号解决；同义词扩展（词典/伪相关反馈）只能覆盖有限改写且引入噪音。
- **关键"转念"**：不建模"词与词的关系"，而是把**整个文本**映射到连续向量空间——语义相似性转化为向量距离；编码器（如 DPR、ANCE、Sentence-BERT）用对比学习让相关对靠近、不相关对远离。
- **推导主线与动机**：检索是"找语义近邻"→ 需要可比较的稠密表示 → 双编码器把查询/文档各压成一个向量（对称 vs 非对称编码）→ 亿级向量无法暴力扫描 → IVF/HNSW 用"粗分桶 + 局部精搜"近似 → 稠密与稀疏互补 → RRF 用排名而非分数融合（规避两路分数不可比）→ 用 Recall/MRR/nDCG 验证每一步是否真的变好。
- **为什么自然得到此结论**：ANN 是"先粗筛后精排"的通用工程思想；RRF 只用排名，天然免疫两路打分尺度不同的问题。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：查询 $q$ 有 3 个相关文档。系统 A 返回前 3 位为 [相关, 不相关, 相关]，系统 B 返回 [不相关, 相关, 相关]，计算 Recall@3 与 MRR（单查询）。
- **解题思路与关键步骤**：Recall@3 = 召回的相关数 / 3；MRR = 1 / 首个相关结果的位置。
- **最终答案**：A：Recall@3 = 2/3 ≈ 0.667，MRR = 1/1 = 1.0；B：Recall@3 = 2/3，MRR = 1/2 = 0.5。**关键推理**：两系统 Recall 相同但 MRR 不同——MRR 惩罚"相关结果排得靠后"，衡量"用户最早何时看到第一个好结果"。
- **易错点**：MRR 只数**第一个**相关结果，不是全部相关结果的平均位置。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：查询有 2 个相关文档（相关性 3 和 2）。系统返回 [rel=3, rel=2, rel=0]，计算 DCG@3 与 nDCG@3。
- **解题思路与完整解答**：DCG@3 = $3/\log_2 2 + 2/\log_2 3 + 0/\log_2 4 = 3 + 1.26 + 0 = 4.26$。IDCG（理想排序 [3,2,0] 相同，因恰好理想）也 = 4.26，故 nDCG@3 = 1.0。若系统返回 [2, 3, 0]：DCG = $2/1 + 3/1.585 = 2 + 1.89 = 3.89$，nDCG = 3.89/4.26 ≈ 0.913。注意分母从 $\log_2(i+1)$ 起算（$i=1$ 时 $\log_2 2 = 1$），IDCG 是"同一相关性集合的最优排列"。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HW04-HW06 的标准流水线：`pyserini.index.faiss` 建向量索引 → `pyserini.search.faiss` 稠密检索 → `pyserini.search.hybrid` RRF 融合 → `trec_eval` 输出 Recall/MRR/nDCG；HW06 在 BEIR 数据上做 BM25 vs Dense vs Hybrid 三方对比，这正是"稀疏、稠密与混合检索评测"正式作业（见 [[📚 教材挂载索引|教材挂载索引]] 的作业入口）。
- 代码形态（faiss 手写对照 + Pyserini 流水线）：
```python
import faiss, numpy as np
def brute_force(query_vec, doc_vecs, k=10):     # 手写对照：全量内积
    return np.argsort(doc_vecs @ query_vec)[::-1][:k]

nlist, nprobe, d = 100, 10, 768                 # faiss IVF：先聚类再局部搜索
index = faiss.IndexIVFFlat(faiss.IndexFlatIP(d), d, nlist)
index.train(doc_vecs); index.add(doc_vecs)
index.nprobe = nprobe
_, I = index.search(query_vec[None, :], k)      # I = 近邻文档 ID
```
```bash
# Pyserini：稠密索引 → 稠密检索 → 混合 → 评测
ENC=sentence-transformers/msmarco-distilbert-dot-v5
python -m pyserini.index.faiss --collection JsonCollection --input ./docs \
  --output ./dense-index --encoder $ENC
python -m pyserini.search.faiss --index ./dense-index --topics queries.json \
  --encoder $ENC --output run.dense.txt
python -m pyserini.search.hybrid --sparse-index ./bm25-index \
  --dense-index ./dense-index --topics queries.json --encoder $ENC \
  --output run.hybrid.txt
python -m pyserini.eval.trec_eval -m recall.100 -m ndcg_cut.10 qrels.txt run.hybrid.txt
```

## 8. 常见误区和易混概念

### 误区 1：稠密检索一定比 BM25 好
- **错误直觉**：神经网络 = 更先进 = 全面碾压；**为什么错**：BEIR 显示稠密检索在**领域偏移**数据集（如 BioASQ、Signal）上常输给 BM25，编码器没见过该领域术语就编码不准。
- **正确理解**：稠密强在语义改写与多语，弱在领域外与稀有实体；这正是 HW05 做**混合**、HW06 做**多方对比**的原因。

### 误区 2：把 Recall@k 和 MRR 当成一回事
- **错误直觉**：都是"查得全不全"的指标；**为什么错**：Recall@k 只看"前 k 里有没有相关"（不关心顺序），MRR 只看"第一个相关在哪"（不关心召回总量），nDCG 两者都管（顺序 + 分级相关）。
- **正确理解**：Recall 管"找得全"，MRR 管"第一个好结果多快出现"，nDCG 管"整体排序质量"；报告时三者并列（HW06 验收要求）。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 稀疏检索（BM25） | 字面重合 | 词袋、可解释、无需训练 | 基线、领域内语料 |
| 稠密检索 | 语义近邻 | 向量空间、需编码器 | 语义改写、多语、RAG |
| 混合检索 | 取长补短 | RRF/加权融合两路 | 生产搜索系统 |
| Recall/MRR/nDCG | 效果量化 | 全/序/序+分级 | HW03-HW06 统一验收 |

### 题目与解析

#### 1. Recall@10、MRR、nDCG@10 分别衡量什么？能否只用其中一个？
> [!question]- 答案解析
> - **答案**：Recall@10 衡量"前 10 位召回相关文档的比例"（找得全不全）；MRR 衡量"首个相关结果排多靠前"（第一个好结果多快出现）；nDCG@10 用位置折扣 + 分级相关性衡量整体排序质量。不能只用其一：Recall 不惩罚顺序、MRR 忽略召回总量、nDCG 需要分级标注。
> - **解析**：HW06 验收要求三者并列报告正是这个原因。
> - **易错原因**：把"召回率"当成排序质量的唯一标准。
> - **对应误区**：误区 2。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 查询有 2 个相关文档（排名 3 和 5），系统返回 10 条。计算 Recall@10 与 MRR。
> [!question]- 答案解析
> - **答案**：Recall@10 = 2/2 = 1.0；MRR = 1/3 ≈ 0.333。
> - **解析**：Recall 分母是"相关文档总数"（2），分子是"前 10 中命中的相关数"（2）；MRR 只取首个相关位置（3）的倒数。
> - **易错原因**：把 MRR 分母写成相关文档数；MRR 与"几个相关"无关，只与"第一个在哪"有关。

#### 3. 在什么条件下稠密检索会输给 BM25？如何验证？
> [!question]- 答案解析
> - **答案**：领域偏移（编码器训练分布 ≠ 目标语料，如生物医学、法律术语）、罕见实体与数字混合查询、低资源语种；验证方式：目标数据集上同时跑 BM25 与稠密并对比 Recall@100/nDCG@10（BEIR 18 个数据集即为此设计）——这是 HW06 的核心结论来源，"混合优于单路"并非恒真。
> - **易错原因**：默认稠密更好而不做对照实验。

#### 4. 两路结果：BM25 中文档 X 排第 2，稠密中 X 排第 10；BM25 中文档 Y 排第 100，稠密中 Y 排第 1。用 RRF（k=60）计算两文档融合分并排序。
> [!question]- 答案解析
> - **答案**：X：$1/(60+2) + 1/(60+10) = 1/62 + 1/70 ≈ 0.0304$；Y：$1/(60+100) + 1/(60+1) = 1/160 + 1/61 ≈ 0.0226$。融合排序 X 在前。
> - **解析**：RRF 只看排名不看分数，所以两路尺度不同也能相加；k=60 是经验值，k 越小对高名次越敏感（HW05 需消融）。
> - **易错原因**：直接把两路分数相加（BM25 分数与内积分数不可比）；忘记 $k$ 是加在分母的常数。

#### 5. 设计一个生产级混合检索系统，说明你的召回、融合、评估三步决策及理由。
> [!question]- 答案解析
> - **答案**：① 召回：BM25（处理领域词）+ 稠密（faiss IVF，$nprobe$ 按时延调），各自 top-100；② 融合：先 RRF 无监督基线，有人工标注再用学习权重（alpha/LTR）并保留消融；③ 评估：报告 Recall@100、MRR、nDCG@10 与 p95 时延，附失败案例分析。"基线优先、融合可解释、指标统一、案例兜底"即覆盖 HW05/HW06 验收要点。
> - **易错原因**：跳过朴素基线直接上复杂融合；只报平均指标不分析失败案例。
