# 🧭 开源作业体系-数据挖掘与信息检索

> 本页是「数据挖掘与信息检索」开源教材与作业的**唯一挂载点**：教材主线、作业链 HW01-HW06、知识点覆盖矩阵、验收方式全部在此对齐。工程实践来源：**Pyserini**（https://github.com/castorini/pyserini / 文档 https://pyserini.readthedocs.io），研究重现以 **Anserini**（https://github.com/castorini/anserini）为参照，评测数据用 **TREC** 与 **BEIR** benchmark，教材主线用 *Introduction to Information Retrieval* 开源版（https://nlp.stanford.edu/IR-book/）。

---

## 📚 教材主线（Spine）

| 角色 | 来源 | 用途 |
|:---|:---|:---|
| 主线教材 | *Introduction to Information Retrieval*（Manning, Raghavan, Schütze，官方开源版） | 倒排索引 → 检索模型 → 评测 → Web 检索的完整理论链 |
| 工程实践 | Pyserini（Apache-2.0，Python 版 Anserini） | BM25 / Dense / Hybrid 检索的标准脚本与评测工具，即本体系 HW02-HW06 的官方对照实现 |
| 研究重现 | Anserini（Java） | 复现 NeurIPS/SIGIR 论文结果（如 doc2query、BM25+RM3）；用官方 `repro` 脚本对照我们自己的复现 |
| 评测数据 | TREC 数据集（如 MS MARCO passage/dev、DL 2019-2023）+ BEIR benchmark（https://github.com/beir-cellar/beir，18 个零样本检索数据集） | 全部 HW 的统一定量与验收口径 |
| 验收源 | Stanford CS246（https://web.stanford.edu/class/cs246/） | 只作 HW01 的习题/项目与验收口径，默认 `link-only` |

**Honor Code 说明**：Pyserini 的官方脚本可运行、可对照，但每个 HW 必须**自实现一份对照实现**（HW02-HW06 手写索引/打分/融合/评测，HW01 手写 MinHash-LSH 与 FP-Growth），先自实现、再跑官方脚本、最后对齐指标并报告差异；BEIR 数据只读不复制官方答案。

| HW02 | 倒排索引与布尔检索 | 建索引：`python -m pyserini.index.lucene --storePositions --storeDocvectors`；布尔查询对照：`python -m pyserini.search.lucene` | [[倒排索引与布尔检索]] | 自实现倒排表与 Pyserini 索引逐项对拍；布尔查询结果与手算一致；建索引时延与内存记录 |
| HW03 | BM25 与 TF-IDF 检索 | 检索：`python -m pyserini.search.lucene --bm25 --k1 0.9 --b 0.4`；评测：`python -m pyserini.eval.trec_eval -m recall.100 -m map -m ndcg_cut.10` | [[BM25与TF-IDF]]、[[倒排索引与布尔检索]] | Recall@100、MRR@10、nDCG@10 与 Pyserini 官方基线差距 ≤ 2%；k1/b 参数扫描报告 |
| HW04 | 稠密检索与向量相似度 | 稠密检索：`python -m pyserini.search.faiss --encoder sentence-transformers/msmarco-distilbert-dot-v5`；索引：`python -m pyserini.index.faiss` | [[稠密检索与评估指标]]、[[BM25与TF-IDF]] | Recall@100、MRR@10；faiss IVF 近似结果与暴力全量结果误差 < 1%；编码时延/单查询时延 |
| HW05 | 混合检索与重排序 | 混合：`python -m pyserini.search.hybrid --sparse-index ... --dense-index ...`；RRF 融合参数对照 | [[稠密检索与评估指标]]、[[BM25与TF-IDF]] | 融合后 nDCG@10 ≥ 单路最优；RRF 的 k 值消融；重排序前后时延对比 |
| HW06 | BEIR/TREC 完整评测项目 | 评测：`python -m pyserini.eval.trec_eval -m recall.100 -m ndcg_cut.10`；BEIR 加载：`beir` 包 / `pyserini.eval.beir_eval` | 三篇知识点笔记 + [[🗺️ 数据挖掘与信息检索学习路径\|学习路径]] | 在 ≥2 个 BEIR 数据集 + 1 个 TREC DL 数据集上跑通 BM25→Dense→Hybrid；报告 Recall/MRR/nDCG、时延与失败案例分析 |

> 分层验收原则：HW01 是挖掘链（数据挖掘底座，可与 [[../10-数据结构与算法/数据挖掘与信息检索 - HW01：LSH 近邻查找与 FP-Growth 阶梯作业\|HW01 说明书]] 并行）；HW02-03 是稀疏检索链（必须顺序完成，自实现为硬要求）；HW04-05 是稠密/混合链（HW03 完成后可并行）；HW06 是 Capstone 结课项目（全部链路的统一评测与报告）。

## ✅ 验收方式与评分

1. **Pyserini 跑通 BM25 基线**：HW03 起先在官方脚本上复现 MS MARCO 或 TREC DL 的官方基线分数（Recall@100 / MRR@10 / nDCG@10），作为所有后续实验的参照系。
2. **自实现对照**：每个 HW 必须手写一份对照实现（HW02 手写倒排索引与布尔合并、HW03 手写 BM25 打分、HW04 手写向量相似度、HW05 手写 RRF 融合），与 Pyserini 输出逐条对拍并报告最大差异。
3. **评估指标报告**：每个 HW 交付统一报告——指标（Recall / MRR / nDCG@k）、时延（建索引、单查询、批量查询）、失败案例（至少 3 个检索错误样例并分析原因）。
4. **满分 Rubric**：官方脚本跑通并记录复现命令（30 分）+ 自实现与官方对拍一致（30 分）+ 指标/时延/案例报告完整（25 分）+ HW06 Capstone 含一次消融（15 分）= 100 分。
