# 查询扩展与伪相关反馈

---

## 0. 学习边界

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：[[🧭 开源作业体系-数据挖掘与信息检索]] 的 HW05 进阶项（RM3 / doc2query），也是 Anserini 官方 `repro` 脚本的经典重现对象（BM25+RM3 是 SIGIR 论文复现基线）；"查询太短、词不匹配"是 [[BM25与TF-IDF|稀疏检索]] 的头号痛点，PRF 是零成本缓解方案，面试高频。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：用户查询平均 2-3 个词，且用词与文档不一致——搜 "car repair" 找不到通篇讲 "automobile maintenance" 的文档（**词汇不匹配**）。直接改模型（上稠密检索）成本高；人工同义词词典覆盖有限、维护昂贵。以前的方法卡在：**查询太短，信息量不足**，而 BM25 只能对"查询里已有的词"打分。因此引入**查询扩展**：给查询补充相关词项再检索。**伪相关反馈（PRF）**假设"第一次检索的前 k 篇就是相关文档"，从里面统计提取扩展词——零人工、全自动；**RM3** 是其中最经典的统计实现；**doc2query** 则反过来在**索引侧**用 T5 为每篇文档预生成"伪查询"并写入索引，让文档更容易被搜到。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：HW05 进阶实验与 HW06 消融素材；PRF 是"两阶段检索"里第一阶段的经典增强（衔接 [[重排序与学习排序]]）；Anserini 的 BM25+RM3 是 TREC 论文复现基线。
- **实际应用场景**：Elasticsearch 的 `rm3` 查询重写；查询改写/建议；RAG 的 query expansion 前身；doc2query 是工业索引增强标配。**高频题型/任务**：写 PRF 四步骤；手算 Rocchio 与 RM3；解释 query drift；对比查询侧与索引侧扩展。

---

## 3. 学它之前需要哪些前置知识？

1. **[[BM25与TF-IDF]]**：打分函数与词项权重；扩展词的最终效果仍由 BM25 打分体现。
2. **概率统计**：条件概率、加权平均与插值（$\lambda$ 混合分布）；RM1/RM3 都是概率模型的变形。
3. **[[倒排索引与布尔检索]]**：词项统计（tf/df）与倒排表是扩展词提取的数据来源。

---

## 4. 用直觉语言解释它

> «"PRF 像先做一遍试卷再借阅高分同学的笔记"：第一次检索（BM25）相当于自己先答一遍，前 k 篇结果当"高分同学的答案"；从这些答案里统计高频词（笔记里反复出现的知识点）补充进查询，再答一遍。doc2query 则反过来：给每本书提前"预写它可能被搜到的问题"贴进目录——用户搜"怎么写诗"也能命中一本通篇讲格律的书。"»
- **直觉类比/几何图像**：Rocchio 是向量空间里的"移动查询点"——向相关文档质心靠近、远离不相关文档质心；RM3 是词项分布层面的"加权混合"——把伪相关集合的词分布与原查询词分布按 $\lambda$ 混合。
- **为什么很自然**：相关文档是查询的"展开版本"——与查询共现的高频词正是缺失的语义线索，统计共现代替人工词典。**一句话直觉本质**：**先粗搜一轮拿到"伪相关文档"统计扩展词重写查询（PRF/RM3），或提前为每篇文档生成可能被搜到的问题（doc2query）——都在补"查询-文档"间的词汇鸿沟。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
- **查询扩展（Query Expansion）**：把查询 $q$ 改写为 $q'$（加入同义/相关词项），再执行检索。
- **伪相关反馈（PRF）**：四步——① BM25 初检取 top-$k$ 文档 $D_r$；② 假设 $D_r$ 相关；③ 从 $D_r$ 统计/学习扩展词；④ 用扩展后的 $q'$ 重新检索。无人工标注、全自动。
- **RM3**：相关性模型（Lavrenko & Croft）的工程版本——用 RM1 估计"相关文档集合的词项分布"，再与原查询词项分布做词级插值。
- **doc2query**：用 T5 对每篇文档生成 $m$ 个伪查询，追加进文档后重建索引——索引侧扩展，查询侧零改动。

### 2. 核心公式
**Rocchio（向量空间）**：
$$q'=\alpha\,q_0+\beta\,\frac{1}{|D_r|}\sum_{d\in D_r}\vec d-\gamma\,\frac{1}{|D_{nr}|}\sum_{d\in D_{nr}}\vec d$$
**RM1（相关文档词项分布）**：
$$P(w\mid R)\propto\sum_{d\in R}P(w\mid\theta_d)\,P(q\mid d)\approx\sum_{d\in R}\frac{tf_{w,d}}{|d|}\cdot\frac{score(q,d)}{\sum_{d'\in R}score(q,d')}$$
**RM3（词级插值）**：
$$P(w\mid q)_{RM3}=(1-\lambda)\,P(w\mid q)_{ML}+\lambda\,P(w\mid R)$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $q, q'$ | 原查询、扩展查询 | 词项集合/向量 | 扩展后重新检索 |
| $D_r, D_{nr}$ | 伪相关 / 不相关文档集 | 各 $k$ 篇 | top-$k$ 与 bottom 样本 |
| $\alpha,\beta,\gamma$ | Rocchio 权重 | $\ge0$ | 常见 $\alpha=1,\beta=0.75,\gamma=0.15$ |
| $\lambda$ | RM3 插值系数 | $[0,1]$ | 越大越依赖伪相关集 |
| $R$ | 相关文档集合（伪） | top-$k$ | PRF 的核心假设 |
| $m$ | doc2query 生成数 | 如 10-40 | 越多召回越高、索引越大 |

### 4. 常见变体与适用条件
- **变体**：Rocchio（VSM）、RM1/RM3（概率）、KL 散度反馈（语言模型）；doc2query（T5）与 docTTTTTquery；查询侧 vs 索引侧。**适用/限制**：初检质量差时 PRF 放大错误（query drift）；短查询收益最大；$\lambda$、$k$ 需在验证集调（MS MARCO 常用 $k=10,\lambda=0.6$ 附近）；doc2query 需 GPU 与索引重建成本。

---

## 6. 推导思路和思想来源

- **最初困难**：词汇不匹配下 BM25 对"未命中词"零贡献；人工词典不可扩展。**直接方法局限**：同义词表覆盖有限且不分领域；显式反馈效果好但需用户标注——PRF 把"标注"替换成"假设"。
- **关键"转念"**：① **假设即标注**：top-$k$ 文档大概率相关（BM25 的精度在前几位通常可观），直接用它们当相关文档；② **文档是查询的展开**：$P(w|R)$ 中与查询共现的词项就是缺失的语义线索——RM1 用词频×查询似然加权统计；③ **插值防漂移**：RM3 把扩展分布与原始查询分布混合（$(1-\lambda)P(w|q)+\lambda P(w|R)$），保住原查询词项的主导地位。
- **推导主线与动机**：检索 → 取 top-$k$ → 估计相关集合词分布（RM1）→ 与查询分布混合（RM3）→ 扩展查询重检。doc2query 则是把同一目标搬到索引侧：文档 → 生成伪查询 → 写入索引。
- **为什么自然得到此结论**：因为"相关文档里反复出现的词"与"查询意图"天然共现；统计共现比人工词典更贴合语料；插值是因为"扩展过度"与"不扩展"之间需要可调的折中。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：词表 $\{检索, 排序\}$。$q_0=(1,0)$；$D_r$ 两文档向量平均 $(0.8,0.6)$；$D_{nr}$ 平均 $(0.2,0.1)$。取 $\alpha=1,\beta=1,\gamma=0.5$，求 $q'$。
- **解题思路与关键步骤**：$q'=(1,0)+1\times(0.8,0.6)-0.5\times(0.2,0.1)=(1.7,0.55)$。
- **最终答案**：$q'=(1.7,0.55)$——第二维（排序）从 0 获得 0.55 权重，扩展后检索会命中讲排序的文档。**易错点**：忘记减去不相关文档质心（$\gamma$ 项）；$\beta,\gamma$ 是平均向量前的系数不是逐文档系数。
- **🤔 追问**：若 $D_{nr}$ 平均 $(0.9,0.9)$？——$q'=(1.0, -0.05)$，第二维变负，说明"不相关文档也高频出现排序"时扩展词被惩罚——这正是 Rocchio 用负反馈抑制噪音词的机制。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：查询 $q=$"retrieval models"，BM25 初检 top-2：$d_1$（retrieval×3, ranking×2, neural×1）、$d_2$（retrieval×2, ranking×1, feedback×2）。用 RM1 估计 $P(w|R)$（词频加权、忽略 $P(q|d)$ 差异），再取 $\lambda=0.5$ 求 RM3 分布并选扩展词。
- **解题思路与完整解答**：RM1（未归一）：retrieval 5, ranking 3, neural 1, feedback 2 → 归一化 $P(w|R)=(0.45,0.27,0.09,0.18)$。原查询分布 $P(w|q)_{ML}$：retrieval 0.5, models 0.5。RM3（$\lambda=0.5$）：retrieval $0.5\times0.5+0.5\times0.45=0.475$，models 0.25，ranking 0.135，feedback 0.09，neural 0.045。扩展词按 RM3 概率选 top-2：ranking 与 feedback。
- **关键推理**：feedback 词出现是因为 $d_2$ 本身讲"相关反馈"——加进查询可能把结果带向 PRF 论文而非"检索模型"，这就是 **query drift** 的微观示例；$\lambda$ 调小（如 0.3）可压住这类噪音词。**易错点**：把 RM3 当成"把文档向量加进查询"（那是 Rocchio）——RM3 是词项分布层面的插值。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HW05 进阶 = 在 Pyserini 上跑 BM25 与 BM25+RM3 对比 nDCG@10/Recall@100（Anserini repro 标准），并用 doc2query 重建索引再对比；至少 3 个查询做漂移案例分析。代码形态：
```bash
# 查询侧：BM25 + RM3（Anserini 复现标准）
python -m pyserini.search.lucene --index msmarco-v1-passage \
  --topics msmarco-passage-dev-subset --output run.rm3.txt \
  --bm25 --rm3 --k1 0.82 --b 0.68
python -m pyserini.eval.trec_eval -m ndcg_cut.10 -m recall.100 msmarco-passage-dev-subset run.rm3.txt
```
```python
# 索引侧：doc2query（T5 生成伪查询后重建索引，查询侧代码不变）
from transformers import T5ForConditionalGeneration, T5Tokenizer
model = T5ForConditionalGeneration.from_pretrained("castorini/doc2query-t5-base-msmarco")
tok   = T5Tokenizer.from_pretrained("castorini/doc2query-t5-base-msmarco")
# 每篇文档：tok(doc) → model.generate(num_return_sequences=10) → 伪查询追加进文档重建索引
```
- **实际价值与转化**：RM3 在 TREC 上通常给 nDCG@10 带来 5-15% 相对提升但非所有查询都受益；doc2query 的代价是索引膨胀（MS MARCO 约 1.5-3 倍）与生成耗时，收益在 Recall 端更明显——HW05 报告里两类扩展都要有消融。

## 8. 常见误区和易混概念

### 误区 1：PRF 一定能提升检索效果
- **错误直觉**：多加了信息，结果只会更好。
- **为什么错**：初检结果本身可能差（查询歧义、语料难），伪相关文档里混入噪音词会把查询带偏（**query drift**）；TREC 上 PRF 对约 70-80% 查询有效，部分查询大幅下降。**正确理解**：PRF 是"期望收益"而非"保证收益"，必须消融并做失败案例分析（HW05 验收要求）。

### 误区 2：RM3 的 $\lambda$ 越大越激进越好
- **错误直觉**：扩展越多越能补足词汇鸿沟。
- **为什么错**：$\lambda\to1$ 时查询完全由伪相关集主导，原查询词项被淹没，漂移风险最大化；$\lambda\to0$ 退化为不扩展。**正确理解**：$\lambda$ 是"信任伪相关集程度"的旋钮，需在验证集上扫描（MS MARCO 常用 0.5-0.9 区间）；$k$ 与 $\lambda$ 联动调。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 查询侧扩展（RM3/Rocchio） | 查询太短 | 检索时动态改写查询 | 在线查询、小改动 |
| 索引侧扩展（doc2query） | 文档搜不到 | 建索引时静态增强文档 | 离线索引、Recall 优先 |
| 词典扩展 | 同义词覆盖 | 人工/静态、领域受限 | 垂直领域词表 |
| 稠密检索 | 语义匹配 | embedding 相似度，无扩展需求 | [[稠密检索与评估指标\|HW04]] |

### 题目与解析

#### 1. 伪相关反馈与（显式）相关反馈的本质区别是什么？
> [!question]- 答案解析
> - **答案**：显式反馈用**用户标注**的相关/不相关文档（准确但昂贵、有交互成本）；伪相关反馈用**系统假设**——直接拿 BM25 初检 top-$k$ 当相关文档（零人工，但假设可能出错）。
> - **解析**：两者共享"从相关文档提取词项扩展查询"的机制；PRF 用"精度换取可用性"，代价是初检错误被放大（query drift）。
> - **易错原因**：把"伪"理解为"假的扩展词"——伪的是"相关标注"，扩展词本身是真实词频统计；对应误区 1（PRF 必胜）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 词表 $\{a,b\}$，$q_0=(1,0)$，$D_r$ 平均 $(0.6,0.4)$，$D_{nr}$ 平均 $(0.9,0.8)$，$\alpha=\beta=1,\gamma=0.5$。求 $q'$ 并解释第二维符号。
> [!question]- 答案解析
> - **答案**：$q'=(1,0)+(0.6,0.4)-0.5(0.9,0.8)=(0.7,0.0)$。
> - **解析**：第二维 $0.4-0.4=0$——"b 词"在相关与不相关文档中同样高频，无区分度，扩展权重被负反馈抵消为 0。这正是 Rocchio 用 $\gamma$ 项抑制噪音词的机制；若 $D_{nr}$ 中 b 更少，b 才会获得正权重。**易错原因**：漏掉 $\gamma$ 项；不理解负反馈的作用是"降权"而非"删除词项"。

#### 3. 什么情况下 PRF 会显著伤害效果？举一个具体场景。
> [!question]- 答案解析
> - **答案**：初检 top-$k$ 质量差时——如歧义查询 "jaguar"（动物/汽车品牌混排）、稀有领域查询（top-10 全是噪音），扩展词把查询带向错误主题（query drift），重检后结果比不扩展更差。
> - **解析**：PRF 的收益上限由初检精度决定；缓解手段：调小 $k$、调小 $\lambda$、词项过滤（停用词/超高频词）、对扩展词加权而非全收。**易错原因**：只报"PRF 平均提升"不分析失败查询——HW05 验收明确要求失败案例分析。

#### 4. RM3（查询侧）与 doc2query（索引侧）在"扩展什么、何时扩展、代价在哪"三方面的对比。
> [!question]- 答案解析
> - **答案**：扩展对象：查询（RM3 动态改写 $q$）vs 文档（doc2query 静态追加伪查询）；时机：每次检索在线执行 vs 建索引离线一次；代价：RM3 增加查询时延与漂移风险，doc2query 增加索引膨胀（1.5-3 倍）与 GPU 生成成本，但查询侧零改动、无在线漂移。
> - **解析**：两者可叠加（doc2query 索引 + RM3 查询 = 双侧扩展）；衡量维度：nDCG@10（RM3 强项）与 Recall@100（doc2query 强项）。**易错原因**：以为 doc2query 是"模型微调"——它不改变检索模型，只改索引内容。

#### 5. 设计一个 PRF 消融实验验证"RM3 在 MS MARCO 上是否值得上线"，写出变量、对照、指标与结论判据。
> [!question]- 答案解析
> - **答案**：固定索引与评测集（msmarco-passage-dev-subset）；自变量 = $(\lambda,k)$ 网格（如 $\lambda\in\{0,0.3,0.6,0.9\}$，$k\in\{5,10,20\}$，$\lambda=0$ 即 BM25 基线）；对照 = BM25 官方基线（$k_1=0.82,b=0.68$）；指标 = nDCG@10 / Recall@100 / 单查询时延；判据 = 存在 $(\lambda,k)$ 使 nDCG@10 显著优于基线（配对检验或 ≥5% 相对提升）且时延增幅可接受，并报告至少 3 个失败查询的漂移分析。
> - **解析**：λ=0 即基线——消融必须含"不扩展"对照；时延是 PRF 上线的真实代价（两遍检索）；失败案例分析把"平均提升"变成"可解释的收益分布"。**易错原因**：只报最佳参数不报网格全貌；没有基线对照就宣称"PRF 有效"。
