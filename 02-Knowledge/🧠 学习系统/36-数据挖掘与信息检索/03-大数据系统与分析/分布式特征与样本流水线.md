## 💡 直觉与动机

在工业级数据挖掘与搜索引擎中，训练模型的数据量常常达到 TB/PB 级别。单机特征提取完全无法满足要求，必须建立分布式特征与样本流水线。

流水线要解决两大核心痛点：
1. **特征穿越（Feature Leakage）**：训练时使用了未来的预测信息（如将用户当天的点击总数作为当天早些时候决策的特征）。
2. **线上线下一致性（Online-Offline Consistency）**：离线 Spark 计算特征逻辑与线上 C++/Java 服务的特征逻辑不一致，导致模型上线后性能崩溃。

## 📐 正式定义与数据流架构

### 工业级样本特征流水线架构

```
用户行为日志 (Kafka/HDFS) ──▶ 分布式 ETL (Spark/Flink) ──▶ 特征存储 (Feature Store)
                                                                 │
      ┌──────────────────────────────────────────────────────────┴─────────────────────────┐
      ▼                                                                                    ▼
离线训练样本集（TFRecord/Parquet）                                                线上实时特征 (Redis/Cassandra)
      │                                                                                    │
      ▼                                                                                    ▼
模型训练 (TensorFlow/PyTorch) ─────────────────────────────────────────────────▶ 在线推理 (Triton/C++ Service)
```

### 观察窗口与点时间连接（Point-in-Time Join）

为了防止特征穿越，特征与标签连接必须满足时间戳因果律：

$$\text{Feature}(t_{\text{feature}}) \quad \text{WHERE} \quad t_{\text{feature}} < t_{\text{label}}$$

数据流水线采用 **As-Of Join**：对每个事件时间 $t$，匹配在 $t$ 之前最新更新的特征版本。

---

## 💻 最小 Python 实现 — 防穿越时间对齐 Join

```python
import pandas as pd

def point_in_time_join(events_df: pd.DataFrame, features_df: pd.DataFrame, on_key: str) -> pd.DataFrame:
    """
    模拟工业级 Point-in-Time Join (点时间防穿越连接)
    events_df: 含 entity_id, event_time, label
    features_df: 含 entity_id, feature_time, feature_val
    """
    # 按照时间升序排列
    events = events_df.sort_values('event_time')
    features = features_df.sort_values('feature_time')

    # 执行 merge_asof
    merged = pd.merge_asof(
        events,
        features,
        by=on_key,
        left_on='event_time',
        right_on='feature_time',
        direction='backward'  # 严格获取 <= event_time 的最新特征
    )
    return merged

# 测试
events = pd.DataFrame({
    'user_id': [101, 101],
    'event_time': pd.to_datetime(['2026-08-01 12:00:00', '2026-08-01 18:00:00']),
    'label': [1, 0]
})

features = pd.DataFrame({
    'user_id': [101, 101, 101],
    'feature_time': pd.to_datetime(['2026-08-01 08:00:00', '2026-08-01 15:00:00', '2026-08-01 20:00:00']),
    'user_3d_clicks': [5, 12, 20]
})

joined = point_in_time_join(events, features, 'user_id')
print(joined[['user_id', 'event_time', 'feature_time', 'user_3d_clicks', 'label']])
```

## ⚠️ 常见误区与避坑指南

1. **直接用全局特征均值填补缺失值**：计算全局特征统计量时使用了包含测试集甚至未来的数据，导致特征泄露。必须按时间窗口滚动计算统计量。

2. **忽略在线离线特征存储格式转换开销**：离线通常用 Parquet/ORC（列式存储），在线用 Redis/Key-Value（行式/KV）。如果在流水线中不统一 schema，会导致解析开销极大。

3. **流水线未实现幂等性（Idempotency）**：任务失败重试时导致数据重复写入样本库，引起分布倾斜。需通过分区重写覆盖保证幂等。
