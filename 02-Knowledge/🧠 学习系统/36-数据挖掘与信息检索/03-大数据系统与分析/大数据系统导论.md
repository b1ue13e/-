## 💡 动机与直觉

随着数据量突破单机内存与单盘容量瓶颈（PB 级甚至 EB 级），传统关系型数据库（RDBMS）在吞吐量、容错性与水平扩展性方面遭遇瓶颈。

**大数据系统（Big Data Systems）** 专注于分布式数据存储、可扩展并行计算与高容错性设计。核心理念从“升级单机硬件（Scale-Up）”转变为“使用廉价通用服务器集群进行水平扩展（Scale-Out）”。

## 📐 5V 特征与系统架构分类

### 1. 大数据的 5V 特征
- **Volume（海量）**：数据规模从 TB 跨越到 PB/EB 级。
- **Velocity（高速）**：数据实时生成并要求毫秒至秒级处理。
- **Variety（多样）**：结构化表、半结构化 JSON/XML、非结构化文本/视频/图。
- **Veracity（真实）**：数据包含噪声、缺失值与脏数据。
- **Value（低价值密度）**：单位数据价值极低，需提炼出高价值知识。

### 2. 分布式系统的 CAP 定理与 BASE 理论
在分布式存储系统中，**CAP 定理**指出以下三个要素最多只能同时满足两个：

$$\text{Consistency (一致性)} + \text{Availability (可用性)} + \text{Partition Tolerance (分区容错性)} \implies \text{只能 3 选 2}$$

在大数据领域，网络分区 $P$ 是必然发生的，因此主流大数据系统在 $CP$（如 HDFS、HBase）与 $AP$（如 Cassandra、DynamoDB）之间做出权衡，引入 **BASE 理论**（Basically Available, Soft state, Eventual consistency）追求最终一致性。

## 💻 最小 Python 实践：分布式 MapReduce 仿真

```python
from typing import List, Tuple
from collections import defaultdict

def mock_map(doc_id: int, text: str) -> List[Tuple[str, int]]:
    """Map 阶段：将文档拆分为 (word, 1) 键值对"""
    results = []
    for word in text.lower().split():
        results.append((word, 1))
    return results

def mock_reduce(word: str, counts: List[int]) -> Tuple[str, int]:
    """Reduce 阶段：对相同 Key 的 Value 进行归约"""
    return (word, sum(counts))

# 仿真驱动
if __name__ == "__main__":
    docs = [
        "Big data systems processing",
        "Distributed data storage and processing"
    ]

    # 1. Map 阶段
    mapped = []
    for idx, doc in enumerate(docs):
        mapped.extend(mock_map(idx, doc))

    # 2. Shuffle / GroupBy 阶段
    shuffled = defaultdict(list)
    for word, count in mapped:
        shuffled[word].append(count)

    # 3. Reduce 阶段
    reduced = [mock_reduce(word, counts) for word, counts in shuffled.items()]
    print("模拟 MapReduce 分布式词频统计结果:")
    print(dict(reduced))
```

## ⚠️ 常见误区与避坑指南

1. **误区：任何数据都应该上大数据系统**
   - 避坑：当数据量不足数十 GB 时，单机 Python (Pandas/Polars) 或 DuckDB 的计算速度远超 Spark/Hadoop，因为分布式系统的网络 Shuffle 与任务调度存在显著的固定延迟。

## 🃏 Anki 卡片

**Q: 分布式系统的 CAP 定理指什么？大数据系统通常如何权衡？**
**A**:
- **CAP**：Consistency（一致性）、Availability（可用性）、Partition Tolerance（分区容错性）三者不可兼得。
- **权衡**：由于网络分区 $P$ 必然存在，大数据系统通常牺牲强一致性，通过 BASE 理论追求最终一致性与高可用性。
