## 💡 直觉与动机

传统企业大数据架构中，存在**数据仓库（Data Warehouse）**和**数据湖（Data Lake）**的割裂：
- **数仓**：支持 ACID 事务、高性能 SQL 查询，但格式封闭、扩展成本高、不适合无结构化/半结构化 AI 数据。
- **数据湖**：基于 HDFS/S3 存储海量原始文件（Parquet/Avro/JSON），成本低但缺乏事务支持，容易演变为“数据沼泽”（Data Swamp）。

**湖仓一体（Lakehouse）**结合两者优点：在低成本数据湖存储上，通过开放格式元数据层实现 ACID 事务、版本控制（Time Travel）与高性能 SQL/AI 混合查询。

---

## 📐 正式定义与核心架构

### 1. 维度建模（Kimball 体系）

数据仓库经典四步设计：

$$\text{业务过程} \to \text{声明粒度} \to \text{确认维度} \to \text{确认事实}$$

- **事实表（Fact Table）**：记录度量事件（如订单金额、点击次数），含大量外键。
- **维度表（Dimension Table）**：提供上下文信息（如用户背景、商品分类）。

### 2. 湖仓一体技术层级

```
                             [应用层]
            BI 报表 SQL / Ad-hoc 查询 / AI 机器学习 / 流计算
                                │
                             [元数据与 ACID 事务层]
              (Delta Lake / Apache Iceberg / Apache Hudi)
            - ACID 事务 (MVCC)  - 时间旅行 (Time Travel)  - Schema 演进
                                │
                             [底层云存储 / 分布式存储]
                  (AWS S3 / HDFS / MinIO / Aliyun OSS)
```

## 💻 最小 Python 实现 — 模拟 ACID 事务与时间旅行

```python
import json
import os

class SimpleLakehouseTable:
    """模拟 Lakehouse 的版本化 commit 提交 (Time Travel 基础)"""
    def __init__(self, table_dir: str):
        self.table_dir = table_dir
        self.meta_dir = os.path.join(table_dir, "_delta_log")
        os.makedirs(self.meta_dir, exist_ok=True)

    def commit(self, added_records: list) -> int:
        version = len([f for f in os.listdir(self.meta_dir) if f.endswith('.json')])
        data_file = os.path.join(self.table_dir, f"part-v{version}.json")
        with open(data_file, 'w', encoding='utf-8') as f:
            json.dump(added_records, f)

        commit_file = os.path.join(self.meta_dir, f"{version:02d}.json")
        with open(commit_file, 'w', encoding='utf-8') as f:
            json.dump({"version": version, "file": data_file, "count": len(added_records)}, f)
        return version

    def read_version(self, version: int) -> list:
        records = []
        for v in range(version + 1):
            commit_file = os.path.join(self.meta_dir, f"{v:02d}.json")
            if os.path.exists(commit_file):
                with open(commit_file, 'r', encoding='utf-8') as f:
                    info = json.load(f)
                with open(info['file'], 'r', encoding='utf-8') as f:
                    records.extend(json.load(f))
        return records

# 示例
import shutil
tdir = "tmp_lakehouse"
if os.path.exists(tdir): shutil.rmtree(tdir)

tbl = SimpleLakehouseTable(tdir)
tbl.commit([{"id": 1, "val": "A"}])
tbl.commit([{"id": 2, "val": "B"}])

print("版本 0 数据:", tbl.read_version(0))
print("版本 1 数据 (Time Travel):", tbl.read_version(1))

shutil.rmtree(tdir)
```

## ⚠️ 常见误区与避坑指南

1. **将 Lakehouse 当作单纯的数据湖**：如果没有元数据事务层（如 Iceberg/Delta），直接在 S3/HDFS 上读写覆盖会发生数据不一致（脏读/并发写冲突）。

2. **过度设计雪花模型**：雪花模型高度规范化，但在大数据分析中会导致超多表 Join，极大降低查询性能。在大数据数仓中优先采用星型模型或宽表反规范化。
