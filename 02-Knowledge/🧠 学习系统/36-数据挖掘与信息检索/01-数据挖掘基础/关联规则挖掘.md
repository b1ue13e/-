## 💡 直觉与动机

关联规则挖掘（Association Rule Mining）起源于超市购物篮分析：**哪些商品经常被一起购买？**。最著名的案例是"买了尿布的顾客通常也会买啤酒"，这种模式无法靠直觉发现，必须通过数据挖掘。

应用场景：电商商品推荐（捆绑销售）、医疗症状共现分析、网络入侵检测中的攻击模式发现、文本关键词共现分析。

核心难点是**搜索空间爆炸**：$m$ 个不同商品最多有 $2^m$ 个候选项集，需要高效剪枝策略。

---

## 📐 正式定义与关键公式

### 基本概念

- **事务（Transaction）**：一次购买记录，如 $T_1 = \{A, B, C\}$
- **项集（Itemset）**：商品的子集，如 $\{A, B\}$
- **$k$-项集**：包含 $k$ 个商品的项集

**支持度（Support）**：

$$\text{Support}(A \Rightarrow B) = P(A \cup B) = \frac{|\{T : A \cup B \subseteq T\}|}{|D|}$$

**置信度（Confidence）**：

$$\text{Confidence}(A \Rightarrow B) = P(B|A) = \frac{\text{Support}(A \cup B)}{\text{Support}(A)}$$

**提升度（Lift）**：

$$\text{Lift}(A \Rightarrow B) = \frac{\text{Confidence}(A \Rightarrow B)}{P(B)} = \frac{P(A \cup B)}{P(A) \cdot P(B)}$$

> $\text{Lift} > 1$：正相关（同时购买的概率高于随机）；$= 1$：独立；$< 1$：负相关。

### Apriori 先验性质定理

> **先验性质（Apriori Property）**：若一个项集是频繁的（Support $\geq$ min\_sup），则其所有子集也是频繁的；反之，若一个项集是非频繁的，则其所有超集也是非频繁的。

这是 Apriori 剪枝的数学基础，可以大幅减少候选集数量。

**Apriori 算法流程**：
1. 扫描数据库，生成频繁 1-项集 $L_1$
2. 由 $L_{k-1}$ 通过连接步（Join）生成候选 $k$-项集 $C_k$
3. 用先验性质剪枝：删除 $C_k$ 中含非频繁 $(k-1)$-子集的候选
4. 扫描数据库计算 $C_k$ 的支持度，筛选出 $L_k$
5. 重复直到没有新频繁项集

## 💻 最小 Python 实现

```python
from itertools import combinations
from collections import defaultdict

def apriori(transactions: list[list], min_sup: float = 0.5) -> dict:
    """
    返回所有频繁项集及其支持度
    transactions: 事务列表，每个事务为商品列表
    """
    n = len(transactions)
    min_sup_count = min_sup * n

    # 统计 1-项集
    counts = defaultdict(int)
    for t in transactions:
        for item in t:
            counts[frozenset([item])] += 1

    frequent = {k: v/n for k, v in counts.items() if v >= min_sup_count}
    all_frequent = dict(frequent)
    k = 2

    while frequent:
        # 连接步：从频繁 (k-1)-项集生成候选 k-项集
        prev = list(frequent.keys())
        candidates = set()
        for i in range(len(prev)):
            for j in range(i+1, len(prev)):
                union = prev[i] | prev[j]
                if len(union) == k:
                    candidates.add(union)

        # 剪枝步：检查所有 (k-1)-子集是否均频繁
        pruned = set()
        for c in candidates:
            subsets = [frozenset(s) for s in combinations(c, k-1)]
            if all(s in all_frequent for s in subsets):
                pruned.add(c)

        # 计算支持度
        counts = defaultdict(int)
        for t in transactions:
            t_set = frozenset(t)
            for c in pruned:
                if c <= t_set:
                    counts[c] += 1

        frequent = {k_: v/n for k_, v in counts.items() if v >= min_sup_count}
        all_frequent.update(frequent)
        k += 1

    return all_frequent

# 示例
transactions = [
    ['A','B','C'], ['A','B'], ['A','C'], ['B','C'], ['A','B','C'],
    ['A'], ['B'], ['A','B'], ['A','C'], ['B','C']
]
result = apriori(transactions, min_sup=0.3)
for itemset, sup in sorted(result.items(), key=lambda x: len(x[0])):
    print(f"{set(itemset)}: support={sup:.1f}")
```

## ⚠️ 常见误区与避坑指南

1. **置信度高但 Lift ≤ 1**：规则 $A \Rightarrow B$ 置信度 80%，但 $P(B) = 90\%$，说明 $A$ 实际上**抑制**了购买 $B$。必须同时看 Lift。

2. **设置 min\_sup 过高或过低**：过高遗漏重要长尾关联；过低候选集爆炸，计算不可行。通常从 $0.01$—$0.05$ 开始调试。

3. **误认为关联规则 = 因果关系**：关联只是相关性，不是因果。"尿布→啤酒"可能是采购时间段的混淆变量。

4. **忽略规则方向性**：$A \Rightarrow B$ 和 $B \Rightarrow A$ 的置信度通常不同，不可互换使用。

5. **Apriori 在大数据上性能瓶颈**：每个 $k$ 都需要扫描全库。大数据场景应使用 FP-Growth（无需生成候选集，一次构建 FP-Tree）。
