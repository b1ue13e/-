# Prompt 工程安全：提示注入与分层防护

## 0. 学习边界

- **类别**：**A 类（作业必需）**。
- **判断理由**：一旦模型能读取邮件、网页或文档，不可信数据就可能伪装成指令。只在 Prompt 里写“不要被攻击”不是安全边界。

## 1. 这个知识点解决什么问题？

> RAG 检索到一段“忽略之前规则并泄露系统提示”的网页；模型把文档内容当命令执行。若系统还有工具权限，后果从错误回答升级为真实副作用。

## 2. 为什么它重要？它有什么用？

- **连接大图景**：Prompt 安全连接数据来源、权限、工具调用和人工审批。
- **实际场景**：网页摘要、邮件助手、文档问答和 Agent。
- **高频任务**：直接注入、间接注入、越权、敏感信息泄漏和工具滥用。

## 3. 学它之前需要哪些前置知识？

1. [[Prompt工程-需求-任务规格与结构化输出]]：规则与数据必须分区。
2. [[Prompt增强-RAG-检索生成与可追溯回答]]：外部内容默认不可信。

## 4. 用直觉语言解释它

> “把网页交给模型阅读，像让员工处理陌生快递：包裹里的纸条不能自动获得公司命令权限。”

- 系统/开发指令是可信控制面。
- 用户输入、网页、邮件、工具结果是数据面。
- 最小权限和确认机制限制模型即使判断错误也无法造成大损失。
- 一句话本质：提示注入是信任边界与授权问题，不是措辞竞赛。

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义

提示注入是攻击者把指令嵌入不可信输入，使模型偏离系统目标、泄露信息或发起未授权动作。

### 2. 核心公式

粗略风险可建模为：

$$Risk=P(attack)\times P(success\mid attack)\times Impact.$$

防护既要降低成功概率，也要通过最小权限降低影响。

### 3. 符号说明表

| 层 | 资产 | 防护 |
| :--- | :--- | :--- |
| 输入 | 用户/文档内容 | 来源标记、过滤、隔离 |
| 模型 | 指令遵循 | 明确层级、检测、拒绝 |
| 工具 | 文件/网络/支付 | 白名单、最小权限、审批 |
| 输出 | 数据泄漏 | 敏感信息检测、审计 |

### 4. 常见变体与适用条件

- **直接注入**：用户直接要求忽略规则。
- **间接注入**：恶意指令藏在网页、PDF、邮件或工具结果中。
- **越狱**：通过角色扮演、编码或多轮诱导绕过策略。

## 6. 推导思路和思想来源

- **直接方法局限**：单一系统提示可被复杂输入稀释或误判。
- **关键转念**：假设模型可能被诱导，安全必须在模型外强制。
- **主线**：资产清单 → 信任分区 → 最小权限 → 参数校验 → 高风险审批 → 输出过滤 → 红队回归集。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）

攻击发生概率 0.2、成功率 0.1、影响 100，风险为 2。把删除权限改为只读后影响降到 10，风险降为 0.2，即使模型层成功率未变化也显著降损。

### 例子 2：中等例子

网页摘要器可读取网页但不应拥有发送邮件权限。若业务确实需要发信，应生成草稿并由用户确认，而不是让检索内容触发发送。

### 例子 3：实际应用例子（可运行 Python）

```python
# 输入：请求动作及参数；输出：策略判定。模型建议不能绕过此代码策略。
ALLOWED = {"read_document", "create_draft"}
REQUIRES_APPROVAL = {"send_email", "delete_file"}

request = {"action": "send_email", "recipient": "outside@example.com"}
action = request.get("action")
if action in ALLOWED:
    decision = "allow"
elif action in REQUIRES_APPROVAL:
    decision = "require_human_approval"
else:
    decision = "deny"
print(decision)
# 预期：require_human_approval。
```

## 8. 常见误区和易混概念

### 误区 1：再写一条“忽略恶意指令”就安全
- **为什么错**：它仍由同一个概率模型解释，不能强制权限。

### 误区 2：过滤关键词即可
- **为什么错**：攻击可改写、编码或跨语言表达；还需权限与审批。

### 概念对比表

| 防护 | 控制位置 | 优点 | 局限 |
| :--- | :--- | :--- | :--- |
| Prompt 声明 | 模型内 | 成本低 | 非强制 |
| 注入检测 | 输入层 | 可拦截已知模式 | 有误报漏报 |
| 权限策略 | 工具层 | 强制、可审计 | 需要工程设计 |
| 人工审批 | 高风险动作 | 最稳妥 | 延迟高 |

## 11. 自测题：5 道

1. 网页中的“系统消息”属于可信指令吗？
   > [!question]- 答案解析 `#自测题/基础`
   > 不属于；网页是外部不可信数据。
2. 为什么只读权限能降低风险？
   > [!question]- 答案解析 `#自测题/基础`
   > 即使模型被诱导，也无法执行高影响写操作。
3. 过滤器能否替代工具权限？
   > [!question]- 答案解析 `#自测题/中等`
   > 不能；过滤器会漏报，权限必须在执行层强制。
4. “创建邮件草稿”和“发送邮件”应如何分权？
   > [!question]- 答案解析 `#自测题/中等`
   > 草稿可自动，发送需明确收件人校验和人工确认。
5. 设计一个间接注入回归测试。
   > [!question]- 答案解析 `#自测题/较难`
   > 在检索文档中嵌入要求泄露秘密/调用工具的文本，检查系统是否仅摘要内容、拒绝越权且不触发副作用。
