# Prompt 增强：RAG 检索生成与可追溯回答

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：RAG 是本课程“增强、评测与可靠性”阶段的核心技术，也是文档问答与可追溯回答的技术底座。LLM 幻觉与知识截止不能仅靠 Prompt 缓解，必须引入外部证据与拒答边界。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：
> GPT 类模型有两个致命缺陷：①**知识截止**——训练数据只到某个时间点，问"昨天的新闻"它不知道；②**幻觉**——不知道时会一本正经编造，且无法追溯来源；③**私有知识**——公司的内部文档、个人笔记，模型从未见过。
> 重新训练/微调模型来注入新知识成本极高（数据收集 + 训练 + 部署）。RAG 的回答：**不更新模型参数，改为更新外部知识库**——先从文档库中检索相关片段，再把片段拼进 prompt 让模型基于材料回答。它省去模型参数训练，但仍有文档清洗、切块、向量化、索引、重排、在线推理、评测和运维成本，不能称为“零成本”。

## 4. 用直觉语言解释它

> «"RAG 就像'开卷考试的学霸'：考试时（回答问题）先快速翻书（检索）找到相关段落，抄在草稿纸上（拼进 prompt），再照着草稿组织答案——所以他的答案有依据、能引用页码（来源）、不会乱编。而普通 LLM 是'闭卷学霸'：全凭记忆，记到哪答到哪，记错了就编。RAG 的关键是'书要编好目录（索引）'和'翻书要快且准（检索）'。"»

- **直觉类比/几何图像**：整个 RAG 管线 = "建图书馆（离线索引）→ 查目录（检索）→ 复印关键页（上下文注入）→ 写报告（生成）"。检索环节用"语义相似度"（向量内积）而非关键词匹配，所以"问'退款政策'能搜到写'return policy'的文档"。
- **为什么很自然**：人类专家回答问题前也会查资料；把"查资料"外置给检索系统，比把资料"背进"模型参数便宜且可控得多。
- **一句话直觉本质**：**把文档库预先向量化索引，查询时检索 top-k 相关片段注入 prompt，让 LLM"基于材料"生成可溯源、低幻觉的回答；知识更新只改库、不动模型。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
**RAG（Lewis et al., 2020）**：三阶段管线——① **索引（Indexing）**：文档切块（chunking）→ 每块嵌入（embedding）→ 存入向量库；② **检索（Retrieval）**：查询嵌入后与库中向量算相似度，取 top-k；③ **生成（Generation）**：把检索片段拼进 prompt，LLM 生成答案。

**Naive RAG 检索+生成**：
$$\text{Answer} = \text{LLM}(\text{prompt}(q, \text{top-}k \text{ chunks}))$$

### 2. 核心公式
**余弦相似度检索**（查询向量 $q$、文档块向量 $d_i$）：
$$\text{sim}(q, d_i) = \frac{q^\top d_i}{\|q\|\,\|d_i\|}$$

**生成条件概率**（检索到的文档集合 $\mathcal{D}_{\text{ret}}$）：
$$P(\text{answer} \mid q) = \prod_t P(y_t \mid y_{<t}, q, \mathcal{D}_{\text{ret}})$$

**混合检索得分**（BM25 稀疏 + 稠密加权）：
$$\text{score} = \lambda \cdot \text{BM25}(q, d_i) + (1-\lambda)\cdot \text{sim}(q, d_i)$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 | 备注 |
| :--- | :--- | :--- | :--- |
| $q$ | 用户查询（嵌入） | $\mathbb{R}^{d}$ | 与文档同嵌入空间 |
| $d_i$ | 第 $i$ 个文档块（嵌入） | $\mathbb{R}^{d}$ | chunk 级向量 |
| $k$ | 检索返回块数 | 3-10 | top-k 超参 |
| $\mathcal{D}_{\text{ret}}$ | 检索到的文档块集合 | 大小 $k$ | 注入 prompt |
| $\lambda$ | 混合权重 | $[0,1]$ | 稀疏/稠密折中 |

### 4. 常见变体与适用条件
- **Naive RAG**：索引→检索→生成，最简单；问题：检索噪声直接污染答案。
- **Advanced RAG**：检索前做查询改写（rewrite）、混合检索、rerank；检索后做上下文压缩（过滤无关块）。
- **Modular RAG**：加入记忆、路由、Agent 化（见 [[05-大语言模型与前沿技术/Self-RAG|Self-RAG]]、[[05-大语言模型与前沿技术/Corrective RAG|Corrective RAG]]）。
- **适用条件**：知识密集型问答（开放域 QA、文档 QA）；**限制**：检索质量决定上限（"garbage in, garbage out"）、多跳推理需多次检索、延迟比纯生成高。

## 6. 推导思路和思想来源

- **最初困难**：LLM 知识截止 + 幻觉 + 私有知识不可得；微调注入新知识昂贵且易灾难性遗忘。
- **直接方法局限**：把全部知识塞进参数（更大模型/更多训练）边际收益递减；提示词里硬塞长文档超上下文窗口且无关噪声干扰。
- **关键"转念"**（Lewis et al., 2020）：**把记忆从参数中"外置"到可检索的数据库**——模型只负责"阅读理解 + 生成"，知识由检索系统按需提供。这呼应了心理学"认知卸载"（cognitive offloading）与经典 IR 传统，同时天然可溯源（答案附来源）。
- **推导主线与动机**：文档切块（信息粒度）→ 稠密嵌入（语义可比）→ ANN 检索（可扩展）→ prompt 组装（上下文注入）→ 生成 + 引用（可验证）→ 反馈闭环（评估与优化）。
- **为什么自然得到此结论**：因为"知识的存储"与"知识的运用"本就该分离：存储用数据库（精确、可更新），运用用 LLM（灵活、可生成）——各取所长。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：3 个文档块嵌入：$d_1=(1,0)$，$d_2=(0,1)$，$d_3=(0.8,0.6)$；查询 $q=(1,0)$。用余弦相似度排序。
- **解题思路与关键步骤**：$\text{sim}(q,d_1)=1$；$\text{sim}(q,d_2)=0$；$\text{sim}(q,d_3)=0.8/\sqrt{1}\cdot\sqrt{1}=0.8$（$\|d_3\|=\sqrt{0.64+0.36}=1$）。
- **最终答案**：排序 $d_1 > d_3 > d_2$；取 top-2 为 $d_1, d_3$。
- **易错点**：忘记归一化（$\|q\|$、$\|d_i\|$ 都要除）；若用内积而非余弦，$d_3$ 的模长会干扰排序。
- **🤔 追问**：如果 $d_3=(2,0)$（同方向模长 2）？—— 余弦相似度仍为 1，与 $d_1$ 并列——余弦对"模长"不敏感，这正是它的用途（语义方向一致即相似）。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：chunk 大小选 200 还是 2000 字符？各有什么代价？
- **解题思路与完整解答**：小 chunk（200）：检索粒度细、命中精准，但语义可能被截断（一个完整段落被切开），且 top-k 覆盖的上下文少；大 chunk（2000）：语义完整、上下文足，但混入无关内容稀释检索精度（一个 chunk 里只有一句相关），且超过模型窗口时需截断。实践：按**语义边界**切（段落/标题/句子组），chunk 300-800 token 常用，重叠 10-20% 防止切断关键句；再配合 rerank 兜底。
- **易错点**：全局用固定字符数硬切（切断句子）；或只调 chunk 不调 k（两者联动）。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HF Course Ch.11 的 RAG Lab + 本路径 [[项目-文档问答]] 的技术底座。代码形态：
```python
# 输入：文档与查询；输出：可定位证据和受约束回答 Prompt。仅用标准库。
import re

documents = {
    "policy#1": "退货政策：签收后 7 天内可无理由退货",
    "policy#2": "退款将在 3-5 个工作日原路返回",
    "policy#3": "食品类商品不支持退货",
}

def terms(text: str) -> set[str]:
    terms_found = set(re.findall(r"[a-z0-9]+", text.casefold()))
    for sequence in re.findall(r"[\u4e00-\u9fff]+", text):
        terms_found.update(sequence[index:index + 2]
                           for index in range(max(1, len(sequence) - 1)))
    return terms_found

def retrieve(query: str, top_k: int = 2) -> list[tuple[str, str]]:
    query_terms = terms(query)
    ranked = sorted(
        documents.items(),
        key=lambda item: len(query_terms & terms(item[1])),
        reverse=True,
    )
    return [item for item in ranked[:top_k] if query_terms & terms(item[1])]

query = "退货政策是什么？"
evidence = retrieve(query)
context = "\n".join(f"[{source}] {text}" for source, text in evidence)
prompt = f"仅根据证据回答；证据不足则回答不知道。\n{context}\n问题：{query}"
print(prompt)
assert evidence and evidence[0][0] == "policy#1"
```

## 8. 常见误区和易混概念

### 误区 1：以为"RAG 就是向量数据库 + 相似度搜索"
- **错误直觉**：装个向量库、embed 一下、搜一下就是 RAG。
- **为什么错**：向量检索只是中间一环；RAG 的完整链路包含切块策略、检索质量（混合检索/rerank）、prompt 组装、生成与引用、评估闭环。检索到垃圾，生成就是垃圾。
- **正确理解**：RAG 是"系统"而非"组件"；每个环节都有独立的质量杠杆。

### 误区 2：以为"RAG 完全消除幻觉"
- **错误直觉**：有检索材料，模型就不会编。
- **为什么错**：检索可能返回不相关/矛盾材料，模型仍可能忽略材料直接生成（忠实度问题），或"自信地"编造材料里没有的细节；评估显示 RAG 显著降低幻觉但无法归零。
- **正确理解**：RAG 让答案**可溯源可验证**（附引用），配合忠实度评测与拒答机制（"资料不足"）才是完整方案。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| RAG（本概念） | 外置知识 + 生成 | 检索注入 prompt | 文档问答、知识库 |
| 微调 | 知识进参数 | 更新权重、贵 | 风格/格式适配 |
| 纯 LLM 生成 | 依赖参数记忆 | 有幻觉、知识截止 | 开放闲聊 |
| 传统检索（BM25） | 关键词匹配 | 稀疏、无语义 | 混合检索的一路 |

### 题目与解析

#### 1. RAG 的三个阶段是什么？每阶段的核心组件？
> [!question]- 答案解析
> - **答案**：① 索引：文档切块 + 嵌入 + 向量库存储；② 检索：查询嵌入 + 相似度 top-k（可加 rerank/混合检索）；③ 生成：检索片段拼 prompt + LLM 生成（可附引用）。
> - **解析**：三个阶段任一环节薄弱都会拖累整体：切块差→检索碎，检索差→生成被噪声污染，生成差→忠实度低。
> - **易错原因**：漏掉索引阶段（以为只有检索+生成）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. $d_1=(2,0)$，$d_2=(0,3)$，$d_3=(1,1)$，$q=(1,0)$，按余弦相似度排序。
> [!question]- 答案解析
> - **答案**：sim(q,d1)=1（同向）；sim(q,d2)=0；sim(q,d3)=1/√2≈0.707。排序：d1 > d3 > d2。
> - **解析**：$d_1$ 虽模长 2 但方向与 $q$ 相同，余弦为 1——余弦只看方向；$d_3$ 有 45° 夹角。
> - **易错原因**：用内积排序（会偏好模长大的 d1 与 d2 混淆）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 3. 知识库文档是长报告（每份 50 页），直接整篇入库有什么问题？怎么切？
> [!question]- 答案解析
> - **答案**：整篇嵌入会"语义平均化"——一个向量混合全文主题，检索时相关段落被稀释，命中率低；且注入 prompt 超窗口。方案：按章节/段落/语义块切（每块 300-800 token），块间保留 10-20% 重叠，保留元数据（来源页码/章节）便于引用。
> - **解析**：chunk 粒度 = 检索粒度；"能独立回答一个问题的最小语义单元"是经验准则。可先用 BM25 粗筛章节，再对章节内精细切块（分层索引）。
> - **易错原因**：固定字符硬切切断句子；或切太碎丢失上下文。
> - **Obsidian 标签建议**：`#自测题/中等`

#### 4. 检索结果质量差（top-1 总是不相关），列出 4 个排查/优化方向。
> [!question]- 答案解析
> - **答案**：① 嵌入模型：换更强的嵌入模型（bge/m3e/e5 系列）或领域微调嵌入（见 [[05-大语言模型与前沿技术/RAG Embedding|RAG Embedding]]）；② 混合检索：BM25 + 稠密加权（$\lambda$ 调优），覆盖关键词型查询；③ rerank：对 top-50 粗召回做精排（cross-encoder，见 [[05-大语言模型与前沿技术/Reranking|Reranking]]）；④ 查询侧：查询改写/扩展（rewrite）、拆分子问题（多跳）；⑤ 数据侧：重切 chunk、清洗噪声文档。
> - **解析**：按"数据→表示→召回→排序→查询"五层排查；rerank 是性价比最高的单点优化。
> - **易错原因**：只换嵌入模型——检索质量是多环节乘积。
> - **Obsidian 标签建议**：`#自测题/中等`

#### 5. 为公司内部文档 QA 系统设计评测方案（含离线与上线前验收）。
> [!question]- 答案解析
> - **答案**：① 建评测集：300-500 条真实问答对（覆盖各文档域），每问标注"答案 + 依据文档块 id"；② 离线指标：检索质量（Recall@k：依据块是否在 top-k 内）、生成质量（答案正确性——用 LLM-as-judge 或人工抽检 20%）、忠实度（答案是否可由检索块支撑，可用 NLI 模型自动判）；③ 消融：换 chunk 大小/k/嵌入模型/是否 rerank 分别跑分；④ 上线前：错误分析（按失败类型归类：检索失败/生成幻觉/拒答不当）+ 延迟预算（p95 < 3s）；⑤ 上线后：日志回流（用户反馈 + 无答案率）形成闭环。
> - **解析**：评测必须"检索"与"生成"分开测才能定位瓶颈；忠实度是 RAG 特有指标（材料支撑性），比单纯答案正确更本质。
> - **易错原因**：只测"答案对不对"，不知道是检索还是生成的问题。
> - **Obsidian 标签建议**：`#自测题/较难`
