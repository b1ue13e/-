# Prompt 工程：任务分解、自一致性与外部验证

## 0. 学习边界

- **类别**：**A 类（作业必需）**。
- **判断理由**：复杂任务的错误会沿步骤放大；分解只有在每一步可检查时才有价值，不能把更长的推理文本误当成更可靠。

## 1. 这个知识点解决什么问题？

> 一次性要求模型“读材料、抽取、计算、比较并给建议”时，任何一步出错都很难定位。简单要求“逐步思考”又可能生成看似合理但无法验证的过程。

## 2. 为什么它重要？它有什么用？

- **连接大图景**：多阶段 Prompt 是工作流和 Agent 的前身。
- **实际场景**：数据分析、规划、长文问答、代码生成和审查。
- **高频任务**：least-to-most、self-consistency、chain-of-verification、单元测试。

## 3. 学它之前需要哪些前置知识？

1. [[Prompt工程-需求-任务规格与结构化输出]]：每个子任务要有契约。
2. [[Prompt评测-实验-指标数据集与误差分析]]：比较直接回答与分解方案。

## 4. 用直觉语言解释它

> “复杂 Prompt 像流水线：先验材料，再抽字段，再计算，最后写结论；每个工位都要有质检，不能只看成品包装。”

- 分解依据应是信息依赖，而不是随意切成句子。
- 自一致性通过多次独立尝试降低随机错误，但不能修复共同偏差。
- 验证器优先使用代码、数据库或规则等外部证据。
- 一句话本质：把复杂任务拆成可验证状态转移，并让关键结论接受独立检查。

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义

设任务 $T$ 分解为有依赖关系的子任务 $T_1\rightarrow\cdots\rightarrow T_n$，每步产生状态 $s_i=f_i(s_{i-1})$，验证器 $v_i(s_i)\in\{0,1\}$ 决定是否进入下一步。

### 2. 核心公式

若各步独立成功率为 $p_i$，无验证的端到端成功率近似：

$$P(success)=\prod_{i=1}^{n}p_i.$$

五步每步 $90\%$ 可靠，整体只有 $0.9^5\approx59\%$。

### 3. 符号说明表

| 符号 | 含义 | 备注 |
| :--- | :--- | :--- |
| $T_i$ | 第 $i$ 个子任务 | 应有明确输入输出 |
| $s_i$ | 中间状态 | 可记录、可复查 |
| $v_i$ | 验证器 | 规则、代码或人工 |

### 4. 常见变体与适用条件

- **Least-to-most**：先解决简单子问题，再组合。
- **Self-consistency**：多样采样后对最终答案投票。
- **外部验证**：计算用程序、事实用检索、代码用测试。
- 涉及隐私或高风险决策时，不要求模型输出隐藏推理；只保存必要的证据和可审计步骤。

## 6. 推导思路和思想来源

- **直接方法局限**：单次长回答无法定位失败层。
- **关键转念**：按依赖图拆任务，并让每层输出结构化中间结果。
- **主线**：画依赖 → 定义状态 → 设计验证器 → 决定重试/回退 → 记录端到端指标。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）

三个独立步骤成功率均为 $0.8$，整体约 $0.512$。若第一步用规则校验将有效成功率提高到 $0.95$，整体为 $0.95\times0.8^2=0.608$。

### 例子 2：中等例子

旅行规划分为：约束抽取 → 候选生成 → 营业时间核验 → 路线排序 → 文案。营业时间必须查外部来源，不能让同一模型“反思”后自证。

### 例子 3：实际应用例子（可运行 Python）

```python
# 输入：多次独立答案；输出：多数票与一致率。
from collections import Counter

answers = ["18", "18", "26", "18", "20"]
counts = Counter(answers)
winner, votes = counts.most_common(1)[0]
consistency = votes / len(answers)
print({"answer": winner, "consistency": consistency})
# 预期：{'answer': '18', 'consistency': 0.6}；低一致率应触发核验而非直接采信。
```

## 8. 常见误区和易混概念

### 误区 1：回答更长就更会推理
- **为什么错**：长度可能只是重复，必须看任务正确率和验证结果。

### 误区 2：让同一模型检查自己就是独立验证
- **为什么错**：生成者和评审者可能共享偏差；优先使用可执行规则或独立证据。

### 概念对比表

| 方法 | 核心作用 | 优点 | 局限 |
| :--- | :--- | :--- | :--- |
| 单次 CoT 提示 | 诱导中间步骤 | 简单 | 不保证正确 |
| 自一致性 | 降低随机错误 | 不需训练 | 成本高、共同偏差仍在 |
| 外部验证 | 检查事实/计算 | 可审计 | 需要工具与规则 |

## 11. 自测题：5 道

1. 四步任务每步成功率 $0.9$，整体约多少？
   > [!question]- 答案解析 `#自测题/基础`
   > $0.9^4=0.6561$。
2. 自一致性为什么需要非零随机性？
   > [!question]- 答案解析 `#自测题/基础`
   > 完全确定的解码会重复同一答案，无法形成多样候选。
3. 计算结果最适合用什么验证？
   > [!question]- 答案解析 `#自测题/中等`
   > 可执行程序、公式或单元测试，而非语言模型自评。
4. 分解过细有什么代价？
   > [!question]- 答案解析 `#自测题/中等`
   > 延迟、成本、状态传递错误和更多失败点。
5. 设计一个“低一致率触发检索”的策略。
   > [!question]- 答案解析 `#自测题/较难`
   > 例如采样 5 次，一致率低于 0.8 时检索权威来源，再要求基于证据重答并记录触发率。
