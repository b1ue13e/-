# Prompt 工程：上下文学习、示例选择与提示敏感性

## 0. 学习边界

- **类别**：**A 类（作业必需）**。
- **判断理由**：Few-shot 不是“多贴几个例子”，而是在上下文中定义任务边界、标签语义和输出格式；错误示例会稳定地教错模型。

## 1. 这个知识点解决什么问题？

> 只有文字说明时，“严重”“相关”“合格”等标签含义仍模糊；加示例后准确率上升，但换个顺序又下降。需要可重复的示例选择与敏感性实验。

## 2. 为什么它重要？它有什么用？

- **连接大图景**：ICL 连接 Prompt、数据集、检索示例和评测。
- **实际场景**：分类、抽取、格式迁移、风格模仿和规则边界示范。
- **高频任务**：Zero-shot 与 Few-shot 对照、示例顺序消融、困难负例设计。

## 3. 学它之前需要哪些前置知识？

1. [[Prompt工程-需求-任务规格与结构化输出]]：先定义标签和验收规则。
2. [[Prompt评测-实验-指标数据集与误差分析]]：用固定测试集比较策略。

## 4. 用直觉语言解释它

> “规则像驾考手册，示例像教练在真实路口示范。只看顺畅路况，学员不会处理边界情况。”

- 示例要覆盖典型正例、典型负例和决策边界。
- 标签分布要平衡，避免模型只模仿最近或多数标签。
- 示例顺序、措辞和相似度都可能影响输出。
- 一句话本质：Few-shot 用少量上下文样本临时定义任务，但必须用实验控制偏差。

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义

ICL 在不更新模型参数的情况下，将示例集 $D=\{(x_i,y_i)\}_{i=1}^k$ 放进上下文，使模型估计：

$$P(y^*\mid x^*,D,I),$$

其中 $I$ 是任务指令。

### 2. 核心公式

顺序敏感度可用不同排列得分的标准差衡量：

$$Sensitivity=\sqrt{\frac{1}{m}\sum_{j=1}^{m}(s_j-\bar{s})^2}.$$

### 3. 符号说明表

| 符号 | 含义 | 备注 |
| :--- | :--- | :--- |
| $k$ | 上下文示例数 | 不是越大越好 |
| $D$ | 示例集合 | 必须与测试集隔离 |
| $s_j$ | 第 $j$ 种排列得分 | 可用准确率/F1 |

### 4. 常见变体与适用条件

- **Zero-shot**：规则清晰且任务常见。
- **Few-shot**：标签私有、格式特殊或有边界案例。
- **检索式 Few-shot**：样本库大，根据当前输入动态选相似示例。

## 6. 推导思路和思想来源

- **直接方法局限**：只写抽象定义无法展示决策边界。
- **关键转念**：把示例当成局部任务规范，而非装饰。
- **主线**：建开发集 → Zero-shot 基线 → 分层选例 → 随机多个顺序 → 报告均值与方差 → 检查泄漏。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）

四种示例顺序准确率为 $0.80,0.80,0.60,0.80$，均值 $0.75$；偏差平方和为 $3\times0.05^2+(-0.15)^2=0.03$，方差 $0.0075$，标准差约 $0.087$。单报最高 $0.80$ 会掩盖敏感性。

### 例子 2：中等例子

情感分类只有正面例子时，模型倾向预测正面；加入“礼貌但投诉”的困难负例，才真正说明标签看诉求结果而非语气。

### 例子 3：实际应用例子（可运行 Python）

```python
# 输入：候选示例与查询关键词；输出：按词集合 Jaccard 相似度选出的两个示例。
examples = [
    ("无法登录账号", "account"),
    ("信用卡重复扣费", "billing"),
    ("希望取消订阅", "cancel"),
]
query = "账号登录失败"

def chars(text):
    return set(text.replace(" ", ""))

q = chars(query)
ranked = sorted(examples, key=lambda item: len(q & chars(item[0])) / len(q | chars(item[0])), reverse=True)
print(ranked[:2])
# 预期：登录相关示例排在最前；真实系统应改用经过评测的语义检索。
```

## 8. 常见误区和易混概念

### 误区 1：示例越多越好
- **为什么错**：会增加成本、冲突、顺序偏差和上下文占用。

### 误区 2：把测试答案放进示例库
- **为什么错**：造成数据泄漏，评测不再代表泛化。

### 概念对比表

| 方法 | 核心问题 | 优点 | 风险 |
| :--- | :--- | :--- | :--- |
| Zero-shot | 指令是否足够 | 成本低 | 边界含糊 |
| 固定 Few-shot | 一组示例能否定义任务 | 稳定、易审计 | 对分布变化迟钝 |
| 检索 Few-shot | 哪些示例最相关 | 个性化 | 泄漏、错误近邻 |

   > [!question]- 答案解析 `#自测题/基础`
