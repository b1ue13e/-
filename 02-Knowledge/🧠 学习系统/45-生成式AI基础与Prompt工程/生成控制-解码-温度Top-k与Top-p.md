# 生成控制：温度、Top-k 与 Top-p 解码
---
## 0. 先判断它值不值得深挖
- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：所有 LLM 应用（对话、摘要、代码）的底层都是"从概率分布里挑 token"的解码过程；贪心/beam/采样、温度/top-k/top-p、重复惩罚是 [[提示工程]] 与 [[对话系统]] 的直接旋钮。面试必考"beam search 与采样的区别""温度怎么调""top-p 是什么""BLEU 的缺陷"。
---
## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> 模型输出的是整个概率分布（每位置 5 万词的 softmax），必须决定"到底输出哪个词"：贪心快但易重复（"我我我"）；beam 爱说套话；纯采样随机性大、可能跑题；且生成文本无"标准答案"，评估也难。
> 文本生成的回答：**解码策略 = 在"质量-多样性-速度"三角上做选择**——贪心/beam（确定性）、温度采样（控随机性）、top-k/top-p（截断低概率词防跑题）、重复惩罚（抑制循环）；评估用 BLEU/ROUGE + 人工/LLM 打分。
---
## 2. 为什么它重要？它有什么用？
- **连接大图景**：解码是 [[GPT系列]] 的出口；[[对话系统]]、[[提示工程]]、[[Agent与工具使用]] 全部建立在其上；[[LLM推理优化]] 优化的正是解码过程（KV Cache/投机解码）。
- **实际应用场景**：聊天（温度 0.7-1.0+top-p）、翻译（beam 4-8）、代码（温度 0.2）、摘要（贪心/低温度）；面试"beam 怎么防重复""temperature=0 是贪心吗""BLEU 为何不适合对话"。

## 4. 用直觉语言解释它
> «"解码策略像'选词游戏的主持人'：模型每步递上一筐词，每个词带一个概率牌。贪心 = '永远拿最大牌'（稳但容易一条道走到黑、车轱辘话）；beam search = '手里同时攥着 4 张候选牌，走到最后挑总分最高的'（稳中求全，但爱说'标准答案'式套话）；温度 = '把概率牌重新洗一洗'——温度低牌面差距拉大（更确定），温度高差距抹平（更随机）；top-k/top-p = '只从最大的前 k 张或累计概率 90% 的牌里挑'（防小概率烂牌捣乱）；重复惩罚 = '已经出过的牌，下次自动扣分'（防复读机）。"»
- **直觉类比/几何图像**：解码 = 在概率树上走路径：beam = 同时走 $k$ 条路；采样 = 每次随机拐弯；惩罚 = 路径上已访问节点的权重衰减。
- **为什么很自然**：生成质量与多样性天然矛盾，策略就是调节这个矛盾的旋钮。
- **一句话直觉本质**：**"文本生成 = 从条件分布 $P(w_t|w_{<t})$ 逐 token 采样/搜索：贪心与 beam 求'最可能'，温度/top-k/top-p 控'多样性'，惩罚控'重复'；评估 = n-gram 重叠（BLEU/ROUGE）+ 人工/LLM 判断。"**
---
## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
**自回归生成**：$P(w_1,\dots,w_T)=\prod_{t=1}^{T}P(w_t|w_{<t})$，逐 token 解码。
**温度采样**：$P(w_t) \propto \exp(z_{w_t}/\tau)$，$\tau$ 控制分布锐度。
**top-k**：只保留概率最大的 $k$ 个 token 并重归一化；**top-p（nucleus）**：保留累计概率达到 $p$ 的最小集合。
**重复惩罚**：已生成 token 的 logit 除以惩罚系数 $\theta$（或加惩罚项）。
### 2. 核心公式
**温度重缩放**：
$$P_\tau(w_t) = \frac{\exp(z_{w_t}/\tau)}{\sum_{w}\exp(z_w/\tau)}$$
**top-p 截断**（$\mathcal{V}^{(p)}$ 为最小集合使 $\sum_{w\in\mathcal{V}^{(p)}} P(w)\geq p$）：
$$P(w_t) = \begin{cases} P(w_t)/\sum_{v\in\mathcal{V}^{(p)}}P(v) & w_t \in \mathcal{V}^{(p)} \\ 0 & \text{otherwise} \end{cases}$$
**重复惩罚**（CTRL 风格，$\theta>1$ 抑制重复）：
$$z_{w_t} \leftarrow z_{w_t}/\theta \quad \text{若 } w_t \text{ 已出现过}$$
### 3. 符号说明表
| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $z_{w_t}$ | logit 分数 | $\mathbb{R}$ | softmax 输入 |
| $\tau$ | 温度 | $[0,2]$ | 0=贪心极限 |
| $k$ | top-k 候选数 | 10–100 | 常用 50 |
| $p$ | top-p 累计概率 | $(0,1]$ | 常用 0.9-0.95 |
| $\theta$ | 惩罚系数 | $\geq1$ | 越大越抑重复 |
| $B$ | beam 宽度 | 2–8 | 候选路径数 |
### 4. 常见变体与适用条件
- **贪心**：快、确定；重复与局部次优。适合摘要/翻译等"标准答案"任务。
- **Beam Search**：全局近似最优；套话、长度偏置（长句分低）、重复；加长度归一化与重复惩罚。
- **温度采样**：$\tau=0.7$ 对话；$\tau>1$ 创意写作（更随机）；$\tau\to0$ 退化为贪心。
- **限制条件**：所有策略都在"概率质量"上操作，模型本身能力是上限；无"完美解码"——评测驱动选择。
---
## 6. 推导思路和思想来源
- **最初困难**：逐 token 贪心导致"局部最优≠全局最优"与重复；纯采样多样性高但质量不稳定。
- **直接方法局限**：beam search（1970s 语音识别）缓解局部最优但引入"套话偏置"；人工规则（n-gram 阻断）治标不治本。
- **关键"转念"**：① 把"概率最高"换成"可控随机"：温度是统计物理/softmax 的经典重缩放（Hinton 蒸馏思想同源）；② 截断低概率词（top-k, Fan et al. 2018；top-p, Holtzman et al. 2020）：长尾分布里大量低概率 token 是"跑题之源"，截断让采样聚焦"可信候选"；③ 重复惩罚：直接操作 logit 抑制已生成词，简单有效。
- **推导主线与动机**：确定性（贪心/beam）→ 随机性（温度）→ 约束随机（top-k/p）→ 反重复（惩罚）：每一步修补上一步的失败模式（重复、跑题、套话）。
- **为什么自然得到此结论**：生成任务的目标函数（质量×多样性）无法解析优化，只能用"分布整形"近似——所有策略都是对 $P(w_t|w_{<t})$ 的改造。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：某位置 logits $z=(A:2.0, B:1.0, C:0.1)$，$\tau=2$，求温度采样分布。
- **解题思路与关键步骤**：除以 2：$(1.0, 0.5, 0.05)$；$e$：$(2.718, 1.649, 1.051)$；归一化：总和 5.418。
- **最终答案**：$P=(0.502, 0.304, 0.194)$。对比 $\tau=1$：$P=(0.659, 0.242, 0.099)$——温度升高使分布更平坦。
- **易错点**：先除 $\tau$ 再取指数（顺序不能反）；$\tau$ 与 logits 尺度相对性。
- **🤔 追问**：$\tau=0.1$ 呢？—— $(20,10,1)$，$e$ 后 $(4.85\times10^8, 22026, 2.72)$，A 概率 ≈ 1——接近贪心。
### 例子 2：中等例子（条件判断与多步推理）
- **题目与完整解答**：beam search 为什么需要长度归一化？—— beam 打分是各 token 对数概率之和（或积），长句自然分低（更多负项），导致 beam 偏爱短句/提前结束。解法：$\text{score} = \frac{1}{T^\alpha}\sum\log P(w_t)$（$\alpha=0.6-1.0$ 长度惩罚），或加 EOS 奖励。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：下面用标准库实现温度与 top-p 过滤，并固定随机种子验证输出；官方 CS336 作业再把它接入语言模型 logits：
```python
import math
import random

def nucleus(tokens: list[str], logits: list[float], temperature: float,
            top_p: float, seed: int = 0) -> str:
    if temperature <= 0 or not 0 < top_p <= 1:
        raise ValueError("temperature > 0 且 0 < top_p <= 1")
    scaled = [value / temperature for value in logits]
    maximum = max(scaled)
    weights = [math.exp(value - maximum) for value in scaled]
    ranked = sorted(zip(tokens, weights), key=lambda item: item[1], reverse=True)
    total, kept, cumulative = sum(weights), [], 0.0
    for token, weight in ranked:
        kept.append((token, weight))
        cumulative += weight / total
        if cumulative >= top_p:
            break
    random.seed(seed)
    return random.choices([item[0] for item in kept],
                          weights=[item[1] for item in kept], k=1)[0]

choice = nucleus(["秋", "风", "雨"], [2.0, 1.0, 0.1], 0.8, 0.9)
print(choice)
assert choice in {"秋", "风"}
```

## 8. 常见误区和易混概念
### 误区 1：以为"temperature=0 就是贪心解码"
- **错误直觉**：没随机性就是贪心。
- **为什么错**：温度公式在 $\tau=0$ 处未定义（除零）；实现上通常用 $\tau$ 极小值或直接把 argmax 当 $\tau=0$ 的特例——语义上等价，但要注意库实现（有些库对温度 0 报错或回退）。
- **正确理解**：$\tau\to0^+$ 的极限 = argmax = 贪心；$\tau=1$ 是原始分布。
### 误区 2：以为"top-p 和 top-k 选一个就行"
- **错误直觉**：都是截断，作用重复。
- **为什么错**：top-k 是"固定数量"截断（分布平坦时可能截掉好词）；top-p 是"动态数量"（分布尖锐时集合小、平坦时集合大）。两者互补，工业上常先 top-k 再 top-p。
- **正确理解**：top-p 更自适应；组合用更稳。
### 概念对比表
| 概念 | 机制 | 特点 | 典型场景 |
| :--- | :--- | :--- | :--- |
| 贪心（本概念） | argmax | 快、易重复 | 摘要 |
| Beam Search | 多路径搜索 | 稳、套话 | 翻译 |
| 温度采样 | 分布重缩放 | 多样性可控 | 对话 |
| top-k/top-p | 截断低概率 | 防跑题 | 通用采样 |
| 重复惩罚 | logit 抑制 | 防复读 | 长生成 |

### 题目与解析
#### 1. 贪心、beam、温度采样、top-p、重复惩罚各自的机制？
> [!question]- 答案解析
> - **答案**：贪心=每步 argmax；beam=保留 $B$ 条路径；温度=logit 除以 $\tau$ 重缩放；top-p=保留累计概率 $p$ 的最小集合；惩罚=已生成词的 logit 除以 $\theta$。
> - **解析**：确定性策略（贪心/beam）与随机策略（温度/top-p）是两大族，惩罚两者都可用。`#自测题/基础`
#### 2. logits=(2,1,0)，$\tau=2$，求温度采样分布。
> [!question]- 答案解析
> - **答案**：除以 2 → (1, 0.5, 0) → $e$ → (2.718, 1.649, 1) → 归一化 → (0.506, 0.307, 0.186)。
> - **解析**：温度 >1 使分布平坦（C 从 $\tau=1$ 的 0.09 升到 0.186）。`#自测题/基础`
#### 3. 机器翻译与创意写作分别用什么解码策略？
> [!question]- 答案解析
> - **答案**：翻译：beam（4-8）+ 长度惩罚（标准答案型、要确定）；创意写作：温度 0.8-1.2 + top-p 0.9-0.95（要多样、防跑题）。
> - **解析**：任务"标准答案程度"决定确定性 vs 随机性。`#自测题/中等`
#### 4. 为什么 beam search 生成文本偏"套话"且偏短？
> [!question]- 答案解析
> - **答案**：beam 追求路径概率最大化 → 高频词路径（套话）天然概率高；长度偏置：打分是负对数概率之和，句子越长累计负值越大，beam 倾向短句/提前 EOS。缓解：长度归一化（length penalty）与 no_repeat_ngram。
> - **解析**：概率最大 ≠ 人类偏好，这是"优化目标错位"的典型。`#自测题/中等`
#### 5. 分析 top-p 相对 top-k 的自适应性（分布尖锐 vs 平坦两种情形）。
> [!question]- 答案解析
> - **答案**：top-k 固定数量：分布尖锐时（几乎确定），top-k 仍保留 $k$ 个低概率词（引入噪声）；分布平坦时（高度不确定），top-k 可能截掉合理候选。top-p 动态调整：尖锐时集合小（≈1 词，接近贪心）、平坦时集合大（保留所有合理候选）——集合大小随熵自适应。
> - **解析**：top-p 用"概率质量"而非"数量"做阈值，匹配分布形状；这就是它成为默认的原因。`#自测题/较难`

- Temperature 如何影响 Token 分布？::用温度缩放 logits；低温使分布更尖锐、更确定，高温使分布更平坦、更随机。
