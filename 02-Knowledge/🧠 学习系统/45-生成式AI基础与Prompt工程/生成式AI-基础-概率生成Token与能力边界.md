# 生成式 AI：概率生成、Token 与能力边界

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**。
- **判断理由**：如果把模型误解为搜索引擎或事实数据库，就无法解释随机输出、上下文限制和幻觉，也无法正确设计 Prompt。

## 1. 这个知识点解决什么问题？

> **我们遇到的麻烦**：同一个问题重复提问，答案会变；模型会流畅地说错；长文放进上下文后仍会漏信息。需要一个不依赖“模型像人一样思考”的可检验解释。

## 2. 为什么它重要？它有什么用？

- **连接大图景**：Prompt、RAG、解码、评测和 Agent 都建立在条件生成上。
- **实际应用**：估计上下文成本、选择采样策略、设计拒答和核验机制。
- **高频任务**：解释 temperature、Token 上限、上下文污染和知识截止。

## 3. 学它之前需要哪些前置知识？

1. **条件概率**：$P(y\mid x)$ 表示在已知输入 $x$ 后输出 $y$ 的可能性。
2. **向量直觉**：模型把离散 Token 映射成向量，再通过多层变换计算下一 Token 分数。

## 4. 用直觉语言解释它

> “模型像一个读完大量文本的续写器：每一步都查看当前纸面内容，为下一个小片段打分，然后选一个写下。”

- **Token** 是模型读写的最小片段，不等于字、词或汉字。
- **上下文** 是本次推理能看到的纸面，不等于永久记忆。
- **参数知识** 是训练后压进权重的统计规律，不是带页码的数据库。
- **一句话本质**：LLM 在上下文条件下反复预测下一个 Token，能力来自统计表示与计算，可靠性必须额外设计。

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义

给定 Token 序列 $x_{1:t}$，自回归语言模型估计下一 Token 的分布 $P(x_{t+1}\mid x_{1:t})$，完整序列概率按链式法则分解：

$$P(x_{1:T})=\prod_{t=1}^{T}P(x_t\mid x_{<t}).$$

### 2. 核心公式

模型输出 logits $z_i$，softmax 转为概率：

$$P(i\mid x_{\le t})=\frac{e^{z_i}}{\sum_j e^{z_j}}.$$

### 3. 符号说明表

| 符号 | 含义 | 范围 | 备注 |
| :--- | :--- | :--- | :--- |
| $x_t$ | 第 $t$ 个 Token | 词表索引 | 不是自然语言“词” |
| $z_i$ | 候选 Token 的 logit | 实数 | 未归一化分数 |
| $T$ | 序列长度 | 正整数 | 受上下文窗口限制 |

### 4. 常见变体与适用条件

- 文本、图像、音频模型都可视为对某种表示的条件分布建模。
- 上下文越长不保证越准；无关内容会稀释证据或引入冲突。
- 训练目标与“真实、无害、遵循指令”并不完全一致。

## 6. 推导思路和思想来源

- **最初困难**：直接给整段文本一个概率难以计算。
- **关键转念**：用概率链式法则拆成一连串下一 Token 预测。
- **推导主线**：文本切成 Token → Token 变向量 → Transformer 汇总上下文 → 输出 logits → softmax → 解码选择 → 把新 Token 放回上下文继续生成。
- **为什么自然**：训练语料天然提供“前缀—下一个 Token”监督信号，不需要逐条人工标注。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）

候选 `北京/上海/广州` 的 logits 为 $[2,1,0]$。指数近似为 $[7.39,2.72,1]$，总和 $11.11$，概率约为 $[0.665,0.245,0.090]$。最高分并非概率 1，所以采样时仍可能选择上海。

### 例子 2：中等例子

问“根据材料回答”，但材料没写日期。模型参数中可能见过相似事实，却不能证明它适用于当前材料。正确系统应把“材料内证据”和“参数记忆”分开，并允许回答“材料不足”。

### 例子 3：实际应用例子（可运行 Python）

```python
# 输入：三个 logits；输出：归一化概率与概率和。
import math

logits = {"北京": 2.0, "上海": 1.0, "广州": 0.0}
weights = {token: math.exp(score) for token, score in logits.items()}
total = sum(weights.values())
probs = {token: round(weight / total, 3) for token, weight in weights.items()}
print(probs)
print(round(sum(probs.values()), 3))
# 预期：{'北京': 0.665, '上海': 0.245, '广州': 0.09}，概率和约为 1。
```

## 8. 常见误区和易混概念

### 误区 1：模型就是搜索引擎

- **为什么错**：生成时默认没有查询可追溯文档库。
- **正确理解**：需要 [[Prompt增强-RAG-检索生成与可追溯回答]] 才能把外部证据接入。

### 误区 2：概率最高就代表事实正确

- **为什么错**：概率衡量在模型分布下“像不像”，不直接衡量现实真伪。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 场景 |
| :--- | :--- | :--- | :--- |
| 参数知识 | 模型训练时压缩了什么 | 难追溯、可能过时 | 通识生成 |
| 上下文知识 | 本次输入给了什么 | 可更换、受窗口限制 | 文档问答 |
| 外部检索 | 当前查到了什么 | 可更新、可引用 | RAG |

## 11. 自测题：5 道

1. 同一 Prompt 输出不同的直接原因是什么？
   > [!question]- 答案解析 `#自测题/基础`
   > 解码可能按概率采样；模型给的是分布，不是唯一答案。
2. logits $[0,0]$ 的 softmax 是多少？
   > [!question]- 答案解析 `#自测题/基础`
   > 两项相同，概率各为 $0.5$。
3. 把整本书塞入上下文一定更好吗？
   > [!question]- 答案解析 `#自测题/中等`
   > 不一定；会增加成本、干扰和证据冲突，需要检索与结构化组织。
4. 为什么“请不要幻觉”不能消除幻觉？
   > [!question]- 答案解析 `#自测题/中等`
   > 它没有提供外部证据、拒答判据或事实核验器。
5. 设计一个区分参数知识与材料知识的实验。
   > [!question]- 答案解析 `#自测题/较难`
   > 构造材料内事实与常识冲突样本，分别测试无材料、给材料、要求引用三种条件并统计依据一致率。
