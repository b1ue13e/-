# Transformer 与大语言模型：GPT 与自回归语言模型

---

## 0. 先判断它值不值得深挖

- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：GPT 是 Decoder-only 自回归范式的代表，也是现代 LLM（ChatGPT、LLaMA、Qwen）的直接祖先；"zero-shot/few-shot/上下文学习"是第五阶段（[[05-大语言模型与前沿技术/🚀 第五阶段：大语言模型与前沿技术|第五阶段]]）全部内容的地基。虽然 HW01-05 不直接手写 GPT，但没有它就无法理解作业体系之外 90% 的现代 NLP。

---

## 1. 这个知识点解决什么问题？

> **我们遇到了什么麻烦**：
> BERT 证明了"双向预训练 + 微调"的威力，但有两个局限：①**每个任务都要微调**——换一个任务就要重新训练任务头，任务一多成本爆炸；②**不会生成**——MLM 学的是"理解"，不是"续写"。
> 而人类使用语言主要是**生成**（说话、写作），且希望模型"一个模型干所有事"。GPT 的回答：放弃双向，用**纯自回归**（只根据左边的词预测右边的词）预训练；到了下游任务，**不微调**——直接把任务描述成"续写"（prompt），模型就能生成答案。这就是"生成式预训练"：一个模型、一个目标（预测下一个词）、通吃所有任务。

---

## 2. 为什么它重要？它有什么用？

- **连接大图景**：GPT-1 证明"生成式预训练 + 微调"可行；GPT-2 证明"不微调也能做任务"（zero-shot）；GPT-3 证明"规模大到一定程度涌现上下文学习"（few-shot）。这条线直接通向 [[检索增强生成RAG]]、Agent 等第五阶段全部内容。
- **实际应用场景**：聊天助手、代码生成、摘要、翻译、问答、写作；几乎所有 2023 年后的大模型产品。
- **高频题型/任务**：面试问"GPT 与 BERT 结构差异""自回归 vs 双向""zero-shot/few-shot/ICL 原理""Scaling Laws"（见 [[05-大语言模型与前沿技术/Scaling Laws|Scaling Laws]]）；实践：用 `transformers` 加载 GPT-2 做续写。

---

## 3. 学它之前需要哪些前置知识？

1. **[[Transformer架构]]**：GPT = Decoder-only Transformer（因果掩码 + 无交叉注意力）。
2. **[[BERT及其变体]]**：预训练-微调范式的参照物。
3. **[[文本预处理]]**：GPT-2 用 byte-level BPE，词表 50,257。

## 4. 用直觉语言解释它

> «"GPT 像一台'接龙机器'：它的全部本领就是看到前面的词，猜下一个词。你给它'从前有座山'，它接'山里有个庙'。预训练就是在整个互联网文本上练接龙——练到极致后，奇迹发生了：把任务包装成接龙的样子（'翻译：猫 → cat'），它居然能'接着写'出正确答案。模型越大，接龙接得越像'真的会思考'——但本质上它每一步都只是在选'最像的下一个词'。"»

- **直觉类比/几何图像**：自回归 = 概率链式法则的机械实现：$P(w_1\dots w_T)=\prod P(w_t|w_{<t})$。GPT 就是一个巨大的条件概率表（参数化的）。
- **为什么很自然**：语言本身就是从左到右产生的；预测下一个词是唯一"不需要任何标注"的监督信号（文本自带标签）。
- **一句话直觉本质**：**用"预测下一个词"这一自监督目标预训练 Decoder-only Transformer，把一切任务都转成"续写"来统一解决；规模扩大后涌现出 zero-shot/few-shot 能力。**

---

## 5. 正式定义、核心公式、符号解释

### 1. 最核心定义
**GPT（Generative Pre-trained Transformer）**：Decoder-only Transformer，因果（causal）自注意力，训练目标为最大化序列对数似然（自回归语言建模）。

### 2. 核心公式
**自回归目标**（参数 $\theta$，序列 $w_1,\dots,w_T$）：
$$\mathcal{L}(\theta) = -\sum_{t=1}^{T} \log P(w_t \mid w_1,\dots,w_{t-1};\theta)$$

**逐位置预测**（$h_t$ 为第 $t$ 步隐藏状态，$W_e$ 为词嵌入）：
$$P(w_t \mid w_{<t}) = \text{softmax}(h_t W_e^\top)$$

**GPT-1 微调目标**（分类任务，$W_y$ 为任务头）：
$$\mathcal{L}_{\text{ft}} = -\sum_{(x,y)} \log P(y \mid x)$$

**Few-shot/ICL 形式**：把任务编码进 prompt $\mathcal{P}$，直接 $P(\text{answer} \mid \mathcal{P})$ 解码（不更新参数）。

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $w_t$ | 第 $t$ 个 token | 词表 50,257（GPT-2） | BPE 子词 |
| $h_t$ | 第 $t$ 步隐藏状态 | $\mathbb{R}^{d}$ | Decoder 输出 |
| $W_e$ | 词嵌入矩阵 | $\mathbb{R}^{V\times d}$ | 输出层共享权重 |
| $T$ | 序列长度 | 1024（GPT-2） | 上下文窗口 |
| $N$ | 层数 / 参数量 | GPT-1: 12层/117M；GPT-3: 96层/175B | 规模是关键变量 |

### 4. 常见变体与适用条件
- **GPT-1（2018）**：117M，生成式预训练 + 微调，证明范式可行。
- **GPT-2（2019）**：1.5B，zero-shot 能力（不微调直接做任务），byte-level BPE。
- **GPT-3（2020）**：175B，few-shot/ICL 涌现；GPT-3.5（InstructGPT，RLHF）→ ChatGPT；GPT-4 多模态。
- **现代衍生**：LLaMA/Qwen/DeepSeek 等开源 Decoder-only 模型（RoPE 位置编码 + SwiGLU + RMSNorm）。
- **适用条件**：生成任务、统一任务接口；**限制**：单向（不看右边）、训练/推理成本高（KV Cache 优化见 [[05-大语言模型与前沿技术/KV Cache|KV Cache]]）、幻觉问题（[[检索增强生成RAG]] 是主要缓解手段）。

## 6. 推导思路和思想来源

- **最初困难**：NLP 任务碎片化——每个任务一个模型一个损失；BERT 缓解了但没消除（仍需微调）。
- **直接方法局限**：任务头微调需要每任务标注数据；多任务联合训练需要多任务数据集，扩展困难。
- **关键"转念"**（Radford et al., 2018-2020）：**只做一件事——语言建模**。语言建模的损失函数不挑任务：任何任务都能"翻译"成"给定上下文预测下一个 token"的形式。于是预训练模型本身就是"万能任务模型"；微调只是锦上添花（GPT-1），甚至不需要（GPT-2/3）。
- **推导主线与动机**：① Decoder-only + 因果掩码（不能看未来）；② 大规模语料预训练；③ 下游任务统一为续写（prompt）；④ 规模法则：参数量、数据量、算力同步增长 → 涌现（见 [[05-大语言模型与前沿技术/Scaling Laws|Scaling Laws]]、[[05-大语言模型与前沿技术/涌现能力|涌现能力]]）。
- **为什么自然得到此结论**：因为"下一个词预测"是信息论意义上最通用的文本监督信号（无损压缩视角：好的 LM ≈ 好的压缩器 ≈ 好的世界模型）。

## 7. 例子：基础 → 中等 → 实际应用

### 例子 1：基础例子（可手算）
- **题目**：词表 {I, love, NLP}，GPT 在位置 3 输出 logits [1.0, 2.0, 0.5]，序列为 "I love [?"，求预测概率与困惑度。
- **解题思路与关键步骤**：softmax：$e^{1}=2.718$，$e^{2}=7.389$，$e^{0.5}=1.649$，和 $=11.756$。$P(\text{NLP}) = 1.649/11.756 \approx 0.140$。
- **最终答案**：$P(\text{love})=0.628$，$P(\text{I})=0.231$，$P(\text{NLP})=0.140$。若真实答案是 NLP，困惑度 $=1/0.140\approx7.1$。
- **易错点**：困惑度是 $e^{\text{cross-entropy}}$ 而非 $1/P_{\max}$——要用真实词的概率。
- **🤔 追问**：如果 GPT 是双向的（能看到右边的词），预测 "I love [?" 会更容易吗？—— 会更容易，但那就不是自回归了；生成时必须只能看左边（因果），这是训练与推理一致的硬约束。

### 例子 2：中等例子（条件判断与多步推理）
- **题目**：few-shot（ICL）和微调的区别是什么？各在什么场景用？
- **解题思路与完整解答**：微调更新模型参数（需要标注数据 + 训练成本，效果最稳）；few-shot/ICL **不更新参数**，只在 prompt 里给几个示例，让模型"照猫画虎"（依赖模型已学到的模式匹配能力）。场景：有标注数据且效果优先 → 微调；无标注/快速迭代/API 调用 → few-shot。GPT-3 的结论：few-shot 显著优于 zero-shot，但远低于微调上限（大模型 + 更多数据时差距缩小）。
- **易错点**：把 ICL 说成"模型学会了新知识"——ICL 是激活已有知识，不是更新权重。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：用 `transformers` 加载 GPT-2 做零样本续写（HF Course 的标准练习）：
```python
from transformers import AutoTokenizer, AutoModelForCausalLM

tokenizer = AutoTokenizer.from_pretrained("gpt2")
model = AutoModelForCausalLM.from_pretrained("gpt2")

prompt = "The capital of France is"
inputs = tokenizer(prompt, return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=10, do_sample=False)
print(tokenizer.decode(out[0], skip_special_tokens=True))
# 期望输出：... is Paris.（自回归下一步预测）
```

## 8. 常见误区和易混概念

### 误区 1：以为"GPT 的注意力是双向的，只是被 mask 了"
- **错误直觉**：GPT 和 BERT 结构一样，只是训练目标不同。
- **为什么错**：GPT 的 Decoder 用**因果掩码**，每个位置只能看自己及左边——这是结构性的单向；BERT 的 Encoder 无掩码，双向。两者"架构不同 + 目标不同"（见 [[BERT与GPT对比]] 的完整对照表）。
- **正确理解**：Encoder（双向、理解）vs Decoder（因果、生成）是两种架构分支。

### 误区 2：以为"GPT 真的在'理解'或'思考'"
- **错误直觉**：ChatGPT 的流畅回答说明它有意识/推理能力。
- **为什么错**：GPT 每一步只做"下一个词的概率分布采样"，没有任何规划或验证机制；流畅是海量文本统计规律的涌现（[[05-大语言模型与前沿技术/涌现能力|涌现能力]]），会一本正经地幻觉（编造事实）。
- **正确理解**：把 GPT 当"极其强大的模式补全器"，用 RAG/工具调用（[[05-大语言模型与前沿技术/Function Calling|Function Calling]]）等外部机制补足事实性。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| GPT（本概念） | 自回归生成 | 因果掩码、单向、LM 目标 | 生成/对话/续写 |
| BERT | 双向理解 | 无掩码、双向、MLM | 分类/标注/检索 |
| T5 | Encoder-Decoder | 文本到文本统一框架 | 翻译、摘要（见 [[04-Transformer与预训练模型/T5\|T5]]） |
| LLaMA 等开源 LLM | GPT 系优化 | RoPE + SwiGLU + RMSNorm | 本地部署 |

### 题目与解析

#### 1. GPT 与 BERT 在注意力上的本质区别是什么？
> [!question]- 答案解析
> - **答案**：GPT（Decoder）用因果掩码，每个位置只能看到自己及左侧 token（单向）；BERT（Encoder）无掩码，每个位置看到全部 token（双向）。
> - **解析**：这决定了能力分工：GPT 擅长生成（与推理时自回归一致），BERT 擅长理解（利用双侧上下文）。详见 [[BERT与GPT对比]]。
> - **易错原因**：以为区别只在训练目标——注意力掩码是结构性差异。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 2. 词表 {a, b, c}，GPT 在位置 2 输出 logits [0, 0, 0]，真实词为 c，求损失与困惑度。
> [!question]- 答案解析
> - **答案**：softmax 均匀分布 $P=1/3$ 每个词；$\mathcal{L}=-\log(1/3)=\ln3\approx1.099$；困惑度 $=e^{1.099}=3$。
> - **解析**：困惑度 = 均匀词表大小的"等效候选数"；3 意味着模型在 3 个词之间完全无法区分。
> - **易错原因**：把困惑度算成 $1/3$ 本身——要取指数（$e^{\mathcal{L}}$）。
> - **Obsidian 标签建议**：`#自测题/基础`

#### 3. 什么场景下选择 few-shot 而不是微调？
> [!question]- 答案解析
> - **答案**：① 无标注数据或标注成本高；② 需要快速迭代（改 prompt 比重训快）；③ 使用 API 无法更新权重；④ 任务种类多且变化频繁。
> - **解析**：微调效果上限更高但需要数据与算力；few-shot 零成本但依赖模型规模（小模型 few-shot 效果差）。数据充足、效果敏感的核心任务 → 微调；探索期、长尾任务 → few-shot。
> - **易错原因**：在小模型上期待 few-shot 效果——ICL 是大模型的涌现能力。
> - **Obsidian 标签建议**：`#自测题/中等`

#### 4. 因果掩码如何实现？为什么训练和推理都必须用它？
> [!question]- 答案解析
> - **答案**：在 $QK^\top$ 的上三角（$j>i$）位置填入 $-\infty$（或极负数），softmax 后权重为 0；实现上常用 `torch.tril` 生成下三角 mask。
> - **解析**：训练时必须用，否则模型"偷看未来词"（目标泄漏——预测 $w_t$ 时看到了 $w_{t+1}$）；推理时必须用，因为推理时未来根本不存在——训练推理一致才能保证生成质量。
> - **易错原因**：对角线处理错（$j=i$ 必须可见）；或用 0/1 mask 但忘记 mask 掉的位置在 softmax 前置 $-\infty$。
> - **Obsidian 标签建议**：`#自测题/中等`

#### 5. 为什么"预测下一个词"这种看似简单的目标能学到句法、事实与推理能力？
> [!question]- 答案解析
> - **答案**：① 下一个词的预测需要综合词法/句法/语义/常识/事实——错误预测的梯度迫使模型编码所有这些信息；② 文本本身蕴含世界（"巴黎是法国的首都"这句话教会事实），语言建模是"无标注的世界知识蒸馏"；③ 从信息论看，压缩（预测）与理解等价（好的预测器必须理解生成文本的规律）；④ 规模法则下，参数量/数据量达到阈值后出现能力涌现（[[05-大语言模型与前沿技术/涌现能力|涌现能力]]）。
> - **解析**：关键论证：语言不是随机符号，它是人类思想的编码；能精确预测语言分布的模型必然内化了语言背后的规律。局限：统计相关 ≠ 因果理解，幻觉由此而来。
> - **易错原因**：把"涌现"神秘化——它来自统计规律在大规模下的相变，不是额外的训练目标。
> - **Obsidian 标签建议**：`#自测题/较难`
