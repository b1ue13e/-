# 优化求解器

## 0. 为什么学它

MPC、轨迹优化、系统辨识最终都要解一个优化问题——**求解器就是"最后一公里"**：建模再漂亮，求解器选错/用错就全白费。本卡是工程工具链总览：CasADi（自动微分+优化）、CVXPY（凸优化建模）、qpOASES/ACADO（C++ 实时 QP/NMPC）、Python Control（分析设计）、drake（MIT 综合平台）。掌握选型规则，才知道"什么场景用什么、怎么把问题喂给求解器"。

## 1. 工具全景与选型

| 工具 | 语言 | 定位 | 典型场景 |
|:---|:---|:---|:---|
| CVXPY | Python | 凸优化建模（QP/SOCP/SDP） | 离线设计、MPC 原型 |
| CasADi | Python/C++ | 自动微分 + 非线性优化 | NMPC、轨迹优化 |
| qpOASES | C++ | 嵌入式实时 QP（在线激活集） | 嵌入式 MPC（毫秒级） |
| ACADO | C++ | NMPC 代码生成 | 实时非线性 MPC |
| Python Control | Python | 经典/现代控制分析与设计 | 传递函数/Bode/Riccati |
| drake | Python/C++ | MIT 机器人综合平台 | 多体动力学 + 优化 + 仿真 |
| KDL | C++ | 运动学/动力学计算库 | ROS 机械臂运动学 |

## 2. 选型规则

| 需求 | 选择 |
|:---|:---|
| 原型验证（不在乎实时） | CVXPY（建模快、可读性好） |
| 非线性模型 MPC | CasADi（自动微分免手推雅可比） |
| 嵌入式实时（<10 ms） | qpOASES（线性 QP）/ ACADO（NMPC 代码生成） |
| 频域/根轨迹分析 | Python Control（`control` 库） |
| 多体机器人 + 优化一体 | drake（Underactuated 课程配套） |
| ROS 机械臂运动学 | KDL / MoveIt |

## 3. 最小可运行例子（CVXPY 解 QP）

```python
import cvxpy as cp
import numpy as np

# 求解 min 0.5 x^T P x + q^T x  s.t. Gx <= h（MPC 的 QP 标准形式）
P = np.array([[4.0, 1.0], [1.0, 2.0]])
q = np.array([1.0, 1.0])
G = np.array([[-1.0, 0.0], [0.0, -1.0], [-1.0, -1.0]])  # 约束：x1>=0, x2>=0, x1+x2>=2
h = np.array([0.0, 0.0, -2.0])

x = cp.Variable(2)
prob = cp.Problem(cp.Minimize(0.5 * cp.quad_form(x, P) + q.T @ x),
                  [G @ x <= h])
prob.solve()
print("最优解:", x.value, "最优值:", prob.value)
```

**运行说明**：`pip install cvxpy numpy` 后直接运行；最优解约 `[0.5, 1.5]`，最优值约 `5.5`（手算可复核：在边界 $x_1+x_2=2$ 上代回，$x_1=0.5$ 时取最小）。这就是 MPC 每步滚动求解的 QP 最小形态。

## 4. CasADi 与 qpOASES 的定位差异

- **CasADi**：符号计算 + 自动微分，把非线性优化问题（NMPC）变成数值问题，可生成 C 代码；
- **qpOASES**：专门解凸二次规划（线性 MPC 的每步 QP），激活集算法，嵌入式友好；
- 一句话：**非线性问题找 CasADi，线性 QP 嵌入式找 qpOASES**（详见 [[OSQP\|OSQP]] 与 [[QP标准形式\|QP标准形式]]）。

## 5. 常见坑

| 坑 | 对策 |
|:---|:---|
| 把非线性问题硬塞给 QP 求解器 | 先判断凸性；非线性用 CasADi/IPOPT |
| 忽略求解器时间 | 实时系统必须测每步求解耗时（qpOASES 毫秒级，CVXPY 百毫秒级） |
| 模型与求解器单位不一致 | 统一单位（rad vs deg、m vs km）再喂给求解器 |
| 无界约束导致求解失败 | 检查约束矩阵正确性、加有限边界 |
