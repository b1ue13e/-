# 仿真平台

## 0. 为什么学它

算法在真车/真机上验证成本高、风险大——**仿真平台是"先虚拟后实体"的必经环节**。但仿真平台五花八门：CARLA 侧重自动驾驶全栈、CarSim 侧重高保真车辆动力学、PyBullet/MuJoCo 侧重机械臂物理仿真。选错平台 = 验证结论不可迁移到实车。本卡给出平台全景与选型规则，解决"我的算法该在哪个环境验证"。

## 1. 平台全景

| 平台 | 类型 | 特点 | 适合 |
|:---|:---|:---|:---|
| CARLA | 自动驾驶全栈仿真 | 城市环境、传感器模型、端到端 | L2+ 自动驾驶验证 |
| CarSim | 高保真车辆动力学 | 商用整车模型、轮胎/悬架细节 | 车辆动力学控制 |
| LGSVL | 自动驾驶仿真 | Unity 场景、多传感器 | 传感器融合测试 |
| Apollo 仿真 | 自动驾驶平台 | 百度 Apollo 配套 | 全栈自动驾驶 |
| PyBullet | 通用物理引擎 | URDF 支持、Python API | 机械臂抓取/控制 |
| MuJoCo | 高精度物理引擎 | 接触动力学、快速仿真 | 强化学习/接触任务 |

## 2. 选型规则

| 需求 | 选择 |
|:---|:---|
| 机械臂抓取/力控 | PyBullet（简单）/ MuJoCo（高精度接触） |
| 车辆横向/纵向动力学验证 | CarSim（高保真）/ 自建 Python 模型（快速原型） |
| 自动驾驶全栈（感知→规划→控制） | CARLA |
| 传感器融合（相机/雷达/LiDAR） | CARLA / LGSVL |
| 规划-控制闭环算法验证 | PythonRobotics（轻量，课程默认） |

## 3. 最小可运行例子（PyBullet 加载机械臂）

```python
import pybullet as p
import pybullet_data

p.connect(p.DIRECT)          # 无界面模式
p.setAdditionalSearchPath(pybullet_data.getDataPath())
robot = p.loadURDF("r2d2.urdf")   # 加载 URDF 模型
p.setGravity(0, 0, -9.81)

# 读取关节信息
for j in range(p.getNumJoints(robot)):
    print(p.getJointInfo(robot, j)[1])  # 关节名
p.disconnect()
```

**运行说明**：`pip install pybullet` 后运行；预期输出 r2d2 的关节名称列表。这是"机械臂仿真入门第一行代码"。

## 4. 仿真保真度 vs 速度的权衡

| 需求 | 保真度 | 速度 | 平台 |
|:---|:---|:---|:---|
| 算法验证（策略对错） | 低 | 快 | Python 自建模型 / PythonRobotics |
| 控制性能（误差指标） | 中 | 中 | CarSim / PyBullet |
| 部署验证（传感器噪声） | 高 | 慢 | CARLA / MuJoCo |

**原则**：先用轻量模型快速迭代算法，再用高保真平台做部署验证——不要一上来就上重型仿真。

## 5. 常见坑

| 坑 | 对策 |
|:---|:---|
| 仿真与实车差距不评估 | 记录 sim-to-real 差异（延迟、噪声、模型误差） |
| URDF/模型文件路径错 | 用 `pybullet_data` 自带模型起步，再换自定义 |
| 忽略传感器噪声建模 | 实车传感器有噪声，仿真也要加（见 [[噪声模型\|噪声模型]]） |
| 平台选定后不迁移 | 算法在轻量平台验证后，必须上高保真平台复验 |
