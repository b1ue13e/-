# 早期终止

> **一句话**：实时 MPC 没有"无限时间"——迭代到预算就用当前解（次优但可用）输出，保证控制周期不超时，这是嵌入式 MPC 的生存之道。

## 0. 为什么学它

采样周期（如 20ms）是硬约束：求解超时=控制失效。早期终止承认"次优但及时"优于"最优但迟到"，是实时系统与理论求解的妥协点。

## 1. 问题

- 求解器理想情况：迭代到收敛精度；
- 实时约束：必须在采样周期内给出结果；
- 硬性等收敛 → 超时 → 控制失效。

## 2. 早期终止策略

```
while 迭代 < 最大迭代数 and 精度 > 容差:
    迭代一步
if 超时 or 迭代数达上限:
    返回当前迭代解 (次优)
```

- 一阶法天然支持：每步都在改善，任意停点可行（见[[一阶QP]]）；
- OSQP 提供 `max_iter` 与自适应容差（见[[OSQP]]）。

## 3. 最小可手算例子（次优解可用性）

**题目**：预算 200 次迭代，第 120 次时精度 1e-3（未达 1e-6），但已超时。输出第 120 次解，后果？

**步骤**：
1. 第 120 次解已接近最优（一阶法前期收敛快）；
2. MPC 只执行第一步 $u_k$，下周期重新优化（见[[滚动优化]]）；
3. 一步次优 + 下周期修正 → 影响极小；若解可行则约束安全有保证。

**含义**："次优但及时"在滚动结构下几乎无感知。

## 4. 常见误区

| 误区 | 正确理解 |
|:---|:---|
| 必须收敛才输出 | 实时预算内输出次优解是正确行为 |
| 次优解不安全 | 只要解可行（满足约束），安全有保证 |
| 早期终止=质量差 | 配合热启动，次优解接近最优 |

## 5. 工程配套

| 配套 | 说明 |
|:---|:---|
| 热启动 | 让次优解更接近最优（见[[热启动]]） |
| 容差分级 | 初始松容差快收敛，后期紧 |
| 兜底 | 超时严重 → 用上周期解/保守控制 |

## 6. 检索练习（闭卷）

1. 写出早期终止策略；
2. 说明次优解为何可接受；
3. 说明工程配套。

## 7. 通过标准

- 能解释次优可用性；
- 能设计兜底。
