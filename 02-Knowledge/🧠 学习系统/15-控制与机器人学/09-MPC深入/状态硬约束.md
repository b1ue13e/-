# 状态硬约束

> **一句话**：硬约束是"必须满足"的安全红线——车速上限、位置边界、障碍距离，违反即不可行；代价是可能让 QP 无解。

## 0. 为什么学它

MPC 的价值在于"约束下最优"。硬约束是物理/安全红线的数学表达，但"绝对满足"是有代价的：扰动下可能无解。理解硬约束的不可行性问题，才能正确设计"硬 + 软"的约束体系。

## 1. 定义

$$\mathbf{x}_{min} \le \mathbf{x}_k \le \mathbf{x}_{max}, \quad \forall k = 1..N$$

## 2. 典型硬约束

| 场景 | 硬约束 |
|:---|:---|
| 车辆 | 速度 $0 \le v \le v_{max}$（物理上限） |
| 车道 | 横向位置在道路边界内 |
| 机器人 | 关节角极限、工作空间边界 |
| 安全 | 与障碍距离下限（见[[避障MPC]]） |

## 3. 硬约束的问题：不可行性

- 约束过紧 + 模型误差 + 扰动 → 预测区间内**无可行解** → MPC 崩溃；
- 扰动使状态已被推到约束外 → 任何控制序列都违反约束。

## 4. 最小可手算例子（不可行性）

**题目**：$v \le 10$（硬），当前 $v_0 = 11$（已被扰动推出界），$a \le -2$ 但 $v$ 在一步内最多降到 9.8。预测是否可行？

**步骤**：
1. 一步后 $v_1 = 11 - 2 = 9 < 10$ ✓ 可行；
2. 但若 $a \ge -0.5$（执行器弱），一步后 $v_1 = 10.5 > 10$ 仍超限 → **无可行解**；
3. 对策：松弛该约束（见[[松弛变量]]）或允许临时违反。

**含义**：硬约束在扰动下可能让整个 QP 无解——这就是软约束存在的理由。

## 5. 处理策略

| 策略 | 说明 |
|:---|:---|
| 松弛变量 | 允许软性违反 + 惩罚（见[[松弛变量]]） |
| 终端集 | 保证末端可行（见[[终端集]]） |
| 约束收紧 | 用安全裕量设计，留误差空间 |
| 降级策略 | 求解失败切保守控制 |

## 6. 常见误区

| 误区 | 正确理解 |
|:---|:---|
| 全部约束都用硬 | 安全红线用硬，性能/舒适用软 |
| 硬约束永远满足 | 扰动下可能无解，需松弛兜底 |
| 无解就加大算力 | 无解是问题不可行，不是算力不足 |
