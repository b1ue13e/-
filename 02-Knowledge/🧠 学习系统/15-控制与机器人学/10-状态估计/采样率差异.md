# 采样率差异

## 0. 为什么学它

真实机器人从不同传感器拿到**频率不等的测量流**：IMU 100–1000 Hz、轮速编码器 50–100 Hz、GPS 1–10 Hz、相机/LiDAR 10–30 Hz。把它们硬塞进"每步一更新"的同步 KF 是错的——正确做法是**异步融合**：高频传感器驱动预测（时间更新），低频传感器到了才触发修正（测量更新）。本卡解决"快慢不等"的多源数据如何喂给同一个估计器。

## 1. 典型多速率配置

| 传感器 | 频率 | 角色 |
|:---|:---|:---|
| IMU | 100–1000 Hz | 高频预测（运动模型驱动） |
| 轮速/编码器 | 50–100 Hz | 高频约束 |
| GPS | 1–10 Hz | 低频修正（绝对位置） |
| 相机/LiDAR | 10–30 Hz | 中频观测（特征/点云） |

## 2. 异步融合策略

### 2.1 按时间戳处理（推荐）
每个测量到达即触发更新，用"该测量时间戳之前的最近一次预测结果"作先验：

```
收到 z_k（带时间戳 t_k）:
    1. 用动态模型把状态前推到 t_k（可能跳过多个预测步）
    2. 执行一次测量更新
```

### 2.2 高低频分层
- **预测步高频**：每个 IMU 采样都跑一次时间更新（$x^- = Ax + Bu$，$P^- = APA^T + Q$）；
- **更新步异步**：低频测量到达时，用最近先验做一次测量更新。
- 即"预测高频、修正低频"的标准异步 KF。

### 2.3 同步化（不推荐，除非实现受限）
- 低频测量插值/外推到高频时刻 → 引入人为相关误差；
- 或降采样统一到最低频率 → 浪费高频信息。

## 3. 工程要点

| 要点 | 说明 |
|:---|:---|
| 时间戳 | 一切异步融合的前提，缺失时间戳无法正确融合 |
| 预测步频 | 由最高频传感器驱动（如 IMU） |
| 更新步频 | 由各低频测量独立触发 |
| 延迟补偿 | 高频预测可补偿低频测量的延迟（见 [[传感器延迟\|传感器延迟]]） |

## 4. 最小可手算例子

**题目**：IMU 100 Hz（预测步 $dt=0.01$ s）、GPS 1 Hz。车辆匀速 $v=10$ m/s，$t=0$ 时 $x_0=0$，$P_0=1$ m²，$Q=0.01$ m²/步，$R=4$ m²。求 $t=0.5$ s 时刻（GPS 尚未到达）预测出的 $x^-$ 与 $P^-$。

**解**：预测步共 50 步，匀速模型 $A=1, B=dt$：

$$
x^- = 0 + 10 \times 0.5 = 5 \text{ m}
$$

协方差每步增长 $Q$：

$$
P^- = P_0 + 50 \times Q = 1 + 0.5 = 1.5 \text{ m}^2
$$

**解读**：50 个预测步累积了 0.5 m² 的不确定性增长；$t=1$ s 时 GPS 到达，才会用 $P^-$ 和 $R$ 做一次更新。这正是"预测高频、更新低频"的量化过程。

## 5. 常见误区

| 误区 | 正确理解 |
|:---|:---|
| 把不同频率测量都按最高频率更新 | 低频测量重复使用 = 人为降低其独立性，协方差虚假收缩 |
| 所有传感器时间戳对齐到同一时刻再融合 | 强制插值引入相关误差；按原始时间戳异步处理更优 |
| 降采样到最低频率"省事" | 丢掉高频信息，动态场景精度损失明显 |
| 预测步数算错 | 两个测量之间的预测步数 = 时间差 / 预测周期，要按时间戳计算 |
