# 指令周期-取指

> 所属模块：[[🗺️ 计算机组成原理学习路径|计算机组成原理学习路径]]
> 对应阶段：[[🧭 阶段1-CPU架构|返回阶段页]]

## 为什么学（问题动机）

CPU 执行任何一条指令，无论它是加法、跳转还是访存，**第一步永远相同：把"下一条指令"从内存搬到 CPU 里**。这一步就是取指（Fetch）。如果取指不成立，译码、执行、访存、写回全部无从谈起——它是冯·诺依曼"存储程序"思想的执行起点。理解取指，是理解数据通路（Datapath）与流水线（Pipeline）的基石。

## 正式定义

**取指（Instruction Fetch）**：根据程序计数器（PC, Program Counter）中保存的指令地址，从指令存储器（Instruction Memory）读出该地址处的一条机器指令，并写入指令寄存器（IR, Instruction Register）的过程。

一条指令周期（Instruction Cycle）的标准五步：

```text
取指(F) → 译码(D) → 执行(EX) → 访存(MEM) → 写回(WB)
```

其中取指是所有指令**共享**的阶段，不因指令类型不同而变化。

## 关键机制与公式

### 硬件组成

| 部件 | 作用 |
|:---|:---|
| PC（程序计数器） | 保存下一条指令的地址 |
| 指令存储器 | 以地址为输入、以该地址的指令为输出的只读存储 |
| 指令寄存器 IR | 暂存刚取出的指令，供译码阶段使用 |

### 取指流程（逐步骤）

1. 把 `PC` 的值送入指令存储器的地址端口；
2. 指令存储器返回 `Mem[PC]`（该地址处的 32-bit 机器指令）；
3. 指令写入 IR；
4. 计算下一条指令地址：`PC_new = PC + 4`（RISC 指令定长 4 字节；若跳转/分支在译码或执行阶段改写 PC）。

### 关键公式

- 下一条顺序指令地址：`PC ← PC + 4`
- 取指时间估算（理想流水线中，时钟周期下限由最慢阶段决定）：`T_cycle ≥ max(T_fetch, T_decode, T_exec, T_mem, T_writeback)`

## 一个最小例子（手算）

假设 RISC-V 指令 `0x00400000` 处存放指令 `lw x5, 8(x6)`（机器码 `0x0062A283`）。

```text
PC = 0x00400000
↓
指令存储器[0x00400000] = 0x0062A283   （读出指令）
↓
IR = 0x0062A283                       （暂存）
↓
PC = 0x00400004                       （顺序取下一条）
```

第 4 步之前，CPU 还不知道这是一条 `lw`——它只是把字节取回来了。**"读懂"指令是译码阶段的事。**

## 常见误区

1. **误区：取指时 CPU 已经知道指令含义。** 错。取指只搬运字节，不理解含义；理解发生在译码。这解释了为什么取指对每条指令都一样。
2. **误区：PC 总是 +4。** 只有顺序执行的指令才是 +4。跳转（j）、分支（beq）在后续阶段会**覆盖** PC，取指阶段计算的 +4 会被丢弃。
3. **误区：指令存储器和数据存储器是同一块。** 经典 RISC 数据通路中它们是分离的（哈佛风格的分离缓存）；冯·诺依曼统一存储中才共用，但取指端口与数据端口仍可能分时复用（导致结构冒险）。

## 自测（先作答，再对照答案）

1. **基础**：一条 RISC-V 指令取指后，PC 的值如何变化？为什么？
2. **中等**：如果指令长度是 2 字节（如 Thumb），顺序取指时 PC 应加多少？
3. **较难**：为什么在流水线中取指阶段通常是每周期必做的固定操作，而译码/执行会因指令而异？这与流水线的"每阶段一个周期"设计有什么关系？

<details>
<summary>参考答案</summary>

1. `PC ← PC + 4`。RISC-V 基础指令集定长 32 位 = 4 字节，顺序执行取下一条指令。
2. `PC ← PC + 2`。取指步长由指令编码长度决定，与 ISA 设计相关。
3. 因为取指对所有指令同构（只按地址取字节），可以在每个周期稳定完成，不依赖指令类型；这让取指成为流水线的固定第一级，其他阶段才需要根据操作码分派。

</details>
