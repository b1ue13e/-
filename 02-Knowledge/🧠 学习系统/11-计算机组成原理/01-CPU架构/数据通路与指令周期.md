# 数据通路与指令周期 (Datapath & Instruction Cycle)

## 1. 为什么学：CPU 内部到底怎么"跑指令"

`CPU与取指执行循环.md` 讲了取指循环的整体概念。这张卡深入到**硬件实现**：数据通路（Datapath）由哪些部件组成、每类部件承担什么职责、一条指令如何沿着数据通路走完五步指令周期。理解数据通路是理解流水线（下一张卡）的前提。

## 2. 数据通路的五大部件

| 部件 | 职责 | 存储/计算 |
|:---|:---|:---|
| **PC（程序计数器）** | 保存下一条指令地址；默认 +4（RISC-V 字长 4 字节），分支/跳转时被改写 | 寄存器（状态） |
| **指令存储器（IMEM）** | 按 PC 地址输出指令 | 只读（指令视角） |
| **寄存器堆（Register File）** | 读两个源操作数 rs1/rs2，写一个目的 rd | 32×32-bit 阵列 |
| **ALU** | 算术/逻辑运算（add/sub/and/or/比较） | 组合逻辑 |
| **数据存储器（DMEM）** | load/store 访问的内存接口 | 读写 |

> 补充：**立即数扩展单元（ImmGen）** 把指令中的立即数字段符号扩展为 32-bit；**控制单元（Control Unit）** 根据 opcode 产生各部件控制信号（RegWrite、ALUSrc、MemRead...）。

## 3. 五步指令周期（Single-Cycle 视角）

| 阶段 | 英文 | 做什么 | 用到的部件 |
|:---|:---|:---|:---|
| 取指 | IF | 从 IMEM 取指令，PC 自增 | PC、IMEM |
| 译码 | ID | 读寄存器堆、解码控制信号 | 寄存器堆、控制单元、ImmGen |
| 执行 | EX | ALU 运算 / 计算地址 / 判断分支 | ALU |
| 访存 | MEM | load/store 访问 DMEM | DMEM |
| 写回 | WB | 结果写回寄存器堆 rd | 寄存器堆 |

**单周期（Single-Cycle）**：一条指令用一个时钟周期走完五步（时钟周期 = 最慢指令路径）；**多周期（Multi-Cycle）**：每步一个时钟周期，部件可复用（ALU 既算地址又算运算）。

## 4. 三种指令类型在数据通路上的路径

| 类型 | 路径 | 关键信号 |
|:---|:---|:---|
| **R 型（运算）** | IF → ID → EX(ALU) → WB | ALUSrc=0（读寄存器）、RegWrite=1 |
| **I 型（立即数/load）** | IF → ID → EX(ALU 算地址) → MEM → WB | ALUSrc=1（用立即数）、MemRead=1 |
| **S 型（store）** | IF → ID → EX(ALU 算地址) → MEM | MemWrite=1、RegWrite=0 |
| **B 型（分支）** | IF → ID → EX(比较+算目标) → 更新 PC | Branch=1、PC 多路选择 |

## 5. 常见误区（反例）

- **误区 1**："寄存器堆和内存都是存储，可以合并"——寄存器堆在 CPU 内、双端口（同时读两个）、~0 延迟；内存在外、单端口、100ns 级，物理性质完全不同；
- **误区 2**："PC 每个周期都 +4"——分支/跳转/异常时会改写 PC，且 RISC-V 的 PC 相对寻址依赖当前 PC 值；
- **误区 3**："数据通路只有一条线"——实际上有**多路选择器（MUX）** 在 ALUSrc、MemToReg、PCSrc 等点切换数据来源，控制单元决定 MUX 的选通。
