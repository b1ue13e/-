# 高级流水线 (Superscalar, Out-of-Order & SMT)

## 1. 为什么学：现代 CPU 的"超标量+乱序+超线程"三板斧

`流水线技术.md` 讲了五级流水线与三类冒险（结构/数据/控制）及基本的转发/暂停/分支预测。这张卡回答现代 CPU 如何**超越单发射顺序执行**：① 超标量（每周期发射多条指令）；② 乱序执行（突破数据依赖顺序限制）；③ 超线程/SMT（一个核同时跑多个线程）。这是理解"为什么程序有时快有时慢"的关键。

## 2. 超标量（Superscalar）

- **定义**：每时钟周期能发射（Issue）多条指令的流水线；
- **需要什么**：多套执行单元（多个 ALU、多个访存端口）、更宽的取指/译码带宽（每周期取 4-8 条指令）；
- **发射宽度**：4-wide、6-wide、8-wide 等（如 Intel Golden Cove 6 宽、Apple M1 8 宽）；
- 直觉：把流水线"横向加宽"，而不是"纵向加深"。

## 3. 乱序执行（Out-of-Order Execution, OoO）

### 3.1 为什么需要

顺序执行中，一条指令卡在等待（如 cache miss 访存），后续无关指令只能空等。乱序执行让**无关指令越过阻塞指令先执行**，提高利用率。

### 3.2 核心机制

| 组件 | 职责 |
|:---|:---|
| **重排序缓冲（ROB, Reorder Buffer）** | 按程序顺序记录指令结果，**按序提交（Commit）**——保证精确异常和精确状态 |
| **保留站（Reservation Station）** | 等待操作数就绪的指令排队区，操作数一到就发射执行 |
| **寄存器重命名（Register Renaming）** | 消除 WAR/WAW 伪相关：把逻辑寄存器映射到物理寄存器 |
| **分支预测恢复** | 预测错误时用 ROB 冲刷（Flush）预测路径指令 |

### 3.3 为什么"乱序执行"不违反程序语义

- 乱序只改变**执行**顺序，**提交**（写回可见状态）仍按程序顺序；
- 寄存器重命名消除了 WAR（先写后读）/WAW（写写）伪依赖，只保留真正的 RAW 数据依赖；
- 精确异常由提交点保证：只有 ROB 头部的指令才能写回（衔接 [[异常处理]] §6）。

## 4. 同时多线程（SMT / 超线程）

- **定义**：一个物理核维护**多套线程状态**（多组 PC/寄存器），共享执行单元，让流水线空档被另一线程的指令填充；
- **直觉**：把"等待延迟"换成"另一线程的计算"——尤其适合 cache miss 多的负载；
- **代价**：执行单元争用、缓存争用（两个线程共享 L1/L2），单个线程性能可能下降；
- 对比：Intel Hyper-Threading（每核 2 线程）；Apple M1 大小核（E-core 不超线程）。

## 5. 常见误区（反例）

- **误区 1**："乱序执行 = 指令不按程序顺序完成"——不，**提交必须按序**，乱序只影响执行阶段，可见状态永远按序；
- **误区 2**："超标量核数越多越快"——发射宽度受指令级并行度（ILP）上限制约（Amdahl 定律的 ILP 版），多数程序 ILP 有限，6-wide 与 8-wide 差距很小；
- **误区 3**："超线程免费获得双核"——SMT 通常只带来 15-30% 吞吐提升，且共享资源可能拖累单线程延迟。
