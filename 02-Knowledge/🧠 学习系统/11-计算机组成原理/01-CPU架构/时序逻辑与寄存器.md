# 时序逻辑与寄存器

---

## 0. 学习边界
- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：HW03（Project 03）的全部交付物（DFF、Bit、Register、RAM 家族、PC）都在本层；更重要的是，**"状态/记忆"是组合逻辑做不到的**——没有寄存器，CPU 连"记住上一步结果"都做不到，Project 05 整机无从谈起。它还是"时钟周期 = 性能单位"这一硬件性能观的起点。

---

## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> 前两个 Project 的电路输出只由当前输入决定，**没有任何记忆**。但计算机必须能"记住"：ALU 算完的结果要存下来供下一条指令用；程序计数器要知道"下一步执行哪条指令"；内存要能存一屏数据。直接把门电路的输出连回输入会形成振荡或不稳定，行不通。
> 因此必须引入**时钟**（一个周期性跳变的信号）与 **DFF**（由时钟沿控制、能"锁住"一个 bit 的元件），再以 DFF 为积木搭出寄存器与 RAM——至此硬件从"纯函数"进化为"带状态的机器"。

---

## 2. 为什么它重要？它有什么用？
- **连接大图景**：[[🧠 CPU与取指执行循环]] 中 A/D 寄存器、PC、指令内存、数据内存全部来自本层；不学它，HW03 之后所有 Project 都无法继续。
- **实际应用场景**：任何 CPU 的寄存器堆、Cache、主存、流水线级间锁存器都是"DFF + 地址选择"的放大版；"建立时间/保持时间、时钟频率"是所有硬件性能讨论的基本语言。
- **高频题型/任务**：DFF 与组合门的行为对比；寄存器 `load` 使能逻辑；RAM 地址位宽计算（$2^k$ 个字）；PC 的 `reset/load/inc` 三控制位；HDL 中 `Register`/`RAM16K`/`PC` 的编写与 `.tst` 时序验证。

---

## 3. 学它之前需要哪些前置知识？
1. **[[🧠 布尔逻辑门与HDL]]**：门、Mux、总线与 `PARTS` 复用——寄存器 = DFF + Mux，RAM = 寄存器阵列 + 解码器。
2. **[[🧠 ALU算术逻辑单元]]**：运算结果要落进寄存器，标志位（`zr`/`ng`）要被 PC 使用——本层正好承接 ALU 的"输出端"。

---

## 4. 用直觉语言解释它
> «"时钟像教室里整齐的拍手节奏：每个"啪"（上升沿）的瞬间，所有同学（DFF）同时把自己手里的纸条（输入）换成本次的新纸条并攥紧，其余时间纸条纹丝不动。寄存器就是"带开关的储物格"：load 开关打开时，下一拍把新值放进去；关着就一直保留旧值。RAM 则是"一排储物格 + 门牌号（地址）"，报哪个号，就把值存进/取出哪个格。"»

- **直觉类比/几何图像**：时钟沿 = 全局统一的"换班时刻"，保证所有存储元件**同步**更新；没有它，各元件更新有先有后，状态就乱了。
- **为什么很自然**：因为"记忆"在物理上需要"在某个确定的时刻把新值固定下来"，而时钟恰好提供一个全系统公认的固定时刻。
- **一句话直觉本质**：**用时钟把"何时更新"统一起来，用 DFF 把"单个 bit 的过去"保存下来，用 load 开关与地址解码把 DFF 组织成寄存器与 RAM。**

---

## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
- **DFF（Data Flip-Flop）**：时序基本单元，在时钟**上升沿**把输入 `in` 采样并输出，其余时间输出保持不变：`out(t+1) = in(t)`（在上升沿处）。
- **1-bit 寄存器（Bit）**：`DFF + Mux`，带 `load` 使能：`load=1` 时下一拍存入新值，`load=0` 时保持旧值。
- **16-bit 寄存器（Register）**：16 个 Bit 并行，`load` 共用一个。
- **RAM**：寄存器阵列 + 地址解码器，支持"按地址读、按地址写"；Hack 中读写同一时钟周期内完成。
- **PC（Program Counter）**：带 `reset/load/inc` 三控制位的 16 位寄存器：`reset` 清零、`load` 载入跳转地址、`inc` 自增 1，三者优先级 reset > load > inc。

### 2. 核心公式
DFF 行为（上升沿时刻）：
$$\text{out}(t+1) = \text{in}(t)$$

Bit 寄存器行为（`load` 使能）：
$$\text{out}(t+1) = \begin{cases} \text{in}(t) & \text{load} = 1 \\ \text{out}(t) & \text{load} = 0 \end{cases}$$

RAM 容量与地址位宽：
$$W = 2^{k} \quad (k = \text{地址位数},\ W = \text{字数})$$

PC 行为（每周期末）：
$$\text{PC}(t+1) = \begin{cases} 0 & \text{reset} \\ A(t) & \text{load} \\ \text{PC}(t)+1 & \text{inc} \\ \text{PC}(t) & \text{其他} \end{cases}$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $t$ | 时钟周期序号 | $\mathbb{N}$ | 一个周期 = 一次上升沿到下一次上升沿 |
| `in`, `out` | DFF/寄存器输入输出 | $\{0,1\}$ 或 $\{0,1\}^{16}$ | 16 位寄存器总线宽度 16 |
| `load` | 写使能 | $\{0,1\}$ | 1 = 下一拍写入新值 |
| `address` | RAM 访问地址 | $[0, 2^k-1]$ | 经解码器选中一行寄存器 |
| `reset/load/inc` | PC 三控制位 | $\{0,1\}$ | 优先级 reset > load > inc |

### 4. 常见变体与适用条件
- **变体**：Hack 用"上升沿触发 DFF"；真实硬件还有电平触发锁存器、双沿触发等，原理一致。RAM 家族按容量递推：RAM8（3 位地址）→ RAM64 → RAM512 → RAM4K → RAM16K（14 位地址）。
- **适用条件**：需要"记忆/状态"的电路——寄存器、计数器、内存、CPU 状态机。
- **限制条件**：时序元件必须有稳定时钟；组合逻辑延迟必须小于时钟周期，否则上升沿采到"还没算完"的值（时序违规）。

---

## 6. 推导思路和思想来源
- **最初困难**：纯组合电路无记忆，无法保存中间结果，也无法形成"循环执行"。
- **直接方法局限**：把输出直接反馈回输入会形成不稳定的环（振荡或竞争），没人能预测结果。
- **关键"转念"**：① 在反馈环中插入一个**受时钟控制的闸门**（DFF），把"无休止的循环"变成"每个周期只前进一步"；② 给 DFF 加 `load` 开关，让"是否更新"由指令说了算；③ 用**地址解码**（Mux/DMux 的规模化）把"一堆寄存器"组织成"按号存取的内存"。
- **推导主线与动机**：DFF（1 bit 记忆）→ Bit（+load 开关）→ Register（16 bit 并行）→ RAM8/64/…/16K（地址解码器 + 多路选择）→ PC（+自增/清零/载入）。每一层只增加"一小点语义"，但合起来就从"存一个数"升级到"可寻址内存 + 程序计数器"。
- **为什么自然得到此结论**：因为"先解决最小单位的记忆，再用组合逻辑做组织与选择，最后用控制位表达语义"是硬件层次化设计的标准递归——与 Project 01 的"门 → 复杂门"完全同构。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：一个 1-bit 寄存器，`load` 序列为 1,1,0,1，`in` 序列为 0,1,1,0（每个周期一个值），写出 `out` 的变化。
- **解题思路与关键步骤**：`out` 在每个上升沿按 `load` 决定是否取 `in`：周期 1（load=1, in=0）→ out=0；周期 2（load=1, in=1）→ out=1；周期 3（load=0, in=1）→ **保持 out=1**；周期 4（load=1, in=0）→ out=0。
- **最终答案**：`out: 0 → 1 → 1 → 0`。
- **易错点**：周期 3 输入虽然是 1，但 `load=0`，值不写入——"输入变化 ≠ 寄存器变化"。
- **🤔 追问**：如果 `load` 恒为 0？out 永远保持初值，寄存器变成"只读"——这正解释了为何 RAM 未选中行不会被动。
### 例子 2：中等例子（条件判断与多步推理）
- **题目**：用 RAM8（8 个字 × 16 位，3 位地址）设计读写通路，说明为什么"读"不需要时钟而"写"需要。
- **解题思路与完整解答**：地址经 3-8 解码器（DMux 级联）选中一行；**读**：用 8 路 Mux16 按地址把选中寄存器的 `out` 送到 `RAM8.out`，纯组合逻辑，随时可读；**写**：`load` 信号与解码器输出做 AND，只有被选中行收到 `load=1`，在时钟沿写入，其余行 `load=0` 保持。**关键推理**：多个寄存器共享一条数据总线，读靠"选择"，写靠"使能"，二者不冲突。
- **易错点**：忘记写通路也要 AND 上"本行选中"——否则所有行同时写入，内存互相覆盖。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HW03 的 `RAM16K` 在 HW05 中成为数据内存与指令内存；PC 是"程序计数器"的原型，其 `reset/load/inc` 正是 HW04 汇编中 `JMP`/`JEQ`/顺序执行三条路径的硬件来源。真实 CPU 的寄存器堆 = "多端口 Register + 地址选择"，Cache 行 = "带标签的 RAM"，思想一脉相承。
- 代码形态（HDL 片段，Bit 寄存器）：
```hdl
CHIP Bit {
    IN in, load;
    OUT out;
    PARTS:
    Mux(a=out, b=in, sel=load, out=w);  // load=1 取新值，否则回读旧值
    DFF(in=w, out=out);
}
```

## 8. 常见误区和易混概念
### 误区 1：以为"组合逻辑有环就能当记忆"
- **错误直觉**：把输出直接连回输入（如 `Or(a=in, b=out, out=out)`）就能"记住"东西。
- **为什么错**：无时钟的反馈环行为不定——可能振荡、可能竞争，模拟器直接拒绝；即使稳定，也无法控制"何时更新"。
- **正确理解**：记忆必须通过**受时钟控制的 DFF** 形成；环上必须有一个"闸门"把更新时刻钉死在时钟沿。
### 误区 2：把"周期"当"瞬间"，以为一个周期内能做无限多事
- **错误直觉**：时钟越快，一个周期内电路能完成的步骤越多。
- **为什么错**：一个时钟周期内，组合逻辑必须完成从输入到输出的全部传播（加法器进位链延迟是典型瓶颈）；周期太短会采到中间值。
- **正确理解**：周期长度由"最慢组合路径延迟 + 时序裕量"决定；性能优化 = 缩短关键路径（如加法器改为先行进位），这是 [[Amdahl定律]] 与流水线讨论的起点。

### 概念对比表
| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 组合逻辑 | 输出=当前输入的函数 | 无记忆、无时钟 | 门、加法器、ALU |
| 时序逻辑 | 输出依赖历史状态 | 有 DFF、有时钟 | 寄存器、RAM、PC（本知识点） |
| 寄存器 | 存一个数 | 地址=固定、load 使能 | CPU 内部临时数据 |
| RAM | 存一批数 | 地址=输入、按号存取 | 内存、指令存储（见 [[🧠 CPU与取指执行循环]]） |

### 题目与解析
#### 1. 为什么"把输出连回输入"不能实现记忆，而 DFF 可以？
> [!question]- 答案解析
> - **答案**：无时钟的反馈环行为不确定（振荡/竞争），且没有"何时更新"的约定；DFF 在反馈环中充当受时钟沿控制的闸门，把更新时刻钉死在上升沿，行为确定且同步。
> - **解析**：`Bit` 的 HDL 中 `Mux(a=out, b=in, sel=load)` 就是"受控反馈"——反馈存在，但被时钟与 load 双重闸住。
> - **易错原因**：以为"有环 = 有记忆"，忽略环必须有时钟闸门。
> - **对应误区**：误区 1（无时钟反馈当记忆）。
> - **Obsidian 标签建议**：`#自测题/基础`
#### 2. RAM16K 需要多少位地址？RAM512 呢？写出换算过程。
> [!question]- 答案解析
> - **答案**：$16\text{K} = 2^{14}$，需要 14 位地址；$512 = 2^9$，需要 9 位地址。
> - **解析**：由 $W = 2^k$ 得 $k = \log_2 W$；16K = 16384 = $2^{14}$。Hack 中数据内存地址 0~16383（14 位），加上屏幕/键盘映射共 15 位地址空间。
> - **易错原因**：把 "16K" 误算成 $2^{16}$（16K = 16 × 1024 = 16384，不是 65536）。
#### 3. 一个 Register 的 `load=0` 且输入总线持续变化，输出会怎样？为什么？
> [!question]- 答案解析
> - **答案**：输出保持不变，持续输出旧值；因为 `Mux(a=out, b=in, sel=0)` 回读的是自身输出，DFF 只在时钟沿把回读值再次锁存，输入变化被隔离。
> - **解析**：这正是"读操作不影响状态"的机制；RAM 中未选中行也因 `load=0`（选中信号 AND 结果为 0）而保持不变。
> - **易错原因**：误以为"输入变化会穿过寄存器"。
#### 4. 若某周期内 `reset=1, load=1, inc=1` 同时为 1，PC 下一值是什么？请推理。
> [!question]- 答案解析
> - **答案**：0（清零优先）。
> - **解析**：Hack 的 PC 实现中，`reset` 的 Mux 位于最外层：先处理 reset（清 0），再处理 load（载入 A），最后 inc（自增）；三控制位同时为 1 时只有 reset 生效。
> - **易错原因**：不记得优先级 reset > load > inc，或以为会"先自增再清零"（结果仍为 0，但推理错误）。
#### 5. 简述：为什么存储元件必须"由时钟控制何时更新"，而不是"输入一变就更新"？
> [!question]- 答案解析
> - **答案**：若每个元件"输入一变就更新"，各组合路径延迟不同，同一时刻不同元件会处于不同"版本"的状态，系统行为不可预测；统一时钟沿使所有 DFF 在同一瞬间采样，保证"全体状态一致地前进一个周期"，这是同步时序设计的基石。
> - **解析**：这也是"组合逻辑延迟必须小于时钟周期"的原因——上升沿必须等到所有路径都稳定后才能到来；HW05 的 CPU 正是靠这一点把取指/执行拆成确定的周期序列。
> - **易错原因**：把同步更新当成可选项，而非正确性前提。
