# ALU算术逻辑单元

---

## 0. 先判断它值不值得深挖
- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：HW02（Project 02）的全部交付物就是本层（HalfAdder → FullAdder → Add16 → Inc16 → ALU）；且 ALU 是 Project 05 CPU 的"计算心脏"——没有它，CPU 无法执行任何 C 指令。补码与溢出是后续汇编、系统软件层反复使用的硬知识，值得一次挖透。

---

## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> Project 01 的门只能做单 bit 的与、或、非、异或。但一台计算机必须能做**算术**：加、减、与、或、取反、比较……朴素做法是每种运算单独造一个电路，那么 CPU 里就要有十多个互相独立的运算器，既不经济也无法在"一条指令里选一种运算"。
> 因此必须引入两样东西：**加法器链**（用门把"两个 16 位数相加"变成现实，靠补码让减法免费）和 **ALU**（一个芯片 + 6 个控制位，用同一套硬件在 16 种运算间切换）。

---

## 2. 为什么它重要？它有什么用？
- **连接大图景**：ALU 的输出会被 [[🧠 时序逻辑与寄存器]] 的 D 寄存器锁存，再被 [[🧠 CPU与取指执行循环]] 的指令控制位驱动；HW02 是硬件链上承 HW01、下启 HW03/HW05 的必经站。
- **实际应用场景**：所有真实 CPU（x86/ARM/RISC-V）的 ALU 都是同一设计哲学的放大版；面试常考"补码溢出判断""用 NAND 搭全加器"。
- **高频题型/任务**：半加器/全加器真值表；补码加减手算；溢出检测规则；ALU 六个控制位的组合效果；HDL 中 `Add16`/`ALU` 的编写与 `.tst` 验证。

---

## 3. 学它之前需要哪些前置知识？
1. **[[🧠 布尔逻辑门与HDL]]**：AND/OR/XOR/Mux 门与 `PARTS` 复用语法——本层所有芯片都由它们拼出。
2. **二进制与补码表示**：只需知道"负数用补码存、补码 = 取反 + 1、n 位补码范围 $[-2^{n-1}, 2^{n-1}-1]$"，细节在本层推导中巩固。

## 4. 用直觉语言解释它
> «"ALU 就像一把瑞士军刀：一个盒子，上面有几个旋钮（控制位），你把旋钮拧到"加"，它就把两个 16 位数加起来；拧到"与"，它就做位与。补码则像汽车的里程表——倒车到 -1 时表盘显示 9999（模 10000），所以"减 1"和"加 9999"是同一件事，减法就此变成加法。"»

- **直觉类比/几何图像**：加法器 = 逐位"半加 + 进位传递"的链条（像竖式加法，只是 1+1 会"满二进一"）；补码 = 模 $2^{16}$ 的钟表算术，表盘只有 16 个刻度。
- **为什么很自然**：竖式加法天生就是"本位和 + 进位"的递归；钟表模算术让负数、减法、溢出全部统一到"加法"一个操作上。
- **一句话直觉本质**：**用进位链把加法做出来，用补码把减法变成加法，再用 6 个控制位让同一套加法/逻辑硬件在 16 种运算间切换。**

---

## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
- **半加器（HalfAdder）**：两位相加，输出本位和 `sum` 与进位 `carry`，不考虑低位进位。
- **全加器（FullAdder）**：三位相加（两输入 + 低位进位 $c_{in}$），输出和与进位 $c_{out}$。
- **ALU**：输入两个 16 位数 $x, y$ 与 6 个控制位，输出 16 位结果 `out` 与两个标志位（`zr` 全零、`ng` 为负）的组合逻辑芯片。

### 2. 核心公式
$$s = a \oplus b \oplus c_{in}, \qquad c_{out} = (a \cdot b) + c_{in} \cdot (a \oplus b)$$

补码与减法（模 $2^{16}$ 加法）：
$$-x \equiv \overline{x} + 1 \pmod{2^{16}}, \qquad x - y = x + (\overline{y} + 1)$$

ALU 控制位语义（对 16 位总线逐位操作）：

| 控制位 | 为 1 时作用 | 控制位 | 为 1 时作用 |
| :--- | :--- | :--- | :--- |
| `zx` | $x \leftarrow 0$ | `zy` | $y \leftarrow 0$ |
| `nx` | $x \leftarrow \overline{x}$ | `ny` | $y \leftarrow \overline{y}$ |
| `f` | 选 `Add`（1）或 `And`（0） | `no` | 输出取反 |

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| $a, b, c_{in}$ | 全加器输入位与低位进位 | $\{0,1\}$ | $c_{in}$ 来自低一位的 $c_{out}$ |
| $x, y$ | ALU 两个 16 位操作数 | $\{0,1\}^{16}$ | 补码解释时范围 $[-32768, 32767]$ |
| $zx, nx, zy, ny, f, no$ | ALU 控制位 | $\{0,1\}$ | 共 $2^6 = 64$ 种组合，Hack 只用 16 种 |
| `out`, `zr`, `ng` | 结果与标志 | $\{0,1\}^{16},\ \{0,1\}$ | `zr=1` 当且仅当 `out=0`；`ng=1` 当且仅当 `out<0` |

### 4. 常见变体与适用条件
- **变体**：Hack ALU 是"逻辑 + 算术"二选一（`f` 位）；真实 CPU 的 ALU 还有移位、比较等更多功能块，但"控制位选路"思想一致。
- **适用条件**：纯组合逻辑，无时钟；运算结果只由当前输入决定。
- **限制条件**：加法器链的进位传播有延迟；补码运算有固定范围，超出即溢出（标志位只报告、不纠正）。

---

## 6. 推导思路和思想来源
- **最初困难**：门只会单 bit 逻辑，做不出"两个 16 位数相加"。
- **直接方法局限**：把 16 位加法拆成 16 个独立问题？——每一位都依赖低一位的进位，无法并行独立求解；而给每种运算都造独立电路又太浪费。
- **关键"转念"**：① 用**进位链**把"位与位之间的依赖"显式建模（半加器 → 全加器 → 16 位行波进位加法器）；② 用**补码**把减法、负数统一成模 $2^{16}$ 加法；③ 用**控制位 + Mux** 把 16 种运算折叠进一个芯片——"多算一器"。
- **推导主线与动机**：真值表 → 半加器公式 → 引入 $c_{in}$ 得全加器 → 串成 `Add16` → 补码使 `x - y = x + (~y + 1)` → 用 `zx/nx/zy/ny` 实现"零化/取反"、`f` 选加或与、`no` 取反 → 六位控制真值表覆盖 $x{+}y,\ x{-}y,\ x{\&}y,\ x{|}y,\ \neg x,\ \neg y,\ {-}x,\ {-}y,\ x{+}1,\ y{+}1,\ x{-}1,\ y{-}1$ 等 16 种运算。
- **为什么自然得到此结论**：因为"把复杂的多位运算归结为逐位的简单操作 + 一种统一表示（补码）+ 一组选择开关"是硬件设计的必然收敛——既省门数，又让指令译码极其简单。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：用 4 位补码手算 $5 + (-3)$。
- **解题思路与关键步骤**：$5 = 0101$；$3 = 0011$，取反 $1100$ 加 1 得 $-3 = 1101$。竖式相加：$0101 + 1101 = 10010$，丢弃第 5 位进位得 $0010 = 2$。
- **最终答案**：$5 + (-3) = 2$，正确，无溢出（两个异号数相加不可能溢出）。
- **易错点**：把"丢弃最高进位"当成错误——在模 $2^4$ 补码里，这个进位正是模运算的"满 16 归零"，必须丢弃。
- **🤔 追问**：如果改成 4 位补码算 $7 + 1$？$0111 + 0001 = 1000 = -8$，两正数相加得负数 → 溢出。
### 例子 2：中等例子（条件判断与多步推理）
- **题目**：判断 4 位补码中 $(-6) + (-5)$ 是否溢出。
- **解题思路与完整解答**：$-6 = 1010$，$-5 = 1011$，相加 $1010 + 1011 = 10101$，取低 4 位 $0101 = +5$。**推理**：两负数相加结果应为负，却得正数 → 溢出。通用判据：**最高位进位 ≠ 次高位进位**（即"符号位被破坏"）。这里最高位进位 1、次高位进位 0，不等 → 溢出。
- **易错点**：只看"有没有最高位进位"判断溢出——本例最高位有进位，但真正的溢出信号是"两个进位不一致"。

### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HW02 的 `ALU.hdl` 由 `Add16`、`Mux16`、`Not16` 等拼装，`zr`/`ng` 标志位直接服务 Project 04 汇编的跳转指令（`JEQ` 查 `zr`、`JLT` 查 `ng`）；HW05 中 CPU 让 ALU 兼任"数据运算"与"地址计算"（`A+1`、`D-A` 等），这就是真实 CPU 复用 ALU 的缩影。
- 代码形态（HDL 片段，控制位选路）：
```hdl
// zx=1 时把 x 清零，否则直通
Mux16(a=x, b[0..15]=false, sel=zx, out=zxed);
Not16(in=zxed, out=nxz);
Mux16(a=zxed, b=nxz, sel=nx, out=x1);   // nx=1 时取反
```

## 8. 常见误区和易混概念
### 误区 1：把补码的符号位当成"独立的符号标记"
- **错误直觉**：最高位是"符号位"，其余位是"数值"，负数就是"符号位 1 + 绝对值"。
- **为什么错**：若是那样，$-3$ 应为 $1011$，但补码中 $-3 = 1101$；且 $1000$ 表示 $-8$ 而非 $-0$。补码是**一个整体**的模 $2^{16}$ 表示，不是"符号 + 数值"拼接。
- **正确理解**：补码中减法和加法完全统一；判断正负只看最高位（`ng`），但数值解读必须整体按模运算。

### 误区 2：以为 ALU 的 `f` 位是"加或减"
- **错误直觉**：`f=1` 做加法、`f=0` 做减法。
- **为什么错**：ALU 里根本没有减法器——减法由"先取反加一（`ny` + `f`）再加法"实现；`f` 只负责在 `Add` 与 `And` 之间选路。
- **正确理解**：`f=0` 是位与、`f=1` 是加法；"减"是若干控制位组合的效果，不是独立模式。

### 概念对比表

| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| 半加器 | 两位相加 | 无 $c_{in}$，只有 2 输入 | 加法器最低位 |
| 全加器 | 三位相加 | 有 $c_{in}$，可级联 | 加法器其余位 |
| ALU | 多种运算合一 | 有控制位，输出标志位 | CPU 运算核心（见 [[🧠 CPU与取指执行循环]]） |
| 普通加法器 | 只做加法 | 无控制位、无标志 | 专用计算单元 |

### 题目与解析
#### 1. 半加器与全加器在结构和功能上有何区别？为什么 16 位加法器不能只用 16 个半加器？
> [!question]- 答案解析
> - **答案**：半加器只有 $a,b$ 两个输入，输出 `sum = a⊕b`、`carry = a·b`；全加器多一个低位进位输入 $c_{in}$，输出 `sum = a⊕b⊕c_in`、`c_out = (a·b) + c_in·(a⊕b)`。除最低位外，每位相加都要加上低位的进位，所以第 2~16 位必须用全加器。
> - **解析**：半加器恰好是 $c_{in}=0$ 的全加器特例；级联时把低位的 `carry` 接到高位的 `c_in` 即得行波进位加法器。
> - **易错原因**：忘记"进位会逐位传递"，误以为每位可独立相加。
> - **对应误区**：误区 2（把 ALU 当减法器）的同类错误——忽视位间依赖。
> - **Obsidian 标签建议**：`#自测题/基础`
#### 2. 用 8 位补码手算 $25 - 40$，写出过程与结果。
> [!question]- 答案解析
> - **答案**：$25 = 00011001$；$40 = 00101000$，取反 $11010111$ 加 1 得 $-40 = 11011000$；$00011001 + 11011000 = 11110001 = -15$。验证：$11110001$ 取反 $00001110$ 加 1 得 $00001111 = 15$，故原值 $-15$ 正确。
> - **解析**：减法统一为"被减数 + 减数的补码"；结果最高位为 1 表示负数，可再取反加一验证。
> - **易错原因**：把 $-40$ 的补码算错（少做"+1"）。
#### 3. 什么情况下补码加法必然溢出？给出判断方法。
> [!question]- 答案解析
> - **答案**：两正数相加结果为负，或两负数相加结果为正，即发生溢出。硬件判据：最高位进位与次高位进位**不一致**时溢出。
> - **解析**：异号相加结果的绝对值不超过任一操作数，不可能溢出，只需检查同号相加；"符号位被进位破坏"等价于两个进位不等。
> - **易错原因**：把"最高位有进位"误当溢出（如 $(-1)+(-1)$ 有进位但结果 $-2$ 正确）。
#### 4. 若 ALU 的控制位为 `zx=1, nx=0, zy=1, ny=1, f=1, no=0`，输出是什么？
> [!question]- 答案解析
> - **答案**：`zx=1` 使 $x=0$，`zy=1` 使 $y=0$，`ny=1` 使 $y$ 取反为全 1（即 $-1$）；`f=1` 做加法 $0 + (-1) = -1$；`no=0` 不取反。输出 `out = -1`（全 1），`zr=0, ng=1`。
> - **解析**：这正是 Hack ALU 真值表中"$y{+}1$→$y{-}1$"类组合的套路：全 1 就是补码 $-1$，所以 `0 + (-1) = -1`。
> - **易错原因**：忘记"全 1 位串 = 补码 -1"，或漏掉 `ny` 在 `zy` 之后仍生效的顺序。
#### 5. 证明：对任意 n 位二进制数 $x$，$\overline{x} + 1 \equiv -x \pmod{2^n}$。
> [!question]- 答案解析
> - **答案**：因为 $\overline{x} = (2^n - 1) - x$（每位取反等于"全 1 减 $x$"），所以 $\overline{x} + 1 = 2^n - x \equiv -x \pmod{2^n}$。
> - **解析**：这解释了为何补码取负只需"取反加一"——硬件上 `Not16 + Inc16` 两行 HDL 即可，无需真正的减法器；也是 HW02 中 `Neg` 的实现依据。
> - **易错原因**：只背结论，说不出 $\overline{x} = 2^n - 1 - x$ 这一关键等式。
