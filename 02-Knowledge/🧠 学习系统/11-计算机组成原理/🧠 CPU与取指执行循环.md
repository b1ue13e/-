# CPU与取指执行循环

---

## 0. 先判断它值不值得深挖
- **类别**：**A 类（核心概念，必须深挖）**
- **判断理由**：HW05（Project 05）的整机 CPU 是本硬件链的**顶点**——前四个 Project 的所有积木在这里第一次组装成"能跑程序"的机器；同时"取指-译码-执行"是计算机体系结构的第一性框架，后续汇编器（HW06）、VM（HW07/08）都围绕它展开。这也是 Nand2Tetris 硬件部分的"毕业考"。

---

## 1. 这个知识点解决什么问题？
> **我们遇到了什么麻烦**：
> 我们有了 ALU（会算）、寄存器与 RAM（会记）、PC（会数数），但它们各自为政：谁告诉 ALU 这次算加法还是减法？算完的结果送给谁？下一条指令的地址怎么变？一台"计算机"必须把这一切**编排成一个无限循环的自动流程**——机器自己从内存取指令、读懂它、执行它、再取下一条。
> 因此必须引入**指令集架构（ISA）**：给机器规定两种指令格式（A 指令、C 指令），并设计**数据通路**（ALU + A/D 寄存器 + PC + 一堆控制线），让每条指令在硬件上自动走完"取指 → 译码 → 执行"，循环不息。

---

## 2. 为什么它重要？它有什么用？
- **连接大图景**：HW05 把 [[🧠 ALU算术逻辑单元]] 与 [[🧠 时序逻辑与寄存器]] 组装成整机；HW04 的汇编程序（Fill/Mult）第一次在自建 CPU 上跑通；HW06 汇编器的翻译目标（A/C 指令编码）就定义在本层。
- **实际应用场景**：任何 CPU（x86/ARM/RISC-V）都是"取指-译码-执行"的工程化变体；理解它才能看懂流水线、分支预测、RISC/CISC 之争。
- **高频题型/任务**：A/C 指令二进制 ↔ 汇编互译；C 指令各字段（a/comp/dest/jump）解码；CPU 内部数据通路连线（Mux 选 y 输入、dest 位生成写使能、jump 位生成 PC 载入信号）；整机测试 `Computer` 的 `.tst` 跑通。

1. **[[🧠 时序逻辑与寄存器]]**：A/D 寄存器、PC、指令/数据内存——CPU 的"记忆骨架"全部来自这一层。
2. **[[🧠 ALU算术逻辑单元]]**：C 指令的 comp 字段直接映射到 ALU 的 6 个控制位；`zr/ng` 标志驱动跳转判断。
3. **[[🧠 布尔逻辑门与HDL]]**：Mux、总线切片等组合技巧用于搭建控制逻辑。

## 4. 用直觉语言解释它
> «"CPU 像一个流水线上的装配工：他面前有一条传送带（指令内存 ROM），每拍从传送带上拿下一张工单（指令）。工单分两种：A 单只写"把数字 5 放进抽屉 A"；C 单写着"把抽屉 D 里的数和抽屉 A 里的数相加，结果放回 D；如果结果小于 0，就把工单流转到第 100 号工位"。装配工看不懂文字，但他身后的机器（ALU、抽屉、计数器）一听控制信号就动。周而复始，直到工单要求停机。"»

- **直觉类比/几何图像**：取指 = 按 PC 号牌取工单；译码 = 拆工单字段（哪些控制线置 1）；执行 = 让 ALU/寄存器/内存按控制线动作；PC 更新 = 决定下一张工单从哪来（顺序 +1，或跳转）。
- **为什么很自然**：因为"循环取工单"是把"无限的程序"压进"有限的硬件"的唯一办法——硬件只有一套，程序却可以任意长。
- **一句话直觉本质**：**用固定格式的指令把"要做什么"编码成二进制，用数据通路把指令译成控制信号并执行，用 PC 的更新规则让机器自动进入下一条指令——计算由此变成可编程的无限循环。**

---

## 5. 正式定义、核心公式、符号解释
### 1. 最核心定义
- **取指-译码-执行循环**：CPU 每周期执行"①用 PC 从指令内存取 16 位指令；②按最高位区分 A/C 指令并拆出字段；③组合逻辑完成运算/访存/写寄存器；④周期末更新 PC 与寄存器"，如此往复。
- **A 指令**：`0xxxxxxxxxxxxxx`（最高位 0 + 15 位值），作用：把该值载入 A 寄存器（既可作地址、也可作立即数）。
- **C 指令**：`111accccccdddjjj`（最高位 111 + a + 6 位 comp + 3 位 dest + 3 位 jump），作用：执行一次运算并决定写哪里、是否跳转。

### 2. 核心公式
指令格式（16 位）：
$$\text{A}: \quad 0\,[a_{14}\cdots a_0] \qquad \text{C}: \quad 111\,a\,[c_1\cdots c_6]\,[d_1d_2d_3]\,[j_1j_2j_3]$$

ALU 双输入与 dest/jump 语义：
$$x = D,\qquad y = \begin{cases} A & a=0 \\ M & a=1 \end{cases}$$

$$\text{dest}: d_1 \to A,\ d_2 \to D,\ d_3 \to M \quad(\text{对应位为 1 即写入})$$

$$\text{jump}: j_1 = \text{out}<0,\ j_2 = \text{out}=0,\ j_3 = \text{out}>0 \quad(\text{满足即 PC} \leftarrow A)$$

PC 更新（周期末）：
$$\text{PC}(t{+}1) = \begin{cases} A & \text{跳转条件成立} \\ \text{PC}(t)+1 & \text{否则} \end{cases}$$

### 3. 符号说明表

| 符号 | 含义 | 取值范围 / 量纲 | 备注 |
| :--- | :--- | :--- | :--- |
| `PC` | 程序计数器 | $[0, 32767]$ | 指向下一条指令地址 |
| `instruction` | 16 位指令 | $\{0,1\}^{16}$ | 最高位 0=A 指令，111=C 指令 |
| `A, D` | 地址/数据寄存器 | $\{0,1\}^{16}$ | A 兼作地址与立即数 |
| `M` | 数据内存字 | $\{0,1\}^{16}$ | `addressM = A`，`outM`/`writeM` 为写接口 |
| `zr, ng` | ALU 标志 | $\{0,1\}$ | 跳转判断的输入信号 |

### 4. 常见变体与适用条件
- **变体**：Hack 是"单周期、指令/数据内存分离（哈佛结构）"的极简 ISA；真实 CPU 用冯·诺依曼结构（统一内存）+ 流水线，但循环骨架相同。
- **适用条件**：任何"程序存储 + 自动执行"的通用计算机；A/C 指令覆盖了算术、访存、控制流三类基本操作。
- **限制条件**：单周期设计下，组合路径延迟决定最高时钟频率；Hack 没有中断、没有特权级，属于教学最小集。

## 6. 推导思路和思想来源
- **最初困难**：有 ALU、有内存、有 PC，但没有"自动编排"机制，机器不知道每条指令该做什么。
- **直接方法局限**：给每条指令单独造一套硬件？程序无限多，硬件做不到；把程序"固化"成硬连线（像早期计算机）？换程序就得改电路。
- **关键"转念"**：**存储程序思想**（冯·诺依曼）——程序与数据一样以二进制放在内存里，硬件只认固定格式；再用"指令字段 → 控制信号"的译码表把软件语义映射到硬件动作。A/C 两类指令把"装载、运算、访存、跳转"四种需求全部编码。
- **推导主线与动机**：需求清单（算、存、取、跳）→ A 指令负责"准备操作数/地址"（15 位值装进 A）→ C 指令负责"运算 + 写回 + 跳转"（comp 位直接复用 ALU 控制位，dest 位生成写使能，jump 位与 `zr/ng` 组合生成 PC 载入信号）→ 用 Mux 在"指令值 / ALU 输出 / PC+1"之间选路，数据通路定型。
- **为什么自然得到此结论**：因为"译码 = 查表生成控制信号"与"控制信号 = 各部件使能位"是硬件设计的必然接口；ALU 控制位设计（前一篇）正是为了此刻能被指令字段直接驱动。

## 7. 例子：基础 → 中等 → 实际应用
### 例子 1：基础例子（可手算）
- **题目**：把汇编 `@17` 与 `D=A` 翻译成二进制。
- **解题思路与关键步骤**：`@17` 是 A 指令：最高位 0 + 17 的 15 位二进制 `000000000010001`，拼成 `0000000000010001`。`D=A` 是 C 指令：前缀 111；comp 为 `A`（a=0, c1..c6 = 110000）；dest 只有 D 位（`010`）；jump 无（`000`）。拼得 `1110110000010000`。
- **最终答案**：`@17 → 0000000000010001`；`D=A → 1110110000010000`。
- **易错点**：A 指令的 15 位值从第 0 位起填，高位补 0；C 指令前缀固定 111，不能少。
- **🤔 追问**：若把 `D=A` 的 comp 改成 `M`（a=1），二进制变 `1111110000010000`——执行的将是"把内存中地址为 A 的值装入 D"。
### 例子 2：中等例子（条件判断与多步推理）
- **题目**：解码指令 `1110001100001001` 并说明 CPU 将做什么。
- **解题思路与完整解答**：前缀 111 确认 C 指令；剩余 13 位 `0001100001001` 拆为：a=0，comp=`000110`（查表 = `D&A`），dest=`001`（d1=1 → 写 A），jump=`001`（j1=1 → out<0 跳转）。**推理**：ALU 计算 `D & A`，结果写入 A 寄存器；若结果 < 0，则下一周期 PC 载入 A（即跳转到 `@A` 指定的地址），否则顺序执行。这等价于汇编 `D&A; JLT` 的机器码。
- **易错点**：dest 三位顺序是 A-D-M（不是 M-D-A）；jump 三位顺序是 JLT-JEQ-JGT，与直觉的"小于、等于、大于"一一对应。
### 例子 3：实际应用例子（真实场景/代码）
- **实际价值与转化**：HW05 的 `CPU.hdl` 把 ALU 同时用于"数据运算"与"地址计算"（`D+M`、`A+1` 等），并通过 `writeM`/`outM`/`addressM` 与数据内存对接；整机 `Computer` 再把屏幕（地址 16384 起）与键盘（24576）内存映射进同一地址空间——这就是真实 SoC 的"外设寄存器映射"雏形。
- 代码形态（HDL 片段，jump 逻辑生成 PC 载入信号）：
```hdl
// 根据 ALU 标志与 jump 位决定是否跳转
Or(a=zr, b=ng, out=zrOrNg);
Not(in=zrOrNg, out=notZrNg);          // out>0
And(a=j1, b=ng, out=jt1);             // JLT
And(a=j2, b=zr, out=jt2);             // JEQ
And(a=j3, b=notZrNg, out=jt3);        // JGT
Or(a=jt1, b=jt2, out=jt12);
Or(a=jt12, b=jt3, out=jump);          // 跳转条件
```

## 8. 常见误区和易混概念
### 误区 1：以为"取指、译码、执行"是三个独立时钟周期
- **错误直觉**：像流水线一样，一条指令要花三个周期才完成。
- **为什么错**：Hack 是单周期 CPU——同一个周期内，PC 取指、组合逻辑译码并执行、上升沿写寄存器，一步完成；"取指-译码-执行"是**概念上的三个子步骤**，不是三个时钟节拍。
- **正确理解**：单周期 = 一条指令一个周期；流水线（HW 之后的进阶话题）才是把三步拆到不同周期重叠执行。
### 误区 2：把 A 指令当成"只能存地址"
- **错误直觉**：`@5` 就是"访问内存地址 5"。
- **为什么错**：A 指令只是"把 5 装进 A 寄存器"；是否访存取决于后续 C 指令的 comp 是否用 `M`（如 `D=M` 才读内存，`D=A` 只是取立即数）。
- **正确理解**：A 寄存器是"地址/立即数双用寄存器"——这是 Hack 极简 ISA 的关键设计，也是 `@` 与 `M` 用法混淆的根源。

### 概念对比表
| 概念 | 核心问题 | 关键区别 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| A 指令 | 装载操作数/地址 | 最高位 0，只写 A 寄存器 | `@100`、`@R0` 等初始化 |
| C 指令 | 运算+写回+跳转 | 最高位 111，含 comp/dest/jump | `D=M+1; JGT` 等主体逻辑 |
| 组合逻辑 | 输出=输入函数 | 无状态 | ALU、译码器（见 [[🧠 ALU算术逻辑单元]]） |
| 时序部件 | 保存状态 | 时钟沿更新 | A/D、PC、内存（见 [[🧠 时序逻辑与寄存器]]） |

### 题目与解析
#### 1. 在 Hack 单周期 CPU 中，"取指-译码-执行"是三个时钟周期吗？请解释。
> [!question]- 答案解析
> - **答案**：不是。三个子步骤在**同一个时钟周期内**完成：PC 组合输出地址 → ROM 返回指令 → 译码器生成控制信号 → ALU/寄存器/内存完成动作 → 上升沿统一写入 A/D/PC。
> - **解析**：单周期 CPU 的周期长度 = 取指+译码+执行整条组合路径的延迟；"三阶段"是概念分解而非时间分解，流水线 CPU 才把三者分到不同周期重叠执行。
> - **易错原因**：把概念步骤与时钟节拍混淆。
> - **对应误区**：误区 1（三周期误解）。
> - **Obsidian 标签建议**：`#自测题/基础`
#### 2. 把机器码 `0000000000111111` 翻译成汇编。
> [!question]- 答案解析
> - **答案**：`@63`。
> - **解析**：最高位 0 → A 指令；后 15 位 `000000000111111` = 63（$32+16+8+4+2+1$），即"把 63 装入 A 寄存器"。
> - **易错原因**：把 15 位值算错（如漏掉某位），或误当成 C 指令。
#### 3. 汇编 `D=M` 与 `D=A` 的执行差异是什么？何时用哪个？
> [!question]- 答案解析
> - **答案**：`D=M` 把"数据内存中地址为 A 的字"读入 D（a=1）；`D=A` 直接把 A 寄存器的值（可能是立即数）放入 D（a=0）。需要读写内存时用 M，只需操作 A 中数值时用 A。
> - **解析**：M 是"以 A 为地址的内存字"，只有 C 指令中出现 `M` 才发生访存；A 指令本身从不访存。
> - **易错原因**：以为 `@5` 就已访问内存——它只是装载地址/立即数。
#### 4. 解码 `1111110000010010`：写出 a/comp/dest/jump 与对应汇编。
> [!question]- 答案解析
> - **答案**：a=1，comp=`110000`（M），dest=`010`（写 D），jump=`010`（JEQ）；汇编为 `D=M; JEQ`。
> - **解析**：ALU 的 y 取 M（`addressM=A` 读内存），`x=D`；结果写入 D；若结果等于 0（`zr=1`），PC 载入 A（跳转），否则 PC+1。
> - **易错原因**：dest 三位顺序是 A-D-M（`010` = 只写 D）；jump `010` = JEQ 而非 JLT。
#### 5. 为什么"跳到 `@label` 地址"必须借助 A 寄存器与 PC 的时序配合，而不是直接把跳转目标算进指令？
> [!question]- 答案解析
> - **答案**：C 指令只有 16 位，前缀 111 加 comp/dest/jump 后已无空间容纳 15 位跳转地址；因此用两条指令协作：A 指令先把目标地址装入 A 寄存器（`@label`），下一条 C 指令在**周期末**用 `jump` 位与 `zr/ng` 判定，命中则 PC ← A（A 是上周期已就绪的稳定值），实现"间接跳转"。
> - **解析**：这种"先装地址、再条件跳转"的两步法是以 16 位定长指令换取简单译码的必然设计；PC 在周期末更新，保证执行与取指不冲突。
> - **易错原因**：忘记跳转目标经 A 寄存器中转，或忽略 PC 更新发生在周期末（时序上 A 必须先于跳转指令一个周期就绪）。
