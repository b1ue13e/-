# 计算机系统层次结构 (System Abstraction Layers)

## 1. 为什么学：理解"一行代码如何变成电信号"

计算机系统由多层抽象堆叠而成。学习者的常见误区是从某一层（比如编程语言）出发，无法解释"变量名在内存里是什么""`printf` 为什么能触发内核"等问题。这张卡建立**从物理层到应用层**的统一层次框架，之后所有阶段（CPU 架构、内存管理、性能优化）都在这个框架里定位。

## 2. 七层抽象模型

| 层次 | 抽象对象 | 典型载体 | 相邻接口 |
|:---|:---|:---|:---|
| **应用层** | 业务逻辑 | 程序/库（libc、Java 运行时） | 系统调用接口 |
| **操作系统层** | 资源管理 | 内核（进程、虚拟内存、文件） | 指令集 ABI / 特权级切换 |
| **ISA 层** | 指令语义 | 汇编指令、寄存器、内存寻址 | 机器码 |
| **微架构层** | 指令执行方式 | 流水线、数据通路、分支预测 | 控制信号 |
| **数字逻辑层** | 电路行为 | 逻辑门、触发器、加法器 | 布尔函数 |
| **器件/物理层** | 电气行为 | 晶体管、时钟、电压 | 逻辑电平 |

> 每层只通过**严格定义的接口**与相邻层交互，这就是"抽象"——上层不关心下层实现细节，下层不关心上层语义。

## 3. 关键推导：一条 C 语句的跨层旅程

以 `int x = a + b;` 为例：

1. **应用层**：`x = a + b` 是高级语言语义；
2. **编译层**：编译器生成汇编 `ADD R1, R2, R3`（ISA 层）；
3. **微架构层**：取指单元把指令从内存取出，译码器产生控制信号，ALU 完成加法（数据通路）；
4. **数字逻辑层**：ALU 内部由全加器级联构成，每个全加器由与或非门实现；
5. **物理层**：门的输出由晶体管导通/截止决定，最终表现为寄存器中电位的翻转。

## 4. 常见误区（反例）

- **误区 1**："程序直接访问硬件"——实际上所有 I/O 都要经过系统调用/设备驱动，用户态无特权指令访问。
- **误区 2**："内存地址就是物理地址"——现代系统用户看到的是虚拟地址，由 MMU 翻译（衔接 [[🧭 阶段2-内存管理]] 的地址转换）。
- **误区 3**："层次越多越慢"——抽象层增加的是开发成本而非运行时必开销；经过优化后（如系统调用批量、JIT）开销可被压缩。
