# 存储层次与性能指标 (Memory Hierarchy & Performance Metrics)

## 1. 为什么学：性能是计组的"统一度量衡"

计算机系统的所有设计决策——指令集、缓存、流水线、并行——最终都用**时间**来验收。这张卡回答两个总图景问题：① 存储系统为什么长成"金字塔"；② 用什么指标客观衡量"快慢"。

## 2. 存储层次金字塔（Memory Hierarchy）

### 2.1 层次与典型参数

| 层次 | 典型容量 | 典型延迟 | 管理主体 | 技术 |
|:---|:---|:---|:---|:---|
| 寄存器 | 32-64 个 | < 1 ns | 编译器 | SRAM 阵列 |
| L1 缓存 | 32-64 KB | 1-4 ns | 硬件 | SRAM |
| L2 缓存 | 256 KB - 1 MB | 4-10 ns | 硬件 | SRAM |
| L3 缓存 | 几 MB - 几十 MB | 10-40 ns | 硬件 | SRAM |
| 主内存 | 几 GB - 几百 GB | 80-100 ns | 操作系统+硬件 | DRAM |
| 本地磁盘 | 几 TB | 5-10 ms | 操作系统 | SSD/HDD |
| 网络存储 | 无限 | 10-100 ms | 分布式系统 | 网络 |

### 2.2 为什么成立：局部性（Locality）

存储层次能工作的前提是**程序访问具有局部性**：

- **时间局部性**：刚访问过的数据很可能再次被访问（循环体）；
- **空间局部性**：访问某地址后，邻近地址很可能被访问（数组顺序遍历）。

> 直觉例子：`sum = 0; for (i=0; i<N; i++) sum += a[i];` —— `a[i]` 的连续访问利用了空间局部性（缓存行预取），`sum` 的反复累加利用时间局部性。

### 2.3 平均访问时间（AMAT）

设命中率 $h$、命中时间 $t_{hit}$、缺失惩罚 $t_{miss}$，则：

$$\text{AMAT} = t_{hit} + (1-h) \times t_{miss}$$

**推导**：每次访问要么命中（$t_{hit}$），要么缺失（额外承担 $t_{miss}$），缺失概率为 $(1-h)$。

## 3. 性能指标

### 3.1 CPU 时间与时钟周期

$$\text{CPU 时间} = \text{指令数} \times \text{CPI} \times \text{时钟周期}$$

- 指令数（Instruction Count）：程序指令总量；
- **CPI**（Cycles Per Instruction）：每条指令平均时钟周期数；
- 时钟周期（Clock Cycle Time）：$1/f$，$f$ 为时钟频率。

### 3.2 加速比与 Amdahl 定律

$$\text{Speedup} = \frac{T_{old}}{T_{new}} = \frac{1}{(1-p) + p/k}$$

$p$ 为可并行比例，$k$ 为加速倍数；串行部分 $1-p$ 是加速上限的瓶颈。详见 [[计算机组成原理-Amdahl定律]]。

### 3.3 吞吐量与响应时间

- **响应时间（延迟）**：单个任务从开始到完成的时间；
- **吞吐量（带宽）**：单位时间完成的任务数。两者可独立优化（如流水线牺牲单条延迟换取吞吐）。

## 4. 常见误区（反例）

- **误区 1**："缓存容量越大越好"——容量增大会增加命中时间（查找延迟），且受 SRAM 面积/功耗约束；层次设计是容量×速度的折中。
- **误区 2**："CPI 越低越好"——CPI 与指令数、频率相互制约（RISC 高 CPI 低指令数 vs CISC 反之），只看单一指标会误判。
- **误区 3**："频率越高性能越好"——同频不同 IPC（每周期指令数）差异巨大；现代瓶颈多在内存墙（Memory Wall）。
