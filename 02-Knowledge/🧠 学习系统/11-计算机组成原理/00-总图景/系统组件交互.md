# 系统组件交互 (CPU-Memory-I/O Interaction)

## 1. 为什么学：计算机不是"CPU 一个零件"

总图景阶段最常见的认知缺失是把计算机当成"CPU 处理器"。实际上性能瓶颈往往在 CPU 与内存、CPU 与 I/O 的**交互路径**上（冯·诺依曼瓶颈）。这张卡建立三大交互通路：CPU↔内存、CPU↔I/O、内存↔I/O。

## 2. 三大交互通路

### 2.1 CPU ↔ 内存：取指与数据通路

- CPU 通过**地址总线**发出地址、**数据总线**传输指令/数据、**控制总线**携带读写信号；
- 单条指令周期：取指（IF）→ 译码（ID）→ 执行（EX）→ 访存（MEM）→ 写回（WB），其中 IF 与 MEM 都要访问内存；
- **冯·诺依曼瓶颈**：指令和数据共用一条总线/存储器，带宽受限（哈佛结构分离指令/数据缓存缓解此问题）。

### 2.2 CPU ↔ I/O：四种交互方式

| 方式 | 机制 | 优点 | 缺点 | 适用 |
|:---|:---|:---|:---|:---|
| **程序控制 I/O（轮询）** | CPU 循环查询设备状态 | 实现简单、延迟确定 | 浪费 CPU | 低速/简单设备 |
| **中断驱动 I/O** | 设备完成时发中断 | CPU 不空转 | 中断开销 | 中低速突发设备 |
| **DMA** | 专用控制器直接搬运内存↔设备 | 不占 CPU | 需要 DMA 控制器、一致性处理 | 高速块传输 |
| **通道 I/O** | 专用 I/O 处理器执行 I/O 程序 | 大规模并行 | 复杂昂贵 | 大型机 |

### 2.3 内存 ↔ I/O：DMA 与一致性

- DMA（Direct Memory Access）让外设控制器直接读写内存，绕过 CPU，搬运完成后再中断通知 CPU；
- 需要处理**缓存一致性**：DMA 写入的内存若在 CPU 缓存中有副本，会造成数据不一致（衔接 [[高级缓存]]）。

## 3. 多核协作与一致性

多核系统中，各核心共享内存但各有缓存，需要缓存一致性协议（如 MESI）保证"每个核心读到最新值"。共享内存带宽成为多核扩展瓶颈（衔接 [[系统组件交互]] 与阶段 4 相关内容）。

## 4. 常见误区（反例）

- **误区 1**："I/O 越快越好，所以全用 DMA"——DMA 有建立/清理开销，小传输用轮询/中断反而更优；
- **误区 2**："CPU 和内存速度差距小"——现代差距达两个数量级（1ns vs 100ns），因此缓存层次才必不可少；
- **误区 3**："多核一定能加速"——共享内存带宽与一致性协议可能使收益递减（Amdahl 定律 + 内存墙）。
