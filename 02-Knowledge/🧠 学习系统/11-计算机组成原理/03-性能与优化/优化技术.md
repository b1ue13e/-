# 优化技术 (Loop Unrolling, Tiling, Prefetch & SIMD)

## 1. 为什么学：常数倍收益从哪来

`优化层次.md` 给了框架，这张卡给**具体招式**：循环展开（减少控制开销）、分块（缓存友好）、预取（隐藏延迟）、零拷贝（减少数据复制）、SIMD（并行计算）。这些技术是 CSAPP Performance Lab 和实际性能优化的主力手段（SIMD 专卡见 [[SIMD编程]]）。

## 2. 核心技术

### 2.1 循环展开（Loop Unrolling）

- **做法**：一次迭代处理多个元素，减少循环控制（比较/跳转）占比，暴露更多指令级并行；
- 示例（展开 4 次）：
  ```c
  for (i = 0; i < n; i += 4) {
      s += a[i] + a[i+1] + a[i+2] + a[i+3];
  }
  ```
- **注意**：展开太多会增大寄存器压力（寄存器溢出 → 性能反而下降）；编译器 -O2 会自动做部分展开。

### 2.2 循环分块 / 缓存分块（Tiling）

- **问题**：大矩阵遍历时工作集超过 L1/L2，反复驱逐（容量缺失）；
- **做法**：把计算切成适配缓存大小的块，块内局部性最大化（衔接 [[优化综合案例]] 案例一）；
- 块大小 = 缓存容量/（每元素字节×涉及数组数）的经验公式。

### 2.3 预取（Prefetching）

- 软件预取：`__builtin_prefetch` 或 `prefetcht0` 指令提前把数据取入缓存；
- 硬件预取：现代 CPU 自动检测顺序/跨步访问模式；
- 适用：延迟敏感的顺序访问（见 [[存储层次详解]]）。

### 2.4 零拷贝（Zero-Copy）

- **问题**：数据在内核/用户态/设备间多次拷贝（read→copy→write）浪费带宽与 CPU；
- **做法**：`sendfile()`/`mmap`/`splice` 让内核直接搬运，避免用户态中间副本；
- 适用：大文件传输、网络代理（衔接 [[优化综合案例]] 案例三）。

### 2.5 其他

| 技术 | 机制 | 收益来源 |
|:---|:---|:---|
| **锁消除/无锁** | 减少同步开销 | 并发场景（本课程已移出 OS 细节，仅作衔接） |
| **SIMD 向量化** | 单指令多数据 | 计算密集（见 [[SIMD编程]]） |
| **数据对齐** | 缓存行/页对齐避免伪共享 | 多核场景 |

## 3. 常见误区（反例）

- **误区 1**："展开越多越好"——寄存器压力与指令缓存占用会反噬（x86 只有 16 个通用寄存器）；
- **误区 2**："分块数越大越好"——块大小要匹配缓存容量，过大等于没分块；
- **误区 3**："预取指令放了就有效"——预取过早（数据被驱逐）/过晚（来不及）都无效，需按延迟调距离。
