# 代码旅程 (Source → Compile → Link → Load → Execute)

## 1. 为什么学：程序从 .c 到运行的完整链条

阶段 3 的起点是"把前面所有知识串起来"。这张卡把 `源程序 → 可执行文件 → 运行` 的完整旅程走一遍：预处理 → 编译 → 汇编 → 链接 → 加载 → 执行。理解这条链是性能分析（瓶颈在哪一层）、调试（问题出在哪一层）和优化（改哪一层有效）的前提。

## 2. 五阶段旅程

| 阶段 | 输入 → 输出 | 工具 | 关键动作 |
|:---|:---|:---|:---|
| **预处理** | `a.c` → `a.i` | cpp | 展开宏、包含头文件 |
| **编译** | `a.i` → `a.s` | cc1 | 高级语言 → 汇编（优化在这里） |
| **汇编** | `a.s` → `a.o` | as | 汇编 → 机器码（含重定位信息） |
| **链接** | `a.o` + 库 → `a.out` | ld | 符号解析、重定位、合并段 |
| **加载/执行** | `a.out` → 进程 | loader | 装入内存、跳转入口、调用 main |

## 3. 关键机制

### 3.1 符号解析与重定位（链接核心）

- **符号表**：每个 `.o` 记录它定义/引用的符号（函数名、全局变量）；
- **符号解析**：链接器把每个引用与一个定义关联（多定义冲突→强符号规则）；
- **重定位**：链接后把引用处地址改为最终虚拟地址。

### 3.2 静态链接 vs 动态链接

| 维度 | 静态链接 | 动态链接 |
|:---|:---|:---|
| 库合并时机 | 链接时复制进可执行文件 | 运行时加载 .so/.dll |
| 文件大小 | 大（每个程序含库） | 小（共享） |
| 启动速度 | 快 | 慢（动态链接器解析） |
| 更新库 | 需重新链接 | 替换库即可（ABI 兼容时） |

### 3.3 加载与进程视角

- 可执行文件按段装入虚拟内存（.text/.data/.bss/.heap/.stack）；
- `.bss` 不占磁盘空间（未初始化数据，加载时清零）；
- 入口 `_start` → 运行时初始化 → `main` → `exit` 返回内核。

## 4. 常见误区（反例）

- **误区 1**："编译和汇编是一回事"——编译是高级→汇编（含优化），汇编是汇编→机器码（机械翻译）；
- **误区 2**："链接错误就是代码写错了"——`undefined reference` 常是漏链接库/函数签名不匹配；
- **误区 3**："加载就是拷贝文件"——现代 OS 用**按需分页（Demand Paging）**惰性加载：只有访问到的页才从磁盘读入（衔接 [[页面管理]]）。

## 5. 与性能分析的联系

- 性能瓶颈定位需要知道"慢在哪一层"：编译器优化（O2/O3）、算法层、内存布局、系统调用——分别对应本阶段 [[编译优化]]、[[Roofline模型]]、[[性能分析方法与工具]]。
