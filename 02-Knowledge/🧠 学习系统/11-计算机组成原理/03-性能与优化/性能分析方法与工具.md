# 性能分析方法与工具 (USE Method, Flame Graphs & Toolchain)

## 1. 为什么学：性能问题怎么"科学地"找

`优化层次.md` 讲了五层优化框架。这张卡给出一套**可操作的分析方法**：① USE 方法（利用率/饱和/错误）；② 火焰图（可视化瓶颈）；③ 工具链选型（perf/strace/gprof/valgrind 各管什么）。分析工具不是越多越好，而是**按问题类型选对工具**。

## 2. 分析方法论

### 2.1 USE 方法（Brendan Gregg）

对每个资源依次问三件事：

1. **U（Utilization）利用率**：资源忙碌时间占比（如 CPU 70% → 有余量；100% → 饱和）；
2. **S（Saturation）饱和度**：是否有排队等待（如 run queue 长度、内存换页量）；
3. **E（Errors）错误**：是否有错误（如重传、超时、ECC 纠错）。

> 适用：定位"瓶颈资源"——先找哪个资源饱和，再深入该资源的细节。

### 2.2 差异分析（Diff Analysis）

- 同一程序在优化前后/不同环境各测一次，用 **perf diff** 对比热点差异；
- 配合二分：逐步隔离变量（参数/环境/负载）定位引入变化的因素。

### 2.3 火焰图（Flame Graph）

- **横轴**：采样时间比例（越宽越热点）；**纵轴**：调用栈深度；
- 顶层是采样时正在执行的函数；宽顶 = CPU 密集，深栈 = 调用开销；
- 由 perf record + `flamegraph.pl` 生成。

## 3. 工具链选型

| 工具 | 用途 | 何时用 |
|:---|:---|:---|
| **perf** | PMU 硬件计数器、采样、火焰图数据 | CPU 瓶颈、IPC/缓存 miss 分析（见 [[perf工具]]） |
| **strace** | 系统调用跟踪 | 频繁系统调用、I/O 瓶颈 |
| **gprof** | 函数级剖析（编译插桩） | 用户态函数热点（较粗） |
| **valgrind/callgrind** | 内存调试 + 缓存剖析 | 内存泄漏、缓存行为模拟 |
| **bpftrace** | 内核/用户态动态追踪 | 定制化、生产环境低开销 |
| **cachegrind** | 缓存/分支预测模拟 | 无硬件计数器时估算 |

## 4. 常见误区（反例）

- **误区 1**："先上工具再想问题"——先明确瓶颈类型（CPU/内存/IO/锁），再选工具；用错工具浪费时间；
- **误区 2**："采样数据就是全部事实"——perf 采样有误差（周期性采样漏掉短函数）；结合计数器与复测；
- **误区 3**："火焰图顶宽=要优化这里"——顶宽可能是被内联/被调用方拖累，要看完整调用链。
