# 优化综合案例 (From Problem Definition to Verified Speedup)

## 1. 为什么学：把方法用在一件真事上

前面所有卡都是"知识"，这张卡示范**完整优化流程**：问题定义 → 现状测量 → 瓶颈分析 → 优化实施 → 效果验证。三个案例覆盖三类典型瓶颈：计算密集（矩阵乘法）、访存密集（数据库查询）、系统密集（Web 服务器）。

## 2. 案例一：矩阵乘法（计算密集）

### 2.1 问题与基线

- 任务：C = A×B（1024×1024）；朴素三重循环作为基线；
- 测量：`perf stat` 记录 IPC、L1/L2/L3 miss、浮点吞吐。

### 2.2 瓶颈分析

- 内层循环 `C[i][j] += A[i][k] * B[k][j]`：B 按列访问 → **空间局部性差**，L1 miss 高；
- 缓存 miss → 内存墙，IPC 远低于理论峰值。

### 2.3 优化实施

1. **循环分块（Tiling）**：按缓存行分块（如 32×32），块内访问命中缓存；预期 2-5x；
2. **循环交换**：把 B 的列访问改为行访问（转置 B 或重排循环）；预期 2x；
3. **SIMD 向量化**：一次算 4 个浮点（AVX）→ 预期再 2-4x；
4. 组合后对照 Roofline 模型验证是否接近硬件上限（衔接 [[Roofline模型]]）。

### 2.4 验证

- 同一机器、同一编译器、同一输入下对比；用 `perf stat` 证明 IPC 与 miss 率改善。

## 3. 案例二：数据库查询（访存/缓存密集）

- 瓶颈：全表扫描命中率低、行布局不连续；
- 优化：列式存储（只读需要的列）、分区/索引、预取；
- 指标：查询延迟与吞吐，验证缓存命中率提升与内存带宽利用。

## 4. 案例三：Web 服务器（系统密集）

- 瓶颈：进程/线程开销、系统调用频繁、上下文切换；
- 优化：epoll 事件驱动（替代多线程）、零拷贝 sendfile、连接池；
- 指标：吞吐（QPS）、延迟 P99、CPU 利用率。

## 5. 通用优化流程（五步）

1. **问题定义**：明确指标（延迟/吞吐/QPS）、约束（硬件/时间）与成功标准；
2. **现状测量**：先测基线，量化瓶颈（USE 方法定位资源）；
3. **瓶颈分析**：perf/火焰图定位热点函数与 miss 源；
4. **优化实施**：按 [[优化层次]] 从性价比最高的层开始，一次只改一个变量；
5. **效果验证**：同一基线对比、A/B 复测、确认无回归（正确性/稳定性）。

## 6. 常见误区（反例）

- **误区 1**："没有基线就优化"——无基线无法判断收益与回归；
- **误区 2**："一次改多个变量"——无法归因哪个优化起效；
- **误区 3**："只看均值"——延迟分布看 P99/P999（长尾请求拖垮体验）。

## 7. 自测与通过标准

- [ ] 我能为给定场景走完五步优化流程；
- [ ] 我能用 perf stat + 火焰图定位一个热点并解释根因；
- [ ] 我能设计 A/B 验证方案并写出基线对比表。
