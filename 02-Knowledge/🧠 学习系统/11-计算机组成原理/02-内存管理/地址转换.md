# 地址转换 (Virtual→Physical Translation)

## 1. 为什么学：虚拟地址如何变成物理地址

`虚拟内存.md` 讲了虚拟内存的三大功能（隔离/大地址空间/共享）与四级页表翻译，`分页机制.md` 讲了分页的基本原理。这张卡聚焦**翻译路径的硬件实现**：页表结构、MMU 的角色、TLB 加速、多级页表为何省内存。

## 2. 翻译的基本流程

```
虚拟地址 VA ──┬── 页号 VPN ──→ 页表(Page Table) ──→ 物理页号 PPN ──┐
              └── 偏移量 VPO ──────────────────────────────────→ 物理地址 PA
```

- 页大小固定（如 4KB），低 12 位为页内偏移（不翻译）；
- 页表以 VPN 为索引，每个表项（PTE）存 PPN + 权限位（有效位 V、读写位 RW、用户位 U、脏位 D）。

## 3. MMU 的角色

**MMU（Memory Management Unit）** 是 CPU 内的翻译硬件：

1. 接收虚拟地址；
2. 查页表（TLB 命中则一步完成）；
3. 检查权限（缺页→异常，越权→保护异常）；
4. 输出物理地址给缓存/内存。

## 4. TLB：翻译的缓存

- **TLB（Translation Lookaside Buffer）**：页表项的高速缓存，按 VPN 索引；
- 命中率通常 >99%；缺失时查内存页表（页表遍历 Page Walk）；
- **TLB 命中时间** ~1 周期，缺失需要访问多级页表（多级页表遍历可能需 4 次内存访问）；
- TLB 也分多级（L1 TLB / L2 TLB），与数据缓存独立。

## 5. 多级页表为什么省内存

若 48-bit 虚拟地址、4KB 页、单级页表需要 $2^{36}$ 个表项（每项 8B = 512GB！）——不可行。四级页表（4-Level）：

- 只分配**实际使用的页目录/页表层级**；
- 未分配的高层目录项为 null，不占内存；
- 典型进程页表总占用仅几 MB。

**四级翻译**：VPN 拆成 4 段（VPN1-4），逐级查页目录基址寄存器（CR3/x86 或 satp/RISC-V）→ L4 → L3 → L2 → L1 → PPN。

## 6. 常见误区（反例）

- **误区 1**："每个进程都要完整的四级页表"——多级页表按需分配，只建用到的层级；
- **误区 2**："TLB 缺失就访问内存一次"——单级页表才如此；四级页表 TLB 缺失需要 4 次页表访问（硬件遍历或软件遍历）；
- **误区 3**："页表只存地址"——PTE 还携带权限/脏位/引用位，缺页异常与写回决策都依赖这些位。
