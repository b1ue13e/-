# 缓存设计 (Cache Mapping, Write Policy & Replacement)

## 1. 为什么学：缓存是"内存墙"的唯一解药

CPU 与内存的延迟差距达两个数量级（1ns vs 100ns）。缓存（Cache）用局部性原理在 CPU 与内存之间插入高速小容量存储。`缓存-映射方式.md` 已讲组相联映射的地址位切分，这张卡把缓存设计的**三大决策**补全：① 映射方式（直接/组相联/全相联）；② 写策略（写直达/写回）；③ 替换策略（LRU 等）。

## 2. 映射方式（Mapping）

### 2.1 三种映射

| 方式 | 块可放置位置 | 优点 | 缺点 |
|:---|:---|:---|:---|
| **直接映射** | 唯一位置（组=索引位） | 硬件简单、命中快 | 冲突缺失高 |
| **组相联** | 组内 n 路任一位置 | 折中（现代标准） | 需要比较器 |
| **全相联** | 任意位置 | 冲突缺失最低 | 硬件最贵（TLB 用） |

### 2.2 地址位切分（组相联）

物理地址分为三段：**标记（Tag）｜索引（Index）｜块内偏移（Offset）**

- 索引位数 = $\log_2(\text{组数})$；偏移位数 = $\log_2(\text{块大小})$；
- 容量公式：$\text{容量} = \text{组数} \times \text{路数} \times \text{块大小}$；
- **冲突缺失**：多个地址映射到同一组导致互相驱逐（直接映射最严重）。

## 3. 写策略（Write Policy）

| 策略 | 行为 | 优点 | 缺点 |
|:---|:---|:---|:---|
| **写直达（Write-Through）** | 同时写缓存和内存 | 简单、一致性易保证 | 每次写都访存，带宽浪费 |
| **写回（Write-Back）** | 只写缓存，替换时才写回内存 | 减少访存、性能好 | 需脏位（Dirty Bit），一致性复杂 |

- **写分配（Write-Allocate）**：写缺失时先加载块到缓存再写；配合写回；
- **写不分配（No-Write-Allocate）**：写缺失时直接写内存不加载块；配合写直达。

## 4. 替换策略（Replacement）

| 策略 | 行为 | 优缺点 |
|:---|:---|:---|
| **LRU（最近最少使用）** | 替换最久未使用的块 | 局部性好，硬件贵（n 路需 n! 状态） |
| **随机** | 随机驱逐 | 硬件极简，平均性能接近 LRU |
| **FIFO** | 先进先出 | 实现简单但可能驱逐热点 |

> 现代 CPU 常用 **近似 LRU**（如 pseudo-LRU 树）平衡硬件成本与命中率。

## 5. 常见误区（反例）

- **误区 1**："缓存越大越好"——容量增大→命中时间变长→可能拖慢整体（L1 保持小是因为要快）；
- **误区 2**："写直达更安全所以更好"——写回配合写分配在现代 CPU 是主流，性能优势明显；
- **误区 3**："LRU 一定最优"——循环遍历大于缓存容量的数组时 LRU 会反复驱逐即将用到的块（抖动），此时随机策略可能更好。
