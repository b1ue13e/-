# 缓存-映射方式

> 所属路径：[[🗺️ 计算机组成原理学习路径|计算机组成原理学习路径]]
> 所属阶段：[[🧭 阶段2-内存管理]]

## 为什么学（问题动机）

内存太慢，寄存器太少。缓存的思路是：**把主存的一部分数据"放"到一个更小更快的地方**。但缓存容量远小于主存，那么问题来了——一个主存地址到底应该放进缓存的哪个位置？这个"放哪里"的规则就是**映射方式（mapping）**。三种方式（直接映射、全相联、组相联）在硬件成本、查找速度和冲突概率之间做出不同权衡；不搞懂它，缓存命中率分析、替换策略、甚至 [[计算机组成原理-阶段作业-02-缓存模拟器]] 的 set index 切分都无从谈起。

## 正式定义

**缓存映射（Cache Mapping）**：决定主存块（Block/Line）在缓存中存放位置的规则。三种方式：

| 方式 | 主存块可存放的位置 | 硬件复杂度 | 冲突概率 | 典型用途 |
|:---|:---|:---:|:---:|:---|
| 直接映射 | 唯一固定位置：`set = index mod 组数` | 低 | 高 | 简单 CPU |
| 全相联 | 任意位置 | 高（需全比较） | 低 | TLB |
| 组相联 | 固定组内任意路：`set = index mod 组数` | 中 | 中 | 主流 L1/L2/L3 |

### 地址位切分（组相联）

一个 32-bit 内存地址在缓存查找时被切为三段：

```text
|  tag（标记） |  set index（组索引） |  block offset（块内偏移） |
|← t 位 →|← s 位 →|← b 位 →|
```

- **b**：块内偏移位数，`块大小 = 2^b` 字节
- **s**：组索引位数，`组数 = 2^s`
- **t**：标记位，`t = 地址位数 - s - b`

**关键公式**：`set index = (address >> b) mod 2^s`，即取地址中间 s 位。

### 组相联的容量关系

`缓存容量 = 组数 × 每组路数 × 块大小`

## 一个最小例子（手算）

设缓存：块大小 16 字节（b=4）、8 组（s=3）、2 路组相联（E=2）。访问地址 `0x0400d7d4`：

1. 取低 4 位（b=4）：`0x...d4` 的低 4 位是 `0100` → block offset = 4
2. 取中间 3 位（s=3）：`0x...d7` → 二进制 `1101 0111`，中间 3 位（bit 4-6）为 `011` → set index = 3
3. 剩余高位为 tag：`0x0400d` → tag = `0x0400d`

```text
地址 0x0400d7d4 = tag(0x0400d) | set(011=3) | offset(0100=4)
```

查找时：CPU 只检查**第 3 组**里的 2 个 line，比较它们的 tag 是否等于 `0x0400d`。命中 → 取块内偏移 4 处的字节；未命中 → 按替换策略（如 LRU）在组内选择一路写入。

## 常见误区

1. **误区：set index 是"组号"，所以组数 = set index 值。** 错。`s` 是索引的**位数**，组数 = `2^s`。地址 `0x...d7` 的中间 3 位 `011` 是组号 3，说明有 8 组。
2. **误区：直接映射 = 只映射一次就固定。** 直接映射的"固定"指**位置**固定（set 由 index 决定），但不同主存块（不同 tag）会争抢同一 set，冲突时互相驱逐。
3. **误区：组相联的"路数 E"越多一定越好。** 路数多 → 冲突 miss 减少，但比较器更多、命中时间变长（硬件更贵、速度更慢）。现代 CPU 通常 L1 用 8 路、L2/L3 用 12-16 路，是延迟与失效率的折中。

## 自测（先作答，再对照答案）

1. **基础**：缓存 32KB、块大小 64 字节、4 路组相联。计算组数 s 与组索引位数。
2. **中等**：地址 `0x12345678`，缓存 b=6、s=5。写出 set index 与 tag。
3. **较难**：为什么 TLB（页表缓存）用全相联而数据缓存用组相联？两种选择分别牺牲了什么？

<details>
<summary>参考答案</summary>

1. 块数 = 32KB/64B = 512 块；组数 = 512/4 = 128 = 2^7 → s=7，组索引 7 位。
2. `0x12345678` 低 6 位 offset = `011000`(0x38 的低 6 位)；bit 6-10 为 set index（取 `0x12345678 >> 6` 后低 5 位）；tag 为剩余高位（`0x12345678 >> 11`）。
3. TLB 条目少（几十到几百条）且 miss 代价极高（页表访问），全相联换来最低冲突率；数据缓存条目多，全相联比较器成本不可接受，组相联在成本与失效率间折中。

</details>
