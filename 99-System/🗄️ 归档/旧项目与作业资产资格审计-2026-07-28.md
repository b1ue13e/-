# 旧项目与作业资产资格审计

> 本页解决“现有项目笔记看起来像完整答案或示例代码，却被误当成可执行作业”的问题。审计只改变**资格判定**，不删除旧笔记，也不覆盖其中可能有价值的手写内容。

## 1. 资格闸门

项目或作业只有同时记录以下字段，才有资格进入 Active Sprint、作业清单和正式评分：

```yaml
source_url:
source_course:
source_version:
license:
adaptation: original | adapted
dataset_version:
starter_code:
tests:
baseline:
solution_visibility: private | summary-only
```

此外还必须满足：

- Starter 与参考实现分离，待实现接口清楚；
- 测试或验收脚本可运行；
- 数据、模型与环境版本可冻结；
- Baseline 使用同一数据切分和评估口径；
- 官方课程内容遵守 Honor Code；
- 没有明确许可证时只保留链接，不复制题目包或答案。

缺少任一资格字段的旧资产一律标记为**隔离（reference-only）**，并在其 Frontmatter 写入：

```yaml
asset_eligibility: reference-only
eligibility_audited: 2026-07-28
eligibility_reason: "缺少正式作业资格字段；仅作参考"
```

隔离不是删除：它仍可用于阅读、找灵感或提炼知识卡，但不能证明课程已经完成。

## 4. 隔离资产如何恢复资格

每次只恢复一个资产：

1. 先确定它是原创、改编还是官方题目入口；
2. 补齐来源、版本、许可证和 Honor Code 边界；
3. 从完整实现中分离 Starter，隐藏或私有保存解答；
4. 补单元测试、验收脚本、固定数据和 Simple Baseline；
5. 写清楚计算预算、失败条件和 Rubric；
6. 运行后记录真实结果，不预填“已达标”；
7. 通过当前课程激活闸门后，才进入 Sprint。
