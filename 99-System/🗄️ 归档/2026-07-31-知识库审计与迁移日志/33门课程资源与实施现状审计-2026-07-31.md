# 33门课程资源与实施现状审计-2026-07-31

> 本页回答两个问题：`高质量来源到底有哪些`，以及 `当前学习系统真实完成到哪一步了`。这页优先反映现实状态，不拿模板数量冒充可执行度。

## 已找到的高质量来源

### 编程 / 实验型课程

- `机器学习`：李宏毅 `ML 2021` 官方作业体系，覆盖 `HW01-HW15`，是当前最适合当样板课的来源。
- `机器学习补充`：Microsoft `ML for Beginners`，含 12 周、26 节课、测验和项目。
- `计算机视觉`：Stanford `CS231n Assignments`。
- `NLP`：Stanford `CS224N` + `Hugging Face Course`。
- `数据结构与算法`：MIT `6.006` + `OpenDSA`。
- `计算机组成原理`：`Nand2Tetris` 官方 `Projects 1-12`。
- `强化学习`：Berkeley `CS188 Projects` + `OpenAI Spinning Up`。
- `量化金融`：Microsoft `Qlib`。
- `最优化`：`CVXPY`。
- `控制与机器人`：`PythonRobotics`。
- `贝叶斯统计`：`PyMC Examples`。
- `运筹学`：`Google OR-Tools`。
- `信息检索`：`Pyserini`。
- `数值分析`：MIT `18.335`。

### 证明 / 数学型课程

- `数学分析 / 测度论 / 实变函数 / 泛函分析` 这类课程也能找到开放教材与 OCW。
- 但这类课程**不应该硬套机器学习式的指标冲榜模板**。
- 正确方式应是：`定义复述 -> 证明重建 -> 反例 -> 条件变式 -> 闭卷验收`。

## 当前学习系统的真实情况

### 方向是对的，但还没有真正可执行

1. 活跃目录中只有原规划 33 门里的 `25 门`。
2. 缺少：`23、27、29、31、32、34、35、37`。
3. 只有 `10 门` 存在 `📚 教材挂载索引.md`。
4. `03-Projects/课程作业`、正式作业索引、实际作业项目目录目前不存在。
5. `17-机器学习` 虽然已有 `15 份作业说明`，但引用的 `starter code / 数据集 / 测试文件` 还没有落地到真实目录。
6. 两个作业审计结果目前都是 `0 门通过`。
7. `.recovery-hold` 中保存着一套 `33 门、33 个资源页、33 个课程作业目录和 405 个作业单元` 的旧设计。
8. 但其中不少是重复模板，不能直接视为完成品。

### 这意味着什么

- 当前最强的是 `设计层`，不是 `执行层`。
- 当前最需要补的是：真实目录、starter、data card、tests、baseline、report、rubric。
- 现在不能把“有很多页面”误判成“已经能开始交作业”。

## 建议实施方式

### 第一阶段：先把 17-机器学习 做成真正可运行的样板课

1. 以李宏毅官方 `HW01-HW15` 为题目主线。
2. 每份作业设置 `Simple / Medium / Strong / Boss`。
3. 但所有指标必须从真实数据跑出来，不能预先编造。
4. 每份作业必须交付：
   - `README`
   - `starter`
   - `data card`
   - `tests`
   - `baseline`
   - `report`
   - `rubric`
5. 第三方解答仓库只作完成后的对照，不能作为题目源。

### 第二阶段：复制到最适合扩展的课程

- `05-计算机视觉`
- `08-NLP全栈`
- `10-数据结构与算法`
- `11-计算机组成原理`
- `13-强化学习`

### 第三阶段：为证明型课程建立另一套模板

- 不再沿用同一套 PyTorch / baseline / 冲榜思路。
- 改为：
  - 定义复述
  - 证明重建
  - 反例构造
  - 条件变式
  - 闭卷验收

## 当前结论

- `17-机器学习` 是最合适的样板课。
- 现在最重要的不是继续批量铺页面，而是让 `17-机器学习` 从“设计完成”升级到“真实可运行”。
- 只有样板课跑通后，剩余课程的模板复制才有意义。
