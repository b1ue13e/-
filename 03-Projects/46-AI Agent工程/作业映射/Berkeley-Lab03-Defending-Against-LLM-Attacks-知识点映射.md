## 3. 完成本作业的最小知识点集

- [ ] 能把允许与禁止行为写成无冲突、可测试的规则。
- [ ] 能将不可信输入放入明确数据边界，不让其改变系统目标。
- [ ] 能对 Lab02 的攻击按类别回归，而不是针对字面字符串。
- [ ] 能同时测攻击成功率 ASR 和正常误拒率 FRR。
- [ ] 能解释课程的 1/3 门槛为何不是生产安全证明。

## 4. 全面掌握扩展知识

- [ ] 纵深防御：prompt、parser、policy、tool ACL、sandbox、human approval、monitoring。
- [ ] 间接注入、RAG 中毒、记忆污染与跨 Agent 消息污染。
- [ ] 输出内容安全与工具行为安全分开判定。
- [ ] 防御版本化、离线评测集、上线 canary 与事故回滚。
- [ ] 分层失败归因：prompt 漏洞、策略漏洞、工具权限、解析器或数据治理。

## 5. 官方验收与自建验收分离

### 官方验收

- [ ] 从官方 Drive 下载当前 Lab03 包并核验说明。
- [ ] 在规定接口内实现自己的 defense prompts。
- [ ] 至少通过 1/3 隐藏攻击测试并按官方表单提交。

### 本库自建验收（非 Berkeley 原题）

- [ ] Lab02 每个攻击机制至少 2 个变体，不共享固定触发词。
- [ ] 至少 20 个正常任务测 TSR/FRR，不能用“全拒绝”过关。
- [ ] 加入含引用、角色扮演、长文本、编码文本的良性边界样例。
- [ ] 加入恶意检索文档，验证其无法提升权限。
- [ ] 写操作默认关闭，开启后需要确定性策略和人工批准。
- [ ] 每次防御修改都跑全量回归并记录差异。
- [ ] `local-acceptance` 安全测试全绿，且新增的正常样例不被全拒绝。

本地基线运行：

```powershell
cd "F:\-\03-Projects\46-AI Agent工程\local-acceptance"
python -m unittest -v
```

`security_harness.py` 的策略只信任结构化通道元数据；高风险动作一律暂停审批，外部文档不能授予非只读能力。`evaluate_metrics` 中 ASR 仅在攻击导致 `allow_action` 时计成功，读取恶意文本本身不算攻击成功；TSR/FRR 同时防止“全拒绝”伪安全。

> [!important] 历史 Gate 与当前学习 Gate 分离
> “隐藏攻击至少 1/3”只描述 Fall 2024 官方门槛，不是生产安全标准，也不是本地课程可复刻的判题器。当前 Gate 同时要求 ASR、TSR/FRR、工具权限、人工审批和全量回归证据。

## 7. 防御审查清单

- [ ] **指令与数据**：外部内容无法改写系统规则。
- [ ] **工具**：模型输出不能绕过 ACL 与 schema。
- [ ] **状态**：恶意内容不会永久写入共享记忆。
- [ ] **消息**：Agent handoff 带来源与信任级别。
- [ ] **输出**：敏感字段去除，错误不泄露内部细节。
- [ ] **终止**：攻击诱导的循环受步数、时间与费用限制。
- [ ] **可用性**：正常复杂任务不被粗暴关键词规则误拒。

## 8. 复盘问题

1. 防御阻止的是模型生成，还是阻止了真实危险动作？
2. 哪些控制只存在于 prompt，哪些落在可信执行层？
3. 防御是否对自己的攻击过拟合？对未见机制如何验证？
4. 防御增加多少延迟、成本和误拒？是否有业务可接受阈值？
