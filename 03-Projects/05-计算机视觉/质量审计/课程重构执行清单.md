## 执行规则（本课程沿用）

1. 知识卡正文逐卡编写：读取 → 判断 → 编写 → 核验 → 检查关系 → 标记 validated；同一时刻仅一张卡 in_progress。
2. 禁止脚本批量生成知识卡正文；脚本只用于扫描、统计、检查、机械移动与引用修复。
3. 每个批次：dry-run（移动/合并/清退）→ 修改 → 最小检查 → 标记 validated → 检查点提交 → 记录 checkpoint_commit → committed。
4. 恢复：先读本清单与 git 状态；`committed` 只做一致性复核；不一致时停止并标记 needs_review。
5. 治理边界：非阻断历史欠债只写入 `质量审计/课程严苛审计.md`；`.归档/` 空壳卡与 CS231n 参考源保持归档不动；G9/G10 为全库工具问题只记录。
