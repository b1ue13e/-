## 2. 环境与最小依赖

- **环境**：纯 Python + `numpy`（或连 numpy 都不用，用 `random`）。无需 gym、无需 GPU。
- **MAB 骨架（可直接用）**：

```python
import numpy as np

class Bandit:
    """多臂老虎机：每臂奖励 = 真实均值 + 高斯噪声。"""
    def __init__(self, means): self.means = np.array(means)
    def pull(self, a): return self.means[a] + np.random.normal(0, 0.1)

def eps_greedy(Q, eps):
    """ε-greedy 选臂。"""
    return np.random.randint(len(Q)) if np.random.rand() < eps else int(np.argmax(Q))

means = [1.0, 0.0, 0.5]          # 3 臂真实均值（题目可改）
bandit = Bandit(means)
Q = np.zeros(3); N = np.zeros(3); eps = 0.1
for t in range(500):
    a = eps_greedy(Q, eps)
    r = bandit.pull(a)
    N[a] += 1; Q[a] += (r - Q[a]) / N[a]   # 增量更新均值估计
print("估计 Q =", np.round(Q, 3), " 真实 =", means)
# 后续：把 ε-greedy 换成 UCB（维护 N、Q，UCB = Q + c·sqrt(ln t / N)），对比累积 regret。
```

- **运行方式**：`python rl_hw01_mab.py`（脚本自写），或 Jupyter 逐格运行。

## 6. 基础要求、必要提示与常见错误

- **必要提示**：ε-greedy 的「探索」也可能抽到最优臂，所以「探索率 ε」≠「选到次优臂的概率」；UCB 的 `ln t` 随步数缓慢增长，自信区间随时间收窄。
- **常见错误**：① 以为 ε-greedy 每步有 ε 概率选**次优**臂（实际是从全部 K 臂均匀随机）；② UCB 误用 `√t` 而非 `√(ln t)`，导致探索过量；③ regret 算成「奖励本身」而非「与最优臂的差距累计」；④ `N=0` 时 `ln t/N` 除零，需用乐观初始化或 `N+1`。
- **调试**：先固定随机种子看 Q2 数值能否复现，再放大 T 看曲线。

## 🃏 知识内化卡片

- Q：ε-greedy 每步选到最优臂的概率？
- A：`1 − ε + ε/K`（以 `1−ε` 贪心选最优，以 `ε` 从 K 臂均匀随机，其中 1/K 概率又选中最优）。
- Q：UCB 为什么用 `√(ln t / N_i)` 而非 `√t`？
- A：`ln t` 增长极慢，使探索随步数自然衰减；用 `√t` 会过度探索永不收敛。`N_i` 在分母：被拉少的臂置信区间更宽，优先被探索。
- Q：regret 的定义？
- A：`regret(t) = Σ_{τ=1}^{t} (μ* − μ_{a_τ})`，即每步相对最优臂的期望损失累计；次线性增长（如 `O(log t)`）表示算法渐近最优。
