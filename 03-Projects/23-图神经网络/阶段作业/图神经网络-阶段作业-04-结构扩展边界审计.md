# 图神经网络-阶段作业-04-结构扩展边界审计

## 学习目标

面对异质图、图 Transformer 或大规模系统需求，能用任务、结构、复杂度和证据选择最小模型，而不是默认换“更前沿”架构。

## 任务边界

本作业是结构与系统边界审计，不要求搭建分布式集群或真实线上 A/B。所有线上、GPU、OGB 或生产结论若没有实际运行证据，必须标记 `[未验证]`，只讨论所需证据和风险。

## 任务

1. 给一个用户—商品—交易图写 relation-specific message、时间可见边界和按关系指标。
2. 在 `n=10^3/10^5`、给定 `|E|` 下比较局部 GAT、dense attention、sparse attention 的主项复杂度和内存风险。
3. 设计 Laplacian PE 与 shortest-path bias 的对照，说明符号/重根和未来边泄漏。
4. 写一份训练/服务边界图：特征新鲜度、fanout、P95/P99、缓存、漂移和回滚。
5. 给出一个“复杂模型不该使用”的 kill 决策，并列出需要新证据才能 pivot 的条件。

## 提交产物

- `report.md`（不超过 6 页）和一个可运行复杂度/内存估算脚本；
- `assumptions.json`、资源表、失败模式、未验证项；
- 不提交官方 Homework 2/3 的答案复写。

先运行课程 worked example，检查复杂度主项与零边界输入，再创建自己的报告和 `submission/s04/`：

```powershell
python starter/run_assignment.py s04 --output artifacts/s04-worked-example
```

它会写入 `estimates.csv` 与 `assumptions.json`；输出是理论估算，不是实测延迟或线上收益。

报告还必须包含一张“缺口→候选架构→新增假设→验证成本→kill 条件”表，以及一段说明 toy 实验为何不足以支持生产结论。估算脚本至少对两组 `n,d,|E|` 输出 dense/sparse 主项，并测试输入为零或稀疏图时的边界。

## 常见失败

- 把异质关系类型压成一个整数权重；
- 比较 dense/sparse 时使用不同隐藏维度或节点数；
- 把理论复杂度直接写成实测延迟；
- 没有真实线上实验，却写“业务指标提升”。

## Rubric（100 分）

- 关系与时间边界 25；结构编码与复杂度 25；系统/线上边界 25；kill/pivot 论证 15；来源与复现 10。
- 通过线 80；把离线 toy 分数写成线上收益或遗漏未来边边界为硬失败。
