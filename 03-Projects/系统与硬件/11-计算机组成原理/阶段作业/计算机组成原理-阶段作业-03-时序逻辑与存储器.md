# 计算机组成原理-阶段作业-03-时序逻辑与存储器

> 非官方中文版：题目结构保留 Nand2Tetris Project 3 官方任务编号（P3a-P3f），语义本地化。

## 1. 作业身份

- 课程：计算机组成原理（阶段1：CPU架构）
- 规模：`stage`（阶段作业）｜形态：`lab`（HDL 时序电路实现）
- 来源：Nand2Tetris Project 3（Sequential Logic / Memory），`adapted_from`
- 官方页：[nand2tetris.org/project03](https://www.nand2tetris.org/project03)
- 前置知识：[[01-CPU架构/时序逻辑与寄存器]]（DFF/时钟/状态保持）、[[00-总图景/数字逻辑设计]]（组合 vs 时序）、[[00-总图景/存储层次与性能指标]]（容量与访问代价）

## 2. 学习目标

完成后你应该能够：

1. 说清"组合逻辑无状态、时序逻辑有状态"的分界，以及时钟周期在其中扮演的角色；
2. 从唯一原语 DFF 出发，用 HDL 逐级构建 Bit → Register → RAM8 → RAM64 → … → RAM16K；
3. 解释存储器"地址译码 + 数据选择"的递归结构（为什么 RAM64 = 8 × RAM8 + DMux8Way/Mux8Way16）；
4. 实现带 `reset/load/inc` 优先级的程序计数器 PC，并说明它为何是取指循环的心脏；
5. 用时序图（时钟周期 t 与 t+1）解释"本周期读到的是上周期写入的值"。

- 禁止事项：不得复制官方参考实现或他人提交。

## 4. 详细题目

### P3a 1-bit 寄存器 Bit

用一个 DFF + 一个 Mux 实现 `Bit.hdl`：`if load(t) then out(t+1)=in(t) else out(t+1)=out(t)`。
**要求**：在 `设计.md` 中画出该芯片的反馈回路，并说明为何反馈不会造成组合环。

### P3b 16-bit 寄存器 Register

用 16 个 Bit 并联实现 `Register.hdl`，共享同一 `load` 信号。

### P3c RAM8

用 8 个 Register + `DMux8Way`（写路径地址译码）+ `Mux8Way16`（读路径数据选择）实现 `RAM8.hdl`，地址宽 3 位。
**要求**：说明"写只写一个字、读随时可读"这一非对称性从何而来。

### P3d 存储器递归扩展 RAM64 / RAM512 / RAM4K / RAM16K

逐级实现：

| 芯片 | 组成 | 地址宽 | 地址切分 |
|:---|:---|:---:|:---|
| `RAM64.hdl` | 8 × RAM8 | 6 | 高 3 位选片 / 低 3 位选字 |
| `RAM512.hdl` | 8 × RAM64 | 9 | 高 3 位选片 / 低 6 位下传 |
| `RAM4K.hdl` | 8 × RAM512 | 12 | 高 3 位选片 / 低 9 位下传 |
| `RAM16K.hdl` | 4 × RAM4K | 14 | 高 2 位选片 / 低 12 位下传 |

**要求**：在 `设计.md` 中写出 RAM4K 里地址 `0b1010_1010_1010` 落在"哪一片 RAM512 的哪一个字"，给出推导。

### P3e 程序计数器 PC

实现 `PC.hdl`，行为优先级为 `reset > load > inc > 保持`：

```
if reset(t)      then out(t+1) = 0
else if load(t)  then out(t+1) = in(t)
else if inc(t)   then out(t+1) = out(t) + 1
else                  out(t+1) = out(t)
```

**要求**：用 Register + Inc16 + 三级 Mux16 实现，并说明为什么优先级不能写反。

### P3f 时序分析（进阶，可选）

在 HardwareSimulator 中用单步时钟（`tick/tock`）观察 `Register` 的写入延迟：给出一张"输入信号 / load / 输出"三行的时序表（至少 4 个时钟周期），标出"读到旧值"的那一拍。完成本题可衔接 [[01-CPU架构/数据通路与指令周期]]。

## 8. 引导与自检（不泄露答案）

- 检查点 1：`Bit` 的输出接回自己的输入，为什么不是组合环？——因为路径上有 DFF，跨越了时钟边界。
- 检查点 2：`RAM64` 的 `address[3..5]` 和 `address[0..2]` 谁负责选片？——想清楚"选片"发生在层级的哪一侧再动手，写反会导致官方测试在第 9 个字才开始失败。
- 检查点 3：PC 在 `reset=1, load=1` 同时为真时输出什么？——按优先级定义自行推。
- 常见失败：写路径忘记用 DMux 而是把 `load` 直接接到所有子芯片（导致全片被写）；读路径 Mux 的 sel 位宽和地址位宽不匹配；PC 用 Inc16 的输出直接反馈而漏掉 Register。
- 提交前清单：□ 8 份 `.hdl` 各自单独通过官方测试；□ 未使用内建时序芯片；□ `设计.md` 含地址切分推导；□ 报告含时序 bug 记录。
