# 计算机组成原理-阶段作业-02-缓存模拟器

> 非官方中文版：任务结构保留 CSAPP Cache Lab Part A 语义，不复制官方答案与隐藏测试。

## 1. 作业身份

- 课程：计算机组成原理（阶段2：内存管理）
- 规模：`stage`（阶段作业）｜形态：`lab`（实验）
- 来源：CSAPP Cache Lab Part A（`adapted_from`），官方 Lab 页 [csapp.cs.cmu.edu](http://csapp.cs.cmu.edu/3e/labs.html)
- 前置知识：[[02-内存管理/缓存设计]]（直接映射/组相联/全相联、LRU、写策略）、[[02-内存管理/缓存性能]]（AMAT、4C 缺失）、[[02-内存管理/虚拟内存]]（地址位切分）

## 2. 学习目标

1. 用地址位切分（tag / set / block offset）解释缓存查找过程；
2. 从零实现一个可配置（s, E, b）的缓存模拟器；
3. 在给定内存跟踪文件上输出 hit / miss / eviction 统计；
4. 用 LRU 策略解释为何"冷 miss 与容量 miss"不可消除。

## 3. 任务背景与边界

- 输入：`valgrind` 生成的 `trace` 文件（格式：`I 0400d7d4,8` / `M 0421c7f0,4` / `L 04f6b868,8` / `S 7ff0005c8,8`）。
- 输出：`./csim -s <S> -E <E> -b <B> -t <tracefile>` 打印 `hits:? misses:? evictions:?`。
- 限制：本题只做 **数据缓存**（忽略 `I` 行）；`M` 视为一次 load + 一次 store；禁止修改 trace 文件。
- 禁止事项：不得查看/复制官方 `csim-ref` 实现或他人提交。

## 4. 详细题目

### 里程碑 1：地址位切分（30 分钟）

给定 `s=4, E=1, b=4`，手算 `0x0400d7d4` 的 tag/set/block offset，写在 `设计.md` 中。

### 里程碑 2：直接映射模拟器

实现 `csim.c`，先只支持 `E=1`（直接映射），跑通官方 `yi.trace`（`-s 4 -E 1 -b 4`）得到 `hits:4 misses:5 evictions:5`。

### 里程碑 3：组相联 + LRU

扩展支持任意 `E`，用"时间戳计数"实现 LRU 替换；通过官方 `-v` 详细输出逐行核对命中/缺失判定。

### 里程碑 4（进阶，可选）

为 `M` 操作打印"一次命中"而不是"一次命中+一次命中"合并显示；或实现 write-allocate / write-back 语义的命中计数差异分析。

## 5. 环境与复现

- 语言：C（C99），仅标准库；无 valgrind 依赖（trace 由教师/自备）。
- 目录：`03-Projects/系统与硬件/11-计算机组成原理/阶段作业/HW02/` 下 `src/`（csim.c）、`traces/`（yi.trace 等）、`设计.md`、`报告.md`。
- 运行：
  ```bash
  gcc -Wall -o csim src/csim.c
  ./csim -s 4 -E 1 -b 4 -t traces/yi.trace
  ```
- 期望输出（官方基准）：`hits:4 misses:5 evictions:5`（直接映射）；组相联时以官方 `csim-ref` 结果为准（本作业提供参考值 `[待验证]` 若无法获取官方工具）。

## 8. 引导与自检（不泄露答案）

- 检查点 1：`yi.trace` 第 1 行 `I` 是否被忽略？——是，本题只模拟数据缓存。
- 检查点 2：`M` 操作是否计为 2 次访问？——是（load + store），但同一次 `M` 内的两次访问若都命中，统计为 2 hits。
- 常见失败：`set index` 位数算错（`s` 是 index 位数不是 set 数）；LRU 用数组遍历但忘记更新最近使用时间；block offset 位数截断错误导致同 tag 多行误判。
- 提交前清单：□ 无 `I` 行污染；□ `M` 计 2 次；□ LRU 边界（全 miss 组）不崩溃；□ 报告含参数扫描表。
