## 2. 学习目标

完成后你应该能够：

1. 完整写出 `call / function / return` 三条命令的**调用约定**（谁保存什么、谁恢复什么）；
2. 画出一个调用帧（frame）的内存布局：返回地址、saved LCL/ARG/THIS/THAT、局部变量区、工作栈；
3. 解释"为什么 `return` 必须先把返回值写到 `*ARG`，再把 SP 设为 `ARG+1`"这一顺序不可交换；
4. 处理多文件工程：生成 bootstrap 代码（`SP=256; call Sys.init 0`）并保证 static 与标签不冲突；
5. 用 VM Emulator 追踪一次递归调用（如 Fibonacci）的帧栈生长与回收。

## 4. 详细题目

### P8a 调用约定手推（先做，禁止边写边猜）

在 `设计.md` 中填完这张帧布局表（地址自 `ARG` 起标注相对偏移）：

| 相对位置 | 内容 | 谁写入 | 谁读取/恢复 |
|:---|:---|:---|:---|
| `ARG+0 … ARG+n-1` | 实参 n 个 | ? | ? |
| `ARG+n+0` | 返回地址 | ? | ? |
| `ARG+n+1` | saved LCL | ? | ? |
| `ARG+n+2` | saved ARG | ? | ? |
| `ARG+n+3` | saved THIS | ? | ? |
| `ARG+n+4` | saved THAT | ? | ? |
| `LCL+0 …` | 局部变量（初值 0） | ? | ? |

并回答：`call f n` 中的 `n` 与 `function f k` 中的 `k` 分别是什么？为什么 `ARG = SP - n - 5`？

### P8b 程序流命令

实现 `label X` / `goto X` / `if-goto X`。

- 标签必须带函数作用域前缀（形如 `FuncName$X`），保证不同函数内同名标签不冲突；
- `if-goto` 弹栈取值，非零跳转。

通过官方测试：`BasicLoop`、`FibonacciSeries`。

### P8c 函数调用命令

实现 `function f k` / `call f n` / `return`：

- `function f k`：生成入口标签 `(f)`，压入 k 个 0 作为局部变量；
- `call f n`：压返回地址标签（唯一，如 `f$ret.3`）、压 LCL/ARG/THIS/THAT、重设 `ARG=SP-n-5`、`LCL=SP`、`goto f`、落返回标签；
- `return`：用临时变量 `FRAME=LCL`、`RET=*(FRAME-5)`，`*ARG=pop()`、`SP=ARG+1`，依次恢复 THAT/THIS/ARG/LCL，最后 `goto RET`。

通过官方测试：`SimpleFunction`、`NestedCall`。

### P8d 多文件与 bootstrap

实现目录输入模式：

1. 扫描目录下全部 `.vm` 文件；
2. 在输出汇编开头生成 bootstrap：`SP=256` 后 `call Sys.init 0`；
3. `static` 变量按各自源文件名生成 `@File.i` 符号。

通过官方测试：`FibonacciElement`（多文件）、`StaticsTest`（多文件 static 隔离）。

### P8e 递归追踪（本作业新增题）

运行 `FibonacciElement`（n=4），在 `报告.md` 中记录：

- 帧栈最深时有几层？此时 SP 大约是多少？
- 选一层帧，写出该层 `LCL/ARG/THIS/THAT` 的实际取值与它保存的上一层值；
- 画一张帧栈生长-回收的示意图（可手绘拍照）。

### P8f 尾调用观察（进阶，可选）

对比"递归 Fibonacci"与"循环 Fibonacci"两个 VM 程序在同一 n 下的执行指令数与最大 SP，说明帧开销的量级；结合 [[02-内存管理/存储层次详解]] 讨论栈深度与内存局部性的关系。

## 8. 引导与自检（不泄露答案）

- 检查点 1：`return` 时若无参数（n=0），`*ARG` 写返回值会覆盖什么？——想清楚"返回地址被返回值覆盖"的场景，这正是必须先取 `RET` 再写 `*ARG` 的原因。
- 检查点 2：恢复 THAT/THIS/ARG/LCL 的顺序能不能反过来？——先恢复 LCL 会毁掉后续偏移的基准。
- 检查点 3：`call` 的返回标签为什么必须唯一？——同一函数被调用多次时，标签重名会让汇编器分配错地址。
- 检查点 4：bootstrap 是否只能出现一次？——多文件模式下若每个文件都生成一次会怎样？
- 常见失败：`FRAME` 与 `RET` 用了同一个 R13 导致互相覆盖；`function f k` 忘记把 k 个局部变量清零；目录模式下把 bootstrap 写在了 `Sys.vm` 之后；标签前缀用了文件名而非函数名（导致同文件不同函数标签冲突）。
- 提交前清单：□ 六组官方测试全过；□ bootstrap 只生成一次；□ 返回标签全局唯一；□ 帧布局表填满；□ 报告含帧栈图。
