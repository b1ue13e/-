## 2. 学习目标

完成后你应该能够：

1. 逐位解释 Hack 的两类指令：A 指令 `0vvvvvvvvvvvvvvv` 与 C 指令 `111accccccdddjjj`；
2. 用 `dest=comp;jump` 三段式写出条件分支与循环，不依赖任何高级语言结构；
3. 使用内存映射 I/O（`SCREEN` 起于 16384，`KBD` 位于 24576）直接驱动屏幕与键盘；
4. 说明"寄存器 A 的双重身份"——既是数据寄存器，又是地址寄存器与跳转目标；
5. 在 CPU Emulator 中用断点与单步定位一个汇编逻辑错误。

## 4. 详细题目

### P4a 指令解码手算（热身，30 分钟）

给出下列机器码，逐位还原成汇编助记符，写在 `设计.md`：

| 机器码 | 类型 | 你的还原 |
|:---|:---:|:---|
| `0000000000010001` | A | ? |
| `1110101010001000` | C | ? |
| `1111110000010000` | C | ? |
| `1110001100000111` | C | ? |

**要求**：对后三行标出 `a / comp(6) / dest(3) / jump(3)` 各字段的切分位置。

### P4b 乘法 Mult

用 Hack 汇编实现 `R2 = R0 * R1`（R0、R1 为非负整数，结果允许 16-bit 溢出回绕）。

- 必须用循环累加实现（Hack ALU 无乘法指令）；
- 必须处理 `R0=0` 或 `R1=0` 的边界；
- 每个代码段前加注释说明其作用（初始化 / 循环条件 / 累加 / 结束死循环）。

### P4c I/O 交互 Fill

实现：键盘有键按下时屏幕全黑（全 1），松开时屏幕全白（全 0），程序无限循环响应。

- 屏幕内存映射从 `SCREEN`（16384）开始，共 8192 个字（256×512 像素 / 16）；
- 键盘状态字在 `KBD`（24576），无按键时为 0；
- **要求**：在 `报告.md` 画出状态转移图（至少 2 个状态 + 触发条件），并说明为什么必须"整屏重刷"而不能只改一个字。

### P4d 分支与比较（本作业新增题）

实现 `R2 = max(R0, R1)`，且当两者相等时 `R2 = R0`、同时把 `R3` 置 1 作为"相等标志"。

- 要求只用一次减法与一条条件跳转完成主判断；
- 在 `设计.md` 中说明：为什么用 `D=M-D;JGT` 判断大小在 16-bit 补码下可能出错（提示：想想溢出），以及你的输入范围假设是什么。

### P4e 数组遍历（进阶，可选）

实现"对 RAM[100..100+n-1] 的 n 个数求和，结果写入 R1"，n 存于 R0。

- 必须用 A 寄存器做指针自增遍历（体会"A 既是地址又是数据"）；
- 完成本题可衔接 [[阶段作业/计算机组成原理-阶段作业-06-汇编器]] 的变量地址分配部分。

## 8. 引导与自检（不泄露答案）

- 检查点 1：`@SCREEN` 之后 `M=-1` 会把屏幕的哪一部分变黑？——只有左上角 16 个像素；想清楚这一点再决定循环边界。
- 检查点 2：程序最后一行如果不写死循环会发生什么？——PC 继续自增，执行未定义内存区，Emulator 行为不可预测。
- 检查点 3：`D;JEQ` 与 `0;JMP` 的区别是什么？前者跳转依赖 comp 结果，后者无条件。
- 常见失败：Fill 只刷了一次屏幕就退出（缺外层无限循环）；Mult 把被乘数和计数器搞混导致死循环；用 `@i` 这类变量前忘了它会从地址 16 开始分配，与手工使用的 RAM 地址冲突；`M=M+1` 之前忘记先设 A。
- 提交前清单：□ Mult 官方比较通过；□ Fill 按键/松开双向验证；□ Max 三种关系各测一次；□ 每段汇编有注释；□ 报告含状态转移图。
