# 计算机组成原理-阶段作业-10-编译器前端

> 非官方中文版：题目结构保留 Nand2Tetris Project 10 官方任务编号（P10a-P10e），语义本地化。

- 课程：计算机组成原理（阶段2 挂载：应用链）

## 2. 学习目标

完成后你应该能够：

1. 实现一个 Jack 词法分析器（Tokenizer），把字符流切成 5 类 token：`keyword` / `symbol` / `identifier` / `integerConstant` / `stringConstant`；
2. 用递归下降（recursive descent）方法实现语法分析器，把 token 流构造成语法树；
3. 说清 Jack 语法中哪些地方需要**前瞻一个 token**（LL(1) 决策点），例如区分 `varName`、`varName[...]`、`subroutineCall`；
4. 输出与官方 `.xml` 逐行一致的语法分析结果（本作业的验收就是 XML 比较）；
5. 解释"为什么前端不需要知道任何目标机器细节"——这正是 HW11 才引入符号表与代码生成的原因。

## 3. 任务背景与边界

- 语言：不限（Python / Java 推荐），仅用标准库。
- 输入输出：`X.jack` → `X.xml`（或目录模式：每个 `.jack` 生成同名 `.xml`）。
- 验收工具：官方 `TextComparer`（忽略空白差异），比较对象为官方提供的 `.xml` 期望输出。
- 范围边界：本作业**不做**符号表、不做类型检查、不生成 VM 代码——这些属于 [[阶段作业/计算机组成原理-阶段作业-11-编译器后端]]。
- 禁止事项：不得复制官方 JackAnalyzer 实现或他人提交。

## 4. 详细题目

### P10a 词法规格与前瞻点分析（先做）

在 `设计.md` 中完成两件事：

1. 列出 Jack 的全部 21 个关键字与 19 个符号（自行从教材/官方规格整理，不抄题面）；
2. 填完这张**前瞻决策表**：

| 语法位置 | 看到的当前 token | 需要看下一个 token 吗 | 三种可能的产生式 |
|:---|:---|:---:|:---|
| `term` 中的标识符 | `identifier` | 是 | `varName` / `varName[expr]` / `subroutineCall` |
| `subroutineCall` | `identifier` | 是 | `f(...)` / `Class.f(...)` / `obj.f(...)` |
| `statement` 起始 | `keyword` | 否 | ? |

### P10b JackTokenizer（词法分析）

实现 Tokenizer，要求：

- 剥离三类注释：`// 行注释`、`/* 块注释 */`、`/** API 注释 */`；
- 正确处理字符串常量（`"..."` 内的空格与符号不得被切分；输出 XML 时**不含引号**）；
- XML 转义：`<` → `&lt;`、`>` → `&gt;`、`&` → `&amp;`、`"` → `&quot;`；
- 输出 `XxxT.xml`（token 流），与官方 `ArrayTestT.xml`、`SquareT.xml`、`ExpressionLessSquareT.xml` 比较通过。

### P10c CompilationEngine（语法分析）

用递归下降实现全部产生式，至少包含：

| 层级 | 产生式 |
|:---|:---|
| 程序结构 | `class` / `classVarDec` / `subroutineDec` / `parameterList` / `subroutineBody` / `varDec` |
| 语句 | `statements` / `letStatement` / `ifStatement` / `whileStatement` / `doStatement` / `returnStatement` |
| 表达式 | `expression` / `term` / `expressionList` |

输出带层级缩进的 `X.xml`，与官方 `ExpressionLessSquare/`、`Square/`、`ArrayTest/` 三组期望输出比较通过。

### P10d 语法错误报告（本作业新增题）

你的分析器遇到下列输入必须**报错并给出行号与期望符号**，而不是崩溃或静默产出残缺 XML：

| 非法输入 | 期望行为 |
|:---|:---|
| `let x = 1` （缺分号） | 报错：第 N 行期望 `;` |
| `if (x > 1 { ... }` （缺右括号） | 报错：第 N 行期望 `)` |
| `class { ... }` （缺类名） | 报错：第 N 行期望 identifier |
| 未闭合的 `/* 注释` | 报错：块注释未终止 |

自建 `tests/bad/` 放 4 个样例，报错输出贴进 `报告.md`。

### P10e 语法树可视化（进阶，可选）

给分析器加 `--tree` 选项，把 XML 转成缩进文本树或 Mermaid 图，选一个含嵌套 `if/while` 的方法画出其语法树。完成后可作为 HW11 遍历顺序的参考图。

## 8. 引导与自检（不泄露答案）

- 检查点 1：`"a < b"` 这个字符串常量里的 `<` 需要 XML 转义吗？——需要；但引号本身不进 XML 内容。
- 检查点 2：`ExpressionLessSquare` 与 `Square` 的差别在哪？——前者刻意去掉了复杂表达式，用来隔离 bug；先过前者再过后者。
- 检查点 3：`term` 看到一个 identifier 时，为什么必须前瞻？——`x`、`x[1]`、`x.f()` 三者的开头完全一样。
- 检查点 4：一元运算符 `-` 与二元 `-` 如何区分？——看它出现在 `term` 的什么位置。
- 常见失败：块注释 `/* ... */` 跨行处理不当，吞掉后续代码；字符串常量中的 `//` 被当成注释剥离；XML 缩进层级与官方不一致（`TextComparer` 忽略空白，但结构标签顺序不能错）；`expressionList` 为空时仍输出了子节点；`return;` 与 `return expr;` 未区分。
- 提交前清单：□ 三组 token 流 + 三组语法树全部比较通过；□ 4 类错误带行号；□ 前瞻决策表完成；□ 递归下降调用图与代码一致。
