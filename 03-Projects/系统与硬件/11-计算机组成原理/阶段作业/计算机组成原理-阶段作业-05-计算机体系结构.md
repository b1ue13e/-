# 计算机组成原理-阶段作业-05-计算机体系结构

> 非官方中文版：题目结构保留 Nand2Tetris Project 5 官方任务编号（P5a-P5e），语义本地化。

## 1. 作业身份

- 课程：计算机组成原理（阶段1：CPU架构）
- 规模：`stage`（阶段作业）｜形态：`lab`（整机 HDL 构建）
- 来源：Nand2Tetris Project 5（Computer Architecture），`adapted_from`
- 官方页：[nand2tetris.org/project05](https://www.nand2tetris.org/project05)
- 前置知识：[[01-CPU架构/数据通路与指令周期]]（取指-译码-执行）、[[01-CPU架构/CPU与取指执行循环]]、[[01-CPU架构/时序逻辑与寄存器]]（PC/寄存器）、[[01-CPU架构/ALU算术逻辑单元]]、[[00-总图景/系统组件交互]]（CPU/内存/IO 的连接）

## 2. 学习目标

完成后你应该能够：

1. 把"指令的每一位"映射到"数据通路上的每一根控制线"，画出完整控制信号表；
2. 用已有芯片（ALU / Register / PC / RAM / DMux / Mux16）组装出可运行的 16-bit CPU；
3. 解释指令存储器（ROM）与数据存储器（RAM）分离的哈佛结构，以及它带来的取指/访存并行；
4. 用地址译码把 RAM16K、Screen、Keyboard 统一到一张 15 位地址空间图上；
5. 让 HW04 写的 `Mult.asm` / `Fill.asm` 在**你自己造的 CPU** 上跑起来。

## 3. 任务背景与边界

- 环境：Nand2Tetris 官方 `HardwareSimulator`。
- 芯片来源：必须复用你在 HW01（P1-2）与 [[阶段作业/计算机组成原理-阶段作业-03-时序逻辑与存储器]]（P3）实现的芯片；内建 `Screen`/`Keyboard`/`ROM32K` 可直接使用（官方规定）。
- 与既有作业的关系：[[大作业/计算机组成原理-大作业-从逻辑门到缓存感知的CPU]] 的 **Part A** 也覆盖 P5，但那里以"综合报告 + 缓存分析"为主。本作业是 P5 的**独立细化训练**：控制信号表、地址空间图、单步时序追踪都在这里做；完成本作业后，大作业 Part A 可直接复用产物，只需补 Part B/C。
- 禁止事项：不得复制官方 `CPU.hdl` 参考实现或他人提交。

## 4. 详细题目

### P5a 控制信号表（必须先做，不许边写边猜）

在 `设计.md` 中填完这张表——**未完成本题不要开始写 CPU.hdl**：

| 指令位 | 名称 | 控制的部件 | 该位为 1 时的效果 |
|:---|:---|:---|:---|
| `instruction[15]` | 指令类型 | A 寄存器输入 Mux | ? |
| `instruction[12]` | `a` 位 | ALU 的 y 输入 Mux | ? |
| `instruction[11..6]` | comp | ALU 控制 | ? |
| `instruction[5]` | dest→A | A 寄存器 load | ? |
| `instruction[4]` | dest→D | D 寄存器 load | ? |
| `instruction[3]` | dest→M | writeM 输出 | ? |
| `instruction[2..0]` | jump | PC load | ? |

并额外写出 **jump 判定逻辑**：给定 ALU 的 `zr`/`ng` 两个标志位与 3 位 jump 字段，`PC.load` 的布尔表达式是什么？

### P5b Memory.hdl（地址空间统一）

实现 `Memory.hdl`，把 15 位地址 `address[0..14]` 映射为：

| 地址范围（十进制） | 设备 | 说明 |
|:---|:---|:---|
| 0 – 16383 | RAM16K | 通用数据内存 |
| 16384 – 24575 | Screen | 8192 字，内存映射显存 |
| 24576 | Keyboard | 只读，1 字 |

**要求**：在 `设计.md` 中说明你用 `address[14]` 与 `address[13]` 做了怎样的两级判别，以及"写 Keyboard 地址"时你的实现如何表现（应为无效写，不得破坏 RAM）。

### P5c CPU.hdl（核心）

实现 `CPU.hdl`，接口为：

```
IN  inM[16], instruction[16], reset
OUT outM[16], writeM, addressM[15], pc[15]
```

必须包含并正确连线：A 寄存器、D 寄存器、ALU、PC、以及 A/M 选择 Mux16。
**要求**：`reset=1` 时下一周期 `pc=0`（重启）。

### P5d Computer.hdl 与整机验证

实现 `Computer.hdl`（ROM32K + CPU + Memory 三者连线），并依次通过官方测试：

1. `CPU.tst` / `CPU-external.tst`
2. `ComputerAdd.tst`（加法冒烟）
3. `ComputerMax.tst`（含条件跳转）
4. `ComputerRect.tst`（含屏幕写入）

### P5e 自造程序上机（本作业新增题）

把 [[阶段作业/计算机组成原理-阶段作业-04-机器语言]] 的 `Mult.asm` 与 `Fill.asm` 汇编成 `.hack`（可用官方 Assembler），载入**你自己的 `Computer.hdl`** 运行：

- `Mult`：设置 R0=6, R1=7，运行至稳定，检查 R2=42；
- `Fill`：在 HardwareSimulator 中改变 Keyboard 输入，观察 Screen 内存变化；
- 在 `报告.md` 记录：一次完整指令的**单步时序追踪**（选 `Mult.asm` 中任意一条 C 指令，写出该周期内 PC / A / D / ALU 输出 / writeM 的取值变化）。

## 8. 引导与自检（不泄露答案）

- 检查点 1：A 指令进入时，A 寄存器的 load 信号应该由谁决定？——不是 `instruction[5]`，想清楚为什么。
- 检查点 2：`writeM` 是组合输出还是时序输出？——它必须在本周期内有效，否则写入会延迟一拍。
- 检查点 3：`addressM` 为什么是 15 位而 A 寄存器是 16 位？——取 `A[0..14]`，最高位在数据用途下才有意义。
- 检查点 4：`ng` 标志能直接用 ALU 输出的最高位吗？——可以，但要确认你的 ALU 是否已导出该位。
- 常见失败：PC 的 `inc` 常置 1 但被 load 覆盖顺序写反；A/M 选择 Mux 的 sel 用了 `instruction[15]` 而非 `instruction[12]`；`writeM` 忘记与"是否 C 指令"做与运算，导致 A 指令也写内存；Memory 中 Screen 的地址偏移未减去 16384。
- 提交前清单：□ 四组官方测试全过；□ 控制信号表先于代码完成；□ 自造 `Mult.hack` 在自造 CPU 上得 42；□ 报告含单周期追踪表。
