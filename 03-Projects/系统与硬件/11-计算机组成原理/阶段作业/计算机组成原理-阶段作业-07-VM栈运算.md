# 计算机组成原理-阶段作业-07-VM栈运算

> 非官方中文版：题目结构保留 Nand2Tetris Project 7 官方任务编号（P7a-P7e），语义本地化。

## 1. 作业身份

- 课程：计算机组成原理（阶段2 挂载：工具链上升段）
- 规模：`stage`（阶段作业）｜形态：`lab`（VM 翻译器实现）
- 来源：Nand2Tetris Project 7（VM I: Stack Arithmetic），`adapted_from`
- 官方页：[nand2tetris.org/project07](https://www.nand2tetris.org/project07)
- 前置知识：[[01-CPU架构/VM栈机与函数调用]]（栈模型与内存段）、[[01-CPU架构/汇编器与符号表]]（生成唯一标签）、[[01-CPU架构/ISA-指令系统详解]]

## 2. 学习目标

完成后你应该能够：

1. 描述栈机（stack machine）的计算范式：所有运算取自栈顶、结果压回栈顶；
2. 把 8 条算术/逻辑 VM 命令翻译成 Hack 汇编，并解释比较运算为何必须生成**唯一标签**；
3. 说清 Hack VM 的 8 个内存段（`local/argument/this/that/constant/static/pointer/temp`）各自的基址来源与寻址方式；
4. 解释 `pointer 0/1` 与 `THIS/THAT` 的关系，以及 `static` 为何用文件名做符号前缀；
5. 用 VM Emulator 逐步验证栈指针 SP 的升降，定位一次"栈失衡"错误。

## 3. 任务背景与边界

- 语言：不限（Python / Java 推荐），仅用标准库。
- 输入输出：`Prog.vm` → `Prog.asm`；产物必须能被 [[阶段作业/计算机组成原理-阶段作业-06-汇编器]] 的汇编器（或官方 Assembler）汇编，并在 CPU Emulator 通过官方 `.tst`/`.cmp` 比较。
- 范围边界：本作业**只做单文件、无函数调用**的 VM 程序；`function`/`call`/`return` 属于 [[阶段作业/计算机组成原理-阶段作业-08-VM函数调用]]。
- RAM 约定（官方）：`SP=0`、`LCL=1`、`ARG=2`、`THIS=3`、`THAT=4`、`temp=5..12`、通用寄存器 `R13..R15=13..15`、静态区 `16..255`、栈区 `256..2047`。
- 禁止事项：不得复制官方 VMTranslator 实现或他人提交。

## 4. 详细题目

### P7a 栈语义手推（先做）

在 `设计.md` 中给出下列 VM 片段执行后的**栈快照与 SP 值**（逐条列出）：

```
push constant 17
push constant 17
eq
push constant 892
push constant 891
lt
and
```

并回答：`eq` 消耗几个栈元素、产生几个？`true`/`false` 在 Hack VM 中用什么整数表示，为什么选这两个值？

### P7b 算术/逻辑命令翻译

实现 9 条命令的翻译：`add`、`sub`、`neg`、`eq`、`gt`、`lt`、`and`、`or`、`not`。

- 一元命令（`neg`/`not`）只改栈顶，不动 SP；
- 二元命令弹两个、压一个；
- 比较命令需生成形如 `EQ_TRUE_0` / `EQ_END_0` 的**带自增计数的唯一标签**。

通过官方测试：`SimpleAdd`、`StackTest`。

### P7c 内存访问命令翻译

实现 `push segment index` 与 `pop segment index`，覆盖全部 8 段：

| 段 | 基址/规则 | push 语义 | pop 语义 |
|:---|:---|:---|:---|
| `constant` | 无 | 压入字面量 index | 非法（不支持） |
| `local / argument / this / that` | `LCL/ARG/THIS/THAT` 间接基址 | `*(base+index)` | 写回 `*(base+index)` |
| `temp` | 固定基址 5 | `RAM[5+index]` | 同左 |
| `pointer` | 0→THIS, 1→THAT | 读 `THIS/THAT` 本身 | 写 `THIS/THAT` 本身 |
| `static` | 汇编符号 `@Prog.index` | 由汇编器分配 RAM ≥16 | 同左 |

通过官方测试：`BasicTest`、`PointerTest`、`StaticTest`。

### P7d 栈失衡诊断（本作业新增题）

自造一个**故意错误**的 VM 程序（例如二元命令后忘记回收一个栈槽），在 VM Emulator 中运行并在 `报告.md` 中记录：

1. SP 的期望值序列 vs 实际值序列；
2. 你如何仅凭 SP 曲线定位到出错的那条命令；
3. 修复后的对照。

### P7e 汇编体积优化（进阶，可选）

统计你的翻译器对 `StackTest.vm` 生成的汇编指令条数。尝试把 `push constant` 的 5 条模板压缩，或把重复的比较逻辑抽成共享子例程（用 `R13` 保存返回地址）。给出优化前后的指令数对比表，并说明"共享子例程"引入了什么新风险。

## 8. 引导与自检（不泄露答案）

- 检查点 1：`pop constant 5` 合法吗？——不合法，想清楚 `constant` 是"虚拟段"这一点。
- 检查点 2：`pop local 3` 需要几个临时寄存器？——先算好目标地址再弹栈，还是先弹栈再算地址？两种顺序中只有一种不会覆盖数据。
- 检查点 3：两个文件都有 `static 0`，翻译后会不会撞同一个 RAM 地址？——这正是文件名前缀存在的理由。
- 常见失败：比较命令的标签计数器是类变量却在多文件间被重置，导致标签重复；`neg` 误写成弹出再压入（SP 多减一次）；`temp` 用了间接寻址（它是固定基址，不该走指针）；生成的汇编中 `@SP` 与 `A=M` 顺序颠倒导致读到 SP 本身而非栈顶。
- 提交前清单：□ 五组官方测试全过；□ 标签全局唯一；□ `static` 带文件名前缀；□ 产物能被自写汇编器汇编；□ 报告含 SP 曲线诊断。
