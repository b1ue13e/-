# 计算机组成原理-课后作业-02-性能剖析与优化

> 非官方中文版：基于 CSAPP Performance Lab 公开规格与 Brendan Gregg USE 方法论设计，任务结构本地化。

## 1. 作业身份

- 课程：计算机组成原理（阶段3：性能与优化）
- 规模：`lesson`（课后作业）｜形态：`lab`（剖析 + 优化实验）
- 来源：CSAPP Performance Lab 公开规格 + USE 方法论，`adapted_from`
- 前置知识：[[03-性能与优化/perf工具]]、[[03-性能与优化/性能分析方法与工具]]（USE 方法）、[[03-性能与优化/优化层次]]

## 2. 学习目标

完成后你应该能够：

1. 用 `perf stat` / `perf record` 测量一个程序的 CPU 时间、IPC、缓存缺失率；
2. 用 USE 方法定位瓶颈资源（CPU 饱和 vs 内存带宽 vs 分支预测）；
3. 基于测量实施至少两种优化（循环展开/分块/预取/SIMD），并用基线对比验证收益；
4. 画一张火焰图（或等价可视化）指出最热路径，并用 Roofline 解释瓶颈类型。

## 3. 任务背景与边界

- 环境：Linux（perf 可用）或 WSL2；C 或 Python 实现基准程序；
- 输入输出：基准程序 + 测量日志 + 优化对比表；
- 禁止事项：不得直接使用第三方优化库（如 BLAS）替代手写优化；不得虚报测量数据。

## 4. 详细题目

### T1 基线测量

编写一个矩阵乘法（512×512，double）基准程序（朴素三重循环），用 `perf stat` 记录：

- CPU 时间 / 周期数 / IPC
- L1/L2/L3 缓存缺失率
- 分支预测失败率

### T2 USE 诊断

回答：瓶颈是 CPU 饱和、访存带宽还是分支预测？给出你的判断依据（数据 + 推理）。

### T3 优化实施

实施至少两种以下优化，每种单独测量并对比基线：

- 循环分块（Tiling，块大小 32/64 对比）
- 循环展开（4 路展开）
- 数据布局优化（交换循环顺序 / 转置 B）
- SIMD 向量化（若工具链支持）

### T4 火焰图与 Roofline

- 用 `perf record` + 火焰图脚本生成火焰图，指出最热 3 个函数；
- 用 Roofline 模型估算该矩阵乘法的计算强度，判断优化是否已接近硬件上界。

## 5. 环境与复现

- 依赖：Linux + `linux-tools`（perf）、`gcc -O2`；Python 3（可选分析脚本）；
- 目录：`03-Projects/系统与硬件/11-计算机组成原理/课后作业/性能剖析/` 下建 `src/`、`measurements/`、`plots/`；
- 运行示例：
  ```bash
  gcc -O2 -o mm src/mm.c
  perf stat -e cycles,instructions,cache-misses,branches,branch-misses ./mm 512
  ```
- 固定 CPU 频率（`cpupower frequency-set -g performance`）与固定矩阵尺寸，保证可复现。

## 6. 提交产物

- `src/mm.c`（基线 + 各优化版本，用宏或分文件隔离）；
- `measurements/perf_stat_*.txt`（每次测量的原始输出）；
- `plots/flamegraph.svg`（火焰图）；
- `报告.md`：基线表、USE 诊断、优化对比表、Roofline 分析、结论与局限。

## 7. 验收标准与 Rubric（满分 100）

| 维度 | 分值 | 标准 |

## 8. 引导与自检（不泄露答案）

- 检查点 1：`perf stat` 中 `cycles` 与 `instructions` 的比值是什么？（IPC，越高越好）
- 检查点 2：矩阵乘法内层循环 `C[i][j] += A[i][k]*B[k][j]` 的空间局部性差在哪？（B 按列访问）
- 常见失败：perf 权限不足（需 `sudo sysctl kernel.perf_event_paranoid=1`）；未固定 CPU 频率导致测量噪声；
- 提交前清单：□ 所有命令可复现；□ 每个优化有独立基线；□ 报告含失败案例（如有）。
