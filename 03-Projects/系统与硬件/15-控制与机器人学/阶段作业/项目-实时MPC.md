# 项目-实时MPC

> 阶段作业（stage · lab）：优化 MPC 求解实时性——热启动、矩阵预计算、代码生成，在限时约束下评估控制频率上限。

## 1. 作业身份

| 项 | 值 |
|:---|:---|
| 课程 | 控制与机器人学（15-控制与机器人学） |
| 规模层级 | `stage`（阶段作业） |
| 任务形态 | `lab`（编程实验 + 报告） |
| 所属阶段 | 阶段 9：MPC 深入 |
| 来源类型 | `local_integration_task`（本地化改编） |

## 2. 学习目标

完成后能够：
- 实现 QP 热启动（上一时刻解作初值）；
- 预计算时不变矩阵（$\Psi, \Theta$）避免重复装配；
- 对比求解时间与可支持的控制频率；
- 评估"实时性 vs 预测精度"的工程权衡。

## 3. 所需知识

- `requires`：热启动、MPC代码生成、预测方程；
- 前置支撑：QP标准形式、OSQP、车辆MPC（上一作业）。

## 4. 任务背景与边界

- **场景**：车辆线性 MPC，目标控制频率 ≥ 50 Hz（求解 ≤ 20 ms）；
- **输入**：模型、$N$、约束、实时性要求；
- **输出**：求解耗时统计、优化前后对比、频率上限；
- **禁止**：只报"能跑"不量化耗时；须有统计与对比。

## 5. 详细题目

**题目 1（基础，25 分）：耗时基线**
1a. 跑通车辆 MPC（复用车辆MPC作业），测单步求解耗时（100 次统计均值/分位）；
1b. 报告当前可支持的最大控制频率；
1c. 定位耗时瓶颈（QP 求解 / 矩阵装配 / Python 开销）。

**题目 2（核心，30 分）：热启动与预计算**
2a. 实现热启动：上一时刻解作本次 QP 初值，重测耗时；
2b. 预计算时不变 $\Psi, \Theta$（时变参考除外），避免每步重装配；
2c. 对比优化前后耗时与频率上限。

**题目 3（进阶，25 分）：参数-实时性**
3a. 扫 $N \in \{5, 10, 20\}$，报告耗时增长曲线；
3b. 扫约束数量（加状态约束），报告耗时变化；
3c. 给出"满足 50 Hz 的最大 $N$"结论。

**题目 4（应用，20 分）：工程权衡**
4a. 对比 Python（CVXPY/OSQP）与代码生成方案（CasADi C 代码）的耗时（可选，记录差异）；
4b. 评估"减 $N$ 保实时 vs 加 $N$ 保精度"的权衡；
4c. 结论：实时 MPC 的部署指南。

## 6. 环境与复现

- Python 3.10+，`numpy`、`cvxpy`/`osqp`、`timeit`；
- 固定模型、种子、仿真时长（≥ 100 步）；
- 报告注明 CPU 型号与求解器版本。

## 7. 提交产物

- 报告：基线、优化对比、参数扫描、权衡、结论；
- 优化前后两版代码 + README；
- 耗时统计表（均值/中位/P95）。

## 9. 引导与自检

- 常见失败：热启动未生效（求解器没复用初值）、预计算矩阵含时变部分、耗时统计未排除 JIT 首步；
- 调试路径：基线 → 热启动 → 预计算 → 扫描；
- 自查清单：
  - [ ] 耗时统计 ≥ 100 次；
  - [ ] 热启动前后有对比；
  - [ ] 预计算正确性有验证（结果不变）；
  - [ ] 频率上限计算正确。
