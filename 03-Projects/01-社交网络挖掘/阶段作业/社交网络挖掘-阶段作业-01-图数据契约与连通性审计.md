# 社交网络挖掘-阶段作业-01-图数据契约与连通性审计

## 学习目标

建立一条从原始事件边表到有向图、统计不变量、连通分量和 Bow-tie 解释的完整审计链。学习者必须证明“数据语义正确”先于“算法输出合理”。

## 任务背景与边界

- 默认输入为 `data/generated/directed_edges.csv`；允许替换为公开数据，但必须补 URL、访问日期、许可、哈希和字段说明。
- 原始事件、清洗后边表和图对象必须分开保存，禁止原地覆盖。
- 第一版统计函数不得调用 NetworkX 同名统计 API；NetworkX 只作为 oracle 交叉验证。
- 全部流程在普通 CPU、2 GB 内存下一分钟内完成。

## 详细任务

### S01-1 冻结数据契约

创建 `manifest.yml`，记录输入哈希、列定义、节点类型、边方向、自环、重复事件、零度节点和缺失值策略。输出清洗日志，保证每一条删除或聚合规则都能解释边数变化。

### S01-2 独立统计与 oracle

独立实现节点数、唯一边数、入度、出度、互惠节点对和自环计数；在 6 节点手算图上给出期望结果，再与 NetworkX 对照。任何差异都必须定位到口径或代码。

### S01-3 连通结构与 Bow-tie

实现或调用 BFS/DFS 得到 WCC/SCC；以最大 SCC 为核心构造 IN、OUT、tendril 和 disconnected。写出区域互斥、区域并集和节点守恒断言，并解释非 Web 网络中这些名称只是方向角色。

### S01-4 对抗性回归测试

至少构造四张边界图：空图、全自环图、两 SCC 单向相连图、含互惠与重复事件图。说明每张图会击穿哪一种幼稚实现。

## 引导与自检

- 先冻结图语义，再写统计；不要让库默认值替你做决定。
- 如果结果不同，先比较事件数、唯一边数、图边数，再检查算法。
- [ ] 手算小图没有调用库函数。
- [ ] 所有清洗动作都有前后计数。
- [ ] Bow-tie 区域互斥且覆盖节点集。
- [ ] README 能从项目根目录复现。
