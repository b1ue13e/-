# 量化金融-大作业-AAPL贯穿式量化研究

## 学习目标

以 AAPL 或同等公开资产完成从数据契约、因子构造、无泄漏回测、成本建模到风险归因的完整研究闭环。目标是证明研究过程可追溯、可复现、可被否证，不是输出投资建议。

## 任务边界

1. 固定数据源、版本、时区、复权和训练/验证/测试日期；提交数据卡与字段审计。
2. 建立等权/买入持有基线，构造一个可解释因子，完成预处理和标签时点审计。
3. 用 walk-forward 或 purged CV 评估，扣除手续费、滑点、冲击和换手成本。
4. 完成参数扰动、子区间、安慰剂、替代数据和压力测试；报告失效与停止条件。

## 提交产物

Python 3.11，pandas、NumPy、SciPy、statsmodels；可选 Qlib。提交 `src/`、配置、锁定依赖、数据卡、运行日志、净/毛绩效表、风险归因、图表和 6-10 页报告。严禁提交凭据、受限数据或可直接复制的答案。

## 验收标准

数据与时点 20；研究设计与无泄漏 25；成本与风险 20；稳健性与反证 20；可复现性与文档 15。任何无法追溯信号日期、成交日期或数据版本的结果不通过。

## 引导自检

- [ ] 全部测试和 smoke run 通过并记录命令。
- [ ] 测试集只使用一次，参数选择与最终评估严格分离。
- [ ] 报告同时给出收益、回撤、换手、尾部损失和分年度结果。

## 运行证据与失败判定

- 固化数据哈希、环境锁文件、配置、日志、图表和一键复跑命令；每个结果可追溯到信号日与成交日。
- 测试集被重复使用、成本或复权口径缺失、任何阶段只能靠手工修改才能运行时，判定为失败。
- 必须保留基线、失败实验、参数扰动与停止规则；最终结论同时说明适用边界和不可推广之处。

## 贯穿式执行顺序

1. **协议冻结**：先写数据截止日、复权口径、信号与成交时点、训练/验证/测试边界、成本和风险限制；冻结后才接触测试集。
2. **数据层**：保存原始与清洗数据摘要、缺失/重复/公司行动检查，确保任一观察都能追溯到日期与字段。
3. **基线层**：实现买入持有、等权或简单动量基线；主模型必须在完全相同的成交与成本口径下比较。
4. **研究层**：完成因子、组合、风险与稳健性实验；每次实验记录唯一 ID、配置差异、输入哈希和结果状态。
5. **最终验收**：只运行一次冻结测试，生成毛/净收益、回撤、换手、尾部风险和分年度表；任何失败步骤都阻断发布。

提交目录至少包含 `data_card`、环境锁定文件、配置、源码、测试、日志、机器可读指标、图表和研究报告。报告必须明确这只是单资产教学研究，不构成可外推的投资结论。
