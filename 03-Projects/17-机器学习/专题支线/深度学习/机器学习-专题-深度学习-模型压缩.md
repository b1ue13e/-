# 机器学习 · 深度学习专题（可选参考）：Compression 模型压缩

> 这份作业把你从“会训练模型”往“会交付模型”推一步。关键不是把模型压得最小，而是学会衡量精度、速度、体积三者之间的取舍。

## 1. 布置时机

- 建议在学完以下内容后布置：
  - 模型训练与评估
  - 蒸馏、剪枝、量化基本概念
  - 部署中的延迟和内存约束
- 最好在学生已经有一个成熟教师模型后布置。

## 2. 前置知识

开始前，学生应该已经会：

1. 保存和评估一个成熟模型。
2. 理解参数量、模型大小和延迟不是一回事。
3. 知道蒸馏、剪枝、量化的大致差异。
4. 会用统一脚本做评估。

## 3. 任务背景

你需要在尽量少损失性能的前提下，把模型变小、变快、变易部署。

这份作业训练的是：

- 小模型与原模型对照
- 蒸馏 / 剪枝 / 量化
- 精度-速度-大小权衡
- 工程口径的一致评估

## 4. 学习目标

完成后，应该能做到：

1. 跑通至少一种压缩方法。
2. 用统一口径比较压缩前后模型。
3. 解释哪种压缩最值当。
4. 理解“参数量减少”不一定等于“真实变快”。

## 6. 数据说明

### 数据类型

- 输入：验证数据与原模型
- 输出：压缩后模型及评估结果
- 任务类型：模型工程优化任务

### 你至少要先弄清楚

1. 用什么硬件测速度。
2. batch size 是否固定。
3. 原模型的 baseline 是多少。
4. 量化或蒸馏后要不要再微调。
5. 真实部署更关心参数、体积还是延迟。

## 9. 分阶段完成要求

### 第一阶段：先跑通

- 固定教师模型
- 做一种基础压缩
- 记录初步结果

### 第二阶段：再改进

- 尝试量化或蒸馏
- 比较不同方法
- 记录延迟和体积

### 第三阶段：最后解释

- 总结最值当方案
- 解释为什么某方案收益不明显
- 做三维权衡比较

## 10. 建议实施步骤

1. 先固定 baseline 模型和验证脚本。
2. 跑简单剪枝或小模型基线。
3. 再做蒸馏或量化。
4. 统一硬件和 batch 测速度。
5. 做压缩前后对照表。

## 11. 引导与自检

- 不同实验用不同硬件测速度。
- 只看参数量，不看真实 latency。
- 量化后精度掉很多却没有再校准。
- 学生模型太小根本学不动。
- 前后评估脚本不一致。
