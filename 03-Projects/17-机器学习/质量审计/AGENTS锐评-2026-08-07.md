## 0. 先给结论：不是"垃圾"，是"半身不遂"

说项目是垃圾，那是气话，不准确。

- **内容层（知识卡、作业）质量不低**：以 `机器学习-线性回归.md` 为代表，推导、几何解释、可运行 PyTorch 代码、闭卷复现、带答案自测题、`## 学完后可以完成` 派生块一应俱全；73 张卡里 72 张有派生作业块；前置知识 MOC（`🧭 机器学习-前置知识.md`）有有序清单、补学顺序、诊断入口、最低通过标准——这部分**对得起 AGENTS §5.1**。
- **作业体系结构合规**：15 份正课程作业 frontmatter 字段零缺失，`🧭 课程作业总索引.md` 用 Dataview 自动查询三层级，MIT 6.036 来源与许可记录到位，Capstone 存在。
- **审计文件诚实**：`质量审计/课程严苛审计.md` 明确写了"C 级、非独立复审、正式发布未完成、A 级因环境不支持子智能体未完成"，没有粉饰——这点要肯定。

**但治理层（入口一致性、阶段 MOC、关系字段、来源口径、历史标签收口）是一塌糊涂**，而且每一处混乱都精确踩中 `AGENTS.md §6.1` 列出的"共有失败模式"。下面逐条点名，全部带文件证据。

## 1. 最致命：Spine 自相矛盾（违反 §5.2 / §2）

这是整个项目最大的硬伤：**声明的主线，和实际内容的主线，不是同一条。**

| 入口文件 | 声称的主线 |
| :--- | :--- |
| `🗺️ 机器学习学习路径.md`（2026-04-18） | 理论主干 = 周志华《机器学习》；Hands-on 管实验；MML 管数学 |
| `📚 教材挂载索引.md`（updated 2026-08-02） | **主教材 = Dive into Deep Learning (d2l.ai)**；周志华/Hands-on/MML 降级为"历史书目仅作补充"；验收源 = 李宏毅 ML2021 |

实测 73 张知识卡的 `source` 字段：

- **71 张写 `source: 周志华《机器学习》第X章`**
- 2 张写 MML
- **仅 7 张**在正文中引用了 d2l.ai

也就是说：索引页在 2026-08-02 单方面宣布"主线换成 d2l"，但 98% 的卡片内容仍按周志华组织，个别卡片（如线性回归）既在 frontmatter 写 `source: 周志华`，又在 `sources:` 块里嵌 d2l + ISL——**一张卡自己都不知道自己主线是谁**。

`AGENTS §5.2` 要求"先做单 Spine 充分性判断，只为明确缺口增加来源；来源数量不参与加分"。这里的问题不是"来源多"，而是**声明的 Spine 与内容 Spine 分裂**，且两个入口文件彼此打架。学习者同时看这两页，会得到两条互相矛盾的"官方路径"。

## 2. 五个阶段 MOC 全部缺法定段（违反 §2）

`AGENTS §2` 明文："**每个阶段 MOC 必须包含 `## 阶段验收与作业`**，其中作业入口优先由 `assignment_level`、`stage_id` 和 `requires` 自动查询生成。"

实测 5 个阶段 MOC 的"验收"段标题：

```
🧭 阶段1-基础概念.md  ->  ## ✅ 阶段验收
🧭 阶段2-线性模型.md  ->  ## ✅ 阶段验收
🧭 阶段3-正则优化.md  ->  ## ✅ 阶段验收
🧭 阶段4-树与集成.md  ->  ## ✅ 阶段验收
🧭 阶段5-其他方法.md  ->  ## ✅ 阶段验收
```

- 段名不对（是 `阶段验收`，不是法定 `阶段验收与作业`）；
- **5/5 都没有由作业 `requires` 反查生成的作业入口**。

后果：`AGENTS §4.5/§4.6` 要求的"学完本阶段 → 能完成什么作业 → 通过什么验收 → 如何进入下一阶段"闭环，在 MOC 层是断的。MOC 里只有验收 checklist，没有把作业挂上来——而作业总索引那边明明具备自动查询能力。这是"能查不查、该挂不挂"的典型治理欠账。

## 3. `upstream` 关系字段失真（违反 §3 / §5.6）

`AGENTS §3`："`upstream` 只表达直接知识依赖，必须使用与实际文件名一致的 `[[wikilink]]`"；第五章验收清单把"存在实际前置却未写 `upstream` / `upstream` 无法解析"列为直接封顶 84 的阻断项。

反例，`03-正则优化/机器学习-计算图.md`：

```yaml
upstream: ["[[机器学习-周志华]]", "[[Hands-on Machine Learning]]"]
```

- 这两个目标是**书库笔记**，不是课程知识卡；
- `[[机器学习-周志华]]` 还是**死链**——书库实际文件名是 `机器学习（周志华）`（全角括号），根本解析不到。

正确做法应指向 `[[机器学习-反向传播算法]]`、`[[机器学习-神经网络]]`、`[[机器学习-梯度下降]]` 等真实前置卡。这张卡还同时缺少 `## 学完后可以完成` 派生块（全库唯一一张缺），`license: "[待验证]"` 却写了指向豆瓣书页的 `source_url`——典型的"未核验当已核验"（违反 §4）。

> 注：除计算图外，其余 71 张卡的 `upstream`/外部链接均可解析（已脚本全量校验，未再发现书名为 upstream 的情况）。问题集中在今天（08-07）仓促新增的这张卡，说明"补 d2l 主线"的过程中出现了半成品直塞。

## 4. 来源字段口径混乱（违反 §3 字段治理 / §4）

- **12 张卡缺 top-level `license`**：`线性回归`、`决策树`、`随机森林`、`XGBoost`、`PCA`、`L1正则化Lasso`、`反向传播算法`、`神经网络`、`模型评估指标`、`数据集划分与交叉验证`、`过拟合与欠拟合`、`逻辑回归`。其中部分把 license 塞进 `sources:` 列表、部分完全没写——**同一仓库两种记法并存**。
- **`线性回归.md` 的 Spine 自指矛盾**：frontmatter `source: 周志华《机器学习》第3章` + `source_url: douban`，同时 `sources:` 块列 d2l（CC BY-SA 4.0）+ ISL。检索练习里又写"Spine（周志华 / Hands-on ML / MML）"。一处文件里出现三套 Spine 表述。
- `AGENTS §3` 要求本地生成页面也记录 `license` 或等价来源信息；`[待验证]` 只能用于**确实无法核验**的内容，不能当占位符滥用。

## 6. 作业 `source_type` 自相矛盾（违反 §5.5.8 真实标注）

`AGENTS §5.5.8`：作业来源必须如实标注，**本地融合任务不得冒充名校官方作业**。

实测同一份作业 `课后作业-机器学习-课后作业-01-线性回归与梯度下降.md` 出现三种说法：

| 位置 | 写的 source_type |
| :--- | :--- |
| frontmatter（第 10 行） | `official_assignment` |
| 正文表格（第 37 行） | `local_integration_task` |
| `🧭 课程作业总索引.md`（第 79 行）统一宣称 | "每份文件 frontmatter 标 `source_type: open_coursework` 且 `source_license_status: verified`" |

三处对不上：frontmatter 是 `official_assignment`，正文是 `local_integration_task`，索引声称全是 `open_coursework`。**索引的"每份都标 open_coursework"对这份作业就是假的**。真实情况应是 `open_coursework`（MIT 6.036 改编）——frontmatter 与索引不一致、且被正文的 `local_integration_task` 进一步搅浑。

## 7. 推进顺序自我打架（违反 §4.5）

- `🗺️ 机器学习学习路径.md` → "推荐推进顺序"：**先做 1+2，再做 4，再回头补 3，最后 5**。
- 五个阶段 MOC 的导航、以及 `🧭 课程作业总索引.md` 的体系结构表，全部是 **1→2→3→4→5 线性顺序**。

学习者在这两份文件里拿到两套阶段次序。若 3 真该在 4 之后，MOC 顺序与作业映射都得重写；若只是"建议跳读"，应明确标注为可选路径而非"推荐推进顺序"。当前写法让"主线顺序"这件事本身失焦。
