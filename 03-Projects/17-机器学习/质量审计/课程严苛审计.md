### 缺陷 1 — 6 张知识卡正文被截断（数据丢失）
- **根因**：`batch3_upstream.py` 在插入 `upstream` 字段时，正则 `m = re.match(r"^(---\n)(.*?)(\n---\s*\n?)", text)` 将 `post` 捕获为**仅含闭合分隔符**（`m.group(3)`），而 `re.match` 未捕获分隔符之后的正文，写回 `pre + new_fm + post` 即**丢弃了全部正文**。结果：6 张卡被静默截断为仅剩 frontmatter（0 行正文）。
- **影响文件**（均为 01–05 阶段核心卡）：
  - `01-基础概念/机器学习-数据集划分与交叉验证.md`（原 444 行 → 截断为 38 行）
  - `01-基础概念/机器学习-过拟合与欠拟合.md`（原 255 行 → 截断为 31 行）
  - `02-线性模型/机器学习-线性回归.md`（原 383 行 → 截断为 32 行）
  - `03-正则优化/机器学习-感知机.md`（原 316 行 → 截断为 23 行）
  - `05-其他方法/机器学习-主成分分析.md`（原 425 行 → 截断为 31 行）
  - `05-其他方法/机器学习-支持向量机SVM.md`（原 373 行 → 截断为 23 行）
- **修复**：从仓库外全量快照 `C:\Users\DELL\.workbuddy\audit\backup\17-机器学习-2026-08-06\` 恢复正文，按 Batch 1 的 `旧名 → 机器学习-前缀` 映射重写正文内 wikilink，保留当前（已前缀化、合规）的 frontmatter，并修正缺陷 2 的引号损坏。恢复后行数 256–445，与原文件一致。
- **附带修复**：同一脚本写入的 `upstream` 值存在引号损坏 `upstream: [\"[[机器学习-模型评估指标]]\"]`，已修正为 `upstream: ["[[机器学习-模型评估指标]]"]`（6 张卡全部修正）。

### 缺陷 2 — 15 个作业文件 frontmatter 分隔符畸形
- **根因**：作业文件使用 `---type: project`（开头 `---` 后无换行），违反 AGENTS.md §3 的 Dataview frontmatter 规范。该 bug 与 Batch 0 修复的 `---type: study` 同源，但 Batch 0 仅扫描了 `02-Knowledge` 课程目录，未覆盖 `03-Projects` 作业目录，故作业文件被遗漏。

- **修复**：对 15 个作业文件执行机械修复 `---type:` → `---\ntype:`（与 Batch 0 同构的安全操作，幂等）。`课后作业-16`（Batch 4 已重写）与新建 Capstone 本就合规，未改动。修复后全部作业 frontmatter 可被 Dataview 正确解析。
